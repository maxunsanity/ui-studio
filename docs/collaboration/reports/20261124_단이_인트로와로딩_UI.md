지시 현중 직접 요청 「게임 시뮬레이터의 오디션과 캐스팅을 다시 살펴봐」

- UI 스튜디오 인트로 r1 25장을 데스크톱에서 열고 연결 22개와 모바일 430px 대표 7상태를 확인했다. P265 인트로 탭, 작업 명세서와 프로필 r14 무료 문구를 읽어 검증했다. 서명 후 연결은 기존 1인 로비를 여는 시안용 연결이다. 빈 첫 로비와 실제 보드 영입 이벤트의 기능 연결은 별도다.
- 7007 게임 시뮬레이터의 오디션 메뉴에서 분리된 자유 테스트 프로필·검토 저장으로 두 갈래를 실행했다. 후보 도착 → 직접 캐스팅 → 영입 연출 건너뛰기 → 보드 계속하기, 후보 도착 → 명함 주기(이야기 1회 개방) → 첫 바퀴 검토 → 찜 후보 우선 초대(4인) → 첫인상 선택 → 3회 비교 → 영입 확인 → 보드 복귀 → 추가 자리 시험을 확인했다. 실제 자연 주행 발란스, 정식 저장 전달 및 두 번째 팀명 입력 화면은 이 검토에서 시험하지 않았다. 검토 모드의 게임 원본은 조회만 했다.
- P100 `오디션_기획서.md:65` 및 `src/audition/board-app.mjs:353`에서 24개 대지 도착과 후보 소개를 확인했다. 첫 멤버는 직접 선택할 수 있고 이후 엔터파워로 열린 합류 자리가 필요하다. 첫 바퀴 종료까지 첫 멤버가 없으면 오디션으로 이어진다. P265 `#intro`의 11/24 결정은 보드 중 첫 캐스팅과 찜 경로에 대응한다. 캠퍼스 HUD의 '쟁탈전'(P98)은 출연권 전투다.
- 7018 인트로 r1의 후보 장면은 `cast-first`·`cast-second`의 영입 완료와 예명으로 시작해 실제 만남 선택·명함·대진 흐름이 빠져 있다. 예명은 P265 확정 UI이며, 7007 보드의 직접 캐스팅·내장 오디션에서는 아직 입력할 화면이 없다(P100 `오디션_기획서.md:219`). 두 번째 멤버 합류 후 팀명 모달은 `src/audition/board-app.mjs:379`에서 소스로 확인했다. 발란스 도구의 얼굴 룰렛은 P265 연출 참조로 확인했다(`src/tools/idleSim/v02/app.js:302` 및 `:2107`). 7018 화면과 원본 기획을 이번 검토에서 고치지 않았다.
- 7007 오디션 최종 확인과 영입 결과에 짝 몬스 지급 옛 문구가 남아 있다(`data/audition_sim/ui_text.csv:14`, `:39`). 직접·대진 모두 새 영입 결과의 `mons`가 `null`이다(`src/audition/engine.mjs:243`). 첫 획득은 별도의 게임 시작 몬스다. 기존 문구를 인트로에 복제하지 않는 것이 필요하다.
- 캡처는 같은 보고명 JPG와 사용자 작업 폴더의 `outputs/오디션_캐스팅_시뮬레이터.png`에 보존했다. 실제 시뮬레이터는 데스크톱 1440px의 폰 프레임에서 확인했다. 3D 지도는 소프트웨어 WebGL을 사용한 별도 검토 브라우저에서 40칸을 확인했다. 이번 변경은 테스트/빌드 없이 브라우저와 저장판 조회로 확인했다. 커밋 없음.
