# HUD·메뉴 페이지 구조 작업 인계 프롬프트 (2026-11-19)

너는 케이팝몬스터즈 HUD 기획서를 이어받아 보정하는 작업자다. 아래에 오늘 「hud 제작」 방(현중·제나·이올카)에서 한 작업과 확정된 결론을 모두 적었다. 이 내용을 기준으로 기획서를 보정하라.

## 1. 작업 규칙 (현중 지시)
- UI 기획서에는 결론(화면·구성·이동)만 쓴다. 조사 과정, 소스 근거 나열, 시스템 기획 내용, 수정 로그는 쓰지 않는다.
- 이미지 중심으로 쓴다. 컨폼된 시안 그림은 해당 절 맨 위에 두고, 표와 설명은 그 아래에 붙인다.
- 페이지·구조를 정하기 전에 게임 시뮬레이터·현황판·발란스 시뮬레이터에 이미 있는 기능을 먼저 확인한다. 짐작으로 표를 짜지 않는다.
- UI 용어는 정확히 쓴다(드롭다운, 책갈피, 창, 칩 등). UI 스튜디오 가이드의 부품 이름을 그대로 쓴다.
- HUD에는 보드 플레이와 관계된 것만 두고, 나머지는 눌러서 들어간 콘텐츠 화면에서 보여 준다.
- 시안 그림에는 개발 상태 표시를 넣지 않는다.
- 금지어: 임시, 미정, 기획 대기, 검수 대기, 발란스 대기, 답 대기, 개발 안 됨, 개발됨.
- 숫자는 지어내지 않는다. 텍스트 칸 글자 수와 숫자 자릿수는 현중에게 확인해 적는다.
- 텍스트 박스·숫자 칸에는 게임 시뮬레이터 소스의 실제 데이터 이름을 기획서와 그림 범례에만 붙인다.

## 2. 오늘 확정된 HUD 결정
- 방패는 따로 두지 않고, 이어지는 하나의 「몬스 기분 게이지」로 보여 준다.
- 돈, 엔터파워, 팬은 줄이지 않고 모든 자릿수를 보여 준다.
- 주사위는 「가진 개수/상한」으로 보여 준다.
- 앨범 상자의 화살표와 드롭다운은 빼고, 두 칸으로 바로 이동한다.
- 음악 앱은 이번 구조에서 뺀다.

## 4. 현중이 짚은 수정 (반드시 반영)
- 캐릭터 정보창에 라포가 있어야 한다. 지금 라포는 관계 화면에만 있으므로 캐릭터 정보창에 라포 책갈피를 더한다.
- 이름은 「크루」다. 「응원 크루」라고 쓰지 않는다.
- 「음악」이 아니라 「앨범」이다. 앨범 안에 차트 보기, 곡마다 페스티벌 출전곡인지 표시, 페스티벌 신청으로 바로 가기를 둔다.
- 몬스 로비에서 몬스 기분 게이지를 보여 준다.
- 돈을 누르면 상점이 열린다. 상점은 돈을 팔지 않는다(루비로 산다).
- 상점 화폐 이름은 「루비」, 아래 메뉴 이름은 「포토카드」다.

## 6. 게임 시뮬레이터와 기획이 다른 곳 (시뮬 쪽을 기획에 맞춘다)
- 아래 메뉴 「카드북」 → 「포토카드」, 위쪽 재화 「보석」 → 「루비」.
- 캐릭터 정보창에 라포 책갈피가 없다.
- 앨범 창에 출전곡 여부 표시와 페스티벌 바로 가기가 없다(차트 보기만 있음).
- 몬스 도감 화면에 몬스 기분 게이지가 없다.
- 건설의 세트 완성 보너스와 상점의 이벤트 보상 입구는 기획서에만 있다.

## 7. 현중이 정할 것
- 친구 메뉴(친구 목록 · 파트너 이벤트 · 선물 · 카드 트레이드)를 정보 펼침 안에 둘지, HUD에 따로 둘지.

## 8. 다음 단계
- 위 표를 기준으로 메뉴별 깊이(1단계 전체 화면 / 2단계 안쪽 화면), 들어오는 길, 뒤로 가면 어디로 가는지를 표로 먼저 현중과 논의한다. 그림은 표가 정해진 뒤에 그린다.
- 그림은 UI 스튜디오 툴에서 직접 그린다(파일·코드 직접 수정 금지).

## 9. 이올카 보탬
- 페스티벌 레이스 다섯 단계는 연료 모으기 · 출발 전 · 레이싱 · 결과 확정 · 기간 종료다.
- 기획서에서 돈과 주사위의 「누를 수 없음」을 고친다. 돈·루비는 상점을 열고, 주사위는 주사위 충전 창을 연다.
- 기록장·소식은 HUD에 두지 않는다.
