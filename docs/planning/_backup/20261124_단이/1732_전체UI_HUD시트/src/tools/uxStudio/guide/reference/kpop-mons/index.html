최신 UI 기획과 작업 명세

2026-11-23 · 현중 요청 반영 · 제안(검수 대기)

몬스 보유 목록에서 개별 정보와 합성을 확인하고, 기분 관리·출동·컨디션 게임을 각각의 화면으로 엽니다.

1. 목적과 범위

정보 → 몬스는 보관함부터 열립니다. HUD → 몬스 기분은 기획사 방어와 지킴이 기분부터 열립니다. 아이돌의 컨디션 회복과 몬스 출동은 보관함에서 바로 접근할 수 있습니다.

3. 화면 깊이와 뒤로 가기

보관함·상세·기분·스케줄·컨디션 게임은 각자 전체 화면입니다. 속성 선택은 드롭다운입니다. 기분 아이템과 팩의 사용 확인은 모달입니다.

  • 상세 뒤로 가기는 보관함으로 돌아가며, 직전 속성 선택과 스크롤을 유지합니다.
  • 기분·출동·컨디션 게임의 뒤로 가기는 호출 화면으로 돌아갑니다. HUD에서 기분으로 왔으면 HUD, 상세에서 컨디션 게임으로 왔으면 해당 몬스 상세입니다.
  • 선택해서 열린 화면을 닫으면 열었던 버튼으로 초점을 돌려줍니다.
4. 화면별 상세

보관함

포토카드의 아이돌 인벤토리처럼 보유 카드를 그리드로 보여줍니다. 높은 단부터 정렬하고, 한 카드에는 그림·이름·단·상태를 표시합니다. 속성 드롭다운에서 수·목·화·금·토를 복수 선택하며, 전체 선택은 속성 제한을 해제합니다. 희귀도 구획과 상단 기능 탭은 제거합니다. 작은 「몬스 팩」 버튼은 상단, 세 가지 바로가기는 공통 하단 메뉴 위입니다.

몬스 상세

대표 그림과 이름 아래에 단계 · 희귀도 · 모은 수를 표시합니다. 「모은 수」는 시안에서 현재 보유 마릿수로 표시합니다. 하단의 합성하기 · 컨디션 게임을 나란히 놓습니다. 간식 주기는 별도의 아이콘 버튼으로 배치합니다.

합성하기

같은 종·같은 단계 두 마리가 있을 때 버튼을 활성화합니다. 누르면 둘을 사용하고 다음 단계 몬스 한 마리를 남깁니다. 결과 메시지와 단계·모은 수를 갱신하고, 남은 보유분을 바탕으로 버튼을 다시 판정합니다. 가능한 단계가 여러 개면 시안은 가장 높은 단계의 쌍을 먼저 사용합니다.

몬스 기분

방패 수, 자동 방어 가능 수, 몬스별 기분을 표시합니다. 기획사 방어는 모든 보유 몬스를 공통 후보로 보며 실제 참가 몬스는 자격 조건으로 자동 결정하는 UI 제안입니다. 몬스 카드를 누르면 개별 상세를 엽니다. 간식은 개별 몬스 상세에서 열며, 보고 있던 몬스 한 마리가 사용 대상입니다. 확인 모달에는 간식 아이콘, 보유 수, 대상, 기분 전후 수치와 1개 사용 버튼을 표시합니다. 취소하면 값이 유지됩니다. 보유량 0, 기분 상한, 기분 조회 불가의 경우 사용 버튼을 비활성화합니다.

몬스 출동

출동은 기존 스케줄의 몬스 필터에서 일정과 진행 상태를 봅니다. 지킴이·수호 배치, 출동 중, 휴식 중 등 편성 제한은 기존 조건을 따릅니다. 컨디션 게임은 아이돌별 컨디션과 수호 몬스를 보여주고, 오늘 완료·수호 미배정·몬스 휴식은 사유를 표시합니다. 이용 가능한 아이돌은 기존 게임 입장으로 이어집니다.

컨디션 게임 · 시뮬레이터 기준

게임 시뮬레이터 원본에서 몬스의 「아이돌 돌봄」을 엽니다. 사용 가능한 수호 몬스를 배정하고 자동 전투를 시작합니다.

공통 부품과 창 크기

보관함 카드, 속성 선택, 간식, 합성 활성·비활성, 게이지, 컨디션 입장 상태, 팩은 몬스 부품 보드에서 확인합니다.

화면 기준은 390 × 844입니다. 가운데 모달은 폭 342로 맞추고 높이는 입장 354, 일시정지 176, 종료 208, 팩 열기 308, 행복 교환 확인 212, 팩 결과 270으로 적용합니다. 하단 바텀시트는 폭 374이며 팩 관리 높이 320, 수호 몬스 선택 높이 478입니다. 속성 드롭다운은 버튼 아래에 붙습니다. 다른 공통 창은 기존 크기를 사용합니다.

몬스 팩과 행복

보유 팩을 선택하면 열기 여부를 확인합니다. 열기를 선택한 뒤 획득 연출과 결과를 표시합니다. 중복이면 보유량과 합성 가능 상태를 갱신합니다. 행복 잔액과 팩 교환은 같은 진입 안에서 보여주며, 확인 뒤 교환 결과를 표시합니다.

5. 규칙과 예외
  • 획득으로 중복이 생기면 보유 수와 합성 가능 여부를 갱신합니다. 실제 합성은 사용자가 버튼을 누를 때 한 번 처리합니다. 결과 때문에 또 합성할 수 있으면 버튼을 다시 활성화합니다.
  • 상한은 기존 10단입니다. 두 몬스 중 사용 중인 배치가 한 곳이면 기존 규칙대로 윗단이 그 자리를 이어받습니다. 두 몬스가 서로 다른 자리에 사용 중이면 처리 기준이 필요합니다.
  • 컨디션 게임은 수호 배정과 몬스 휴식 상태를 확인합니다. 컨디션 회복이 반영된 결과 이후 수호 몬스는 시뮬레이터 설정상 24시간 쉽니다.
  • 기분 아이템을 적용해도 방패 수는 그대로 보입니다. 보드의 기숙사·본가에 도착하면 기존 회복 규칙에 따라 방패 +1과 지킴이 기분 20% 회복이 적용됩니다.
6. 리소스와 데이터

보유 몬스 이미지·공통 하단 메뉴·9슬라이스 버튼을 재사용합니다. 간식은 시안용 전용 아이콘을 사용합니다. 화면은 종 ID, 단계별 보유 수, 희귀도, 배치·휴식 상태, 선택 속성, 아이템 잔액, 기분값을 읽습니다. 시안의 간식 기분 +10은 미리보기 값입니다.

7. 결정이 필요한 항목
  • 현재 보유 수와 합성 재료를 어떤 자료에서 읽을지 연결합니다. 상세의 「모은 수」를 누적 획득 수로 볼 경우 기존 시안과 표시 기준을 맞춥니다.
  • 10단 중복의 행복 전환 시점, 두 재료가 각기 사용 중인 경우의 우선순위, 합성 후보가 여러 단계일 때 선택 기준을 확인합니다.
  • 간식의 회복량·보유 제한·획득처는 발란스 대기입니다.
  • P243의 「한 마리 한 자리」와 다른 UX 제안입니다. 방어 후보는 공통으로 관리하고, 수호는 컨디션 게임, 출동은 스케줄에서 선택합니다. 수호·출동 중 실제 방어 참여 조건과 동시 참여 처리는 이후 규칙 정의가 필요합니다.

진입과 흐름

HUD 하단 정보 → 몬스. 몬스 로비는 보관함이 먼저 열립니다. 보관함 → 상세 → 배치 변경으로 이어지고, 지킴이·수호·출동은 각각 같은 로비의 책갈피입니다. 합성이나 교환은 실행 전에 대상·수량을 확인합니다.

배경과 버튼은 기존 HUD·포토카드의 9슬라이스 규격을 사용합니다. 공통 창은 374×748입니다. 모달은 가운데(Y=48), 바텀 시트는 하단(Y=96)에 놓습니다. 닫으면 열었던 화면으로 돌아갑니다. 실제 게임 데이터와 발란스 연동은 별도입니다.
