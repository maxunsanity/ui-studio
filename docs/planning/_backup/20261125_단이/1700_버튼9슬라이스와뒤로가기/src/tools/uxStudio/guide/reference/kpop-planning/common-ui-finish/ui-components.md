# 케이팝몬스터즈 공통 UI 규격과 부품서

제안 · 검수 대기 | 2026-11-25 | 세부 와이어프레임 공통 적용 기준

## 기준 화면과 작업 방식

게임 화면은 UI 스튜디오 논리 390×844에서 먼저 맞춘다. 브라우저 1440px와 430px에서 표시를 확인하고, Studio 기기 선택의 큰 폰과 짧은 폰을 사용해 안전 영역과 스크롤도 점검한다. 기존 기획서의 데이터 연결, 화면 이름과 전환을 출발점으로 삼는다. 새 레이아웃은 기존 화면과 같은 진입 조건에서 전후 캡처를 비교한다. 

모노카피바라 GO에서 화면 틀 재사용, 닫기 입력영역과 아이콘 분리, 버튼 눌림의 앞면과 받침 분리를 가져온다. KingShot 샘플의 목록 헤더 고정과 내부 스크롤, Tile Survival 샘플의 딤과 하단 행동 고정도 적용할 수 있다. 화면별 밀도와 동선은 케이팝몬스터즈의 저장판과 기획서에서 결정한다.

## 버튼과 아이콘 부품

아래 치수는 390×844 논리 px 기준 검수안이다. 게임 전용 컨트롤은 해당 화면의 목적과 기존 조작을 먼저 확인한다.

| 부품 | 논리 크기 | 구성과 상태 |
|---|---:|---|
| 주 행동 버튼 | 높이 54 | 화면에서 가장 먼저 찾을 행동 한 곳. 무채색 밝은 앞면, 아래쪽 받침, 선명한 문구. 기본·초점·눌림·비활성 확인. |
| 같은 행의 보조 버튼 | 높이 54 | 주 버튼과 정렬. 얕은 프레임과 좁은 폭을 사용한다. 두 행동의 우선순위는 화면마다 명세한다. |
| 단독 보조 버튼 | 높이 44 | 상세·이전·설명 등 보조 이동. 긴 문구가 들어갈 폭을 확보한다. |
| 아이콘 버튼 | 입력 최소 44×44 | 공통 기호 24×24, 뒤로·닫기 등 식별이 중요하면 최대 28×28. 입력 영역과 그림을 따로 편집한다. |
| 상태·재화 아이콘 | 16 또는 20 | 글자 옆에서 상태나 단위를 표시한다. 상태 변화는 숫자 또는 문구로도 확인할 수 있게 한다. |
| 기능 바로가기 아이콘 | 그림 32 또는 40 | 로비에서 상징과 이름으로 인식한다. 게임 내 표시 조건, 실제 입력 경계, 근접 조작과의 겹침을 확인한다. |
| 주사위 굴리기 | 기존 HUD 전용 높이 유지 | 배율, 재화, 주 버튼이 한 조작 묶음이다. HUD 미리보기에서 함께 확인한다. |

세부 와이어프레임의 주 버튼은 앞면, 받침, 문구가 읽혀야 한다. Studio의 버튼 프레임과 눌림 깊이를 사용한다. 눌림 이동 3px를 대표 화면부터 검수하고 입력 경계는 고정한다. 초점과 비활성도 구분하고 사용 불가 이유는 관련 정보 옆에 둔다. 아래 받침 두께와 그림자는 작은 화면에서도 글자를 가리지 않는 수준으로 맞춘다. 

## 모달과 바텀시트 부품

| 종류 | 논리 크기 검수안 | 동작 기준 |
|---|---:|---|

| 정보 모달 | 폭 최대 358 | 제목과 닫기를 고정한다. 긴 내용은 본문 안에서 스크롤하고 선택 행동이나 확인은 아래에서 찾을 수 있게 한다. |
| 바텀시트 | 폭 374, 최대 높이 748 | 왼쪽·오른쪽 여백 8. 제목과 닫기, 내용 스크롤, 하단 행동 영역의 역할을 구분한다. 스케줄 이야기 바꾸기의 374×748을 기준 사례로 사용한다. |

모달, 시트, 페이지는 Studio의 종류 설정과 실제 실행 표시가 일치해야 한다. 닫기·뒤로·외부 탭·드래그 허용은 원래 기획에 맞춰 결정한다. 구매 확정과 보상을 받는 화면은 각 버튼의 결과를 동작 시험으로 확인한다. 모달/시트 뒤쪽 입력 차단, 닫은 뒤 돌아오는 화면과 포커스도 확인한다. 

## 2D와 3D 표현

세부 와이어프레임의 2D 조작, 프레임, 배경판, 텍스트는 무채색과 명도 차로 우선순위를 만든다. 3D 보드, 장면, 캐릭터, 건물처럼 공간과 재질을 보여 주는 원화는 컬러를 유지한다. 입체 버튼도 무채색 2D 조작 규칙으로 표현한다. 컬러 장면 위에는 제목, 조작, 상태가 읽히는 바탕을 둔다. 컬러 사용 여부는 Studio 자원 이름만으로 판단하지 않고 실제 쓰임과 렌더를 확인한다.

## 연출 명세 부품

세부 와이어프레임에서 입력 → 조건 → 시작 화면 → 피드백 → 도착 화면을 작성한다. 화면을 눌러야 알 수 있는 대기·성공·실패·완료 상태는 각각 확인할 수 있어야 한다.

| 상황 | Studio에 남길 내용 | 미리보기 확인 |
|---|---|---|
| 주 버튼 | 버튼 상태 효과, 앞면, 눌림 깊이, 연결 대상 | 입력 시 앞면 이동, 입력 경계 유지, 기존 확인 화면으로 이동 |
| 장면 전환 | 출발·도착과 카메라 이동 대상, 기존 전환 조건 | 같은 마을의 시설에 집중되는 순서와 되돌아가는 위치 |
| 모달과 시트 | 딤, 입력 차단, 등장·퇴장 방향, 닫기 조건 | 배경 클릭의 결과, 긴 본문 스크롤, 버튼에 닿는지 확인 |
| 게임 연출 | 발표 전 상태, 진행, 결과, 재진입 경로 | 주사위와 카드 사례의 단계 순서, 50바퀴 시 완료 카운트와 버튼 상태 |
 
게임 연출의 시간이나 밸런스 값은 해당 기획의 수치를 연결한다. 값이 없는 항목은 검수 대기로 남긴다.

## 이미지 활용과 화면 검수

자원 목록은 현재 23개 등록 저장판에서 확인한 402개 참조로 정리했다. 사용처, 화면 수, 파일 존재, 컬러 유지 선언 여부를 목록에서 확인한다. 한 번 등록한 원본은 여러 화면에서 참조하고 화면마다 fit과 대체 텍스트를 맞춘다. 이미지의 색, 축소 가독성, 투명 여백, 404는 실제 미리보기에서 다시 확인한다.

화면마다 목적과 주 행동 하나를 찾을 수 있는지 먼저 본다. 정보 세 줄을 보여 주더라도 개별 액션이 없다면 하나의 영역 안에서 묶고, 비용처럼 결정에 직접 필요한 내용은 따로 읽히도록 둔다. 긴 문구, 좁은 기기, 비활성, 복귀, 재열기와 기존 링크를 확인한다. 기준을 실제로 확인한 화면과 저장 데이터만 확인한 화면은 검수표에 표시한다.

미니게임은 이번 범위에서 제외한다. 페스티벌은 주간까지 검수한다. 월드 페스티벌, 시즌 마감, 독립음악앱은 보류한다. 새 도시의 로비 진입과 진행 수는 기존 HUD 동선에서 확인한다.

## 게이지와 수치의 역할

| 종류 | 실제 적용 두께 | 표현 |
|---|---:|---|
| 다음 해금 목표 | 14px | 엔터파워 상세에서 최고 도달 값과 해금 목표를 함께 표시 |
| 방문 바퀴 | 8px | 새 도시 HUD의 카운트 아래 표시. 시작은 빈 트랙, 마지막은 98%, 종료는 100% |
| 보조 상태 | 6px | HUD 몬스 기분. 주사위 조작보다 낮은 위계 |
| 시설 단계 | 7px | 건설 상세에서 단계 수 바로 아래 보조 표시 |

구매 가격, 수량, 보유량과 개별 보상은 숫자로 표시합니다. 미정 값은 기획에서 정한 표시를 유지합니다.

## 크기가 바뀌는 박스의 9슬라이스 검사

이미 정한 UI 스튜디오 사용 설명서의 판·창 9슬라이스 규칙을 공통 부품의 제작·저장 조건으로 적용합니다. 정보 박스, 모달, 바텀시트의 외곽은 원본 이미지의 9슬라이스를 사용합니다. 네 모서리는 고정하고 변과 가운데 영역만 늘립니다. 내용 여백은 따로 잡습니다. 실제 크기가 고정폭 합보다 작은 경우 모서리 보존 범위를 벗어납니다.

문구, 아이콘, 입력 영역과 프레임을 분리합니다. 주 버튼은 기존에 정한 버튼 프레임과 상태 구성에 맞춥니다. 게이지의 트랙·채움은 정보와 진행 상태를 표현하는 독립 레이어입니다.
