# 전체 캔버스·상세 편집·디자인 가이드

## 전체에서 세부로
1. 전체 캔버스 상단에서 프로젝트·저장 설계 이름을 확인합니다. 관리 메뉴에서 프로젝트 폴더와 설계를 바꿉니다.
2. 왼쪽 화면 목록 또는 가운데 보드를 눌러 화면 전체를 선택합니다. 오른쪽에는 그 화면의 설명·종류·논리 크기·실제 저장 연결만 나옵니다.
3. 정렬 보기는 다섯 개씩 한 줄입니다. 연결 보기는 시작 화면에서 명시 목적지를 따라 놓고 미연결 화면을 표시합니다. 보드 끌기/방향키로 자유 배치하고 Esc로 드래그를 취소합니다.
4. 확대·축소와 스크롤은 캔버스 보기만 바꿉니다. 연결 배치·확대·스크롤은 workspace/설계/보기별 로컬 설정이며 게임 화면의 좌표를 바꾸지 않습니다.
5. 상세 편집에서 부모와 자식 부품을 개별 선택하고 디자인 가이드에서 크기·위치·선·이미지·글자를 조절합니다. 상단의 현재 화면 이름과 단계 이동을 확인하세요.

## 같은 설계의 세 표현
| 표현 | 표시하는 것 |
| --- | --- |
| 와이어프레임 | 큰 구역과 버튼 외곽, 대표 그림 자리, 텍스트 행. 실제 그림과 제품 문구는 요청하지 않습니다. |
| 세부 와이어프레임 | 실제 그림의 알파 윤곽·단색 면·얕은 그림자. 원래 native 문구·폰트·크기·부품 위치·분할 프레임을 유지합니다. |
| 본 UI | 설계의 이미지·색·효과와 정확한 native 문구. |

세 표현은 같은 ID·계층·배치·연결을 읽는 보기입니다. 표현 변경만으로 W/P/U 제작 단계가 완료되거나 기준판이 저장되는 것은 아닙니다. 단계별 파일 보존은 별도의 제작 단계 기준판 기능을 사용합니다.

## 기본 와이어를 읽기 쉽게 만드는 규칙
큰 네모만 그린 v1은 정보가 부족했고, 그림마다 칸을 만든 v2는 바탕·원화·프레임·배지가 겹쳐 복잡했습니다. 현중의 두 피드백을 보존하고 v3에서 다음 공통 보기 규칙을 적용했습니다.
- 버튼 외곽과 거의 같은 그림, 부모를 가득 채우는 배경 그림은 같은 경계를 두 번 표시하지 않습니다.
- 같은 action owner 안에는 대표 이미지 슬롯을 최대 하나만 남깁니다. 겹친 원형 바탕·원화·테두리 중 안쪽의 실제 내용 자리를 우선합니다.
- 작은 배지와 얇은 선 장식은 기본 표현에서 생략합니다. action 없는 겹친 이미지도 대표 슬롯으로 줄이고 떨어진 아이콘은 유지합니다.
- 원래 요소를 이동·삭제하거나 게임 자원을 바꾸지 않습니다. 계층·역할·기존 반응형 사각형으로 표시만 걸러내며 게임 이름·화면 이름·ID에 따른 예외를 만들지 않습니다.
- 실제 그림의 모든 겹침과 글자 내용을 살펴볼 때는 세부 와이어프레임을 사용합니다.

현중은 세부 단색 방향이 적당하다고 말씀하셨습니다. 이는 해당 표현 방향에 대한 피드백이며 전체 샘플의 원본 동등성이나 최종 시각 승인으로 확대하지 않습니다.

## 수정·미리보기·저장 확인
1. 상세 편집 또는 디자인 가이드의 미리보기는 현재 선택 화면 하나와 미저장 변경을 표시합니다. 프로젝트·화면·저장 여부를 확인합니다.
2. 모달 샘플도 선택 모달만 표시합니다. 뒤 페이지를 자동 합성하지 않습니다.
3. 파일에 저장한 다음 파일·공유의 저장 샘플 보기에서 저장판을 읽습니다. 화면 선택과 표현 메뉴로 모든 저장 화면을 볼 수 있습니다.
4. 게임 흐름·실제 모달 동작 검사는 편집 도구의 동작 시험을 별도로 사용합니다. 보기용 샘플을 위해 임시 게임 버튼이나 연결을 추가하지 않습니다.
5. 화면/자식 선택을 바꾸면 주소의 workspace·project·screen·element·view도 따라갑니다. 새로고침 뒤 같은 대상을 확인합니다. 미저장 이탈 경고를 승인 없이 우회하지 않습니다.

Undo/Redo 전면 버튼은 제거했고 기존 키보드/엔진 기록은 보존합니다. 전체 캔버스는 부품 편집기를 띄우지 않으며 실제 입력은 보드 하나에만 받습니다. 정적 그림을 만들 때 authored 정상/비활성 상태를 먼저 그린 다음 입력 처리를 해제하여 inert 때문에 모든 버튼이 비활성 그림으로 보이지 않게 합니다.
