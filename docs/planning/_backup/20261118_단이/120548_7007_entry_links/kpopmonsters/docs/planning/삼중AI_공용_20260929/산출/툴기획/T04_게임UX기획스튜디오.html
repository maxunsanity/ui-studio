1. 개요

간략

배치된 화면을 누르면 기능·연결·결과를 함께 확인하는 UX 기획 스튜디오를 만듭니다. 모바일 세로 게임을 먼저 지원하고 다른 게임의 화면과 데이터도 불러올 수 있는 구조로 잡습니다. 로비는 첫 검증 샘플입니다.

첫 제작 범위

첫 사용 가능한 판은 로비 + 연결 대상 화면 + 모달 + 성공/실패 안내 + 복귀입니다. 배치 조절만 되는 로비 한 장으로 첫 판을 완료 처리하지 않습니다. 샘플은 스튜디오 시험용이며 실제 게임의 로비 도입·경제·운영 정책을 확정하지 않습니다.

‘로비→상점→상품 상세→시험 결과→상점→로비’를 첫 수직 흐름으로 제안합니다. 상품/잔액/가격/응답은 명확하게 표시된 시험 데이터이며 실제 결제나 원표·게임 장부를 사용하지 않습니다. 선택 없음, 취소, 성공, 잔액 부족, 요청 실패를 각각 시험합니다. 로비/상점의 최종 구성과 자료 출처는1단계에서 최신 공개 원본에 맞추고 시험 제안을 표시합니다.

현중과 AI가 함께 쓰는 순서

화면/요소를 선택 → 필요한 변경을 말함 → 선택 ID·기기·상태·저장 버전·미저장 변경을 파일로 공유 → AI가 같은 정본을 읽음 → 변경 전후 비교 → 적용 → 저장·재열기 확인 순서입니다. 외부 AI에 자동 메시지를 보내는 기능으로 해석하지 않습니다. 오래된 수정안은 충돌을 표시하고 최신 사용자 변경을 덮어쓰지 않습니다.

첫 검증 흐름

로비에서 연결 요소 선택 → 관련 화면 열기 → 대상 선택 → 모달 열기 → 시험 조건 선택 → 성공/실패 안내 → 닫기 → 원래 화면의 선택·필터·스크롤 복원 순서입니다. 연결에 쓰는 실제 콘텐츠는 1단계에서 최신 공개 기획 원본을 대조해 명시하며, 원본이 없는 부분은 ‘시험용 제안’으로 표시합니다.

툴 탐색의 이전/다음과 게임 UX의 뒤로/닫기/취소를 구별합니다. 관계도를 열어도 현재 선택과 미저장 수정이 없어지지 않습니다.

4. 상세 기획

공통 설계 원본

화면·요소·동작·연결·상태·데이터 참조·시험 데이터·연출 프리셋·기기 프로필·출처·버전을 하나의 설계 JSON으로 연결합니다. 화면 미리보기, 설명표, 관계도, 저장/내보내기가 이 원본을 공유합니다. 그래프 배치 좌표와 실제 UI 좌표는 분리합니다.

요소는 고유 ID와 사람이 보는 이름/번호를 갖습니다. 표시 번호를 바꿔도 설명과 연결이 끊기지 않아야 합니다. 미정 조건은 미정으로 남고 시험에서도 확인 필요로 표시합니다.

단계별로 만들 결과와 통과 기준

단계만드는 것실제로 확인할 것단계가 끝나면 보여드릴 것
1. 설계·기술 검증설계 파일 구조, 로비 샘플 범위, 좌표·저장 방식, 검증용 최소 화면확대 상태의 끌기/중첩 부모 좌표, 저장→재열기 일치, 실패 시 원본 보존샘플 구성 목록·실제 저장 파일·기술 검증 결과. 결과에 따라 세부 방법 보정
2. 배치와 기능 설명왼쪽 화면/요소 목록, 중앙 편집, 오른쪽 설명, 이동/크기/정렬/간격·되돌리기요소↔설명 양방향 선택, 키보드 미세 이동, 원복, 저장 후 배치/설명 유지현중이 직접 위치·크기·설명을 바꿔 저장할 수 있는 판
3. 연결과 동작 시험연결 대상/조건/전달값/복귀 양식, 관계도, 상태 실행기, 시험 기록로비→연결 UI→모달→성공/실패/취소→복귀, 같은 화면 정보 변경, 다중 진입점첫 사용 가능한 UX 시뮬레이터. 버튼 선택 시 설명·선·대상 동시 강조
4. 공통 UI와 연출모달·토스트·스낵바·바텀시트·도움말, 공통 등장/퇴장, 용어집뒤 화면 입력/초점 처리, 중첩/연타/중단/재열기, 이벤트 하나로 여러 UI 변화공통 동작을 재사용하고 효과를 눌러 시험하는 판
5. 기기·보기 비교폰/폴드/태블릿 규칙, 와이어프레임↔그래픽, 동일 상태 비교넘침·잘림·터치영역·안전 영역·스크롤, 두 보기의 배치/상태/연출 시점 일치다른 기기와 그래픽 적용 전후를 비교하는 판
6. 협업·출력·범용 검증선택 정보 공유, AI 변경안 비교/적용, 기획서·연결표·JSON 출력, 두 번째 샘플버전 충돌 거부, 기획/설명/연결 출력 일치, 다른 콘텐츠에서도 같은 편집 기능 사용다른 AI/기획자에게 넘길 수 있는 설계 묶음과 사용법

서로 다른 단계라도 ‘저장·복원·오류 보존’은 처음부터 유지합니다. 첫 단계에서 실측한 결과 없이 제작 시간이나 라이브러리 성능을 확정하지 않습니다. 각 단계 완료 때 현중이 볼 수 있는 실행판과 남은 요구 목록을 함께 제출합니다. 요청 범위나 저장/연결 정책이 크게 바뀌면 기획서를 먼저 갱신하고 해당 변경을 확인받습니다.

연결과 상태

연결 종류는 화면 이동, 겹쳐 열기/닫기, 같은 화면 안 변화, 조건 분기, 외부/비동기 작업, 데이터/콘텐츠 관계입니다. 관계도는 ‘전체 주요 화면→선택 화면의 연결→선택 버튼의 분기’로 좁혀 보여줍니다. 행동과 결과를 선에 표기하며 선 색만으로 구별하지 않습니다. 도달 불가·대상 없음·복귀 미정·미연결 버튼을 목록으로 보여줍니다. 의도한 순환은 허용합니다.

동작은 입력 사건→조건→동작 종류→대상→전달값→결과→복귀 정책으로 작성합니다. 대기/성공/실패/취소/시간 초과는 구별하고, 실제 서버·결제 대신 시험 데이터를 사용합니다. 같은 화면의 탭/선택/패널도 상태 변경으로 표현합니다. 다중 화면 동시 표시(MR·키오스크)의 데이터 참조 가능성은 모델에 남기되 3D 편집 기능은 후속으로 둡니다.

배치와 반응형

부모 기준 위치/크기, 앵커, 고정/가변, 최소/최대, 여백/정렬, 줄바꿈, 넘침/스크롤, 안전 영역, 시각 크기와 터치 영역을 나눕니다. 실제 저장 좌표와 화면의 확대 표시를 구별합니다. 기기 프로필 치수는 시험 설정이며 제품 비율로 확정하지 않습니다. 비교 보기는 같은 설계와 시험 상태를 공유합니다.

공통 양식과 출현 연출

모달 여부는 뒤 UI의 입력 차단 동작이고, 바텀시트는 나타나는 형태입니다. 딤/스크림은 시각 레이어이며 입력 차단과 별개입니다. 도움말에 내부 조작이 필요한 경우 툴팁과 구별합니다. 토스트/스낵바는 자동 종료·행동 버튼·중복 대기열을 각각 정의합니다.

출현 연출은 트리거, 등장/유지/퇴장, 방향·이동·크기·투명도·곡선·시간, 순서/지연, 입력 허용, 소리, 동작 줄이기, 중단/재실행을 공통 프리셋으로 관리합니다. 닫힘→열리는 중→열림→닫히는 중 상태를 시험합니다. 연출 중 위치를 배치 저장값으로 덮어쓰지 않습니다. 미리보기 모달이 스튜디오의 오른쪽 편집 조작을 막지 않도록 범위를 한정합니다.

구현 위치와 기술 선택안
