## 실제 연결과 시연 경계
- 로비 시작 → 모험: 이번 현중 직접 지시 근거. 영상 자체에서 관찰한 입구라고 기록하지 않는다.
- 모험 중앙 진행 → 스킬 선택 → 각 카드 선택 후 모험. 실제 레벨 계산 대신 UI 시연이다. 각 스킬 효과·HP·레벨 계산을 창작하지 않는다.
- 모험 대박 → 신화 스킬 → 공통 닫기/복귀. 신화 닫기는 영상 끝까지 누르지 않은 공통 샘플 닫기다.
- 모험 중박 → 즉시 룰렛 → 닫기/복귀는 영상에서 관찰한 경로다.
- 설정·통계·새로고침의 결과·학습한 스킬의 목적지·뽑기 결과는 영상 밖이라 추가 페이지/결과/결제/확률을 만들지 않는다. 눌림 피드백과 목적지 구현을 구분한다.
- 동작 검수는 /ui-studio/preview.html?project=ux-gjs-4e64eb72&workspace=workspace-ac9e2a9e-65c0-4fe8-b67a-79a5a9ae42d7. 공통 .33/.34의 단독 sample-preview는 그림 한 장 검토용이며, 왕복 동작 검수를 대신하지 않는다.

## v001의 잘못과 v002 제작 기준
1. 대박을 천사 얼굴로 바꾼 것은 아이콘 의미부터 잘못이다. 대박=작은 슬롯 기계, 중박=금속 테두리/포인터를 가진 작은 룰렛으로 새로 그린다. 비슷한 색의 아무 그림으로 대체하지 않는다.
2. 스킬 선택 상단은 악어 없는 검 든 카피바라다. 로비/프로필의 악어 탄 그림을 재사용하지 않는다. 모험 스틸도 작은 카피바라·긴 낮은 악어·별도 초록 새와 넓은 빈 땅의 비율을 지킨다.
3. 본UI 아이콘을 단색 도형/폰트 상징으로 간단히 만든 시안을 완성 그림으로 내지 않는다. 검은 외곽→재질 앞면→밝은 베벨→안쪽 그림자→작은 효과를 실제 축소/확대에서 확인한다. 단순 프레임·배지·표준 기능 기호는 고해상도 코드 원화로 새로 그릴 수 있지만, 사물/캐릭터의 고유 실루엣을 생략하는 근거가 아니다.
4. 원본 캡처는 분석/새 그림의 시각 참조로만 사용한다. 원본 픽셀을 제품 assets에 잘라 붙이지 않는다. imagegen으로 새로 그린 authoring 원본은 assets/authoring/adventure/v002, production은 assets/production/adventure/v002, 역할/SHA/가공은 _작업/codex/adventure02/assets-v002.json에 남긴다. 그림 글자는 굽지 않고 native로 분리한다.
5. 하트의30%·강타의%는 원본 의미다. 임의 상승 화살표로 대체하지 않는다. 30%와%는 native 글자이며 스킬 그림과 함께 앞면 그룹에 둔다. 룰렛은 회복용 십자/불꽃 효과가 붙은 스킬 아이콘을 재사용하지 않고 전용 하트·검·방패로 구분한다.
6. 투명 파일 사각형과 그림 실루엣은 다르다. alpha32 경계+작은 여백으로 production을 정리하고 alpha의 작은 가장자리는 보존한다. 같은 wrapper 안에서 contain으로 비율을 유지한다. 그림의 빈 여백을 핑계로 버튼 wrapper를 화면별로 늘리지 않는다.
7. 슬롯 새 원화에 제목 리본이 포함됐으면 옛 리본을 겹치지 않는다. 중앙 띠/두 상단 홈/하단 받침에 글자와 아이콘을 새 그림 기준으로 정렬한다. 그림 자체를 캡처와 동일하다고 자칭하지 않는다.

## 공통 규격과 앵커
좌표계504×894. 스크린샷마다 다른 크기를 기준으로 삼지 않고 아래 family/variant를 native 수치와 앵커로 적용한다.
- 모험 장면504×410 / 스탯504×60 / 메시지폭488, 한줄높이74·두줄100. 두 메시지의 테두리 두께는 같은 규칙이며 높이만 다른 자원 variant다. 하단 바탕은 y410부터 화면 끝까지 세로 늘림.
- 모험 주 버튼 입력264×108, 고정 림264×108, 앞면264×100. 좌우 보너스 입력88×88/그림 슬롯76×72, 같은 부모·하단 앵커, 주 버튼보다 top+12. 제목은 앞면 그룹 안에 두어 함께 눌린다. 횟수는 별도 표시값이다.
- 스킬 카드3행472×114, y310/436/562, 간격12. 앞면472×110, 아이콘 프레임92×104/그림78×80, 같은 제목·설명·등급 슬롯. 새로고침200×64, 학습한스킬64×72.

## 눌림·정식 도구 조립
- 모든12새 버튼은 공통 pressFeedback 논리3px. 입력 루트와 고정 림은 고정, 앞면 그룹만 이동한다. 그림과 제목/기호도 앞면 자식이다. 상용 게임 동작/데이터 갱신은 구현하지 않는다.
- 작은 아이콘을 고정 림에도 그대로 복제하면 눌릴 때 두 그림이 겹친다. 슬롯/룰렛의 고정 밑판과 움직이는 그림을 분리한다. 원본에 별도 판이 없는 책 버튼은 고정 입력만 두고 보이는 중복 림을 숨긴다.
- 폴더/설계/그림 등록과 조립은 정식 native UI로만 한다. 외부 설계 JSON·숨은 모델 setter·비공개 저장 API를 사용하지 않는다. 스크립트는 새 원화 가공/파일 검증 및 허용된 UI 조작을 묶는 데만 쓴다.
- 공통 .34에서 편집 명령은 ‘편집 도구’ 안으로 이동했다. 옛 .edit-menu를 반복 시도하지 않고 새 UI를 읽어 _작업/codex/adventure02/native_ops_v34.mjs의 UI 조작으로 복제/정렬한다. 도구 소스를 샘플 전용으로 고치지 않는다.
- 1차의 HMR 반영 전 미저장0을 확인하고 묶음마다 정식 저장한다. HMR이 현재 화면을 되돌리면 선택/주소를 다시 확인하고 남은 단계만 수행한다.

## 검수와 증거
- 실제 로비 시작→모험→스킬 카드3개 선택/복귀, 대박·중박→닫기/Enter/Space/Escape, 초기 초점/ShiftTab/닫기 후 초점 복귀를 확인한다.
- Space hold에서 앞면/그림/글자의 이동과 림/입력 고정을 각각 실측하고 해제 후 원복을 확인한다. 설정값 검증과 실제 화면 실측을 구분한다. touch/outside cancel까지 확인하지 않았다면 미확인으로 적는다.
- CSS1440×900/430×843, native390×844에서 이미지 로딩·깨짐·바깥 넘침·부품 정렬을 확인한다. 캡처의 실제 픽셀과 CSS 크기를 구분한다. 브라우저 배율 변화 뒤 실제 innerWidth/innerHeight를 다시 읽는다.
- 팝업 전환 중의 캡처를 완성 화면으로 내지 않는다. opacity1의 안정 프레임을 캡처한다. 초기 실수/재검수 기록도 보존한다.
- 저장/내보내기2,000,000B·자원개별300,000B와 공식 readDesignFile을 확인한다. JSON 단독에는 그림 파일이 동봉되지 않으므로 프로젝트 ui-studio/assets를 함께 보존한다.
- 최신 결과/미확인/캡처/백업은 docs/collaboration/reports/20261118_adventure_new_pages.md. 7007은 보류, 공통 도구와 다른 샘플/전역 검수 포인터는 수정하지 않는다. 최종 판단은 현중이다.
