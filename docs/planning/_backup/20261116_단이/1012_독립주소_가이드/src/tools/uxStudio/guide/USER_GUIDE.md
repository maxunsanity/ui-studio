## 1. 시작과 프로젝트 구분
이 도구의 정본은 /Users/max/projest_max/ui-studio/입니다. 이 Mac에서는 7007 기획서 툴의 툴 기획 → T04 → UX 스튜디오 경로를 유지하며 /docs/planning/ux-studio.html에서 독립 도구의 소스·API를 연결합니다. 케이팝 자체는 기획서·시뮬레이터 프로젝트이며 실제 게임이 아닙니다. 케이팝의 옛 도구 소스는 보존본으로 둡니다.

상단 가이드에서 사용 설명서, 툴 기획, 제작 구조, AI 규칙과 미완료를 도구 안에서 읽습니다. 공통 안내는 독립 정본이고 선택 프로젝트 안내는 해당 ui-studio/guide/ 사본입니다. 가이드를 여닫아도 편집 문서나 저장 버전은 바뀌지 않습니다.

samples/monopoly-go/는 검증용 샘플 프로젝트입니다. 현재 샘플이나 가이드가 있다고 모노폴리 GO 게임 전체를 구현한 상태는 아닙니다. 별도 실행이 필요하면 독립 루트 README.md를 먼저 읽습니다. npm start는 scripts/start.mjs를 사용하며 이 Mac에서는 기존 Vite 5.4.21 설치를 재사용합니다.

게임 폴더는 네이티브 폴더 찾기로 직접 선택합니다. 폴더마다 ui-studio가 별도로 생기며, 설계·자원·가이드·연결 현황을 그 안에 보관합니다. 기존 ui-studio는 다시 엽니다. 기존 파일을 초기 상태로 덮어쓰는 작업이 아닙니다. 형식이 다른 기존 폴더나 안전하지 않은 경로는 거부할 수 있습니다.

폴더 프로젝트 ID(workspace ID)는 게임 폴더를 구분합니다. 설계 문서의 projectId는 한 폴더 안의 개별 설계를 구분하는 기존 필드명입니다. 서로 다른 폴더 안에 같은 설계 ID가 있어도 같은 문서가 아닙니다. 저장·재열기·소비 화면에서 폴더와 문서를 함께 확인하세요. 폴더 선택 전의 레거시 저장공간은 별도로 보존됩니다. 독립 정본의 기존 설계 저장 위치는 _작업/codex/ux-studio/projects/이며 케이팝의 보존본을 새 저장 정본으로 혼용하지 않습니다.

처음 선택한 폴더에서는 기존 UI를 변환·연결할지, 독립 UI로 작업할지, 취소할지 먼저 묻습니다. 폴더 열기 자체는 동의가 아닙니다. 변환·연결 요청은 AI에게 작업을 요청한 상태이며 자동 변환 완료가 아닙니다. 상세 규칙은 EXISTING_GAME.md를 읽으세요.

폴더 전환 중 미저장 수정이 있으면 저장 후 전환 / 수정 버리고 전환 / 취소 중 선택합니다. 저장 실패 시 원래 문서와 미저장 수정을 유지해야 합니다. 취소하면 현재 폴더와 문서에 남습니다.

## 2. 화면과 부품을 편집하기
기존 편집 화면에는 배치 편집과 동작 시험이 나뉘어 있습니다. 배치 편집에서 화면 목록으로 대상을 고르고 레이어 목록에서 요소와 부모를 확인합니다. 유닛 추가에서 필요한 UI를 넣습니다. 위치와 크기는 기본적으로 부모 영역 기준 %입니다. 확대율은 저장 좌표가 아닙니다.

요소를 선택해 기능·정보·표시글·배치·연결과 조건을 작성합니다. 드래그와 크기 손잡이로 배치를 바꾸고, 세부 입력칸으로 수치를 확인합니다. 복사·붙여넣기·복제·그룹·그룹 해제·정렬·되돌리기·다시하기를 사용합니다. 여러 요소 이동의 기준 부모를 확인하세요. 보호되거나 지원하지 않는 구조는 가져오기·저장 시 거부할 수 있습니다.

화면에는 page, modal, toast, sheet 종류가 있습니다. 왼쪽 화면 목록은 기본 페이지 중심입니다. 모달·바텀·탑 등은 공통 연출에서 현재 화면 위에 띄워 확인합니다. 미리보기만 한 연출은 저장되지 않습니다. 선택 버튼 동작에 지정해야 연결 설정에 남습니다.

기기 프로필은 세로폰 390×844, 폴드 690×844, 태블릿 768×1024, 짧은 폰 360×640을 제공합니다. 특정 프로필에서 보인다고 모든 기기의 완성 배치를 보장하지 않습니다. 실제 검수 크기를 따로 기록하세요.

## 3. 게임 UI 조립과 표시
전체 구성 아래 바탕·프레임·이미지·텍스트·배지 같은 부품을 둡니다. 구성 전체가 입력과 행동을 소유하고 자식 시각 부품은 부모 입력으로 전달할 수 있습니다. 전체를 고르는 편집 동작과 게임에서 버튼을 누르는 동작을 구분합니다.

구조 보기는 역할을 살피는 표시이고 게임 보기는 같은 설계의 실제 이미지 표현입니다. 두 개의 다른 설계를 만드는 기능이 아닙니다. 게임 보기라는 이름은 최종 게임이나 그래픽이 완성되었다는 뜻이 아닙니다.

UI 구조 설계에서 종류, 상태, 분할선, 고정 폭, 내용 여백과 반복을 확인합니다. 버튼의 3슬라이스와 판·창의 9슬라이스는 모서리와 테두리를 유지하면서 프레임을 늘리는 방식입니다. 기본/눌림/선택/비활성 상태는 미리보기로 비교합니다. 종류 안내 색만 보고 입력 가능 여부를 판단하지 않습니다.

일반 요소의 부품 분해는 명령으로 실행합니다. 기존 파일을 열었다는 이유만으로 모든 요소가 자동 변환되지는 않습니다. 현재 로비 UI 구조 적용 명령도 실제 게임 전체 UI 변환과는 별개입니다.

## 4. 입력과 행동 연결
입력 역할은 자체 동작 / 부모에 전달 / 표시 전용 / 입력 차단입니다. 입력 가능 여부, 사각형·타원 입력 범위와 시각 부품의 좌표는 별도 의미입니다. 배경이나 장식에 행동이 불필요하면 표시 전용으로 둡니다.

연결·조건에서는 출발 요소, click 이벤트, 조건, 행동, 대상과 전달값을 확인합니다. 행동은 화면 이동, 뒤로, 열기, 닫기, 선택, 필터, 구매 시험, 피드백, 모듈 요청을 지원합니다. 위에서부터 조건을 확인해 처음 참인 행동 하나를 실행합니다. 미정 조건은 실행을 멈춥니다. 미정 목적지나 수치를 확정값으로 꾸미지 마세요.

동작 시험에서 실제로 눌러 페이지 이동·모달 열기/닫기·복귀·입력 소유자를 확인합니다. 시험 잔액·상품·응답은 설계의 fixtures에 있는 시험 데이터입니다. 실제 재화나 게임 저장 파일을 바꾸는 동작이 아닙니다. 모듈 요청과 콘텐츠 슬롯도 게임 호스트가 연결해야 실제 게임 기능과 콘텐츠가 됩니다.

## 5. 이미지와 자원
직접 이미지 가져오기는 PNG/JPEG/WebP, 개별 300,000bytes 이하입니다. 모델 전체 설계 파일은 2,000,000bytes 이하로 가져옵니다. 이미지의 base64 문자열과 다른 설계 내용도 문서 크기에 포함됩니다. 이미지가 각각 제한 안이어도 전체 문서가 너무 커질 수 있습니다.

원본 영역이나 프레임 검사에는 1~4096px 원본 크기 제한이 있습니다. 그림의 분할선과 영역이 원본 범위 안인지 확인합니다. 배경 이미지 맞춤은 부모 기준 상·우·하·좌 px 여백을 사용합니다. fit의 contain/cover/fill은 자르는 방식과 늘리는 방식이 다릅니다.

임의 SVG나 외부 HTML을 직접 이미지로 가져오는 기능은 제공하지 않습니다. 도구가 제공하는 공통 프레임 자원과 사용자 래스터 가져오기를 구분합니다. 폴더의 assets는 독립 UI 자원 보관 위치이며, 모든 자원이 자동으로 게임 자산 서비스에 등록되는 것은 아닙니다.

## 6. 단계와 저장
편집기의 기준판 단계 W는 와이어프레임, P는 프로토타입, U는 완성 UI라는 이름입니다. 이 W/P/U 저장 기능과 대표 결과의 W/P/U/S 단계 종합검수는 구분합니다. S의 세부 기준을 이 안내에서 임의로 만들지 않습니다. 단계 이름만 고르거나 기준판을 저장했다고 완성 판정을 내리지 않습니다. 현재 종합검수는 0/4입니다.

이어받은 대표 저장본 기준은 ux-gjs-61ad2d1f r14, 3개 page·1개 modal·24개 부품·6개 연결입니다. 현재 UI·그래픽·전체 샘플은 미완료이며 이 숫자는 실제 게임 전체 구현이나 자동변환의 완료를 뜻하지 않습니다.

파일에 저장은 현재 설계를 서버 저장공간에 기록하고 재읽기를 확인하는 기존 기능입니다. r14 같은 revision은 저장 버전입니다. 다른 창이 먼저 저장한 버전과 충돌하면 덮어쓰기를 거부합니다. 오류 메시지를 읽고 현재 수정을 보존하세요.

파일 · 공유에서 저장한 설계 선택과 현재 파일 다시 열기를 사용합니다. 설계 JSON 가져오기는 편집 문서를 바꾸며 저장과는 별개입니다. 내보내기는 JSON 사본을 받는 기능입니다. 저장 UI 함께 보기는 저장본을 소비 렌더러에서 엽니다. 편집 중 미저장 내용이 자동으로 반영되었다고 생각하지 마세요.

제작 단계 기준판은 먼저 현재 수정을 저장한 뒤 W/P/U와 revision을 붙여 보존합니다. 기준판을 불러오는 것은 편집 화면에 내용을 가져오는 동작이며 자동 덮어쓰기가 아닙니다. 확인 후 저장합니다. 저장 백업과 기준판은 목적이 다릅니다.

GrapesJS 시험 편집기는 별도 경로입니다. 단계 저장은 브라우저 localStorage에 저장하는 시험 기능이고, 사본 저장은 새 설계 ID로 서버에 저장하는 기능입니다. 공용 편집기의 파일 저장·기준판과 혼동하지 마세요. W/P/U라는 이름이 같아도 저장 위치가 다릅니다.

## 7. 다시 열고 확인하기
같은 게임 폴더를 선택한 뒤 올바른 설계 문서와 revision을 확인합니다. 다른 폴더의 최근 문서나 같은 이름의 설계와 혼동하지 않습니다. 저장 후 다시 열기와 저장 UI 함께 보기에서 화면·부품·연결이 유지되는지 확인합니다.

확인할 항목: 화면 이동, 팝업 닫기와 복귀, 입력 영역, 장식의 입력 제외, 이미지 누락, 긴 글, 스크롤, 모바일 넘침, 저장 충돌과 재열기입니다. 데스크톱 1440과 모바일 430px, 폰 논리 390×844의 실제 검수 범위를 기록합니다. 소스 검사·자동 시험·실제 화면 확인을 서로 대신했다고 적지 않습니다.

앵커·피벗·레이아웃 그룹·마스크·자동 게임 연결·완성 게임 그래픽·전체 샘플 완성은 현재 제공 범위를 넘어서는 항목입니다. 남은 작업은 PROGRESS.md를 확인하세요.
