## 부품 디자인 가이드에서 직접 편집하기 · .9

현재 사용자 정정을 보존한 요구·사용 원리입니다. 직접 편집 구현과 실제 브라우저 검수는 대표 본체에서 진행 중입니다. 아래 순서를 적은 사실만으로 구현 완료·화면 통과·UI 승인을 뜻하지 않습니다. 문서 설명서 가이드(openManual)는 읽기 전용이고, 부품 디자인 가이드는 실제 설계를 편집하는 화면입니다.

1. 전체 캔버스나 상세 편집에서 실제 부품을 선택해 디자인 가이드를 엽니다. 부모 경로와 직접 자식에서 선택을 바꿔도 같은 screen/element ID와 parentId를 이어 사용합니다. 별도 설계 복제본을 만드는 동작이 아닙니다.
2. 선택 부품을 중심에 맞춰 실제 그림을 봅니다. 모든 후손의 빨간 선·숫자를 기본으로 덮지 않고 치수는 선택 영역 바깥에서 읽습니다. 하위 선 켜기/끄기로 필요한 경계를 비교합니다. 선택·확대·보조선 표시만으로 설계의 미저장 수정이 생기지 않아야 합니다.
3. 선택 부품의 경계 선을 움직이거나 위치·크기 값을 고쳐 실제 부품을 편집합니다. 적용한 변화는 같은 부품의 실제 설계와 미저장 상태에 반영되고 되돌리기/다시하기로 복구되어야 합니다. 치수 보조선이나 가이드 내부 사본만 바뀐 상태를 편집 완료로 보지 않습니다. 부모 %·논리 px·확대율을 구분하며 앵커·안전 영역·자동 배치의 기존 제약을 유지합니다. 지원하지 않는 변환은 이유를 표시해야 합니다.
4. 이미지 넣기는 해당 workspace의 검증된 자원을 그 부품에 연결합니다. 이미지 빼기는 그 부품의 표시 이미지 참조만 해제합니다. 부품의 ID·부모·배치·나머지 속성이나 원자원 파일을 삭제하지 않고, 같은 자원을 쓰는 다른 부품에도 영향을 주지 않아야 합니다. 되돌리기로 연결을 복구할 수 있어야 합니다.
5. 가이드를 닫아도 적용한 설계 수정은 편집기에 남아야 합니다. 실제 설계를 되돌리기/다시하기한 뒤 현재 경로의 파일 저장 또는 사본 저장을 수행하고, 같은 workspace·설계 ID/revision·부품 ID를 확인해 다시 엽니다. 브라우저 단계 저장은 파일 저장과 다릅니다. 실제 검수 여부는 본체 기록을 따릅니다.

계층 행의 이름·아이콘·빈 공간은 그 행의 실제 부품 선택으로 연결합니다. 펼침/접기는 독립 조작이므로 부모나 다른 행을 잘못 선택하거나 수정하지 않아야 합니다. 캔버스·속성 패널·가이드가 같은 부품을 선택했는지 확인합니다. 레이어·중앙 캔버스·속성 세 영역은 두 경계를 끌어 폭을 조절합니다. 이 조절은 도구 보기 설정이며 부품 좌표·설계 revision·미저장 상태를 바꾸지 않아야 합니다.

관찰 근거는 `_작업/codex/ux-studio/20261116-board-measurements/independent-measurements.json`과 같은 폴더의 `notes.md`입니다. 원본 551×984px의 상위 25개/세부 포함 67개 측정 박스에 원본 px·중심·W/H 비율을 기록했습니다. 이는 관찰 자료 수이며 설계 부품 수나 검수 통과 수가 아닙니다. 고대비 잉크·실색은 대체로 ±1px, 그림 외곽·가림은 ±2px이고 숨은 경계는 미확인입니다. 글자 가시 bbox·잉크 높이를 실제 원본 font-family/size/weight/line-height로 확정하지 않습니다. x/w는 W=551, y/h는 H=984로 나눕니다.

.8의 전체 화면 Slot_3D/별도 2D overlay·Img_SNSAvatar와 명시 컨펌 이후 승인 기록 원칙은 유지합니다. 현재 화면/버전의 명시 컨펌 전에는 승인 스냅샷을 만들지 않습니다. 프로젝트 guide .4 사본은 보존합니다.

게임 폴더는 네이티브 폴더 찾기로 직접 선택합니다. 폴더마다 ui-studio가 별도로 생기며, 설계·자원·가이드·연결 현황을 그 안에 보관합니다. 기존 ui-studio는 다시 엽니다. 기존 파일을 초기 상태로 덮어쓰는 작업이 아닙니다. 형식이 다른 기존 폴더나 안전하지 않은 경로는 거부할 수 있습니다.

폴더 프로젝트 ID(workspace ID)는 게임 폴더를 구분합니다. 설계 문서의 projectId는 한 폴더 안의 개별 설계를 구분하는 기존 필드명입니다. 서로 다른 폴더 안에 같은 설계 ID가 있어도 같은 문서가 아닙니다. 저장·재열기·소비 화면에서 폴더와 문서를 함께 확인하세요. 폴더 선택 전의 레거시 저장공간은 별도로 보존됩니다. 독립 정본의 기존 설계 저장 위치는 _작업/codex/ux-studio/projects/입니다. 이관 출처에 남은 옛 저장 데이터와 혼용하지 않습니다. 주소의 /ui-studio/는 도구 입구이며 게임 폴더의 workspace ID가 아닙니다. 주소가 바뀌었다는 이유로 설계가 새로 만들어지거나 다른 게임으로 이동하지 않습니다.

폴더 전환 중 미저장 수정이 있으면 저장 후 전환 / 수정 버리고 전환 / 취소 중 선택합니다. 저장 실패 시 원래 문서와 미저장 수정을 유지해야 합니다. 취소하면 현재 폴더와 문서에 남습니다.

## 2. 화면과 부품을 편집하기
전체 캔버스에서 화면·레이어를 한 작업공간에 펼쳐 보고 확대·손 이동·화면 맞춤과 부품 선택을 사용합니다. 상단에서 프로젝트 종류·이름·실제 경로, 설계 이름·revision·미저장 상태를 확인합니다. 선택 부품 상세 편집을 누르면 같은 workspace·설계·화면·요소를 이어 엽니다. 미저장 변경은 사본 저장 후 이동 / 수정 버리고 이동 / 계속 편집으로 처리합니다.

상세 편집에는 배치 편집과 동작 시험이 나뉘어 있습니다. 배치 편집에서 화면 목록으로 대상을 고르고 레이어 목록에서 요소와 부모를 확인합니다. 유닛 추가에서 필요한 UI를 넣습니다. 위치와 크기는 기본적으로 부모 영역 기준 %입니다. 확대율은 저장 좌표가 아닙니다.

요소를 선택해 기능·정보·표시글·배치·연결과 조건을 작성합니다. 드래그와 크기 손잡이로 배치를 바꾸고, 세부 입력칸으로 수치를 확인합니다. 복사·붙여넣기·복제·그룹·그룹 해제·정렬·되돌리기·다시하기를 사용합니다. 여러 요소 이동의 기준 부모를 확인하세요. 보호되거나 지원하지 않는 구조는 가져오기·저장 시 거부할 수 있습니다.

화면에는 page, modal, toast, sheet 종류가 있습니다. 왼쪽 화면 목록은 기본 페이지 중심입니다. 모달·바텀·탑 등은 공통 연출에서 현재 화면 위에 띄워 확인합니다. 미리보기만 한 연출은 저장되지 않습니다. 선택 버튼 동작에 지정해야 연결 설정에 남습니다.

기기 프로필은 세로폰 390×844, 폴드 690×844, 태블릿 768×1024, 짧은 폰 360×640을 제공합니다. 특정 프로필에서 보인다고 모든 기기의 완성 배치를 보장하지 않습니다. 실제 검수 크기를 따로 기록하세요.

## 3. 게임 UI 조립과 표시
전체 구성 아래 바탕·프레임·이미지·텍스트·배지 같은 부품을 둡니다. 구성 전체가 입력과 행동을 소유하고 자식 시각 부품은 부모 입력으로 전달할 수 있습니다. 전체를 고르는 편집 동작과 게임에서 버튼을 누르는 동작을 구분합니다.

구조 보기는 역할을 살피는 표시이고 게임 보기는 같은 설계의 실제 이미지 표현입니다. 두 개의 다른 설계를 만드는 기능이 아닙니다. 게임 보기라는 이름은 최종 게임이나 그래픽이 완성되었다는 뜻이 아닙니다.

UI 구조 설계에서 종류, 상태, 분할선, 고정 폭, 내용 여백과 반복을 확인합니다. 버튼의 3슬라이스와 판·창의 9슬라이스는 모서리와 테두리를 유지하면서 프레임을 늘리는 방식입니다. 기본/가리킴·키보드 초점(highlighted)/눌림/선택/비활성 상태는 미리보기로 비교하고 현재 상태의 프레임 이미지 교체로 각각 지정합니다. 동작 시험·소비 미리보기에서 포인터·초점·누름·선택·비활성 상태에 맞춰 표현합니다. 종류 안내 색만 보고 입력 가능 여부를 판단하지 않습니다.

일반 요소의 부품 분해는 명령으로 실행합니다. 기존 파일을 열었다는 이유만으로 모든 요소가 자동 변환되지는 않습니다. 현재 로비 UI 구조 적용 명령도 실제 게임 전체 UI 변환과는 별개입니다.

## 4. 입력과 행동 연결
입력 역할은 자체 동작 / 부모에 전달 / 표시 전용 / 입력 차단입니다. 입력 가능 여부, 사각형·타원 입력 범위와 시각 부품의 좌표는 별도 의미입니다. 배경이나 장식에 행동이 불필요하면 표시 전용으로 둡니다.

연결·조건에서는 출발 요소, click 이벤트, 조건, 행동, 대상과 전달값을 확인합니다. 행동은 화면 이동, 뒤로, 열기, 닫기, 선택, 필터, 구매 시험, 피드백, 모듈 요청을 지원합니다. 위에서부터 조건을 확인해 처음 참인 행동 하나를 실행합니다. 미정 조건은 실행을 멈춥니다. 미정 목적지나 수치를 확정값으로 꾸미지 마세요.

동작 시험에서 실제로 눌러 페이지 이동·모달 열기/닫기·복귀·입력 소유자를 확인합니다. 시험 잔액·상품·응답은 설계의 fixtures에 있는 시험 데이터입니다. 실제 재화나 게임 저장 파일을 바꾸는 동작이 아닙니다. 모듈 요청과 콘텐츠 슬롯도 게임 호스트가 연결해야 실제 게임 기능과 콘텐츠가 됩니다.

## 5. 이미지와 자원
직접 이미지 가져오기는 PNG/JPEG/WebP, 개별 300,000bytes 이하, 원본 가로/세로 1~4096px입니다. 새 이미지는 선택 workspace의 assets/에 sha256 내용 해시 이름으로 저장하고 설계는 assetRef를 참조합니다. 이미지 목록 새로 읽기와 저장된 이미지 재사용으로 같은 폴더의 자원을 다시 고릅니다. 이미지와 현재 상태의 프레임 이미지가 같은 파일 계약을 사용합니다. 기존 설계의 내장 data URI는 계속 읽습니다.

모델 전체 설계 파일은 2,000,000bytes 이하로 가져옵니다. 기존 base64 이미지와 다른 설계 내용도 문서 크기에 포함됩니다. 자원 참조로 옮겼다고 설계 제한이 사라지지는 않습니다. 파일 내용·MIME·원본 크기·내용 해시·workspace 범위와 참조 존재를 검사합니다.

원본 영역이나 프레임 검사에는 1~4096px 원본 크기 제한이 있습니다. 그림의 분할선과 영역이 원본 범위 안인지 확인합니다. 배경 이미지 맞춤은 부모 기준 상·우·하·좌 px 여백을 사용합니다. fit의 contain/cover/fill은 자르는 방식과 늘리는 방식이 다릅니다.

## 5-1. 실제 컨트롤 사용

## 5-2. 안전 영역·앵커·자동 배치·스크롤
상세 편집의 응답형 배치 · 안전 영역에서 화면의 위·오른쪽·아래·왼쪽 안전 여백과 부품의 기준을 정합니다. 실제 새 배치를 적용할 때만 schemaVersion 4와 각 화면 logicalSize를 저장합니다. 창을 열기만 하면 기존 1/2/3 설계를 바꾸지 않습니다. 논리 크기와 검수 기기 크기를 구분합니다.

안전 영역 기준은 화면 직속 부품에만 적용합니다. 앵커는 모서리·가운데 고정, 가로/세로 늘림과 직접 min/max/pivot/position/sizeDelta 편집을 지원합니다. min/max/pivot은 0~1, 위치·크기 차이는 논리 px이며 Y 앵커는 아래에서 위로 증가합니다. 앵커와 부모 맞춤 inset은 함께 쓰지 않습니다.

컨테이너 자식 자동 배치는 가로·세로·고정 열 그리드입니다. 문서의 직속 자식 순서, 고정 itemSize 너비/높이, 간격·내부 여백·열 수를 사용합니다. 자식 위치·크기는 부모가 정하므로 자식 앵커·inset·safe area와 혼합하지 않습니다. 기존 layout.direction만 있는 설계는 새 자동 배치로 활성화하지 않습니다.

영역 넘침은 표시/자르기/가로/세로/양방향 스크롤을 제공합니다. 같은 DOM 영역이 그림과 입력을 함께 자릅니다. 회전·3D·모든 엔진의 LayoutGroup/Mask·Figma 동등 호환을 제공하는 기능은 아닙니다.

편집기의 기준판 단계 W는 와이어프레임, P는 프로토타입, U는 완성 UI라는 이름입니다. 이 W/P/U 저장 기능과 대표 결과의 W/P/U/S 단계 종합검수는 구분합니다. S의 세부 기준을 이 안내에서 임의로 만들지 않습니다. 단계 이름만 고르거나 기준판을 저장했다고 완성 판정을 내리지 않습니다. 현재 종합검수는 0/4입니다.
