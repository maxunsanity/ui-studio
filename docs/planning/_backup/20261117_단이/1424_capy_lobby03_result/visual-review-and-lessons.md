# 확대 비교·실수 예방 실행 가이드
작성 codex(단이·2차) · 제안(검수 대기)

현중 직접 지시: “색상이 같다고 그냥 넘어가지 말고 확대해서 차이점을 살펴보고 만들어야 돼”, “실수한것들도 전부 가이드에 넣어서 다시는 실수 하지 않게 하고”. 아래는 실제 발생한 누락/실패와 재발 방지 절차다. 문서 작성이 오류 제거나 전체 제작 완료를 보증하지 않으므로 작업마다 검수한다.

## 그림을 만들기 전에 하는 확대 검수

1. 원본 전체 화면에서 상단·하단·메시지 바·팝업·배지·선택 상태를 목록화한다. 작은 띠/보조 영역도 독립 역할인지 확인한다.
2. 원본과 저장 미리보기의 같은 영역을 200~300%로 확대한다. 실제 원본 픽셀과 보간 확대를 구분한다. 분석용 크롭은 reference 증거에만 두며 제작 자원으로 쓰지 않는다.
3. 색 이름만 비교하지 않는다. 외곽 실루엣, 이중 테두리, 테두리 두께, 내측 림, 윗면 하이라이트, 아래쪽 음영, 모서리 반경, 투명 구멍/외곽, 아이콘 원 비율, 글자 외곽선/기준선, 배지, 선택/기본 변형을 각각 대조한다.
4. 공통 토큰은 wrapper·입력·아트 슬롯·폰트·간격·앵커를 고정한다. 밑판/프레임 디테일을 생략하는 근거가 아니다. screenshot별 크기 변동을 따라 같은 family의 wrapper를 바꾸지 않는다.
5. 그림·입력·바탕·프레임·글자·효과를 나눈다. 선택 상태는 같은 크기의 variant로 둔다. 장면/캐릭터도 새로 그리며 영상 픽셀을 제품에 재사용하지 않는다.

## 실제 실수·원인·예방 절차

|---|---|---|
|로비 상하단이 검은 띠처럼 보임|공통 위치 확인용 단색 바를 디테일 제작으로 이어가지 못함|구조 초안과 미술 완성을 구분. 각 버튼 밑판/선택 상태, 재화 캡슐/프로필 프레임을 별도 제작하고 확대 대조. r5/r9는 최종 미술 기준이 아님.|
|하단 메뉴 위 메시지 바 누락|하단 영역을 메뉴 하나로만 분류|메시지 바를 별도 family로 목록/토큰/부품에 추가. 실제 문구·동작이 미관찰이면 임의 내용/기능을 만들지 않음.|
|같은 색이라 구조 차이를 놓침|작은 전체 화면만 보고 색상 계열로 판단|색·실루엣·테두리·내측 명암·하이라이트·모서리·선택/배지 상태를 독립 검사항목으로 비교.|
|새 버튼 생성이 안 됐는데 기존 생존일 글자를 잘못 수정|다른 viewport/팬 위치의 옛 좌표로 drag, 기존 active ID를 새 ID로 오인|추가 전 ID 집합/현재 CSS canvas bounds를 읽고, 추가 후 새 ID·kind·부모가 확인될 때만 이름/속성을 변경. 변화 없으면 즉시 중단. 이번 기존 글자는 native로 원래 이름/문구/rect/폰트 복구.|
|reload로 잘못된 수정이 사라질 것이라 예상|브라우저 draft가 다시 유지됨|reload를 복구 보장으로 쓰지 않음. 저장본·미저장 표시·ID/문구/rect를 직접 대조, native Undo 또는 정확한 속성 복구 후 재저장 확인.|
|AX 수치 필드가 두 개로 잡힘|전체 AX 끝의 focused-element 설명까지 검색|숫자 인덱스로 시작하는 실제 control 행만 검색하고 label/종류를 정확히 대조. 1개가 아니면 입력하지 않음.|
|글자 패널을 열었는데 다음 필드가 없음|속성 변경 후 비동기 재표시가 details를 닫음|입력→Tab→새 AX 확인. 닫힌 실제 패널을 다시 연 뒤 새 인덱스로 입력. 이전 인덱스/열림 상태를 재사용하지 않음.|
|summary가 AX에서는 button인데 Playwright role=button으로 못 찾음|DOM details/summary와 AX 역할 차이|새 DOM의 실제 details class와 summary를 확인해 클릭. 임의 selector나 좌표 반복 금지.|
|배지 이미지 아래로 글자를 재부모화하려다 실패|현재 부모 메뉴가 badge 역할 이미지를 부모 후보로 제공하지 않음|부모 옵션을 실제 확인. 이번에는 배지 그림과 글자를 같은 Btn_Nav_* 소유의 동일28px 영역에 두어 별도 분리. 지원되지 않는 계층을 외부 JSON으로 강제하지 않음.|
|복제 후 부모·좌표·이미지 맞춤을 그대로 가정|복제는 부모 누락/상대좌표·기존 맞춤을 유지할 수 있음|새 ID와 실제 parentId, 부모 크기, local/global rect, fit을 확인. 그림은 contain, 의도된 밑판 늘림/슬라이스는 명시.|
|상하단을 legacy % 위치만으로 배치하면 긴 폰에서 상대 간격이 달라짐|전체 높이 비율 배치와 고정 논리 크기/하단 앵커 혼동|메시지 바/시작 버튼은 아래 고정, 제목/목록은 위 고정. 390/430 기기 보기에서 메시지 바와 nav 접합/시작 간격을 실측. 실제 안전영역 지원 확인은 별도.|
|길어진 UI batch가30초 제한에 걸려 세션 초기화|여러 복제/편집을 한 호출에 묶음|작은 단위로 저장. 시간 초과 후 실제 UI의 생성 ID와 저장 revision부터 읽고 남은 작업만 수행. 전체 batch 재실행으로 중복 생성 금지.|
|file chooser 성공 반환인데 기본 이미지/등록SHA0 유지|호출 성공과 실제 등록/설계 참조를 혼동|반환→프로젝트 파일→등록 assetRef/SHA→저장 재읽기→실제 img.complete/naturalSize를 별도 확인. 허용된 프로젝트 이미지 경로+AX/Tab으로 성공했음.|
|shape 바 양끝에 가는 빈틈|SVG shape의 x=1/width98% 인셋|새 단색 자원으로 해결한 초기 이력. 디테일 판에서는 별도 새 밑판 자원 사용. wrapper만 확대해 보정하지 않음.|
|Swift 메타 읽기 성공을 프레임 성공으로 볼 위험|AVAssetImageGenerator는 모든 프레임 디코딩 실패|디코더 인수 문서의 검증된 ffmpeg 경로/원본 시각을 사용. metadata/추출/파일/시각검사를 구분.|
|캡처 크기/기기 프로필을 실제 CSS viewport로 보고할 위험|파일 픽셀·브라우저 CSS·폰 논리 크기가 서로 다름|세 값을 기록. 390/430 기기 프로필만 봤다면 CSS430 실제 화면 검수라고 적지 않음.|
|제작 순서 변경 중 빈 프로필 화면이 남을 위험|로비 디테일 지시 전에 프로필 page→modal만 준비|사용자 로비 수정 우선으로 native Undo해 빈 화면 제거. 생성 캐릭터 원화는 보존하되 적용/연결 완료로 세지 않음.|

## 저장 전 필수 점검

- [ ] 새 ID/기존 ID와 부모·연결 보존, 변경 대상 정확성
- [ ] 공통 wrapper/내부 슬롯/폰트/배지/간격·앵커 일치
- [ ] 전체 화면과 원본/미리보기 200~300% 확대 비교
- [ ] 어두운 색이라도 테두리/내측 명암/선택 상태/누락 영역 대조
- [ ] 원화·production·등록SHA·저장 참조·실제 이미지 로딩 확인
- [ ] 데스크톱/모바일 CSS와 기기 보기의 넘침·기준선·입력, 캡처 픽셀 기록
- [ ] 실제 연결/닫기/복귀 확인 범위와 미구현 목적지 구분
- [ ] 이번 실패와 복구/미확인·다음 작업을 같은 보고에 추가

상태를 “파일 준비 / native 적용 / 저장 재읽기 / 확대 시각 검수 / 기기 검수 / 연결 시험 / 사용자 검수 대기”로 나눠 기록한다. 색상이 유사하거나 정적 검사가 통과했다는 이유로 미술/동작 검수를 생략하지 않는다.

이 판의 시작 버튼은 native tint 앞면만 normal1→pressed0.741→release hover0.949→blur normal1, 고정 림 filter none을 실제 확인했습니다. 이 검증은 이동 구현·실제 전투 진입·모든 화면 연결 성공을 뜻하지 않습니다. 1차의 전체 시험 수는 1차 보고이며 2차에서 재실행한 수가 아닙니다.
