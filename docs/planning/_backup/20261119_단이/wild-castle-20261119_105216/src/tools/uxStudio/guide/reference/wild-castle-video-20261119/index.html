# 와일드 캐슬 독립 UI 샘플 제작 가이드

codex(단이·2차) · 2026-11-19 10:27 KST · 제안(검수 대기)

## 시작 원본과 범위
공식명: 와일드 캐슬 TD - 왕국 건설 타워 디펜스 / Wild Castle: Tower Defense TD, Funovus. 공식 확인: https://play.google.com/store/apps/details?hl=ko&id=com.wildsky.wildcastle 및 https://www.funovus.com/games/wild-castle/ . 제목 화면이 없는 영상의 HUD·캐릭터·전투 구성을 공식 자료와 대조했다. 영상46.43초·1080×2340·30fps. 전체2fps93샘플,4접촉시트,장면후보33개를 확인했다. 캡처 시각은 추출 요청 초이며 정확한 원본PTS 검증값으로 표현하지 않는다. 원본 SHA972593cc74bffd99dc31c7a76801302ea39efd2a1a1183cc2f9be72b99fad6a3.

현중 추가 지시: “하단에 하나 비워져 있는데.. 고렙 되면 조금씩 달라지긴 하네..참고해서 개선해”. 추가 첨부는 WC07로 보존했다. 마을 버튼 자리와 고레벨의 다른 HUD·거래·주변 메뉴·영웅8칸을 반영한다. 해금 레벨이나 내부 화면은 추정하지 않는다.

## 그대로 이어 만드는 순서
1. 루트 AGENTS.md와 ui-studio/AGENTS.md, 현재 guide .39 및 실제 프로젝트 metadata를 읽는다. 현재 직접 요청과 과거 작업 기록을 구분한다.
2. reference 원본 전체 접촉시트→안정된 대표 프레임→확대한 UI 순서로 본다. 검은 녹화 여백은 UI에 넣지 않는다. 캡처를 제작 자원으로 가져오지 않는다.
3. sample-reference-data.json의 KingShot r129 실제 스크롤/눌림 부품과 Royal r194 실제 프로필 계층을 참고한다. 다른 샘플의 좌표나 그림을 그대로 복사하지 않는다.
4. 독립 샘플 wild-castle, workspace workspace-279f493b-a942-4f5a-b176-d042ea9960f2, project ux-957138c6를 7018 실제 Studio UI로 연다. 설계 JSON은 외부에서 쓰거나 API/콘솔로 조립하지 않는다. 파일은 읽기 전용 감사에만 사용한다.
5. 같은 판틀을 먼저 묶는다. 영상 대표6상태+첨부 고레벨 로비1상태, 독립 판틀5종이다. 상점 스크롤의6섹션은 한 페이지이며 고레벨도 로비의 상태 차이이다.
6. ui-tokens.json의 논리390×780과 공통 HUD66/하단60을 사용한다. 하단 입력 영역은 상점80·마을80·리플레이80·전투98, 간격4px이다. 상태가 달라도 공통 항목 위치를 스크린샷 크기로 다시 정하지 않는다.
7. 게임 필드는 새로 그린 정지 그림만 사용한다. 나머지 텍스트·가격·수량·판·아이콘·스크롤·입력은 native 부품으로 분리한다. source 캡처와 freshly generated atlas는 완전히 구분한다. 생성 atlas의 새 그림 셀 분리는 가능하나 원본 게임 캡처를 잘라 붙이지 않는다.
8. 아이콘 묶음을 만들 때 프레임/그림/글자/입력 전체의 역할을 확인한다. 붙여넣기 뒤 부모·로컬좌표·연결을 실제 UI에서 재확인한다. 전체 카드가 입력 영역이며 가격 글자만 작은 버튼으로 만들지 않는다.
9. normal/pressed는 같은 캔버스로 만들고 입력 영역은 고정한다. 로비 버튼은 새 그림 상태쌍과 글자2px 이동, 고레벨 캐슬/궁수/거래는 제목·비용·레벨/아이콘 앞면 그룹을 지정한다. 고정 림/배지는 앞면과 분리한다.
10. 영상에 실제 나온 이동만 우선 연결한다. 상점/전투의 복귀는 native “이전 화면”으로 하여 고레벨에서 열었으면 고레벨로 돌아온다. 가짜 레벨업·결제·해금·게임 정책은 만들지 않는다.
11. 영상 저레벨과 첨부 고레벨은 상태 선택/개별 화면 미리보기로 비교한다. 레벨에 따라 자동 해금되는 기능을 구현했다고 표현하지 않는다. 마을/거래/주변 메뉴는 내부 자료가 없어 눌림만 제공한다.
12. 실제 동작 시험·390×780과 기기/뷰포트 검수·저장 재읽기·이미지404·자원SHA·W/P/U·내보내기를 구분해서 증거를 남긴다. 검수하지 않은 항목은 완료로 쓰지 않는다.

## 현재 작동 범위와 한계
- 7개 native 화면, 상점 일반상품27개+광고제거 배너1개, 재능12타일, 프로필9초상, 고레벨8영웅 슬롯. 새 bitmap/geometry 121역할, 최대 287,164B. 엔진 원본 그림을 쓴 것이 아니다.
- 실제 버튼 이동/팝업 닫기/세로 스크롤과 누름 피드백을 시험한다. 상품/재능/초상 등 미관찰 내부 동작은 누름만 한다.
- 상단 선택 탭은 native 선택 표시다. 스크롤 위치 추적·해당 섹션 직접 점프는 구현하지 않았다. 획득하기→상점은 현재 패키지 시작 위치로 열려 영상의 골드 직접 진입과 다르다.
- 재능을 바꿔 다른 설명을 보여주거나 초상 선택을 실제 프로필에 반영하는 동작은 미구현이다. 기본 쿨타임 선택/기본 여우 선택 표시를 유지한다.
- 모달 자체 engine dim은 끄고 재능/프로필의 자체 dim만 쓴다. 골드 부족 안내는 dim 없이 띄운다.
- 모든 값은 sample-data.json의 관찰 표시값이다. 실제 잔액·쿨타임·성장 규칙은 구현하지 않았다. 게임 필드 새 그림의 캐릭터/비율/세부 디자인은 해석 시안이며 원본과 시각 동일 판정은 받지 않았다.
- 일부 상점 상세 장식·추가증정 배지·원본 폰트/텍스처의 정밀 동등성은 추가 검수 대상이다. 기능 조립과 아트 동일성 승인을 구분한다.

## 확인된 실수와 재발 방지
- 하단 빈칸을 단순 여백으로 확정하지 않는다. 이번 추가 자료에서 마을이 확인됐다. 같은 게임도 레벨/진행에 따라 HUD·주변 메뉴·성벽·슬롯이 달라질 수 있으므로 공통 틀+관찰 상태를 따로 기록한다.
- 비슷한 색이라고 같은 판으로 간주하지 않는다. 선택 프레임, 그림자 깊이, 헤더/메시지 위치와 모서리를 확대 대조한다. 검은 백판 일부만 있는 현상도 영역/부모/클립/전체 배경을 나눠 확인한다.
- 빈 글자를 입력할 때 선택만 하고 빈 문자열을 타이핑하면 이전 글자가 남을 수 있다. 실제 Backspace→Tab 후 저장/미리보기로 확인한다. 복제된 ×와 “뒤로” 잔여를 이번에 수정했다.
- 네이티브 이미지가 달린 부품을 곧장 “스크롤 목록”으로 바꾸면 검증에서 거절된다. 이미지 없는 컨테이너를 만들거나 지원되는 영역+세로 스크롤을 쓴다. 오류 문구가 300KB라도 파일 크기 문제라고 단정하지 않는다.
- 단축/복제 부품이 접힌 부모 안에 있으면 선택이 안 된다. 실제 레이어 펼침 상태와 다중 선택 여부를 먼저 확인한다. 타임아웃 뒤에는 만들어진 부분을 읽고 이어 하며 중복 생성하지 않는다.
- 모달 닫힘 애니메이션 직후 snapshot만 보면 아직 남아 있을 수 있다. 실제 dialog hidden/target visible을 기다리고 판정한다.
- 재능35.5초 안정 프레임을 기준으로 쓴다. 34.5초 요청 캡처는 팝업 전 장면이어서 대체 기준으로 쓰면 안 된다. 생성 atlas는 프롬프트 순서가 아니라 실제 셀 내용/알파를 보고 역할을 매긴다.
- 서버/7007/다른 샘플/공통 소스/원본은 바꾸지 않는다. 공통 조사서 등록은1차와 충돌 없이 정리한다. 예약·자동 조회·새 게임/해금 설정을 추가하지 않는다.
