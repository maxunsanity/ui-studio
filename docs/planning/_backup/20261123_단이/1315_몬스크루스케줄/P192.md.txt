# P192 · 응원 크루 · 상세 기획서

**보는 법** 목차 → 전체 흐름 → 화면 → 기능별 그림 순서로 읽습니다. [대표 기획서](../개발진행기획_v01/콘텐츠별_v03/응원크루_핵심제안서.html)와 같은 기준입니다.

**지금 상태** 전체 목록·봇 크루10개·로컬 이미지 파일 선택·명시적 단독 시험의 앨범 없는 만들기를 반영했습니다. 별도 단독 시험에서 생성·10종 이미지·파일 저장/실패 보호·새로고침을 확인했고, 1차를 현중 지시로 정리합니다. 발란스값·실제 계정 서버·총공 실제 집행·홍보 추가 기획은 계속 대기입니다. 출전 신청·곡 사용 동의·등록 뒤 로비는 P207/P191의 현재 계약을 따릅니다.

## 크루 출전곡 투표와 크루장 신청

**현재 단독 테스트 · 2026-11-10 13:58 KST · 제안(검수 대기)**

게임 시뮬레이터 단독 테스트는 상위 메뉴를 주간 페스티벌과 월드 페스티벌로 나눕니다. 폰 하단도 주간·월드로 바로 엽니다. 일반 월드 입구는 개인 출전이며, 크루 출전은 응원 크루의 고정된 크루장 전용 신청 버튼에서만 시작합니다. 크루 화면에는 앨범의 데뷔 준비·앨범 활동·차트·파이널 단계표를 표시하지 않습니다. 주간 신청 뒤에는 레이싱 입장과 주간 진행·레이싱 기록을 바로 볼 수 있습니다. 레이싱 입장은 같은 발매 앨범의 기존 시티 투어 자동차 레이싱으로 연결합니다. 기록은 기본 펼침으로 표시합니다.

단독 테스트에서 월드 메뉴(개인·크루)에 진입하면 현재 주간 신청·버프·자동 연료/레이싱 진행을 새 시험 상태로 초기화합니다. 원본 신청 영수증은 이력으로 보존하고 현재 유효한 신청에서 제외합니다. 다시 주간에 들어오면 앨범 선택·신청부터 시작합니다. 앨범·공통 팀·이미 지급된 공통 재화·월드 신청·크루 투표는 지우지 않습니다. 이전 자동 진행 기록은 다음 실제 보드 저장에서 보관하며 활성 기록과 분리합니다. 이 초기화는 단독 테스트만의 조작이며 실제 운영 일정·게임 일차·일반 연결 플레이의 버프 정책을 바꾸지 않습니다.

자유 테스트에서는 이전 앨범의24시간 차트가 진행 중이어도 새 앨범을 먼저 발매할 수 있습니다. 기존 차트·실적·제작비 결제·발매곡을 보존하고 새 곡의 이벤트 참가는 순서대로 대기합니다. 기존 순차 차트 진입 경로를 사용하며 일반 연결 플레이의 차트 잠금과 운영 수치는 변경하지 않습니다.

일반 주간·월드 입구는 모두 개인 신청입니다. 크루 소속·직책과 관계없이 내 발매 앨범 한 곡을 선택하며 크루장도 개인 월드에 출전할 수 있습니다. 크루 월드 신청은 크루 페이지에서 크루장만 시작하고 개인 출전과 서로 잠그지 않습니다.

크루 멤버는 현재 크루에 공유된 발매곡 한 곡에 내부 투표하고 변경·취소할 수 있습니다. 현재 소속·현재 공유 상태를 다시 확인하며 탈퇴한 멤버나 철회된 공유곡의 선택은 현재 집계에서 제외합니다. 이 결과는 참고용으로만 표시하고, 크루장은 득표순·참여율·미투표와 관계없이 최종 공유곡을 고릅니다. 원소유자의 해당 회차 사용 동의와 크루장 권한은 실제 신청 때 재검사합니다. 원소유자는 일반 크루원이어도 크루 페이지에서 자기 곡의 회차 사용 동의·철회를 할 수 있습니다.

내부 출전곡 투표는 관객의 페스티벌 투표·공식 점수·크루재화 보상과 별개입니다. 투표 자체로 감상·팬·인기·점수·재화를 만들지 않습니다. 실제 로컬 신청/투표 원장으로 연결했으며 온라인 계정·공식 운영 기간과 총공 기능 완성으로 해석하지 않습니다.

## 1. 개요

출처: (합침) [응원 크루 제안](../../../proposal-concept/cheer-guild.html) · [크루 대표](../개발진행기획_v01/콘텐츠별_v03/응원크루_핵심제안서.html).

**앨범을 보고 모이고, 크루 미션으로 같은 재화를 쌓고, 누적획득량으로 크루를 키웁니다.**

기여는 획득한 크루재화량 하나로 보고, 레벨도 그 재화의 누적획득량으로 정합니다. 크루재화를 써도 개인 기여·누적획득량·레벨은 줄지 않습니다.


<a id="crew-overview"></a>

```mermaid
flowchart TB
  A["크루 찾기·만들기"] --> B["홍보·공개 앨범 확인"]
  B --> C["가입 신청·수락"]
  C --> D["앨범 중심 크루 내부"]
  D --> E["기존 보드·팬덤·찬스 활동"]
  E --> F["크루 미션 진행·보상 확인"]
  F --> G["크루재화 한 종류 획득"]
  G --> H["개인 기여·크루 누적획득량"]
  H --> I["누적획득량으로 레벨·단계 혜택"]
  G --> J["사용 가능한 크루재화 잔액"]
  J --> K["크루 홍보·홍보알림 사용안"]
  K --> L["비용 공급 전 집행 대기"]
  I --> D
```

| 영역 | 유저가 하는 일 |
|---|---|
| 발견·가입 | 전체 크루 목록·대표 이미지·소개·모집을 보고 공개 화면에서 신청, 미소속은 만들기 |
| 작품 | 등록 앨범을 좌우로 보고 해당 작품의 참여 아이돌 소개 확인 |
| 미션·재화 | 기존 활동 미션을 수행하고 크루재화 한 종류 보상 확인 |
| 성장 | 내 획득 기여·크루 누적획득량·데이터 기준 레벨과 혜택 확인 |
| 내부·운영 | 회원 상세·공지·내 알림함·권한별 심사/모집/멤버 관리 |
| 홍보 사용안 | 재화로 홍보 노출·홍보알림을 이용하는 안, 비용 공급 전 대기 |

길드와 응원 크루는 하나입니다. 크루 회원은 사용자 모임이며 앨범에 참여한 아이돌과 구분합니다. 새 보상 종류·기여축·XP를 만들지 않습니다.

## 3. 구동 방법·시뮬레이션

화면 흐름: 소속과 관계없이 전체 크루 → 대표 이미지·소개·공개 앨범·모집 → 신청/수락 → 내 크루 내부 → 미션·재화·회원 상세·알림함·관리. 미소속의 만들기는 일반 실행과 명시적 단독 시험의 자격을 따로 확인합니다.


<a id="crew-screens"></a>

```mermaid
flowchart TB
  A["전체 크루·미소속은 만들기"] --> B["공개 홍보·앨범 미리보기"]
  B --> C["신청·취소·처리 상태"]
  C --> D["수락 뒤 내부 홈"]
  D --> E["앨범 캐러셀·참여 아이돌 상세"]
  D --> F["미션 목록·진행·보상·대기 사유"]
  D --> G["사용가능 잔액·누적획득량·내 기여"]
  G --> H["레벨·혜택·획득과 사용 내역"]
  D --> I["크루 회원 목록·클릭 상세"]
  D --> J["내부 공지·내 알림함"]
  D --> K["권한별 관리"]
  K --> L["가입 심사·모집·공지"]
  K --> M["운영진·강퇴·위임·본인 탈퇴"]
  D --> N["홍보 노출·홍보알림: 비용 공급 대기"]
```

| 화면 | 표시·주 행동 | 접근 |
|---|---|---|
| 전체 크루 | 모든 현재 크루의 이미지·이름·멤버 수·소개·모집·공개 화면, 접힌 검색/필터 | 소속 여부와 무관 |

### 월드2차 · 개인과 크루는 서로 다른 출전 경로

**현재 개발되지 않음, 진행 중 · 제안(검수 대기).** 개인 유저 명의 출전과 크루 명의 출전을 구분합니다. 개인은 아이돌 한 명만 출전한다는 뜻이 아니고 팀·유닛 발매곡도 가능합니다. 자세한2차 본문은 [P191 투표/개인콘텐츠](산출_기획서_음원×페스티벌_v1_클로드.html#festival-phase2), 쉬운 전체 흐름은 [P207](../개발진행기획_v01/콘텐츠별_v03/월드페스티벌_핵심제안서.html#world-full-journey), [제안서 카드](/docs/planning/proposal-concept/fest.html#slide-1)에 연결합니다.

| 구분 | 개인 출전자 | 크루 출전자 |
|---|---|---|
| 신청 | 본인 발매곡 한 곡, 크루 미가입도 가능 | 현재 크루장이 공유곡 한 곡 신청·원소유자 회차 동의 |
| 게임 콘텐츠 | 개인 특화 무대·인터뷰·디렉팅 등과 공통 종목 | 공통 종목·파트 응원 릴레이·응원 큐 퍼즐 |
| 인기 | 실제 게임으로 얻은 인기 재화를 지정곡에 사용 | 같은 사용 원장·같은 entry 최고점 목표, 인원 단순 합산 보너스 없음 |
| 차트 | 개인 명의 entry의 별도 보기·전체 순위 동시 확인 | 크루 명의 entry의 별도 보기·전체 순위 동시 확인 |
| 혜택 | 개인 발견 슬롯·내 팀 베스트 기록·기념 연출 후보 | 협동 편성·합동 연출·기여 기록 후보 |
| 표와 권한 | 자기 곡 일반표 제외안과 자기 게임활동 허용을 구분 | 크루장이 회원 투표·타인 작품 동의/공개를 대신하지 않음 |

인기 재화는 현재 원본에서 별도 존재를 확인하지 못한 신규 제안이며 크루 재화·앨범 이벤트 재화와 다릅니다. **기본 게임의 인기 획득과 크루 미션 보상 청구를 분리**하고 미션 청구는 crew_currency만 지급합니다. 크루 재화 지출을 사람표로 바꾸지 않으며 총공 준비/이벤트 개최는 후속 기획입니다. 실제 참여/인기 사용의 인정 기여만 C로 검토합니다.

같은 종목을 여러 회원이 했다고 각자의 공식 슬롯을 출전곡에 무한 합산하지 않습니다. 개인의 동등한 혼자/공개 과제와 실제 시간·무료 기회·매칭 대기를 함께 검수합니다. 크루 미션·레벨·재화 원본은 그대로이고2차 기능은 구현하지 않습니다.

### 크루 찾기·만들기·가입 (현재 방향)

**「전체 크루」와 「내 크루」를 구분하며 소속 여부와 관계없이 전체 목록에 들어갈 수 있습니다.** 전체 목록은 현재 투영된 크루를 임의 개수로 자르지 않습니다. 대표 이미지·이름·실제 멤버 수·소개·모집 상태·공개 화면 열기를 작은 행으로 보여 주고, 검색/필터는 기본 접힘입니다. 내 소속 표시와 봇 표시는 별개입니다. 공개 앨범이 없는 크루도 소개와 모집 상태를 볼 수 있으며 내부 앨범·신청 메모를 공개 목록의 대체 자료로 쓰지 않습니다.

로컬 시험 fixture는 봇 크루 **10개**입니다. 기존 3개 저장은 누락된 7개만 추가하며 기존 크루·소속·역할·앨범·공개 동의·사용자 요청/영수증을 초기화하지 않습니다. 같은 확장을 재시도해도 중복 생성하지 않고, 봇은 실제 회원·유효 감상·득표로 표시하지 않습니다. 이 10개는 시험 구성 수이며 운영 정원·가입 한도가 아닙니다.

만들기는 미소속 여부와 기존 명령을 재사용합니다. **현재 소유자의 검증된 명시적 standalone 시험 환경**에서만 발매 앨범 없이 만들 수 있습니다. 단순 URL·UI 플래그나 metadata-only 문맥은 허용 근거가 아닙니다. source가 같은 pageScope/run/session/season·owner/team·sourceRevision의 준비된 시험 원본을 확인해야 하고 UI/명령이 같은 `isStandaloneCrewCreationReady`를 사용합니다. 일반 실행의 본인 발매 앨범 조건은 유지하며 앨범을 자동 생성하거나 새 창설 비용·정원·보상을 정하지 않습니다.

### 크루 대표 이미지·개인 파일 (현재 계약)

대표 이미지는 사용자가 **자기 기기 디스크에서 직접 고른 PNG/JPEG/WebP 파일**로 변경합니다. 입력은 2 MiB 이하이며 여백을 포함해 256×256 WebP로 다시 인코딩하고 결과는 64 KiB 이하로 제한합니다. 파일의 원래 이름·경로·메타데이터를 커리어에 남기지 않으며 외부 전송은 없습니다. 권한은 현재 크루장 또는 `editPublicity`를 위임받은 운영진에게만 있고 명령 시점에 현재 소속·권한·scope를 다시 확인합니다.

이미지 바이트는 IndexedDB Blob 전용 저장소에 총 **16장·1 MiB** 한도로 둡니다. 커리어/명령에는 `imageRef={kind,assetId,mime,width,height,byteLength}`의 6필드와 scope만 전달하며 Blob·base64·data URL·object URL·원본 파일을 넣지 않습니다. 실제 바이트 상한은 이미지 저장소의 한도이고 기존 요청 영수증/이벤트까지 저장 증가가 0이라는 뜻은 아닙니다. 정적 봇 이미지 10종과 개인 파일 Blob 한도는 별도입니다.

```mermaid
flowchart LR
 F["개인 디스크 파일 선택<br>PNG/JPEG/WebP·2 MiB 이하"] --> N["여백 포함 256×256 WebP<br>메타데이터 제거·64 KiB 이하"]
 N --> B["한도 내 IndexedDB Blob 저장<br>16장·총 1 MiB"]
 B --> R["6필드 imageRef + scope"]
 R --> C["set_crew_image<br>현재 소속·leader/editPublicity 재검증"]
 C -->|"확인된 성공"| V["해당 크루 대표 이미지 참조 반영"]
 V --> U["이전 Blob 정리·object URL 해제"]
 C -->|"실패·결과 불명"| E["정본 재조회·대상만 정리/보존"]
```

| 저장·처리 | 현재 계약 |
|---|---|
| Blob 저장소 | IndexedDB `kpopmonsters-crew-portraits-v1` / `images`, 키 `[runId,sessionId,seasonId,crewId,assetId]` |
| 정본 명령 | `set_crew_image {requestId,crewId,scope:{runId,sessionId,seasonId},imageRef:{kind:'local',assetId,mime:'image/webp',width,height,byteLength}}` |
| 한도 적용 | 한 readwrite 트랜잭션에서 저장소 전체 장수·바이트를 확인, 초과/IndexedDB 불가/디코드 실패 시 정본 변경 안 함 |
| 처리 중 이동 | writer 전 입력 화면이 사라지면 취소, writer 시작 뒤에는 처리 결과 확인까지 이어감 |
| 교체·실패 | 새 Blob 저장 후 명령 실행, 성공 또는 정본의 정확한 참조 일치 확인 뒤 이전 Blob만 정리. 명확한 실패는 후보만 정리하고 결과 불명·scope 변경은 보존 후 상태 안내 |
| 정리·표시 | 다시 그리기·화면 종료에서 object URL 해제, 다른 실행/사용자 Blob을 임의 삭제하지 않음. 고아 Blob도 한도에 포함 |
| 외부 경계 | 외부 업로드·공개 게시·파일 경로 기록 없음, 입력 원본/이미지 바이트는 career/localStorage/명령/values Map에 넣지 않음 |

대표 이미지 참조가 없으면 해당 봇 fixture의 정적 이미지를 쓰며 권한 없는 방문자는 파일 선택기를 보지 않습니다. 정적 에셋은 서비스 리소스이고 개인 업로드 Blob의 64 KiB 한도와 구분합니다. 대표 이미지 편집 권한은 다른 소유자의 앨범 홍보 동의를 대신하지 않습니다.

### 앨범·크루 회원·아이돌 정보 (현재 방향)

등록 앨범이 내부 첫 화면에 보입니다. 발매 후 자동 공유와 기존 수동 공유는 회원 내부 공유이며 공개 홍보 허용이 아닙니다. 같은 발매 앨범 원본을 참조하며 커버·곡명·참여 아이돌을 좌우로 봅니다. 등록·해제는 현재 소속과 작품 권한을 확인하고, 크루 노출 정리와 원본 앨범 보존을 구분합니다. 해당 작품에 참여하지 않은 현재 팀 멤버를 앨범 참여자로 붙이지 않습니다.

공개 홍보는 앨범 원본 소유자가 본인 글·본인 발매 앨범·현재 동일 membership을 확인한 뒤 명시적으로 허용합니다. 크루장·운영진이 다른 소유자의 동의를 대신할 수 없고 봇에도 자동 공개 예외를 두지 않습니다. 홍보 공개허용/해제는 무료 설정이며 크루재화를 쓰는 홍보 노출·홍보알림과 별개입니다. 찾기·공개 홍보는 유효한 `publicAlbums`만 읽고 내부 앨범 전체를 대체 표시하지 않습니다. 탈퇴·강퇴·재가입 뒤 이전 동의만으로 자동 재공개하지 않으며, 유료 홍보도 현재 유효한 소유자 동의가 있는 작품만 표시합니다. 앨범 원본의 소유권은 그대로 유지합니다.

### 홍보 사용·기본알림 (제안과 현재 방향 구분)

기본 시스템 알림은 가입 신청 접수·처리 결과, 공지, 보상, 멤버 관리·탈퇴·강퇴·위임·운영권한, 레벨 변화 등의 본인 안내입니다. 원인 사건에 따라 자동·무료로 표시하고, 미읽음/읽음과 원본 연결을 제공합니다. 같은 사건을 다시 읽어도 알림을 복제하지 않습니다. 기존 공유글 알림은 같은 원본을 읽는 투영과 본인 읽음 상태를 구분합니다.

크루 홍보 노출·홍보알림은 크루재화 사용처의 제안(검수 대기)입니다. 홍보할 글·현재 권한·공개 범위를 확인한 다음 데이터의 레벨 혜택 해금 → 유효한 비용 → 현재 잔액 순서로 확인합니다. 해금 기준·비용·노출/빈도 정책이 없으면 대기합니다. 완료된 공개 홍보만 찾기·홍보 페이지에 표시하고 내부 거래·비용은 공개하지 않습니다. 기본알림에 비용을 붙이지 않고, 비용 미공급 상태에서 잔액 차감·홍보 노출·발송 완료를 만들지 않습니다. 외부 메시지는 보내지 않습니다. 무료 기본알림에는 유료 홍보의 레벨 혜택 해금 조건을 적용하지 않습니다.

홍보 노출은 노출기간·동시노출 한도까지 공급되어야 하며 완료·기간 유효·원본 미철회 상태만 공개 목록에 표시합니다. 홍보알림은 현재 크루원에게 한 번 보여주는 게임 내 알림이며 노출기간을 요구하지 않습니다. 같은 활성 홍보 재요청은 기존 효과를 재사용하고 재차감하지 않습니다. 완료·만료 뒤 반복 정책이 미공급이면 다시 집행하지 않고 대기합니다.

로컬 메모리 fixture의 compact JSON UTF-8 실측은 기존 3개 **14,880 B** → 신규 10개 **22,529 B(+7,649 B)**, 기존 3→10 이행 **22,923 B(+8,043 B)**입니다. 같은 시험 원본의 비교이며 모든 실제 저장의 고정 증가량으로 일반화하지 않습니다. 이미지 바이트의 career 증가량은 0 B이지만 서로 다른 이미지 변경 명령의 기존 fingerprint·영수증·이벤트 메타데이터는 누적됩니다. Blob 저장소 한도는 이 커리어 이력의 상한이 아닙니다.

구조와 값은 데이터로 공급합니다. 이 문서에서 새 표·스키마·열·생성물을 등록하거나 원표를 수정하지 않습니다. 숫자 빈칸을 확정 0으로 바꾸지 않습니다. 현재 source의 정확한 계약·필드는 담당 구현 회신과 함께 하단 기록에 구분하며 실제 운영 승인을 뜻하지 않습니다.

주사위 환산: 크루 미션에 새 주사위 보상·기존 재화 교환을 추가하지 않습니다. 크루재화 목표·획득량·배수·사용 비용은 발란스 대기입니다.

### 1차 정리·종결 · 2026-11-06

**기록 구분:** 주간 콘텐츠는 현중이 직접 확인했습니다. 단이는 새 고유 단독 시험 범위 두 개에서 월드 개인/크루 최종 등록·참여 로비·명시 대회 복귀·동일 유형 재신청 제거·새로고침 후 월드 자동 복귀를 확인했습니다. 로비는 실제 출전곡의 이미지·이름·아티스트·크루와 같은 회차 순위만 강조합니다. 미집계 순위/득표율은 집계 전이고 앨범 활동100위를 페스티벌 순위로 쓰지 않습니다.

출전곡 공통 재생/전체화면 공연 이미지+시험 음원, 음악 앱의 같은 월드 회차·출전곡 연결과 다른 참가곡으로 재생 전환을 실제 화면에서 확인했습니다. 현재 자산은 정지 복셀 이미지와 라이선스 시험 음원이며 실제 생성 동영상·사용자 제작 원곡이 아닙니다. 소리 출력 자체·공식 온라인 투표/집계는 미확인입니다.

크루는 앨범 없는 명시적 단독 시험에서 생성했고, 소속 후에도 전체 크루 목록에 접근해 봇10개와 내 크루를 확인했습니다. 봇10개 대표 이미지 로딩, 로컬 파일→256px WebP→Blob 저장·표시·새로고침 유지, 잘못된 파일 거절 시 이전 이미지 보존을 확인했습니다. 일반 게임의 발매 앨범 조건·크루장/원소유자 권한은 집중 시험으로 구분 검증했고 실제 모든 권한 조합을 클릭 검수한 것은 아닙니다.

**저장/시험 범위:** 기존 사용자 저장을 삭제·덮어쓰지 않고 고유 testPage를 사용했습니다. 브라우저 저장 용량 부족 때 기존 호스트가 표시한 탭 세션 저장 경로로 신규/재접속을 확인했습니다. 원본 main/발란스 이어하기·복구의 전체 검증으로 확대하지 않습니다. 공유 저장·발란스/idleSim·현황판·7007서버/금지 포트는 수정하지 않았습니다. 이미지 바이트는 career/localStorage에 넣지 않습니다.

**증거/검사:** 도메인9/9, 로컬 이미지 프로토콜10/10, source/view6/6, 페스티벌 메모리 UI12개 통과. 기존 비교 시험의 실패 집합은 전후 동일하며 전체 시험 통과로 쓰지 않습니다. 새로고침·등록·감상 연결의 실제 캡처와 파일/백업/명령은 [이번 공용 보고](/docs/planning/삼중AI_공용_20260929/보고/20261106_090357_단이_월드참여로비_크루목록_이미지업로드.md)에 연결합니다.

### 수락 기준

- 미션 보상은 `crew_currency` 한 종류이고 개인 재화·돈·팬·능력·아이템·별도 XP를 추가하지 않습니다.
- 기여는 획득한 크루재화량이며 레벨은 크루 누적획득량으로 정합니다. 사용은 잔액만 줄입니다.
- 본인의 실제 writer 관측·당시 소속을 확인하며 같은 mission+membership은 한 번만 보상합니다.
- 버튼·봇·미리보기·미션보상·원장획득을 미션 진행으로 다시 세지 않습니다.
- 미정 목표·보상량·레벨 기준·사용 비용을 0·임의 수치로 채우지 않고 발란스 대기 사유를 표시합니다.
- 홍보·회원 내부·관리의 공개 정보와 권한을 구분하고 회원 상세와 아이돌 상세를 구분합니다.
- 신청은 현재 소속 생성·수락이 끝나야 가입 완료입니다. 소속 변경은 과거 정당한 원인·거래를 지우지 않습니다.
- 기본알림은 무료이며 유료 홍보안은 비용 공급 전 차감·노출을 실행하지 않습니다.
- 전체 크루는 소속과 무관하게 열리고 10개 시험 크루와 내 크루/봇 표시를 구분합니다. 기존 3개 저장의 이행은 사용자 기록을 초기화하지 않습니다.
- 이미지 선택은 본인 디스크 파일·현재 크루장/위임 권한·scope를 확인하고 Blob 한도와 6필드 참조를 지킵니다. 실제 IndexedDB·디코드·동시 탭·교체/실패 검증은 정적 검사와 구분합니다.
- 앨범 없는 만들기는 검증된 명시 standalone에만 열고 일반 실행의 발매 조건과 미소속 확인을 유지합니다.
- 페스티벌 신청·활동 로비는 P207/P191 현재 계약을 따르며 공식 평가·실제 총공·홍보 추가 기획과 실제 화면 미확인을 숨기지 않습니다.
