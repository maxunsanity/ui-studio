# 1·2차 HUD 구성·샘플 재사용·실수 방지

2026-11-19 · codex(단이). 사용자 최신 지시를 우선합니다. 여기서 시안의 수치는 제작 제안이며 게임 발란스·최종 시각 승인이 아닙니다.

## 범위와 순서

1. 원본 기획서의 표시 정보·동작·상태·근거와 현재 저장본을 읽습니다.
2. 기능과 구조가 비슷한 샘플을 비교합니다. 이름이나 그림 분위기만으로 고르지 않습니다.
3. 화면 전체 구성 시안을 먼저 보여 줍니다. 기획서 문장을 단순히 박스로 옮기지 않습니다.
4. 큰 영역·정보 우선순위·입구 동선이 맞는지 먼저 확인합니다. 기존 1차도 완벽하거나 변경 금지된 것으로 가정하지 않습니다.
5. 2차에서 부품·부모자식·크기/간격·글자 자리·배지·입력·상태·연결을 구체화합니다.
6. 실제 스튜디오에서 편집·저장·재열기·입력과 기기 배치를 확인합니다. 별도 시안 파일 작성이나 공통 도구 코드 수정은 실제 HUD 제작과 구분해 보고합니다.

## 2차의 표현

- 완성 아이콘 원화·캐릭터 그림·재질·광택·입체 버튼·장식 스타일을 추가하지 않습니다.
- 아이콘·이름·남은 시간·배지는 분리합니다. 같은 역할은 같은 기준선·간격·크기를 사용합니다.
- 클릭 범위와 묶음의 사각형을 완성 화면에 그리지 않습니다. 투명 입력 부모와 자식으로 구성하고, 편집 가이드에서만 범위를 봅니다.
- 실제 판이나 경계가 필요한 부품만 보이는 선을 사용합니다. 이벤트마다 사각 칸·원 테두리·시간 캡슐을 무조건 추가하지 않습니다.
- 프로필 둘레에는 팀 평균 컨디션 게이지가 필요합니다. 프로필 이미지와 입력 영역을 가리지 않으며 사각 테두리로 가두지 않습니다.
- 대기·이동·도착처럼 정보량이 달라지면 필러 높이와 게임 가시 영역의 관계까지 보여 줍니다.

## 샘플에서 가져올 것

모노폴리GO r354 Page_Board와 카피바라고 r90 Page_Capybara_Lobby에서 확인한 재사용 구조는 부모 버튼 / 아이콘 / 라벨 / 알림 배지의 분리입니다. 자식은 부모 입력에 전달하고 버튼과 상태를 별도로 봅니다. 이 기록은 샘플의 모든 시각·테두리·폰트가 적합하다는 승인이 아닙니다.

원화·색·재질까지 복사하지 않습니다. 해당 역할의 부모 크기·논리 좌표·입력 구조·표시 순서를 비교한 뒤 대상 프로젝트의 공통 규격에 맞춥니다. 복제에서 따라온 행동·배지·앵커·그림자와 부모 누락도 확인합니다.

## 버튼과 공통 안내

- 기본 아이콘과 정보 표시도 원문 및 최신 지시에 따라 입력 대상인지 확인합니다. 이미지라는 이유로 클릭 불가라고 단정하지 않습니다.
- 연결이 있으면 기존 동작을 실행합니다. 연결 없는 입력 대상은 공통 안내 후 확인으로 닫습니다. 없는 게임 화면을 임의 제작하지 않습니다.
- 명시적인 표시 전용·비활성·입력 차단과 접힌 메뉴·모달 뒤 입력은 구분합니다.
- 모달 안에서 발생한 안내는 그 모달의 키보드 접근 범위 안에서 닫을 수 있어야 합니다. 안내 Escape가 원래 모달을 닫지 않도록 합니다.
- 다음 정상 입력이나 화면 전환에 이전 미연결 안내가 남지 않아야 합니다.

## 문서와 AI 진입

작업 명세는 선택한 부품을 만들 수 있는 수준의 구성·표시·동작·문구 규칙과 미정 항목을 담습니다. 짧게 보이려고 필요한 정보를 없애지 않습니다. 데이터·이미지·조사 근거를 모두 담은 문서는 ‘원본 기획서’로 별도 버튼에서 열고 변경 이력은 따로 둡니다. 작업 화면에는 승인 이력·관리 안내·보고 문구를 반복 노출하지 않습니다.

다음 AI의 진입 안내에는 현재 workspace/project/revision, 작업 범위, 실제 파일 경로와 읽는 순서를 적습니다. 스크린샷이나 버튼을 우연히 발견해야만 명세를 읽을 수 있게 만들지 않습니다. 1·2차 기획을 후속 본UI 스타일·게임 기능 승인으로 확대하지 않습니다.

## 이번 전체 구성 제안 v1

390×844를 배치 검토 기준으로 합니다. 상단64 / 게임404 / 재화54 / 필러160 / 행동80 / 하단82로 합계844입니다. 이동 중에는 필러84 / 게임480으로 바꾸어 합계를 유지합니다. 모두 검토할 시안값이며 기존 합의 치수·게임 값으로 자칭하지 않습니다.

프로필과 게이지, 상단 정보, 중앙 앨범·페스티벌, 좌우 각5개 이벤트, 재화3구역, 필러, 배수·굴리기, 하단6메뉴를 한 화면에 제시했습니다. 기본 메뉴·프로필·공통 안내·대기/이동/도착을 눌러 살펴보는 별도 구성 시안이며 스튜디오 r52를 수정한 결과가 아닙니다.

## 실패에서 바꾼 방법

| 이전 문제 | 지킬 방법 |
|---|---|
| 긴 원문을 무조건 요약해 제작 규칙이 빠짐 | 부품별 작업 규칙은 남기고 근거·표를 접어 정리 |
| 합의 상태와 작업 설명을 화면에 반복 노출 | 작업 필드와 필요한 버튼만 표시, 이력은 분리 |
| 이벤트를 사각형 슬롯에 가둠 | 입력 부모는 투명하게, 표시 부품은 개별 배치 |
| 2차에 원화·재질·장식을 넣음 | 무채색 구조·기본 기호·부품별 자리만 표현 |
| 구역 전체에 굴리기 연결을 걸고 실제 버튼이 없음 | 구역과 실제 입력 소유자를 구분 |
| 미리보기나 코드 수정만 하고 실제 제작처럼 설명 | 시안/코드/실제 편집/저장/실화면 검수를 각각 보고 |

그림 비교·사용자 수정·새 실패가 나오면 근거와 이유를 이력에 추가하고, 검토된 규칙만 가이드에 승격합니다.

## 로비가 인게임인 경우 · 상태 구성 보정
현중 최신 지시: 로비가 곧 인게임이며 필러 연출·종류 때문에 여러 화면이 필요하고 각각의 하위 버튼이 보여야 합니다. 이전 ‘로비 하나만 남긴다’를 인게임 상태별 시안 금지로 확대하지 않습니다. 참고 전용 페이지 정리와 인게임 변형 화면의 제작·검수를 구분합니다.
공통 HUD를 같은 규격으로 유지하고 필러/행동 영역만 상태별로 바꿉니다. 색·문구만 다른 상태는 같은 틀을 공유하되 검수에서 각 상태를 선택할 수 있어야 합니다. 22개 상태 보기는22개 독립 판틀을 뜻하지 않습니다.
필러 진행: 넘기기/건너뛰기, 종료: 굴리기, 파손: 수리/굴리기(수리 노출은 원문 제안), 출연권: 도전, 감옥: 복귀 굴리기, 나쁜 기운 상한: 디펜스. 필러 안에 넘기기 버튼을 넣지 않고 아래 행동줄에 배치합니다. 디펜스 상태는 필러를 건너뜁니다.
정보: 팀/아이돌/관계/크루. 몬스: 방패/몬스. 설정: 계정 바꾸기/지금 저장/개발 메뉴(개발용). 앨범 보상 보기와 페스티벌 레이스/추천도 각각 별도 입력입니다. 페스티벌 전·주간·월드는 같은 틀의 내용 상태로 봅니다.
대기/이동/자동/부족/판정과 결과/장면/대사/리액션/보상/종료, 파손/도전/감옥/디펜스, 각 펼침과 팀/개별을 검수합니다. 이동·판정 중 버튼 막힘과1초 꾹 누르기 상태도 표시하되 시안에서 실제 게임 판정이나 재화 처리를 수행하지 않습니다.

## 실제 스튜디오 제작에서 확인한 보정 · 2026-11-19

- 외부 조작 없이 스튜디오의 선택·복사·그룹·부모 이동·수치 적용·저장으로 제작합니다. 브라우저 안내 캐시가 비었으면 공식 앱 설치 폴더의 동일 안내와 기존 연결 경로부터 확인합니다. 안내가 없다는 이유만으로 도구 전체가 없다고 단정하지 않습니다.
- 색 입력이 HEX만 지원하는 경우, 버튼 전체 불투명도를 낮추면 자식도 숨습니다. 투명 그룹을 입력 부모로 만들고 원래 ID의 빈 입력 요소만 불투명도0/부모 전달로 보존합니다. 아이콘·이름·시간·배지는 투명 그룹의 형제로 두며 기존 자식 ID를 보존합니다.
- 그림·배지가 표시 전용 상태로 클릭을 가로채면 부모 버튼 중앙을 눌러도 반응하지 않을 수 있습니다. 실제 아이콘/글자/배지 지점의 입력을 각각 확인하고 자식은 부모에 전달합니다.
- native 입력은 클릭→전체 선택→실제 입력→Tab 후 레이어 이름/저장본으로 확인합니다. fill로 입력칸 값만 바뀐 것을 저장 모델 반영으로 세지 않습니다. 위치 수치는 4개 입력 후 ‘수치 적용’으로 반영합니다.
- 이미지→텍스트 변환은 자원 참조와 이미지 자리 표시 스타일도 지워야 합니다. 남은 variant=image가 게이지 아래에 엉뚱한 꺾쇠를 그린 사례를 회귀 시험으로 고쳤습니다. 자원 파일 원본은 삭제하지 않습니다.
- 새 화면 연결은 대상 UI를 고른 뒤 실행 조건을 정합니다. 대상 없는 상태에서 화면 이동으로 바꾸면 도구가 조건을 미정으로 되돌리므로 마지막 저장본 조건까지 확인합니다.
- 편집기 미리보기는 실행기를 공유해 화면 이동/뒤로/팝업/공통 안내를 시험합니다. 전체 캔버스의 정적 보드, 개별 팝업 단독 보기, 실제 게임 엔진 실행은 구분합니다.
- 페이지 정리는 스튜디오의 ‘이 화면 삭제’로 하며 들어오는/나가는 연결을 함께 지웁니다. 삭제 전 저장본 백업·시작 화면 보호·Undo 복귀와 공통 연출 선택값 유효성을 확인합니다.
- 원문 최대 필러170은 유지합니다. 이동/판정은84, 결과/장면/대사는170, 디펜스는필러없음으로 제작했습니다. 이는 실제 제작 배치이며 게임 판정/보상/자동 진행을 구현했다는 뜻이 아닙니다.
- 3버튼은 원문에 실제 등장 상황이 없어 별도 Template_Action_3 규격 틀로만 만듭니다. 없는 게임 상황을 새로 정하지 않습니다.
- 프로젝트 저장 설계는2,000,000bytes 이하입니다. 현재 공통 HUD 반복을 포함해 약1.81MB이므로 새 전체 화면을 무작정 추가하지 말고 다음 작업 전에 저장 크기와 재사용 범위를 확인합니다.

- 게임 자동 진행·1초 꾹 누르기 타이머·실제 판정/보상은 구현하지 않았습니다. 상태 시안과 수동 화면 연결을 게임 실행으로 설명하지 않습니다.
