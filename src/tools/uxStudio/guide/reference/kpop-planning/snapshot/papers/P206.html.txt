<p><b>이 문서는</b> 한 화면의 탐험·출동, 조각 도감, 공동 참가·보상과 추가 소셜 기능을 설명하는 책갈피 상세 기획서입니다.</p>

<p><b>보는 법</b> 1장 용어·개요 → 4장 플레이·UI → 6장 정산 → 7장 상태를 읽습니다. 발표용 요약은 <a href="/docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EB%9D%BC%ED%8F%ACAI%ED%83%90%ED%97%98_%EA%B8%B0%ED%9A%8D%EC%84%9C.html" data-paper-path="docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EB%9D%BC%ED%8F%ACAI%ED%83%90%ED%97%98_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">핵심제안 개발 P152</a>, 실행은 <a href="/docs/planning/game-simulator.html?module=simulator_module_journey" data-paper-path="docs/planning/game-simulator.html">게임 시뮬레이터</a>, 시안은 <a href="#ui-preview">같은 문서 아래 UI</a>에서 확인합니다.</p>

<p><b>지금 상태</b> 기본 탐험·조각 도감·모의 공동 참가·기존 출동은 개발됨. 친구 아이돌·우정 포인트·우리 사이 보기는 게임 시뮬레이터의 조작으로 제공하며, 발란스 두 도구는 자동 계산·성장 현황판은 읽기 전용 합계로 구분했습니다. 실제 외부 친구 서버는 후속입니다. 신규 수치는 모두 <b>임시(나중에 결정)</b>입니다.</p>

<section class="part" id="part-1"><h2>1. 개요</h2>

<p>출처: (합침) <a href="/docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EB%9D%BC%ED%8F%ACAI%ED%83%90%ED%97%98_%EC%9B%90%EB%B3%B8/2%EA%B3%84%EC%B8%B5%EB%9D%BC%ED%8F%AC_AI%ED%83%90%ED%97%98%EC%84%9C%EC%82%AC_%ED%86%B5%ED%95%A9%EA%B8%B0%ED%9A%8D%EC%84%9C_v1.0_%EC%9B%90%EB%B3%B8.html" data-paper-path="docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EB%9D%BC%ED%8F%ACAI%ED%83%90%ED%97%98_%EC%9B%90%EB%B3%B8/2%EA%B3%84%EC%B8%B5%EB%9D%BC%ED%8F%AC_AI%ED%83%90%ED%97%98%EC%84%9C%EC%82%AC_%ED%86%B5%ED%95%A9%EA%B8%B0%ED%9A%8D%EC%84%9C_v1.0_%EC%9B%90%EB%B3%B8.html">제안서 원문 P153</a>, 현재 탐험 시뮬레이터와 사용자 제공 화면 자료.</p>

<div class="table-scroll"><table><thead><tr><th>위치</th><th>이름과 역할</th></tr></thead><tbody><tr><td>상위 메뉴·모바일 하단</td><td>모험</td></tr><tr><td>메인 위쪽</td><td>탐험 목록. 아이돌 편성·몬스 분신의 도시 이동</td></tr><tr><td>모험 화면 상단 고정</td><td>모험 발견 도감. 탐험·출동에서 모은 조각으로 아이템 완성</td></tr><tr><td>같은 메인의 출동 영역</td><td>기존 출동 목록. 탐험과 전환하는 탭 없음</td></tr><tr><td>피그마의 ‘발견’</td><td>후속 출동 구조의 참고 원본. 조각 도감과 별도</td></tr></tbody></table></div>

<p>탐험·출동을 같은 메인에 함께 배치합니다. 상위 이름은 모험이며 내부 journey ID·URL은 유지합니다. 탐험과 출동은 각각 3개 반이 보이는 가로 캐러셀입니다. 도감 상세는 모바일 프레임 안의 모달로 엽니다.</p>

<p><b>피크민 공식 조사:</b> <a href="https://scopelyexplore.helpshift.com/hc/en/11-pikmin-bloom/faq/2146-expeditions/" target="_blank" rel="noopener">탐험</a>은 이미 발견된 과일·모종 등을 골라 피크민을 보내고 가져오는 활동입니다. 물건 선택 → 편성 → GO → 회수입니다. 분수는 선택한 힘과 물건 무게를 비교하는 최소 운반 조건입니다. <a href="https://scopelyexplore.helpshift.com/hc/ko/11-pikmin-bloom/faq/2142-mushrooms/" target="_blank" rel="noopener">버섯</a>은 여러 플레이어가 작업력을 모아 목표를 해결하고 시간·작업력 결과의 보상을 받는 공동 도전입니다.</p>

<p><b>화면 대조 해석:</b> 첨부 원문의 ‘여정’(현재 게임 명칭: 탐험)의 공동 작업·전체 능력·참가자·시간·등급은 버섯형에 가까운 요소입니다. ‘발견’은 물건 목록과 회수 후 서사·카드 획득을 포함합니다. 피크민 용어와 피그마 용어가 일대일로 같다는 뜻은 아닙니다. 우리 쪽은 현중의 최신 이름·구조를 우선합니다.</p>

<p>피그마 링크는 현재 로그인 요청 화면으로 원본 전체 재열람이 불가능했습니다. 현중이 올린 완료된 발견 설명·서사·참가 순위 보상 이미지와 이번 정정을 직접 근거로 삼습니다. 피크민의 최소 운반 조건을 우리 카드 자리 상한으로 오해하거나 운영 수치를 그대로 복사하지 않습니다.</p>

<div class="table-scroll"><table><thead><tr><th>임시 항목</th><th>값</th></tr></thead><tbody><tr><td>아이돌 최대 / 자리 상한</td><td>5명 / 5자리</td></tr><tr><td>1·2·3성 / 4성 / 5성 자리</td><td>1 / 2 / 3</td></tr><tr><td>탐험 능력</td><td>현재6축 합 ÷100 + 등급×40, 최소80</td></tr><tr><td>추천 속성</td><td>해당 카드 능력×1.2</td></tr><tr><td>진행량</td><td>기존 시간(분)×기준 능력500</td></tr><tr><td>기본 속도 / 선택</td><td>×60 / ×1·10·30·60·120</td></tr><tr><td>1회 진행</td><td>시험 시간300초</td></tr></tbody></table></div>

<h3 id="4-3-공동-탐험과-합류">4-3. 공동 탐험과 합류</h3>

<p>한 탐험에 여러 플레이어가 각자 편성을 보냅니다. 현재 정원은 내 팀 포함 최대6팀이며, 공동 원버튼 시험은 엔터파워 해금 범위(최대6팀)에 맞춥니다. 내 순위1·2·3·마지막을 시험할 수 있습니다.</p>

<p>기여도는 참가한 뒤 실제 처리한 진행량입니다. 늦게 합류한 친구에게 지난 진행을 소급하지 않습니다. 속도·정지·계속·1회 진행에서도 중복 계산하지 않습니다. 동률은 참가 순서이며 완료 때 결과를 고정합니다.</p>

<p>실제 외부 초대·친구 계정 지급·여러 기기 동기화는 후속 서버 작업입니다. 현재 친구는 로컬 모의 참가자입니다.</p>

<h3 id="4-4-플레이어-순위와-보상-ui">4-4. 플레이어 순위와 보상 UI</h3>

<p>첨부 리스트는 <b>아이돌 순위가 아니라 플레이어별 참가 보상 목록</b>입니다. 행마다 순위·아바타·이름·기여도·추가 카드팩/상자를 표시합니다. 목록은 스크롤되고 내 행을 아래에서 다시 강조합니다. 내 순위가 마지막이어도 바로 찾을 수 있어야 합니다.</p>

<p>기본 보상은 순위와 별개입니다. 참가자2명 이상일 때 상위3명에게 추가 보상을 보여줍니다. 친구 행은 모의 보상 목록이고 내 수령분만 공통 지갑·카드에 정산합니다.</p>

<p>실제 팩 장수·확률·보장은 기존 표를 읽습니다. 상자는 묶음 연출이며 전역 미등록 상자 아이템을 소유한 것으로 처리하지 않습니다. 내 내용물은 돈·주사위로 펼쳐 정산합니다. 모든 신규 값은 임시(나중에 결정)입니다.</p>

<h3 id="4-5-탐험-보상과-추가-조각">4-5. 탐험 보상과 추가 조각</h3>

<p>기본 카드팩1개, 단계별 돈·주사위, 명시한 추가 시험 보상과 내 순위 추가 보상을 지급합니다. 탐험에서 찾은 것은 <b>도감 아이템 조각</b>입니다.</p>

<p>결과에 ‘추가로 발견하였습니다’ → 아이템 이름 → 조각×수량을 표시하고 탐험 지급에 포함합니다. 임시로 회당 조각1개, 진행55%에 발견 기록, 완료 때 확인 가능입니다. 도감 수량은 실제 탐험 보상 저장 뒤 증가합니다. 미리보기·재접속·재열람으로 더 주지 않습니다.</p>

<h3 id="4-7-아이템-완성서사">4-7. 아이템 완성·서사</h3>

<p>같은 아이템 조각3개가 임시 완성 기준입니다. 오른쪽에서1~99개로 시험합니다. 완성 지급을 준비한 항목은 그때 조건을 고정합니다.</p>

<p>아이템 화면은 이름·현재/필요 조각·진행 막대·고유 이야기·완성 보상·버튼입니다. 부족하면 버튼을 막습니다. 조각은 소비하지 않습니다. 완성 보상은 항목별 현재 세션에서1회이며 임시로 기본 카드팩1개+기본 돈·주사위입니다.</p>

<p>탐험 이야기는 이동·활동·팀 관계, 도감 이야기는 물건의 단서→인물의 사연→아이돌 행동→후일담입니다. 두 서사를 복제하지 않습니다. 도감 완성·이야기 재열람은 팀 라포를 다시 올리지 않습니다.</p>

<h3 id="출동의-실제-보유-몬스-편성">출동의 실제 보유 몬스 편성</h3>

<p><b>출동</b>은 기획사에서 실제 보유하고 선택한 몬스를 읽습니다. 공통 편성의 순서를 보존하되 이 활동은 기존 adventure.json의 maxParty=5와 시작 검증을 사용합니다. 디펜스·출연권 대전의 최대10을 출동에 그대로 늘리지 않습니다.</p>

<p>명시적으로0마리를 선택했거나 보유 몬스가 없으면 출동을 시작하지 않습니다. 자동 계산도 출동 횟수·출동 보상·해당 소모를0으로 남기며 미보유 종이나 멤버의 짝 몬스로 채우지 않습니다. 뉴스→사옥 출발→비행→대결→보상 흐름과 기존 티켓·시간·기본 보상·속성 규칙은 유지하고, 신규 출동에 도감 조각을 추가합니다. 몬스 종을 재화처럼 소비하거나 합성·행복을 바꾸지 않습니다.</p>

<p>독립된 모험 단독 테스트의 새 생성 팀은 보유 기록 자체가 없을 때 기존 게임의 첫 몬스 지급 설정으로 출동 편성을 준비합니다. 실제 전송 팀·본편·다른 테스트 저장은 바꾸지 않고, 이미 저장된 빈 보유나 수동으로 비운 편성도 유지합니다. 새로고침해도 추가 지급하지 않습니다.</p>
<p>탐험의 내 아이돌 최대5명·친구 동행·몬스 분신의 도시 이동은 별도 흐름입니다. 이 출동 편성 보완으로 탐험·여정의 전투 참가 몬스까지 확대하지 않습니다. 라포·우정 포인트·탐험 조각·도감·퍼즐·기존 카드 보상도 그대로 유지합니다.</p>

<h3 id="4-8-출동-유지와-후속-피그마-발견">4-8. 출동 유지와 후속 피그마 발견</h3>

<p>현재 뉴스→1번 사옥 출발→탑뷰 비행→대결→보상을 유지합니다. 엔진·진행 시간·기존 보상 추첨을 도감과 섞지 않습니다.</p>

<p>사용자 첨부에서 읽은 후속 완료 UI:</p>

<ol>
<li>완료된 발견은 완료 순서대로 목록 맨 앞에 정렬.</li>
<li>‘발견 완료!’ 아이콘과 테두리 효과.</li>
<li>클릭하면 관련 카드 캐릭터 이미지·관련 카드 이야기.</li>
<li>이야기는 아래에서 위로 자동 스크롤.</li>
<li>‘건너뛰기’는 이야기만 넘겨 카드 획득 화면으로 이동.</li>
<li>획득 확인 후 모험 메인. 상자·재화는 해당 항목의 보상만 표시.</li>
</ol>

<p>이것은 현중이 ‘발견 즉 출동’으로 매핑한 후속 기준입니다. 이번에 출동 전체를 개조했다고 보고하지 않습니다. 발견 장소의 생성·입장 자리·다른 유저 초대 규칙은 후속 원본 대조 대상입니다.</p>

<p>중복된 모험 본문 제목과 공통 필러 제목을 제거합니다. 상단 공통 메뉴 제목은 모험으로 유지합니다.</p>

<p>전체 버튼은 하단 공통 행동 영역에 둡니다. 긴 아이템·출동·기록 목록은 모달 본문만 스크롤합니다. 모달의 배경 입력을 막고, 처음 열 때 제목으로 초점을 옮기며 Tab 순환·Escape 닫기·열었던 버튼 복귀를 제공합니다. 모달은 웹뷰 전체가 아닌 모바일 프레임 안에 한정됩니다.</p>

<p>보상 벡터10종은 별도 데이터 경로에서 연결합니다. 숫자와 지급은 기존 실제 계산을 그대로 읽으며 그래픽 변경으로 보상량을 변경하지 않습니다. 데이터가 더 많거나 작은 기기에서는 필요한 목록 스크롤을 허용합니다.</p>

<p><b>게임 조작·자동 계산·현황판 조회로 역할 구분 · 신규 수치는 임시(나중에 결정).</b> 라포와 우정 포인트를 다음처럼 구분합니다.</p>

<div class="table-scroll"><table><thead><tr><th>구분</th><th>기준</th></tr></thead><tbody><tr><td>라포</td><td>내 소유 아이돌끼리의 관계</td></tr><tr><td>우정 포인트</td><td>친구 소유 아이돌과 함께 탐험했을 때 받는 별도 재화</td></tr><tr><td>직접 능력 배움</td><td>보류. 동료에게서 세부 능력이 직접 오르는 기능을 이번 개발에서 제외</td></tr><tr><td>우정 포인트 사용처</td><td>나중에 결정. 현재는 적립·보유·획득 표시를 제공</td></tr><tr><td>표시</td><td>재화 아이콘+수량. 긴 텍스트 보상 상자로 표시하지 않음</td></tr></tbody></table></div>

<p>내 아이돌 편성 → 친구 팀 선택(선택 사항) → 내 아이돌 관계 확인 → 탐험 → 기존 보상과 우정 포인트 확인·수령입니다.</p>

<p>편성의 핵심 버튼은 「친구와 함께」와 「내 아이돌 관계 보기」입니다. 복잡한 목표·행동 선택은 자동 추천으로 줄이는 안을 유지합니다.</p>

<p><b>B. 기존 봇에 아이돌 편성 연결</b></p>

<p>기존 미라·누리·하리·보라·다니·솔의 botId·소식·프로필을 사용하고 각 봇 아래 아이돌 팀을 연결합니다. 친구 프로필과 아이돌은 서로 다른 대상입니다.</p>

<p>친구 아이돌에는 소유자 ID+아이돌 ID·이름·초상화·몬스 연결·현재 활동 능력을 둡니다. 능력은 기존 탐험 기여와 결과 계산에 쓰며, 내 아이돌에게 복사하거나 전수하지 않습니다.</p>

<p>내 아이돌 최대5명과 참가 플레이어 정원은 별개입니다. 친구도 플레이어별 최대5명을 보내는 안이며 현재 공동 참가 정원은 내 팀 포함 최대6팀(친구 +5팀)이며 엔터파워로 친구 슬롯을 해금합니다. 전송 데이터가 있으면 우선 사용하고 단독 시험에서는 임시 편성을 준비합니다.</p>

<p>기존 power만 있는 옛 봇 기록은 도움·기여도를 보존합니다. 개별 소유자·아이돌 참여가 확인되지 않은 옛 기록에 우정 포인트를 소급 지급하지 않습니다.</p>

<p><b>C. 라포 정보창 — 내 아이돌끼리</b></p>

<p>「내 아이돌 관계 보기」 모달은 선택한 내 아이돌끼리만 비교합니다. 친구 아이돌은 친구 팀 정보에서 따로 보며, 내 라포 선이나 점수에 섞지 않습니다.</p>

<div class="table-scroll"><table><thead><tr><th>기본 화면</th><th>자세히 보기</th></tr></thead><tbody><tr><td>내 아이돌 얼굴·이름</td><td>같은 쌍의 원본 ID·최근 사건</td></tr><tr><td>현재 관계 단계</td><td>신뢰·이해·협력·긴장4축</td></tr><tr><td>이번 이야기 대상 두 사람·추천 이유</td><td>실제 최근 변화 전후·기록 시각</td></tr><tr><td>긴장이 있는 경우 별도 배지</td><td>원본 미연결·단계 판정 상태</td></tr></tbody></table></div>

<p>단계는 기존 표의 처음 봄→아는 사이→동료→친한 동료→단짝입니다. 긴장을 임의로 좋은 관계 평균에 합치지 않습니다. 미확인 값은 미확인으로 표시합니다.</p>

<p>자동 추천은 기존 쌍 선택 규칙과 회당1쌍을 유지합니다. 모든 내 아이돌 조합이 한 번에 상승한다고 안내하지 않습니다. 친구와의 라포 저장·새 교류 관계 체계는 이번 범위에서 만들지 않습니다.</p>

<p><b>D. 우정 포인트 — 별도 재화</b></p>

<p>나 혼자 또는 내 소유 아이돌끼리만 보낸 경우 우정 포인트는 없습니다. 내 다른 팀을 다른 친구로 판정하지 않습니다. 친구 명단에만 있거나 참여 요청만 보낸 상태도 적립 조건이 아닙니다.</p>

<p>함께 진행한 구간이 있어야 합니다. 이미 끝난 탐험에 이름만 추가해서 포인트를 받지 않습니다. 여러 친구가 함께해도 같은 내 회차의 포인트를 친구 수만큼 중복 지급하지 않습니다. 친구 능력이 높다는 이유로 포인트가 더 오른다는 규칙도 넣지 않습니다.</p>

<p>시간은 시험 화면의 클릭 횟수나 배속이 아닌 실제 탐험 진행 기록으로 계산합니다. 봇 친구는 오른쪽의 시험 자료로 같은 조건을 검증합니다. 실제 친구 계정 간 초대·접속·정산 서버는 별도 개발 대상입니다.</p>

<p><b>E. 아이콘과 수량 UI</b></p>

<p>아이콘은 기존 재화와 어울리는 토큰 모양입니다. 두 하트를 겹친 보라·분홍 표식과 금색 테두리로 돈·주사위·라포 표식과 구별합니다.</p>

<ul>
<li>보상 칩: 우정 포인트 아이콘 + ×10처럼 수량을 나란히 표시합니다.</li>
<li>보유 칩: 모험 안의 작은 재화 영역에 아이콘+현재 수량을 표시하는 안입니다.</li>
<li>이름은 접근성 이름/설명에서 확인할 수 있게 하고, 긴 텍스트 상자를 기본 보상 표현으로 쓰지 않습니다.</li>
<li>예상 보상과 실제 지급 완료를 구분합니다. 미수령 미리보기가 보유량을 올리지 않습니다.</li>
<li>친구가 없는 탐험의 미리보기에서는 포인트 보상을 숨기거나 지급 없음 상태로 표시합니다.</li>
<li>기존 상단 돈·주사위·보석3개 공통 영역을 무리하게4칸으로 바꾸지 않습니다.</li>
</ul>

<p>벡터 아이콘은 문서 리소스와 게임 데이터 경로에 보존하고 게임의 보유·보상 칩과 자동 계산 합계에 연결했습니다. 사용처가 정해지지 않았으므로 아이콘을 눌러 상점이나 소모 화면으로 이동시키지 않습니다.</p>

<p><b>F. 저장·정산·인계</b></p>

<p>우정 포인트는 공통 currency_master와 기존 지갑의 friendshipPoints 항목으로 연결합니다. 아이템 보상에서 재화를 참조할 필요가 있으면 같은 재화 ID로 연결하며 독립된 두 지갑을 만들지 않습니다. 도감 수집 기록이나 기존 라포 수치를 포인트 지갑으로 대용하지 않습니다.</p>

<p>완료 시 참여 소유자·아이돌·합류 시점·함께한 구간·최종 포인트를 회차에 고정합니다. 수령 ID로 돈·주사위·카드·라포·조각과 우정 포인트를 함께 저장하고, 실패하면 함께 되돌립니다. 재수령·재접속·모달 열람으로 중복 적립하지 않습니다.</p>

<p>전송 받은 포인트 잔액을 우선합니다. 미확인 전송을 임의의0으로 덮어쓰지 않습니다. 신규/이전 세션의 필드 추가는 버전과 기본값을 구분한 별도 이관으로 처리합니다. 정수·0이상·안전한 저장 범위로 검증합니다.</p>

<p>친구 지갑·소유권은 내 수령 처리에서 수정하지 않습니다. 옛 기록과 이미 받은 보상에 포인트를 소급하지 않습니다. 직접 능력 성장/학습 사건은 추가하지 않습니다.</p>

<p><b>G. 오른쪽 시험과 개발 순서</b></p>

<p>오른쪽에는 친구 팀·참가/합류 시점·초기 보유 포인트·임시 적립량·예상/실제 적립 결과를 둡니다. 기존과 같은 원버튼 시험 UX를 사용하며 별도 저장·초기화 버튼은 추가하지 않습니다.</p>

<div class="table-scroll"><table><thead><tr><th>순서</th><th>개발</th><th>확인</th></tr></thead><tbody><tr><td>1</td><td>내 라포 정보 모달</td><td>내 소유자만, 열람으로 값이 바뀌지 않음</td></tr><tr><td>2</td><td>기존 봇의 아이돌·친구 선택</td><td>소유자/아이돌/플레이어 구분</td></tr><tr><td>3</td><td>우정 포인트 규칙·아이콘·보유/보상 표시</td><td>혼자 없음·동행 적립·늦은 합류·복수 친구 중복 없음</td></tr><tr><td>4</td><td>신규 공통 재화·영수증·인계</td><td>실제 잔액 보존·한 번 수령·실패 되돌림·옛 기록 호환</td></tr><tr><td>5</td><td>원버튼 시험·버튼 규격·종류 필터·캡처</td><td>기존 출동/카드 성장/보상 보존</td></tr></tbody></table></div>

<p>직접 능력 배움은 보류, 우정 포인트 사용처는 미정입니다. 친구 편성·재화 등록·보유·보상·정산·전송 연결을 적용했습니다. 기존44PASS는 이전 구현 기록이며 이번 시험 결과는 4-11절과 최신 보고에 구분합니다.</p>


<h3 id="4-11-네-도구-구현계산조회-범위">4-11. 네 도구 구현·계산·조회 범위</h3>

<div class="table-scroll"><table><thead><tr><th>도구</th><th>하는 일</th><th>모험에서 보여 주는 것</th></tr></thead><tbody><tr><td>게임 시뮬레이터</td><td>실제 게임 플레이와 오른쪽 시험 조작</td><td>편성·친구 동행·우리 사이 보기·수동 보상 수령·조각 퍼즐</td></tr><tr><td>발란스 시뮬레이터</td><td>기존 시작 버튼으로 일차를 자동 진행</td><td>탐험·출동 횟수와 돈·주사위·우정 포인트·카드팩 계산량·조각·자동 퍼즐 완성 합계</td></tr><tr><td>발란스 툴</td><td>복사한 팀·지갑으로 지정 일수 자동 계산</td><td>조건별 합계와 최근 일별 결과. 원본 게임 저장은 변경하지 않음</td></tr><tr><td>성장 현황판</td><td>발란스 실행 결과를 읽기만 함</td><td>중앙 모험 누적 횟수 → 기존 진행·경제 상세에서 보상 합계 확인</td></tr></tbody></table></div>

<p>수동 플레이와 원버튼 재현은 게임 시뮬레이터에 둡니다. 발란스 시뮬레이터에는 별도의 편성·보상 받기·퍼즐 조작을 두지 않습니다. 카드팩은 ID·수량·계산 결과를 전달하며 실제 카드 지급·개봉 연결은 기획 정의(클로드)의 카드팩 작업과 연결합니다. 탐험의 아이돌 분신 연출과 몬스의 보유·합성 규칙은 유지하며, 출동 편성만 실제 기획사 보유·선택을 읽습니다.</p>

<p>기본 봇 6명에 3명씩 임시 편성하며, 전송된 소유자·아이돌 편성이나 명시적인 빈 명단을 우선합니다. 잘못된 잔액·편성을 임시 팀이나 0으로 덮지 않습니다. 우정 포인트와 친구 팀 정책은 <code>data/simulator/adventure-social.json</code>을 공통으로 읽습니다.</p>

<p><b>게임의 시험 순서:</b> 우정 동행 원버튼 시험 → 결과 → 보상 받기. 보상 받기 전에는 지갑을 올리지 않습니다. 절반 진행·도착까지 진행·늦은 합류도 오른쪽 시험 영역에서 재현합니다. 관계 모달에는 내 선택 아이돌의 얼굴·이름·관계 단계·이번 이야기 대상·4축 값과 확인 가능한 최근 변화량을 표시합니다. 친구 아이돌은 내 라포 쌍에 포함하지 않습니다.</p>

<p><b>발란스의 자동 정산:</b> 기존 일차가 끝날 때 현재 성장 단계·티켓 규칙·최상 결과 보상 표를 계산합니다. 같은 실행의 같은 날은 한 번만 정산하며 온라인·오프라인·반복 시험이 같은 자동 계산을 사용합니다. 돈·주사위·우정 포인트·조각·카드팩 계산량과 퍼즐 완성 횟수를 보여 줍니다. 카드팩 ID·수량은 외부 연결용 결과로 남기고 카드 지급·개봉을 새로 구현하지 않습니다.</p>

<p><b>발란스 툴:</b> 현재 게임 또는 전송 자료를 복사한 독립 계산입니다. 자료가 없을 때 공통 생성 5명을 사용합니다. 일수는 기본 3일·최대 60일이며 모두 임시(나중에 결정)입니다. 자동 계산 버튼 하나로 다음 구간을 계산하고 합계·최근 일별 결과를 비교합니다.</p>

<p><b>성장 현황판:</b> 발란스 실행의 모험 누적 횟수를 중앙 상태에 연결하고 기존 진행·경제 패널 상세에서 탐험·출동·돈·주사위·우정 포인트·카드팩 계산량·조각·퍼즐 결과를 읽습니다. 현황판 자체는 보상을 지급하지 않습니다. 기존 몬스 관찰·규칙·패널은 수정하지 않습니다.</p>

<p><b>조각 반복 퍼즐:</b> 기존 규칙(같은 아이템 9조각·3×3·주사위 27)을 게임 모험의 도감 아이템 상세 모달로 옮깁니다. 배치는 저장하지만 맞춘 미리보기만으로 조각이나 지갑을 바꾸지 않습니다. 보상 수령 시 실제 획득 조각·그림·회차·배치를 다시 검증하고 지갑·조각 사용·다음 회차를 함께 정산합니다. 실패하면 되돌리고 중복 수령은 지급하지 않습니다. 기존 12조각·24조각 회차 기록을 보존하며 기존 1회 도감 완성 보상과 반복 퍼즐 영수증을 구분합니다. 발란스에서는 같은 조각 누적과 반복 완성 결과만 자동 계산합니다.</p>

<p>현재 게임 탐험은 진행량/능력 기반을 유지하고 발란스 자동 계산은 기존 일별 표·성장 단계·티켓 순서를 사용합니다. 모든 콘텐츠를 동일한 게임 진행 엔진으로 교체했다고 안내하지 않습니다. 신규 수치는 임시(나중에 결정)이며 우정 포인트 사용처·직접 능력 배움은 미정·보류입니다.</p>

<p>발란스에서 전송한 직후 아직 성장 화면을 열지 않았어도 검증된 초기 기준 데이터를 읽어 조각·퍼즐 소비·티켓을 확인합니다. 전체 성장 저장과 초기 기준 저장을 구분하고, 깨진 데이터는 초기값으로 덮지 않고 오류로 표시합니다. 발란스 툴에서 게임 자료를 복사할 때도 퍼즐 사용 기록을 함께 복사합니다.</p>

<p>구현 연결은 <code>src/simulator/adventure/transfer.mjs</code> → 기존 balance-transfer → generated-source → 게임 모험입니다. 전달 정보와 기존 카드·경제 데이터는 각각의 기존 규격을 유지합니다. 자동 계산 합계는 현황판에서 읽기만 합니다.</p>

<h3 id="필요-시스템">필요 시스템</h3>

<p>기존 편성·공동 참가·기여·도시 연출·서사·공통 정산·도감 시스템을 사용합니다. 친구 프로필 아래 다른 소유자의 아이돌 편성, 내 관계 정보창, 기존 지갑·수령 기록 확장을 연결했습니다.</p>

<h3 id="화면연출-목록">화면·연출 목록</h3>

<p>기존 화면과 크기는 4-9절, 친구·관계·우정 포인트의 정적 시안은 4-10절을 기준으로 합니다. 추가 기능의 시안을 실제 구동 화면과 구분합니다.</p>

<h3 id="남은-결정">남은 결정</h3>

<p>우정 포인트 사용처·최종 적립량, 운영 입장 횟수·시간·보상 수치, 전용 도감 그림. 직접 능력 배움은 보류하며 실제 친구 서버는 별도 개발 대상입니다.</p>

<h3 id="4-12-1103-편성-개선-내-아이돌과-친구-아이돌">4-12. 11/03 편성 개선 · 내 아이돌과 친구 아이돌</h3>

<p>보낼 대상의 표기는 <b>보낼 아이돌 선택(0/5)</b>입니다. 내 아이돌은 최대 5명이며 등급에 따른 자리 사용량은 별도로 표시합니다. 내 아이돌 아래에는 같은 카드 형태의 <b>친구 동행 칸 5개</b>를 둡니다. 빈 칸에서 친구를 고르고, 그 친구가 가진 아이돌을 직접 골라 동행시킵니다. 친구 이름·선택 아이돌 수만 짧게 표시하고 누르면 편성을 바꿉니다.</p>

<p>내 팀 포함 최대 6팀입니다. 친구는 최대 <b>+5팀</b>, 친구 팀마다 아이돌 1~5명을 보낼 수 있습니다. 실제 친구 서버 연결 전에는 기존 모의 친구 또는 전송된 친구 명단으로 시험합니다.</p>

<p><b>두 성장 축:</b> 내 아이돌끼리의 라포 관계 개선과 친구 아이돌 동행의 우정 포인트를 분리합니다. 친구 아이돌을 내 라포 쌍에 섞지 않습니다. 직접 능력 상승과 추가 혜택 확장은 다음 작업입니다. 우정 포인트는 기존 적립·수령 규칙을 유지하며 사용처는 미정입니다.</p>

<p><b>데이터·검증:</b> 친구 소유자 ID 아래 선택한 아이돌 인스턴스 ID만 저장합니다. 출발할 때 선택 아이돌의 능력을 합산해 참가 기록에 고정합니다. 타 친구 아이돌·중복 ID·빈 편성·팀당 5명 초과·해금 팀 수 초과는 거부합니다. 전체 편성을 검증한 뒤 티켓을 소비합니다. 늦은 합류는 현재 해금 한도와 해당 탐험 출발 시 한도를 모두 지킵니다. 기존 진행 기록·수령 보상을 재작성하지 않습니다.</p>

<p>오른쪽 공동 탐험 시험도 현재 해금 수와 전체 6팀을 넘기지 않습니다. 자동 발란스 계산은 기존 1친구 팀 정책을 유지합니다. 편성 UI는 게임 시뮬레이터에만 둡니다. 출동·몬스·카드팩 지급 및 추첨은 이번 변경의 수정 대상이 아닙니다.</p>

<h3 id="4-14-1103-모험-ui-캐러셀과-출발-흐름">4-14. 11/03 모험 UI · 캐러셀과 출발 흐름</h3>

<p>현재 게임 화면은 이 절을 기준으로 합니다. 이전 4-13 서비스 배치는 로그로 보존했습니다.</p>

<div class="table-scroll"><table><thead><tr><th>영역</th><th>서비스 화면</th></tr></thead><tbody><tr><td>모험 발견 도감</td><td>메인 맨 위에 6개 분류·수량을 압축 표시. 메인 영역을 스크롤해도 위에 고정. 상세·완성 보상은 모달</td></tr><tr><td>티켓·재화</td><td>티켓 아이콘+수량, 탐험 종류, 우정 포인트를 한 줄에 표시</td></tr><tr><td>탐험 목록</td><td>한 화면에 3개 반이 보이는 캐러셀. 탐험 대표 8개·출동 대표 8개를 먼저 봅니다. 각 캐러셀은 따로 이동하며 탐험 전체는 종류별 6개 페이지, 출동 전체는 13개 목록으로 엽니다</td></tr><tr><td>대표 이미지</td><td>보컬·댄스·공연·뷰티·방송·팬·도시 여행·야간 8종 콘셉트 이미지. 탐험별 재지정 가능</td></tr><tr><td>탐험 준비</td><td>아이돌 편성→이야기 요약→보상을 하나의 스크롤 페이지에 배치. 상단 탭은 해당 위치로 이동</td></tr><tr><td>이야기 선택</td><td>메인에는 짧은 요약만. ‘탐험 보내기’→출발 전 이야기 모달→기본 설정 그대로 보내거나 주제·행동·관계 대상 변경</td></tr><tr><td>진행 중</td><td>친구 추가 칸을 숨김. 기존 도시 3D 위·아래의 진행 정보와 마일스톤은 유지하고 실제 내 아이돌·동행 친구 아이돌 전원이 이동하는 작은 카드 행렬을 표시</td></tr></tbody></table></div>

<p>이야기 주제는 서사를 바꿉니다. 행동은 대사·장면을 바꾸고, 경로·성장 단계별 관계 사건이 없을 때 라포 사건의 대체값으로도 사용됩니다. 화면에 현재 적용 방식과 예상 변화를 설명합니다. 이야기 선택으로 카드팩·돈·주사위 보상량이 증가하지 않으며, 라포와 보상은 기존처럼 완료 후 수령 시 반영합니다.</p>

<p>편성·친구·이야기·보상 선택은 탭 이동에도 보존됩니다. 출발 확인 전에 티켓을 사용하지 않습니다. 이동 카드는 출발 때 고정한 실제 참가자만 읽으며 친구의 아이돌과 내 아이돌을 구분합니다. 몬스 데이터·보유·능력과 출동의 뉴스·비행·대결은 변경하지 않습니다.</p>

<p>대표 이미지는 UI 설정의 covers.images / covers.categories / covers.keywords / covers.routes로 관리합니다. 개별 탐험의 로컬 이미지 경로가 있으면 우선하며, 그렇지 않으면 제목·장소 키워드→분류→기본 그림 순으로 선택합니다. 외부 URL은 그림으로 삽입하지 않습니다. 8종은 정적 512px 썸네일이며 원본 생성 이미지도 별도로 보존합니다.</p>

<p>편성 페이지에는 내 아이돌·친구 편성, 선택한 이야기 요약, 큰3칸 보상 카드·우정 포인트·추가 조각 안내가 이어집니다. 상단 탭을 누르면 같은 페이지의 목표 구간으로 이동하고 상단 탭은 고정됩니다. 실제 탭 패널 교체나 다른 페이지 전환을 하지 않습니다. ‘목록’은 모험 메인으로 돌아갑니다.</p>

<p>보내기 모달은 주제·행동·관계 대상·현재 관계 예상·대사 미리보기를 보여 줍니다. 기본 선택을 그대로 보내는 버튼을 제공하며, 개별 선택을 수정한 뒤 다시 출발 확인으로 돌아옵니다. 닫기·Escape는 출발하지 않고 편성을 유지합니다. 정산·티켓 소모는 기존 start/claim 흐름만 사용합니다.</p>

<p>마일스톤 구간은 기존 진행 참고값 0/25/55/80/100%를 표시합니다. 내 실제 편성 및 동행 친구 편성의 고정 기록을 합쳐 이동 카드를 만들며, social/helper의 동일 팀 표현은 한 번만 표시합니다. 10명은10명, 최대6팀30명은30명이며 작은 카드가 여러 줄로 이동합니다. 정보가 없는 과거 기록에 가짜 인원을 채우지 않습니다. 경로 이동 위치는 실제 진행률이며 짧은 걸음 움직임만 반복합니다. 정지는 걸음도 멈추고, 움직임 줄이기 설정에서는 반복 움직임을 끕니다.</p>

<p>이 변경은 게임 시뮬레이터의 모바일 UI 작업입니다. 발란스 자동 계산·성장 현황판에는 플레이용 메뉴를 옮기지 않으며 기존 전송 계약·카드팩 지급 경계를 보존합니다.</p>

<h3 id="4-15-내-아이돌-관계-관계-허브뉴런-공통-데이터">4-15. 내 아이돌 관계 · 관계 허브·뉴런 공통 데이터</h3>

<p>‘내 아이돌 관계 보기’는 눈에 띄는 버튼으로 표시합니다. 현재 탐험의 편성 여부와 무관하게 내 아이돌 전체의 관계를 모달로 볼 수 있습니다. 5명 팀이면 10쌍이며 친구 아이돌은 내 라포에 섞지 않습니다.</p>

<p>관계도에서 얼굴·관계선을 보고 두 아이돌을 고르면 가까움·상호 신뢰·이해·협력·긴장과 현재 단계를 숫자·막대로 확인합니다. 가까움은 현황판과 같은 기존 산식을 사용합니다. 미확인 값은 대시로, 실제0은0으로 구분합니다.</p>

<p>게임 시뮬레이터의 모험·관계 허브·뉴런은 같은 팀 ID와 저장된 관계값을 우선합니다. 처음 함께하는 팀의 기록이 없으면 등록된 라포 시작 범위·성격 궁합 규칙으로 없는 쌍만 계산합니다. 새 성격·새 발란스 값을 만들어 넣지 않습니다. 기존0·빈 값·변화 기록을 초기화하지 않습니다. 시험에서 누적한 사본과 실제 저장은 구분합니다.</p>

<p>라포 시작 계산과 저장 쌍 우선 처리를 current-team-rapport.mjs로 공통화했습니다. 관계 허브가 현재 후보의 정확한 쌍만 골라 읽더라도, 전원에 적용되는 */* 시작 규칙을 공통 계산기가 함께 읽습니다. 같은 후보 ID로 같은 규칙을 사용하므로 화면을 오가며 시작값을 다시 추첨하지 않습니다. 모험의 준비 화면은 선택한 아이돌의 사건 대상 쌍과 내 전체 관계 정보의 쌍을 구분합니다.</p>

<p>개별 쌍 CSV의 직접값과 충돌은 원본대로 보존합니다. 중복·잘못된 저장 형식은 새 값으로 덮지 않고 확인 대상으로 남깁니다. 저장에 명시된 null을 새 시작값으로 채우지 않습니다. 공통 조회와 관계 모달 열기는 지갑·보상·라포 저장을 변경하지 않습니다.</p>

<p>관계 허브의 1회/자동 시험은 같은 관계 계산기로 이전 결과를 누적하고, 뉴런은 같은 사본의 쌍·축을 읽습니다. 원래 팀의 저장 관계를 바꾸는 동작과 구분하며 모험의 실제 수령은 기존 정산 경로를 사용합니다.</p>
