## 1. 목적

1. 제안서 허브에 「타일로 보기」와 함께 「카드로 보기」를 추가합니다. 기존 타일 보기는 지우지 않습니다.
2. 카드로 보기는 제안서를 **순서대로 편하게 읽는 화면**입니다. 한 번에 한 장의 제안서에 집중하고, 앞뒤 제안서는 양옆에서 보이게 합니다.
3. 카드는 **포켓몬 카드 같은 실제 게임 카드(TCG)** 구조로 만들고, 우리 게임의 디자인 컨셉인 **유리 복셀 캐릭터**의 느낌을 살립니다. 모으고 싶은 카드처럼 보이는 것이 목표입니다.
4. 각 카드에서 중요도, 구현 난이도, 장 수, 현중 확인 상태(통과/대기)를 한눈에 봅니다. 통과/대기 상태는 타일 보기와 같은 저장 위치를 씁니다.

## 2. 사용 흐름

> v0.3 변경: 2항의 「가운데 큰 카드」는 「화면 전체 배경 + 큰 헤드라인 카피」로, 5항의 카드 뒷면은 「자세히(F)」 패널로 바뀌었습니다. 6항의 통과/대기는 타이포 영역 버튼과 하단 카드 도장으로 표시합니다. 나머지 흐름은 같습니다.

1. 허브 상단의 보기 전환에서 「카드로 보기」를 누릅니다.
2. 첫 카드(01 간략판 제안서)가 가운데에 크게 놓이고, 양옆에 이전·다음 카드가 기울어진 채 작게 보입니다. 주소에 `#economy`처럼 덱 id가 있으면 그 카드에서 시작합니다.
3. ←/→ 키, 마우스 휠, 스와이프, 하단 화살표, 하단 목록 칸으로 넘깁니다. 옆 카드를 누르면 그 카드가 가운데로 옵니다.
4. 가운데 카드를 누르면 **바로 그 제안서가 열립니다**(타일과 같은 주소). 브라우저 뒤로 가기로 카드 로비에 돌아오면 주소의 `#덱id`로 같은 카드에서 다시 시작합니다.
5. 카드 오른쪽 아래 「뒤집기」 버튼이나 F 키로 뒷면을 봅니다. 뒷면에는 장 목록(TRACK 01~), 핵심 3줄, 결정 대기 수, 마지막 수정 시각이 있습니다. TRACK 줄을 누르면 해당 장(`#slide-N`)으로 열립니다.
6. 다 읽은 뒤 뒷면 또는 하단 바에서 「통과」 또는 「대기」를 누릅니다(P/H 키, 0 키는 해제). 통과 카드에는 홀로그램 포일과 금빛 반짝임이 생기고, 대기 카드는 채도가 낮아집니다.
7. 상단 「타일로 보기」를 누르면 기존 타일 허브로 돌아갑니다.

## 3. 화면 구성(메인창 와이어 · v0.4 카드 주인공)

카드가 화면의 중심입니다. v0.3 레퍼런스에서 얻은 타이포 원칙(작은 라벨 → 아주 큰 카피 → 작고 흐린 부제, 그림은 칸에 가두지 않음)은 **카드 한 장 안에** 적용합니다. 배경은 현재 카드 그림을 크게 흐려 번지게 하는 정도로만 씁니다.

### 4-4. 이미지 크롭 규칙

1. 일러스트 창은 4:3입니다(v0은 5:4). `object-fit: cover`로 채우고, 덱마다 초점(`object-position`)을 따로 둡니다.
2. 카드구성20 대표 카드처럼 **그림 안에 이미 카드 틀과 이름이 있는 이미지**는 1.12배 확대하고 초점을 위쪽 34~40%에 둡니다. 흰 틀과 아래 이름 칸이 창 밖으로 나가고, 캐릭터의 얼굴부터 허리까지가 남습니다.
3. 가로 그림(도시, 무대)은 가운데 50%를 기본으로 하고, 한 그림을 두 덱이 쓰면 초점을 다르게 둡니다(예: `mons-td-defense-v1.png`는 악귀 덱에서 위쪽 몬스와 악귀, 전투 덱에서 아래쪽 무대).
4. 그림에 UI 화면 캡처나 글자가 많은 시안은 대표 그림으로 쓰지 않습니다.
5. 그림을 못 불러오면 창에 「그림 없음」을 표시합니다.

## 7. 통과/대기 체크와 타일 연동

### 7-1. 찾은 것

- 타일 허브 `concept-flow.html`에는 **통과/대기 체크 기능과 저장 상태가 없습니다.** `localStorage`, `sessionStorage`를 쓰지 않습니다.
- 타일의 배지(「정한 것 있음」 · 「결정 대기만」 등)는 파일 안의 고정 목록 `decidedIds`(10/01 14:50 기준)에서 나옵니다. 사용자가 바꿀 수 없습니다.
- 덱 목록은 같은 파일 안의 `tiles` 배열(이름·부제), `deckOpen` 객체(열 주소), `detailGroups`(묶음)에 있습니다. 별도 데이터 파일은 없습니다.
- 기획 도구(`src/tools/planningDocs/main.ts`)는 허브를 iframe으로 띄우고 `postMessage({pdConcept})`로 열림/닫힘만 주고받습니다. 저장 상태는 없습니다.

### 7-2. 제안: 공용 키 하나

| 항목 | 값 |
|---|---|
| 저장소 | 브라우저 `localStorage` (같은 주소 `http://127.0.0.1:7007`에서 타일·카드가 함께 읽습니다) |
| 키 | `kpm.proposalReview.v1` |
| 값 | `{"v":1,"updated":"ISO 시각","items":{"economy":{"s":"pass","at":"ISO 시각","by":"card"},"dice":{"s":"hold",...}}}` |
| 상태 | `pass`(통과) · `hold`(대기) · 항목 없음(미확인) |
| 같은 버튼 다시 누름 | 해제(미확인) |
| 동기화 | `storage` 이벤트로 다른 탭(타일 보기)에서 바꾸면 즉시 반영합니다. |
| 덱 id | 타일 허브의 `tiles[].id`를 그대로 씁니다(`economy`, `p00`, `deck0930` 등). |

### 7-3. 시안의 허브 데이터 공유

- 카드 시안은 시작할 때 `concept-flow.html`을 읽어 `deckOpen`(열 주소)과 `tiles`(이름)를 가져옵니다. 타일에서 주소가 바뀌면 카드도 같은 주소를 엽니다.
- 각 덱 HTML을 읽어 `.slide` 개수와 제목으로 장 수와 TRACK 목록을 갱신합니다. 읽기에 실패하면 07:05 스냅숏 값을 씁니다.

`concept-flow.html`의 `tileCard()`에 아래를 더하면 타일에도 같은 상태가 보입니다. 이번 작업에서는 허브 파일을 고치지 않았습니다.
