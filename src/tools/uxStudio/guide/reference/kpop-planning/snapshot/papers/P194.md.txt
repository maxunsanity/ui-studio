# P194 · 시즌 · 상세 기획서

**이 문서는** 공용 시즌 안에서 조건형 곡 제작·발매·차트·파이널의 기간을 맞추고, 시즌 끝에 남길 기록과 정리할 상태를 나눕니다.

**보는 법** 1장 공용 시즌 → 4장 기간·마감·보존 → 7장 통합 순서로 읽습니다. 공용 게임에서 같은 실행의 앨범·차트·파이널 시험 기록을 확인합니다. 운영 달력·시즌 전환·계정 보존은 별도 연결 항목입니다.

**지금 상태** 9주 시즌·주간 페스티벌·9주차 월드·보존 후 초기화를 상세 기획했습니다. 현행60일 운영 원본과 주간/월드·계정 보존 연결은 변경 대기입니다.

### 콘텐츠 경계

공용 시즌 날짜·콘텐츠 마감·졸업·초기화·보존을 관리합니다. 개인의 제작 조건과 곡 성적은 [음원](../%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EC%9D%8C%EC%9B%90%EC%98%81%EC%83%81_%ED%95%B5%EC%8B%AC%EC%A0%9C%EC%95%88%EC%84%9C.html), 최종 결과는 [페스티벌](../%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EC%9B%94%EB%93%9C%ED%8E%98%EC%8A%A4%ED%8B%B0%EB%B2%8C_%ED%95%B5%EC%8B%AC%EC%A0%9C%EC%95%88%EC%84%9C.html), 자원별 보존은 각 원본을 따릅니다.

## 4. 상세 기획

### 앨범 소규모 차트 연결

앨범 발매로 열리는100명·약1일 순위 이벤트 게임입니다. 현재 로컬은 본인+가상99명을 명시합니다. 첫100위에서 출발하고 후속은 현재 보유 팬·계층과 직전 마감 최종성적으로 시작합니다. 보드 신규 팬 증가를 주력으로, 주사위 소모를 보조로 점수를 쌓아 현재 순위별 돈·팬·기존 능력을 적립하고 다음1번START에서 정산합니다. 만료 뒤 신규 효과는 끝나며 얻은 성장·미정산 적립·최종 성적은 보존합니다. 보통 활동은4~5번째 첫1위 도전, 성장 좋은5~8번째 입장1위도 가능하며 차수별 고정 등수는 없습니다. 메인 차트 말풍선·활동/다음 시작 예상 게이지는 같은 규칙을 읽습니다. [앨범 차트 정본](../%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EC%9D%8C%EC%95%85%EB%B0%A9%EC%86%A1%EC%B0%A8%ED%8A%B8_%EA%B8%B0%ED%9A%8D%EC%84%9C.html)에서 성장곡선·원본·계산·저장·실제 구현을 봅니다. 실제 유저 매칭 서버는 미구현이며 유저 투표는 없습니다.

### 시즌과 콘텐츠의 시간 기준

시즌은 공용 달력의 총9주입니다. 주차는 시즌 시작 기준으로 계산하고 늦게 데뷔해도 같은 주차를 사용합니다. 매주 한 번 페스티벌을 진행하며 마지막9주차에 월드페스티벌을 진행한 뒤 시즌을 초기화합니다. 주간·월드의 등록·공개·조회/추천·투표·심사·집계·발표 시간은 각각 구분합니다. 각 화면에서 자기 날짜로 회차를 만들지 않습니다.

| 주차 | 시즌 일차 환산 | 콘텐츠 |
|---|---|---|
| 1주 | 1~7 | 성장·발매·앨범 성장 차트·주간 페스티벌 |
| 2주 | 8~14 | 성장·다음 발매·주간 페스티벌 |
| 3주 | 15~21 | 성장·다음 발매·주간 페스티벌 |
| 4주 | 22~28 | 성장·다음 발매·주간 페스티벌·선택 지역 활동 |
| 5주 | 29~35 | 성장·다음 발매·주간 페스티벌 |
| 6주 | 36~42 | 성장·다음 발매·주간 페스티벌 |
| 7주 | 43~49 | 성장·다음 발매·주간 페스티벌 |
| 8주 | 50~56 | 성장·남은 제작 기회·주간 페스티벌 |
| 9주 | 57~63 | 월드페스티벌 등록·홍보·평가·최종 집계·보존·시즌 종료 |

9주=63일은 주당7일 환산입니다. 실제 서버 공용 일차와 가속 시험 일차를 구분합니다. 요일·시작 시각·휴지기와9주차 주간 회차의 별도 중복 개최 여부는 운영 달력에서 확정해야 합니다. 위 표는9주차를 월드 주간으로 표현한 기획이며, 확인되지 않은 주중 배분을 넣지 않습니다.

### 앨범 차트와 페스티벌의 분리

앨범 차트는 유저 투표 없이 무작위 소규모 그룹에서 팬·성장·앨범 실적을 비교하는 콘텐츠입니다. 발매별 약1일 리그·성장 유사 매칭·보드 실적과 돈 효과 종료를 정의하며 정확한 기간/지급 방식은 별도로 정합니다. 주간·월드페스티벌은 실제 유저의 참여·조회/추천·투표·유저 채점단 등 평가를 조합하는 별도 콘텐츠입니다. 팬 투표100%로 처리하지 않습니다. 두 콘텐츠의 순위ID·결과·보상 원장을 섞지 않습니다.

데뷔곡을 포함해 최대8개의 싱글을 발매할 수 있습니다. 모든 유저에게8곡을 의무 지급하지 않습니다. 주차가 바뀌어도 개인 제작의 기간·미션·성장 문턱을 건너뛰지 않습니다. 9주차 월드는 이미 발매한 곡 중 한 곡으로 출전하며, 상세 참가 자격과 마감은 페스티벌 정본을 따릅니다.

### 시즌 상태와 전환 순서

~~~mermaid
flowchart LR
 A["시즌 진행·주간 회차"] --> B["9주차 월드"]
 B --> C["최종 집계 동결"]
 C --> D["돈 보상·수령 중복 검증"]
 D --> E["계정 보존 기록 완료"]
 E --> F["기존 시즌 초기화"]
 F --> G["다음 시즌"]
~~~

| 상태 | 허용 행동 | 전환 조건 |
|---|---|---|
| active | 성장·조건형 발매·앨범 차트·주간 활동 | 공용 달력 진입 |
| world | 월드 등록·정해진 기간의 홍보/참여/평가 | 9주차 도달 |
| finalizing | 유효 행동 검증·점수와 순위 동결 | 평가 마감과 서버 검증 완료 |
| rewarding | 대상별 돈 보상 원장 기록 | 순위·규칙 버전 동결 |
| archiving | 곡·성적·발표·귀속 기록 보존 | 지급/미지급 상태와 영수증 보존 |
| resetting | 원본 시스템의 시즌 항목 초기화 | 시즌 종료·미결 정산 처리·보존 완료 |
| next | 새 시즌 범위 생성 | 이전 season_id 전환 영수증 확인 |

위 상태 이름은 개발 계약 제안입니다. 화면 클릭만으로 공용 시즌을 초기화하지 않습니다. 최종 결과가 없거나 보상/보존 저장이 실패하면 해당 단계에서 재시도하고 초기화를 먼저 진행하지 않습니다. 전환 키는 account_id·from_season_id·to_season_id로 중복 실행을 막습니다. 실제 서버 제작은 현재 범위에 포함하지 않으며 로컬 시뮬레이터는 같은 계약의 시험임을 표시합니다.

| 시설·대지·도시 진행 | startNewSeason의 freshBoard 경로 | 음악 모듈에서 별도 초기화식을 만들지 않음 |
| 팬 계층 | 콘크리트 팬 보존, 라이트·코어·휴덕·악개·안티 정리 | 새 시즌 차트 팬 입력은 초기화 후 실제 계층을 다시 읽음 |
| 돈·주사위 | 현행 함수는 유지, 이월 정책 미정 기록 | 음악 순위 보상을 임의 삭제하거나 추가 이월 정책을 만들지 않음 |
| 일반 카드·미개봉 팩 | 현행 시즌 초기화 경로 사용 | 수집 보상 claimed 기록은 기존 중복 방지 범위 유지 |
| 몬스 보유·합성·행복 | 기존 resetMonsSeason과 해당 정본 | 계정 보존과 시즌 임시 상태를 분리 |
| 발매 앨범·차트·페스티벌 결과 | 보존 대상과 계정 인터페이스 연결 필요 | 현재 실행 저장을 계정 영구 보존 완료로 오인하지 않음 |
| 크루 소속 | 기존 기획의 계정 소속 보존 | 시즌 기여/회차와 소속 자체를 분리 |
| 곡 제작 기준점·활동·투표권 | 시즌 범위와 마감 규칙에 따라 새 범위 | 지난 시즌 지표로 새 제작/평가를 우회하지 않음 |

근거는 기존 경제 seasonProgress/startNewSeason, 팬 seasonKeepConcrete, 몬스 정본과 저장 기획입니다. 기록장·명예의 전당의 계정 보존 규칙이 현행 로컬 삭제 경로와 다른 경우 보존 단계를 먼저 연결해야 합니다. 소식/응원 알림과 공식 결과 영수증의 보관 범위도 분리합니다.

### 데이터 계약과 실패 처리

- season_id·starts_at·ends_at·week_index·calendar_version·rule_version을 회차와 모든 평가/보상에 보관합니다.
- 서버 시간으로 경계를 판정하고 로컬 시계 변경·자정·재접속·지연 도착 때문에 회차가 중복되지 않게 합니다.
- 기준 시각 이전에 발생했지만 늦게 도착한 사건의 인정 마감과 정정 방식은 운영 규칙으로 둡니다.
- 종료 직전 발매·제작 중인 초안·미등록곡·늦은 참가를 구분합니다. 이전 시즌 결과는 읽기 전용으로 보존합니다.
- 보상 계획은 돈만 사용합니다. 금액은 임시 발란스 테이블과 원장에 버전을 남기며, 순위 재표시·새로고침·전환 재시도로 돈을 다시 지급하지 않습니다.
- 월드 최종 발표 전 기준·가중치·표 인정 규칙을 바꾸지 않습니다. 오류 정정은 원결과와 정정 근거를 함께 남깁니다.

### 현재 구현과 필요한 변경

현행 season_config.season_days는60이며 최신9주 기획과 일치하지 않습니다. 기존 구현은 같은 실행의 앨범·크루·차트·파이널 기록 보존 시험과 기존 보드 정산 연결이 있습니다. 주간/월드 회차 타입·9주 달력·계정 보존 후 전환 조정은 미구현입니다. 60일 원본을 읽는 실제 도구를9주 적용 완료로 표시하지 않습니다.

표 담당이 공용 season_days를63으로 정합화한 뒤 같은 원본을 읽는 게임·자동 발란스·툴이 일치하는지 검증합니다. 별도의 음악 전용60/63일 원본을 중복 운영하지 않습니다. 현황판은 전환 결과를 읽으며 수동 초기화·회차 생성 기능을 추가하지 않습니다.

### 구현 원본과 운영 원본의 경계

- 기능 조작은 게임 시뮬레이터에서 수행합니다. 모바일 하단에는 크루·월드페스티벌·앨범 바로 가기를 기존 메뉴 아래에 배치하며, 최종 UI 기획에 맞춰 재배치할 수 있습니다. 오토플레이는 자동 시험, 현황판은 결과 조회입니다.
- [음악 규칙 원본](../../../../../data/music_career/music_career_rules.json)의 미정 수치는 null로 유지합니다. 원본·단위·기준 사건이 없으면 대기하며 시험값을 운영값으로 저장하지 않습니다.
- [실제 보드 연결](../../../../../src/simulator/music-career/game-bridge.mjs)은 관측한 방송·공연과1번 START 통과만 받아 기존 지갑·팬·능력 입구에 적용합니다. UI의 출발점 통과 시험은 시험 정산 기록만 만들며 실제 지갑에 지급하지 않습니다.
- 앨범 능력 보상 계수/원본 영수증은 canonical_score 최종점수입니다. 각 합류 멤버에 전량을 배분하고, 공용 게임은 그대로, 오토플레이는 검증된 기존 표시 배율 K를 한 번 적용합니다. 재능·주사위·포지션 배율은 다시 곱하지 않으며 기존 개인 단계 상한·일일 제한을 지킵니다. 조건 판정은 별도로 관측값과 문턱의 단위를 맞춥니다.
- 실제 지역 방문·현지 공연 원장, 운영 파이널 자격/달력, 수상별 reward_group 매핑, 계정 명예 기록 인터페이스는 미공급입니다. 지역 선택 시험과 결과 보존을 실제 방문·시상 지급·계정 영구 저장 완료로 처리하지 않습니다.

### 수락 기준

같은 실행과 곡 참조를 사용하고, 미정값을 확정0이나 임의 보상으로 바꾸지 않습니다. 실제 보드 사건과 시험 조작을 구분하며 같은 활동·표·정산은 한 번만 반영합니다. 기획과 계산·실제 화면 검수 범위를 나눠 기록합니다.

### 뺀 것·옮긴 것·보존한 것

이전 본문과 변경 근거는 하단 로그에서 보존합니다. 다른 콘텐츠 전체 준비중 목록과 전체 기획·표 재검수는 이 기능 개발 범위에 포함하지 않습니다.


### 후속 로컬 구현과 남은 연결

9주 조회 달력과 공용 길이 불일치 가드를 구현했습니다. 현재60일 원본은 유지하므로 실제 게임을9주 적용 완료라고 표시하지 않습니다. 계정 보존·보상 성공 뒤 기존 reset 전환은 별도 구현/담당 원본 연결 대기입니다.

관련 통합시험과 별도 팬 단조 경계3,751건을 통과했습니다. 정확한 최신 통과 수와 명령은 공용 보고·검증 로그에 기록합니다. 실제 공용게임의 명시 시험 조건으로 신규 발매 자동 연결·메뉴 왕복·새로고침 보존을 확인했습니다. 새 주간/월드 참여집계·운영 순위/지갑지급·63일 초기화를 완료한 검수가 아닙니다.
