<p>주간·월드의 일반 입구는 모두 개인 신청입니다. 내 발매 앨범을 선택하고 같은 화면에서 신청하며, 월드는 성공 뒤 내 출전곡 참여 로비를 엽니다. 개인/크루 선택·선택되지 않은 곡 확인·별도 준비 단계를 두지 않습니다. 크루 소속·직책과 관계없이 크루장과 멤버도 개인 월드에 출전할 수 있습니다.</p><p>크루 월드 신청은 크루 페이지에서 크루장에게만 <h3>대표곡과 나머지 곡 (적용 규칙)</h3>
<p>대표곡 한 곡과 나머지 발매곡이 함께 실적을 쌓습니다. 대표곡의 비중을 높게 두고 최근 발매곡을 우대하며 발매 후 시간이 흐르면 효율이 감소합니다. 대표곡 계수·일반곡 계수·시간 감쇠 구간·수익 및 성장 계수는 데이터에서 조절합니다. 미정값을0으로 확정하지 않습니다.</p>
<h3>실제 활동 원본 (임시 시안)</h3>

<p><strong>제안(검수 대기) · 기획만.</strong> 방송27/28/30·공연32/33/35는 첫 발매 전에도 홍보·버스킹 활동을 합니다. 첫 발매 후에는 같은6개 위치의 표시명과 간판/무대 조명이 정식 방송·공연 상태로 바뀌고, 발매곡 연계 실적을 기록합니다.</p>

<h3>현재 연결과 실행 역할</h3>
<p>기존 방송국·콘서트장의 실제 관측 사건을 곡별로 한 번 기록합니다. 활동 당시의 대표곡 여부와 발매 경과일을 보존하며 미정 계수는 정산 대기입니다. 출발1번의 실제 통과가 누적 보상을 정산하고, 같은 통과·활동·영수증은 재지급하지 않습니다. UI의 시험 통과는 시험 활동의 정산 기록만 만들고 지갑에 지급하지 않습니다. 실제 보드 통과의 돈·팬·능력 지급은 자동/게임 엔진 구현과 회귀시험으로 검증합니다. 능력은 canonical_score 최종점수로 연결하며 공용 게임은 배율1, 오토플레이는 기존 K 표시만 한 번 적용합니다.</p>
<p>기능 조작 화면은 게임 시뮬레이터입니다. 상단은 <strong>데뷔 준비 → 앨범 활동 → 차트 → 파이널</strong>의 마일스톤으로 현재 단계와 다음 목표를 보여 줍니다. 조건·앨범 편집·다른 기록·시험 운영 입력은 접어 두고 현재 행동을 먼저 표시합니다. 오토플레이 테스트는 같은 규칙으로 자동 진행하고 현황판은 결과를 읽습니다. 현황판에 별도 제작·발매·투표 조작이나 보상 계산을 만들지 않습니다.</p>
<p>실제 노래·외부 배포·실제 회원 서버는 현재 연결 전입니다. 시험 회원·시험값은 표시를 유지하고 운영 원본을 덮어쓰지 않습니다.</p>

<h3>구현 원본과 운영 원본의 경계</h3>
<ul>
<li>기능 조작은 게임 시뮬레이터에서 수행합니다. 모바일 하단에는 크루·페스티벌·앨범·차트 바로 가기를 기존 메뉴 아래에 배치하며, 최종 UI 기획에 맞춰 재배치할 수 있습니다. 오토플레이는 자동 시험, 현황판은 결과 조회입니다.</li>
<li><a href="../../../../../../data/music_career/music_career_rules.json">음악 규칙 원본</a>의 미정 수치는 null로 유지합니다. 원본·단위·기준 사건이 없으면 대기하며 시험값을 운영값으로 저장하지 않습니다.</li>
<li><a href="../../../../../../src/simulator/music-career/game-bridge.mjs">실제 보드 연결</a>은 관측한 방송·공연과1번 START 통과만 받아 기존 지갑·팬·능력 입구에 적용합니다. UI의 출발점 통과 시험은 시험 정산 기록만 만들며 실제 지갑에 지급하지 않습니다.</li>
<li>앨범 능력 보상 계수/원본 영수증은 canonical_score 최종점수입니다. 각 합류 멤버에 전량을 배분하고, 공용 게임은 그대로, 오토플레이는 검증된 기존 표시 배율 K를 한 번 적용합니다. 재능·주사위·포지션 배율은 다시 곱하지 않으며 기존 개인 단계 상한·일일 제한을 지킵니다. 조건 판정은 별도로 관측값과 문턱의 단위를 맞춥니다.</li>
<li>실제 지역 방문·현지 공연 원장, 운영 파이널 자격/달력, 수상별 reward_group 매핑, 계정 명예 기록 인터페이스는 미공급입니다. 지역 선택 시험과 결과 보존을 실제 방문·시상 지급·계정 영구 저장 완료로 처리하지 않습니다.</li>
</ul>
<h3>수락 기준</h3>
<p>같은 실행과 곡 참조를 사용하고, 미정값을 확정0이나 임의 보상으로 바꾸지 않습니다. 실제 보드 사건과 시험 조작을 구분하며 같은 활동·표·정산은 한 번만 반영합니다. 기획과 계산·실제 화면 검수 범위를 나눠 기록합니다.</p>
<h3>뺀 것·옮긴 것·보존한 것</h3>
<p>이전 본문과 변경 근거는 하단 로그에서 보존합니다. 다른 콘텐츠 전체 준비중 목록과 전체 기획·표 재검수는 이 기능 개발 범위에 포함하지 않습니다.</p>
<h3>후속 로컬 구현과 남은 연결</h3>
<p>기존 방송·공연 실적과 실제1번 START 정산 경로를 보존합니다. 발매 자동 공유·등록은 활동 사건이나 즉시 보상을 만들지 않습니다. 성장 차트는 활동합계를 상대 정렬하지 않으며 필요한 기존 활동 실적을 명시 metric으로 받을 수 있습니다. 차트 돈 견적은 기존 START의 돈·팬·부분 능력을 다시 지급하지 않습니다.</p>
<p>관련 통합시험과 별도 팬 단조 경계3,751건을 통과했습니다. 정확한 최신 통과 수와 명령은 공용 보고·검증 로그에 기록합니다. 실제 공용게임의 명시 시험 조건으로 신규 발매 자동 연결·메뉴 왕복·새로고침 보존을 확인했습니다. 새 주간/월드 참여집계·운영 순위/지갑지급·63일 초기화를 완료한 검수가 아닙니다. <a href="../../../%EC%A6%9D%EA%B1%B0/20261103_142753_%EB%8B%A8%EC%9D%B4_9%EC%B0%A8_%EC%95%A8%EB%B2%94%ED%81%AC%EB%A3%A8_%EC%9B%94%EB%93%9C%ED%8E%98%EC%8A%A4%ED%8B%B0%EB%B2%8C_%ED%86%B5%ED%95%A9%EA%B0%9C%EB%B0%9C/release-followup-actual.jpg">실제 발매 자동 연결 검수 화면</a></p>
<p><a href="/docs/planning/balance-tool.html?topic=balance_topic_music">음악 발란스 주제</a>는 같은 음악 원본을 읽는8행 상태표입니다. 로컬 이벤트는 팬/보드 목표와1회 반영 한도를 원표에서 표시하고 실제 저장 결과를 조회합니다. 현황판은 자동 결과 조회이며 제작·발매·투표 조작을 넣지 않습니다.</p>
