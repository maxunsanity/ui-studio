<section class="part" id="part-1"><h2>1. 개요</h2>

<p>출처: (합침) <a href="/docs/planning/proposal-concept/growth.html" data-paper-path="docs/planning/proposal-concept/growth.html">건물 성장 제안서</a>, 건설 시뮬레이터와 시설·단계 표.</p>

<p>9시설은 사옥, 보컬 녹음실, 댄스 연습실, 콘서트장, 뷰티 스튜디오, 예능 방송국, 프로듀싱 스튜디오, 팬샵, 아카데미입니다. 각 시설은 전체 0~30단계로 표현하고, 본관과 부속 A·B의 세 동이 차례로 자랍니다. 플레이어는 보드 위치와 관계없이 건설 화면에서 시설을 고르고 돈으로 증설합니다.</p>

</section><section class="part" id="part-3"><h2>3. 구동 방법·시뮬레이션</h2>

<p>화면 흐름: 공용 하단 건설 → 도시 지도와 선택 상세 → 견적 확인·구매 → 조립 연출 → 저장된 도시. 이전 화면 확인은 아래 진행표의 연결 보고에서 볼 수 있습니다. 이번 문서 수정에서 새 실행·캡처는 하지 않았습니다.</p>

<h3 id="건설-시뮬레이터-열기"><a href="/docs/planning/game-simulator.html?module=simulator_module_building" data-paper-path="docs/planning/game-simulator.html">▶ 건설 시뮬레이터 열기</a></h3>

<ol>
<li>지도에서 건물이나 빈 부지를 누르거나 우상단 「시설 모두 보기」의 2열 목록에서 시설을 고릅니다. 선택만으로 돈을 쓰지 않습니다.</li>
<li>현재 단계와 다음 단계, 비용과 예상 잔액을 확인합니다. 「한 단계 증설」은 한 단계 비용을, 「최대 증설」은 가능한 단계 수와 총비용을 보여 줍니다.</li>
<li>원하는 버튼을 누르면 거래를 시도합니다. 성공 후 조립 장면을 보여 주고 지도에 돌아옵니다. 오른쪽 정보는 출처·견적·저장 상태를 확인하는 개발용 영역입니다.</li>
<li>같은 진행으로 다시 열 때 저장된 단계와 잔액을 읽습니다. 지갑 또는 성장 기록을 안전하게 연결하지 못하면 구매를 잠급니다.</li>
</ol>

<p>건설 거래의 견적은 <code>building_master_level.csv</code>의 시설·단계별 비용을 읽어 목표 단계까지 합칩니다. 예를 들어 이전 화면 보고에서 보컬 녹음실 1→2단계 거래는 3,000이었지만 이는 <b>당시 실행값</b>이며 최종 가격이 아닙니다. 표의 비용과 효과는 발란스 대기입니다.</p>

<p>공통 핵심제안 모델의 기본 레슨 배수는 능력 시설에 대해 <code>building_master_level.csv</code>의 <code>effect_lesson_mult</code>를 읽고, legacy 선택은 <code>facility_growth_level.csv</code>의 <code>lesson_mult</code> 비교 경로입니다. 다만 현재 아이돌 성장 허브는 <code>buildBook</code>과 <code>lessonMultFor</code>를 통해 아직 <code>facility_growth_level.csv.lesson_mult</code>를 읽습니다. 지도 어댑터는 같은 시설 단계를 연결하며 배수 원천을 master로 교체하지 않습니다. 문서의 기본 계약과 현재 허브 연결 차이를 구분하고, 두 배수 중 하나를 새 최종값으로 결정하지 않습니다. 보드 경제의 시설별 수익 열과 도착 화면의 임시 표시 보상도 역할이 다릅니다. 도착 필러 설정은 표시 보상을 실제 보유량에 더하지 않는 시안이라고 명시합니다. 최종 수익·레슨량·확률은 발란스 대기입니다.</p>
