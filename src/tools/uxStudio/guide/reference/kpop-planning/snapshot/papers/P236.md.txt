## 1. 숏츠·스테이지·음원 보기의 역할

| 구분 | 숏츠 | 스테이지 | 음원 보기 |
|---|---|---|---|
| 중심 | 게시된 짧은 영상과 채널 | 보드에서 진행하는 실제 공연 | 곡/앨범·전체 영상 음원 |
| 목적 | 아이돌 발견·구독·소통 | 현재 무대 관람·공연 활동 | 곡 감상·보관·차트·투표 |
| 시작 | 게시자가 매체를 준비하고 공개 | 보드 공연의 실제 시작 | 곡/앨범/매체 선택 |
| 대상 | 권한 있는 공개 후보·구독·관계 피드 | 고정 기본100명+관계자/주간 상대, 월드 키 별도 | 곡/차트/앨범의 해당 목록 |
| 시간 | 게시 후에도 감상 가능한 콘텐츠 | 현재 공연과 다시보기 구분 | 전체/짧게/큐/셔플 등 명시 모드 |
| 순서 | 개인 추천 또는 구독/관계 신작 순서 | 고정 관람 명단 안의 채널별 무대 | 현재 곡·사용자 큐·차트 |
| 원본 | 숏츠 게시물 한 건 | 공연 한 건 | 곡/앨범 한 건 |
| 점수 | 재생·구독이 공식 표/G가 아님 | 검증된 공식 결과만 G 후보 | 공식 평가·투표의 공통 입구 |

~~~mermaid
flowchart LR
 A["곡·앨범"] <--> S["숏츠 게시물"]
 P["공연 한 건"] --> H["허용된 하이라이트 숏츠"]
 H --> S
 S <--> M["음원 보기 · 같은 곡"]
 S <--> V["스테이지 · 같은 공연/권한"]
~~~

숏츠는 스테이지100명의 또 다른 화면이 아니라 공개 게시물을 발견하는 독립 기능입니다. 숏츠에서 구독해도 스테이지의 고정 관람 명단에 자동 편입되지는 않습니다. 스테이지 안에서 보여 주는 관련 숏츠는 현재 관람 대상·매체 권한을 함께 적용합니다.

공연 영상 전체와 하이라이트 숏츠는 연결되지만 서로 다른 매체일 수 있습니다. 같은 게시물을 여러 화면에서 보여 줄 때는 원본을 복사하지 않고 같은 게시물 ID를 참조합니다. 서로 다른 편집본은 별도 게시물이며 원공연 ID로 묶어 반복 노출을 조절합니다.

## 2. 게시물·아이돌/팀 채널·원본

### 2-1. 어떤 콘텐츠가 들어오나

| 유형 | 원본 연결 | 연결 버튼 |
|---|---|---|
| 발매곡 하이라이트·뮤직비디오 컷 | 실제 곡/앨범·허용된 구간 | 곡 보기·전체 영상 |
| 연습·댄스·보컬·비하인드·인터뷰 | 게시자·아이돌/팀·공개 매체 | 채널 보기. 곡이 연결된 경우만 곡 보기 |
| 공연 하이라이트·직캠 | 실제 performanceId와 허용된 매체 | 원공연 보기. 관련 곡이 있을 때 곡 보기 |
| 관계/구독 영상 | 같은 게시물에 친구·크루·구독 포함 사유 | 원본 게시물과 반응 유지 |

공연 키 전용 실황/다시보기를 공개 숏츠에 그대로 넣지 않습니다. 별도 공개 허용된 하이라이트만 공개 후보로 취급합니다. 곡/원공연이 없는 게시물에 연결 버튼을 만들거나 관계없는 샘플 곡을 대신 연결하지 않습니다.

### 2-2. 채널과 구독 대상

채널은 아이돌·팀(유닛 포함)을 중심으로 둡니다. 제작 유저·소유/게시 주체와 출연 아이돌 크레딧을 분리해 표시합니다. 한 영상에 여러 아이돌이 나와도 업로드/발행 채널 하나를 기준으로 구독하고, 출연자 프로필은 각각 열 수 있게 하는 안입니다.

| 상태 | 세부안 |
|---|---|
| 채널 구독 | 명시적으로 선택한 channelId에 연결 |
| 팀 구독 | 그 팀 채널의 게시물만. 모든 멤버 개인 채널·제작자의 다른 팀을 자동 구독하지 않음 |
| 채널 개명 | 같은 ID이면 구독 유지·이름만 갱신 |
| 팀/시즌 변경 | 기존 채널과 보관 콘텐츠 보존. 다른 아이돌 IP/새 채널 자동 구독은 하지 않음 |
| 구독 해제 | 구독 피드에서 제거. 공개 영상 자체의 추천 자격과는 별개 |
| 이 채널 추천 안 함 | 추천 제외 의사를 별도로 보존. 구독 목록/직접 채널 열람과 구분 |
| 친구·크루 | 관계 원본을 해당 게시 채널에 연결. 자동 구독으로 처리하지 않음 |

아이돌/채널 소유 이전·팀 해체·계정 변경·시즌 승계의 세부 권한은 정책 결정 대기입니다. 표시 이름이나 화면용 track 문자열을 고유 채널 ID로 사용하지 않습니다.

### 2-3. 게시·수정·삭제

~~~mermaid
flowchart LR
 D["초안·매체/곡/공연 연결"] --> M["재생 준비·게시 권한"]
 M --> P["공개 게시"] --> I["피드 후보 색인"]
 P --> U["수정·공개 범위 변경"]
 P --> H["숨김/삭제"]
 H --> R["후보·대기열·재생 권한 갱신"]
~~~

게시자가 허용된 원본과 매체를 연결하고 제목·태그·출연자·공개 범위를 정하는 독립 게시 기획입니다. 발매곡 제작/공연을 재실행하지 않습니다. 매체가 준비되지 않은 초안은 추천 영상으로 미리 공개하지 않습니다.

동일 게시물의 공개 범위나 제목 변경은 revision 갱신이며 새 게시물 수·추천 기회를 반복 생성하지 않습니다. 다른 실제 편집본은 새 shortId를 가질 수 있으나 같은 원곡/원공연·게시자 묶음으로 재업로드 반복을 제어합니다. 숨김/삭제는 후보와 재생 권한에 반영하고 기존 반응/공식 기록의 보존 범위는 원본 정책을 따릅니다.

## 3. 최초 관심사·수정·스킵과 시청 반응

**제안(검수 대기). 처음에는 취향을 가볍게 묻고, 이후에는 실제 시청 반응으로 맞춰 갑니다.** 관심사는 선택 사항이며 친구·크루·구독이 없어도 바로 감상할 수 있습니다.

| 항목 | 선택·처리 |
|---|---|
| 장르 | 기존 원본의 댄스 팝·발라드·힙합을 복수 선택. ID는 각각 `music_career_genre_dance_pop`, `music_career_genre_ballad`, `music_career_genre_hiphop` 재사용 |
| 무대 스타일 | 공연·댄스·보컬·비하인드·인터뷰는 후보 라벨 예시이며 아직 등록되지 않은 기획. 확정 분류·ID와 연결 자료는 후속 검수 |
| 선택 완료 | 실제로 고른 값만 관심사로 저장. 선택하지 않은 항목을 선호·비선호로 간주하지 않음 |
| 나중에·닫기 | 관심사 없이 피드 진입. 가입·구독·친구 추가를 요구하지 않음 |
| 최초 안내 무응답 | 안내를 보였다는 상태와 관심사 저장 상태를 분리. 접속을 선택 완료·구독 동의로 기록하지 않으며 감상을 막지 않음 |
| 선택 중 이탈·연결 실패 | 저장 성공 전에는 미선택 상태 유지. 실패 안내 후 다시 선택하거나 그대로 감상. 재접속 때 임의 선택값 생성·매번 강제 안내 금지 |
| 나중에 수정 | 숏츠의 관심사 진입점에서 추가·해제. 기존 시청·구독·친구·크루 기록은 유지하고 다음 추천부터 반영 |

장르 원본은 `data/music_career/music_career_resources.json:22~34`입니다. 장르와 무대 스타일은 서로 다른 분류이며 ‘보컬’을 새 음악 장르처럼 등록하지 않습니다.

~~~mermaid
flowchart LR
 A["처음 방문"] --> B["관심사 선택 · 나중에"]
 B --> C["현재 관계·구독·관심사 확인"]
 C --> D["추천 감상"]
 D --> E["유효한 시청 반응"]
 E --> D
~~~

| 반응 | 추천에 쓰는 의미 |
|---|---|
| 실제 재생·완료·다시 보기 | 재생 성공과 실제 활성 시청을 확인한 뒤 취향 신호로 사용 |
| 좋아요 | 명시적인 긍정 반응. 같은 동작 재전송으로 신호를 중복 누적하지 않음 |
| 빠르게 넘김·관심 없음 | 넘김과 명시적 비선호를 구분. 관심 없음은 관련 추천을 줄이는 강한 의사 표현 |
| 화면 노출·버퍼링·오류 | 유효 시청으로 세지 않음. 연결 불량을 싫어함으로 해석하지 않음 |

유효 재생의 시간·완료 기준, 반응별 가중치·감쇠·반복 제한 기간은 **발란스 대기**입니다. 잠깐 본 장르 하나로 모든 추천을 바꾸지 않고 새 취향을 발견할 후보도 남깁니다.

## 4. 추천·구독·친구·크루 피드의 후보와 순서

~~~mermaid
flowchart LR
 C["공개·관계/구독 후보"] --> F["권한·미시청·동일 원본 확인"] --> R["피드별 순서·다양성"] --> Q["확정 목록"]
~~~

**추천은 취향 발견, 구독은 선택한 채널의 신작, 친구·크루는 관계 대상의 신작을 보는 곳입니다.** 구독 대상은 아이돌·팀 채널이며 제작 유저 크레딧은 따로 표시합니다. 유저 전체를 구독했다고 해석하거나 같은 유저의 다른 팀까지 자동 구독하지 않습니다.

| 피드 | 후보 범위 | 기본 순서·소진 처리 |
|---|---|---|
| 추천 | 권한을 통과한 공개 숏츠에서 관심사·반응, 구독 채널, 친구·크루 연결 채널, 새 창작자 후보를 혼합 | 미시청 우선으로 취향 적합도·신선도와 후보 다양성을 함께 반영. 같은 창작자 연속 제한. 부족하면 허용된 공개 후보로 넓히며, 전체가 없으면 빈 상태 |
| 구독 | 현재 구독한 아이돌·팀 채널만 | 미시청 우선 → 공개 최신순. 미시청을 다 보면 완료 안내와 직접 다시보기. 비구독 영상 자동 혼입 금지 |
| 친구·크루 | 현재 유효한 친구·크루 관계와 연결된 채널만. 전체/친구/크루 필터 | 미시청 우선 → 공개 최신순. 필터마다 같은 순서 적용. 관계 밖 영상 자동 혼입·크루 가입 강제 금지 |

추천의 처리 순서는 **공개·권한 검사 → 후보 수집 → 시청·중복 확인 → 취향 평가와 출처 혼합 → 연속 제한 → 페이지 확정**입니다. 관계자 전체를 먼저 소진하거나 구독 영상 전체를 앞에 붙이지 않습니다. 혼합 비율·가중치·반복 제한은 정책 데이터로 두며 수치는 발란스 대기입니다. 등급·점수·구독자 수만으로 기본 순서를 정하지 않습니다.

관심사·반응이 없으면 관계·구독 후보와 다양한 공개 시드를 섞습니다. 관계·구독도 없으면 다양한 장르·무대 스타일의 공개 시드와 새 창작자로 시작합니다. 관심사를 선택했다면 그 값을 초기 신호로 쓰되 다른 후보를 모두 없애지 않습니다. 같은 정렬값은 게시 ID 등 안정된 기준으로 나누어 페이지 왕복·재요청 때 중복·누락을 줄입니다.

영상에는 채널명, 아이돌·팀, 제작 유저 크레딧을 구분하고 해당되는 친구·크루·구독 배지를 함께 보여 줍니다. ‘추천 이유’에는 ‘선택한 힙합 관심사’, ‘구독한 팀’, ‘친구의 채널’, ‘새로운 팀 발견’처럼 실제 사용한 이유를 표시합니다. 확인하지 않은 관계나 타인의 시청 이력을 이유로 만들지 않습니다.

### 첫 영상과 다음 영상

특정 곡/공연/공유 링크에서 들어오면 사용자가 선택한 그 게시물부터 재생하고, 이후에도 그 문맥을 유지합니다. 추천 피드의 첫 영상은 권한을 통과한 미시청 후보를 평가해 정하고, 다음 순서는 출처 혼합·창작자/원공연 반복 제한을 적용합니다. 구독·관계 피드는 아래 기본 정렬만 사용합니다.

| 관심사 I | 실제 시청 기록 H | 추천 초기 근거 |
|---|---|---|
| 있음 | 없음 | 직접 선택 관심사 + 현재 구독/관계 + 새로운 공개 후보 |
| 없음 | 있음 | 실제 시청 반응 + 현재 구독/관계 + 발견 후보 |
| 있음 | 있음 | 수정한 명시 관심사와 실제 반응을 함께 반영. 지금 재생 중인 영상은 유지 |
| 없음 | 없음 | 관계/구독이 있으면 활용. 그것도 없으면 주제·창작자가 다양한 공개 발견 후보 |

처음 아무 정보도 없는 상태에서는 확인된 개인 취향이라고 표시하지 않고 ‘새로운 아이돌 발견’ 등 실제 근거를 보여 줍니다. 공개 발견 후보는 구독자/조회수 상위 영상만으로 채우지 않으며, 새로운 게시자도 후보에 들어갈 경로를 둡니다. 초기에는 정책 데이터로 정렬하고 이후 모델을 붙이더라도 후보 범위·권한·중복·복귀 계약을 유지하는 안입니다.

## 5. 관계 8조합·빈 상태·중복과 변경 정책

~~~mermaid
flowchart LR
 A["친구 F · 크루 C · 구독 S"] --> U["8조합의 합집합·사유 보존"] --> E["영상 없음 / 모두 봄 / 조회 실패 구분"]
~~~

아래 F/C/S의 있음·없음은 각각 친구 관계/크루 관계/구독 채널의 존재입니다. 게시물 수나 현재 미시청 영상 수와는 별개입니다. D는 권한을 통과한 공개 발견 후보이며, 모든 추천 조합에는 D의 새 창작자 후보가 참여합니다.

| F | C | S | 추천에 더하는 연결 후보 | 구독 피드 | 친구·크루 피드 |
|---|---|---|---|---|---|
| 없음 | 없음 | 없음 | 관심사·반응. 둘도 없으면 다양한 공개 시드 | 구독 없음 | 관계 없음 |
| 있음 | 없음 | 없음 | 친구 채널 + 관심사·반응 | 구독 없음 | 친구 |
| 없음 | 있음 | 없음 | 크루 채널 + 관심사·반응 | 구독 없음 | 크루 |
| 없음 | 없음 | 있음 | 구독 채널 + 관심사·반응 | 구독 채널 | 관계 없음 |
| 있음 | 있음 | 없음 | 친구·크루 합집합 + 관심사·반응 | 구독 없음 | 친구·크루 합집합 |
| 있음 | 없음 | 있음 | 친구·구독 합집합 + 관심사·반응 | 구독 채널 | 친구 |
| 없음 | 있음 | 있음 | 크루·구독 합집합 + 관심사·반응 | 구독 채널 | 크루 |
| 있음 | 있음 | 있음 | 친구·크루·구독 합집합 + 관심사·반응 | 구독 채널 | 친구·크루 합집합 |

각 행은 앞 절의 공통 정렬을 따릅니다. 합집합은 같은 영상 한 건과 여러 포함 이유를 보존한다는 뜻이며, 관계가 겹친 횟수만큼 추천 점수를 단순 가산하지 않습니다.

| 실제 상태 | 안내·다음 행동 |
|---|---|
| 구독 자체가 없음 | ‘구독한 채널이 없어요.’ 채널 찾기 또는 추천으로 직접 이동 |
| 친구·크루 관계가 모두 없음 | ‘친구·크루의 숏츠가 아직 없어요.’ 관계 찾기·크루 둘러보기는 선택 사항 |
| 선택한 관계 필터에 대상 없음 | ‘친구가 없어요’ 또는 ‘가입한 크루가 없어요.’ 전체 필터·추천으로 직접 이동 |
| 대상은 있으나 공개 게시물 없음 | ‘아직 공개한 숏츠가 없어요.’ 구독·관계를 임의 해제하지 않음 |
| 허용된 게시물은 모두 시청함 | ‘새 숏츠를 모두 봤어요.’ 직접 다시보기·추천 이동. 외부 영상 자동 보충 없음 |
| 권한상 재생 가능한 게시물 없음 | ‘지금 재생할 수 있는 숏츠가 없어요.’ 숨겨진 게시물 수·제목을 노출하지 않음 |
| 조회 실패·연결 끊김 | ‘불러오지 못했어요.’ 재시도 제공. 이를 관계 없음·게시물 없음으로 기록하지 않음 |
| 추천의 전체 공개 후보도 없음 | ‘지금 볼 수 있는 숏츠가 없어요.’ 재시도·다른 콘텐츠 이동 |

동일 숏츠는 한 번만 표시하고 같은 원공연의 재편집·다른 카메라 영상은 원본 묶음으로 중복 노출을 제어합니다. `shortId`와 원공연 참조는 구분하며, 다른 실제 공연까지 하나로 지우지 않습니다. 시청 이력은 피드·기기 전환으로 새 미시청이 되지 않으며 직접 다시보기는 허용합니다.

차단·삭제·공개 범위·재생 권한이 모든 정렬보다 우선합니다. 이미 받은 후보도 재생 전에 확인하고, 삭제·차단된 영상은 대기열과 추천에서 제외합니다. 구독 해제·친구 해제·크루 탈퇴는 다음 후보에 반영하되 남은 포함 이유가 있으면 그 피드의 자격은 유지합니다. 캐시와 페이지 커서가 오래돼도 철회된 권한을 되살리지 않습니다.

구독·추천 노출은 스테이지 고정 그룹 자동 편입, 팬 평가 자격, 투표 수·무게를 만들지 않습니다. 키 전용 원본·실황·리플레이를 숏츠 추천으로 우회하지 않으며, 별도 공개 권한이 명시된 하이라이트만 공개 후보로 다룹니다.

## 6. 100만 동접 · 어떻게 준비하고 보여 주나

동접100만 명은 전체 게임 접속 규모이며, 그중 숏츠를 보는 실제 관객·후보 콘텐츠 수·개인의 관계 수는 별도입니다. 모든 이용자/콘텐츠를 화면에 나열하거나 매 넘김마다 전체를 다시 검색하지 않습니다.

~~~mermaid
flowchart TD
 P["게시·재생 준비·공개 상태"] --> I["관심사·채널·팀·크루·발견 색인"]
 I --> C["1 · 필요한 후보만 축소"]
 U["관심사·구독·관계·실제 반응"] --> C
 C --> F["2 · 개인별 권한/중복·혼합·점수화·재정렬"]
 F --> Q["현재 세션의 짧은 영상 큐·커서"]
 Q --> V["한 영상 재생 · 다음 큐 보충"]
 V --> H["유효 반응 비동기 반영"]
 H --> F
 M["매체 전송·캐시"] --> V
~~~

### 6-1. 두 단계 편성

| 단계 | 처리 | 범위 |
|---|---|---|
| 후보 축소 | 관심사별 공통 후보·채널 신작·관계 게시물·새 창작자 목록에서 일부를 취득 | 공개 추천과 관계/구독 전용 후보를 구분 |
| 개인별 확정 | 최신 권한/관계·숨김·시청 이력·같은 게시물/공연 묶음 확인 후 취향·신선도·다양성 순서 확정 | 한 관객에게 필요한 제한된 후보만 처리 |
| 전달·재생 | 확정한 짧은 목록과 다음 커서 전달. 큐가 줄면 다음 묶음을 요청 | 이미 받은 다음 영상은 큐에서 사용 |
| 관측·학습 | 실제 활성 재생·완료/넘김·명시 선호를 재전송 중복 없이 반영 | 공식 투표 접수와 별도 처리 |

Google의 추천 시스템 자료는 후보 생성·점수화·재정렬을 구분합니다. 여기서는 후반 두 처리를 개인별 확정 단계로 묶어 설명합니다. 현재 YouTube 내부 시스템을 복제했다는 뜻이 아니라 후보를 먼저 줄이는 구조를 참고한 우리 기획안입니다. [공식 구조 설명](https://developers.google.com/machine-learning/recommendation/overview/types)

### 6-2. 소규모와 100만 명

| 항목 | 동접100명 수준 | 동접100만 명을 고려한 안 |
|---|---|---|
| 공개 후보 | 가용 영상과 소진 상태 확인 | 관심사·채널·크루별 공통 후보 묶음을 분산/재사용 |
| 개인별 추천 | 제한된 후보를 개인별 정렬 | 같은 원칙으로 개인 작업 분산. 전역 전체 검색을 피함 |
| 인기 채널 게시 | 해당 채널 신작 갱신 | 백만 구독자에게 동시에 원본을 복사하지 않고 공유 신작 색인과 증분 후보 사용 |
| 관계·구독 | 현재 관계 반영 | 매 요청 전체 목록 재조회보다 변경 버전·증분 후보·세션 상태 활용 |
| 미디어 | 실제 영상 준비/재생 확인 | 추천 계산 경로와 영상 전달/캐시를 분리 |
| 반응 | 실제 반응·오류 구분 | 비동기 집계. 공식 표는 별도 원장에서 확인 |
| 후보 부족 | 허용된 공개 범위 확장 또는 빈 상태 | 같은 규칙 유지. 관계 전용 피드는 범위를 넓히지 않음 |

후보 개수·큐 길이·선로딩 범위·갱신 간격·노출 비율·동시 처리 목표값은 발란스/서비스 정책 대기입니다. 이 문서의 동접 시나리오는 부하 시험 통과 결과가 아닙니다.

### 6-3. 순서·커서·중복

피드 세션은 종류·필터·후보 스냅샷·커서·이미 제공/재생한 게시물을 구분합니다. 새 영상이 들어와도 현재 영상과 이미 확정한 다음 순서를 밀어내지 않습니다. 새로고침/관심사 변경은 현재 영상을 유지하고 다음 후보부터 새 기준을 쓰는 안입니다.

같은 요청/커서 재시도는 같은 결과로 이어져야 합니다. 다음 페이지와 이전 페이지의 같은 shortId는 중복 제거합니다. 실제 재생 전 대기열에 들어갔다는 이유만으로 시청 완료로 기록하지 않습니다. 계정의 앱/기기별 시청 확인을 맞추되, 시청 기준·보관 기간은 별도 정책입니다.

다른 shortId라도 같은 원공연/원곡의 반복 편집이면 같은 묶음의 연속 노출을 제한합니다. 진짜 다른 컷까지 같은 게시물로 삭제하지 않으며, 원본 묶음 ID와 게시물 ID를 구분합니다. 같은 제작자가 여러 채널로 도배하는 경우도 게시 주체 단위 다양성 정책을 함께 검토합니다.

### 6-4. 지연·장애·권한

| 상태 | 표시·처리 |
|---|---|
| 개인 추천 계산 지연 | 유효한 공개 공통 후보에 개인 숨김/중복 필터를 적용한 대안. 추천임을 표시 |
| 구독/관계 후보 조회 지연 | 해당 피드의 재시도/연결 상태. 무관한 공개 후보로 자동 대체하지 않음 |
| 다음 큐 지연 | 현재 재생과 받은 큐 유지. 끝나면 불러오는 중/재시도 |
| 고부하 | 새 추천 갱신·선로딩을 줄이는 안. 현재 재생·권한·명시 조작 우선 |
| 삭제/권한 철회 | 캐시에 남아 있어도 재생 전/중 상태를 확인해 중단·제외 |
| 권한 판단 불명 | 보호 매체를 공개로 가정하지 않고 확인 대기 |
| 출연자 오프라인 | 공개 게시물은 원본의 공개 권한대로 감상. 실제 LIVE 표시와 구분 |
| 관객 네트워크 단절 | 연결 상태 표시. 사전 저장/오프라인 재생 권한을 자동 부여하지 않음 |

| 스테이지 → 음원 | 공연 사용 곡/앨범 | 같은 곡 정보·영상 감상 |
| 음원 → 스테이지 | 곡에 연결된 실제 공연·회차 | 현재 관람 명단/키가 허용하는 공연 목록 |
| 어느 화면 → 채널 | 원본 게시 channelId | 아이돌/팀 채널·구독·기존 게시물 |
| 숏츠 → 투표 | entry/round 참조 | 음악 앱의 기존 공식 투표 입구 |

관련 숏츠는 추천 전체 피드와 별도 문맥입니다. ‘이 곡의 숏츠’/‘이 공연의 숏츠’ 표시를 두고 관련 영상이 없으면 없는 상태를 안내합니다. 다른 곡/공연 영상으로 자동 바꾸지 않으며 사용자가 추천으로 이동하면 문맥을 전환합니다.

### 7-2. 화면과 버튼

기존 세로 전체 화면·위아래 넘김·영상 위 메뉴를 재사용합니다. 우측에는 게시물 찜/댓글/공유/채널을 두고, 하단에는 아이돌/팀·곡 정보와 현재 가능한 곡 보기/원공연 보기를 제공합니다. 긴 정보는 펼치고 연결이 없는 버튼은 숨기거나 사유를 표시합니다. 숏츠 안에 별도의 공식 투표함을 만들지 않습니다.

스테이지의 내 PIP는 실제 공연 시작 때 열리고 영상/음원 하나의 초점을 공유합니다. 스테이지에서 공연을 보고 숏츠/음원으로 이동해도 공연 사건을 새로 만들지 않습니다. 보드 진행/실제 공연 조작과 화면 감상은 기존 게임의 입력 규칙에 맞춰 검수합니다.

### 7-3. 위치와 큐 복원

~~~mermaid
sequenceDiagram
 participant A as 원래 화면
 participant R as 공통 재생·이동 문맥
 participant B as 연결 화면
 A->>R: 곡/게시물/공연·피드/필터·큐/위치 보존
 R->>B: 같은 원본 참조·권한 확인
 B->>R: 뒤로 가기
 R-->>A: 원래 화면·항목·위치 복원
 Note over A,B: 삭제·권한 철회면 대안 상태·같은 음원 동시 재생 금지
~~~

| 문맥 | 보존 |
|---|---|
| 숏츠 | 현재 shortId·피드 종류·필터·커서·영상 위치 |
| 음원 보기 | track/album·일반 큐·현재 위치·전체/짧게·셔플/반복 |
| 스테이지 | 관람 모드·고정 그룹/회차·채널·공연·PIP 줄임 상태 |
| 오디오 | 한 번에 하나의 활성 출력·이전 재생 위치 |
| 댓글/공유 시트 | 대상 게시물 고정·넘김 잠금·닫은 후 같은 게시물 |

기존 숏츠 닫기의 일반 재생 복귀는 일시정지 복원을 기준으로 검수합니다. 새 자동 재생/복귀 정책은 명시적으로 정하고 두 음원을 동시에 재생하지 않습니다.

영상 간 시간 연결은 같은 매체 revision과 구간 대응 정보가 있을 때만 합니다. 숏츠10초와 공연10초가 자동으로 같은 지점이라는 식으로 추정하지 않습니다. 구간 대응이 없으면 허용된 전체/다시보기의 시작 지점으로 열고 이전 화면은 자체 위치를 유지합니다.

### 7-4. 스테이지 관람 권한

공개 숏츠를 발견/구독했다고 스테이지의 N/W 명단에 새 유저를 자동 추가하지 않습니다. 기본100명·친구크루 초과·주간 상대·월드 키는 [공연 상세 P234](산출_기획서_공연스테이지_상세_v1.html)를 따릅니다.

원공연 이동 시 현재 관람 명단·공식 회차·키 관람권·매체 공개 범위를 다시 확인합니다. 권한이 없으면 해당 원공연을 재생하지 않고 관람 조건/내 그룹 보기 등 가능한 이동만 제시합니다. 별도로 공개 허용된 하이라이트는 그 공개 권한대로 감상할 수 있습니다.

월드 키 전용 매체의 주소를 숏츠 공개 후보에 그대로 넣지 않습니다. 원공연이 끝나면 다시보기 여부를 확인하고, 회차가 바뀌거나 키가 만료돼도 이전 큐가 관람권을 되살리지 않습니다. 이 전환은 P234의 관람 명단이나 이미 인정한 점수를 바꾸지 않습니다.

## 8. 게시물 반응·공식 점수·데이터

~~~mermaid
flowchart LR
 C["동일 게시물 원본"] --> S["찜·댓글·공유·구독 기록"]
 C --> P["원곡·원공연 참조"]
 V["공식 투표·공연 결과"] --> L["별도 회차 원장"]
~~~

### 8-1. 원본과 반응의 단위

| 대상 | 같은 원본으로 공유하는 것 | 별도 구분 |
|---|---|---|
| 동일 shortId | 여러 화면의 게시물·찜·댓글·공유 기록 | 화면마다 게시물을 복제하지 않음 |
| 서로 다른 편집본 | 각 게시물의 반응 | parentPerformanceId/track 참조로 묶음만 연결 |
| 같은 공연 | 실황/다시보기/하이라이트의 공연 근거 | 편집본별 재생이 새 공연/G를 만들지 않음 |
| 곡·앨범 | 원곡 정보·음원 찜/보관함 | 숏츠 게시물 찜과 혼동하지 않음 |
| 페스티벌 출전 | 같은 entry/round의 공식 평가 | 추천 피드·노출·구독 수와 별개 |

‘추천’이라는 말은 두 가지를 구분합니다. 상단 추천 피드는 개인에게 영상을 골라 주는 기능이고, 기존 곡 추천 행동은 페스티벌의 명시 평가입니다. 영상 조회·구독·피드 점수를 공식 표로 자동 환산하지 않습니다.

명시적 찜/댓글/공유/구독을 재전송해도 같은 요청을 한 번 처리합니다. 실제 온라인 기능은 이후 서버 계약으로 검증하며 현재 로컬 시험 데이터를 실유저 반응 수로 승격하지 않습니다. 구독자/댓글 수가 없어도 숨기거나 사실대로 표시하고 가짜 유저 수를 만들지 않습니다.

### 8-2. 권한과 관계 변경

| 변화 | 추천 | 구독·친구/크루 피드 |
|---|---|---|
| 구독 해제 | 공개 영상은 취향에 맞으면 가능. 구독 배지는 제거 | 구독 자격 제거 |
| 친구 해제/크루 탈퇴 | 공개 영상 자체는 가능. 철회된 관계 배지 제거 | 다른 관계 사유가 없으면 제외 |
| 관계/크루 전용 공개 철회 | 재생 권한 제거 | 후보/큐에서 제외 |
| 차단/삭제/비공개 | 후보/재생에서 제외 | 동일 |
| 관심사 수정 | 다음 추천부터 새 취향 | 구독·관계 원본은 유지 |
| 채널 추천 안 함 | 해당 추천 제외 | 직접 구독/채널 보기 정책과 구분 |

기존 후보/커서/캐시는 최신 권한보다 우선하지 않습니다. 관계 자체가 없거나 게시물이 없는 경우와 서버 조회 실패를 다른 상태로 유지합니다.

### 8-3. 데이터 연결 설계

| 묶음 | 원본/필드 예시 | 목적 |
|---|---|---|
| 게시물 | shortId/contentId, channelId, ownerRef, visibility, mediaRef/revision, 공개 시각 | 게시·공개·재생 원본 |
| 관계 원본 | viewerAccountId, friend/crew 참조·유효 버전 | 정확한 관계 후보 |
| 구독 | viewerAccountId + stable channelId | 명시한 채널만 구독 |
| 관심사 | 기존 genreId + 등록할 styleId·선택 상태 | 선택/미선택·수정 |
| 원곡/공연 | album/track 참조, canonical performanceId, 허용 구간 | 세 화면의 같은 콘텐츠 |
| 피드 | feedKind, contextRef, snapshot/cursor, 제공/재생 상태 | 현재 큐·중복·왕복 |
| 반응 | request/eventId, viewer, shortId, 동작·실제 재생 구간 | 중복 처리·유효 신호 |
| 공식 평가 | entryId/roundId·별도 영수증 | 투표·G·인기 사용과 분리 |

원곡의 화면용 album_/entry_/catalogue_ 문자열을 그대로 정본 ID로 승격하지 않습니다. 기존 원본 참조와 신규 게시물/채널 원본을 연결하는 어댑터를 검수합니다. 신규 콘텐츠·채널·선호·피드 정책 표는 설계안이며 이번에 실행 CSV/스키마를 추가하지 않습니다.

시청 이력·영상 원문을 브라우저 한 판 저장에 무한 누적하지 않습니다. 계정/세션/시즌의 보존 범위, 저장량·압축/만료·실패 복구를 계산한 뒤 구현합니다.

## 9. 검수 사례와 남은 결정

~~~mermaid
flowchart LR
 A["관계8조합·관심사/기록"] --> B["후보·권한·순서·소진"]
 B --> C["음원↔숏츠↔스테이지"]
 C --> D["100만 동접·장애·중복 검수"]
~~~

| 검수 | 기대 |
|---|---|
| 친구/크루/구독 8조합 | 각 후보 원본·피드 자격과 맞음 |
| 각 조합 × 관심사/시청 기록 4상태 | 총32개 출발 상태가 정의됨 |
| 관심사 선택/스킵/무응답/연결 실패 | 실제 선택만 저장·바로 감상 가능한 경로 |
| 같은 채널이 친구·크루·구독 모두 해당 | 영상 한 건·포함 사유 여러 개 |
| 구독은 있으나 게시물 없음/전부 봄 | 정확한 빈 상태, 다른 채널 자동 삽입 없음 |
| 전체 공개 후보도 없음 | 실제 빈 상태, 가짜 게시물/무한 반복 없음 |
| 신규 게시자·무구독 사용자 | 구독/성장 상위자만의 발견 공간이 아님 |
| 인기 채널 대량 게시·다수 계정 동시 진입 | 공통 후보/짧은 큐·게시자 다양성 검수 |
| 같은 게시물 재요청·오래된 커서 | 중복·누락·권한 철회 처리 |
| 영상 재생 중 새 추천 | 현재 영상·보존한 큐를 갑자기 교체하지 않음 |
| 음원→관련 숏츠/공연→뒤로 | 같은 원본·필터·위치 복원 |
| 관련 게시물 없는 곡/공연 | 임의 다른 콘텐츠로 바꾸지 않음 |
| 키 전용 공연에 공개 숏츠로 접근 | 원공연 권한 재확인·우회 불가 |
| 구독 후 스테이지 진입 | 관람 그룹/주간 상대/표 예산 불변 |
| 댓글/공유 중 넘김·복귀 | 대상 게시물 고정·같은 문맥 복귀 |
| 구독/관계 철회·삭제·비공개 | 다음 후보·재생 요청에 최신 상태 적용 |
| 추천 계산 지연·관계 조회 실패 | 피드 범위와 권한 유지·오류를 빈 상태와 구분 |
| 같은 영상 여러 화면에서 반응 | 같은 게시물 원장에 한 번 기록 |
| 공식 투표 | 음악 앱의 같은 곡/회차·자격·중복 검증 |
| 동접100만 명 | 실제 부하 시험·목표 지연/오류 기준 미충족 시 기능 완료로 표시하지 않음 |

검수 지표는 피드 응답 지연, 다음 영상 첫 화면까지의 시간, 길이를 고려한 유효 시청, 후보 소진, 같은 게시물/공연 반복, 관계/권한 위반, 원본 이동·복귀 실패, 공식 표 원장 불일치입니다. 목표 수치는 서비스 검증 전입니다.

### 남은 결정
- 무대 스타일 분류·ID와 채널/아이돌·팀 소유/시즌 승계.
- 추천 혼합 비중·신호 가중치·반복 기간·유효 시청 기준.
- 공개 게시·매체 준비·숏츠 길이·업로드/편집 경로.
- 큐 길이·선로딩·커서 보관·관계 증분·부하 목표.
- 영상/음원/공연 사이 시간 대응과 미디어 권한 정책.
- 채널 추천 제외·알림·신고/숨김 관리·보존/삭제 범위.
- 운영 서버·기존 시뮬 연결·실제100만 동접 검증.

## 10. 공식 조사와 현재 구현

~~~mermaid
flowchart LR
 O["공식 참고 원칙"] --> D["우리 게임 기획"]
 E["기존 폼·로컬 시험"] --> N["신규 피드·서버 연결 검증"]
~~~

### 10-1. 참고한 원칙과 우리 제안

YouTube는 Shorts 피드를 개인화하고 시청·검색·구독·좋아요·관심 없음 등의 신호를 활용한다고 설명합니다. 우리 기획은 이 방향을 참고하되 첫 관심사 선택·친구/크루·스테이지 연결을 별도 설계했습니다. [YouTube 공식 추천 설명](https://support.google.com/youtube/answer/16089387?hl=en)

YouTube 공식 구독 설명은 선택한 채널의 새 영상을 구독 피드에서 보는 흐름을 안내합니다. 우리 구독 피드의 ‘미시청 우선→공개 최신순’은 이 게임의 제안이며 현재 YouTube의 모든 화면 정렬과 동일하다고 쓰지 않습니다. [공식 구독 설명](https://support.google.com/youtube/answer/4489286?hl=en)

Google의 추천 학습 자료는 후보 생성·점수화·재정렬과 다양성/신선도 조정을 설명합니다. 이 기획의 후보 축소→개인별 확정 구조는 개념 참고이며 특정 기술 스택·처리량·완성 모델을 확정하지 않습니다. [공식 추천 구조](https://developers.google.com/machine-learning/recommendation/overview/types)

### 10-2. 현재 원본과 구현 사실

| 현재 원본 | 확인 범위 |
|---|---|

| 공통 플레이어 | 하나의 미디어 요소, 일반 큐/곡/위치 보존과 숏츠 복귀 |
| 찜·댓글·공유·추천·투표 | 로컬 시험 기록 연결. 온라인 실유저 서비스/공식 인정 아님 |
| 현재 매체 | 복셀 정지 이미지3종+라이선스 시험 MP3. 실제 영상 생성 완료를 뜻하지 않음 |
| 신규 관심사·구독·추천·관계 피드 | 로컬 UI 시안으로 임시 화면·메모리 상태 표현. 실제 추천·계정 구독·관계 서버는 미개발. 화면 갱신용 subscribe 함수와 소셜 구독을 구분 |
| 시뮬 소속 | 기존 음악 앱은 P207 공용 모듈로 유지. stage/shorts/music_ui_preview 실행 모드는 유지하되 음원 감상은 등록된 같은 controller와 단일 플레이어 재사용. 기존 운영 로직을 복제하지 않음 |

기존 장르 원본과 재생/소셜 계약은 유지하고 독립 게시물·채널·피드를 새로 연결하는 계획입니다. 구현·부하·운영 소셜 검증은 이후 작업입니다.

## 11. 로컬 UI 시안과 실제 미개발 범위

이 절은 **로컬 UI 구현과 확인한 범위**입니다. 실제 공연·추천·계정 소셜 등 운영 기능 개발 완료나 실제 서버 검증 결과를 뜻하지 않습니다. 위 장의 실제 서비스 규칙은 구현 대상으로 유지합니다.

| 실행 모드 | 로컬 UI 시안 |
|---|---|
| `simulator_module_stage_ui_preview` | [스테이지 실행](/docs/planning/game-simulator.html?module=simulator_module_stage_ui_preview) |
| `simulator_module_shorts_ui_preview` | [숏츠 실행](/docs/planning/game-simulator.html?module=simulator_module_shorts_ui_preview) |
| `simulator_module_music_ui_preview` | [음원 실행](/docs/planning/game-simulator.html?module=simulator_module_music_ui_preview) |

공통 게임 하단에 **미디어** 메뉴를 따로 둡니다. 기본 진입은 스테이지이며 공용폰의 외부 actions 영역에서 스테이지·숏츠·음원을 전환합니다. 음원은 별도 UI를 복제하지 않고 등록된 기존 음악 화면·controller·단일 플레이어를 재사용합니다. 미디어 안에서는 게임 장식과 플로팅 표시를 숨기고 게임으로 복귀할 수 있으며, 미디어 선택 표시와 기존 하단2행 높이를 유지합니다. 우측 외부 패널의 임시 조건과 실제 음악 원장의 곡·투표·BGM은 구분합니다.


<a id="media-music-integration"></a>
### 기존 음악 화면 재사용과 게임 왕복

| 항목 | 현재 구현·저장 경계 |
|---|---|
| 공통 음악 원본 | native 음악 화면과 미디어 진입이 등록된 music controller·registry·미디어 요소 하나를 공유. 같은 팀/session의 현재 곡을 읽음 |
| 시안 단독 | fixture adapter가 임시 곡을 화면용으로 변환. 공통 career source나 별도 저장/지갑/팀을 생성하지 않음 |
| 최초 실제 곡 연결 | 게임에서 등록된 음악 화면이 아직 없을 때만 내 발매곡 보기 버튼으로 기존 music_app에 명시 진입. 자동 초안·지원금·공연 사건을 만들지 않음 |
| 최소 조작 | 둘러보기·차트·보관함 3탭, 한 줄 곡 목록, 제목/커버 1회로 전체 플레이어. 허용 투표만 1회 조작하며(투표 취소 없음) 기존 기간·소유·자격·한도 검사를 통과 |
| 미디어·게임 왕복 | 감상 중 게임 장식·플로팅 UI를 숨기고 게임으로 복귀. 보드에서 미디어 재진입 때 등록된 현재 음악 화면을 재사용 |
| 크루·운영 경계 | 현재 크루 이름을 유지. 별도 앱 서버·실시간 공연·개인 추천·대규모 인원 정렬·계정 소셜은 이 UI 통합으로 개발하지 않음 |

BGM은 현재 소유한 실제 발매 앨범의 검증된 재생 src에만 허용합니다. 시안 fixture나 다른 팀의 곡을 내 BGM으로 바꾸지 않습니다. 선택은 메모리에만 두고 해당 곡을 반복하며 보드 왕복에 유지합니다. 다른 명시 재생으로 초점을 넘기거나 BGM을 끝내면 기존 반복 설정을 복원합니다. 새로고침 뒤 선택·재생 복원은 보장하지 않습니다.

격리된 실제 UI에서 음악→생성 1회 결제→재킷→제작→발매→새로고침 보존과 미디어의 실제 곡 1회 선택·BGM·게임 복귀·보드에서 미디어 재진입·내 발매곡 명시 연결을 확인했습니다. 이는 실제 추천/공연 서버나 계정 구독·대규모 정렬·부하 검증의 완료를 뜻하지 않습니다.

영상으로 표시하는 시안 매체는 영상 포스터와 라이선스 샘플 음원입니다. 실제 동영상 생성·실시간 방송으로 표시하지 않습니다.


| 시안 범위 | 현재 표현하는 것 |
|---|---|
| 임시 콘텐츠 | 가상 아이돌·곡·숏츠·공연과 서로 연결된 화면용 참조 |
| 관계 10사례 | 친구·크루·구독 8조합과 친구/크루 100명 초과 2사례. 표시 인원·포함 사유는 임시 데이터 |
| 스테이지 | 6채널, 내 그룹/주간/월드 화면, 공연 목록·감상, 보드 우측 내 PIP의 확대·줄이기·닫기 |
| 숏츠 | 첫 관심사 선택/나중에, 추천/구독/친구·크루 화면, 위아래 넘김, 관련 음원·공연 이동 |
| 화면 반응 | 찜·댓글·구독·키 잠김·PIP 선택과 화면 이동을 같은 시안 세션의 메모리 상태로 표현 |
| 음원·차트 | 등록된 기존 음악 3탭·한 줄 목록·전체/미리듣기·재생 목록·허용 투표 재사용. 종합·급등·추천·찜·실력·게임·인기 응원 7종 예시 차트는 UI 시안으로 구분 |
| 매체 | 기존 복셀 정지 이미지와 라이선스 샘플 음원 사용. 실제 동영상·실시간 방송이 아니며 포스터와 음원을 구분해 표시 |
| 바깥 조작 패널 | 임시 데이터 안내, 관계 사례, 100명/100만 명 예시 조건, 내 공연·월드 키 잠김 상태 전환 |

100명/100만 명 전환은 화면 확인용 조건을 바꾸는 조작입니다. 실제 접속자를 생성하거나 실제 매칭·인원 정렬·100만 동접 부하 시험을 수행하지 않습니다. 예시 인원·순위·반응·관계 수는 운영 수치나 실제 계정 기록으로 사용하지 않습니다.

| 실제 미개발 범위 | 시안과의 경계 |
|---|---|
| 추천·인원 정렬·매칭 | 실제 후보 수집·개인 추천·등급별 명단 배정·주간 매칭·규모별 처리 미구현 |
| 공연·게임 점수·공식 투표 | 실제 공연 사건·배틀·공식 점수 인정·투표 접수 미구현 |
| 재화·키 권한과 소비 | 실제 지갑·키 획득/소비·회차 관람권 발급·서버 권한 검사 미구현. 잠김 해제는 화면 상태만 변경 |
| 계정 소셜·공개 게시 | 실제 계정 구독·댓글 전송·공개 게시·반응 집계 미구현. 공유 시트는 외부 SNS로 발송하지 않음 |
| 서버·저장 | 시안 전용 운영 서버/API·계정 저장은 미구현. 등록된 기존 음악 화면은 원래 앨범/투표 원장을 읽고 기존 허용 명령만 사용. 시안 메모리를 실제 저장 성공으로 표시하지 않음 |

시안 조작은 `/src/simulator/media-preview.mjs`와 `/data/simulator/media_preview.json`, 음악 화면은 `/src/simulator/music-career/music-app-panel.mjs`와 `/src/simulator/media-preview/music-registry.mjs`를 재사용합니다. 임시 시안 데이터와 실제 앨범/투표 원장을 섞지 않으며, fixture adapter는 별도 source나 저장 범위를 만들지 않습니다.
