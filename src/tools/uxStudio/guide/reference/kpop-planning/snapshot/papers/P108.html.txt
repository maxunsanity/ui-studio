<p><strong>지금 상태</strong> 팬 시험·핵심제안 경제 계산·보드 도착 돈(기본 돈 + 팬 돈)·건물 팬 말풍선·팬 이탈 차감·앨범 이벤트 정산이 들어가 있습니다. 팬층·수익·습격 운영 통합 장부와 자동 발란스의 개별 멤버 정산은 <strong>개발 안됨</strong>, 팬·보상 수치는 <strong>발란스 대기</strong>입니다.</p>

<p>게임에서 팬은 아이돌을 응원하는 사람이며, 수익은 시설과 활동을 이어갈 돈입니다. 시설 투자와 아이돌 성장은 서로 이어지지만, 시험 화면에서 표시한 팬이나 보상이 곧 실제 지갑에 지급된다는 뜻은 아닙니다. 팬 수익의 최종 공식·인원·비율은 <strong>발란스 대기</strong>입니다.</p>

</section><section class="part" id="part-3"><h2>3. 구동 방법·시뮬레이션</h2><p>화면 흐름: 공용 시뮬레이터 → 아이돌 성장 또는 팬 증가 → 현재 팀 확인 → 시험 조건 선택 → 변화 관찰. 시험 수치는 실제 게임의 지급이나 최종 발란스가 아닙니다.</p>
<h3><a href="../../../../game-simulator.html?module=simulator_module_fan_growth">▶ 팬 증가 시뮬레이터 열기</a></h3>
<h3><a href="../../../../game-simulator.html?module=simulator_module_idol_growth">▶ 아이돌 성장 시뮬레이터 열기</a></h3>
<ol>
<li>현재 세션의 팀·팬 정보를 확인합니다. 팬이 실제로 0인 것과 층별 원본이 전달되지 않은 것은 다르게 표시합니다.</li>
<li>현재 팀 화면은 읽기 전용입니다. 「독립 시즌 시험」 또는 「독립 개별 시험」을 누르면 별도의 시험 창이 열립니다.</li>
<li>별도 창에서 시험 대상·시작 인원·조건을 확인합니다. 없는 자료는 임의로 채우지 않으며 예시는 명시적으로 불러옵니다.</li>
<li>시즌을 돌리거나 개별 활동을 시험하고 시작값과 결과를 비교합니다. 시험은 별도 범위에서 진행하며 원래 팀의 팬 장부·지갑을 덮어쓰지 않습니다.</li>
<li>팬 증가 전용 시험의 운영 통합과 앨범 이벤트 연결은 구분합니다. 앨범은 <a href="/docs/planning/game-simulator.html?module=simulator_module_music_chart">같은 공용 게임의 차트</a>에서 발매·실제 보드·활동 게이지·만료·다음 앨범을 시험합니다.</li>
</ol>
<figure class="doc-diagram"><div class="mermaid">flowchart LR
 A[현재 세션 자료] --&gt; B[팀과 팬 상태 확인]
 B --&gt; C[시험 대상과 조건]
 C --&gt; D[하루 이동 계산]
 D --&gt; E[전후 팬층 비교]

<p>앨범 이벤트의 추가 현금은0이며 신규 <strong>앨범 이벤트 재화</strong>를 별도 원장에 적립합니다. 실제 보드 사건의 순위/배수를 동결한 뒤 기존1번 출발점 통과에서 재화·팬·고정 참여자 능력과 함께 처리합니다. 기존 보드 돈·일반 방송/공연 보상은 유지합니다.</p>
<p>순위1/2<del>10/11</del>25/26<del>50/51</del>100위의 배수1 재화량은10/6/4/2/1의 <strong>로컬 값</strong>입니다. 차트 점수·money·경제S와 단위가 다릅니다. 시티 투어 참가비로 사용합니다. 직접 현금 교환·시즌 보존과 정식 재화표 등록은 별도입니다.</p>
<p>게임 START의 전용 원장·기존 팬/멤버 성장 callback·중복 영수증·복구 연결을 구현했습니다. 자동 발란스는 개별 멤버 writer가 없어 신규 앨범 정산 전체를 대기로 둡니다. 일부 재화만 지급하거나 합류 전원에게 임의 배분하지 않습니다. 최신 실제 정산 화면은 사용자 확인 항목입니다.</p>
<h3>앨범 참여자에게만 주는 1일 추가 능력 — 게임 소스 구현</h3>
<p>리그는 발매한 앨범의 <strong>고정 참여 명단·파트·참여도</strong>를 함께 사용합니다. 순위와 보드 실적에서 나온 멤버별 기본 능력량에 각 참여자의 계수를 적용하고, 보컬·랩·제작 역할에 맞는 기존 세부 능력으로 보냅니다. 미참여 멤버의 이 앨범 추가 능력량은0입니다. 기본량을 인원수나 참여도 합계로 나누지 않는 <a href="%EC%A0%95%EC%82%B0%EA%B8%B0%EC%A4%80_%EB%B0%9C%EB%9E%80%EC%8A%A4%EA%B5%AC%EC%A1%B0_%EA%B8%B0%ED%9A%8D%EC%84%9C.md">P179 정산 기준</a>을 유지합니다.</p>
<p>기간중 추가 효과를 적립하고 기존1번 출발점을 통과할 때 정산합니다. 기간이 끝나면 새 적립은 멈추며 이미 적립된 미정산분도 그 곡의 고정 명단으로 처리합니다. 현재 대표곡이나 현재 팀 명단으로 대상을 바꾸지 않습니다. 새 멤버·이름 변경·성장 상한 도달로 남은 양을 다른 멤버에게 옮기지 않습니다.</p>
<p>전용 이벤트 재화와 직접 팬은 기존 팀 소유 범위에 한 번 처리하며, 일반 보드 성장과 앨범 추가 성장을 화면과 영수증에서 구분합니다. 미참여자가 일반 레슨으로 성장한 것을 앨범 보상 오류나 앨범 참여로 해석하지 않습니다. 기존 팬/계층·활동량·차트 점수의 산식은 이번 대상 기획에서 변경하지 않습니다.</p>
<p><strong>현재 구현:</strong> 리그는 albumId/memberId/statId별 대상·요청량을 만들고 게임은 기존 멤버별 성장 callback에 연결합니다. 고정 ID가 현재 팀에 없으면 임의 다른 멤버에게 보내지 않습니다. 자동 발란스 targeted API와 최신 실제 정산 검수는 대기입니다.</p>

<h3>팬층 · 현재 시험</h3>
<p>팬 증가 화면은 라이트·코어·콘크리트를 화면 팬으로 보여 주고 머글·휴덕·악개·안티를 별도로 보여 줍니다. 표의 <code>fan_tier_fan</code>은 라이트로 합쳐 제거된 호환 항목(<code>ladder=removed</code>)입니다. 일부 old 전이 행·legacy 스위치가 남는 사실과 현재 화면의 층 목록을 구분합니다. 팬층의 이동은 원본 표와 시험 입력을 따릅니다. 이동량·비율과 수익 효과는 발란스 대기입니다.</p>

<h3>수익 계산 · 핵심제안 모델</h3>
<p>핵심제안의 <code>tileIncome</code>은 시설 칸이면 해당 시설 단계의 수익과 그 칸 팬 곡선을 읽고 칸 가중치·판정·주사위 배수 적용 여부를 따집니다. 사업 시설은 팬 합을 쓰는 추가 계산이 있습니다. 시설이 아닌 고정 수익 칸은 별도 값으로 처리합니다. 이 식은 <strong>핵심제안 시즌 모델</strong>의 현재 계산이며 실제 게임의 모든 지급 경로가 연결됐다는 의미가 아닙니다.</p>

<h3>남은 결정</h3>
<p>팬층 이동 비율과 마일스톤 보상은 계산값으로 켭니다. 인구 51,609,121 · 콘서트 잭팟 이동 켬(그날 콘서트 잭팟으로 옮긴 양은 하루 이동에서 빼서 이중 이동 없음) · 능력→팬 켬 · 건물 도착 즉시 팬 켬. 건물 팬은 라이트층에 들어가며 멤버별로 기록하고 건물 합계는 멤버 합입니다. 건물 위에 아이돌 NPC는 그리지 않고, 보드(발란스 시뮬·현황판)의 건물 위 말풍선에 그 건물에 지금 남은 팬과 빠진 팬을 표시합니다. 말풍선을 누르면 멤버별 팬 수가 나옵니다. 아이돌 NPC 수(팬 5,000명당 1명 · 건물당 상한 100)는 기록에만 계산되고 화면에 그리지 않습니다. 팬 돈은 위 「보드 도착 돈」을 따릅니다. 출발 칸 사옥은 팬 배분 대상이 아니며 말풍선에 「팬 배분 대상 아님(시작 칸)」을 표시합니다. 말풍선 숫자는 늘 건물 합계이고, 멤버 수와 멤버별 팬은 펼쳤을 때만 보입니다. 두 번째 룰렛 잭팟 칸(5.05%)에 멈추면 콘서트 건물에서 보드 전체 팬을 가져오고, 그 이동을 도착 글에 함께 적습니다. 콘크리트 팬 비율 목표는 현재 측정값(무료 17.26<del>18.83%, 헤비 32.15</del>32.44%)으로 둡니다.</p>

<h3>공통 시간 버프와 오른쪽 상세</h3>
<p>시간 버프는 타입·출처·현재 저장 범위·기준 시계·시작/종료 시각·남은 시간·효과를 공통 형식으로 표시합니다. 앨범은 <code>album_rank</code> 타입입니다. 게임 상단 연출 영역에는 현재 순위·<strong>시:분:초</strong>만 작은 한 줄 칩으로 겹쳐 표시하고, 누르면 같은 곡의 차트로 이동합니다. 차트 화면에서는 이 칩을 숨기고 오른쪽 상세는 유지합니다. 적립 기준·긴 설명은 오른쪽에 둡니다. 크기·위치·여백과 차트 숨김 대상은 공통 UI JSON에서 조절합니다. 오른쪽에는 곡·현재 순위·남은 시간·주요 효과의 대표 요약이 항상 보입니다. 참여자별 능력·미정산·시계와 상세 계산은 기본 접힌 상세 보기에 두고 펼칠 때 확인합니다. 시간/상태 갱신·오른쪽 host 이동에서도 펼친 상태를 유지합니다. 하단 차트는 실제 차트 화면에서만 선택 표시를 하고, 버프가 켜져 있다는 이유로 선택 표시하지 않습니다.</p>
<p>오른쪽에는 곡·고정 참여자·현재 순위·유효 남은 시간, <strong>활동1회·배수1의 적립 기준</strong>, <strong>이 곡의 실제 START 미정산 합계</strong>를 구분해 표시합니다. 시험 적립은 별도입니다. 화면 숫자는 한 바퀴의 고정 지급량이 아니며, 유효 활동에서 쌓인 적립을 기존 출발점 정산에서 지급합니다. 만료되면 신규 적립과 활성 표시가 끝나며 이미 적립한 기록은 정산 대상으로 남습니다.</p>
<p>공통 표시는 캐시된 시간만 매초 갱신하고 저장 전체를 매초 검증하지 않습니다. 숨은 화면은 타이머를 멈추고 복귀 시 원본을 확인합니다. 기존 멤버 시간 버프는 원래 <code>ends_at</code>과 계산을 유지하며, 명시한 시계 변환기를 통해 같은 표시 계약에 연결합니다. 비어 있는 기존 표에서 버프를 만들거나 다른 시계의 날짜를 임의로 합치지 않습니다.</p>
<h3>출발점 추가 보상 필러·자동 결과 연결 — 후속 기획, 미구현</h3>
<p><strong>출발점 통과 → 기존 정산 확정 → 일반 보상 → 앨범 버프 추가 보상</strong> 순서의 필러 연출이 필요합니다. 별도 앨범 줄에 실제 영수증의 전용 재화·팬·참여 멤버별 능력을 표시합니다. 클릭 전부터 정산 결과를 이해할 수 있어야 하며, 연출 재생이 지급을 다시 실행하면 안 됩니다.</p>
<p>발란스 시뮬레이터도 같은 계산·정산 영수증을 결과로 내보내고, 현황판은 그 결과를 읽어 일반 보상/앨범 추가 보상과 실제 지급/대기를 나눠 표시해야 합니다. 현황판에서 별도 보상을 계산하거나 수동 지급하지 않습니다. 필러 연출·개별 writer·자동 결과 내보내기·현황판 상세 반영은 각각 후속 개발/검수 항목입니다.</p>

<p><strong>한 명이 참여하면 솔로, 팀 일부의 두 명 이상이 참여하면 유닛, 팀 전원이 참여하면 팀 앨범</strong>입니다. 5명 팀에서 3명이 부르는 앨범은 유닛입니다. 한 명뿐인 팀의 첫 싱글도 솔로입니다. 처음 곡을 만들 때 고른 참여 멤버·파트를 앨범에 고정하며, 이 명단이 추가 능력을 받을 대상을 정합니다.</p>
