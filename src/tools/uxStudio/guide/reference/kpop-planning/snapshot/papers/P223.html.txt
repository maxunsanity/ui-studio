<p class="doc-key" data-mons-inner-plan-status="proposal">컨디션 개발 현황: 성장 정산·몬스 배정 화면·현재 컨디션 단계의 게임·진행률 회복과 배정 몬스의 실제3D 모델을 연결했습니다. 발란스 몬스 탭과 게임 몬스 화면에서 돌봅니다. 출현·초반XP·비정지 FIFO·원GLB 전투와 본게임 공용 연결을 적용했고 일반1배속 전투·선택 누적·성공 결과를 확인했습니다. 레이저 머리 위 드론은 별도11항 소스와 실제 이동·총구를 확인했으며, 기존 승리 기록과 변경 시점을 구분합니다. 이전 설정의 화면 확인과 구분합니다. 전체 아이돌 요약 표시와 실제 작은 폰 화면 검수도 진행 중입니다.</p>

<p>출처: (합침) <a href="../../../%EB%B3%B4%EA%B3%A0/20261030_%EC%9C%A0%EB%A5%B4%EB%84%B7_%EB%AA%AC%EC%8A%A4%EB%B3%B4%EC%9C%A0%EA%B5%AC%EC%A1%B0_%EA%B8%B0%ED%9A%8D%EC%A0%9C%EC%95%88.html">몬스 보유 구조 제안</a> · <a href="../../%EA%B8%B0%ED%9A%8D%EC%84%9C/%EC%82%B0%EC%B6%9C_%EA%B8%B0%ED%9A%8D%EC%84%9C_%EC%B9%B4%EB%93%9C%EB%AA%AC%EC%8A%A4_%EC%83%88%EA%B5%AC%EC%A1%B0_v1_%ED%81%B4%EB%A1%9C%EB%93%9C.html">P226 카드·몬스 새 구조</a> · <a href="%EB%AA%AC%EC%8A%A4_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">P96 몬스</a>.</p>
<p>몬스의 소유자는 <strong>기획사</strong>입니다. 보유 몬스는 몬스 4축 종합 로비에서 기획사 지킴이 · 아이돌별 수호 몬스(컨디션) · 스케줄 유닛으로 배정하며 같은 몬스는 한 곳에만 들어갑니다(P243 4 · 5장). 게임 처음 시작 때 첫 몬스 1마리를 받고 오디션은 몬스를 주지 않습니다. 이후 얻는 몬스는 모두 1단 한 마리이며, 같은 종 · 같은 단 2마리가 되면 즉시 윗단 1마리로 합성되어 10단까지 오릅니다. 10단을 넘친 몫은 <strong>공용 행복 재화</strong>로 적립하고, 행복 10으로 몬스 팩 1을 교환합니다.</p>

<section class="part" id="part-3"><h2 id="3-구동-방법시뮬레이션">3. 구동 방법·시뮬레이션</h2>
<p>화면 흐름: 첫 몬스 받기 → 팩 받기·자동 개봉 → 새 종/자동 합성 → 행복 적립/상한 주사위 → 보유 목록·상세·현황판. 스샷 미완 · 이식 비교 해당 없음.</p>
<ul>
<li><a href="/docs/planning/idle-sim.html">발란스 시뮬레이터</a>는 자동 굴림 중 실제 획득 결과를 보여주고 하단 몬스에서 현재 보유와 공용 행복을 확인하는 경로입니다.</li>
<li><a href="/docs/planning/balance-tool.html?topic=balance_topic_mons_pack">발란스 툴 · 몬스 획득·합성</a>은 팩 받기·자동 개봉·합성 결과를 시험하는 경로입니다. 시뮬레이터와 같은 획득 연출을 사용합니다.</li>
<li><a href="/docs/planning/growth-board.html?open=p6">성장 현황판 06</a>은 보유 종·지금 단(1~10단)·공용 행복과 실제 변화 기록을 읽기만 합니다.</li>
<li class="yr-old">문서 하단의 이전 구조 시안은 보존 자료이며 새 행복 재화의 적립 결과를 확인하는 실행 경로는 위 공용 화면입니다.</li>
</ul>
</section>

<h3 id="몬스-ui와-성장-현황판-06">몬스 UI와 성장 현황판 06</h3>
<p>UI는 보유 목록·선택한 몬스 상세·최근 실제 획득/합성·보유 행복을 보여줍니다. 개별 몬스는 지금 단과 다음 단까지 남은 마리 수, 행복은 공용 잔액으로 표시합니다(R-MON-5). 현황판은 <code>owned</code>, <code>happiness</code>, <code>history/last</code>, <code>runId</code>를 읽고 같은 사건을 중복 표시하지 않습니다. 최초 연결은 기준 상태로만 잡으며 실제 새 획득·적립 ID가 들어올 때만 원천 → 06 테두리 → 중앙 정보선을 보여줍니다. 엔터파워·사옥은 실제11→06 기록, 미션·튜토리얼·미분류 보관팩은 실제12→06 기록을 읽습니다. 미션의 실제 플레이·장부 → 12 진행 → 수령 영수증 → 06 몬스팩·행복 → 중앙으로 연결 기록을 표시합니다. 엔터파워·사옥의 직접 팩은 11 → 06이며 행복 교환은 중앙 → 06으로 구분합니다. 진행만 올랐거나 같은 영수증을 다시 표시한 때에는 획득·성장선을 새로 만들지 않습니다. 현황판은 이 기록을 읽기만 하며 보상과 능력을 추가 지급하지 않습니다. 같은 영수증의 행복 적립을 별도 사건으로 다시 만들지 않습니다. 12패널·기존 6축·뉴런은 유지합니다.</p>
<h3 id="탐험-그림-퍼즐-연결-현재-세팅-v1">탐험 그림 퍼즐 연결 · 현재 세팅 v1</h3>
<p>기존 <strong>6분류·27종 도감</strong>을 유지하고, 퍼즐은 <strong>동일 그림 조각 9개로 맞추는 3×3 한 종류</strong>입니다. 실제 수령한 같은 그림(itemId)의 조각만 사용하며 각 그림의 조각을 따로 계산합니다. 칸당 조각 1개, 완성 보상은 <strong>주사위 27개 · 현재 세팅 v1</strong>입니다.</p>
<p>회차별 고유 영수증으로 조각 9개 사용·실제 주사위 지급·해당 그림의 다음 회차를 한 번에 확정하며, 다시 누르거나 저장을 재시도해도 중복 수령하지 않습니다. 초과한 같은 그림 조각은 다음 회차로 이월합니다. 각 그림의 누적 발견·스토리·도감·완성 기록·이전 수령 이력과 다른 그림의 조각은 남습니다. 모험 전체 정의는 <a href="%EB%9D%BC%ED%8F%ACAI%ED%83%90%ED%97%98_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">P152</a>, 연결 그림은 <a href="%EB%AA%AC%EC%8A%A4_%EA%B8%B0%ED%9A%8D%EC%84%9C.html#puzzle-link">P96 4장</a>에 둡니다.</p>

<h3 id="발란스-전체-실행과-몬스-저장의-경계">발란스 전체 실행과 몬스 저장의 경계</h3>
<p><a href="%EB%B0%9C%EB%9E%80%EC%8A%A4%EC%8B%9C%EB%AE%AC%EB%A0%88%EC%9D%B4%ED%84%B0_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">P171 발란스 시뮬레이터</a>는 같은 플레이 전체를 새로고침 뒤 이어갑니다. 몬스 종·합성·행복·처리 영수증을 일차·경제·능력·카드/팩·미션·모험 티켓/조각/퍼즐/우정·라포·게이지·이력·난수 커서와 한 묶음으로 저장합니다. 복원 뒤에는 멈춘 상태로 돌아오고 기존 시작 버튼으로 계속하며, 초기화할 때 새 시험을 만듭니다.</p>
<p>발란스 전용 체크포인트는 <code>kpopmonsters.idle-sim.run.v1</code>, 내부 저장 구분은 <code>simulator_module_balance_idle</code>입니다. 별도 게임의 기획사 몬스·행복·성장 저장을 시험 진행과 섞거나 초기화하지 않습니다. 몬스의 시즌 보존 규칙은 해당 진행 안에서 유지하며, 일차와 경제가 새 실행인데 예전 몬스·행복만 남는 혼합 상태로 복원하지 않습니다.</p>
<p>모든 필수 파트와 버전·체크섬·원본 데이터 서명이 맞아야 함께 복원합니다. 누락이나 불일치가 있으면 몬스만 살리는 부분 복원 대신 해당 시험 전체를 새로 시작했다는 안내를 표시합니다. 과거의 몬스 일부 저장을 완전한 실행 자료로 간주하지 않습니다. 첫 몬스·팩·행복은 기존 지급·소비 영수증을 보존하므로 새로고침과 현황판 재조회가 추가 획득을 만들지 않습니다.</p>
<p>외부 발란스 화면은 실제 획득·합성·행복 변화와 필러를, 내부 현황판은 원천·소비·미공급·실제 장부를 보여줍니다. 06은 같은 실행의 보유와 확정 영수증만 읽고 다른 실행의 몬스로 보충하지 않습니다. 미션 일반 흐름과 몬스 수령 사건을 중복 재생하지 않으며 같은 실행의 오래된 revision으로 최신 보유를 덮지 않습니다. 이 연결 보완으로 합성·행복·대체 주사위 등 원표 수치를 변경하지 않았습니다.</p>

<h4>보유·배정·회복의 관계</h4>
<p>기획사 소유 몬스를 아이돌별 수호 몬스로 배정하는 신규 기획입니다. 같은 종1개는 동시에 아이돌1명에 배정하며 전투 밖에서 무료 교체합니다. 보유 종·행복·단과 배정은 별도로 저장합니다.</p>
<p>몬스가 관리하는 값은 아이돌별 컨디션0~100입니다. 실제 능력 획득으로 감소하고 현재 컨디션의5단계에 대응하는 ‘컨디션 게임’으로 회복합니다. 상세 수치와 게임 규칙은 P96, 공통 성장·저장은 P107, 출처별 연결은 P169를 따릅니다.</p>
<p>배정·컨디션 게임·회복은 동작과 저장을 연결했으며 비율은 현재 세팅입니다. 실제 화면 검수와 기존 보유/지급 완료는 구분합니다. <span class="yr-old">앞선 나쁜 영향 일상누적·영구 순차해금 초안은 대체합니다.</span></p>
<h4>기획사 보유와 아이돌 배정</h4>
<ul><li>기획사 소유는 유지하고 아이돌 1명에게 보유 몬스 1종을 배정합니다. 현재 인벤토리가 종 단위이므로 배정 키도 보유 종 ID를 사용합니다. 같은 보유 종의 동시 배정은 아이돌 1명까지로 제한합니다.</li><li>배정·해제·교체는 전투 밖에서 무료이며 몬스를 소모·복제하지 않습니다. 몬스가 한 마리뿐이면 다른 아이돌에게 옮겨 돌볼 수 있습니다. 미배정이면 해당 아이돌에 배정하는 동선을 먼저 엽니다.</li><li>배정 중인 아이돌과 몬스는 컨디션 게임 한 판 동안 교체할 수 없습니다. 기존 디펜스·출연권·모험 출동 명단은 별도이며 새 배정으로 보유 수나 기존 출전 명단을 바꾸지 않습니다.</li><li>후보의 옛 mons_id/generated_mons는 새 배정의 근거가 아닙니다. 실제 기획사 인벤토리와 candidate_id 기반 배정표에서만 읽습니다.</li></ul>

<h4>현재 컨디션 규칙과 캐릭터 정보 연결</h4>
<p>컨디션 전투는 이동형 CRUSHER와 TITAN을 사용합니다. 고정형 NEXUS는 이 모드에서 제외하고 기존2·5단계를 CRUSHER로 연결합니다. 원래 스퀘어 게임의 NEXUS·벽 패턴과 원본 자산·CSV는 변경하지 않습니다.</p>
<p>개인 컨디션은0~100이며 기획사 나쁜 기운과 별개입니다. 캐릭터 정보의 개별 능력에서 컨디션·배정 몬스·게임 입장 상태를 확인합니다. 미배정은 기존 몬스 배정 화면으로, 배정됨은 같은 아이돌의 기존 컨디션 게임으로 연결합니다. 사용한 몬스는 게임 종료 후24시간 쉬며 다른 아이돌에게 옮겨도 제한을 유지합니다. 패배도 사용으로 세고 나가기·안전 취소는 회복0·사용 횟수 제외입니다.</p>
<p>현재 회복 방식은 정책 v6의 fill_by_progress입니다. 전투 설정의 웨이브 표는3단계 기준이며, 다른 단계는 보스 등장 시간의 비율로 웨이브·종대 시각을 늘리거나 줄입니다. 스킬 선택 카드는 전투 화면 크기를 바꾸지 않고 하단에 겹쳐 표시하며 전투·선택권 누적은 계속됩니다. 보스 처치는100까지, 패배는 정산 시점의 빈 만큼×진행률을 회복합니다. 고정 회복값 recovery_bp와 기본 보스 시간은 fixed 방식의 값이므로 현재 방식의 회복량·단계별 시간으로 쓰지 않습니다. 실제 결과와 중복 지급 검사는 기존 계산·저장 어댑터가 맡습니다.</p>
<p>발란스 자동 진행에서만 컨디션50% 이하이고 배정 몬스가 쉬지 않을 때 자동 사용합니다. 현재 자동 판은 완주를 가정한 시험 계산이며 실제3D 플레이 결과가 아닙니다. 시뮬 하루는86400초로 계산하고 주사위 한 번 또는 오프라인 계산이 끝난 뒤 검사합니다. 여러 날 오프라인 계산은 마지막에 한 번만 검사합니다. 본 게임 수동 플레이에 자동 완주를 적용하지 않습니다.</p>
