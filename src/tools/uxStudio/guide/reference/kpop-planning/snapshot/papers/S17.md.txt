# S17 · 기획서 툴 제작 기본 양식 v02

**이 문서는** 새 게임에서 기획서 툴을 만들 때 그대로 따라 채우는 **제작 기본 양식(계약서)**입니다. 지금 케이팝 몬스터즈 툴이 실제로 어떻게 생겼는지를 예로 들고, 새 프로젝트가 채울 빈칸을 정리합니다.

**보는 법**
- 1장: 툴 기능 33개 목록
- 2장: [시뮬레이터](../../../game-simulator.html) 구조(등록 → 실행 → 저장 → 복귀)와 새 모듈 붙이는 절차(2-3, 빈칸 양식)
- 3장: 왼쪽 흐름도 내비와 문서 읽기 공통 규칙
- 5장: 새 게임에서 채우는 제작 계약 표(핵심)
- 6장: 아직 남은 빈 곳
- 표의 「현재 프로젝트 예」 칸은 케이팝 몬스터즈 값이고, 새 게임의 고정값이 아닙니다.
- 시뮬레이터 없음 (툴 양식 문서). 툴 열기: [기획서 툴](/docs/planning/planning-docs-tool.html) · 이전 판: [v01 원문](S17_기획서툴_제작기본양식_v01.md)

**지금 상태 (10/30 코드 기준)**
- **개발됨**: 1장 기능 목록, 시뮬레이터 공용 host와 등록표(`data/simulator/simulator_module.csv`, 지금 22개), 흐름도 표(`data/simulator/flow_node.csv` 29행 · `flow_edge.csv` 28행), 메모리 현재행 변환(`src/simulator/growth-relation/record-rows.mjs`).
- **바뀐 점**: 10/23 이후 모듈이 17→22개로 늘었고 메뉴가 기본/성장 도구/보조로 나뉘었습니다. 흐름도 표에는 새 모듈 5개가 아직 없습니다.
- **현재 개발되지 않음, 진행 중**: 복귀 허용 목록 하나로 모으기, 현재행 변환의 실제 저장·import 연결, 프로젝트 설정 파일 하나로 범용화, 완전히 빈 프로젝트 부팅, 임시 부모·복귀·데이터선.
- 본문 표의 줄 번호는 빼고 파일 이름만 남겼습니다.

**구조를 고칠 때:** [게임 시뮬레이터의 연결·화면·저장 계약](#game-simulator-data-contract)을 먼저 읽습니다. 아래 개수와 과거 검수 기록은 표기된 시점의 예이며 현재 실행 상태의 증거로 대신하지 않습니다.

## 2. 시뮬레이터 구조
### 2-1 현재 구성·생명주기·저장 경계
이 절은 현재 케이팝몬스터즈 구현입니다. 공통 부품을 재사용할 수 있지만 다른 게임으로 설정만 바꿔 완전히 전환되는 상태는 아닙니다.

**등록/실행:** host는 `data/simulator/simulator_module.csv`를 읽고 ID·instance_key·panel_key·needs_world와 `entry_path`를 검증합니다. `entry_path`는 `/docs/planning/_runtime/simulator/` 아래이고 `..`가 없어야 합니다. 실행은 기본적으로 등록 `entry_path`를 import하지만, host의 명시 모듈 분기는 등록 `source_path`에 entry의 query를 붙여 직접 import합니다. growth-lab 설정 목록에 든 모듈은 공통 `growth-lab/view.mjs`로 들어갑니다. 이는 모든 source를 새로 허용하는 규칙이 아니며, 현재 host의 지정 분기·등록행·growth-lab 설정을 함께 확인하는 기존 구현 설명입니다.

| 단계 | 현재 동작 | source 근거 |
|---|---|---|
| mount | 필요한 world만 lazy-load하고 등록 entry 또는 위 예외 경로를 import한 뒤 mount(ctx) 호출, controller 필수 메서드 검사 | host.mjs |
| context | world/profile/panel/text/flow/hub/navigate/testSession/testPage/dataSource/mobileFrame 등을 공급 | host.mjs |
| 재사용 | controller·진행 중 mount Promise를 instance_key별 cache | host.mjs·99~102 |
| activate/deactivate | 이전 controller를 숨기고 새 행을 activate(row,request); 일반 전환은 cache 유지 | host.mjs~114 |
| 같은 모듈 상세 | 전체 선택을 반복하지 않고 선택적 openDetail(request) 호출 | host.mjs~151 |
| 이동 제한 | canDeactivate와 메인 복귀의 beforeNavigate는 서로 다른 검사 | host.mjs·136~142 |
| serialize | snapshot API가 controller 결과를 수집; 이 호출 자체가 자동 저장은 아님 | host.mjs |
| dispose | scope 이동·세션 교체·pagehide 때 controller/공통 UI/world 정리 | host.mjs~90·122·159~166 |

**저장:** 팀·성장 기록은 test-session·handoff·snapshot·checkpoint·hub·출연권 장부·page scope로 나뉘며, 하나의 storageKey가 전체 원본은 아닙니다. 기록별 키와 쓰기 주체는 [S16](S16_오디션허브메뉴_데이터흐름.md) 권한표를 봅니다.

**공통 화면:** mobile-frame.mjs~104는 content/filler/actions/information의 기존 DOM을 옮기고 :196~202에서 복원합니다. normal/popup은 설정의 논리 크기를 scale하고, inline은 실제 배치 픽셀·scale1을 사용합니다(:116~133·159~185). 현재 설정390×844는 모든 모드의 고정 크기라는 뜻이 아닙니다. phone-fit.mjs~22는 보드 폰과 우측 aside의 폭·resize를 연결합니다. native-mobile-frame.mjs~21은 host 공용 폰이며 각 모듈 내부 폰과 구분합니다.

공통 요약은 host가 전달한 현재 scope의 Storage를 읽습니다. 메인·단독의 출처를 구분하고, 요약 reader가 팀·지갑을 새로 만들지 않습니다. 보드 리뷰는 현재 getState를 요약하며 환경 적용 callback도 있으므로 화면 전체를 읽기 전용이라고 부르지 않습니다. [현재 구조·writer 계약](#game-simulator-data-contract)을 함께 따릅니다.

**복귀 정책은 아직 분산돼 있습니다.** 허용 목록이 casting-flow·detail-navigation·host·idol_growth/play에 따로 있고 공통 정책은 없습니다. 위치별 내용은 [S16](S16_오디션허브메뉴_데이터흐름.md) 3장 8을 봅니다.

**source/runtime:** 현재 game-simulator.html은 /src/simulator/host.mjs를 직접 실행합니다. 이후 각 모듈은 등록 entry 또는 host의 명시 분기를 사용합니다. 음악 runtime은 source mount 재수출 진입이며, 다른 _runtime 파일에는 과거 묶음도 남아 있습니다. 실제 실행 HTML·등록행·source 관계를 읽고, 과거 host.js 반영 기록을 현재 진입점으로 단정하지 않습니다. 빌드·서버 재시작 권한은 이 설명에서 부여하지 않습니다.

### 2-1a. 현재 프로젝트의 네 도구 · 원본·계산·저장 경계

아래는 현재 케이팝몬스터즈 코드의 배치 예입니다. 계산 함수 재사용과 저장 공유는 다른 계약입니다. 기능마다 원표·로더·계산·쓰기 주체와 조회 경로를 직접 확인하며, 이 표를 다른 프로젝트의 고정값이나 모든 기능의 운영 완료로 쓰지 않습니다. 기존 2-1·2-2의 개수와 검수 기록은 각 절에 적힌 시점과 구분합니다. 현재 실행 경로는 아래 표와 2-1의 등록/실행 문단을 함께 읽습니다.

| 도구 | 맡는 작업 |
|---|---|
| 게임 시뮬레이터 P94 | 등록된 게임 기능을 직접 조작하고 연결·정산·복귀를 검수 |
| 발란스 시뮬레이터 P171 | 시나리오·배수·자동 정책으로 시즌을 진행하며 경제·성장·보상을 관측 |
| 발란스 툴 S02 | 원표와 시험 입력을 숫자·그래프로 비교 |
| 성장 현황판 P169 연결 | 현재 실행이 보낸 상태·변화·출처·정산 기록과 상세를 조회 |

원본·수정 위치와 저장 경계:

- **게임 시뮬레이터 P94** · `game-simulator.html` → `src/simulator/host.mjs`. **원표·계산:** `simulator_module.csv`의 entry/source, 공통 세션 계약과 모듈별 실제 CSV/JSON·게임 계산. **저장·조회:** host가 같은 session/run과 허용된 `testPage` 저장을 전달. 모듈별 허용 writer를 확인하며 메인·단독 시험·조회 source를 구분.
- **발란스 시뮬레이터 P171** · `idle-sim.html` → `idleSim/v02/app.js`. **원표·계산:** `loadBalanceData`·성장 입력 로더·기존 경제 함수. 음악도 같은 career 계산을 사용하되 실제 엔진 관측과 조건을 따름. **저장·조회:** idle 전용 페이지 저장과 `kpopmonsters.idle-sim.run.v1` 실행 기록이 주체. `kpopmonsters.growth-board.v1`은 전달용 projection이며 게임 복원 원본이 아님.
- **발란스 툴 S02** · `balance-tool.html` → `balanceTool/shell.ts/main.ts`. **원표·계산:** `tool_balance_source.csv`와 `data.ts`의 명시 참조표, 기존 경제/시즌 계산. 음악 비교는 규칙 복사본과 preview 함수. **저장·조회:** 주제 선택 등 표시 저장과 비교 입력을 구분. 비교값만으로 원표 변경이나 운영 보상 지급의 완료를 판단하지 않습니다. 기존 시즌 계산은 공용 경제 함수의 팬 기록을 쓰는 함수(writer)에 도달할 수 있으므로 실행 주소의 `testPage`/기본 저장 범위와 실제 저장 결과는 별도로 확인합니다(실제 저장 미검수).
- **성장 현황판 P169 연결** · `growth-board.html` → `growthBoard/main.mjs`. **원표·계산:** 유효한 전달 payload·전달용 저장과 상태/표시용 표. parent/opener·동일 출처·run/순서 계약으로 수신. **저장·조회:** 게임 성장·경제·보상 writer가 되는 화면이 아님. 실제와 샘플·연결대기를 구분하고 다른 출처를 현재 실행의 실제값으로 채우지 않음.

새 기능의 조작·비교·자동 관측·조회가 어느 도구에 들어가는지 먼저 정합니다. 저장 API와 초기화 범위는 실제 함수에서 따로 확인합니다. 페이지 저장 prefix가 있다는 사실만으로 모든 공통 조작까지 격리됐다고 단정하지 않습니다. 브라우저 시험 기록과 본게임 계정·서버 저장의 완료도 구분합니다.

문서 하단 표시 시안은 시안별 CSV/API·계산·writer·저장 경로를 확인하여 메모리·DOM 표시와 실제 네 도구·계정 저장 연결을 구분합니다. 시안 버튼의 동작만으로 운영 연결이나 저장 성공을 확인했다고 쓰지 않습니다.

같은 `value_status`나 ID 이름도 소유표별 계약을 확인합니다. 이 문서의 옛 현재행 생성 상태 예와 `planning_value_status` 사전은 서로 대체하는 계약이 아닙니다.

### 2-1b. 기획서 툴과 게임 시뮬레이터의 연결·화면·저장 구조

이 절은 현재 소스에서 확인한 구조입니다. [네 도구의 경계](#current-tool-boundaries)와 [S16 데이터 흐름](S16_오디션허브메뉴_데이터흐름.md)을 함께 읽습니다. S16의 단일 허브·필드별 권한은 기획 목표이며, 아래 저장층이 모두 하나의 데이터베이스로 합쳐졌다는 뜻은 아닙니다. 소스에 경로가 있는 사실과 실제 화면·저장·플레이 확인 결과도 구분합니다.

#### 실행 경로와 책임

```mermaid
flowchart TD

  R --> H["게임 시뮬레이터 host<br>진입 scope 결정·세션 검사"]
  H --> L["컨트롤러<br>mount → activate ↔ deactivate → dispose"]
  L --> F["공통 폰<br>content·filler·actions·information"]
  H --> S["현재 저장 범위<br>메인 또는 명시 testPage"]
  A["오디션 인계 handoff"] --> T["test-session<br>session ID·run ID·멤버 출처"]
  T --> S
  S --> G["성장 snapshot + full checkpoint"]
  G --> O["현재 팀·성장·지갑 reader"]
  O --> L
  L --> C["음악·카드·건설 등<br>기능별 명령과 writer"]
  C --> G
  C --> M["음악 원장·허브 팬·전용 재화<br>각 계약에 따른 기록"]

```

실행 진입점은 등록표의 `entry_path`가 기본입니다. host에는 지정된 `source_path` 직접 import와 성장 실험 도구의 공통 view 분기가 있으므로, 파일 이름만 보고 실제 실행 파일을 단정하지 않습니다. `_runtime` 파일도 재수출 진입과 묶인 실행 파일이 섞일 수 있습니다. 수정할 소스·등록행·실제 진입점의 관계를 함께 확인합니다.

#### 식별자는 서로 다른 목적입니다

| 식별자 | 뜻 | 혼동하면 생기는 문제 |
|---|---|---|
| `moduleId` | 사용자가 고른 기능·보기의 ID입니다. | 화면을 바꿀 때마다 새 팀이나 새 저장을 만드는 것으로 오해합니다. |
| `instance_key` | 컨트롤러 재사용 묶음입니다. 음악 제작·발매·차트·페스티벌 등은 같은 음악 인스턴스의 다른 mode입니다. 성장 실험 도구는 별도 cache 접미 규칙이 있습니다. | 같은 묶음에 컨트롤러를 중복 생성하거나 다른 mode의 DOM·리스너를 남깁니다. |
| `mode`, `panel_key` | 같은 기능 묶음 안의 보기와 패널 배치를 고릅니다. | 화면 패널을 저장 범위로 오인합니다. |
| `pageScope` / URL `testPage` | 브라우저 저장 키 앞에 붙는 독립 시험 범위입니다. | 같은 module이라도 다른 팀을 읽거나 메인 진행을 덮어씁니다. |
| `testSession.id` | 현재 시험 세션의 식별자입니다. 세션 교체를 검출하는 기준입니다. | 예전 탭의 화면이 새 세션을 갱신합니다. |
| `runId` | 현재 판의 출처입니다. 오디션은 인계의 resultId와 연결됩니다. | 다른 판의 결과·보상·성장을 합칩니다. |
| `candidate_id` | 멤버의 동일성을 구분하는 ID입니다. 이름·색상·그림은 식별자를 대신하지 않습니다. | 이름이 같은 다른 후보의 능력·이야기를 붙입니다. |
| `mons_id` | 멤버와 함께 기록된 몬스 정보입니다. 후보 ID와 다른 칸입니다. | 오디션의 빈 몬스 칸 때문에 같은 멤버를 다른 사람으로 오인하거나, 반대로 명시된 다른 몬스를 무조건 허용합니다. |
| `seasonId`, `actorId`, `teamId` | 음악 원장의 시즌·행위자·팀 범위입니다. 현재 음악 어댑터는 같은 세션에서 일관된 actor/team ID를 만듭니다. | 다른 시즌·팀의 앨범과 정산 영수증을 섞습니다. |
| `revision`, `data_signature`, `checkpoint_signature` | 관측한 버전·입력 출처·전체 진행 상태의 일치를 검사하는 근거입니다. | ID만 맞는 낡은 화면이 최신 진행을 덮어씁니다. |

[module/instance 등록](/data/simulator/simulator_module.csv), [host](/src/simulator/host.mjs), [성장 컨트롤러 구분](/src/simulator/growth-lab/routes.mjs), [세션 계약](/src/simulator/shared/session.mjs), [멤버 비교](/src/simulator/shared/member-identity.mjs)를 함께 따릅니다. 한 ID를 다른 ID의 대체 키로 쓰지 않습니다.

**오디션의 빈 몬스 칸 예외는 좁게 적용합니다.** 같은 run·같은 session이고 handoff의 resultId까지 일치하는 오디션에서, 전달된 `mons_id`가 빈 문자열일 때 현재 snapshot의 몬스 값을 허용합니다. 멤버 수·순서·중복 없는 후보 ID는 계속 일치해야 합니다. 전달 몬스가 명시됐는데 다르면 거절하며, 다른 source나 세션 표식이 없는 snapshot에 이 예외를 확대하지 않습니다. card projection 내부 멤버와 snapshot의 현재 몬스 일치 검사는 별도로 유지합니다. full checkpoint는 기존 run·서명·revision·후보 ID 검사 경로를 따릅니다. 모든 reader가 동일한 몬스 검사를 한다고 가정하지 않습니다. 현재 공통 함수의 사용 범위를 넘어 다른 reader도 모두 통일됐다고 단정하지 않습니다.

#### 연결 화면·단독 시험·발란스 전송의 경계

| 구분 | 입력과 진입 | 유지할 경계 |
|---|---|---|
| 메인 연결 | 현재 세션과 진행을 읽습니다. host 안의 일반 메뉴·콘텐츠 이동은 현재 저장 범위를 유지합니다. | 메뉴 변경만으로 새 generated 세션을 만들거나 다른 namespace를 고르지 않습니다. |
| 음악 직접 진입 | 명시적인 `testPage`가 없고 유효하게 읽히는 메인 test-session이 있으면 음악 가족은 그 범위를 우선합니다. 메인 음악 주소는 `hubSource=main`을 유지합니다. | `hubSource=main`은 탐색 문맥이며, 그 자체가 payload·지갑·full checkpoint 유효성을 증명하지 않습니다. |
| 명시적 단독 시험 | URL의 `testPage`가 있으면 그 scope를 우선합니다. `getTestStorage()`가 접두 키로 격리하며 현재 scope의 키만 열거·제거합니다. | 메인 팀을 몰래 복사하거나 메인 scope로 자동 복귀시키지 않습니다. 호출자가 원래 Storage를 직접 쓰는 우회 경로도 따로 살핍니다. |
| 생성 팀 음악 fixture | 소유한 generated/sample 세션에서 현재 멤버·snapshot을 보존한 채 설정에 따른 시험 환경을 만듭니다. 초기 marker가 재진입 때 반복 보충을 막습니다. | 오디션·발란스 전송·외부 주입 진행을 fixture 대상으로 넓히지 않습니다. 시험 지갑·요건을 실제 진행으로 설명하지 않습니다. |
| 발란스 전송 | 관측값과 원본 후보를 명시적으로 전송하고 전용 `testPage`에 세션·snapshot·표시된 projection을 준비합니다. 점수는 전송 배율을 기준으로 원단위로 변환합니다. | 원래 발란스 판이나 기존 메인 판을 덮어쓰지 않습니다. 표시 배율을 다시 능력에 곱하거나 projection을 full checkpoint로 자칭하지 않습니다. |
| 단독 음악 시나리오 | 명시 단독 앨범·차트·페스티벌은 시험 시작 버튼으로, 시티 투어는 명시 music_city scope 첫 활성화에서 현재 멤버를 고정한 시험곡·리그·최초 급유 재화를 준비합니다. 최신 실제 플레이는 미확인입니다. | 기존 발매곡/미수령 경기·영수증을 재사용하고 초안·편집·종료 리그/마감은 보존합니다. 실제 음원 생성/제작비 청구는 생략합니다. 지원금·조건 preset은 연계/오디션/발란스 전송에 적용하지 않습니다. |

원본은 [host](/src/simulator/host.mjs), [기획서 실행 도크](/src/tools/planningDocs/main.ts), [저장 scope](/src/simulator/shared/test-storage.mjs), [음악 fixture](/src/simulator/shared/standalone-test-environment.mjs), [발란스 전송](/src/tools/idleSim/v02/balance-transfer.mjs)입니다.

기획서 도크도 `module`만 기억해서는 안 됩니다. 실행 화면이 보낸 `testPage`와 허용된 `hubSource`를 함께 보존해야 링크 열기·새로고침 후 같은 진행을 가리킵니다. 음악 가족 여부는 등록된 `instance_key`에서 가져오며 별도 모듈 목록을 임의로 복제하지 않습니다.

#### 컨트롤러와 공통 폰의 수명

| 시점 | 현재 동작 | 새 기능을 붙일 때 지킬 점 |
|---|---|---|
| `mount(ctx)` | host가 Storage·map·testSession·testPage·공통 폰·navigate 등을 전달하고 필수 메서드를 검사합니다. 인스턴스와 진행 중 mount를 cache합니다. | 전달받은 `dataSource.storage`를 사용합니다. mount를 화면 전환 때마다 새로 호출하는 전제를 두지 않습니다. |
| `activate(row, request)` | 선택된 행·mode·상세 요청을 반영합니다. | 같은 인스턴스의 다른 mode에서도 누락 없이 보기를 바꿉니다. |
| `deactivate()` | 이전 화면을 숨기고 활성 입력·연출을 중단합니다. 일반 전환은 인스턴스를 보존합니다. | 숨긴 화면의 타이머·입력·소리·world 실행이 남지 않도록 자기 기능을 정리합니다. |
| 같은 모듈 상세 요청 | 지원되는 앨범 선택이나 `openDetail()`처럼 해당 컨트롤러의 기존 진입점을 사용합니다. | URL에 팀 payload를 복사해 다른 원본을 만들지 않습니다. |
| `serialize()` | host의 조회 API가 컨트롤러 상태 요약을 수집합니다. | 이 호출을 저장 성공·자동 저장 기능이라고 설명하지 않습니다. |
| `dispose()` | 세션 교체·페이지 종료·범위 변경 등에서 DOM·구독·타이머·공통 자원을 정리합니다. | deactivate와 dispose를 같은 의미로 처리하지 않습니다. |
| 전환·가시성 검사 | `canDeactivate`, 복귀 시 `beforeNavigate`, 문서와 부모 화면의 숨김 상태를 각각 처리합니다. | 이들 검사를 하나의 전역 이동·저장 정책이 이미 시행된 것으로 확대하지 않습니다. |

| 화면 영역 | 쓰임 | 소유 경계 |
|---|---|---|
| `content` | 보드·3D·콘텐츠 본문·전용 화면 | 해당 기능의 DOM·렌더링을 넣습니다. |
| `filler` | 도착 설명·안내·결과 연출 | 계산 결과를 설명하는 영역이며 별도 보상 지급 엔진이 아닙니다. |
| `actions` | 현재 화면에서 필요한 선택·진행 버튼 | 콘텐츠와 같은 DOM을 중복 소유하지 않습니다. 숨겨진 모드의 버튼은 비활성·숨김을 정리합니다. |
| `information` | 팀·멤버·능력 정보와 상세 | 현재 source의 출처와 누락 상태를 표시합니다. 정보창을 열었다는 이유로 팀·성장·지갑을 생성하지 않습니다. |
| 제작용 우측 패널·공통 요약 | 원본 수치·조작 조건·진행 상태 확인 | 현재 scope의 진행을 요약합니다. 화면 표시 어댑터가 게임 상태 전체의 writer가 되지는 않습니다. |

[mobile-frame](/src/simulator/shared/mobile-frame.mjs)은 기존 DOM을 옮기고 정리 시 복원합니다. [native-mobile-frame](/src/simulator/shared/native-mobile-frame.mjs)은 host의 공통 폰을 만들고 현재 성장 source에서 지갑 표시를 갱신합니다. 오디션·보드·캐스팅처럼 내부 폰을 쓰는 컨트롤러는 host 폰을 중복 표시하지 않습니다. [common-tool-ui](/src/simulator/shared/common-tool-ui.mjs)는 현재 전달된 scope의 요약·화면 어댑터를 붙입니다. 예전의 “단독 화면에서도 항상 mainStorage 요약” 설명을 현재 구현으로 일반화하지 않습니다.

normal/popup은 설정의 논리 크기를 기준으로 맞추고 inline은 실제 배치 크기를 사용합니다. 현재 설정에 있는 폰 크기나 특정 모듈의 actions 높이를 모든 화면의 고정 규격으로 복사하지 않습니다.

음악의 선택 추가 수신은 `dataSource.musicCareerObservation(request)`입니다. 동일 session/run/season/team·snapshot revision/checkpoint signature를 되돌려 확인한 데뷔 기준일·미션 완료 영수증·원시 팬층만 메모리에서 채택합니다. 돈·능력·멤버·전체 checkpoint는 바꾸지 않습니다. 기본 host 제공자는 미연결이며, 수신 코드 준비와 실제 원천 공급/운영 문턱 통과는 구분합니다. [필드/처리/예외 정본](../개발진행기획_v01/콘텐츠별_v03/앨범발매_기획서.html)과 [소스 수신 모듈](/src/simulator/music-career/linked-observation.mjs)을 따릅니다.

#### 저장층과 writer를 구분합니다

아래 표는 확인한 로컬 구현의 저장 책임입니다. 서버 정본·모든 기능의 권한 강제·전체 호출자 검수가 완료됐다는 뜻은 아닙니다. 기록별 writer를 통과하는 명령과 실제 성공 반환을 확인합니다.

|---|---|---|---|

| 음악 원장 | 앨범·활동·차트·페스티벌·크루·리그·영수증. `kpopmonsters.music-career.<sessionId>.<seasonId>.v1` | 음악 controller의 검증된 명령과 정식 보드 관측 bridge | session·run·season·actor·team 범위를 확인합니다. 화면별 원장 복사본이나 별도 정산 엔진을 만들지 않습니다. |

| 시설 단계 | 별도 map 시설 저장과 성장 snapshot의 현재 시설 관측 | 시설 저장 API와 정식 건설 transaction | 표시된 레벨만 바꾸고 비용·checkpoint를 생략하지 않습니다. 허용된 구조·담당 범위 안에서 고칩니다. |

#### 음악에서 현재 팀을 사용하는 순서

| 확인 단계 | 사용할 근거 | 없거나 맞지 않을 때 |
|---|---|---|
| 현재 팀 | host가 준 세션과 현재 Storage의 session/run, handoff, 유효한 snapshot, 공통 멤버 비교 | 다른 팀을 가져오지 않고 세션 변경·멤버 불일치를 표시합니다. |
| 멤버·능력 | 현재 snapshot의 후보 ID·세부 능력·현재 6축, 같은 멤버의 handoff 성별·프로필 근거 | 능력·프로필을 다른 후보 표의 순번·이름으로 대체하지 않습니다. 성별 근거 충돌과 미공급도 구분합니다. |
| 시간·미션·제작 지갑 | 유효한 full checkpoint의 day·season·미션·money와 현재 source revision | metadata-only 상태로 남깁니다. day·season·돈을 임시 확정해서 제작·지급을 열지 않습니다. |
| 판매 이벤트 입력 | 유효한 현재 능력과 현재 팬 관측, 허용된 리그 규칙 | 입력 대기와 발매 자체의 성공을 분리합니다. 유효한 full checkpoint가 실제 0팬임을 증명하는 로컬 0팬 경로도 별도 출처로 표시합니다. |
| 실제 정산 | 정식 보드의 관측 증거와 기존 경제·성장 적용, 원장·checkpoint·팬 기록의 복구 계약 | 운영자 시험 입력이나 클릭 한 번을 실제 보드 정산·실보상으로 설명하지 않습니다. |
| 페스티벌 참가·투표 | 현재 팀과 발매 앨범에 더해 기간·참가 자격·투표 자격·횟수·판정 정책 | 팀 연결 성공과 정책 대기를 분리합니다. 미공급 정책을 임의 true·0·예시 점수로 채우지 않습니다. |

오디션 세션을 시작하면 초기 snapshot이 먼저 존재할 수 있습니다. 정식 보드 런타임은 handoff로 팀을 만들고 초기 snapshot을 restore한 뒤 성장 bridge로 full checkpoint를 저장합니다. snapshot-only 상태를 음악에서 읽을 수 있다는 사실은 그 즉시 제작 지갑·미션·보상도 사용할 수 있다는 뜻이 아닙니다. 정식 보드의 초기 상태 생성과 생성 팀 fixture는 서로 대체하지 않습니다.

현재 음악 source의 기본 참가·투표 자격은 미공급 상태입니다. 페스티벌의 운영자 시험, 점수·보상 정책, 실제 참가 판단은 각각 원본 기획과 구현을 확인해야 합니다. 이번 팀 연결 수정이나 단독 시나리오로 정책까지 확정됐다고 기록하지 않습니다.

#### 도구별 역할을 혼동하지 않습니다

| 도구 | 주로 하는 작업 | 이 도구만으로 완료라고 할 수 없는 것 |
|---|---|---|
| 기획서 툴 | 원본·표·개발 계획을 읽고 관련 실행 화면을 연결 | 본게임 저장·게임 정산·기능 플레이 |
| 게임 시뮬레이터 | 현재 팀 또는 명시적 시험 범위에서 기능을 직접 조작하고 연결·표시·정산·복귀를 확인 | 발란스 결정·서버 저장·모든 기능의 운영 완료 |
| 발란스 시뮬레이터 | 시나리오·배수·자동 정책으로 동일 계산 경로의 경제·성장·보상을 관측 | 게임 화면의 동일 진행·동일 UX·모든 저장 공유 |
| 발란스 툴 | 원표·시험 입력·계산 결과를 숫자와 그래프로 비교 | 원표 수정 승인·실제 보상 지급·실제 저장 격리 확인 |
| 성장 현황판 | 전달된 실행 상태·변화·출처·상세를 조회 | 게임 성장·경제 상태의 새 정본 또는 정산 writer |

[현재 도구별 진입점](#current-tool-boundaries)을 따릅니다. 같은 계산 함수를 쓰거나 같은 이름의 능력 칸을 보여 준다는 이유로 입력 단위·저장 키·writer까지 같다고 판단하지 않습니다.

#### 증상에 따라 먼저 확인할 곳

| 보이는 문제 | 먼저 확인할 근거 | 피할 임시 처리 |
|---|---|---|
| 같은 화면인데 다른 팀이 나옴 | URL의 testPage·hubSource, 현재 testSession.id/runId와 저장 prefix | 이름으로 팀을 합치거나 메인 저장을 다른 scope에 복사 |
| 팀 정보 전체가 안 열림 | session/run/후보 수·순서, 공통 멤버 검사와 sourceReason | 데이터가 없다고 새 팀을 자동 발급 |
| 멤버는 보이지만 제작·돈이 막힘 | metadata-only인지, 유효한 full checkpoint·day·season·money와 busy 여부 | snapshot에 돈·시간을 직접 채워 정식 진행으로 승격 |
| 발매했지만 판매 리그가 없음 | 실제 팬 계층·현재 능력·이벤트 등록 원장과 source 입력 | 미관측 팬을0으로 만들거나 같은 앨범 리그를 중복 생성 |
| 페스티벌 참가·결과가 막힘 | 회차·기간·발매곡과 자격·한도·점수 정책의 공급 여부 | 팀 연결 문제와 미정 운영 정책을 한 원인으로 처리 |
| 단독 시험 시작이 거절됨 | 허용된 명시 scope·생성 source·fixture marker·기존 초안/수정 여부 | 오디션/전송팀에 시험 지원금을 넣거나 사용자 초안을 삭제 |

단독 시작의 코드는 [시험 시나리오 helper](/src/simulator/music-career/standalone-scenario.mjs), 값과 문구는 [별도 시험 JSON](/data/simulator/music-career-test-scenario.json)입니다. 시험곡에는 실제 음원이 없으며 현재 멤버의 역할/계수를 기존 lineup 검증으로 동결합니다. 보상은 선택 기능의 기존 writer/현재 scope 조건을 따릅니다. 시티 단독 급유 재화는 최초 영수증으로만 지급하고 재접속으로 보충하지 않습니다. 페스티벌 시험은 기존 파이널 시험 경로이며 정식 주간·월드의 신규 운영 완성을 뜻하지 않습니다.

#### 다른 작업자가 변경하기 전에 확인할 계약

### 2-3 새 모듈을 붙이는 실제 절차 + 빈칸 양식
오늘 능력·관계 허브는 등록표/기획 → 공용 controller → runtime 진입 보완 → 도크·주소/메인 원본 연결 → 표시·상세 검수 순으로 붙였습니다(R02·R05·R09~R11·R16). 아래는 그 누락과 실패 사례를 반영한 절차이며 새 게임 값은 비워 둡니다.

1. **원본·권한:** 문서번호 ___ / 카탈로그 경로 ___ / 현재 담당 ___ / 허용 파일 ___ / 읽을 표·연결자료 ___ / 쓰기 권한 ___를 확인합니다. 기존 카드와 같은 문서를 중복 등록하지 않습니다.
2. **등록 행:** module_id ___ / label ___ / entry_path ___ / source_path ___ / instance_key ___ / panel_key ___ / mode ___ / needs_world ___ / doc_no ___ / plan_id ___ / sort_order ___를 채웁니다. 표 담당 권한을 확인하고 구조 변경은 schema 원본·생성기·--check로 처리합니다.
3. **controller:** mount(ctx)에서 공통 context와 현재 scope의 dataSource를 받습니다. activate/deactivate/serialize/dispose를 구현하고 같은 instance_key 재사용을 고려합니다. 모듈별 host·폰·저장 체계를 임의 복제하지 않습니다.
4. **실행 진입:** runtime entry 공급 방식을 ___(재수출/지정 생성물 등)로 기록하고 등록 주소의 존재·HTTP/module import를 확인합니다. 오늘 source만 있고 growth_relation.js가 없어404가 난 사례(R05)를 반영했습니다. source 수정만으로 압축 runtime이 바뀐다고 가정하지 않습니다. 빌드/재시작은 담당·지시 ___를 먼저 확인합니다.

### 3-1. CSV와 Markdown 읽기 계약

현재 공통 `parseCsv(text, sourceName?)`에는 `strict` 옵션이 없습니다. 비어 있지 않은 출처명을 전달한 경우 읽은 각 데이터 행과 헤더의 칸수가 다르면 오류를 냅니다. 호출부의 이름 전달과 `gameValidation`의 별도 검사를 확인하고, 스키마 생성 `--check`와 CSV 원문 행폭 검사를 같은 검사로 집계하지 않습니다. 칸수가 같다는 사실만으로 값·키·참조와 전체 표/데이터가 정상이라고 판정하지 않습니다.

새 표는 작성 기본형의 각 구분칸을 `---`로 씁니다. 현재 reader는 `--`도 인식하므로 기존 2하이픈 표를 일괄 오류로 판정하지 않습니다. 목차 hash는 문장부호·공백 처리와 중복 접미사를 포함한 실제 renderer ID와 대조하고, 실제 문서에서 목차 이동도 확인합니다.

현재 예의 증거는 [0320 원본 iframe·흐름도 경계](../../증거/20261023_0330_단이_원본iframe_흐름도경계/manifest.json), [0355 배지·변환 검증](../../증거/20261023_0400_단이_배지_저장행변환/)입니다. 앞의 캡처는 당시 실제 화면 증거이며 이번에 같은 화면을 반복 시험했다는 뜻이 아닙니다.
