## 현재 운영표 전체 목록

현재 등록은 **56줄: 활성54·비활성2**입니다. 일일은 활성15·비활성2, 주간12, 업적14, 도전4, 가이드7, 이벤트2입니다. 아래 값은 mission_config·condition·reward_group_entry를 직접 대조한 스냅샷이며 원표가 바뀌면 함께 갱신합니다. 활성은 조건 달성이나 지급 완료를 뜻하지 않습니다. 비활성2줄은 진행·자동 수령에서 제외합니다.

**미션 처리 순서** 실제 장부 관측 → 조건·목표 판단 → 수령대기 → 원보상 전체 지급 → 고유 수령 영수증 → 기간 변경 후 초기화입니다. 게임의 실제 시각은 기존 규칙을 쓰고 시뮬레이터는 미션에만 일차 달력을 투영합니다. 일일1→2·주간7→8 전에 만료될 수령대기를 먼저 받고, 묶음미션을 다시 관측한 뒤 새 기간을 엽니다. 시즌 말에는 남은 수령대기를 정산합니다. 가이드 계정1회와 이벤트 회차 정책은 그대로 유지합니다.

아이돌 등급팩 일일5·주간5의 기존 조건·목표·보상은 유지합니다. 전체 미션 API에서 수령한 항목을 기존 아이돌 자동 지급 경로가 다시 발급하지 않도록 연결해 같은 기간의 중복 지급이 없음을 확인했습니다. 일말 미션 수령 전에 실제 자동 모험·출동 결과의 실행 횟수를 미션 장부에 연결합니다. 보상은 자동 모험의 기존 정산에서만 지급하며 같은 일차 재실행·중복 결과는 다시 집계하지 않습니다. 명시0·빈 보유의 출동은0회이고, 실행하지 않은 출석·이벤트는 연결 대기로 남깁니다. 실제 연결 장부가 없는 대전 등도 가짜 횟수로 완료하지 않습니다.

현황판은 실제 원천→12의 미션 진행, 실제 수령 영수증→06의 몬스팩과 중앙 연결을 표시합니다. 엔터파워·사옥의 직접팩은11→06입니다. 원장에 없는 보상·성장을 선이나 숫자 이동이 새로 만들지 않습니다.

## 간략

**머리표** 시스템 기획 · S11 · 미션 · 모노 241 · 242 · 49 · 243 이식(구조 그대로 · 케이팝 이름으로 바꿈)

**제목** 미션 — 하던 플레이를 세어서, 하단 탭에서 등록된 주사위·돈·팩을 받는다

**훅** 오늘 뭘 하면 주사위가 오나? 「활동 미션」 탭이 답한다.

**두 줄 요약**
- 미션은 새 놀이가 아니라 **이미 하는 플레이(굴림 · 증설 · 칸 도착 · 미니게임)의 횟수 장부**다. 다 차면 하단 3번 「활동 미션」 탭에서 바로 받는다.
- 현재 탭은 일일·주간·업적·도전·가이드·이벤트 여섯 종류입니다. 목표·잠금·복합 보상은 운영표를 읽고 보상에 굴림·팬덤 배율을 붙이지 않습니다.

```mermaid
flowchart LR
  P[하던 플레이<br/>굴림 · 증설 · 칸 도착 · 미니게임] -->|track_event +1| C[미션 장부<br/>mission_config]
  C -->|목표 다 참| R[수령대기<br/>빨간 점]
  R -->|받기 · 전체 받기| G[등록 통화 · 팩]
  T[로컬 자정 · 월요일 0시] -.->|비움| C
```

1. **센다** — 보드에서 이미 하던 일을 할 때마다 미션 칸이 +1 된다.
2. **찬다** — 목표에 닿으면 「수령대기」가 되고 하단 탭에 빨간 점이 뜬다.
3. **받는다** — 목록에서 바로 「받기」 또는 「전체 받기」. 창을 한 번 더 열지 않는다.
4. **비운다** — 게임의 일일은 로컬 자정, 주간은 월요일0시입니다. 시뮬레이터는 일일1→2·주간7→8 전환 전에 수령대기를 받은 뒤 초기화합니다.

| 왜 지금 | 이게 핵심 | 이게 아닌 것 |
|---|---|---|
| 현재 운영표56줄·활성54·비활성2와 공통 미션 API가 있으며, 시뮬레이터 하단 전체 목록·기간 말 수령을 연결해 확인 중 | 하던 일을 세는 장부 · 목록에서 바로 받기 · 일일/주간 | 새 놀이가 아니다 · 사는 창(상점)이 아니다 · 홍보 미션(리드젠 · 혜택 탭)이 아니다 · 출석이 아니다 |

### 5. 표와 값 칸

현재 운영 mission_config·mission_tab_config·mission_state_config가 등록되어 있고 보상은 reward_group/entry, 잠금은 condition_group/condition, 이벤트 회차는 event_template와 event_config를 함께 읽습니다. 아래 이식 관계는 구조 참고이며 실제 열 이름·수량은 상단 전체 목록과 원표를 기준으로 봅니다.

```
mission_config                 허브 · 한 줄 = 미션 하나
   ├── period → mission_tab_config.tab_id
   ├── mission_type → mission_type_config
   ├── track_event               세는 열쇠(4-1)
   ├── reward_group_id → reward_group_entry 전체 지급
   └── condition_group_id → 팬·일차·팀 최고 등급 잠금
mission_state_config           doing / ready / done / locked
mission_dev_action_config      개발 빌드만
page_layout(page_id=mission)   탭 띠 · 전체 받기 · 카드 목록
text_ko(ui_ms_*)               글자(클로드 표)
```

| 무엇 | 표 · 줄 열쇠 | 상태 |
|---|---|---|
| 미션 한 줄 | `mission_config`: mission_id·period·mission_type·title_ko·body_ko·track_event·target·reward_type·reward_group_id·condition_group_id·active. 실제 수량은 보상표, 팬·일차·등급은 조건표 | 정규화된 현재 원표 구조. 목표·보상·잠금 수치를 이 문서에서 변경하지 않음 |

### 7. 아직 안 한 것 · 확인 필요
- 팬·일차·팀 최고 등급 잠금은 현재 condition 원표와 AND 판단을 유지. 최종 문턱 발란스와 아직 공급되지 않은 조건은 별도 검토.
- 최종 경제 발란스와 미션별 보상 총량. 등록된 몬스·아이돌팩은 현재 실제 보상이며 이번 문서 작업에서 수량을 바꾸지 않음.
- 시뮬레이터의 일일1→2·주간7→8 경계 전 수령, 시즌 말 정산, 같은 기간 중복 방지를 기간 연결 검수 완료.
- 주간 수령 소식 자랑(R-S11-10) — S15 소셜(2차 5단계)에서 구조만 · **확인 필요 · 보류**. (이식)
- 실제 자동 모험·출동 횟수는 일말 미션 정산 전에 집계하며 같은 일차·중복 결과는 추가 집계0. 출석·이벤트·대전 등 실제로 실행하지 않은 콘텐츠는 연결 대기로 남김.
- 미션 표와 API는 구현되어 있으며 하단 전체 목록·자동 수령·성장 현황판은 기간 연결 검수 완료. 실제 미션 보상은 행동층으로 기록하고 기본 무료 입력과 중복 집계하지 않음.
