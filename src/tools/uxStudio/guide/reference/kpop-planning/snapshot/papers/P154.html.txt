<section class="part" id="part-1"><h2>1. 개요</h2>

<p>출처: (신규) 현중 10/19~20 직접 지시 · 현재 작업 원문 · 최초 개선 원문. 별도 콘서트 제안서 파일은 미완이며, 확인된 직접 지시와 실제 소스를 기준으로 작성합니다.</p>

<p>서버가 정한 보상을 바꾸지 않고, 콘서트 룰렛의 배치·캐릭터·카메라·조명으로 보여 주는 도구입니다. UI 프레임은 시뮬레이터의 밝은 톤으로 고정하고 같은 주소에서 게임 무대의 낮/밤 색상을 비교합니다.</p>

<blockquote><p>흐름: 서버 인덱스 → 확정 보상 → 가능한 연출 → 공개·받기</p></blockquote>

<h3 id="콘텐츠-경계">콘텐츠 경계</h3>

<ul>
<li>맡는 것: 예시 보상 인덱스 해석, 같은 결과 배치, 세 연출 방식, 10기본 동작·100변형 탐색, 두 카메라·두 테마, 확률·2D 배치 작업실과 사람이 편집하는 원본 표·룰렛 세팅 연결입니다.</li>
<li>다른 범위: 운영 확률표·실제 지급·서버 서명·계정 재화, 실제 카드9종 그림 매핑은 연결하지 않았습니다.</li>
<li>기준: 구현된 흐름은 확정(해당 소스 근거)으로 기록합니다. 예시 수량과 연출 시간·색상은 운영 밸런스 확정이 아닙니다.</li>
</ul>

<h3 id="현재-기준과-목표">현재 기준과 목표</h3>

<p>(신규) 기본은 낮 무대·예시 보상/연출 랜덤·빠른 테스트이며 캐릭터 연출을 켜지 않으면 판만 회전합니다. 캐릭터 연출을 켠 상태에서는 전체 랜덤과 세 가지 동작 방식을 비교할 수 있습니다. 준비만 자동으로 하고 재생은 직접 누릅니다. 보상·패킷·프리셋을 고정할 때는 테스트 설정을 엽니다.</p>


<h3 id="보상과-연출의-관계">보상과 연출의 관계</h3>

<p>게임의 목표는 서버가 미리 정한 돈·주사위·카드 결과를 정확하게 보여 주는 것입니다. 서버 보상 인덱스와 표 판본·조건이 일치할 때만 같은 결과를 만드는 배치와 가능한 연출을 고릅니다. 현재는 이 계약을 <b>로컬 예시</b>로 시험하며, 운영 서버 서명·확률표와 실제 지급은 작업전입니다. 카드의 무작위 결과도 이미 해결된 카드 정보가 있어야 보여 줍니다.</p>

</section><section class="part" id="part-3"><h2>3. 구동 방법·시뮬레이션</h2>

<p>화면 흐름: P94 이벤트 게임·미니게임 첫 줄 → 콘서트 룰렛 통합 도구 → 보상 공개 → 받기·초기 준비 화면 · 스샷 엔티티 표 편집 입구 · 예시 세팅·정책 상태 · 운영 세팅 대기 · 전체 테이블·보상7행 · 이식 비교 해당 없음</p>

<blockquote><p>흐름: 입구 열기 → 연출 선택·자동 준비 → 직접 재생 → 받기·복귀</p></blockquote>

<ol>
<li><a href="/event/concertRoulette/probability/director12.html" data-paper-path="event/concertRoulette/probability/director12.html">통합 도구</a>를 엽니다. UI 프레임은 밝게 고정이며 무대만 밝게/어둡게 또는 ?theme=light / ?theme=dark로 낮/밤을 비교합니다. 주소에 reward·preset을 지정하지 않으면 예시 보상·연출 랜덤으로 시작합니다. 기본 화면 상단의 무대 색상 옆에서 카메라 타입과 자동 카메라 켜기/끄기를 바로 고릅니다.</li>
<li>기본은 캐릭터 없이 판만 회전합니다. 「캐릭터 연출」을 켜면 전체 랜덤·① 판과 캐릭터 회전·② 고정판 걷기·③ 주변 순환과 순차 진입을 비교할 수 있습니다. 준비 후 직접 재생합니다.</li>
<li>화면 아래 고정 조작 바의 연출 재생을 누릅니다. 기본 랜덤에서는 매번 새 예시 패킷과 그 보상에 맞는 연출·길이를 고릅니다. 같은 결과 다시 보기는 직전 보상·동작·카메라·길이를 그대로 재현합니다.</li>
<li>보상·레벨/배수·패킷·프리셋을 직접 지정하거나 데이터를 가져오면 상세 고정으로 전환합니다. 현재 패킷 원문·확정 보상 JSON과 연출 목록 열기는 테스트 설정에 있으며, 상세 목록은 기본 닫힘입니다.</li>
<li>보상 공개 후 같은 하단 바의 받기를 누르면 초기 배치·기본 시점·조작 상태로 돌아갑니다. 중지도 같은 바에 있고 받기 대기 시간은 연출20~30초에 포함하지 않습니다.</li>
</ol>

<p>기본 화면은 방식4개와 큰 무대를 중심으로 보여 줍니다. 상세 연출 브라우저는 테스트 설정의 연출 목록 열기로만 열고, 작은 화면에서는 닫아 무대를 봅니다. 테스트 설정은 닫기·Escape로 닫고 내부에서 스크롤합니다. 마우스 드래그·휠·우클릭 이동과 탑뷰 복귀를 지원합니다.</p>

<p>상세 목록의 <b>100종 전체 체험</b> 버튼을 직접 누르면 UI 데이터가 지정한 복합 예시 인덱스104와 예시 레벨·배수로 고정합니다. 검수용 예시이며 실제 지급은 없습니다. 기본 예시 랜덤도 내장7패킷 중104를 고를 수 있지만, 이 버튼은 상세 고정으로 바꾸어 전체 목록을 살펴보는 별도 동선입니다. 상세 탐색·추천·재생은 현재 확정 보상을 유지하고, 조건이 맞지 않는 보상을 조용히 대체하지 않습니다.</p>

<p>확률·배치 탭은 기존2D 작업실을 유지합니다. 현재 보상과 같은 결과를 만드는 배치만 연출에 전달합니다. 데이터·설명 탭의 정지 장면 보기는 연출 탭 무대로 돌아와 표시하며, 보상 공개 정지 장면도 하단 받기 후 초기 화면으로 돌아갑니다.</p>

<p>저장·복원: 테마 선택과 주소·seed·계획/데이터 JSON 내보내기를 사용합니다. 본편 진행·계정 보상 저장은 미구현입니다. 문서 안에는 시뮬레이터 iframe을 넣지 않습니다.</p>

<h3 id="통합-도구-사용법-사용법-문서-내용">통합 도구 사용법 (사용법 문서 내용)</h3>

<h3 id="바로-확인하기">바로 확인하기</h3>

<ol>
<li>게임 시뮬레이터의 이벤트 게임에서 검색 가능한 세로 게임 목록의 콘서트 룰렛을 엽니다. 주소에 reward·preset을 지정하지 않으면 예시 보상·연출 랜덤으로 시작합니다.</li>
<li>기본은 캐릭터 없이 판만 회전합니다. 「캐릭터 연출」을 체크하면 기존 전체 랜덤·① 판 + 캐릭터 회전·② 고정판 캐릭터 걷기·③ 주변 순환·순차 진입을 함께 비교합니다. 체크만 바꾸면 같은 보상·계획을 유지하며 다시 준비하고, 체크 상태는 저장하지 않습니다. 기본 모드에서는 캐릭터 모델을 로드·생성하지 않습니다. 무대 준비 후 재생 버튼을 눌러 진행합니다.</li>
<li>화면 아래 고정 바에서 연출 재생을 누릅니다. 기본 랜덤은 매번 새 예시 패킷과 그 보상에 맞는 연출·길이를 고릅니다. 같은 결과 다시 보기는 직전 보상·동작·카메라·길이를 그대로 재현합니다.</li>
<li>보상·레벨/배수·패킷·프리셋을 고정하려면 테스트 설정을 엽니다. 직접 지정 또는 데이터 가져오기는 상세 고정으로 전환하며 URL reward/preset도 고정입니다. 연출 목록 열기는 테스트 설정 안에 있고 상세 브라우저는 기본 닫힘입니다.</li>
<li>UI 프레임은 밝게 고정이며 무대의 밝게/어둡게 또는 ?theme=light / ?theme=dark로 게임 캔버스의 낮/밤 공연만 비교합니다. 이 선택은 현재 보상·동작을 유지합니다.</li>
<li>공개된 보상을 보고 하단 받기를 누르면 처음 준비 화면으로 돌아갑니다. 중지도 같은 바에 있습니다. 받기를 기다리는 시간은20~30초에서 제외합니다.</li>
</ol>

<p>상세 카드·검색·이전/다음·추천은 테스트 설정에서 연출 목록 열기를 누른 뒤 사용합니다. 선택하면 현재 보상으로 준비만 하며, 작은 화면에서는 목록을 닫고 무대를 봅니다. 테스트 설정은 내부 스크롤·닫기·Escape를 지원합니다. 연출 설명·결과 확인은 선택 이유·제외 사유·타임라인·보상 일치 결과를 접어 둡니다.</p>

<h3 id="예시-랜덤과-상세-고정">예시 랜덤과 상세 고정</h3>

<p>기본 예시 랜덤은 내장 보상표·연결표·카탈로그 객체를 그대로 사용할 때만 내장7패킷에서 선택 방식에 가능한 패킷을 모아 동일 비중으로 선택한 뒤 그 보상에 맞는 연출을 고릅니다. 기본 메뉴는 전체 예시의 후보 합집합100종과 방식별20/10/70종을 표시해 현재 보상 때문에 메뉴를 끄지 않습니다. 운영 확률이나 이미 받은 서버 보상의 재추첨이 아닙니다.</p>

<p>상세 고정에서는 현재 확정 보상의 종류·예시 등급·동작 조건에 맞는 후보만 활성화하고 부적합 항목은 사유·가능 개수와 함께 비활성화합니다. 목록·랜덤·실행은 같은 기존 엔진 조건을 사용합니다.</p>

<p>보상 변경 뒤 부적합 수동 선택은 가능한 자동 범위로 돌아가며, 방식 자체에 후보가 없으면 전체 랜덤으로 돌아갑니다. 전체 범위에도 후보가 없으면 실행을 막습니다. 상세 탐색·추천·재생은 보상 수량이나 카드 결과를 바꾸지 않습니다. 가져온 데이터는 예시 형식이어도 상세 고정이며 운영 패킷을 랜덤으로 바꾸지 않습니다. 기본 메뉴의 로컬 예시 랜덤과 구분합니다. 내장 데이터에서 기본 방식 메뉴를 다시 명시 선택하면 예시 랜덤으로 돌아가며, 가져온 데이터는 기본 메뉴를 골라도 고정을 유지합니다.</p>

<p>상세 목록의 <b>100종 전체 체험</b> 버튼을 직접 누르면 UI 데이터의 복합 예시 인덱스104와 예시 레벨·배수로 상세 고정합니다. 검수용 예시이며 실제 지급은 없습니다. 기본 예시 랜덤도7패킷 중104를 선택할 수 있으며, 이 버튼은 전체 목록을 살펴보기 위한 별도 상세 고정 동선입니다. 전체 체험용 패킷이 현재 표에 없으면 바꾸지 않고 사유를 표시합니다.</p>

<p>100프리셋은 기본 동작10개×변형10개의 조합이며 독립 제작 애니메이션100개를 뜻하지 않습니다. 전체 랜덤·방식 내 랜덤·수동 선택과 마지막 밀기50%의 정확한 범위는 P154 상세 기획을 확인합니다.</p>

<h3 id="카메라보드화질">카메라·보드·화질</h3>

<p>기본 화면 상단의 무대 색상 옆에서 카메라 타입과 자동 카메라 켜기/끄기를 바로 조절합니다. 현재 카메라는 전체 무대 회전·크레인 두 타입과 두 타입의 랜덤입니다. 화질과 현재 샷 설명은 테스트 설정에서 확인하고 카메라 선택기는 중복하지 않습니다. 카메라 랜덤은 동작 랜덤과 독립이고, 자동 카메라 끄기·직접 드래그·모션 줄이기를 존중합니다. 탑뷰로 기본 시점을 복원합니다.</p>

<p>UI 프레임은 아이보리·초록 톤으로 고정하고 밝게/어둡게는 게임 무대만 낮/밤 공연으로 전환합니다. 낮 무대는 청회색 외곽·밝은 회색 무대·톤을 정리한5색 바닥으로 구분합니다. 낮/밤 모두 외곽 관객·응원봉은 제외하고 캐릭터 연출을 켜면 무대의 36캐릭터를 쓰고, 주변 조명 타워는 유지합니다. 기본 화질은 빠른 테스트이며 테스트 설정에서 원본 화질로 바꿉니다. 빠른 테스트는 DPR1·렌더배율0.85·가장자리 보정/번짐 끄기·프레임 상한30, 원본 화질은1.7·1·사용·60입니다. 실제 FPS나 개선 배수를 측정한 수치가 아닙니다.</p>

<p>캐릭터 원본·동작·소품은 보존하고 팔레트/자세/bounds/배치 계산과 탐색 DOM을 재사용합니다. 확정 보상과20~30초·받기 복귀는 유지합니다.</p>

<h3 id="확률배치와-정지-장면">확률·배치와 정지 장면</h3>

<p>확률·배치 탭은 같은 도구 안의 기존 작업실입니다. 확정 보상과 같은 결과를 만들 수 있는 배치만 전달하며 보상을 대체하지 않습니다.</p>

<p>데이터·설명 탭에서 표 가져오기/내보내기, 계획 JSON, 고정 프레임 검수·상태 원문을 확인합니다. 정지 장면 보기를 누르면 연출 탭 무대로 돌아와 선택한 장면을 보여 줍니다. 보상 공개 정지 장면도 하단 받기 후 초기 화면으로 돌아갑니다. 실제 한 판을 재생하는 검사가 아닙니다.</p>

<h3 id="세팅-표와-정책-상태">세팅 표와 정책 상태</h3>

<p>현재 표 편집 입구 · 예시 세팅 상태 · 운영 대기 화면 · 보상7행·전체 테이블</p>

<p><a href="/docs/planning/game-table-tool.html?plan=planning_development_plan_concert_slot#concert_roulette_setting" data-paper-path="docs/planning/game-table-tool.html">전체 테이블</a>에서 룰렛 세팅 한 행을 먼저 고릅니다. 보상표 문서·판본, 연출 묶음 문서·판본, 니어미스 정책을 연결합니다. 통합 도구 예시와 스케줄 룰렛·팬덤 응원 슬롯의 운영 대기 세팅을 구분합니다. ?setting=세팅ID로 같은 세팅의 도구를 열 수 있습니다. 운영 보상표가 비어 있으면 예시로 대체하지 않고 대기 상태를 표시합니다.</p>

<p>니어미스 발생 비율·연속 상한·강도, 놓칠 목표 보상·장면 비중·실제 배치 검증은 발란스 대기입니다. 기존 마지막 밀기50%와 구분하며 꽝은 추가하지 않았습니다. 장면4분류와 선택 계약은 기반이고 큰 보상을 놓치는 실제 장면 완료를 뜻하지 않습니다.</p>

<p>시간은 세팅+보상 등급 한 행에서 공통 설정을 상속하거나 범위를 지정합니다. 현재 예시1~3등급은 기존20~30초 공통 기술 시안을 참조하며 운영 등급별 차등 시간은 결정 대기입니다. 없는 규칙·빈 범위를 기본값으로 채우지 않습니다.</p>

<p>보드의 스케줄 룰렛·팬덤 응원 슬롯은 세팅 참조와 수동 도구 진입 기반을 연결합니다. 현재 칸 ID와 기존 배치 참고8관계를 사용하며, 운영 세팅의 도착 자동 실행·비용·추첨·지급은 연결하지 않습니다. 별도 임시 보드 검수 경로는 예시 연출을 자동 재생하고 표시 전용 결과만 전달합니다.</p>

<h3 id="원본-데이터와-상태">원본 데이터와 상태</h3>

<p>활성 원본은 대상별 엔티티 CSV 한 벌입니다. 보상7행, 프리셋100행, 행동10행, 문구98행으로 사람이 편집합니다. 카드·역할·키프레임·허용 목록은 고정ID의 하위 표로 분리합니다. 행 삽입·정렬·수량 수정 때 ID를 다시 만들지 않고 순서는 sort_order로만 바꿉니다. 연결은 kind/ref_id 한 쌍이며 판본은 값 열에 둡니다.</p>

<p>설정CSV29개와 모듈 입구CSV1개를 전체 테이블/사용 관계에 등록합니다. entity-tables12·entity-schema12가 현재 엔티티 표를 기존 보상·연출 계약 객체로 조립합니다. setting-policy12는 세팅·정책·시간·찬스 참조를 확인합니다. 이전 path-node CSV8개·JSON8개는 활성 데이터 폴더에서 빼고 이전기획 보관에 보존합니다. node_path/type/value와 JSON 셀은 현재 편집 원본이 아닙니다. JSON 가져오기·내보내기는 계약 교환 기능입니다.</p>

<h3 id="사람이-편집하는-세팅-표-확정소스-구조-운영값-결정-대기">사람이 편집하는 세팅 표 (확정·소스 구조 / 운영값 결정 대기)</h3>

<p>보상 한 행, 연출 프리셋 한 행, 코믹 행동 한 행으로 편집합니다. 카드·참여 역할·키프레임·허용 목록은 해당 대상의 하위 표로 나눕니다. 풀네임 행 ID는 의미를 기준으로 한 번 정하고, 행 삽입·정렬·수량 변경으로 다시 만들지 않습니다. 순서는 sort_order로만 바꿉니다.</p>

<p>보상 인덱스와 연출 프리셋의 기존 외부 식별자는 호환용 값으로 유지하고 내부 연결은 kind/ref_id 한 쌍으로 지정합니다. 판본은 문서 표의 값 열과 서버 패킷에만 두며 고정 행 ID에는 넣지 않습니다. node_path·node_type·node_value와 JSON 셀을 원본 편집 형식으로 사용하지 않습니다.</p>

<h3 id="찬스-칸과-룰렛-세팅-연결-확정수동-진입-기반-자동-실행-미연결">찬스 칸과 룰렛 세팅 연결 (확정·수동 진입 기반 / 자동 실행 미연결)</h3>

<p>기존 보드 미니게임의 스케줄 룰렛·팬덤 응원 슬롯 행에 roulette_setting_kind/ref_id를 연결합니다. 찬스 연결 표는 기존 배치 규칙의8개 관계를 원본 ID로 참조합니다. 칸 이름·위치·시설을 복사하지 않으며 정식 board_tile의 칸 ID를 사용합니다.</p>

<p>기존 성장 화면은 board_minigame과 tile_feed를 사용하고 tile_minigame 표는 배치 참고 원본입니다. 이번 연결은 현재 칸 ID에서 해당 설정의 도구로 들어가는 수동 링크와 설정 확인 기반입니다. 운영 세팅의 보드 도착 자동 실행·입장 비용·운영 추첨·실제 지급은 연결하지 않습니다. 운영 세팅에 유효한 보상표가 없으면 예시 보상으로 조용히 대체하지 않고 대기 상태를 보여 줍니다. 보드 검수 요청은 별도 임시 어댑터로 예시 연출을 자동 재생하고 표시 전용·지급 없음 결과를 돌려줍니다. 이 경로의 <code>hub.complete</code>는 검수 완료 영수증이며 실제 보상 지급이 아닙니다.</p>

<h3 id="보상-등급별-시간-확정참조-기반-운영-범위-결정-대기">보상 등급별 시간 (확정·참조 기반 / 운영 범위 결정 대기)</h3>

<p>시간 규칙은 세팅+보상 등급 한 행입니다. inherit는 공통 시간 설정을 참조하고 range는 해당 행의 최소·최대 시간을 사용합니다. 없는 등급·중복 규칙·빈 시간 범위는 대기로 처리하고 임의 수치로 채우지 않습니다.</p>

<p>현재 예시1·2·3등급은 현중이 요청한 기존20~30초 기술 시안을 inherit로 참조합니다. 작은 보상과 큰 보상에 서로 다른 운영 시간을 확정한 상태가 아닙니다. 운영 등급별 범위는 발란스 대기로 두고 이후 같은 표에서 정합니다.</p>

<div class="table-scroll"><table><thead><tr><th>선택 상태</th><th>예시 패킷·보상</th><th>연출 선택·재생</th></tr></thead><tbody><tr><td>예시 보상·연출 랜덤 · example_random</td><td>내장 보상표·연결표·카탈로그를 그대로 사용할 때만, 선택 방식에 가능한 내장7개 패킷을 모아 동일 비중으로 하나를 고릅니다.</td><td>방식 클릭은 새 패킷·연출 준비만 합니다. 일반 재생은 새 패킷·연출을 고릅니다.</td></tr><tr><td>상세 고정 · detail_fixed</td><td>테스트 설정의 보상/조건/패킷/프리셋 직접 조작, 데이터 가져오기, URL reward/preset 지정은 그 보상을 유지합니다.</td><td>현재 보상 조건에 맞는 후보만 고르며 수동 프리셋은 지정 동작을 유지합니다.</td></tr><tr><td>같은 결과 다시 보기</td><td>직전에 준비·재생한 패킷과 정확한 보상을 유지합니다.</td><td>동작·카메라·길이도 유지하며 새 예시를 고르지 않습니다.</td></tr></tbody></table></div>

<p>기본 메뉴의 개수는 내장 예시 전체에서 체험 가능한 후보의 합집합입니다. 현재 화면의 보상 하나 때문에 기본 메뉴를 끄지 않습니다. 현재 구성은 전체100·① 판+캐릭터20·② 고정판10·③ 순차 진입70이며, 상세 고정 화면은 현재 보상의 가능 개수를 표시합니다. 개수는 카탈로그 구성이지 보상 확률이 아닙니다.</p>

<p>로컬 예시 랜덤은 다음 테스트에 사용할 서버 패킷 예시를 고르는 기능입니다. 운영 보상 확률을 만들거나 이미 받은 서버 패킷의 보상을 재추첨하는 기능이 아닙니다. 가져온 표·연결표·카탈로그는 예시 형식이어도 고정으로 취급하며 운영 패킷을 랜덤으로 바꾸지 않습니다. 상세 목록에서 카드를 고르거나 이전/다음·추천을 사용하는 것은 현재 보상을 유지하는 상세 선택입니다. 내장 데이터에서 기본 방식 메뉴를 다시 명시적으로 고르면 예시 랜덤으로 돌아갑니다. 가져온 데이터는 기본 메뉴를 골라도 고정을 유지합니다.</p>

<h3 id="연출-탐색과-조건-확정기존-선택-엔진">연출 탐색과 조건 (확정·기존 선택 엔진)</h3>

<p>카탈로그100프리셋은 기본 동작10개×변형10개의 조합입니다. 독립 애니메이션100개를 새로 제작한 뜻이 아닙니다. 기본 동작은 판 무대 회전·고정판 달리기·바깥/가운데/동시/순차 진입·마지막 경계 대기·고리 연쇄·보상 집중으로 나눕니다.</p>

<p>상세 고정에서는 확정 보상의 종류·예시 등급·동작 조건에 맞는 후보만 활성화합니다. 부적합 카드는 비활성·사유·가능 개수를 표시합니다. 목록과 랜덤·실행은 selectPresentation12의 같은 조건을 사용합니다. 상세 보상 변경 후 부적합 수동 선택은 가능한 자동 범위로, 방식 자체에 후보가 없으면 전체 랜덤으로 돌아갑니다. 전체 범위에도 후보가 없으면 실행을 막습니다.</p>

<p>전체 랜덤은 가능한 전체 후보에서 하나를, 방식 내 랜덤은 선택한 방식 안에서 하나를 고릅니다. 수동 선택은 고른 변형을 준비합니다. 상세 고정의 일반 재생은 보상을 유지하며 새 연출 seed와 길이를 고르고, 기본 예시 랜덤의 일반 재생은 새 내장 패킷도 선택합니다. 같은 결과 다시보기는 직전 보상·선택·움직임·카메라·길이를 재현합니다.</p>

<h3 id="회전순차-진입마지막-행동-확정연출-소스">회전·순차 진입·마지막 행동 (확정·연출 소스)</h3>

<p>판과 캐릭터 함께 회전, 고정판 위 캐릭터 이동, 주변 순환 후 순차 진입 세 방식을 유지합니다. 순차 진입은 첫째 판 정지 뒤 둘째·셋째 고리에 들어가며, 판과 배우 속도를 분리하고 임시 점유색·경계 대기·연쇄 이동 뒤 최종 결과 칸에 도착합니다.</p>

<p>밀기 가능한 자동 랜덤 연출의 마지막 활성 고리는 마지막 밀기50%/직접 입장50%로 분기합니다. 앞 고리의 연쇄와 수동 프리셋은 유지하고, 원래 밀기 없는 타입에는 새 밀기를 만들지 않습니다. 전체100종의 밀기율이50%라는 뜻은 아닙니다.</p>

<h3 id="무대-낮밤과-최적화-확정소스-기술-설정">무대 낮/밤과 최적화 (확정·소스 / 기술 설정)</h3>

<p>UI 프레임은 기존 시뮬레이터와 맞춘 아이보리·초록 톤으로 고정합니다. 밝게/어둡게는 게임 연출 캔버스만 낮/밤 공연으로 전환합니다. 낮 무대는 청회색 외곽·밝은 회색 무대·톤을 정리한5색 바닥으로 구분하며, 테마 변경은 보상·선택 동작을 바꾸지 않습니다. 무대 색상과 카메라 선택은 독립입니다. 외곽 관객·응원봉은 두 테마 모두 제외하며 조명 타워는 보존합니다.</p>

<p>원본 캐릭터·18개 클립·소품을 유지하고 팔레트 버퍼를 공유합니다. 같은 자세 갱신·템플릿 bounds·배치 분석을 재사용하며 탐색 DOM은 변경된 부분만 갱신합니다. 배치 LRU는 최대8개이고 값이 바뀌면 다시 계산합니다. 위 프레임 수치는 상한이며 실제 FPS·실제 속도 개선 배수는 측정하지 않았습니다. 연출20~30초와 받기 흐름은 유지합니다.</p>

<h3 id="맞은-칸-강조-표시-확정소스">맞은 칸 강조 표시 (확정·소스)</h3>

<p>이벤트 시험 화면은 모바일·게임 목록·설정의 3열이며 기본 게임은 몬스 인형뽑기입니다. 목록은 검색/종류 필터와 자체 스크롤을 사용하고 좁은 창에서는 옆 패널로 엽니다. 공통 진행·예상성장·긴 검수 설명은 이 페이지에서 표시하지 않습니다.</p>

<p>콘서트는 캐릭터 연출 체크를 끄면 판만 돌고, 켰을 때만 기존 캐릭터 모델과 선택한 동작을 보여줍니다. 최종 정지 후 기존 resolveStops의 winning_cells로 확인된 3N칸만 원본 색상 데이터를 유지하며 표시 밝기를 3.0배 높여 강조합니다. 얇은 선 대신 실제 폭이 있는 짙은 바깥 테두리와 밝은 금빛 안쪽 테두리를 함께 쓰며 채움 펄스·미세한 오버레이 상승을 적용합니다. 임의의 색 비교나 새 당첨 판정은 하지 않습니다.</p>

<p>표시 설정은 <code>data/presentation09.json</code>의 <code>winning_floor12</code>입니다. 강조 구간은 <code>min(hold_ms, 기존 rewardMs × max_hold_ratio)</code>이고, 그만큼 기존 보상 공개 시간에서 나누어 사용합니다. 현재 표시 시안의 상한은 1,200ms이며 총 연출 시간·확정 보상·최종 정지값은 바뀌지 않습니다. reduced motion에서는 정적인 테두리를 사용합니다. 준비/취소/받기/숨김/종료 때 효과와 RAF를 정리합니다. 이 설정은 운영 확률·보상 발란스 수치가 아닙니다.</p>
