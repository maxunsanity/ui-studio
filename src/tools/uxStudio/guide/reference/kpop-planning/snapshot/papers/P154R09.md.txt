## 1. 원칙 (지키지 않으면 검사에서 멈춤)

1. **표의 원본은 스키마 원본 표 두 개**입니다: `schema_table.csv`(표) · `schema_column.csv`(칸). 아래 생성물은 손으로 고치지 않습니다.
   - `src/data/schema.ts` · `data/game/table_registry.csv` · `data/planning_csv_table.csv` ← `node scripts/schema-generate.mjs` (두 번 돌린 뒤 `--check`가 조용하면 끝)
2. **표 키 = 파일 이름(확장자 빼고)**, 풀네임입니다. 예: `board_tile` → `data/game/board_tile.csv`, `bad_energy_wave_flow` → `data/bad_energy/bad_energy_wave_flow.csv`.
3. **행 ID는 표 키로 시작하는 풀네임**입니다. 예: `schema_table_board_tile`, `building_master_facility_dance`, `cost_group_entry_…`. 한 번 정한 ID는 바꾸지 않습니다(ID 고정). 하위 표가 마스터 ID를 그대로 쓰는 것은 허용된 예외입니다.
4. **버전 표시 금지**: 폴더 · 파일 · 표 키 · 행 ID에 `v01` · `v05` · `-v06` 같은 표시를 붙이지 않습니다. 새 판을 만들면 옛 판은 보관 폴더로 보내고 이름은 그대로 씁니다(10/19).
5. **값은 짓지 않습니다.** 정해지지 않은 숫자 · 이름은 빈칸으로 두고 `value_status` 등에 「발란스 대기」라고 적습니다. 빈칸을 0이나 기본값으로 바꾸는 코드도 금지(검사가 막음). 다른 표에 있던 값을 옮기는 것은 짓는 것이 아니며, 옮긴 곳을 메모에 적습니다.
6. **칸 이름 규칙**: 다른 것을 가리키는 칸은 `…_kind` + `…_ref_id` 한 쌍. 값 칸에 파일 경로를 넣지 않습니다(경로는 `resource_master`).
7. **같은 내용을 두 곳에 두지 않습니다.** 칸 위치 · 시설 · 이름처럼 이미 원본 표가 있는 정보는 그 표 ID로 연결만 합니다(6절 보드 참고).
8. 금지 낱말: 「아이돌 캐스팅」, 「해외」는 새로 쓰는 글 · 이름에 쓰지 않습니다.

## 3. 스키마 원본 표의 칸

### schema_table (표 한 줄)
- `table_key` 표 키 · `rel_path` 파일 경로 · `layer` 묶음(game · master · bad_energy …)
- `status`: `registered`(등록 · 검사 대상) · `unregistered`(있지만 미등록) · `archived`(보관됨, `rel_path`가 보관 폴더를 가리킴)
- `pk` 첫 칸(주키) · `game_schema_order`(게임 스키마에 들어가는 순서) · `registry_order` · `planning_order`(기획 CSV 목록 순서)
- `read_game` · `read_tool` · `read_script` … 읽는 곳 표시 · `planning_id` · `label_ko` · `group_ko`(표 툴 묶음 이름)
- `create_mode`: `header_only`(새 빈 표 → 머리줄만 만들어 줌) · `has_rows`(이미 줄이 있는 표)
- 보관할 때는 줄을 지우지 않고 `status=archived` + `rel_path`를 보관 위치로 바꿉니다.

### schema_column (칸 한 줄)
- `table_key` · `column_name` · `column_order`(CSV 머리줄 순서와 같아야 함) · `value_type`(string · number)
- `fk_target`(다른 표 칸을 가리킴) · `min_value` · `max_value`(지금은 경고만, 숫자가 정해지면 저장 차단) · `optional_order` · `deferred_*`(발란스 대기 허용 칸)
- 칸을 더하면: CSV 머리줄 + 이 표 한 줄을 **같이** 고치고 `schema-generate`를 돌립니다.

### schema_change_log (바꾼 기록)
- 표 · 칸을 더하거나 이름을 바꾸거나 보관하면 한 줄 남깁니다. `change_type` 예: `add_table` · `archive_version` · `rename_table_key`(old_value · new_value에 표 키를 띄어쓰기로 나란히 · id_rename_map이 이것을 읽음) · `rename_folder` · `rename_code_path`.

## 4. 마스터 + 하위 표, 공통 틀

**마스터 표**(공통 칸만) + **하위 표**(그 종류에만 있는 칸, 마스터 ID를 씀):

- `item_master` (+ `item_master_dice_mult` · `item_master_card_pack` · `item_master_casting` · `item_master_shop_sku` · `item_master_shop_gem_ladder` · `item_master_sale_offer`)
- `character_master` · `skill_master` · `ability_master`(+ `ability_detail`) · `currency_master` · `missile`(+ option) · `aura`(+ option)

**공통 틀**(여러 기능이 같은 모양으로 씀):
| 틀 | 표 | 쓰는 법 |
|---|---|---|
| 보상 | `reward_group` · `reward_group_entry` | 주인(source_table · source_id)마다 묶음 하나, 줄마다 `reward_kind` + `reward_ref_id` + `amount`(+ 확률 `weight`) |
| 비용 | `cost_group` · `cost_group_entry` | 주인(source_kind · source_ref_id)마다 묶음 하나, 빈 묶음 = 무료. 코드: `src/game/economy/costGroup.ts` |
| 조건 | `condition_group` · `condition` | 주인 줄의 `condition_group_id`로 연결, `match_mode`(지금 all만), 중첩 1단계. 코드: `conditionGroup.ts` |
| 효과 | `effect` · `effect_link` · `effect_modifier` | 주인(owner_kind · owner_ref_id) → 효과, 조건 묶음 연결 가능. 겹침 순서는 발란스 대기 |
| 운영 덮어쓰기 | `live_config` | 표 · 키 · 값 · 기간 · 우선순위 · segment. 충돌 규칙은 코드(`resolveLiveOverrides`) |
| 시안 | `design_profile` · `design_profile_value` | 원본 표는 한 벌, 시안 값만 따로(운영 · 경제와 섞지 않음) |
| 리소스 | `resource_master` · `resource_link` · `resource_variant` | 그림 · 모델 경로는 여기만. 다른 표는 `resource_master_id`로 가리킴 |
| 이름 목록 | `enum_value` | 칸에 들어갈 수 있는 값 목록 |

## 5. 코드에서 읽는 법

- **표 키로 읽기**: `readTables(['board_tile','building_master'])` (`src/data/commonLoader.ts`) — `schema_table.rel_path`를 따라감. 직접 경로를 코드에 적지 않습니다.
- **게임 표 묶음**: `loadGameTables()` (`src/data/loader.ts`) — `game_schema_order`가 있는 표 + 마스터 참조(`@이름`).
- **콘텐츠 폴더 + 짧은 이름**: `tableFileOf('/data/bad_energy/','wave')` → `bad_energy_wave.csv` (`src/data/tableFile.mjs`). 규칙이 있는 폴더: `board_runtime` · `mons_proto` · `bad_energy`. 새 폴더는 규칙을 더하지 말고 풀네임 파일 이름을 그대로 쓰세요.
- 화면에서 쓰는 CSV 읽기: `src/data/csv.ts`(게임) · `src/simulator/csv.mjs`(시뮬레이터 · 보드 맵) — 엄격 모드(칸 수가 다르면 멈춤).

## 7. 표를 더하거나 바꾸는 순서

1. `schema_table.csv`에 표 한 줄(표 키 · `rel_path` · `pk` · `status` · 필요하면 `create_mode=header_only`)
2. `schema_column.csv`에 칸 줄들(머리줄 순서대로 `column_order`)
3. CSV 파일(머리줄이 2와 같게) · 값은 짓지 않음
4. `node scripts/schema-generate.mjs` 두 번 → `node scripts/schema-generate.mjs --check` 조용함
5. `schema_change_log.csv`에 한 줄
6. 검사(8절)를 돌리고 결과를 보고에 붙임
7. 같은 단계에서 **표와 읽는 코드를 함께** 바꿉니다. 바꾸기 전 파일은 `_이전기획_보관/<날짜>/…/수정전/`에 복사.

보관할 때: 파일은 `_이전리소스_백업/…`(쓰지 않는 자료) 또는 `_이전기획_보관/…`(백업)로 같은 상대 경로로 옮기고, `schema_table` 줄은 `archived`로. `planning_csv_usage` · `resource_master` · `resource_link`에서 그 표 · 파일을 가리키던 줄도 보관 폴더로 옮깁니다(끊긴 줄 0).

## 9. 자주 하는 실수

- 생성물(`schema.ts` · `table_registry.csv` · `planning_csv_table.csv`)을 손으로 고침 → 다음 생성 때 사라짐
- 코드에 `/data/xxx/v01/…` 같은 옛 경로 · 버전 폴더를 적음
- 빈칸을 0으로 채움 · 예시 숫자를 「확정」으로 적음
- 보드 칸 이름 · 시설을 화면 코드에 배열로 적음
- 보관 폴더(`_이전리소스_백업`) 파일을 import · fetch · 링크함 → 개발 서버가 403으로 막음

- **빈 표는 두지 않습니다**: 다른 표로 통일했거나 쓰지 않게 된 표(예: 10/19 `mons_skill` → `skill_master`)는 읽는 곳과 함께 `_이전리소스_백업/이전판/` 으로 옮깁니다. 그 표만 가리키던 빈 열도 같이 지웁니다.
