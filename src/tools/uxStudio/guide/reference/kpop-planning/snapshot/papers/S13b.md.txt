## 간략

**머리표** 시스템 기획 · S13b · 미니게임 이벤트 · 모노 이벤트 미니게임 셋 + 간단 셋 이식

**제목** 미니게임 이벤트 — 보드에서 모은 재화로 하루짜리 놀이를 한다

**훅** 오늘 오른쪽 레일엔 「쏘기」가 열려 있다. 칸에 도착할 때마다 도전권이 떨어지고, 한 번에 몰아 쏴서 순위를 올린다.

**두 줄 요약**
- 셋 다 같은 흐름: **칸 도착 드랍 → 재화 → 놀이 → 단계 · 순위 보상**. 회차는 하루(24시간).
- 갈래가 다르다: 쏘기 = (경쟁) 순위 · 드랍 = (도전) 마일스톤 · 관문 = (도전) 단계 반복.

```mermaid
flowchart LR
  B[시설 칸 도착] -->|확률 × 양 × 배수| C[재화<br/>도전권 · 드랍 공 · 곡괭이]
  C --> A[쏘기<br/>점수 → 순위]
  C --> P[드랍<br/>공 → 번개 → 단계]
  C --> H[관문<br/>칸 파기 → 관문 통과]
  A --> R[순위 보상]
  P --> M[단계 보상]
  H --> M
```

1. **모은다** — 오른쪽 레일에 열린 이벤트의 재화가 칸 도착 때 떨어진다.
2. **논다** — 이벤트 창에서 재화를 써서 한 판(쏘기 · 공 떨어뜨리기 · 칸 파기).
3. **오른다** — 점수 · 번개 · 관문이 쌓여 단계 보상 또는 순위가 오른다.
4. **닫힌다** — 하루가 지나면 남은 재화는 사라지고 순위는 정산.

| 왜 지금 | 이게 핵심 | 이게 아닌 것 |
|---|---|---|
| S07에 틀 · 드랍 · 수요 · 보상 줄만 있고 놀이 규칙 · 칸 · 단계 문턱이 없다(2차 3단계) | 보상에 배수 안 곱함 · 꽝 없음 · 받기 전엔 다음 판 막힘(쏘기) · 재화 이월 없음 | 보드 미니게임(S07 3절 · 칸에서 바로) · 전투 이벤트(라바 · 스퀘어 간단) |

## 2026-10-28 · 이벤트 선반 단독 시험 연결 참고

작성자 `codex` · 제안(검수 대기). 앞의 운영 기획·값·이력 및 모노간단 구현 참고를 보존하며, 이 절은 현재 공용 시뮬레이터의 실제 연결 범위를 기록합니다. 케이팝 운영 보상·발란스 확정이나 본편 통합 완료를 뜻하지 않습니다.

### 기존 연결 차이와 현재 시험 호스트

기존 이벤트 선반은 양궁·퍼즐드랍의 HTML만 iframe으로 열었습니다. 두 게임은 `aa:ready`/`pd:ready` 뒤 기존 호스트의 지갑 동기화를 기다리므로, 화면의 재화 0과 비활성 도전은 정상적인 재화 소진이 아니라 호스트 연결 누락이었습니다. 현재 `src/simulator/event-package-host.mjs`가 기존 `archeryHost.ts`·`prizeDropHost.ts`를 모듈별로 마운트하고, 현재 iframe의 origin과 source가 맞는 메시지만 받습니다. iframe 교체·종료 때 기존 호스트의 정리 계약도 호출합니다.

최초 재화는 원본의 지급 함수를 재사용합니다. 양궁은 `event/archeryArena/archery_arena_integration_config.csv`의 `starter_bow_stands=5` 및 기존 호스트의 1회 지급 플래그를 따릅니다. 일일 무료는 기존 `archery_arena_event_config.csv`의 1발 규칙을 그대로 읽으므로 새 시험 첫 화면에서 6발을 관찰했습니다. 퍼즐드랍은 기존 `prizeDropHost.ts`의 3공 최초 지급을 사용합니다. 시뮬레이터에 새 지급 수치·교환비·전투 수치를 만들지 않았습니다. 기존 호스트의 보상·드랍 CSV 주소는 실제 존재하는 `archery_arena_*`·`prize_drop_*`·`lava_quest_*` 파일명으로만 바로잡았습니다.

별도의 시험 세션이 재화·보상을 보관하며 로비 허브의 실제 지갑과 원본 성장 수치는 변경하지 않습니다. 같은 시험에서 다시 들어와도 최초 재화가 중복 지급되지 않습니다. 양궁·퍼즐드랍 초기화가 겹칠 때 과거 지갑으로 다른 게임의 지급 플래그를 덮는 문제는 모든 호스트 마운트를 한 큐로 순서대로 처리하고, 큐 안에서 최신 저장을 읽도록 고쳤습니다.

### 실제 화면 확인과 저장 범위

CUA 독립 탭에서 양궁 첫 화면 6발→1발 도전→5발·점수 증가, 퍼즐드랍 3공→가운데 낙하→2공과 보드 진행을 확인했습니다. 각 게임 재입장 뒤 소모된 잔액이 유지되었습니다. 퍼즐 원본 보드 366×518은 `mobile-frame.json`의 게임별 viewport로 연결했고, 공통 폰 390×844는 유지했습니다. 스퀘어간단도 iframe 내부가 실제 세로 viewport를 갖게 해 전투·일시정지·계속하기 입력을 확인했습니다. 회전 경고나 게임 규칙을 지우지 않았습니다.

양궁 점수·순위·메타·순위 초기화도 시험 페이지와 시험 run별 이름공간을 사용합니다. `simulatorEventScope` query를 기존 호스트→현재 iframe→저장 도우미로 전달합니다. 해당 query가 없는 일반 게임 URL은 기존 저장 키를 그대로 사용하며, native `localStorage` 자체를 바꾸거나 기존 값을 삭제하지 않습니다. 소스가 없는 양궁 패키지는 data 번들 6곳·game 번들 4곳의 저장 접근만 도우미로 연결했고 나머지 바이트는 원본 복원 SHA256으로 대조했습니다. 부모 메타·진단·포디엄 코드도 같은 저장 도우미를 사용합니다.

마지막 A/B/A 화면 시험에서 A는 1발 사용 뒤 점수55·5발, 새 B는 점수0·6발, A 재입장은 점수55·5발을 유지했습니다. 점수55는 해당 무작위 한 발의 관찰값이며 기획 수치가 아닙니다. 관련 단위 시험은 `tests/simulator-event-frame-fit.test.mjs`·`simulator-event-host-session.test.mjs`·`simulator-event-frame-storage.test.mjs` 합계 12/12 통과했습니다. 전체 보상 분기·시각 정산·마일스톤 완주를 검수한 것은 아닙니다.

### 라바와 획득 팩의 남은 연결

라바에는 기존 `lavaHost.ts`와 시작 티켓3·입장1 소모 함수가 있으나, mount만으로 이 흐름이 시작되지는 않습니다. 도전은 본편 공유 던전 callback을 요구합니다. 현재 케이팝 프로젝트에는 `ui/lava/LavaView.ts`·`flow/lavaDungeon.ts`·`event/minigames/lavaEventProgress.ts` 및 원본 boot/data loader 연결이 없어 실제 던전을 호출할 수 없습니다. 따라서 선반은 「본편 던전 연결 준비 중」과 사유를 표시하고, 눌러도 반응 없는 외부 도전 iframe 진입을 막습니다. 기존 라바 자료는 보존하며 실행 완료로 표시하지 않습니다. 모노 전투 수치나 임의 전투를 복사해 채우지 않았습니다.

이벤트에서 얻는 돈·주사위·루비·팩은 단독 시험 기록에만 보관합니다. 기존 port의 모노 카드 종류와 현재 케이팝 카드북의 연결은 별도 작업이므로, 팩을 모노 카드로 열거나 현재 카드 효과에 적용하지 않습니다. 화면에는 「팩 보관 · 현재 카드북 연결 대기」를 표시합니다. 운영 회차·본편 시설칸 드랍·전체 정산·현재 카드북 팩 개봉은 남은 통합 범위입니다.

등록 `simulator_module_events`의 기획 ID `P58`과 현재 catalog의 문서 대응 차이는 별도 표 관할 확인이 필요합니다. 이번 변경에서는 등록표를 임의 수정하지 않았습니다.
