<p><b>이 문서는</b> 40칸 보드에서 위치와 칸의 역할, 아홉 시설이 연결되는 곳, 도착 뒤 어느 시스템으로 이어지는지를 설명합니다. 주사위로 도착한 칸에 따라 활동이 달라지고, 받은 수익은 시설을 키우는 데 사용합니다.</p>
<p><b>보는 법</b> 1장 시설 연결 수 → 4장 도착 처리·성장·표시 시안 → 6장 원표 순서로 읽습니다.</p>
<p><b>지금 상태</b> 현재 보드 표·도착 시험과 임시 성장 배정의 읽기 경로가 있습니다. 전체 화면·정산 통합 검수와 최종 수치는 남아 있습니다.</p>

<section class="part" id="part-1"><h2>1. 개요</h2>

<p>보드는 40칸이 이어진 한 바퀴입니다. 사옥을 포함한 시설 연결 위치는 25칸, 건물 없는 위치는 15칸입니다. 이 중 <b>사옥은 출발 칸</b>이므로 표의 <code>tile_kind=building</code>인 일반 건물 도착은 24칸입니다. <a href="/docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%ED%95%84%EB%9F%AC%EB%A3%B0%EB%A0%9B_v01/%ED%95%84%EB%9F%AC%EB%A3%B0%EB%A0%9B_%EA%B8%B0%ED%9A%8D%EC%84%9C.html" data-paper-path="docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%ED%95%84%EB%9F%AC%EB%A3%B0%EB%A0%9B_v01/%ED%95%84%EB%9F%AC%EB%A3%B0%EB%A0%9B_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">필러 룰렛</a>의 24칸과 사옥을 포함한 시설 연결 25칸을 같은 수로 혼동하지 않습니다.</p>

<p>시설은 보드 길 사이에 서고, 각 칸은 시설 ID를 참조합니다. 건물에 도착한다고 자동으로 단계가 오르지 않습니다. 수익과 성장, 돈을 사용한 건설·증설은 각 시스템의 규칙을 따릅니다.</p>

<li>메인에서 현재 진행을 열고 배수와 주사위를 선택합니다.</li>
<li>이동한 위치의 번호·이름을 확인합니다. 시설 위치는 연결 시설과 그 단계, 나머지 위치는 각 칸의 기능으로 이어집니다.</li>
<li>쟁탈·건설 등은 전용 도구가 맡으며 같은 도착 정보를 사용합니다. 시험용 조작으로 칸을 고른 결과와 자연스러운 보드 플레이를 구분합니다.</li>
<li>도착 처리를 마친 뒤 메인에서 같은 진행을 이어갑니다. 이 문서를 여는 것만으로 시뮬레이터나 3D 화면은 실행하지 않습니다.</li>
</ol>

<h3 id="시작부터-도착까지">시작부터 도착까지</h3>

<p>플레이어는 같은 팀과 보드 진행을 열고 보유 주사위와 열려 있는 배수를 확인합니다. 배수는 이번 굴림에 쓰는 주사위 양이자 일부 도착 수익에 적용되는 값입니다. 열림 조건·보유량이 부족하면 다른 배수를 고릅니다. 두 주사위 눈의 합으로 현재 칸에서 앞으로 이동하고, 40번을 지난 뒤 1번 사옥을 다시 만나는 원형 경로입니다. 플레이어가 도착할 칸을 직접 고르지는 않습니다. 전용 검토 화면의 강제 도착은 시험 조작입니다.</p>

<p>경제 계산 코드에서는 도착 위치와 경로를 계산한 다음 해당 배수만큼 주사위를 차감하고, 시작점을 지나면 한 바퀴 수익을 처리합니다. 감옥에 갇힌 상태는 더블과 시도 횟수를 별도로 검사하므로 일반 이동과 다를 수 있습니다. 그다음 도착 칸의 종류와 표에 따라 돈·성장·콘텐츠를 처리하고, 결과와 현재 위치를 같은 진행에 남깁니다. 수익·감옥 비용·배수는 해당 표의 설정을 따르며 최종 수치는 발란스 대기입니다.</p>

<h3 id="시설에-도착하면-무엇을-하나요">시설에 도착하면 무엇을 하나요</h3>

<p>보드가 칸의 <code>fac_id</code>를 읽어 해당 시설과 현재 단계를 찾습니다. 예를 들어 7·9·22번은 서로 다른 위치지만 같은 보컬 녹음실을 가리킵니다. 세 위치에 시설을 따로 세 개 키우는 뜻이 아닙니다. 각 칸에서 성장·수익에 쓰는 입력은 보드 보상 표와 시설 단계·개인 성장·경제 원본이 맡습니다.</p>

<p>일반 건물 24칸은 도착 필러의 대상입니다. 현재 필러 시뮬레이터는 올킬·차트인·광탈 중 한 결과를 정해 휠로 보여 줍니다. 이 화면의 보상은 <b>표시 전용</b>으로 실제 지갑에 더하지 않습니다. 독립 표시 시안은 현재 건물 칸 <code>base_income</code> 0을 읽어 표시 코인도 0입니다. 기존 설명·policy 라벨의 30·30·40과 <code>building-arrival.json</code>의 실제 표시 추첨 가중치 15·50·35는 서로 다릅니다. 이 혼재는 표시 시안의 설명 차이이며 운영 지급 확률 오류라는 뜻이 아닙니다. 별도 경제 엔진은 자기 표의 판정으로 수익을 계산하고, 성장 허브에서는 그 경제 결과를 필러 표시 영수증에 전달하는 경로도 있습니다. 독립 필러 추첨·허브 전달 표시·경제 계산을 같은 모드로 합치지 않으며 최종 수익·확률은 발란스 대기입니다.</p>

<p>도착 성장은 같은 팀의 멤버와 세부 능력에 연결합니다. 성장 계산이 만든 결과와 수익 계산이 만든 결과는 각각의 원본에서 받으며, 필러 화면은 전달받은 성장 요약을 보여 줄 수 있습니다. 대표 6축은 세부 능력의 평균 표시입니다. 어떤 세부 능력이 얼마나 오르는지와 미정 배수는 발란스 대기입니다.</p>

<p>건설은 <b>도착과 별도의 선택</b>입니다. 현재 자금과 시설 단계, 비용 표를 확인하고 사용자가 건설 또는 증설을 선택합니다. 도착 룰렛의 「건물 연출 보기」는 현재 저장된 단계를 보여 주는 연출이며 그 버튼 자체가 단계나 돈을 바꾸지 않습니다. 건설의 실제 거래와 표시 전용 외관 확인은 <a href="/docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EA%B1%B4%EB%AC%BC%EC%84%B1%EC%9E%A5_%EA%B8%B0%ED%9A%8D%EC%84%9C.html" data-paper-path="docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EA%B1%B4%EB%AC%BC%EC%84%B1%EC%9E%A5_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">P106</a>의 경로를 구분합니다.</p>

<h3 id="저장복귀와-예외">저장·복귀와 예외</h3>
