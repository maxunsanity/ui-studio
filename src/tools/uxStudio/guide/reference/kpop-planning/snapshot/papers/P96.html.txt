<p><strong>보는 법</strong> 1장 전체 관계 → 3장 실행 링크 → 4장 몬스 UI·행복·그림 퍼즐 → 7장 실제 개발 상태 순서입니다. 몬스 보유 세부는 <a href="%EB%AA%AC%EC%8A%A4%EB%B3%B4%EC%9C%A0_%ED%95%B5%EC%8B%AC%EC%A0%9C%EC%95%88%EC%84%9C.html">P223</a>, 모험 전체 정의는 <a href="%EB%9D%BC%ED%8F%ACAI%ED%83%90%ED%97%98_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">P152 모험</a>을 함께 읽습니다.</p>
<p><b>지금 상태</b> 현재 개발되지 않음, 진행 중. 합성 규칙(<code>mons_merge_rule.csv</code> <code>merge_cap</code> 10 · <code>merge_pair_size</code> 2) · 카탈로그 27종 · 디펜스 스킬 · 행복 지갑 · 행복 10 → 몬스 팩 1 교환과 기존 경제 API 연결은 개발됨입니다. 게임 시뮬레이터 몬스 패널은 종마다 지금 단 · 합성 횟수를 보여주며(11/16 종 × 단 마릿수 반영), 4축 로비 화면 · 컨디션 미니게임은 현재 개발되지 않음, 진행 중입니다.</p>
<p class="doc-key" data-mons-inner-plan-status="proposal">컨디션 개발 현황: 성장 정산·몬스 배정 화면·현재 컨디션 단계의 게임·진행률 회복과 배정 몬스의 실제3D 모델을 연결했습니다. 발란스 몬스 탭과 게임 몬스 화면에서 돌봅니다. 출현·초반XP·비정지 FIFO·원GLB 전투와 본게임 공용 연결을 적용했고 일반1배속 전투·선택 누적·성공 결과를 확인했습니다. 레이저 머리 위 드론은 별도11항 소스와 실제 이동·총구를 확인했으며, 기존 승리 기록과 변경 시점을 구분합니다. 이전 설정의 화면 확인과 구분합니다. 전체 아이돌 요약 표시와 실제 작은 폰 화면 검수도 진행 중입니다.</p>

<p>출처: (신규) <a href="../../../../proposal-concept/bad-data.html">악귀와 몬스 제안</a> · <a href="../../../../proposal-concept/audition.html">오디션</a> · <a href="../../../../proposal-concept/mons-skill.html">몬스 스킬</a>. 이식 책갈피: 해당 없음.</p>
<p>몬스는 아이돌 곁에 떠다니는 노래의 수호신이며 <b>기획사가 소유</b>합니다. 게임 시작 때 첫 몬스를 받고, 이후 몬스 팩 · 보상 · 스케줄 · 디펜스로 모읍니다. 모든 획득은 <b>1단 한 마리</b>로 들어오고 팩 등급은 없습니다. 같은 종 · 같은 단 2마리가 되면 버튼 없이 즉시 한 단 위 1마리가 되며 최대 <b>10단</b>(10단 1마리 = 1단 512마리)입니다. 단이 오르면 나쁜 기운 디펜스 스킬 단계만 오르고 공격력 · 방어력 수치는 없습니다. <b>행복은 별도의 공용 재화</b>로, 10단을 넘친 몫이 적립되며(<code>happiness_per_merge</code> 현재 세팅값 1) 행복 10으로 몬스 팩 1을 교환합니다. 규칙 원문은 <a href="../../기획서/산출_기획서_20261113_몬스4축로비_규칙.md">몬스 4축 로비 규칙서</a> 3 · 4장입니다.</p>

<p>P96은 몬스의 종류·표현·획득과 기분의 기획 및 자산 연결을 다룹니다. 기획사 소유 · 인벤토리 · 자동 합성 · 출전 수 규칙의 세부는 <a href="%EB%AA%AC%EC%8A%A4%EB%B3%B4%EC%9C%A0_%ED%95%B5%EC%8B%AC%EC%A0%9C%EC%95%88%EC%84%9C.html">P223 몬스 보유</a>가 담당합니다. 실제 전투 흐름과 승패는 <a href="%EB%82%98%EC%81%9C%EA%B8%B0%EC%9A%B4%EB%94%94%ED%8E%9C%EC%8A%A4_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">P104</a>, 오디션과 멤버 인계는 <a href="%EC%98%A4%EB%94%94%EC%85%98_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">P100</a>이 담당합니다. 뽑기방은 별도 이벤트 체험이며, 거기에서 나온 화면상 성공을 본편 몬스 소유로 간주하지 않습니다. 12지신 제작물은 기존 NPC용 자료이며 기본 몬스 10종과 구분합니다.</p>

<p><b>몬스 4축 종합 로비</b> 몬스 탭은 로비와 같은 급의 전체 화면 하나로 묶습니다(P243 9장 Q3).</p>

<li><a href="/docs/planning/game-simulator.html?module=simulator_module_journey">탐험 · 발견 도감</a>: 6분류·27항목의 발견 조각을 그림 퍼즐로 이어 보는 경로입니다. 모험 전체 규칙은 P152를 따릅니다.</li>

<h3 id="4-0-몬스-ui와-공용-행복-재화-현재-세팅-v1">4-0. 몬스 UI와 공용 행복 재화 · 현재 세팅 v1</h3>
<p>하단의 기존 몬스 항목을 사용합니다. 화면 위에는 <strong>기획사 보유 종 수와 보유 행복</strong>, 가운데에는 보유 목록, 항목을 누르면 큰 초상·원소·역할 설명·지금 단 · 다음 단까지 남은 마리 수(R-MON-5)·획득 기록을 보여줍니다. 같은 종의 여러 칸을 만들지 않고 종마다 한 칸을 씁니다. 미보유 종과 획득한 종은 구분합니다.</p>
<p>행복은 몬스마다 붙는 단계가 아니라 <strong>기획사가 보유하고 교환에 쓰는 공용 재화</strong>입니다. 개별 몬스에는 지금 단과 다음 단까지 남은 마리 수를 표시합니다(R-MON-5). 단 합계를 행복 잔액으로 계산하지 않고, 행복은 10단을 넘친 몫에서만 적립합니다(R-MON-4). 행복의 적립·사용·현재 잔액은 공용 지갑 기록을 읽고, 시즌이 바뀌어도 행복과 처리한 거래 기록은 남깁니다. 행복10→몬스팩1 교환과 보석100·하루3회 상점은 등록된 비용·보상 표를 읽습니다. 기존 합성 기록의 과거 환산은 별도 정책이며 이번 실세이브 변환은 없습니다.</p>

<h3 id="4-0-2-성장-현황판-06과-공용-행복">4-0-2. 성장 현황판 06과 공용 행복</h3>
<p>06 칸은 공용 보유 데이터의 <strong>행복 잔액·누적 적립·사용량</strong>, 종별 지금 단 · 합성 횟수(종 × 단 마릿수 저장, 11/16 반영), 실제 획득과 적립 기록을 읽습니다. 상태가 바뀌면 06 테두리를 갱신하고, 고유 획득/적립 사건이 새로 들어온 때만 <strong>실제 원천 → 06 → 중앙 정보선</strong>을 보여줍니다. 엔터파워·사옥은 11 → 06, 미션·튜토리얼·미분류 보관 팩은 12 → 06이며, 원천이 명시된 실제 연결 기록만 사용합니다. 행복 교환의 확정 소비 거래는 중앙 → 06으로 구분합니다. 미션의 실제 플레이·장부 → 12 진행 → 수령 영수증 → 06 몬스팩·행복 → 중앙으로 연결 기록을 표시합니다. 엔터파워·사옥의 직접 팩은 11 → 06이며 행복 교환은 중앙 → 06으로 구분합니다. 진행만 올랐거나 같은 영수증을 다시 표시한 때에는 획득·성장선을 새로 만들지 않습니다. 현황판은 이 기록을 읽기만 하며 보상과 능력을 추가 지급하지 않습니다. 상태 차이만으로 보상이나 능력 상승을 새로 만들지 않습니다. 12패널·기존 6축·뉴런은 유지합니다.</p>
<p>개별 몬스의 단이 오르면 나쁜 기운 디펜스 스킬 단계만 오릅니다(R-MON-7). 행복 잔액을 공격력·팬·수익 배율로 적용하지 않습니다. 전투 편성·능력의 현재 적용 범위는 <a href="%EB%82%98%EC%81%9C%EA%B8%B0%EC%9A%B4%EB%94%94%ED%8E%9C%EC%8A%A4_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">P104</a>를 따릅니다.</p>

<section data-mons-inner-plan="v4"><h3 id="mons-inner-plan-20261105">몬스 배정과 컨디션 게임</h3>
<p><strong>신규 기획 · 제안</strong> · 현재 세팅값 정책 v6. 상세 원본: <a href="몬스_기획서.html#mons-inner-plan-20261105">P96 몬스</a> · <a href="몬스보유_핵심제안서.html#mons-inner-plan-20261105">P223 보유·배정</a> · <a href="아이돌능력_기획서.html#mons-inner-plan-20261105">P107 개인 성장</a> · <a href="성장관계_기획서.html#mons-inner-plan-20261105">P169 성장 연결</a></p>
<h4>컨디션 게임으로 정리한 기준</h4>
<p>아이돌별 컨디션을 몬스가 돌보는 구조입니다. 기획사 보유 몬스를 아이돌에게 배정하고, 배정 몬스로 현재 컨디션 단계에 대응하는 게임을 플레이해 회복합니다. 사용자가 지정한 이름은 ‘컨디션 게임’이며, 아이돌 컨디션 5단계와 게임 5단계를 연결합니다.</p>
<p>능력이 실제 오르면 컨디션이 감소하고 이후 새 능력 획득 배율에 반영합니다. 기존 스퀘어 전투·몬스와 배경3D·이동형 보스를 재사용하며, 정책 v6의 단계별 보스 시간과 진행률 회복을 적용합니다. 구현과 실제 화면 검수 범위는 아래 연결 현황에서 구분합니다.</p>
<p><span class="yr-old">앞선 일상/사건 누적 나쁜 영향 게이지와 별도 영구 5단계 해금 초안은 이 설계로 대체합니다.</span> 새 개인 게이지는 컨디션 하나이며, 기획사 나쁜 기운·몬스 공용 행복·전투 체력과 구분합니다.</p>
<h4>기획사 보유와 아이돌 배정</h4>
<ul><li>기획사 소유는 유지하고 아이돌 1명에게 보유 몬스 1종을 배정합니다. 현재 인벤토리가 종 단위이므로 배정 키도 보유 종 ID를 사용합니다. 같은 보유 종의 동시 배정은 아이돌 1명까지로 제한합니다.</li><li>배정·해제·교체는 전투 밖에서 무료이며 몬스를 소모·복제하지 않습니다. 몬스가 한 마리뿐이면 다른 아이돌에게 옮겨 돌볼 수 있습니다. 미배정이면 해당 아이돌에 배정하는 동선을 먼저 엽니다.</li><li>배정 중인 아이돌과 몬스는 컨디션 게임 한 판 동안 교체할 수 없습니다. 기존 디펜스·출연권·모험 출동 명단은 별도이며 새 배정으로 보유 수나 기존 출전 명단을 바꾸지 않습니다.</li><li>후보의 옛 mons_id/generated_mons는 새 배정의 근거가 아닙니다. 실제 기획사 인벤토리와 candidate_id 기반 배정표에서만 읽습니다.</li></ul>
<h4>아이돌 컨디션 5단계</h4>
<p>컨디션은 아이돌별 0~100, 신규 합류 초기값은 100입니다. 저장은 0.01포인트 정수 단위로 하고 5단계는 설정표에서 계산합니다. 단계 값을 별도로 저장해 현재 수치와 어긋나게 만들지 않습니다. 아래 범위·배율은 현재 세팅 정책 v6입니다.</p>
<div class="table-scroll"><table><thead><tr><th>컨디션 단계</th><th>범위</th><th>능력 획득 배율</th><th>대응 컨디션 게임</th></tr></thead><tbody><tr><td>5 · 최상</td><td>80 이상~100</td><td>100%</td><td>5단계 · 맑은 무대</td></tr><tr><td>4 · 좋음</td><td>60 이상~80 미만</td><td>95%</td><td>4단계 · 집중의 무대</td></tr><tr><td>3 · 보통</td><td>40 이상~60 미만</td><td>85%</td><td>3단계 · 흔들리는 무대</td></tr><tr><td>2 · 피곤</td><td>20 이상~40 미만</td><td>70%</td><td>2단계 · 잡음의 무대</td></tr><tr><td>1 · 지침</td><td>0 이상~20 미만</td><td>50%</td><td>1단계 · 휴식의 입구</td></tr></tbody></table></div>
<p>이번 행동을 시작할 때의 컨디션으로 그 행동 전체의 획득 배율을 한 번 정합니다. 같은 행동이 18개 세부 능력으로 나뉘어도 뒤쪽 항목만 낮은 배율을 받지 않습니다. 기존 능력·재능·천장을 깎지 않고 새로 획득하는 증가량을 조정합니다.</p>
<p>실제 증가가 없으면 감소도 없습니다. 현실 시간·접속 종료·일차 변경만으로 감소시키지 않습니다. 컨디션 0에서도 성장 배율 50%를 유지하고 게임 입장을 막지 않습니다.</p>
<h4>능력 획득과 피로의 현재 세팅 비율</h4>
<div class="table-scroll"><table><thead><tr><th>대상</th><th>최종 실제 증가 기준</th><th>컨디션 소모</th></tr></thead><tbody><tr><td>18세부 능력</td><td>정규화 점수 합 1점 = 현재 표시 1,000점</td><td>0.25</td></tr><tr><td>영어·중국어·일본어</td><td>정규화 언어 점수 합 10점</td><td>0.25</td></tr><tr><td>태도·성실성·6축 평균·팀 능력</td><td>18세부에서 계산되는 값</td><td>추가 소모 0 · 원래 세부 증가에 포함</td></tr><tr><td>초기 능력·불러오기·동기화·시험 강제값</td><td>새 성장 지급이 아님</td><td>소모 0</td></tr></tbody></table></div>
<p>소모 = 0.25 × (최종 실제 18세부 증가 합 + 최종 실제 언어 증가 합 ÷ 10). 입력에 단위 태그를 붙여 정규화합니다. 실제 게임 person.got/snapshot은 이미 정규화 단위여서 그대로 읽고, 발란스의 표시 증가량만 ability_score_mult로 나눕니다. TalentSide 내부 값은 tm.scale로 표시값으로 바꾼 후 공통 배율로 나눕니다. 이미 정규화된 값을 다시 나누지 않습니다.</p>
<p>예: 실제 표시 능력 합 +20,000이면 컨디션 -5, 정규화 언어 +20점이면 -0.5입니다. 예상 +20,000 중 상한 때문에 실제 +4,000만 받았다면 -1만 적용합니다. 0.01 미만 반올림 잔량만 누적 보존해 작은 성장 여러 번과 한 번의 큰 성장이 같은 비용이 되게 합니다. 컨디션0을 넘는 소모는 부채로 이월하지 않고 바닥 도달 시 소모 잔량도 비웁니다. 예: 컨디션1에서 소모5가 발생하면0으로 끝내며 다음 보스 처치 성공 시 컨디션100까지 회복합니다.</p>
<p>정규화 언어 1,000은 5등급 문턱이며 성장 상한이 아닙니다. 그 이후 실제 증가도 같은 비율을 사용합니다. 태도·성실성은 현재 각 9세부의 평균이므로 독립 성장으로 다시 차감하지 않습니다.</p>
<p>현재 일일 제한은 daily_cap_kind=step의 세부별 단계 제한이 먼저 적용됩니다. 초반 세부별 10×11.5%×18=20.7일 때 피로 5.175가 되는 산술 예이며, 모든 단계·언어까지 포함한 고정 일상한이라는 뜻이 아닙니다. 현재 약 9.5 정규화점 성장 예시라면 하루 피로 약2.375입니다. 보상 폭증 시 피로도 실제 획득량에 비례합니다.</p>
<h4>현재 컨디션에 맞는 한 판</h4>
<ol><li>캐릭터 정보의 개별 능력에서 컨디션을 확인하고 ‘컨디션 게임’을 누릅니다. 미배정 상태는 ‘몬스 배정하고 돌보기’로 기존 배정 화면을 엽니다. 선택 아이돌의 현재 컨디션 단계와 배정 몬스를 확인하고 그에 맞는 게임 1~5단계로 입장합니다.</li><li>입장 시 대상 아이돌 ID·배정 몬스 ID·컨디션 단계·설정 버전을 고정합니다. 컨디션 35라면 2단계이고 보스 처치 후100이 되면 다음 입장은5단계입니다. 컨디션이 내려가면 대응 단계도 내려갑니다. 별도 영구 순차 해금 기록은 만들지 않습니다.</li><li>보스 등장 전까지 기존 스퀘어의 웨이브·종대·이동·자동 공격·전투 중 성장 구조에 이번 라운드 설정을 적용합니다. 몬스와 배경을3D로 표현하고 기존 공격 판정과 예고를 읽기 쉽게 유지합니다.</li><li>현재 컨디션 단계의 설정 시간에 대표 보스1종이 등장합니다. 컨디션 모드는 시간 경과만으로 자동 성공하지 않고 기존 보스 사망→클리어 처리를 연결합니다.</li><li>보스 처치 성공이면 대상 아이돌의 정산 시점 현재 컨디션을100까지 회복합니다. 입장 당시 수치로 덮어쓰지 않습니다. 회복량과 단계 변화, 몬스 귀환을 짧게 보여 줍니다.</li><li>패배는 정산 시점의 빈 만큼×진행률을 회복하고, 도중 나가기·취소는 회복0입니다. 추가 피로0, 입장 비용0입니다. 컨디션100은 회복 필요 없음으로 표시합니다. 성공 반복의 별도 주사위·돈·팩 보상은 붙이지 않습니다.</li></ol>
<p>컨디션이 낮을수록 판이 길고 적이 강해집니다. 패배해도 진행률만큼 회복하며, 단계별 난이도 체감은 실측 대기입니다. 모든 단계는 합성0회 몬스로도 성공 가능한 기준으로 조정합니다. 컨디션의 능력 획득 배율을 몬스 전투 공격력에 다시 적용하지 않습니다.</p>
<h4>이동형 보스와 5단계 현재 세팅</h4>
<p>기존 이동형 CRUSHER·TITAN의 보스 AI와 스퀘어 전투 엔진을 재사용합니다. 현재 연결은 game JSON의 tiers·round와 정책 v6의 care를 원본으로 읽습니다. 이전 보스 체력·생성 배수의 출발표는 로그에 보존하고 현재 수치로 복제하지 않습니다.</p>

<p>보스 등장 시 일반 적 추가 생성을 멈추는 설정과 기존 보스 패턴을 따릅니다. 합성 전투 보정은 없습니다(11/13 제외, P243 9장 Q2). game JSON의 synthesis_bonus는 꺼 두어(enabled false) 전투 배수가 1로 고정됩니다. 컨디션 게임은 아이돌 컨디션만 회복하고 몬스 공 · 방을 올리지 않으며 공용 행복을 자동 차감하지 않습니다. 최신 라운드의 성공률·보스전 시간·실제 회복 저장 왕복은 아직 확인 전입니다.</p>
<h4>피로도에 따른 난이도 · 시간 · 회복 (11/09 제안 · 개발 적용)</h4>
<p>현재 설정 v6의 단계별 시간·적 세기·진행률 회복을 적용합니다. 아래 수치는 설정 파일의 현재 세팅값입니다. 최신 단계별 실제 완주·패배 회복의 저장 왕복과 장기 난이도 실측은 검수 전입니다.</p>
<div class="table-scroll"><table><thead><tr><th>컨디션 단계</th><th>컨디션</th><th>판 길이(보스 등장)</th><th>적 세기</th><th>보스</th><th>끝까지 깨면</th><th>못 깨면</th></tr></thead><tbody><tr><td>1 지침</td><td>0~19</td><td>150초</td><td>×1.30</td><td>CRUSHER</td><td>100까지</td><td>빈 만큼 × 진행률</td></tr><tr><td>2 피곤</td><td>20~39</td><td>120초</td><td>×1.15</td><td>CRUSHER</td><td>100까지</td><td>빈 만큼 × 진행률</td></tr><tr><td>3 보통</td><td>40~59</td><td>90초</td><td>×1.00</td><td>TITAN</td><td>100까지</td><td>빈 만큼 × 진행률</td></tr><tr><td>4 좋음</td><td>60~79</td><td>60초</td><td>×0.90</td><td>CRUSHER</td><td>100까지</td><td>빈 만큼 × 진행률</td></tr><tr><td>5 최상</td><td>80~100</td><td>45초</td><td>×0.80</td><td>CRUSHER</td><td>100까지</td><td>빈 만큼 × 진행률</td></tr></tbody></table></div>
<ul><li><b>피곤할수록 길고 어렵게</b> — 채울 양이 많은 만큼 판도 길고 적도 셉니다. 대신 못 깨도 간 만큼은 회복되므로, 지친 아이돌이 회복을 아예 못 받는 일은 없습니다(이전 「1단계를 가장 쉽게」는 이 규칙으로 바꿈).</li><li><b>끝까지 깨면 100%</b> — 보스까지 처치하면 컨디션을 최대(100)까지 채웁니다.</li><li><b>못 깨면 간 만큼만</b> — 회복 = 빈 만큼(100 − 지금) × 진행률. 진행률 = 보스 전에는 버틴 시간 ÷ 보스 등장 시간 × 0.8, 보스가 나온 뒤에는 0.8 + 보스 체력 깎은 비율 × 0.2, 처치 = 1(0.8 · 0.2는 현재 세팅값).</li><li>예: 컨디션 30(2단계)에서 120초 판 중 60초에 쓰러지면 진행률 0.4 → 70 × 0.4 = +28 → 58. 보스 체력 절반을 깎고 지면 0.9 → +63 → 93. 처치하면 100.</li><li><b>0초 · 시작 전 취소는 0</b> — 판 도중 나가기도 0초 취소로 처리해 회복 0입니다(현중 11/10 「0으로 둬」 확정 · 조금 하다 나가기를 반복하는 게 이득이 되지 않게)(쓰러져서 진 판만 진행률 회복). 추가 피로 · 입장 비용 · 다른 보상은 지금처럼 0.</li><li>사용한 몬스는 게임 종료 뒤24시간 쉽니다. 승리와 패배는 사용으로 세고, 나가기·안전 취소는 세지 않습니다. 하루 소모량과 회복 효과의 장기 발란스는 현재 v6와 자동 사용 조건으로 실측하며 과거 고정 회복량 기반 추정을 재사용하지 않습니다.</li><li><b>본 게임도 같은 규칙</b> — 발란스 시뮬 · 몬스 메뉴 · 본 게임 컨디션 화면이 모두 같은 계산 모듈(<code>idol-condition-care.mjs</code>)과 같은 설정 표를 쓰므로 한 번에 적용됩니다. 본 게임 화면의 진행률 표시 · 결과 연출은 함께 개발합니다.</li><li>설정과 저장은 정책 v6의 단계별 판 설정·진행률 회복을 연결합니다. 결과 영수증의 진행률과 보스 체력 감소 비율을 검증하여 기존 writer로 저장하며, 옛 영수증은 해당 버전의 규칙으로 읽습니다. recovery_bp는 현재 진행률 방식에서 쓰지 않습니다.</li></ul>
<h4>발란스 시뮬 · 몬스 자동 사용 (11/10 · 현중 「50프로 남으면 그때 몬스 쓰는 걸로 · 현황판에서 보여 주고 · 화살표로 해당 아이돌 피로도로 · 피로도가 차는 걸로」)</h4>
<ul><li>발란스 자동 사용은 별도 시험 정책입니다. 수동 전투와 같은 회복 계산·저장 규칙을 사용하지만 실제 전투를 플레이한 결과로 기록하지 않습니다.</li><li><b>바뀜 · 발란스 시뮬 전용</b> — 자동 진행 중 멤버 컨디션이 50% 이하(<code>balance_auto_care.threshold_bp</code> 5000 · 현재 세팅값)가 되면, 그 멤버에게 붙은 몬스가 쉬는 중이 아닐 때 자동으로 컨디션 게임을 한 판 씁니다.</li><li><b>자동 판 결과(가정)</b> — 실제 판 플레이 수치가 나오기 전까지 「끝까지 깸」으로 셈(<code>assumed_result: clear</code> · 현재 세팅값) → 최대까지 참. 판 실측 뒤 평균 진행률로 바꿈.</li><li><b>규칙은 손으로 쓸 때와 같음</b> — 같은 계산 모듈 · 같은 저장 writer · 몬스 하루 한 번(24시간 = 시뮬 하루) 그대로. 몬스가 없거나 쉬는 중이면 안 씀. 자동 사용은 자동 진행을 멈추지 않음.</li><li><b>검사 시점</b> — 주사위 한 번이 끝날 때마다 · 오프라인 계산이 끝났을 때. 오프라인 계산 도중(여러 날 한꺼번에)은 끝난 뒤 한 번만 검사(한계).</li><li><b>현황판</b> — 몬스 칸 컨디션 막대에 50% 선(몬스 쓰는 선) · 몬스를 쓰면 그 멤버의 몬스 → 컨디션 막대로 화살표가 올라가고 막대가 전 값에서 새 값까지 차오름. 처음 열 때 이미 있던 판은 움직이지 않고, 새로 들어온 판만 화살표와 「+회복량」 표시를 1.6초 보여 줍니다(11/10 개발 적용 · 시험 값으로 1440 · 2048 확인 · 실제 시뮬 장기 진행 미확인).</li></ul>

<p>소유하지 않은 후보는 생성 초기 컨디션으로, 실제 합류 멤버는 현재 저장으로 표시합니다. 과거 generated_mons나 미연결 값을 실제 배정/컨디션100으로 꾸며 넣지 않습니다. 자료가 없으면 연결 상태를 보여 줍니다.</p>

<h4>현재 컨디션 규칙과 캐릭터 정보 연결</h4>
<p>컨디션 전투는 이동형 CRUSHER와 TITAN을 사용합니다. 고정형 NEXUS는 이 모드에서 제외하고 기존2·5단계를 CRUSHER로 연결합니다. 원래 스퀘어 게임의 NEXUS·벽 패턴과 원본 자산·CSV는 변경하지 않습니다.</p>
<p>개인 컨디션은0~100이며 기획사 나쁜 기운과 별개입니다. 캐릭터 정보의 개별 능력에서 컨디션·배정 몬스·게임 입장 상태를 확인합니다. 미배정은 기존 몬스 배정 화면으로, 배정됨은 같은 아이돌의 기존 컨디션 게임으로 연결합니다. 사용한 몬스는 게임 종료 후24시간 쉬며 다른 아이돌에게 옮겨도 제한을 유지합니다. 패배도 사용으로 세고 나가기·안전 취소는 회복0·사용 횟수 제외입니다.</p>
<p>현재 회복 방식은 정책 v6의 fill_by_progress입니다. 전투 설정의 웨이브 표는3단계 기준이며, 다른 단계는 보스 등장 시간의 비율로 웨이브·종대 시각을 늘리거나 줄입니다. 스킬 선택 카드는 전투 화면 크기를 바꾸지 않고 하단에 겹쳐 표시하며 전투·선택권 누적은 계속됩니다. 보스 처치는100까지, 패배는 정산 시점의 빈 만큼×진행률을 회복합니다. 고정 회복값 recovery_bp와 기본 보스 시간은 fixed 방식의 값이므로 현재 방식의 회복량·단계별 시간으로 쓰지 않습니다. 실제 결과와 중복 지급 검사는 기존 계산·저장 어댑터가 맡습니다.</p>
<p>발란스 자동 진행에서만 컨디션50% 이하이고 배정 몬스가 쉬지 않을 때 자동 사용합니다. 현재 자동 판은 완주를 가정한 시험 계산이며 실제3D 플레이 결과가 아닙니다. 시뮬 하루는86400초로 계산하고 주사위 한 번 또는 오프라인 계산이 끝난 뒤 검사합니다. 여러 날 오프라인 계산은 마지막에 한 번만 검사합니다. 본 게임 수동 플레이에 자동 완주를 적용하지 않습니다.</p>
