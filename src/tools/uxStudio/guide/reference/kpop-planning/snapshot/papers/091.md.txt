# 091 · AI 컷씬 마스터 — 통합 기획

2026-09-22 · 단이 · 검토용 초안 v0.5

이 문서는 제작 방향·화면·기능을 검토하는 기획이다. 제안 기능은 아직 구현되지 않았으며, 기존 시제품의 완성도나 자동 생성 품질을 보장하지 않는다. 짝 HTML은 화면 구성과 컷 선택을 체험하는 기획 시안이다.

## 01. 무엇을 만들 것인가

**준비된 캐릭터·배경·검증된 모션에 시나리오와 참고 영상의 연출 방식을 적용해, 수정하고 게임에서 재생할 수 있는 컷씬을 만드는 도구.**

사용자는 이야기와 원하는 느낌을 지시한다. 단이는 이를 배우의 행동·대사·표정·카메라·시간으로 정리한다. 도구는 허용된 리소스를 찾아 장면을 구성하고 문제를 표시한다. 사용자는 미리보기에서 특정 부분만 고친다.

최종 목표는 2D·3D 모두다. 첫 검증은 현재 자산을 활용하는 **카툰 3D / 2.5D, 두 사람이 서서 대화하는 20~30초**로 제한한다. 카툰 재질과 원근·직교 카메라는 별도 선택이다. 진짜 평면 2D 레이어·스프라이트 실행기는 후속 단계로 둔다.

### 기존 프로젝트와 같은 점 / 다른 점

- 같은 점: 기존 기획서 툴의 문서·HTML 한 쌍과 CSV 목차를 사용한다. 기능을 모듈로 나누고 콘텐츠를 데이터로 관리한다.
- 다른 점: 이 챕터는 게임 제작 도구 연구다. 행보판의 규칙이나 등장인물 설정을 컷씬 도구 전체의 제약으로 적용하지 않는다.
- 모노카피바라의 내부 컷씬 제작 도구는 확인하지 않았다. 동일 구조나 호환성을 전제하지 않는다.

## 02. 사용자 요구와 현재 상태

| ID | 사용자 요구 | 현재 확인 상태 | 다음 기획 |
|---|---|---|---|
| U01 | 리소스를 준비하고 단이에게 콘티 지시 | 정해진 양식 해석·데이터 전달 가능 | 자연어 의도 분석과 장면 초안 생성 |
| U02 | 2D와 3D 모두 지원 | 3D·카툰 2.5D·기본 이미지 모드 | 공통 장면 데이터 + 표현 방식별 실행기 |
| U03 | 촬영 화면을 중앙에 크게 | 시제품 적용 | 결과 화면 우선 배치 유지 |
| U04 | 하단 작업 공간 크기 조절·자유 이동 | 분할 크기 조절·휠·가운데 버튼·우클릭 이동 적용 | 화면별 상태 저장·단축키 안내 |
| U05 | 얼굴·전신·다양한 카메라·360도 | 수동 컷 구성과 회전 촬영 시험 | 의미에 맞는 구도 선택·가림 검사 |
| U06 | 두 배우의 대화·색상 구분 | 독립 배우·머리/옷 색 변형 적용 | 화자와 촬영 대상 분리·청자 반응 강화 |
| U07 | 기존 씬을 지우지 않고 종류별 비교 | 장면 목록·버전별 시제품 보존 | 변경 비교·부분 재생성·잠금 보존 |

| U10 | 시나리오에 맞는 동작·대사·연출 | 자동 계획 기능 없음 | 모션 검색·카메라 규칙·대사 타이밍 조합 |
| U11 | 먼저 HTML·MD로 화면과 기능 기획 | 이 문서에서 수행 | 기획 검토 후 범위를 정해 개발 |

현재 편집기는 리소스를 조립·재생하는 시제품이다. 영상 이해 모델, 자동 감독, 음성 생성, 립싱크, Blender 왕복 동기화, Unity/Unreal 내보내기는 아직 연결하지 않았다.

### 다시 반복하지 않을 실패

- 모션 이름이 ‘인사’여도 첫 자세는 웅크림일 수 있다. 원본 VRMA_02의 시작 골반 높이 약 0.32m, 무릎 회전 약 146~155도가 확인됐다. 이 값은 해당 파일 좌표계의 관찰값이며 모든 모델의 기준값이 아니다.
- 전신 동작에서 골반 이동을 빼고 다리 회전만 쓰면 접지와 신체 연결이 깨진다. 전신 모션은 골반·다리를 함께 평가한다.
- 상체 부분 적용은 전신 모션을 자연스럽게 만드는 만능 해법이 아니다. 양발을 디딘 작은 제스처에 한정하고 어깨·가슴·목 연결을 검수한다.
- 카메라 컷마다 모션을 재시작하면 동작이 튄다. 배우·대사·카메라는 공통 시간축을 공유하되 별도 트랙으로 둔다.
- 한두 장면 캡처가 자연스러움의 증거는 아니다. 전체 연속 재생과 동작 진입·종료 구간을 확인한다.
- 브라우저 저장은 PC 전체 동기화가 아니다. 프로젝트 이름·버전·저장 위치를 표시하고 파일 전달 경로를 유지한다.

## 05. 사용 흐름

1. **프로젝트 준비**: 장면 유형·표현 방식·화면 비율·목표 길이·캐릭터와 배경 선택.
2. **참고 영상 등록**: 사용할 10~20초 구간을 지정하고 무엇을 참고할지 선택. 구도 / 리듬 / 동작 / 표정 / 전환을 따로 지정.
3. **분석표 확인**: 원본 시간·관찰 내용·추정 내용·확신 정도를 확인하고 고친다. 음성이 없으면 대사 자동 추출을 비활성화한다.
4. **시나리오 작성**: 누가 누구에게 무엇을 왜 말하는지, 감정 변화와 금지 행동을 입력한다.
5. **리소스 매칭**: 가능한 모션과 연출 패턴을 제안한다. 없는 행동은 ‘필요 자산’으로 표시하며 임의로 다른 동작을 끼우지 않는다.
6. **그림 콘티·애니매틱**: 컷별 그림과 대사·청자 반응·카메라 구도를 먼저 검토하고 시간 흐름을 재생해 확인한다. MD 표와 JSON은 그림과 같은 컷 ID로 연결한다.
7. **장면 조립·검사**: 실행 가능한 데이터로 변환하고 누락·겹침·가림·모션 연결을 검사한다.
8. **재생·부분 수정**: “B가 대답하기 전에 0.5초 기다려”, “A 손짓만 줄여”를 변경 범위와 함께 미리 본다.
9. **버전 저장·게임 전달**: 현재 결과를 별도 버전으로 저장하고 원본·수동 수정·출처를 보존한다.

초기에는 단이가 분석표와 콘티 데이터를 만들고 편집기로 전달한다. 이후 웹 내부 자동 분석 API를 연결한다. 두 방식은 같은 입력·출력 규격을 사용한다.

## 06. 화면 전면 재설계 · 씬 중심 제작 공간

2026-09-22 사용자 요청에 따라 기존 S01~S08 분산 화면 구성을 재설계한다. **실제 툴 구현에 앞서 화면 설계부터 검토한다. 콘티 내용과 그림 제작은 다음 작업이다.** 기존 시제품과 씬은 변경하지 않는다.

[새 화면 설계 전체 화면](http://127.0.0.1:7007/docs/planning/screen-design/index.html)에서 씬 선택, 제작 단계 전환, 빈 컷 카드 배치, 단이 패널 접기, 촬영/작업 영역 높이를 확인할 수 있다. 이것은 실제 제작 도구가 아니라 저장되지 않는 인터랙티브 설계안이다.

[상세 화면 설계 MD](http://127.0.0.1:7007/docs/planning/screen-design/AI_컷씬_마스터_화면설계.md)에 각 화면, 상태 규칙, 그림 콘티 구성, 변경 영향, 저장 구조와 수락 기준을 명시한다.

### 공통 화면 틀

- 최상단: 프로젝트, 저장 위치·연결 상태, 버전.
- 왼쪽: 폴더와 씬 파일. 씬마다 대표 그림·유형·상태를 표시한다.
- 상단: 선택 씬의 7단계 마일스톤. 현재 보고 있는 단계와 실제 작업 상태는 별개다.
- 중앙: 선택 단계의 작업과 결과물. 그림 콘티에서는 컷 그림을, 씬 제작에서는 촬영 화면을 가장 크게 본다.
- 오른쪽: 접을 수 있는 단이 패널. 대상 씬·컷, 지시, 실제 읽은 자료, 변경·검사 기록을 확인한다.

### 화면 체계

| 화면 | 구성 | 이전 기능 대응 |
|---|---|---|
| W00 프로젝트·씬 파일 | 폴더·썸네일·목록·버전·파일 정보 | S01 확장 |
| W01 요청 정리 | 사용자 원문·구조화 요청·가정·미결 | S03의 시나리오 입력 |
| W02 리소스 확인 | 인물·배경·모션·원본 전신 검수 | S05와 리소스 관리 |
| W03 연출자료 검토 | 상세 MD·영상 원본·기법·채택/제외 이유 | S02·S07 통합 |
| W04 그림 콘티 | 시간순 그림 카드·대사·선택 컷 확대·실제 결과 비교 | S03의 콘티 전면 재설계 |
| W05 애니매틱 | 큰 콘티 재생·그림/대사/음성 시간축 | 새 전용 화면 |
| W06 씬 제작 | 큰 촬영 화면·하단 자유 시점 공간·독립 트랙 | S04 유지·재배치 |
| W07 재생 검수·비교 | 이전/현재·전체 재생·문제·결과 저장 | S06 확장 |

S08 AI 작업실은 별도 페이지 대신 모든 제작 단계의 공통 단이 패널로 통합한다. 프로젝트 → 씬 → 컷 → 독립 대사·동작·카메라 트랙의 계층을 유지한다.

### 마일스톤은 씬 파일마다 보존

요청 정리 → 리소스 확인 → 연출자료 검토 → 그림 콘티 → 애니매틱 → 씬 제작 → 재생 검수.

대기·진행 중·검토 필요·완료·막힘·재검토 필요·미확인을 구분한다. 탭 이동이나 파일 존재만으로 완료 처리하지 않는다. 데이터 검사와 실제 재생 검수는 별도로 기록한다. 이전 씬의 상태는 근거 확인 전 ‘미확인’으로 이관한다. 수정된 내용이 영향을 주는 결과만 재검토 표시하고 이전 정상 버전은 보존한다.

### 그림 콘티와 편집 화면

컷마다 그림·컷 ID·시간·구도·화자/대사·행동·상태를 한 카드에 묶는다. 이동이 큰 컷은 선택 상세에서 시작/중간/끝 프레임을 본다. 실제 3D 캡처와 참고/컨셉 이미지를 구분하고 원본 씬 리비전과 연결한다. 빈 컷은 임의 그림이나 대사를 만들지 않는다.

촬영 편집은 중앙 큰 촬영 화면, 하단 자유 시점 작업 캔버스, 최하단 시간축이다. 분할 크기를 조절하고 촬영 카메라와 탐색 카메라를 분리한다. 휠 확대·가운데 버튼 이동·우클릭 회전·WASD/QE·F 집중은 실제 편집기 연결 때 적용한다. 입력 필드에서는 장면 단축키가 작동하지 않는다.

## 08. 참고 영상은 어떻게 적용하나

**관찰 → 추정 → 일반화 → 우리 장면에 맞춤 → 검증**으로 나눈다. 영상 하나에서 보이지 않는 3D 공간과 관절을 정확히 복원한다고 전제하지 않는다.

| 단계 | 수행 내용 | 사람이 확인할 것 |
|---|---|---|
| 자르기 | 사용자가 참고할 구간 지정·컷 경계 후보 찾기 | 게임 UI·선택 대기·로딩 화면 제외 |
| 읽기 | 인물 식별·화면 점유·구도·동작·전환·오디오 유무 | 가려진 행동은 ‘미확인’ 처리 |
| 기록 | 원본 시간·표본 프레임·관찰 문장·추정·확신 정도 | 정확한 렌즈/3D 좌표라고 단정하지 않음 |
| 패턴화 | A/B를 화자/청자/전경 배우로 치환 | 특정 대사·캐릭터를 그대로 복사하지 않음 |
| 적용 | 대사 길이·배우 크기·거리·배경에 맞춰 다시 계산 | 영상의 시간을 새 대사에 무조건 늘려 맞추지 않음 |
| 검사 | 좌우 관계·가림·시선·행동의 의미 확인 | 부적합하면 분석/콘티 단계로 돌아감 |

예: ‘A가 말하지만 B의 반응을 먼저 보여 준 뒤 A의 어깨 너머로 전환’이라는 규칙을 저장한다. 실제 카메라 좌표는 우리 두 배우의 머리·어깨 위치에서 계산한다.

사용자가 제공한 두 영상의 이전 분석은 표본 관찰이며 정밀 컷 경계표가 아니다. 첫 실험은 영상 2의 약 15~26초를 후보로 삼고 실제 컷 경계를 다시 확인한다. 음성이 없으므로 화면 행동과 카메라만 참고하고 새 대사는 별도 입력한다.

## 09. 모션·카메라·대사 결정 규칙

### 모션

모션 카드에 시작 자세 / 끝 자세 / 사용 구간 / 전신·부분 / 이동량 / 접지 / 감정 / 강도 / 시선 제약 / 모델 검수 버전 / 출처를 기록한다. ‘검수 전·사용 가능·조건부·사용 금지’를 구분한다.

대화 기본은 서 있기·호흡·듣기다. 의미 있는 단어·감정 변화에만 손짓을 넣는다. 화자와 청자가 동시에 큰 제스처를 하지 않는다. 동작 진입·유지·종료를 합쳐 선택하고, 속도를 과도하게 늦춰 길이를 맞추지 않는다. 부족한 동작은 기본 대기와 누락 표시로 남기거나 Blender 제작 작업으로 보낸다.

발 접지는 샘플 사이 발 위치와 바닥 거리·미끄러짐을 측정한다. 부분 제스처는 안정된 하체 위에 적용 가능한 것으로 검수된 것만 허용한다. IK는 손·발 목표 위치를 맞추는 보정이며 자연스러움의 자동 보장은 아니다.

### 카메라

패턴 후보는 전신 투샷 / 미디엄 투샷 / 양방향 어깨 너머 / 화자 클로즈업 / 청자 반응 / 느린 접근 / 마무리 후퇴다. 360도는 별도 강조 패턴으로 유지한다.

AI는 의도에 맞는 패턴과 촬영 대상을 고른다. 규칙 모듈이 머리·어깨 위치, 신장, 거리, 화면 비율로 카메라를 계산한다. 얼굴 가림·클리핑·안전 영역·배우 사이 선의 어느 쪽에서 찍는지 확인한다. 같은 얼굴에 연속으로 비슷한 크기의 컷이 이어질 때 경고한다.

### 대사·음성·표정

화자와 촬영 대상은 다를 수 있다. 자막은 컷과 분리된 독립 구간이다. 무음 반응과 대답 전 대기 시간을 명시한다. 음성 미지정 시 읽기 시간은 임시 추정이라고 표시한다. 실제 음성이 생기면 길이를 확정하고 후속 반응·컷을 재검토한다. 감정 표정과 발음 입 모양은 별도 트랙으로 혼합한다.

## 10. 제작 구조와 역할

| 모듈 | 책임 | 경계 |
|---|---|---|
| 웹 편집기 | 입력·분석 확인·콘티·공간·시간축·변경 비교 | 모델 생성이나 Blender 연산을 브라우저 기능으로 가장하지 않음 |
| 리소스 목록 | 파일 버전·태그·검수 구간·호환성 | 자연어에서 임의 파일명을 생성하지 않음 |
| 참고 분석 모듈 | 컷 후보·관찰·근거·확신 정도 | 정확한 3D 복원과 분리 |
| 연출 계획 모듈 | 대본 의미·반응·패턴·모션 후보 선택 | 구조화 데이터만 출력; 임의 실행 코드 금지 |
| 장면 조립 모듈 | 시간·좌표·동작 연결 계산 | 동일 입력과 선택값이면 동일 실행 데이터 |
| 검사 모듈 | 데이터 제약·리소스·시각·접지 검사 | 사람의 감정 연기 판단을 대신했다고 주장하지 않음 |
| Blender 작업 도구 | 모델 정리·리타기팅·접지/전환 보정·베이크 | 로컬 작업 큐, 진행 상태·실패 이유·취소 제공 |
| 실행 어댑터 | Three.js 우선; 추후 Unity/Unreal·평면 2D | 공통 규격을 각 엔진 기능으로 변환 |
| 저장 모듈 | 프로젝트·변경 기록·파일 참조·복구 | 로컬 저장과 공유 저장의 상태 구분 |

제안 구성: TypeScript 기반 웹 편집기·규격 검사·장면 조립 / Three.js + VRM·VRMA 미리보기 / Python + Blender 배치 작업 / 영상 전처리 도구 / 필요 시 영상 이해·언어·음성 API. 특정 AI 공급자·모델·비용은 아직 정하지 않았다.

외부 분석은 작은 서비스 인터페이스로 분리한다. 프로젝트마다 보낼 자료·분석 구간을 표시하고 키는 서버 측에서 관리한다. 실패·시간 초과·취소 시 현재 프로젝트는 유지한다. 업로드하지 않는 로컬 분석·단이 수동 분석도 같은 규격으로 사용한다.

## 11. 데이터 규격 초안

콘텐츠와 선택 규칙은 JSON·CSV에서 관리한다. 애니메이션·카메라 실행 코드는 이를 읽는 공통 모듈로 둔다. 다음은 제안 규격이며 현재 프로젝트의 version:1 형식과 같지 않다.

| 데이터 | 주요 필드 | 연결 |
|---|---|---|
| Asset | id, version, kind, uri, contentHash, rig, scale, credit, rightsNote | 배우/모션에서 참조 |
| MotionSegment | id, sourceId, in/out, start/endPose, rootMode, footContact, mask, tags, review | 원본의 검수된 구간 |
| ReferenceShot | id, videoId, in/out, observations, estimates, evidence, confidence | 연출 패턴의 근거 |
| DirectionPattern | id, roles, intent, cameraRule, timingRule, constraints, sourceRefs | 특정 인물과 분리 |
| ScenarioBeat | id, speaker, listener, text, intent, emotion, pause, constraints | 이야기의 한 의미 단위 |
| ScenePlan | id, beats, actors, chosenPatterns, assetVersions, unresolved | 사람이 확인하는 초안 |
| Sequence | schemaVersion, fps, duration, cameraTrack, actorTracks, dialogueTrack, events | 실제 재생 데이터 |
| RevisionPatch | baseRevision, targetIds, changedFields, locks, reason, provenance | 부분 수정·충돌 검사 |

시간은 실행 단계에서 정수 프레임을 기준으로 한다. 화면에는 초·타임코드를 표시한다. 원본 영상의 시간과 우리 시퀀스의 시간을 별도로 저장한다. 카메라 컷과 모션 구간의 ID를 분리한다.

```json
{
  "schemaVersion": 2,
  "status": "proposal",
  "fps": 24,
  "beat": {"id": "beat-02", "speaker": "A", "listener": "B", "text": "조금 기다렸어.", "intent": "welcome"},
  "camera": {"patternId": "ots-listener-to-speaker", "subject": "A", "foreground": "B", "startFrame": 72, "endFrame": 168},
  "gesture": {"actorId": "A", "segmentId": "greeting-standing-reviewed", "startFrame": 80, "endFrame": 144},
  "locks": ["actors.A.position"],
  "provenance": {"referenceShotId": "ref-02-shot-04", "review": "required"}
}
```

이 예제 ID는 설계 설명용이다. 실제 리소스가 등록되어 있다는 뜻이 아니다. version:1 프로젝트는 원본을 백업한 뒤 변환하고 검증한다. 마이그레이션 실패 시 덮어쓰지 않는다.

## 12. 부분 수정·검사·저장 규칙

- 전체 재생성과 선택 영역 수정은 별도 동작. 기본은 선택한 컷/배우/트랙만 수정.
- 변경 전에 기준 버전과 수정할 필드를 고정한다. 원본과 결과의 차이를 보여 주고 잠긴 필드 변경은 적용하지 않는다.
- 대사 길이처럼 다른 트랙에 영향을 주는 변경은 영향받는 구간을 함께 표시한다. 후속 컷 이동을 숨기지 않는다.
- 자산 교체는 같은 ID의 새 버전으로 기록한다. 다른 브라우저에서 없는 파일은 다시 연결한다.
- 프로젝트 저장에는 장면·버전·출처·검수 정보 포함. 게임용 데이터에는 실행에 필요한 정보와 정확한 자산 참조만 포함.
- 초안/검사 실패/검토 필요/검수 통과를 구분한다. 검사 통과가 연기 품질의 최종 승인과 같지는 않다.
- 외부 서비스 실패 시 자산을 만든 것처럼 표시하지 않는다. 준비됨·처리 중·실패·취소를 구분한다.

## 13. 첫 제작 범위와 개발 순서

목표: 동일한 두 캐릭터·같은 방·3~5컷·20~30초 대화 한 장면으로 ‘참고 영상 → 분석 → 콘티 → 재생 → 한 부분 수정’을 끝까지 연결한다. 이전 8컷 씬은 비교 기준으로 보존한다.

| 단계 | 결과물 | 통과 후 다음 단계 |
|---|---|---|
| P0-A 기획 검토 | 이 MD·HTML, 화면 8개, 기능 우선순위, 데이터 초안 | 첫 사용 흐름과 범위 채택 |
| P0-B 모션 기반 정리 | 선 대기·듣기·작은 설명·인사·끄덕임 5가지 검수 | 전신 정면/측면 연속 재생에서 튐·접지 확인 |
| P0-C 참고 분석 실험 | 사용자 영상 한 구간의 근거 포함 컷표·패턴 | 관찰과 추정 구분, 사람이 컷 경계 수정 가능 |
| P0-D 장면 조립 | 대본→패턴·모션 선택→3~5컷 재생 | 없는 자산 차단, 컷 사이 배우 시간 유지 |
| P0-E 수정·보존 | 한 부분 변경·잠금·이전 버전 비교 | 다른 컷/수동 수정이 바뀌지 않음 |
| P1 제작 연결 | Blender 교환, 음성·표정·게임 이벤트 | 실제 자산 왕복과 종료/스킵/중단 복귀 확인 |
| P2 표현 확장 | 평면 2D·다인물·걷기·고급 카메라·출력 | 각 기능별 지원 범위와 품질 기준 검증 |

일정은 투입 인력·자산 준비·분석 서비스 실험 뒤 산정한다. 자동 감독부터 크게 만들기보다 검수된 동작과 작은 장면을 먼저 연결한다.

### 첫 버전에서 하지 않을 것

단일 그림에서 고품질 캐릭터 자동 완성, 임의의 게임 영상에서 정확한 전신·카메라 완전 복원, 전투·군중·복잡한 접촉 연기, 모든 엔진 원클릭 변환, 실시간 Blender 양방향 동기화. 이 항목은 별도 연구가 필요하다.

## 14. 검증 시나리오와 완료 기준

| 검사 | 조건 | 기대 결과 |
|---|---|---|
| 잘못된 인사 선택 | 웅크림 시작 모션에 선 인사 요청 | 자동 제외 또는 검토 경고·검수된 구간 제안 |
| 모션 연속성 | 동작 중 카메라 컷 변경 | 동작 시간 유지·시작 자세로 튀지 않음 |
| 접지와 몸 연결 | 손짓 전/중/후·역방향 스크럽 | 양발 위치·골반·상체 연결 확인, 차이가 나면 실패 기록 |
| 무음 참고 영상 | 오디오 없는 사용자 영상 | 가짜 대사/음성 생성 없이 무음 표시 |
| 카메라 가림 | 전경 배우가 얼굴을 가림 | 문제 구간 표시·각도/거리 대안 |
| 자산 부족 | 걷기 없는 모델에 함께 걷기 요청 | 누락 행동 표시·대기 대안은 명시적으로 제안 |
| 부분 수정 | B 반응만 0.5초 지연 | 변경 영향 표시, 잠긴 A/카메라는 유지 |
| 저장·복원 | 내보내기 후 다른 브라우저에서 가져오기 | 장면 목록·배우 색·트랙·자산 버전 동일 |
| 게임 연결 | 완료·스킵·중단 각각 실행 | 카메라·입력·UI 복구, 완료 이벤트 중복 없음 |
| 영상 응용 | 같은 연출 패턴에 다른 대사 길이 | 좌표 복사가 아니라 구도·반응 순서 재계산 |

정량 기준 초안: 데이터 유효성 100%, 없는 자산 참조 0건, 잠금 필드 변경 0건, 동일 입력의 조립 결과 일치. 발 미끄러짐·가림 허용치·성능 목표는 실제 모델과 대상 기기로 측정해 정한다. 첫 시제품은 데스크톱 30fps 이상을 측정 목표로 제안하되 달성했다고 간주하지 않는다.

## 17. 영상 자료와 연출 지식을 제작 때마다 조회하는 구조

2026-09-22 추가 요구: 여러 녹화 영상을 자료로 제공하고, AI가 지시마다 관련 영상·연출 이론·프롬프트를 검토한 다음 편집기를 직접 조작한다. 씬은 개별 파일로 관리하며 기존 씬을 보존한다.

첫 구현은 모델 재학습 대신 **프로젝트에 영구 저장한 자료를 검색하고 필요한 내용을 제작 입력에 포함하는 방식**이다. 대화 기억만으로 처리하지 않는다. 프롬프트는 원본·관찰·사용 조건·검증 기준이 연결된 버전 있는 자료로 관리한다.

### 자료 등록과 검수

1. 원본 파일을 변경하지 않고 영상 ID·파일 해시·길이·오디오 유무·출처를 등록한다.
2. 지정 구간을 우선 분석한다. 구간 미지정이면 컷 후보와 접촉 시트를 만들고 참고할 구간을 고른다.
3. 관찰 사실, 의도 추정, 미확인 사항을 분리한다. 배우·구도·카메라 이동·편집·몸동작을 구간별로 기록한다.
4. 인물 이름을 화자·청자·제삼자 역할로 바꾸고 적용 조건·피해야 할 상황을 적는다.
5. 원본 구간과 분석을 함께 검토하여 초안 → 검수 완료 또는 보류로 저장한다. 미검수 자료는 자동 제작의 확정 근거로 사용하지 않는다.
6. 장면에 적용한 결과와 사용자 수정 이유를 연결한다. 한 번의 수정은 해당 씬에만 적용하고, 프로젝트 기본 규칙 채택은 별도 기록한다.

### 지시마다 실행할 순서

지시 → 현재 씬·잠금·자산 확인 → 관련 자료 검색 → 후보 적합성 비교 → 콘티와 근거 기록 → 편집 명령 실행 → 연속 재생 검사 → 부분 수정·버전 저장.

인원·대화 목적·감정 변화·정적/이동·시간·지원 모션으로 우선 거른다. 그 뒤 유사한 연출을 비교한다. 모든 영상을 매번 다시 분석하지 않고 관련 카드와 원본 구간을 조회한다. 근거가 모자라면 ‘일반 규칙에 따른 제안’으로 표시하고 영상에서 확인한 것으로 꾸미지 않는다.

| 지식 종류 | 보관 내용 | 채택 기준 |
|---|---|---|
| 영상 관찰 | 원본 ID·시작/끝·프레임·실제 보이는 행동 | 관찰과 추정 분리 |
| 연출 방법론 | 구도·시선·공간 관계·반응 컷·리듬 원칙 | 출처와 적용 조건 확인; 절대 규칙으로 고정하지 않음 |
| 상황별 패턴 | 1인 독백 / 2인 대화 / 3인 대화 / 관계·감정 | 역할 수·의도·지원 동작이 맞음 |
| 제작 프롬프트 | 역할·대사·길이·자산·제약을 넣는 양식 | 구조화된 콘티와 선택 이유 출력 |
| 프로젝트 선호 | 큰 제스처 제외, 반응 컷 선호 등 | 사용자 채택 범위와 날짜 기록 |

1인 독백은 감정 변화·시선 대상·침묵의 길이, 2인 대화는 화자/청자·반응·좌우 관계, 3인 대화는 발언자와 반응 대상·제삼자의 위치·시선 연결을 각각 기록한다. 처음부터 세 분류의 자료를 받을 수 있지만 실제 조립 품질 검증은 2인 → 1인 → 3인 순으로 확장한다.

### 연출 카드와 프롬프트 규격

ReferenceVideo: id, uri, hash, duration, audio, source, notes.
ReferenceSegment: id, videoId, inSeconds, outSeconds, evidenceFrames, observations, estimates, unknowns, reviewStatus.
DirectionRecipe: id, version, situation, roleCount, intent, applicableWhen, avoidWhen, shotRules, actingRules, requiredCapabilities, referenceSegmentIds, theorySourceIds, promptTemplate, validationRules, reviewStatus.
GenerationRun: id, instruction, baseSceneRevision, retrievedRecipeVersions, selectedReasons, rejectedReasons, assetVersions, promptVersion, patch, validationResults, resultingRevision.

제작 프롬프트는 다음 양식을 기준으로 한다:

```text
목표: {상황과 감정 변화}
배우 역할: {화자·청자·제삼자}
대사 및 길이: {대본}, {목표 길이}
참고: {검수된 연출 카드 ID·버전}, {원본 구간}, {방법론 출처}
사용 가능한 리소스: {검수 모션·표정·배경 ID와 버전}
보존 조건: {잠금 필드·기존 컷·금지 행동}
작업: 참고 기법의 적합성을 먼저 설명하고, 우리 공간에 맞는 콘티와 편집 명령을 작성한다.
출력: 컷·시간·촬영 대상·화자·청자 반응·모션 ID·대사·근거·미해결 항목.
검사: 발 접지, 몸 연결, 시선, 가림, 동작 연속성, 잠금 보존.
자산이 없으면 없는 동작을 구현한 것으로 표시하지 않는다.
```

## 18. 씬 파일 관리와 AI 직접 편집

화면 번호 S01~S08은 이전 설계 이력이다. 최신 배치와 통합 관계는 6절의 W00~W07 및 상세 화면 설계 MD를 따른다. 아래 저장 규격·편집 명령은 유지한다.

### S01 확장: 씬 파일 탐색기

왼쪽 프로젝트·폴더 트리, 중앙 썸네일/목록, 오른쪽 선택 파일 정보. 더블클릭으로 편집 탭을 연다. 새 씬·복제·이름 변경·이동·검색·휴지통·복원이 필요하다. 인원·태그·수정일·검사 상태·누락 자산으로 찾는다.

같은 씬의 수정 이력은 리비전, 다른 연출 시안은 씬 복제본으로 관리한다. 씬 ID는 이름이나 폴더를 바꿔도 유지한다. 자산은 프로젝트 공용 목록을 참조하며 씬마다 모델을 중복 복사하지 않는다.

```text
project/
  project.json              프로젝트 ID·규격 버전
  folders.json              폴더 ID·부모 관계·표시 이름
  scenes/<sceneId>.scene.json
  assets/manifest.json      모델·모션·배경의 ID·버전·파일 참조
  references/videos.json    원본 영상 목록
  references/segments/      구간 분석과 근거 프레임 참조
  direction/recipes/        검수된 연출 카드·프롬프트
  direction/theory/         방법론과 출처
  revisions/<sceneId>/      변경 기록·복원용 스냅샷
  runs/                     제작별 자료 조회·선택·검사 기록
```

이것은 목표 저장 규격이다. 첫 저장 어댑터는 로컬 작업 서비스가 지정 프로젝트 폴더만 읽고 쓴다. 웹 화면은 API로 접근한다. 호스팅 환경에서는 동일 인터페이스의 서버 저장 어댑터가 필요하며, 기존 IndexedDB를 다른 창·기기에 공유 저장소인 것처럼 표시하지 않는다. 저장은 기준 리비전 검사 → 임시 파일 → 원자적 교체 순서로 처리한다. 오래된 창의 저장은 충돌을 알리고 최신 씬을 덮어쓰지 않는다. 원본 version:1 프로젝트와 기존 5종 씬은 백업 후 개별 파일로 변환한다.

### S07 신규: 연출 자료실·샘플 비교

왼쪽 인원/상황/감정/구도 필터와 영상 목록, 중앙 원본 플레이어·구간 표시·우리 씬 비교, 오른쪽 분석·적용 조건·프롬프트·근거. 원본 시간과 우리 씬 시간을 각각 표시하고 대응 컷으로 이동한다. 파일이 없으면 재연결 상태를 표시한다. 프롬프트를 고쳐도 원본 분석은 보존하고 새 카드 버전을 만든다.

### S08 신규: AI 제작 작업실

왼쪽 씬 파일과 현재 선택 범위, 중앙 지시·진행 상태·결과 미리보기, 오른쪽 검토한 자료·선택 이유·변경 내역·문제 목록. 자료 선택/제외, 카메라만 재구성, 동작만 수정, 선택 구간 재생, 되돌리기를 제공한다. S04 장면 편집기에서도 같은 작업실을 패널로 연다.

AI는 화면 좌표를 임의로 클릭하는 방식에 의존하지 않고 편집기 명령 인터페이스를 사용한다. readScene, searchReferences, getReferenceSegment, listReviewedMotions, proposePatch, validatePatch, applyPatch, renderPreview, inspectSequence, undoRevision이 제안 명령이다. 도구 입력·결과는 구조화 데이터로 검증한다.

applyPatch는 baseRevision·targetIds·locks를 확인하고 하나의 트랜잭션으로 적용한다. 잠금 위반이나 충돌은 전체 적용을 중단한다. 정상적인 되돌릴 수 있는 편집은 사용자의 제작 지시에 따라 실행하고, 실행 전후 차이를 기록한다. 자료 분석이나 검사 실패를 제작 성공으로 표시하지 않는다. 취소 시 마지막 유효 리비전으로 돌아갈 수 있어야 한다.

## 19. 사용자와 단이의 준비 목록

### 사용자: 처음에는 이 정도면 시작 가능

| 준비물 | 처음 전달할 양 | 설명 |
|---|---|---|
| 참고 녹화 영상 | 우선 3~5개 권장; 더 많아도 등록 가능 | 파일명은 그대로 가능. 원본을 제공하면 단이가 ID와 목록을 정리 |
| 좋아하는 구간 | 영상마다 시간 또는 간단한 설명 | 예: 12~20초 상대 반응 컷이 좋다. 모르면 단이가 후보 선정 |
| 첫 장면의 상황 | 2~3문장 | 누가 누구에게 무엇을 말하며 감정이 어떻게 변하는지 |
| 대사 | 있으면 제공, 없으면 단이가 초안 | 처음 20~30초 분량을 목표로 조정 |
| 마음에 드는/싫은 점 | 각 한두 문장 | 예: 작은 손짓 선호, 발 들기·과한 몸 흔들기 제외 |

녹화는 가능하면 원래 화면 비율·해상도와 연속 흐름을 유지한다. 전환 전후 여유를 포함하고 게임 UI는 남아 있어도 된다. 음성은 있으면 타이밍 분석에 도움이 되지만 필수는 아니다. 개인 알림 등 무관한 화면은 제외한다. 모든 영상을 미리 편집하거나 전문 프롬프트를 작성할 필요는 없다.

### 이미 있는 것으로 시작할 것

플로우 캐릭터와 색상 변형 두 배우, 기존 배경, 공식 모션 7종, 기존 씬 5종, 제공한 대화 영상 2개와 연구 기록을 재사용한다. 새 모델 구매는 첫 실험의 필수 준비가 아니다. 단이는 실제 파일 존재·버전·호환성과 검수 상태를 구현 전에 다시 확인한다.

### 단이가 담당할 준비와 산출물

- 영상 목록·시간 코드·접촉 시트·구간별 분석 카드 작성.
- 관찰·추정 분리와 방법론 출처 조사, 적용 조건을 갖춘 연출 프롬프트 작성.
- 공식 모션 7종의 대화용 사용 구간 검수, 부족한 동작의 Blender 보정 작업 목록 작성.
- 개별 씬 저장 규격·자료 검색·AI 편집 명령 연결, 기존 씬 보존과 복원 기능 구현.
- 첫 대화 씬 제작 후 원본 참고 구간·선택 이유·결과·실패 항목을 함께 기록.

사용자는 선호와 결과를 판단하고, 단이는 분석·구조화·구현·검증을 담당한다. 새 모션 제작과 유료/외부 서비스 도입이 필요해지면 필요한 범위와 이유를 구체화한다.

## 20. 실행 준비와 첫 완료 기준

| 순서 | 작업 | 산출물 | 완료 조건 |
|---|---|---|---|

| 3 | 씬 파일 저장과 자료 검색 연결 | 파일 탐색기·자료실·조회 기록 | 다른 창에서 최신 리비전 조회, 충돌 처리 |

| 7 | 자료와 상황 확장 | 1인 독백·3인 대화·추가 패턴 | 각 상황별 검수 후 자동 선택에 편입 |

추가 검증: 관련 자료가 없는 지시, 검수 취소된 카드, 원본 파일 누락, 같은 씬을 두 창에서 수정, 대사 길이 변경, 3인 요청에 2인 패턴만 있는 경우를 각각 시험한다. 자료가 없으면 근거 없음 또는 지원 부족을 표시하며 검토한 척하지 않는다.

이번 준비 단계의 완료물은 업데이트한 MD·HTML, 영상 제출 양식, 분석 카드 양식이다. 자동 분석·검색·직접 편집 기능의 연결은 다음 구현 단계이며 아직 완료된 기능으로 표시하지 않는다.

여기서 학습자료는 AI가 작업 전에 읽고 검색할 지식 파일을 뜻한다. 모델 자체를 재학습한 상태는 아니다. 출처 요약과 아래의 우리 프로젝트용 조건·프롬프트·검사 제안을 구분한다. 모든 카드는 실제 씬 적용 검수 전이다.

## 출처와 확인 범위

- **Y01 · [Yale · Cinematography](https://filmanalysis.yale.edu/cinematography/)** — 교육 자료 본문. 샷 크기·시점·팬/틸트·초점 이동을 구별한다. 동일 구도도 맥락에 따라 의미가 달라진다.
- **Y02 · [Yale · Editing](https://filmanalysis.yale.edu/editing/)** — 교육 자료 본문. 공간과 동작의 연속성을 위한 편집, 시선 연결과 샷의 관계를 다룬다.
- **S01 · [StudioBinder · 180 degree rule](https://www.studiobinder.com/blog/what-is-the-180-degree-rule-film/)** — 제작사 교육 자료. 대화 축의 한쪽에서 촬영해 좌우 관계를 유지한다. 축을 바꾸는 연출에는 관객이 공간 변화를 이해할 단서가 필요하다.
- **S02 · [StudioBinder · Blocking and staging](https://www.studiobinder.com/blog/blocking-and-staging-scenes/)** — 제작사 분석 자료. 배우 배치와 움직임, 카메라를 함께 설계해 관계와 주목 대상을 전달한다.
- **S03 · [StudioBinder · Shot reverse shot](https://www.studiobinder.com/blog/shot-reverse-shot-cutaways-coverage/)** — 제작사 교육 자료. 대화 촬영은 발언자의 교대뿐 아니라 청자의 반응과 편집할 구도의 확보를 포함한다.
- **S04 · [StudioBinder · Arc shot](https://www.studiobinder.com/camera-shots/camera-movements/arc-shot/)** — 제작사 교육 자료. 아크 샷은 피사체를 중심으로 카메라 위치가 원호를 그리며 움직이는 촬영이다.
- **A01 · [Adobe · Camera shots and angles](https://www.adobe.com/creativecloud/video/production/cinematography/camera-shots-and-angles.html)** — 제작 도구 공식 교육. 샷 크기, 높이·각도, 주관 시점, 이동 촬영을 구분해 목적에 맞게 선택한다.
- **A02 · [Adobe · J cuts and L cuts](https://www.adobe.com/uk/creativecloud/video/discover/j-cut-and-l-cut.html)** — 제작 도구 공식 교육. J컷은 다음 소리를 화면보다 먼저, L컷은 앞 소리를 다음 화면까지 이어 붙인다. 대화의 반응과 흐름을 설계하는 데 쓴다.
- **E01 · [Epic · Cine Camera Actor](https://dev.epicgames.com/documentation/en-us/unreal-engine/cinematic-cameras-in-unreal-engine)** — 엔진 공식 문서. 필름백·렌즈·초점·추적과 후처리 설정을 제공한다. 영화 용어를 실제 카메라 파라미터로 구체화할 때 참고한다.
- **B01 · [Blender · Cameras (개발 문서)](https://docs.blender.org/UATEST/manual/en/dev/render/cameras.html)** — 공식 검색 본문 발췌 확인. 원근/직교, 화각과 초점 거리, 초점 대상과 심도를 설명한다. stable/4.5 본문 조회는 실패했으며 설치 버전 API는 구현 시 확인해야 한다.
- **R01 · [Cine-AI · Evin et al. (2022)](https://arxiv.org/abs/2208.05701)** — 초록과 본문 3·4·7절 확인. 기법 선택·배치·가시성 검사와 일반화 한계를 상세 MD D10에 정리했다. 구현 재현은 수행하지 않았다.
- **R02 · [FilmAgent · 연구팀 프로젝트](https://filmagent.github.io/)** — 연구팀 개요 확인. 준비된 3D 공간에서 대본·연기·촬영을 나누고 중간 결과를 반복 검토하는 구조다. 우리 리그에서 품질이 보장된다는 의미는 아니다.

AAAI의 카메라 계획 관련 두 논문은 검색 초록만 확인되고 본문 요청은 실패해 핵심 규칙 근거로 편입하지 않았다. Blender stable 및 4.5 페이지도 조회 실패하여 공식 개발 문서의 검색 본문 범위만 사용했다. 연구 논문의 실험 결과를 우리 모델과 에디터의 성능으로 옮겨 주장하지 않는다.

## 상황별 제작 양식

고정된 정답이 아니라 지시와 자산에 맞게 바꿀 기본안이다. 아래 순서·동작 선택은 단이의 설계 제안이다.

### P01 · 1인 독백·결심

- 의도: 주변을 보던 인물이 결심하는 감정 변화
- 기법: C01, C03, C04, C11, C09

- 필요한 기능: 정적 대기·시선·미세 표정
- 확인: 혼잣말의 대상과 내면 독백/실제 발화 구분

### P02 · 2인 차분한 인사

- 의도: 서서 짧게 인사하고 반가움을 나누는 대화
- 기법: C01, C05, C06, C07, C10
- 기본 순서: 투샷 → A 인사 → B 반응 → B 대답 → 함께 마무리
- 필요한 기능: 선 대기·검수된 작은 인사·듣기
- 확인: 양발 접지, 과한 손짓 제외

### P03 · 2인 숨기는 대화

- 의도: 한 사람은 질문하고 상대는 망설이는 대화
- 기법: C05, C06, C04, C09, C20

- 필요한 기능: 대기·시선 피하기 또는 지원 가능한 대안
- 확인: 거짓말을 특정 제스처로 확정하지 않음

### P04 · 3인 질문·중재

- 의도: A가 B에게 질문하고 C가 중재하는 대화
- 기법: C21, C07, C08, C06
- 기본 순서: 3인 전체 → A 질문 → B 반응 → C 개입 → 관계 재소개
- 필요한 기능: 배우 3명·대기·듣기·작은 설명
- 확인: 화자/수신자/반응대상/제삼자를 매 비트 기록

### P05 · 3인 둘과 하나

- 의도: 두 사람과 한 사람의 의견이 갈리는 대화
- 기법: C21, C22, C04
- 기본 순서: 전체 관계 → 두 사람 구도 → 한 사람 반응 → 재전체
- 필요한 기능: 배우 3명·배치·시선 지원
- 확인: 반응 대상의 감정이 바뀔 때만 컷 강화

### P06 · 회전 강조 후 대화 복귀

- 의도: 사용자가 회전 연출을 요청한 강조 순간
- 기법: C15, C08, C03
- 기본 순서: 기준 구도 → 연속 회전 → 새 관계 확인 → 안정된 대화 구도
- 필요한 기능: 전 경로가 갖춰진 3D 배경·충돌 검사
- 확인: 360도를 필수 기본값으로 고정하지 않음

## AI가 매 지시 때 읽을 제작 절차

1. 지시에서 인원, 감정 변화, 대사 길이, 이동 여부, 원하는 구도와 잠금을 추출한다.
2. 인원·필수 리소스·검수 상태로 후보를 거른다. 사용자 영상 카드와 이론 카드를 따로 조회한다.
3. 선택한 카드 ID·버전·적합 이유와 제외 이유를 남긴다. 이론 카드만 있으면 ‘영상 근거 없음’으로 표시한다.
4. 대사를 의미 단위로 나누고 화자, 수신자, 반응 대상을 지정한다. 대사마다 무조건 컷을 바꾸지 않는다.
5. 규칙으로 카메라 후보를 계산하고 가림·축·시선·배우 크기·경로 충돌을 검사한다. 감정 적합성은 별도 화면 검토한다.
6. 변경안을 편집기에 적용하고 전체 구간을 연속 재생한다. 검사 실패는 대체안과 함께 남기며 성공으로 처리하지 않는다.
7. 사용자 수정과 검수 결과를 기록한다. 검수한 모델·공간·기법 범위만 다음 자동 선택에 활용한다.

## 수치와 구현의 경계

30도, 일정한 클로즈업 비율, 몇 초마다 컷 같은 값은 절대 법칙으로 고정하지 않는다. 인물 신장·렌즈·화면비·상황에 따라 검사 기준을 조정한다. 렌즈 초점 거리만으로 최종 원근감을 복제할 수 없으므로 위치·센서·투영·화면비를 함께 기록한다.

360도는 제자리에서 방향만 도는 팬과 인물 둘레로 위치가 움직이는 아크를 구분한다. 직교 카메라에서는 앞뒤 이동만으로 대상 화면 크기가 바뀌지 않아 스케일을 따로 관리해야 한다. Blender와 웹 실행기의 심도·카툰 재질 결과는 실제 렌더 비교가 필요하다.

## 22. AI 컷씬 마스터 · 지시에서 콘티까지

최신 화면 설계는 6절을 따른다. 아래 로컬 준비 도구는 텍스트 콘티/JSON 규격 v0.1이다. 컷별 그림·애니매틱·마일스톤 UI는 상세 설계에 추가되었으며 이 도구에 구현된 것으로 취급하지 않는다.


버전 0.1 · 2026-09-22 · 제작 절차와 콘티 규격

사용자는 리소스와 원하는 이야기를 지시한다. 단이는 현재 리소스를 확인하고, 관련 지식을 읽고, 연출의 이유가 있는 콘티를 작성한다. 검사한 콘티를 에디터에 적용하고 재생 결과를 확인하는 것이 목표다.

이번 버전에서 실제 동작하는 것은 **리소스 파일 확인·해시 기록 → 관련 MD 본문 묶기 → AI 작성 입력 생성 → 작성한 콘티 데이터 검사 → 같은 데이터의 MD 표 출력**이다. 자연어 해석·콘티 창작은 단이가 수행한다. 에디터 적용·Blender 실행·재생 검사 어댑터는 아직 연결하지 않았다.

## 사용자의 지시 형태

전문 양식을 쓰실 필요 없이 아래처럼 말하면 된다.

> 플로우와 파란색 변형을 써서 두 사람이 연습실에서 만나 대화하는 장면을 만들어줘. A가 반갑게 인사하고 B는 조금 망설이다 대답해. 25초 정도, 작은 손짓만 하고 마지막은 B 얼굴로 마무리해.

필수는 사용하려는 리소스의 식별과 장면의 의도다. 리소스 이름이 모호하면 현재 목록에서 후보를 확인한다. 배우 수·시간·마무리·원치 않는 행동이 생략되면 기존 프로젝트 기본값과 문맥으로 초안을 만들고 가정으로 기록한다. 존재하지 않는 자산을 추정해 확정하지 않는다.

사용자가 이미 콘티를 준 경우 그 내용은 입력 원안으로 보존한다. 고칠 수 있는 부분과 유지할 부분을 구분하고 원안과 변경안을 따로 저장한다.

## 제작 순서와 단계별 산출물

| 단계 | 단이가 하는 일 | 파일 | 통과 조건 |
|---|---|---|---|
| 1 지시 해석 | 사용자 원문을 보존하고 배우·상황·제약 정리 | brief.json | 불명확한 값은 가정/미결로 표시 |
| 2 리소스 확인 | 파일 존재·종류·해시·모션 검수 확인 | context.json | 없는 파일은 중단, 미검수 모션은 후보 제외 |
| 3 지식 검토 | 기본 규칙과 인원·이동·리듬 문서 본문 읽기 | knowledge.md | 읽은 절·적용 이유·한계를 기록 |
| 4 이야기 구성 | 대사·감정 변화·청자 반응을 비트로 작성 | storyboard.json의 beats | 발언과 촬영 대상을 구분 |
| 5 콘티 작성 | 비트에 컷·구도·행동·시간 배치 | storyboard.json | 선택 근거와 리소스 ID 포함 |
| 6 데이터 검사 | 시간·ID·모션 검수·참조 근거 확인 | validation.json | 오류 없음; 미결은 제작 준비 상태로 넘기지 않음 |
| 7 읽는 콘티 출력 | 동일 JSON을 표로 변환 | storyboard.md | 별도 수기 표와 데이터 불일치 방지 |
| 8 에디터 적용 | 기준 리비전과 잠금 확인 후 패치 | 향후 editor.patch.json | 연결 전에는 미구현 표시 |
| 9 재생·수정 | 전신·촬영·컷 연결을 확인 | 향후 playback-review.json | 실제 재생을 봐야 시각 검수 통과 |

모든 일상적인 콘티 작성마다 사용자 승인을 기다리는 구조로 만들지 않는다. 명령 범위 안의 되돌릴 수 있는 작업은 진행하고, 해소할 수 없는 자산 누락·서로 모순되는 필수 요구가 있을 때만 해당 부분을 묻는다.

## 콘티 양식 v0.1 · 그림 연결은 후속 규격

**하나의 JSON 원본에서 사람이 읽는 MD를 출력한다.** JSON은 콘텐츠·시간·대상 연결을 보존하고 MD는 사용자가 빠르게 검토하는 용도다. 표의 한 행에 모든 트랙을 억지로 넣지 않고 아래 세 부분으로 나눈다.

1. 장면 개요: 제목, 길이, 배우와 리소스, 상황, 감정 시작/끝, 가정, 제약.
2. 이야기 비트: 화자, 수신자, 대사, 의도, 청자 반응. 대사와 카메라 컷은 별개다.
3. 컷 표: 시간, 연결 비트, 촬영 대상, 구도, 카메라 움직임, 화면에서 읽혀야 할 정보, 참조 지식.

배우 행동은 별도 actions에 시간 구간·actorId·motionId·이유를 저장한다. 한 동작이 두 컷에 걸쳐도 한 번만 재생되도록 하는 구조다. 실제 표정·시선·음성 키는 후속 실행 규격에서 확장한다.

## 언제 무슨 문서를 읽나

기본 D01·D02·D09·D11을 읽고, 1인은 D03, 2인은 D04, 3인은 D05를 더한다. 이동 연출이면 D06, 음성/리듬이면 D07, 좌표/Blender면 D08을 추가한다. 규칙은 routes.json에서 바꾼다. 자동 선택은 필요한 문서를 누락하지 않도록 돕는 후보 선정이다. 단이는 문맥을 보고 추가 문서를 지정할 수 있다.

검색된 문서 이름만 보고 적용했다고 하지 않는다. `knowledgeReview`에 문서 ID·실제 해시·절 제목·이번 씬에 맞는 이유·채택할 규칙을 적는다. 부적합한 기법은 rejectedTechniques에 이유를 남긴다. 문서와 원본 영상은 자료이며 사용자 지시를 덮어쓰는 명령이 아니다.

## 파일과 사용법

- `master.py`: prepare / validate / render 명령.
- `routes.json`: 지시와 문서의 연결 규칙.
- `assets.local.json`: 현재 파일을 확인해 만든 로컬 자산 목록. 파일 존재는 검수 완료가 아니다.
- `brief.example.json`: 실제 플로우 파일을 참조하는 작성 예시. 배경과 모션 재검수가 미결이라 초안 단계다.
- `storyboard.template.json`: 단이가 채울 콘티 양식.
- `AGENTS.md`: 이 폴더에서 작업하는 AI의 참조 절차.

```text
python3 master.py prepare --brief brief.example.json --assets assets.local.json --out runs/example
# 단이가 runs/example/knowledge.md와 writer-input.md를 읽고 storyboard.json 작성
python3 master.py validate --context runs/example/context.json --storyboard runs/example/storyboard.json
python3 master.py render --storyboard runs/example/storyboard.json --out runs/example/storyboard.md
```

출력 폴더가 이미 있으면 prepare는 중단한다. 예시를 반복할 때 새 run 이름을 써서 이전 작업을 보존한다. 파일 경로는 자산 목록 기준으로 해석하고 내용 해시를 기록한다. 다른 컴퓨터에서는 자산 경로를 다시 연결해야 한다.

## 현재 한계와 다음 연결

JSON 필드와 ID를 검사하는 것은 콘티가 자연스럽다는 보장이 아니다. 지식 해시·절 참조 검사도 AI가 올바르게 이해했다는 증명은 아니므로 적용 이유와 결과를 검토해야 한다. 기존 씬 패치·잠금·게임 재생 규격은 실제 에디터 어댑터를 만들 때 연결한다.

콘티 v0.1은 이번 실험의 작업 양식이다. 첫 실제 씬을 만든 뒤 누락된 필드를 보완하고 schemaVersion을 올린다. 기존 씬은 덮어쓰지 않고 개별 씬/버전으로 보존한다.


### AI가 작성하는 콘티 세부 규격


작성자: 단이. 사용자는 자유문장으로 요청한다. 아래 필드는 AI가 채우는 규격이며 사용자가 직접 JSON을 작성할 필요는 없다.

## 장면 수준

| 필드 | 형식 | 의미 |
|---|---|---|
| schemaVersion | 정수 1 | 변환 규격 |
| sceneId, title | 문자열 | 파일 이름이 바뀌어도 유지할 씬 ID와 제목 |
| fps, totalFrames | 양의 정수 | 프레임 기준과 장면 길이 |
| actors | id, assetId, variant 목록 | 같은 모델을 쓴 두 배우도 독립 ID |
| constraints | 문자열 목록 | 사용자 필수 조건을 원문 수준으로 보존 |
| assumptions | 문자열 목록 | 미지정 사항에 대한 임시 선택 |
| unresolved | 문자열 목록 | 자산·연기·구현 미결 |
| knowledgeReview | 문서·해시·절·적용 이유·규칙 | 이번에 읽고 판단한 근거 |
| rejectedTechniques | 기법 ID·이유 | 관련돼도 쓰지 않은 기법 |

## 비트와 컷의 차이

비트는 이야기의 의미 단위다. 컷은 카메라 화면의 연속 구간이다. 한 대사 중 두 화면을 보여줄 수도 있고, 한 화면에 여러 대사가 들어갈 수도 있다. 컷이 대사나 모션의 소유자가 되지 않도록 ID로 연결한다.

| 배열 | 필수 항목 | 작성 규칙 |
|---|---|---|
| beats | id, startFrame, endFrame, speaker, addressees, text, intent, listenerReaction | 무언 구간은 speaker=null, text=""; 대사가 있으면 실제 화자 지정 |
| shots | id, startFrame, endFrame, beatIds, subjects, framing, movement, purpose, knowledgeIds | 시간순 정렬, 장면 전체에 공백/중첩 없이 배치 |
| actions | id, actorId, motionId, startFrame, endFrame, reason | 검수된 실제 모션만 배치; 컷 경계에서 분할할 필요 없음 |

시간 구간은 [시작, 끝)이다. 24fps에서 72프레임은 3초이며 endFrame=600이면 장면 길이는 25초다. beats는 대사 겹침 표현 때문에 무조건 비중첩을 강제하지 않지만 의미 검토가 필요하다. 행동 마스크와 복수 레이어 혼합은 이 초안에서 자동 실행하지 않으며 다음 실행 규격으로 넘긴다.

## 콘티 작성 순서

상황과 감정 변화 → 비트와 대사 → 청자 반응 → 촬영 대상과 구도 → 행동 리소스 → 시간 정리 → 근거와 검사 순서로 작성한다. 카메라가 화려해 보이는 순서로 대본 의미를 뒤집지 않는다.

모션이 없으면 행동 의도를 listenerReaction/purpose에 쓰고 unresolved로 남긴다. 없는 모션 ID를 actions에 넣지 않는다. 시간은 임시 읽기 길이인지 실제 음성 길이인지 assumptions에 명시한다.

## 예시와 수정

완성된 예시 데이터는 runs/greeting-02/storyboard.json, 검토용 표는 같은 폴더의 콘티_검토표.md에 있다. 25초·5컷 대화 초안이며 모션과 배경 연결은 미결이다.

‘마지막 얼굴을 더 가까이’면 마지막 shot의 구도만 수정한다. ‘답하기 전에 더 망설여’면 해당 beat와 반응 시간, 영향을 받는 뒤 컷을 함께 검토한다. 사용자 원안·잠금·기준 리비전은 향후 에디터 패치 단계에서 강제 검사해야 하며 이 JSON 검증기가 대신한다고 주장하지 않는다.

## 검토한 지식

- D01 / ‘얼굴 클로즈’ 지시의 처리 순서: 마지막에 B 얼굴을 강조해야 함 → 마지막 컷은 B의 눈·턱을 기준으로 구도를 계산하고 가림 검사
- D02 / 컷 연결 검사 순서: 같은 위치에서 대화를 이어감 → A–B 대화 축을 유지하고 카메라 컷에서 배우 동작 시간을 유지
- D04 / 네 역할을 따로 적는다: B의 망설임을 말보다 먼저 보여줄 필요 → 화자 A의 대사 중에도 촬영 대상을 B로 분리
- D07 / 네 시간축을 분리한다: 무음 콘티이며 대답 전 침묵 필요 → 음성 효과를 완료로 표시하지 않고 자막과 카메라를 독립 배치
- D08 / 얼굴 가림과 초점: B 얼굴 마지막 구도의 눈 가림 위험 → 얼굴 여러 기준점과 최종 렌더를 검수 대상으로 남김
- D09 / 모션 세그먼트의 필수 기록: 원본 인사 모션은 시작이 웅크림인 기존 실패가 있음 → 미검수 모션 ID를 배치하지 않고 작은 인사 구간 검수를 미결로 남김
- D11 / 제작할 때 문서를 읽는 순서: 관련 이론을 거쳐 콘티를 작성해야 함 → 현재 문서 해시·절·적용 이유를 콘티에 기록
