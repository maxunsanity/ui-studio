<p>출처: (신규) <a href="../../../../proposal-concept/balance-sim.html">발란스 시뮬레이터 제안 카드</a> · <a href="../../../../proposal-concept/season.html">시즌 제안</a>. 이식 비교: 해당 없음.</p>
<p>이 도구는 게임을 오랫동안 반복했을 때 성장과 재화의 흐름을 살펴보기 위한 화면입니다. 시험 입력으로 하루 주사위를 정하고 굴리면 도착한 칸의 수익과 성장, 건물 증설, 팬의 변화가 이어집니다. 눈에 보이는 연출은 계산 결과를 설명하며 그 자체가 새 보상 판정을 만들지는 않습니다.</p>

<section class="part" id="part-3"><h2 id="3-구동-방법시뮬레이션">3. 구동 방법·시뮬레이션</h2>
<p>화면 흐름: 발란스 시뮬레이터 진입 → 입력과 팀 확인 → 시작·굴림 → 성장과 일별 기록 확인. 이식 비교: 해당 없음.</p>
<p><strong><a href="/docs/planning/idle-sim.html">발란스 시뮬레이터 열기</a></strong> · <strong><a href="/docs/planning/balance-tool.html">발란스 툴 열기</a></strong></p>
<ol>
<li>화면에서 팀과 현재 일차·보유 주사위를 확인합니다. 굴림은 시작 버튼을 눌러 진행하고 멈춤으로 중단합니다.</li>
<li>무료·평균·헤비 입력을 고르면 표에 적힌 하루 주사위 시나리오를 사용합니다. <strong>진행 중 입력을 바꾸어도 현재 일차·카드·돈·단계는 유지되고, 새 지급량은 다음 날부터 적용됩니다.</strong> 이미 받은 오늘의 몫은 다시 바뀌지 않습니다.</li>
<li>배수를 선택하고 굴림·능력·건물·팬·카드·모험 등의 화면에서 현재 결과를 살펴봅니다. 잠긴 배수는 엔터파워·보유 주사위·그날 상한을 함께 확인합니다.</li>
<li>일별 기록과 로그로 시험 결과를 비교합니다. 새로고침하면 같은 실행의 일차와 전체 진행을 함께 복원하고 <strong>멈춘 상태</strong>로 돌아옵니다. 기존 시작 버튼으로 계속합니다. 새 실행은 초기화할 때 시작하며, 저장이 불완전하거나 원본이 맞지 않으면 일부만 복원하지 않고 기존 기록을 보존한 채 재개 중단 안내를 표시합니다. 자동으로 새 팀을 만들지 않습니다.</li>
</ol>
<p>하루 통째 800개 지급은 없앴습니다. 무료는 모든 무료 일일 보상(자동 충전 · 미션 · 이벤트 칸 · 보드 등)의 합으로 하루 800~900을 기준으로 보고(60일 평균 835.6), 나머지는 상점 유료 구매(준비중)입니다. 평균·헤비의 구매 입력 및 1일차 지급 여부 등은 표에 임시 또는 발란스 대기로 표시됩니다. 입력 수를 다른 재화 지급과 중복 집계하지 않도록 출처를 확인합니다.</p>
</section>

<h3 id="4-2-건물과-엔터파워">4-2. 건물과 엔터파워</h3>

<p>카드는 획득·중복과 아이돌 능력에 연결된 결과를 보여 줍니다. 모험은 기존 시작 버튼으로 진행하며 현재 성장 단계·티켓·보상 표에 따라 자동 계산합니다. 현재 구현(11/10): 주사위를 한 번 굴릴 때마다 티켓 1장을 쓰고, 표 adventure_dispatch_config의 ticket_use_mode = alternate에 따라 모험 → 출동 → 모험 순서로 번갈아 씁니다. 출동할 몬스가 없으면 그 장은 모험으로 씁니다. 하루 상한(expedition_per_day)은 그날 쓴 장까지 합쳐 세고, 하루 끝에 그날 장부 한 줄로 미션 기록·아이돌 카드팩을 처리합니다. 모험 결과는 adventure_success_rate 표(등급·인원·성공률 ± 흔들림)로 굴려 성공이면 단계 등급, 실패면 가장 낮은 등급이 됩니다. 등급은 라포 좋음·나쁨으로 이어지고, 실패해도 보상은 줄지 않고 라포만 나빠집니다(현중 11/10 10:38). 결정 대기: 성공률 기준 표(통합목록 10번 · 지금 굴리는 adventure_success_rate 예 92 ± 4 / adventure_stage_scale sim_success_pct 100), ticket_use_mode 표 줄 정본(통합목록 4번). 별도의 편성·시험·보상 받기·퍼즐 조작은 게임 시뮬레이터에 둡니다.</p>
<p>탐험·출동 횟수, 돈·주사위·우정 포인트·카드팩 계산량·조각·자동 퍼즐 완성 합계와 최근 일별 결과를 표시합니다. 같은 실행의 같은 날은 중복 정산하지 않습니다. 카드팩 ID와 수량은 실제 보상 원본에서 보관함으로 전달하고, 등록된 팩은 기존 카드 개봉 API와 대상·등급 조건에 따라 자동 개봉합니다. 대상이나 조건이 맞지 않으면 보관합니다. 방치 엔진은 그날 쌓인 카드도 자동 개봉하고(engine.ts cardBook), 카드 ID 대응은 card_id_map.csv(테마 01~05 60줄 = 슬롯 n ↔ Cnn)를 읽습니다. 헤비 입력은 9주(63일) 2,000만 원 = 하루 7,149개(구매 6,349 + 무료 800)입니다. 문 표시는 합류 멤버만 평균합니다. 시험용 ?nosave=1 은 자동 저장을 끄고 화면에 「[시험용] nosave=1 · 자동 저장 꺼짐」을 띄웁니다. 성장 현황판에는 모험 누적 횟수와 진행·경제 상세 합계를 전달합니다.</p>
<p>나쁜 기운은 굴림·루머·시간·일차 가운데 표에 값이 제공된 경로로 쌓입니다. 발란스용 습격은 성공으로 처리하고 제공된 보상 표를 사용합니다. 이것은 <a href="%EB%82%98%EC%81%9C%EA%B8%B0%EC%9A%B4%EB%94%94%ED%8E%9C%EC%8A%A4_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">P104</a>의 실제 전투 승패와 별개의 시험 규칙입니다. 값이 비어 있으면 해당 경로를 발란스 대기로 두고 보상을 임의로 만들지 않습니다.</p>

<p>미션 전체는 <a href="../../%EC%8B%9C%EC%8A%A4%ED%85%9C%EA%B8%B0%ED%9A%8D/S11_%EB%AF%B8%EC%85%98.md#%ED%98%84%EC%9E%AC-%EC%9A%B4%EC%98%81%ED%91%9C-%EC%A0%84%EC%B2%B4-%EB%AA%A9%EB%A1%9D">S11 운영표 전체 목록</a>의 56줄(활성54·비활성2)을 봅니다. 활성은 달성 가능이나 수령 완료를 뜻하지 않습니다. 실제 조건·목표·보상과 연결되지 않은 콘텐츠를 구분하며, 시뮬레이터 하단 미션의 기간 말 자동 수령은 기간 연결 검수 완료입니다.</p>
<h3 id="4-3-2-실제-미션-전체와-기간-말-수령-기간-연결-검수-완료">4-3-2. 실제 미션 전체와 기간 말 수령 · 기간 연결 검수 완료</h3>
<p><a href="/docs/planning/idle-sim.html">하단 미션</a>은 운영표56줄 가운데 활성54개를 실제 잠금·목표·진행·보상·수령 상태로 읽고 비활성2개를 별도로 구분합니다. 상세 ID·종류·조건·보상·초기화는 <a href="../../%EC%8B%9C%EC%8A%A4%ED%85%9C%EA%B8%B0%ED%9A%8D/S11_%EB%AF%B8%EC%85%98.md#%ED%98%84%EC%9E%AC-%EC%9A%B4%EC%98%81%ED%91%9C-%EC%A0%84%EC%B2%B4-%EB%AA%A9%EB%A1%9D">S11 전체 목록</a>에서 대조합니다. 아이돌 등급 팩10미션은 기존 조건과 보상을 보존하며 같은 기간에 기존 아이돌 지급과 다시 겹쳐 주지 않습니다.</p>

<p>미션의 실제 플레이·장부 → 가운데 굴림·진행 → 수령 영수증 → 06 몬스팩·행복 → 중앙으로 연결 기록을 표시합니다. 엔터파워·사옥의 직접 팩은 11 → 06이며 행복 교환은 중앙 → 06으로 구분합니다. 진행만 올랐거나 같은 영수증을 다시 표시한 때에는 획득·성장선을 새로 만들지 않습니다. 현황판은 이 기록을 읽기만 하며 보상과 능력을 추가 지급하지 않습니다.</p>
<p>게임 시뮬레이터의 공용 등록 경로는 기존 P94 실행 파일을 사용하며, 바뀐 표 위치를 등록 원본에 맞춰 복구합니다. 이 문서에서는 제품 화면에 개발 설명을 추가하지 않습니다.</p>
<h3 id="4-4-결과-표시와-기록">4-4. 결과 표시와 기록</h3>
<p>발란스 화면은 <strong>외부에 보이는 실제 보상과 성장</strong>을 표현합니다. 남색 바탕과 청록 강조의 굴림 필러에서 주사위가 320ms 동안 굴러간 뒤, 실제 도착 보드명·두 눈과 합·적용 배수를 보여주고 그 굴림의 실제 혜택을 이어 표시합니다. 굴림·도착 설명과 기존 성장 필러를 구분하며, 표시 장면이 별도의 지급 판정을 만들지 않습니다.</p>
<p>능력·돈·팬·시설 단계가 바뀌면 실제 전후 차이와 영수증을 읽어 숫자 이동과 성장 장면을 만듭니다. 움직임을 줄이는 설정에서도 계산된 값은 갱신됩니다. 카드 정보 탭을 읽는 동안 자동 굴림이 일으키는 배경 보상 비행은 억제하고 실제 변화 배지로 전달합니다. 사용자가 직접 개봉한 결과는 실제 개봉 한 번에 한 번만 비행하며, 정보 재조회나 같은 영수증 재표시로 다시 지급하지 않습니다.</p>
<p>일별 기록은 그날의 입력·사용 주사위·수익·팬·증설과 능력을 남깁니다. 기록이 없는 옛 자료의 건물 단계나 미공급 값을 0으로 바꾸지 않고 미확인으로 둡니다. 오프라인 계산은 자리를 비운 시간을 시험 엔진의 굴림으로 환산하는 기존 기능이며, 새로고침 뒤 같은 진행을 복원하는 전체 실행 저장과 구분합니다.</p>

<p>뉴런은 굴림과 성장의 결과를 <strong>읽어서 보여 주는 공통 패널</strong>입니다. 발란스 시뮬레이터의 굴림 화면에서 뉴런 보기를 열면 이 실행에 실제 합류한 아이돌, 선택 멤버, 능력과 시설 단계를 표시 모델로 만듭니다. 패널에서 다른 합류 멤버를 선택하면 발란스 화면의 선택도 그 멤버로 맞춰집니다. 이는 이 발란스 실행의 관찰이며 공용 게임 저장에서 현재 팀을 읽어 오는 별도 뉴런 경로와 출처가 다릅니다.</p>
<p>한 번 굴리기 전과 후를 비교할 때는 같은 실행 ID·점수 단위이고 관찰 순서가 앞으로 진행한 기록만 비교합니다. 확인된 능력이나 단계가 실제로 바뀌면 선·빛으로 표시합니다. 이전 값이 없는 첫 관찰, 같은 기록의 재표시, 다른 실행이나 단위 변경은 성장으로 꾸며 내지 않습니다. 보상은 원래 경제·카드 정산에서 처리하며 뉴런은 <strong>새 주사위·돈·능력·보상을 지급하거나 게임 저장을 변경하지 않습니다.</strong></p>

<p>P171 발란스 굴림에서 뉴런 보기가 켜져 있을 때는 뉴런 안의 확인된 변화선·빛을 유지하고, 돈·팬·엔터파워·나쁜 기운·콘텐츠·몬스가 다른 창으로 이동하는 표시는 목적 창의 빛과 기존 수신 배지로 바꿉니다. 뉴런으로 전환할 때 남은 비행과 필러는 표시 완료로 정리하며 같은 영수증을 나중에 다시 재생하지 않습니다. 숨겨진 필러를 출발점으로 기다려 굴림이 멈추지 않게 합니다.</p>

<p>이 규칙은 발란스 굴림의 뉴런 보기 ON에만 적용합니다. 계산·저장·보상 지급은 그대로이며, 뉴런을 끈 일반 모드의 비행과 03 개인 단계·08 팀 등급 상승의 기존 2초 강조를 유지합니다. 별도 게임 뉴런·공통 정보창의 동작은 바꾸지 않습니다.</p>

<p>고정 보기에서는 전체 기반 → 팀·관계 → 선택한 개인의 6축 → 소속 세부와 아카데미의 네 단계로 살펴봅니다. 전체·이전·다음 버튼으로 이동하거나 세밀 모드에서 확대합니다. 보컬·댄스·랩·비주얼·끼와 예능감·프로듀싱의 각 축은 세부 세 개를 읽습니다. 현재 능력과 재능은 다른 원본으로 표시하고, 외국어 3개와 태도·성실성은 6축·18세부에 새로 더하지 않는 별도 아카데미 정보입니다.</p>
<p>발란스 실행은 현재 시설의 실제 단계와 보드 위치를 표시합니다. 멤버 ID·능력·단계·학습·시설의 자료가 일부 빠지면 그 부분은 연결 대기로 남기되 확인된 다른 값은 유지합니다. 실제 0과 값이 없는 상태를 구분하며, 축 평균과 세부 원본이 맞지 않으면 임의로 고치지 않고 대조 필요로 표시합니다. 생성 재능의 표시 단위 변환은 원본 설정을 한 번 적용하고 같은 값을 반복해서 확대하지 않습니다.</p>

<p>공통 뉴런에서는 같은 세션·실행에 속한 현재 멤버 두 사람과 유효한 저장 관계가 함께 확인될 때만 관계를 표시합니다. 신뢰는 색, 이해는 선 두께, 협력은 거리, 긴장은 높이에 반영합니다. 한 명이면 쌍이 없고, 두 명이어도 원본이 없거나 중복·다른 팀이면 <strong>관계 기록 대기</strong>로 둡니다. 관계 수치가 없는 위치는 장식용 배치이며 친밀도를 뜻하지 않습니다.</p>
<p><strong>현재 P171 발란스 실행은 관계 기록을 뉴런 모델에 전달하지 않습니다.</strong> 따라서 공통 패널에 관계 보기 단계가 있더라도 이 실행의 실제 관계 값이 연결되었다고 표시하지 않습니다. P152 모험의 관계 사건이나 다른 성장 저장을 임의로 가져와 채우는 기능도 아닙니다. 별도의 공통 뉴런 경로는 유효한 성장 저장의 관계를 읽을 수 있으며, 그 경로와 발란스 실행의 연결 여부를 따로 확인합니다.</p>
<p>독립 뉴런의 명시적 임시 시험에서는 1·2·5·10명과 능력·관계·아카데미·시설·단계·누락 상황을 표시용으로 재생합니다. 10명은 배치 시험이며 실제 팀 인원 변경이나 P171의 실제 결과가 아닙니다. 성장 테스트 도구의 시험 사본 역시 원래 저장과 분리됩니다. 표시 비율과 관계·학습 미정값은 발란스 대기입니다.</p>

id="4-8-전체-화면-맞춤과-성장의-입력출력">4-8. 전체 화면 맞춤과 성장의 입력·출력</h3>
<p>모바일·팝업·기획서 안 실행은 각 화면의 실제 보이는 높이와 폭에 맞춰 <strong>전체를 같은 비율로 줄입니다.</strong> 굴림 결과·배수 조작·필러·아래 메뉴가 함께 들어오게 하며, 능력 등 다른 탭의 본문은 원래 스크롤을 유지합니다. 작은 화면에서 큰 글자를 유지하려고 아래 조작을 자르지 않습니다.</p>
<p>두 화면은 같은 실행의 실제 영수증과 계산 전후를 읽습니다. 현황판은 주사위 소비 → 굴림 → 보드 → 혜택 콘텐츠 → 실제 아이돌·팀·재화 결과와 후속 변화의 내부 흐름을 보여 줍니다. 발란스 시뮬레이터는 실제 보드 도착명과 혜택 배지에서 지급·성장 결과로 가는 비행을 보여 줍니다. 화면 밖 메뉴의 수신은 기존 다음 탭 표시와 ‘건’ 배지로 확인하며, 열람·같은 기록 재수신으로 획득 효과를 다시 만들지 않습니다.</p>
<p>현황판은 6축과 12칸을 유지하고 아이돌 초상·팀 백판을 구분합니다. 실제 입력은 민트색, 성장 결과는 금색 방향선과 테두리 빛으로 보여 줍니다. <strong>뉴런으로 보기</strong>는 기존 공통 뉴런에 같은 실행의 합류 멤버·능력·시설 자료를 전달합니다. <strong>입력·출력 연결</strong>에서 켜짐·꺼짐과 현재 값을 읽을 수 있습니다. 현황판은 칸 사이 연결뿐 아니라 칸(콘텐츠) 안의 데이터 흐름(예: 능력 칸의 세부 능력 → 단계 → 팬)도 실제 코드 계산 그대로 보여 주며, 굴림을 멈췄을 때와 굴리는 중 모두 같은 방식으로 보여 줍니다.</p>

NPC는 아이돌마다 따로 세고 건물 합계도 같이 기록합니다(NPC 1명 = 팬 5,000 · 상한 100 · 임시(나중에 결정)). 건물에 NPC가 모인 화면 표현은 현재 개발되지 않음, 진행 중. 카드가 개인·팀 스탯을 통해 팀 등급에 미치는 간접 영향과 구분합니다. 81개 성장 목록의 표시 위치가 연결된 것과 모든 계산이 구현된 것은 별개입니다. 미정 수치나 미연결 효과를 연출이 대신 만들지 않습니다.</p>
<h3 id="4-9-내부-현황판과-같은-실행의-전체-저장">4-9. 내부 현황판과 같은 실행의 전체 저장</h3>
<p>일일 무료 지급은 자동 충전과 이벤트에서 실제로 받은 정수 주사위만 집계합니다. 미션·보드·미니게임·구매 지급은 별도로 읽습니다. 소수 이월분·첫날 지급 여부·마지막 지급일·실제 수령 합계는 지갑과 같은 전체 체크포인트에 저장하며, 복원과 같은 날 재호출은 다시 지급하지 않습니다. 판정별 횟수·얻은 팬·빠진 팬·순변화도 함께 복원합니다. 이 기록이 없던 옛 저장은 기존 진행을 보존하고 ‘복원 이후 집계·이전 기록 없음’으로 구분합니다. 기록되지 않은 과거 값은 추정하지 않으며, 새 기록 필드가 손상되면 원본을 보존하고 재개를 중단합니다.</p>
<p>내부 성장 현황판은 <strong>계산·원천·소비·미공급과 실제 장부</strong>를 확인하는 곳입니다. 도착 수입과 증설·건설 지출, 주사위 소비·지급을 정산 장부와 완료 영수증으로 구분하며 잔액 차이를 임의의 보상이나 비용으로 꾸미지 않습니다. 02의 외국어·성실성·태도 가운데 실제 팀 계산에 연결된 입력만 팀 방향으로 전달합니다. 미션은 일반 성장 기록과 수령 영수증을 중복 세지 않고, 선택 멤버별 실제 변화만 해당 멤버의 연결선으로 보여줍니다. 다른 실행의 몬스와 원본이 없는 라포를 대체 자료로 채우지 않으며, 같은 실행의 관찰 순서가 뒤로 간 갱신은 적용하지 않습니다.</p>

</div><p>저장 단위는 <code>kpopmonsters.idle-sim.run.v1</code>의 전체 체크포인트이며, 발란스 내부 저장은 <code>simulator_module_balance_idle</code> 이름공간으로 분리합니다. 별도 게임의 계정·성장 저장을 덮거나 초기화하지 않습니다. 모든 필수 파트와 버전·체크섬·원본 데이터 서명이 맞아야 한 번에 복원하며, 하나라도 빠지거나 원본이 다르면 부분 복원 없이 해당 발란스 시험 전체를 새로 시작합니다. 과거에 몬스만 남은 부분 저장을 완전한 실행 자료로 간주하지 않습니다. 복원 직후에는 멈추며 기존 시작 버튼으로 계속하고, 초기화는 새 시험을 만드는 조작입니다.</p>
<p>외국어 현재값은 처음에 받은 학습 점수를 한 번만 포함하고 이후 실제 아카데미 증가량만 더합니다. 하루 성장 상한은 하루 시작 기준을 기록한 뒤 원래 스위치와 방식대로 적용하며, 현재 꺼진 스위치를 문서나 연출이 임의로 켜지 않습니다. 이 연결 수정으로 운영 CSV의 수치·보상량을 바꾸지 않았습니다.</p>
<h3 id="board-missions-inspector-20261103">4-9-1. 현황판 보드·미션 확대 조회</h3>
<p>성장 현황판 가운데 아래의 ‘능력 성장 연계/성장 흐름도’ 그림을 없애고, 하단의 보드 위치·이름 정보를 <strong>현재 보드</strong> 요약으로 옮깁니다. 그 옆에는 「미개발 이벤트 보상」 한 칸을 둡니다(모든 이벤트를 담고 하루 1회 지급 · 누르면 항목별 내용. 출석 40.75·8시간 선물 30은 「작업 완료」와 실제 수치, 나머지는 준비중). 위 띠의 카드 몫 칸은 <strong>자동 충전</strong> 칸(엔터 파워 단계 · 다음 문턱 · 하루 충전량. 문턱 1→60, 100→90, 250→120 · 임시(나중에 결정))이 되고, 카드 몫 비율은 05 카드 보유 칸 맨 아래 한 줄로 옮깁니다. 10번 팬과 겹치던 팬 칸 자리에는 <strong>미션 정보</strong> 칸(누적 수령 · 수령 가능 · 진행 중)을 둡니다. 보드 정보는 중앙 하단 한 곳에서 읽고 기존 그리드·가운데 레이더 구조를 유지하며, 실제 높이를 하단 여정과 나누고 긴 상세는 읽기 페이지로 이어 갑니다.</p>
<p>발란스 시뮬레이터 하단은 페이지 넘김 없이 30칸 한 화면입니다. 평소 접힌 칸에는 이름과 데이터가 있음을 알리는 점만 두고(숫자·건수 배지 없음) 굴림 칸을 가장 크게 둡니다. 칸을 누르면 그 칸이 2×2로 커지며 상세를 마크다운으로 보여 주고 나머지 칸은 다시 배치됩니다. 비슷한 탭은 합쳐 쓰고 남는 칸은 비워 둡니다. 상단의 「무료 800」 메뉴는 없앴고, 대신 「무료 N」 한 줄(정수)을 둡니다. N은 게임 진행 보상(보드 등)을 뺀 자동 충전 + 이벤트 칸 + 미션의 하루 몫이며, 누르면 출처별 내역(정수)이 펼쳐집니다. 남은 주사위가 30개 이하이면 그날을 닫고 다음 날로 넘어갑니다(economy_config.csv day_end_dice_left 30 · 임시(나중에 결정)). <strong>이벤트</strong> 칸은 현황판 「미개발 이벤트 보상」과 같은 목록을, <strong>자동 충전</strong> 칸은 엔터 파워 단계·다음 문턱·하루 충전량을 보여 줍니다. 주사위가 지급될 때와 일차가 넘어갈 때는 출처 칸에서 지갑으로 주사위가 날아가고 화살표로 어떤 보상 때문인지 표시합니다. 멈춘 상태에서 현황판 칸을 누르면 연결된 콘텐츠로 가는 화살표만 보이고, 화살표 위에 어떤 데이터가 가는지(예: 팬 · 주사위)만 짧게 적습니다 — 현재 개발되지 않음, 진행 중.</p>

<p>보드와 미션을 누르면 <strong>기존 카드와 같은 보드 안 확대 세션</strong>으로 엽니다. 오른쪽 기존 카드들은 작은 띠로 남기고 같은 상세 영역에서 내용을 읽습니다. 휴대폰 세로에서는 가운데 아래 두 칸 폭으로 표시합니다. <strong>전체 보기 또는 Escape</strong>로 돌아오며, <code>open=board</code>·<code>open=missions</code> 직접 주소도 같은 확대 상태로 엽니다.</p>
<p>보드 확대에 처음 들어오면 현재 칸을 선택하고, 현재 칸과 다른 <strong>전체 40칸</strong> 중 하나를 골라 볼 수 있습니다. 선택한 칸은 같은 실행의 실시간 갱신 중 유지하며 현재 위치 표시와 따로 구분합니다. 다른 실행으로 바뀌면 이전 실행의 선택·계산을 섞지 않고 새 현재 칸을 기준으로 다시 표시합니다. 미션 확대도 열린 상태에서 같은 실행의 최신 스냅샷을 반영합니다.</p>
<p>각 칸은 <strong>같은 관찰 시점</strong>의 실제 시설 단계·팬 상태·엔터파워·실제 적용 배수·버프 공급/적용 상태를 기준으로 조회합니다. 배수 선택값만으로 지급액을 확정하지 않고, 잠금·보유 주사위·일차 제한 등을 거친 실제 적용 배수를 읽습니다. 조건이나 판정에 따라 보상이 달라지는 경우는 분기별 입력·적용 계수·보상 가능 범위를 함께 보여 줍니다.</p>
<p>돈은 올킬·차트인·광탈 또는 판정 없는 칸을 구분하고, 실제 적용 배수·이벤트 버프·시설 상태 보정과 시설별 팬 추가 수입을 함께 읽습니다. 능력은 현재 멤버의 능력·재능·포지션·라포·휴식·일일 상한을 원래 레슨 계산의 사본에 적용한 멤버별 세부 전후 예상입니다. 팬은 현재 팬층과 성장 단계·합류 인원에 따른 상한, 도착·레슨에 따른 변화를 구분합니다. 돈의 정본 시설 단계와 실제 레슨의 시설 단계는 각각 원래 계산 기준을 따릅니다.</p>
<p>잭팟은 발동 가능한 판정과 당첨 확률·당첨했을 때의 돈을 구분하며 다음 굴림의 통 1회 적립을 포함한 조건부 예상으로 읽습니다. 표에 잭팟이 연결되어 있어도 현재 규칙에 발동 판정이 없으면 발동 없음으로 표시합니다. 출발 통과와 감옥의 더블 탈출·최종 벌금은 도착 수입과 나눠 읽습니다. 팬 반응·찬스 카드와 추가 룰렛·쟁탈전은 추첨·상대·승패 뒤 결정되는 부분과 현재 발란스 대기를 구분하며 미확정 보상은 확정 합계에 넣지 않습니다.</p>
<p><strong>현재 조건의 예측</strong>은 아직 도착·추첨·승패·지급 판정이 확정되지 않은 조회입니다. <strong>지난 실제 지급</strong>은 같은 실행의 완료 정산과 확정 영수증에서 읽어 별도로 표시합니다. 과거 지급을 현재 칸의 예측으로 재사용하거나, 조건별 가능량을 이미 받은 보상으로 표현하지 않습니다. 자료가 없는 버프·계수는 연결 대기, 꺼진 효과와 실제 0은 각각 구분합니다.</p>
<p>미션 숫자는 발란스 시뮬레이터가 보내는 스냅샷과 확정 수령 영수증에서 읽습니다. 잠김·비활성을 수령 가능에 넣지 않고 같은 영수증을 중복 집계하지 않습니다. 확대 목록에서 기간·목표·진행·잠금 조건·보상과 실제 수령 기록을 구분합니다. 미션의 일괄 수령과 기간 말 정산은 기존 시뮬레이터 처리에 맡깁니다.</p>
<p><strong>열기·칸 선택·실시간 갱신은 읽기 전용입니다.</strong> 조회가 난수를 소비하거나 주사위를 굴리지 않으며, 보상 지급·능력 성장·경제 저장을 바꾸지 않습니다. 운영표의 조건·수치·보상량과 카드·몬스 지급 규칙도 그대로 읽습니다. 실제 화면과 자동시험의 최종 확인 범위는 대표 본체의 공용 보고에서 구분합니다.</p>

<p>팬의 실제 증감이 음수이면 팬 → 여정의 소비 방향으로 읽습니다. 세부 능력은 실제 참여자와 세부 항목의 점수 증감으로만 전달하며, 가중치가 적용된 종합 능력·축·팀 평균과 합산하지 않습니다. 미정값을 0이나 예시 수량으로 채우지 않습니다.</p>
<p>첫 조회·복원·다른 실행 전환은 이미 보유한 결과를 조용한 기준선으로 읽습니다. 같은 실행 범위의 같은 영수증은 한 번만 전달하며, 재조회나 기록의 삭제 후 재등장을 새 지급·새 전달로 만들지 않습니다. 같은 보상에 대한 일반 보드 표현은 검증된 현재 굴림의 돈·팬·세부 능력만 표시 사본에서 분리해 중복을 막고 원래 장부와 보유량을 보존합니다.</p>
<p>별도 임시 발란스는 공식 미정 원표를 덮지 않는 설정과 실제 정산 경로를 사용합니다. 앨범의 임시 정책, 크루의 실제 임시 원장, 주간 혜택·연료·레이싱의 임시 projection을 각각 읽고 ‘임시 적용 / 공식 대기’를 구분합니다. 원형 journey.scenario.economicEffectsImplemented=false, buff.applied=false와 공식 weekly/festival writer 대기 원인은 그대로 남으며, 별도 임시 실제 적용을 가리는 문구로 사용하지 않습니다.</p>
<p>주간 1일 혜택은 해당 주 마지막 하루의 실제 보드 굴림 배수만 활동량으로 누적합니다. 현재 임시 모의 순위와 활동 누적에 따른 다음 실제 START 1회당 예정 요청량을 표시합니다. 상세에는 projection이 보낸 현재 활동 배율과 활동 기여를 표시하며 UI가 이 배율이나 예정 수량을 다시 계산하지 않습니다. 예정 돈·팬·세부 능력·주사위·카드팩은 받은 보상이 아니며, 활동 1단위당 연료 드롭도 START 보상과 따로 읽습니다. 현재 설정에서 실제로 공급된 0과 미공급 null은 구분합니다.</p>
<p>혜택 기간의 표시와 실제 보상을 구분합니다. 현재 활동·순위·누적 배율·다음 START 예정량·연료 쌓임과 소모·실제 경기 진행 및 결과 보상을 읽습니다. 좁은 요약은 현재 구간·압축 인덱스·최근 수령을 우선하며 전체 수량·고정 대상·점수 단위·영수증·경기 기록은 기존 확대와 공용 상세의 읽기 페이지에서 끝까지 봅니다.</p>
<p>레이싱은 앨범 발매 주의 별도 자격과 실제 연료를 따릅니다. 주간 1일 혜택이 비활성이어도 자격 기간 안의 연료·레이싱·결과가 이어질 수 있습니다. 실제 기존 레이싱 결과로 정산하며, 앨범 순위 보상과 주간 혜택·레이싱 영수증은 서로 다른 출처로 구분합니다. 모든 보상은 자동 수령 경로이고 조회 버튼은 청구·출전·지급을 실행하지 않습니다.</p>
<p>현재 구현(11/10 · 발란스 시뮬): 레이싱은 연료를 쓰는 그 굴림에 바로 끝나고, 결과·레이스 보상 영수증이 같은 굴림에 자동으로 들어갑니다. 한 판 비용은 표의 race 값(steps × unitsPerLap × currencyPerUnit, 지금 임시 20)이고, 연료가 남으면 그만큼 판이 이어지며 판 수 상한은 없습니다(11/05 결정 「반복 상한 없음」과 같음). 현황판 페스티벌 등록 칸에는 최근 받은 보상 한 줄과 연료·인기 재화 한 줄을 표시합니다. 이 코드는 코덱스 구역이지만 발란스 시뮬 안에서만 바뀐 것이라 결정: 그대로 둠(현중 11/10 12:15 · 통합목록 3번), 코덱스에게는 알리기만 합니다.</p>
<p>인기 재화는 별도 ID(currency_master_currency_popularity)로 재화 표에 등록돼 있습니다. 현재 구현(11/10): 지급 기간의 굴림마다 연료와 같은 양으로 쌓이고(저장 칸 없이 굴림 기록에서 셈), 그 주가 지나면 0으로 소진되며, 쓰는 곳은 없습니다. 9주(월드)에는 지급이 없어 잔액이 0입니다. 결정 대기: 얻는 방법(통합목록 13번), 9주에 얻는 방법(12번), 코드 ID·표 줄 정본(4번). 양과 쓰는 곳은 발란스 대기입니다.</p>
<p>실제 수령은 raw rewardReceipts의 applied 표식만으로 정하지 않습니다. 원본 상태·엔진 적용·범위 검증을 통과한 receipts proof의 같은 ID가 있어야 돈·팬·주사위·카드팩·고정 대상의 세부 능력 증감을 표시합니다. 예정 세부 능력의 공용점수와 실제 영수증의 현황판점수는 구분하고 가중 종합 능력에 더하지 않습니다.</p>
<p>크루 actualEconomy가 공급되면 공용 재화 보유·누적 획득·내 획득 기여·실제 임시 레벨과 benefits의 원래 이름·상태·필요 레벨을 읽습니다. 임시 레벨의 기존 앨범 홍보/알림 해금은 새 돈·팬·능력 배율이 아닙니다. 기존 rewardAmounts=null이 이 원장 조회를 덮지 않으며, 없는 레벨·혜택 관측은 대기로 남깁니다.</p>
<p>앨범 슬롯 수는 원본 최대 발매 수를 따르며 현재는 8개입니다. 슬롯과 선택한 앨범의 전체 조건은 한 화면에서 읽고, 높이 407px의 낮은 본문에서도 조건·보상/기록 버튼·하단 바로가기가 겹치지 않게 배치합니다. 하단 성장 여정·크루는 같은 조회 목적지의 낮은 바로가기 행으로 표시하고 자세한 상태는 해당 상세에서 읽습니다. 과거·잠긴 미래 앨범에 다음 제작 대상의 조건을 붙이지 않으며 충족·부족·관측 대기와 실제 0·값 미정을 구분합니다. 새 발매 알림은 해당 사건 1건의 한 줄 상태와 곡명을 한 묶음으로 보여 주고 전체 슬롯·조건 페이지를 넣지 않습니다.</p>
<p>자동 제작·발매는 원래 조건 전체를 함께 통과해야 합니다. 첫 제작 기준은 실제 합류 멤버의 평균 단계가 기준에 도달한 굴림에서 관측하고, 그 기준 사건 이후 기간과 성장·시설·미션·엔터파워 조건을 유지합니다. 임시 설정은 원본의 미정 수치만 보충하며 날짜만으로 조건을 우회하지 않습니다. 실제 발매 참여자는 앨범에 고정된 대상이고 조회·재선택은 제작·발매·지급을 실행하지 않습니다.</p>
<p>주간 흐름은 앨범 1일 이벤트, START 정산, 보드 활동의 연료 적립, 연료 소비와 경기, 실제 경기 결과 수령을 단계별로 읽습니다. 실제 영수증·연료 잔액·경기 진행/순위는 관측값이고 다음 START는 임시 견적입니다. 정식 주간 참가 연결, 앨범 이벤트와 임시 주말 혜택의 통합, 경기·공연의 주간 순위 기여는 대기로 표시합니다. 월드 흐름은 참가 방식·57~63일 기간과 실제 기록을 보여 주되 월드 평가·득표·홍보 효과·연습 보드·인기 재화 및 순위 기여는 연결 대기로 남깁니다. 현재 연료나 과거 경기 기록을 미래 월드 수령·월드 인기 점수로 바꾸지 않습니다.</p>
<p>기획서 안의 게임 화면도 전송된 모듈·시험 범위와 검증된 소유 실행을 유지합니다. 음악 콘텐츠 사이의 이동이나 팝업·확대만으로 다른 실행을 만들거나 독립 표본과 합치지 않습니다. 실제 전체 체크포인트와 실행·세션·시즌·배우·팀 범위가 맞는 원본으로만 경제와 수령을 연결하고, 메타데이터만 공급된 화면을 실제 정산 권한으로 쓰지 않습니다.</p>

<p>게임 시뮬레이터의 페스티벌 화면에는 자동 혜택·레이싱을 별도로 표시합니다. 게임의 실제 굴림이 남긴 활동량·누적 배율·다음 START 예정량·연료 적립과 소모·경기 진행·실제 순위·검증된 자동 수령을 읽습니다. 기존 공식 참가와 수동 3D 경기·결과 청구는 원래 화면과 조작을 유지합니다. 자동 기록을 열거나 페이지를 바꾸는 동작은 출전·연료 소모·보상 청구를 실행하지 않습니다.</p>
<p>발란스와 게임의 자동 혜택은 각 실행의 현재 projection을 조회합니다. 실제 게임 적용은 실제 굴림 정산의 범위 검증·중복 차단을 통과한 영수증만 사용하며, 화면 새로고침으로 다시 진행하지 않습니다. 주간 START와 경기 결과의 주사위·카드팩·돈·팬·세부 능력은 각각 공급된 수량과 실제 고정 대상을 따릅니다. 임시 설정과 공식 운영 대기는 계속 구분합니다.</p>

<h3 id="4-11-실제-보상의-원인계수와-능력-추적-경계">4-11. 실제 보상의 원인·계수와 능력 추적 경계</h3>
<p>현황판의 <strong>원인·계수</strong> 조회는 정산이 끝난 실제 한 굴림을 기준으로 보상별 <strong>입력 → 적용 계수·보정 → 실제 지급액</strong>을 나눠 보여 줍니다. 도착 수입·통과·잭팟·감옥·지급이 확정된 추가 룰렛·캐스팅 등은 원래 결과를 구분해 읽고, 팬 관련 입력·시설 단계와 관련 계수·주사위 배수는 계산 원본이 제공한 값만 표시합니다. 제시된 보상량과 실제 지급 여부는 다르게 다룹니다.</p>
<p>계산식과 입력이 없는 항목, 꺼진 효과, 발란스 대기값은 각각 구분합니다. 화면에서 계산식을 다시 실행해 지급액을 만들거나 빈 계수를 중립값·0으로 채우지 않습니다. 다른 실행의 자료나 이미 지난 정산을 현재 결과로 바꾸지 않습니다.</p>
<p>팬층·능력·시설과 돈·주사위의 전후 차이는 <strong>같은 구간에 관찰한 변화</strong>입니다. 증설·건설·다른 수령이 함께 섞일 수 있으므로 잔액 차이를 한 보상의 지급액으로 쓰지 않습니다. 팬층 이동의 전후·상한 제거·판정 결과도 관측으로 나누며, 이를 특정 팬·시설 계수가 추가로 만든 순이익이라고 단정하지 않습니다. 계수와 실제 지급액을 보여 주는 것과 <strong>각 효과 덕분에 얼마가 더 올랐는지를 분해하는 것</strong>은 별도입니다.</p>
<p><strong>능력 계산의 실제 입력과 처리 과정 관측을 연결했습니다.</strong> 기본 성장 입력, 건물 레슨·포지션·라포의 적용값과 규칙 공급 상태, 주사위 적용 배수, 재능선 전후 구간의 처리, 일일 상한 적용과 멤버별 최종 세부 능력을 기존 계산에서 기록해 읽습니다. 상한 적용 전 증가량과 적용 후 결과는 구분하며 같은 실행·정산 순서·멤버·점수 단위를 맞춥니다. 라포가 실제 계산에서 1배였다는 관측과 라포 규칙·축 자료의 공급 여부는 별도로 표시합니다. 실행 자료가 미공급이면 규칙 연결 대기로 두며 1배 관측을 라포 영향 구현 완료라고 해석하지 않습니다. 임의의 성장 속도 %나 원인별 인과 기여율은 만들지 않습니다. 실제 화면에서 보상 입력·계수·지급액과 능력 세부 관측 표시를 확인했습니다.</p>
<h3 id="필요-시스템">필요 시스템</h3>
<p>공통 경제 계산, 시설 단계와 엔터파워, 아이돌 성장·팬 상태, 표 로더와 일별 기록이 필요합니다. 뉴런은 발란스 실행의 관찰 모델, 공통 3D 패널, 능력·시설 정의와 표시 자원 정리가 필요합니다. 관계 원본은 별도 공통 뉴런 경로에서 검증하며 현재 발란스 입력에는 없습니다. 카드·모험·디펜스는 각 시험이 제공하는 데이터와 저장 범위를 따릅니다.</p>

<h3 id="all-resource-ability-flow">4-12. 재화와 능력의 전체 흐름</h3>
<p>목적은 재화와 능력의 전체 흐름을 확인하는 것입니다. 현황판은 굴림에서 어느 콘텐츠로 입력됐고 어디에 쓰여 무엇을 바꿨는지 보여 줍니다. 발란스 시뮬레이터는 같은 영수증의 실제 도착 혜택과 지급·성장 결과를 필러와 비행으로 보여 줍니다. 표시가 보상이나 능력을 다시 지급하지 않습니다.</p>

<p>굴림 직후 혜택 콘텐츠가 먼저 반짝이고 실제 아이돌·팀 또는 재화 목적지로 짧게 이어집니다. 입력선 200ms와 결과선 620ms는 최대 200ms의 경유 간격으로 겹쳐 재생합니다. 일반 능력 01은 320ms의 짧은 갱신 반응만 사용하고 계산·굴림을 강제로 멈추지 않습니다. 03 개인 단계·08 팀 등급의 실제 상승은 기존 공통 2초 강조를 유지합니다.</p>
<p>이동 문구는 한글 항목과 짧은 증감으로 표시합니다. 정확한 원문 수치·전후·원천·기록 건수와 ID는 상세에 보존합니다. 작은 실제 증가량을 0으로 만들지 않고, 서로 다른 멤버·항목·단위·원천을 임의 합산하지 않습니다. 같은 표시가 반복되면 건수를 함께 표시합니다.</p>
<p>돈 원천 분리는 실제 지급 합계와 맞는 자료에만 적용합니다. 원본이 없거나 합계가 맞지 않으면 지갑 관측과 원천 연결 대기를 표시합니다. 실제 0·꺼짐·미공급·미지급 시안은 각각 구분합니다. 팬·시설·라포 변화가 관찰됐다는 사실만으로 새 능력 효과나 원인별 이익 기여율을 만들지 않습니다.</p>
<p>오프라인은 현재 계산 구간의 원장을 매 정산에서 읽어 최근 장부가 잘리기 전의 합계를 보존합니다. 하루 주사위·쟁탈전·확정 추가룰렛·게이지·방어·자동모험의 직접 지급도 별도로 관측합니다. 원문 ID는 한정된 표본과 전체/생략 건수로 보존하며 실제 합계는 표본 수와 별개입니다. 이미 원본이 없던 과거를 잔액 차이로 복원하지 않습니다. 전체 기간 능력에는 카드 성장이 포함되므로 개별 카드 관측과 다시 합산하지 않습니다.</p>
<p>탭 열람·첫 관찰·같은 영수증 재수신·새로고침은 새 획득으로 재생하지 않습니다. 현황판의 진행 중 연결은 크기 변경과 재렌더링에 맞춰 위치를 갱신합니다. 상세 열람은 배경 연출을 정리하고 새 기록을 소비하여 닫은 뒤 과거 보상이 몰려 재생되지 않게 합니다.</p>
<p>검수는 같은 실제 플레이의 일차·재화·능력·위치·최근 기록 복원, 카드 탭 반복 효과 방지, 굴림·일차·시간→기운, 돈·능력·건물→엔터파워 비행을 포함합니다. 실제 방어 1회와 랜덤 카드 1장 지급을 확인했습니다. 모든 시즌·물리 휴대폰·아직 공급되지 않은 규칙의 검수를 뜻하지 않습니다.</p>
<h3 id="idol-condition-foundation">컨디션과 몬스 배정 정보의 저장</h3>
<p>컨디션·배정 몬스·변경 버전을 현재 아이돌 상태에 보존하고 기존 전체 실행 checkpoint와 함께 저장·복원합니다. 저장된0은 그대로 유지하고 새 필드가 없는 이전 저장에만 초기100·미배정을 추가합니다.</p>
<p>컨디션 설정은 기존 TABLES·실행 서명과 분리하여 정책 파일 추가만으로 원래 실행이 무효화되지 않게 합니다. 현재값은 뉴런·현황판 전달과 게임 시뮬레이터 전송에도 포함합니다.</p>
<p>데이터·저장에 이어 실제 성장의 단계별 획득량과 피로를 연결했습니다. 배정 화면·게임·회복을 연결했습니다. 배정 몬스의 실제3D 모델을 연결했으며 전체 아이돌 요약 UI와 실제 화면 검수는 진행 중입니다.</p>

<h4 id="idol-condition-growth-settlement">실제 성장 정산 연결 현황</h4>
<div class="table-scroll"><table><thead><tr><th>구간</th><th>현재 연결 범위</th></tr></thead><tbody><tr><td>성장 정산</td><td>카드·레슨·학습·시설·아카데미·후합류 보너스·콘텐츠·방치 계산의 시작 단계 고정과 최종 실제 증가 피로를 연결. 초기/복원/중복/파생 평균은 차감0</td></tr><tr><td>비율과 단위</td><td>5/4/3/2/1단계 획득100/95/85/70/50%. 정규화18세부 합1점당 컨디션0.25, 언어1점당0.025. 표시 배수는 정산 전에 환산</td></tr><tr><td>이월과 원복</td><td>이미 보정된 이월은 재배율하지 않고 실제 수령 때만 피로. 일상한/아카데미 취소분0. 저장 실패 시 능력·컨디션·영수증을 함께 복원</td></tr><tr><td>영수증</td><td>아이돌 last_growth와 최근 행동 요약만 보존. 과거 전체 중복은 기존 카드/시설/콘텐츠 장부가 차단. 같은 보상 재연출은 새 차감 아님</td></tr><tr><td>남은 구현</td><td>전체 아이돌 요약 UI→실제 화면·장기 통합 실측</td></tr></tbody></table></div>
<p>정책은 <a href="/data/simulator/idol-condition.json">컨디션 설정 JSON</a>, 계산은 공통 idol-condition-growth 모듈을 사용합니다. 기존 표·운영 카드 수치·상한을 바꾸지 않습니다. 컨디션 게임의 실제 처치·패배 결과를 같은 실행의 영수증으로 저장한 경우에만 회복합니다. 처치는100까지, 패배는 빈 만큼×진행률이며 나가기·취소는0입니다.</p>

<h4>현재 컨디션 규칙과 캐릭터 정보 연결</h4>
<p>컨디션 전투는 이동형 CRUSHER와 TITAN을 사용합니다. 고정형 NEXUS는 이 모드에서 제외하고 기존2·5단계를 CRUSHER로 연결합니다. 원래 스퀘어 게임의 NEXUS·벽 패턴과 원본 자산·CSV는 변경하지 않습니다.</p>
<p>개인 컨디션은0~100이며 기획사 나쁜 기운과 별개입니다. 캐릭터 정보의 개별 능력에서 컨디션·배정 몬스·게임 입장 상태를 확인합니다. 미배정은 기존 몬스 배정 화면으로, 배정됨은 같은 아이돌의 기존 컨디션 게임으로 연결합니다. 사용한 몬스는 게임 종료 후24시간 쉬며 다른 아이돌에게 옮겨도 제한을 유지합니다. 패배도 사용으로 세고 나가기·안전 취소는 회복0·사용 횟수 제외입니다.</p>
<p>현재 회복 방식은 정책 v6의 fill_by_progress입니다. 전투 설정의 웨이브 표는3단계 기준이며, 다른 단계는 보스 등장 시간의 비율로 웨이브·종대 시각을 늘리거나 줄입니다. 스킬 선택 카드는 전투 화면 크기를 바꾸지 않고 하단에 겹쳐 표시하며 전투·선택권 누적은 계속됩니다. 보스 처치는100까지, 패배는 정산 시점의 빈 만큼×진행률을 회복합니다. 고정 회복값 recovery_bp와 기본 보스 시간은 fixed 방식의 값이므로 현재 방식의 회복량·단계별 시간으로 쓰지 않습니다. 실제 결과와 중복 지급 검사는 기존 계산·저장 어댑터가 맡습니다.</p>
<p>발란스 자동 진행에서만 컨디션50% 이하이고 배정 몬스가 쉬지 않을 때 자동 사용합니다. 현재 자동 판은 완주를 가정한 시험 계산이며 실제3D 플레이 결과가 아닙니다. 시뮬 하루는86400초로 계산하고 주사위 한 번 또는 오프라인 계산이 끝난 뒤 검사합니다. 여러 날 오프라인 계산은 마지막에 한 번만 검사합니다. 본 게임 수동 플레이에 자동 완주를 적용하지 않습니다.</p>
