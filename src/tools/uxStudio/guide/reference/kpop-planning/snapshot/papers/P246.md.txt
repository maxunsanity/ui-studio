# 아이돌 기본 동작 · 포즈 · 모션 수집 기획서 v01

**이 문서는** 보유 아이돌 한 명마다 붙는 2D 그림과 동작(포즈 · 모션)을 정하고, 카드 1장 = 포즈 1장 + 모션 1개 해금, 카드 밖 보상으로 얻는 보너스 포즈, 총 포즈 수량과 ComfyUI 생산량, 포토카드 화면과 아이돌 능력 보기 화면의 연동, 주간 MV 컷씬이 동작을 고르는 법을 정리한 기획서입니다.

**보는 법** 1장 목적 → 2장 읽은 원본 → 3장 구조도 → 4장 동작 목록 → 5장 해금 연결 → 6장 보너스 포즈 → 7장 리소스 세트 · 총 포즈 수량 → 8장 2D · ComfyUI 규격 → 9장 동작 보기 → 10장 포토카드 ↔ 아이돌 능력 보기 → 11장 MV 컷씬 → 12장 40자리 나눔 · 표 연결 → 13장 카드 ID 규칙 → 14장 뒷 수정 목록 → 15장 7007 기획서툴 확인 → 16장 초안 파일 → 17장 동작 연결 구조(애니메이터 표).

**지금 상태** 산출 폴더 초안입니다. `data` · `data/master` · 라이브 CSV · `schema.ts` · 화면 코드는 바꾸지 않았습니다. 작성 유르넷(총괄) · 2026-11-14 (KST). 이전 판 백업: `산출/개발진행기획_v01/_backup/20261114_1519_유르넷_모션기획서/`.

## 4. 아이돌 동작 목록 (19행)

- **동작 종류 19개** = 기본 대기 1 + 카드 12(대기 4 · 리액션 3 · 퍼포먼스 4 · 시그니처 1) + 보너스 포즈 6. 30명 모두 같은 동작 종류를 쓰고, 그림은 1차 2D 리소스 세트 5개 중 배정된 세트를 읽습니다.
- 우선: 필수 1차 5 · 무비용 8 · 확장 6.
- 급은 비앙카 별비중표 그대로: ★1 대기 · ★2 리액션 · ★3 · ★4 퍼포먼스 · ★5 시그니처. 그래서 ★1 네 칸은 카드 주제를 살린 **대기 변형**(마이크 · 리듬 · 비트 · 거울)입니다.
- ID 규칙: `character_motion_idol_{급}_{동작}`, 3D `anim_…`, 2D 컷 slot `motion_2d_…`(sort_order = 컷 번호).
- 감정 · 표정 분류: 평온 · 미소 · 웃음 · 설렘 · 신남/환호 · 감동 · 놀람 · 집중/몰입 · 자신감/당당/카리스마 · 행복 · 뿌듯.

### 7-3. (b) 3D 실제 리소스

- 실제 출시 리소스는 3D입니다. 실제 캐릭터마다 나중에 만들고, 만들어지면 `resource_variant`(`variant_type=anim_clip` · `model_path`)로 **같은 motion_id · 같은 슬롯**에 붙여 2D를 대신합니다. 동작 목록 · 해금 표 · 컷씬 데이터는 그대로 씁니다.
- 3D 수량은 실제 캐릭터 수에 따라 정해지므로 이 기획서에서 용량을 계산하지 않습니다. 1명당 붙는 자리는 7-1과 같습니다(모델 1 + 애니 클립 19).

## 8. 2D 그림 · ComfyUI 출력 규격 · 리소스 슬롯

- 이 장의 규격은 **1차 2D 리소스(개발 · 시뮬 확인용)** 기준입니다. ComfyUI 생성 → 바탕 제거(투명) → 256색 양자화로 줄여 저장. 실존 인물 · 실존 IP를 닮지 않게(헌법 제9조). 한 아이돌 그림은 같은 캔버스 · 같은 바닥선.

## 10. 포토카드 ↔ 아이돌 능력 보기 연동

- 아이돌 능력 보기 = 기존 `docs/planning/idol-growth-neuron.html` 「아이돌 개인 성장 · 3D 뉴런」의 「{이름} 개인 능력 보기」(P174 · P107). 화면 구조는 그대로 두고 입구 버튼과 키만 맞춥니다.
- 두 화면은 **같은 `character_master_id` · 같은 보유 아이돌 행 · 같은 카드 칸 행**을 읽습니다(P107 「카드 결과는 같은 멤버 ID로 받는다」).

```mermaid
flowchart LR
  K["character_master_id · 보유 아이돌 행"] --> P["포토카드<br/>목록 → 12칸 · 보너스 → 동작 보기"]
  K --> A["아이돌 능력 보기<br/>6축 18세부 · 뉴런"]
  P -- 능력 보기 --> A
  A -- 카드 12칸 · 동작 보기 --> P
  G["카드 획득"] --> C["카드 칸 owned=1"]
  C --> U1["능력 갱신(12칸 덱 능력)"]
  C --> U2["포즈 · 동작 해금"]
  RW["포즈 미션 완료"] --> U2
  U1 --> A
  U2 --> P
```

| 흐름 | 순서 |
|---|---|
| 포토카드 → 능력 보기 | 아이돌 상세 「능력 보기」 → 같은 id로 능력 보기 |
| 능력 보기 → 카드 12칸 · 동작 보기 | 능력 보기 머리 버튼 → 포토카드 같은 아이돌 상세 |
| 카드 1장 획득 | ① 칸 owned=1 → ② 능력 갱신(P107) → ③ 같은 칸 포즈 · 동작 해금 → ④ 두 화면이 같은 행을 다시 읽어 새 해금 배지 |
| 포즈 미션 완료 | 보너스 칸 해금만(능력은 바뀌지 않음) → 포토카드 배지 |

- 화면 구조도까지만 정했고 실제 UI 제작 · 시뮬 부착은 하지 않았습니다.

## 11. 무비 · MV 컷씬이 동작을 고르는 법

- 주간 출품 = 음원 + 영상, 영상이 없으면 아이돌 이미지 자동 컷씬, 편집은 사진 컷씬 + 모션샷(R-06-12 · R-08-2). 월드는 외부 mp4 3분(R-08-19).
- 자동 컷씬은 **출품 팀 멤버가 해금한 동작만** 씁니다.

| 곡 구간 | 1순위 | 없으면 |
|---|---|---|
| 인트로 | idol_react_confident_wave · idol_idle_rhythm_step | idle_basic + 대표 포즈 |
| 벌스 | idol_perform_live_sing · idol_idle_beat_nod | idol_idle_mic_ready |
| 프리코러스 | idol_idle_rhythm_step · idol_perform_keyboard | idol_idle_mic_ready |
| 코러스 · 킬링 파트 | idol_perform_killing_part | idol_idle_rhythm_step |
| 브리지 | idol_react_touched · idol_react_laugh_clap | idol_idle_mirror_pose |
| 엔딩 | idol_signature_ending | idol_perform_broadcast_heart → idol_idle_mirror_pose |
| 사진 컷 사이 | 포즈 미션 보너스 포즈(트로피 · 깃발 · 투샷) | 대표 포즈 |

- 이어 붙이기: 앞 동작 끝 자세 = 뒤 동작 시작 자세면 바로, 다르면 idle_basic 1컷 또는 컷 전환. 「다음 동작」 열이 1순위.
- 박자: 연속 컷을 한 박자 또는 반 박자에 1장. 3D 교체 뒤에는 같은 motion_id의 `anim_…`을 같은 구간에 재생.

## 15. 7007 기획서툴에서 404였던 이유

- 7007은 `vite`(레포 루트가 root, `publicDir: data`)입니다. 레포 파일을 **경로 그대로** 내주고 루트에 `index.html`이 없어서 `http://127.0.0.1:7007/`는 404였습니다.
- 기획서툴 입구는 `/docs/planning/planning-docs-tool.html`이고, 문서는 `data/planning_doc_catalog.csv`에 등록된 번호로 엽니다(`?face=shelf&doc={번호}`). 이 기획서는 11/14에 catalog P246으로 등록되어 `?face=shelf&doc=P246`으로 열립니다(짝 html도 같은 날 생성). md 파일 자체는 `/docs/planning/삼중AI_공용_20260929/산출/개발진행기획_v01/캐릭터_기본동작_모션목록_v01.md`(URL 인코딩)로 200이지만 글자 그대로 보입니다.
- 처음 작성 때는 catalog에 등록하지 않아 캡처를 md → HTML 렌더로 찍었습니다.

| `character_animator` | 인물 종류별 동작 묶음과 기본 동작 | 컨트롤러 | 4 (아이돌 · 스태프 · 기획사 · 팬클럽 회장) |
| `character_animator_state` | 묶음 안의 동작 하나하나. 반복 여부, 시작 · 끝 자세, 마지막 장 멈춤, 해금 줄 | 상태 | 40 |
| `character_animator_signal` | 동작을 바꾸는 신호 | 파라미터 · 트리거 | 17 |
| `character_animator_transition` | 어느 동작에서 어느 동작으로, 무슨 신호에, 몇 번째로, 어떻게 이어 붙일지 | 연결선 | 122 |
| `character_motion_clip` | 동작 × 그리는 방식(2D · 3D) → 실제 그림 자리 | 클립 | 58 (동작 29 × 2) |

### 17-1. 상태 (`character_animator_state`)

- 아이돌 묶음은 동작 목록 19행과 1:1입니다(대표 10자리는 17-5). `state_kind`는 4장 분류(대기 idle · 리액션 react · 퍼포먼스 perform · 시그니처 signature · 보너스 포즈 bonus_pose).
- 자세 열쇠는 4장 글을 그대로 옮긴 여덟 가지입니다.

| 열쇠 | 4장 글 |
|---|---|
| `pose_stand_basic` | 기본 선 자세 |
| `pose_mic_hold` | 마이크 든 자세 |
| `pose_seated` | 앉은 자세 |
| `pose_stage_start` | 무대 시작 자세 |
| `pose_killing_end` | 킬링 파트 끝 자세 |
| `pose_hold` | 포즈 유지 |
| `pose_heart_hold` | 손하트 유지 |
| `pose_ending_hold` | 엔딩 포즈 유지(마지막 장 정지) |

- `hold_last_frame = 1`은 끝 자세가 「유지」인 동작입니다. `character_motion_unlock_id`로 그 동작이 열렸는지 봅니다.

### 17-2. 신호 (`character_animator_signal`)

| 신호 | 언제 | 근거 |
|---|---|---|
| `request` | 반복 동작에서 다음 동작으로 넘어갈 때 | 4장 「다음 동작」 |
| `motion_end` | 반복하지 않는 동작이 끝나면 자동으로 | 4장 「반복」 · 「다음 동작」 |
| `preview_play` | 포토카드 동작 보기에서 고른 동작을 재생 | 9장 |
| `song_intro` · `song_verse` · `song_prechorus` · `song_chorus` · `song_bridge` · `song_ending` · `song_photo_gap` | 자동 컷씬이 곡 구간에 맞는 동작을 고를 때 | 11장 |

| `dialogue_enter` · `dialogue_speak` · `dialogue_listen` | 대사창에서 그 인물이 등장하거나 말하거나 듣는 줄일 때(대표 10자리) | 17-5 · P239 |
| `outcome_great` · `outcome_miss` | 칸 도착 판정이 대박 · 운망일 때 | 헌법 제6조 · 02장 |
| `schedule_work` | 스케줄 스태프 자리 · 개인 레슨에 나가 있는 동안 | P241 · 05장 R-05-23 |
| `stage_cheer` | 주간 · 월드 페스티벌 무대가 진행되는 동안 | 08장 |

- 지금 표에는 이 기획서와 P239에 근거가 있는 신호만 넣었습니다. 보드 칸 도착 · 카드 획득 같은 게임 신호는 화면에 붙일 때 이 표에 줄을 더하고 연결선을 답니다.

### 17-3. 연결선 (`character_animator_transition`)

| 묶음 | 줄 | 만든 규칙 |
|---|---|---|
| 4장 「다음 동작」 | 47 | 반복 동작은 `request`, 1회 동작은 `motion_end`. 기본 대기는 「모든 동작」이라 나머지 18개로 모두 이어짐. 적힌 순서가 `priority` |
| 11장 곡 구간 | 20 | `from_state_id = any`. 1순위 동작이 앞 번호, 「없으면」 동작이 뒤 번호 |
| 9장 동작 보기 | 19 | `any` → 고른 동작 |
| 17-5 대표 10자리 | 36 | 묶음 3개 × 12줄(동작 6개마다 들어가는 줄 1 + 기본 대기로 돌아가는 줄 1) |

- `need_unlocked = 1`: 열리지 않은 동작으로 가는 줄은 건너뛰고 다음 `priority` 줄을 봅니다(11장 「출품 팀 멤버가 해금한 동작만」).
- `join_mode`는 11장 이어 붙이기 규칙을 값으로 옮긴 것입니다.

| 값 | 뜻 | 줄 |
|---|---|---|
| `direct` | 앞 동작 끝 자세 = 뒤 동작 시작 자세 → 바로 이어 붙임 | 41 |
| `via_idle_cut` | 자세가 다름 → 기본 대기 1컷 또는 컷 전환을 사이에 둠 | 24 |
| `by_pose` | 출발 동작이 정해지지 않은 줄(`any`). 그때의 끝 자세와 도착 동작의 시작 자세를 비교해 위 둘 중 하나로 정함 | 57 |

### 17-4. 클립 (`character_motion_clip`)

| 그리는 방식 | 그림 자리 | 길이 · 속도 | 지금 |
|---|---|---|---|
| `2d` | 첫 컷 = 포즈 그림(`card_pose_NN` · `bonus_pose_NN`), 이어지는 컷 = `motion_2d_{동작}` · 512×768 | 컷 수는 4장 「2D 표현」, 속도는 `beat`(한 박자 또는 반 박자에 1장) | 기본 대기와 카드 12칸의 첫 컷 샘플 그림 있음(13), 보너스 6칸은 그림 없음 |
| `3d` | `anim_…` 클립 이름, `resource_variant`의 `anim_clip` | `clip_length`(클립 길이 그대로) | 리소스 없음. `fallback_render_kind = 2d`라 2D로 보여 줌 |

- 3D 리소스가 나오면 이 표의 3D 줄에 `resource_ready = 1`만 바꾸고 `resource_variant`에 줄을 답니다. 상태 · 신호 · 연결선 · 해금 표는 그대로입니다.
- 한 인물이 어느 리소스 세트를 쓰는지는 `character_master.resource_set_id`(7장)가 정하고, 클립은 세트 안의 자리 이름만 가리킵니다.

### 17-5. 대표 10자리 묶음 (스태프 · 기획사 · 팬클럽 회장)

현중 11/15 「응 만들어줘」 · 「스태프와 팬 동작 설정은 니가 결정해서 만들어」 · 「그림은 나중에 하고 구조만 만들어 놓고」. 11/14에는 포즈 · 동작을 아이돌에게만 두었고(1장 15:23), 대표 10자리는 대표 그림 1장뿐이었습니다. 연결 구조가 생겨 대표 10자리도 묶음을 하나씩 두고, 동작은 그 인물이 게임에서 하는 일에 맞춰 클로드가 정했습니다. 해금 없이 처음부터 씁니다. 그림은 아직 만들지 않고 자리만 둡니다.

| 묶음 | 인물 | 동작(상태 7) |
|---|---|---|
| `character_animator_staff` | 스태프 6(보컬·랩 · 댄스 · 작곡 · 연기 · 스타일리스트 · 무대 디렉터) | 기본 대기 · 인사 · 말하기 · 끄덕이며 듣기 · 박수 칭찬 · 아쉬워하기 · **지도하기** |

- 모든 동작은 끝나면 기본 대기로 돌아갑니다(1회 동작은 `motion_end`, 반복 동작은 `request`). 연결선은 묶음마다 12줄입니다.
- 동작 원본은 `character_motion_npc.csv`(10행)이고, 어느 묶음이 쓰는지(`use_group`) · 들어가는 신호(`enter_signal`) · 다음 동작이 한 줄에 있습니다. 아이돌 동작 표(19행)와 해금 표(19행)의 행 수는 그대로입니다.
- 그림: 첫 컷 자리는 대표 그림(`portrait_main`), 컷 수는 비어 있음(0으로 동작), 클립 표의 `resource_ready`는 모두 0입니다. 그림은 나중에 만듭니다.

## 18. 2D · 3D 리소스 표 (라이브)

현중 11/16 「리소스는 3d 와 2d 리소스 둘다 추가해놔」 · 「2d 리소스 테이블과 3d 리소스 테이블을 만들고 2d 리소스는 우리 지금 만들어 놓은거 추가하고 3d 리소스 테이블은 나중을 위해 … 애니메이터 중심의 리소스 테이블로」. 7장(2D 세트 · 3D 교체) · 8장(2D 슬롯) · 17장(애니메이터)을 실제 표로 옮깁니다. 17장 초안 8개도 같은 이름으로 `data/master`에 올립니다.

```mermaid
flowchart LR
  CM["character_master<br/>character_type · seat_group · card_deck_id"] -->|character_animator_id| AN["character_animator<br/>동작 묶음"]
  AN --> ST["character_animator_state<br/>동작(상태)"]
  CM -->|resource_2d_set_id| R2["character_resource_2d<br/>만든 그림 한 장 = 한 줄"]
  CM -->|resource_3d_set_id| M3["character_resource_3d_model<br/>모델 · 뼈대"]
  M3 --> C3["character_resource_3d_clip<br/>세트 × 동작 = 클립"]
  ST --> C3
  C3 --> E3["character_resource_3d_event<br/>클립 안 타이밍"]
  M3 --> F3["character_resource_3d_face<br/>표정(모프)"]
  M3 --> A3["character_resource_3d_attach<br/>손에 드는 소품"]
```

### 18-1. 캐릭터 마스터에 더한 열

| 열 | 값 | 쓰임 |
|---|---|---|
| `seat_group` | idol_30 · staff_6 · company_3 · fan_leader_1 | 40자리 어느 묶음인지 |
| `card_deck_id` | card_theme_idol · card_theme_staff_{자리} · card_theme_fan_president | 그 자리 카드덱(카드 기획서 4-1a). card_theme 11덱 교체 전이라 아직 표 연결 검사는 걸지 않음 |
| `character_animator_id` | character_animator_idol · staff · company · fan_leader | 동작 묶음(17장) |
| `resource_2d_set_id` | 아이돌 5세트 `character_resource_2d_set_{이름}` | 2D 그림 묶음. 대표 10자리는 그림이 없어 비어 있음 |
| `resource_3d_set_id` | 비어 있음 | 3D 실제 리소스가 들어오면 채움. 비어 있으면 2D로 보여 줌(8장) |

- `character_type` 옵션값에 staff · company · fan_leader를 더했습니다. 대표 10자리(스태프 6 · 기획사 3 · 팬클럽 회장 1)는 **자리 틀** 줄 10개이고, 섭외된 실제 인물은 저장에 들어갑니다.

### 18-2. 2D 리소스 표 `character_resource_2d`

- 지금 만들어 둔 1차 2D 그림(`1차리소스_아이돌5`) 5세트 × 15장 = **75줄**. 한 장 = 한 줄이고, 크기 · 용량은 실제 파일을 재서 적었습니다.
- 슬롯: `portrait_main` 1 · `portrait_thumb` 1 · `card_pose` 0~12(13장). 보너스 포즈 6 · 연속 컷 · 대표 10자리 대표 그림은 아직 만들지 않아 줄이 없습니다.
- 카드 포즈 실제 크기는 384×576으로, 8장 규격(768×1152)의 절반입니다.

### 18-3. 3D 리소스 표 (애니메이터 중심)

3D는 **동작(애니메이터 상태)마다 어느 클립을 어떻게 트는지**를 중심에 둡니다. 게임은 신호만 보내고(17장), 상태가 정해지면 그 인물의 3D 세트에서 그 상태의 클립 줄을 찾아 틉니다. 줄이 없거나 `resource_ready = 0`이면 2D로 보여 줍니다.

| 표 | 한 줄 | 주요 열 | 애니메이터로 치면 |
|---|---|---|---|
| `character_resource_3d_model` | 3D 세트 하나의 모델 | 모델 파일 · 뼈대 종류(humanoid · generic) · 뼈 수 · 기준 뼈(root · hips · head · 양손) · 표정 수 · 크기 · 바닥 높이 | 모델 + 아바타 |
| `character_resource_3d_clip` | 세트 × 동작 상태 | 클립 이름 · 층(body 몸 · face 얼굴) · 길이 · 반복 · 제자리 여부(root_motion) · 속도 · 섞어 들어가기 · 나가기 시간 · 박자 맞춤 | 상태에 붙는 클립 + 전환 시간 |
| `character_resource_3d_event` | 클립 안의 한 순간 | 0~1 위치 · 종류(소리 · 효과 · 박자 · 소품 보이기) · 대상 | 애니메이션 이벤트 |
| `character_resource_3d_face` | 모델의 표정 하나 | 모프 이름 · 표정 종류(눈 감기 · 찡그림 …) · 켜는 클립 | 블렌드셰이프 |
