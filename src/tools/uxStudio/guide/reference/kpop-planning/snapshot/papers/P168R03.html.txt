<h2>1. 이번에 바꿀 방향</h2>
<p><strong>카드 이름 → 게임 효과 한 문장 → 받는 멤버별 능력명과 +상승량 → 보유·덱 수집</strong>으로 모바일 카드와 발란스툴 상세를 맞춥니다. 가장 중요한 숫자는 카드 표의 원량이 아니라 그 카드가 실제로 올린 세부 능력의 증가량입니다.</p>
<p>현중이 제시한 두 화면과 인용 대화에서 요구한 “기획 반영 시점 같은 이상한 글자 제거”, “게임 카드 설명처럼”, “양쪽 시뮬레이터 모두”, “효과가 실제 적용되는지 확인”을 계획과 수락 기준에 반영합니다. 인용된 작업 시간·하위 작업 시작·수행 약속을 이 채팅의 개발 완료 사실로 옮기지 않습니다.</p>
<p>게임 화면에는 내부 처리 용어와 빈 설명 행을 반복하지 않습니다. 실제 값이 없는 상태는 짧게 알리며 가짜 +0이나 가짜 상승량을 넣지 않습니다. 계산 근거·임시 상태·원본 키는 기획 문서와 검수용 영역에 보존합니다.</p>

<h3>출처가 있는 수치 예시</h3>
<p>아래는 새 발란스 값이 아니라 <strong>현재 표와 코드식의 조건부 산술 검산</strong>입니다. 실제 카드 획득 시험 결과가 아닙니다.</p>
<ul><li>원량 0.18: card.csv의 1성 단일 대상 카드입니다.</li><li>1단계 폭: 화면 점수 10,000점입니다. 현재 천장 척도와 점수배율1000, 단계0~10%에 따른 값입니다.</li><li>기준 입력: dice_unit_core=0.058, need_dice_base=3300, step_coef=1, early_boost=1입니다.</li><li>전량·1차 구간·비포지션·경계/천장/상한에 걸리지 않는 조건이면 10,000×(0.18÷0.058)÷3300 = 9.404388…입니다. 화면에는 <strong>+9.4</strong>로 표시합니다.</li><li>같은 조건에서 포지션25% 보정이 붙으면 11.755485…이며 화면에는 <strong>+11.8</strong>입니다.</li><li>이 두 숫자를 모든 1성 카드·모든 멤버에 고정하지 않습니다. 실제 단계·재능 경계·대상·분할·포지션에 따라 달라집니다. 시안의 예시 멤버와 시작값0, 재능1순위가 음정으로 선택되는 조건은 검산용이며 실제 팀원이 아닙니다. 아주 작은 상승 상태는 표기법을 설명하는 가상 예시이며 특정 멤버의 실제 기록이 아닙니다.</li></ul>
<p>현재 표 값은 임시(나중에 결정)·발란스 대기 상태를 유지합니다. 새 기본량·새 비율·새 보상을 입력하지 않았습니다.</p>
<h3>정밀도와 단위</h3>
<p>기존 현중 지시대로 게임 화면은 <strong>최대 소수점 한 자리</strong>입니다. 내부 계산과 기록은 원본 정밀도를 보존합니다. 반올림한 전후값을 빼서 증가량을 구하지 않습니다.</p>
<ul><li>9.404… → +9.4, 실제0 → +0입니다.</li><li>0보다 크고0.1보다 작으면 <strong>0.1 미만 상승</strong>으로 표시합니다. 작은 양수를 +0으로 숨기지 않습니다.</li><li>현재값이8.7→8.7로 보이더라도 원본 차이가 양수이면 ‘0.1 미만 상승’이 함께 보입니다.</li><li>값이 없으면 ‘상승량 기록 없음’, 정의가 비면 ‘효과 수치 미정’입니다. 둘을0으로 바꾸지 않습니다.</li><li>카드 효과 숫자는 k/M 축약을 쓰지 않고 쉼표를 포함한 실제 점수를 표시합니다. 팀 평균·6축 평균·18세부 합은 다른 값이며 별도 보상처럼 더하지 않습니다.</li></ul>
<h2>4. 플레이어가 읽는 카드 설명</h2>
<table><thead><tr><th>현재 문구</th><th>새 화면 문구·처리</th></tr></thead><tbody><tr><td>기획 효과 / 기획 대상 / 기획 반영 시점</td><td>표를 걷고 효과 한 문장 + ‘팀 전체 · 첫 획득 시 1회’ 칩으로 정리합니다.</td></tr><tr><td>재능 1순위 · 받는 멤버마다 해당 재능을 확인합니다</td><td>‘팀원마다 재능 1순위 능력이 오릅니다.’로 설명합니다. 결과는 각 멤버의 실제 능력명으로 풀어 씁니다.</td></tr><tr><td>팀 전원 · 각자 흡수율로 능력 성장</td><td>대상은 ‘팀 전체’로 짧게 표시합니다. 상승량은 멤버별 숫자로 보여줍니다.</td></tr><tr><td>능력 성장 · 주 효과</td><td>중복된 분류 줄을 생략합니다.</td></tr><tr><td>보조 옵션 없음</td><td>빈 보조 영역 자체를 생략합니다. 확정된 보조가 있을 때만 별도 효과를 표시합니다.</td></tr><tr><td>표 효과량0.18 · 임시(나중에 결정)</td><td>일반 카드 설명에서는 뺍니다. 검수용 계산 근거로 보존합니다.</td></tr><tr><td>성장 반영 연결 대기</td><td>실제 상태로 분기합니다. 결과가 있으면 제거하고, 수치 미정/기록 없음/중복/실제0을 각각 알립니다.</td></tr><tr><td>획득 전후 성장에 보유0→1</td><td>‘보유0→1장’으로 따로 표시합니다. 성장 결과는 능력명과 실제+수치입니다.</td></tr></tbody></table>
<p>‘첫째 재능’ 카드 이름만으로 구체 능력을 모르는 문제가 남으므로, 상세에는 멤버별 능력 이름과 숫자가 반드시 함께 나옵니다. 예를 들어 카드명과 관계없이 수신 멤버의 음정·안무 정확도처럼 실제 정산된 세부 이름을 씁니다. 카드명의 인물은 덱 인물이며 효과 받는 멤버 전체와 같다고 가정하지 않습니다.</p>
<h2>5. 두 화면의 배치</h2>
<h3>모바일 게임 시뮬레이터</h3>
<p>상단 공통 재화·팀/멤버 정보·하단 공통 메뉴는 유지합니다. 카드 상세에서 큰 물음표 그림을 줄이고 <strong>그림+별·카드명·보유</strong>를 한 묶음으로 배치합니다. 그 아래에 효과 한 문장과 첫 획득 조건, 멤버별 수치가 연속해서 보이게 합니다.</p>
<ul><li>그림은 상세 본문 높이의 대부분을 차지하지 않게 제한하고, 모바일 기준 약120~160px 안에서 배치합니다. 미보유 공통 ?와 획득 후 원래 그림 공개 규칙은 유지합니다.</li><li>기존 하단 ‘카드 성장정보’는 상태에 따라 ‘획득 시 예상’, ‘이번 획득 효과’, ‘획득 당시 효과’로 표시합니다. 카드명·별·덱 이름을 위아래에 반복하지 않습니다.</li><li>멤버 한 행에는 초상/이름 → 능력명 → +상승량을 놓습니다. 전후값은 작은 보조 줄입니다. 2개 세부 효과면 같은 멤버 아래 두 줄로 묶습니다.</li><li>여러 멤버는 같은 본문에서 이어 봅니다. 본문+필러에 각각 독립 스크롤을 만들지 않습니다. 작은 높이·많은 멤버에 필요한 단일 스크롤은 허용하며 내용을 잘라 숨기지 않습니다.</li><li>‘능력 보기’는 기존 공통 모달로 연결합니다. 결과 재열람이 재지급을 실행하지 않습니다.</li><li>아래에는 보유 장수·고유n/12·12장 보기·덱 모음을 유지합니다. 카드 상세에서 카드 이동은 기존 경로를 사용합니다.</li></ul>
<h3>발란스툴 v02</h3>
<p>어두운 카드 화면 안에 <strong>작은 그림+이름/별/보유 → 효과 한 문장 → 같은 멤버별 결과 목록</strong>을 놓습니다. 현재 긴 2열 기획 항목 표와 큰 하단 공백을 줄입니다. 효과 수치 영역을 상단에서 바로 읽을 수 있게 합니다.</p>
<ul><li>모바일과 같은 결과 모델·문구·단위를 사용합니다. 양쪽에 별도 증가 계산식을 만들지 않습니다.</li><li>기본 카드 설명에는 원본 키·규칙 상태·작성자·기획 반영 시점을 붙이지 않습니다.</li><li>검수용 원량·규칙 버전·사건 ID·팀 평균·후보 범위·비율 빈칸은 별도 ‘계산 근거’ 접힘에 둡니다.</li><li>예측은 ‘획득 시 예상’, 정산 결과는 ‘이번 획득 효과’, 과거는 ‘획득 당시 효과’입니다. 조회한 결과가 어느 시점인지 제목으로 구분합니다.</li><li>같은 카드가 중복으로 다시 나왔다면 이번 결과는 중복입니다. 이전 최초 상승량은 이전 획득 이력에서만 보입니다.</li></ul>
<h2>6. 상태마다 숫자가 나오는 조건</h2>
<table><thead><tr><th>상태</th><th>게임 표시</th><th>수치 원본</th></tr></thead><tbody><tr><td>미보유·계산 가능</td><td>획득 시 예상 +멤버별 값</td><td>부작용 없는 현재 규칙 계산입니다. 획득 당시 결과와 다를 수 있습니다.</td></tr><tr><td>최초 획득·정산 완료</td><td>이번 획득 효과 / 실제 능력명 +값 / 전→후</td><td>수령 사건의 멤버별 최종 기록입니다.</td></tr><tr><td>같은 카드 중복</td><td>중복 카드 · 이번에는 능력이 오르지 않습니다.</td><td>해당 수령 건의 중복 판정입니다. 예전 card_gain을 붙이지 않습니다.</td></tr><tr><td>분할 수치 미정</td><td>효과 수치 미정</td><td>비율이 비어 있는 원본 상태입니다. 보유와 수집은 따로 갱신됩니다.</td></tr><tr><td>획득했지만 결과 기록 없음</td><td>상승량 기록 없음</td><td>+0 또는 ‘효과 적용됨’으로 바꾸지 않습니다.</td></tr><tr><td>실제 계산0</td><td>능력명 +0 · 확인된 사유</td><td>엔진에서 제공한 실제 판정만 씁니다. 천장/한도를 UI가 추측하지 않습니다.</td></tr><tr><td>아주 작은 양수</td><td>능력명 · 0.1 미만 상승</td><td>원본 delta&gt;0입니다.</td></tr><tr><td>보정형4덱</td><td>정의된 효과명·정의된 값만 표시합니다.</td><td>능력+1로 바꾸지 않습니다. 현재 미구현 효과를 발동했다고 쓰지 않습니다.</td></tr><tr><td>빈 자리·합류 전</td><td>실제 주효과 대상과 미합류 보조를 구분합니다.</td><td>정산 당시 합류 ID입니다. 보조 소급/후임 이전을 새로 정하지 않습니다.</td></tr></tbody></table>
<p>중복은 별 교환 재료라는 원칙까지 반영합니다. Q5 교환 세부는 열려 있으므로 교환 가능한 별 수·버튼·비율을 먼저 만들지 않습니다.</p>
<h2>7. 개발자가 연결할 기록</h2>
<p>현재 CardGainEvent.changes는 팀 평균 세부이고 before/after.ability는 후보 전원 배열입니다. 멤버별 결과로 쓰려면 정산하는 지점에서 같은 합류 ID 집합을 기준으로 각 멤버의 전후를 기록해야 합니다. 현재 팀과 과거 팀을 바꿔 끼우거나 이름으로 인물을 맞추지 않습니다.</p>
<p>아래는 논리 항목 제안이며 schema/CSV를 이번에 수정한 것이 아닙니다.</p>
<table><thead><tr><th>묶음</th><th>필요한 내용</th></tr></thead><tbody><tr><td>수령 식별</td><td>test_session_id·run_id·receipt_id·event_id·card_id·획득묶음 ID·출처·시각/순서입니다. 한 묶음 안의 같은 카드도 구분합니다.</td></tr><tr><td>실제 수신자</td><td>획득 당시 합류 member_id, 당시 이름, 대상 세부ID, 적용 여부와 미적용 이유입니다.</td></tr><tr><td>멤버별 변화</td><td>세부 before·after·delta의 원본 정밀도, 표시 단위, 숫자 계산에 사용한 규칙 버전입니다.</td></tr><tr><td>처리 상태</td><td>최초/중복/수치대기/능력외/오류/확정 결과입니다. 상태가 없는 것과 실제0을 구분합니다.</td></tr><tr><td>보유·수집</td><td>보유 장수 전후, 고유 수집 전후, 덱 조각 진행과 별도 완성 보상 처리입니다.</td></tr></tbody></table>
<p>기존 획득·성장 계산기를 공통으로 호출하고 <strong>정산 결과 하나를 두 UI가 조회</strong>합니다. 카드북 sessionStorage와 발란스 엔진 상태를 통째로 합치지 않습니다. 저장 소유자는 같은 세션·run의 기존 정본이며 브리지는 입력과 결과만 연결합니다. 첫 적용 완료 표식은 보유 숫자가 아니라 처리 식별자로 보존해야 합니다.</p>
<p>현재 코드의 위험과 보완 조건은 다음과 같습니다.</p>
<ul><li>app.js:1014는 같은 카드의 첫 card_gain을 찾습니다. 수령 건을 고르지 않으면 중복 카드에 예전 상승량이 붙습니다. receipt_id를 우선하여 해당 건의 card_gain/card_dup/card_wait를 묶어야 합니다.</li><li>app.js:1015~1024는 같은 카드의 모든 사건을 합칩니다. 이번 획득 결과·과거 이력·현재 보유를 분리합니다.</li><li>CardMeasure의 팀 평균 changes를 개인 값으로 복제하지 않습니다. memberChanges 같은 멤버별 기록(이름 가칭)을 기존 정산 지점에서 만듭니다.</li><li>abilityMean의 모집단과 details의 합류 대상이 다릅니다. 카드 결과는 같은 합류 ID 집합·같은 세부점수 단위여야 합니다.</li><li>수치대기여도 cardSeen이 먼저 올라갑니다. 비율을 나중에 채웠다고 과거 카드가 자동 적용되는 구조가 아닙니다. 소급 지급은 별도 결정과 중복 방지 후속 범위입니다.</li><li>현재 일일 상한은 OFF입니다.
