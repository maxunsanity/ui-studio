# AI 컷씬 마스터 · 화면 설계 v0.2

2026-09-22 · 단이 · 구현 전 검토안

## 이번 작업의 범위

기존 편집기에 패널을 덧붙이기 전에 화면 구조 전체를 다시 설계한다. HTML은 화면 이동·씬 선택·빈 컷 카드 선택·패널 조절을 체험하는 설계안이다. 실제 파일 저장, 그림 생성, AI 실행, 3D 렌더링과 배포는 수행하지 않는다. 시나리오와 그림 콘티 작성은 다음 작업이다. 이전 시제품과 기존 씬은 그대로 보존한다.

## 1. 가장 중요한 구조

프로젝트 → 씬 파일 → 컷 → 대사·동작·카메라 트랙의 계층으로 관리한다. 씬은 이야기 한 묶음이고 컷은 촬영 구도 하나다. 대사와 배우 동작은 컷을 넘어 이어질 수 있다. 한 컷 카드 안에 표시하더라도 데이터의 재생 시간을 컷 시작에서 매번 초기화하지 않는다.

화면은 여러 독립 도구를 오가는 형태에서 **선택한 씬의 제작 과정을 따라가는 작업 공간**으로 재설계한다. 공통 외곽 화면을 유지하고 중앙 작업 영역만 제작 단계에 맞게 바뀐다. 프로젝트 공용 자산·자료실을 열어도 돌아갈 씬·컷·재생 위치를 잃지 않는다.

## 2. 공통 화면

| 영역 | 항상 알 수 있는 것 | 동작과 보존 상태 |
|---|---|---|
| 최상단 프로젝트 바 | 프로젝트 이름, 저장 위치·연결 상태, 현재 버전 | 프로젝트 전환, 저장, 가져오기·내보내기, 도움말 |
| 왼쪽 씬 파일 탐색기 | 폴더, 씬 이름, 유형, 대표 그림, 최근 수정·상태 | 검색, 열기, 새 씬, 복제, 이름 변경, 이동, 휴지통·복원 |
| 선택 씬 헤더 | 씬 이름, 리비전, 저장 여부, 전체/선택 컷 범위 | 별도 버전 저장, 비교, 씬 정보 |
| 상단 제작 마일스톤 | 7단계 상태와 현재 보고 있는 단계 | 단계 클릭 → 결과물과 작업 화면. 선택과 완료 상태를 분리 |
| 중앙 작업 공간 | 지금 할 일, 단계별 산출물·미해결 항목 | 단계 전용 편집·검토 |
| 오른쪽 단이 패널 | 현재 지시, 대상 범위, 참조 자료, 실행 기록, 검사·변경 내용 | 접기, 단계와 무관하게 같은 실행 작업 확인 |
| 단계 정보 | 상태, 막힌 이유, 결과물 버전, 마지막 갱신 | 결과 열기, 실패 항목 재시도, 필요한 입력으로 이동 |

화면을 크게 쓸 때 단이 패널을 접는다. 좁은 화면에서는 씬 목록과 단이 패널을 접이식으로 전환한다. 마일스톤은 가로로 이동할 수 있게 하며 항목 이름을 알아볼 수 있어야 한다. 상태는 색뿐 아니라 텍스트로 표시한다.

## 3. 화면과 경로

| ID | 화면 | 진입 | 중앙 내용 | 오른쪽 정보 |
|---|---|---|---|---|
| W00 | 프로젝트·씬 파일 | 상단 프로젝트 / 왼쪽 씬 목록 | 폴더별 씬, 썸네일·목록 전환, 유형·상태 필터 | 선택 파일 정보, 사용 자산, 이력·복원 |
| W01 | 요청 정리 | 마일스톤 01 | 사용자 원문, 단이의 구조화 요청서, 가정·미결 | 제작 범위, 원하는 결과·금지 조건 |
| W02 | 리소스 확인 | 마일스톤 02 | 인물·배경·모션 목록, 파일 연결·검수 상태 | 선택 자산 세부, 모델별 사용 가능 구간 |
| W03 | 연출자료 검토 | 마일스톤 03 | MD·기법 카드·영상 검색, 채택/제외, 근거 | 조건 적합성·선택 이유·자료 버전 |
| W04 | 그림 콘티 | 마일스톤 04 | 컷별 그림 카드, 선택 컷 확대, 대사·연출 | 컷 속성·참고 자료·변경 범위 |
| W05 | 애니매틱 | 마일스톤 05 | 큰 재생 화면, 컷 스트립, 대사·소리 시간축 | 타이밍, 검토 메모, 음성 유무 |
| W06 | 씬 제작 | 마일스톤 06 | 큰 촬영 화면, 아래 자유 시점 공간, 시간축 | 컷·배우·카메라 속성 / 단이 패널 전환 |
| W07 | 재생 검수·비교 | 마일스톤 07 | 전체/부분 재생, 문제 목록, 이전/현재 비교 | 검사 근거, 수정 지시, 저장·출력 |

기존 S01~S08을 새로운 화면에 대응시킨다. S01→W00, S02/S07→W03의 영상 연구·자료실, S03→W01/W04, S04→W06, S05→W02의 모션 검수, S06→W07. S08 AI 제작 작업실은 별도 고립 화면 대신 모든 W01~W07의 공통 단이 패널로 통합한다. 기존 기능의 삭제를 의미하지 않는다.

## 4. 그림 콘티 화면 W04

중앙 상단에 씬 이름·컷 수·길이·콘티 버전·보기 전환을 표시한다. 그 아래 시간순 그림 카드를 기본 2~3열로 배치한다. 카드 높이의 대부분은 그림이며, 긴 설명은 선택 컷 상세에서 확인한다. 컷이 없으면 임의 시나리오를 넣지 않고 ‘콘티 작성 전’을 표시한다.

각 카드에는 컷 ID, 순서, 시작/끝 시간, 컷 이름, 대표 그림, 촬영 구도, 화자·대사 요약, 동작·검토 상태를 넣는다. 클릭하면 같은 컷의 확대 그림과 전체 대사·청자 반응·카메라 의도·출처를 확인한다. 카드 순서 변경은 컷 ID를 바꾸지 않으며 영향받는 타이밍을 재계산한다.

카메라나 인물 움직임이 큰 컷은 시작·중간·끝 프레임을 선택해서 본다. 세 프레임을 모든 카드에 항상 펼치지 않는다. 경로 화살표와 시선 표시는 별도 오버레이로 켜고 끈다.

이미지 출처를 구분한다: 실제 3D 장면에서 캡처 / 단순 인물 모형 프리비즈 / 업로드 참고 그림 / 생성 컨셉 이미지. 컨셉 이미지나 참고 그림을 실제 씬과 일치하는 캡처로 취급하지 않는다. 기본 제작 결과는 실행 씬과 같은 구도로 캡처하는 방식을 목표로 한다. 컷별 그림의 원본 씬 리비전·카메라·시간·프레임을 기록한다.

하단 선택 컷 비교 영역은 ‘콘티’와 ‘실제 씬 미리보기’를 나란히 본다. 아직 구현된 씬이 없으면 ‘미리보기 없음’으로 표시한다. 그림 생성 실패·이미지 누락·낡은 리비전도 각각 구분한다. 카메라가 바뀌면 이전 이미지를 보존하면서 재캡처 필요를 표시한다.

## 5. 제작 마일스톤

01 요청 정리 → 02 리소스 확인 → 03 연출자료 검토 → 04 그림 콘티 → 05 애니매틱 → 06 씬 제작 → 07 재생 검수.

이것은 실제 작업 상태다. 단계 탭을 클릭하거나 그림 하나를 생성했다고 단계 전체를 완료하지 않는다. 목표 씬에 해당하는 결과와 검사를 갖춰야 완료할 수 있다. 미완성 단계도 열어 내용을 확인할 수 있다. 수정할 때마다 승인 창을 띄우지 않으며 이미 받은 제작 지시 범위에서 단이가 진행한다. 사용자 선택이 필요한 문제만 ‘검토 필요’로 남긴다.

| 단계 | 완료 근거 | 막힘 예 |
|---|---|---|
| 요청 정리 | 제작 의도·대상·금지 조건·미결 영향 기록 | 사용할 캐릭터를 특정할 수 없음 |
| 리소스 확인 | 선택 파일 존재·버전 확인, 필요한 모션의 모델별 검수 | 없는 파일, 검수되지 않은 필수 동작 |
| 연출자료 검토 | 읽은 상세 문서·버전·적용/제외 이유와 컷 연결 | 적합한 근거·동작 없음 |
| 그림 콘티 | 컷 데이터와 최신 그림, 대사·행동·카메라 대응 검사 | 특정 컷 그림 없음, 데이터와 구도 불일치 |
| 애니매틱 | 전체 컷과 독립 대사 트랙 시간, 실제 미리보기 확인 | 타이밍 끊김, 요청한 음성 누락 |
| 씬 제작 | 편집 가능한 씬 생성·참조 자산·필수 구조 검사 | 리그 불일치·적용 실패 |
| 재생 검수 | 전체 연속 재생·진입/종료·문제 해결 근거 | 발 접지·몸 연결·가림 문제 잔존 |

단계 기록: sceneId, revision, runId, status, startedAt, finishedAt, inputs, outputs, checks, blockers, reviewedBy. ‘완료 4/7’은 단계 수이며 품질 점수나 남은 시간의 추정치가 아니다. 기존 씬은 자료를 확인하기 전 ‘미확인’으로 이관한다.

### 수정 영향

- 대사 내용 변경: 콘티 텍스트·애니매틱·씬 대사·검수 재확인. 구도에 영향 없으면 그림 전체를 재생성하지 않는다.
- 컷 카메라 변경: 해당 컷 그림·애니매틱·씬 카메라·구도 검수 재확인.
- 캐릭터·모션 변경: 관련 자산 검수와 동작, 가림·접지 검수 재확인. 영향받는 컷의 그림도 갱신한다.
- 씬 이름만 변경: 파일 메타데이터만 갱신. 완료 상태를 무효화하지 않는다.
- 자료 원문 변경: 해당 자료를 사용한 계획을 재검토. 제작 결과를 자동 폐기하지 않는다.

의존 관계로 영향받는 산출물만 ‘재검토 필요’로 표시하며 이전 정상 결과는 보존한다. 실제 판정은 입력 리비전·내용 해시 비교에 따른다.

## 6. 씬 제작 화면 W06

촬영 화면을 중앙에서 가장 크게 보여준다. 자유 시점 작업 캔버스는 그 아래에 배치하고 드래그 분할선과 키보드로 높이를 조절한다. 시간축은 최하단에 접기/확대가 가능하다. 선택 컷의 콘티를 작은 비교 패널로 열 수 있다.

촬영 카메라와 편집 탐색 카메라는 독립적이다. 작업 캔버스에서 휠 확대, 가운데 버튼 이동, 우클릭 회전, 우클릭 유지 WASD/QE 이동, F 선택 대상 집중을 제공한다. 선택 대상이 없으면 전체 프레이밍. 현재 조작 방식 안내를 캔버스 안에서 열 수 있다. 입력 필드·그림 콘티 위에서는 3D 단축키가 실행되지 않는다.

카메라 컷·인물 전신·제스처·시선·표정·대사/음성·효과는 독립 트랙으로 둔다. 카메라 컷 전환이 배우 애니메이션을 재시작하지 않는다. 오른쪽은 ‘속성 / 단이 / 검수’로 전환하며 좁은 화면에서 셋을 동시에 펼치지 않는다.

## 7. 리소스·연출 자료·단이 패널

W02 모션 검수는 정면·측면 전신 재생, 골반 이동, 발 접지, 시작/끝 자세, 사용 가능한 시간 구간을 확인한다. 전체 모션 사용과 부분 적용을 구분하며 파일 확인과 품질 검수 상태를 별도로 표시한다.

W03의 자료 원문은 요약과 별도로 직접 열 수 있어야 한다. 영상은 원본 시간·구간 프레임, MD는 문서·섹션·버전으로 이동한다. ‘이번 제작에 읽음’은 실제 조회 기록이 있을 때만 표시한다. 라이브러리에 들어 있다는 사실을 현재 작업에 검토했다는 뜻으로 쓰지 않는다.

단이 패널은 지시 입력보다 앞에 대상 씬·컷·리비전·잠금 조건을 보여준다. 실행 중에는 읽는 자료, 생성·변경하는 결과, 검사 상태를 표시한다. 새 지시는 기존 실행에 보충인지 새 실행인지 구분해 기록한다. 취소·재시도·되돌리기는 데이터 단위 명령으로 구현하고, 실패 시 마지막 정상 결과를 보여준다. 웹 내부 AI 연결 전에는 ‘실행 미연결’이며 성공 메시지를 흉내내지 않는다.

## 8. 파일 관리·저장

씬 이름과 ID를 분리한다. 원본과 복제본은 다른 sceneId, 같은 씬의 수정은 revision으로 구분한다. 씬 파일에는 자산을 중복 내장하지 않고 프로젝트 공용 ID·버전을 참조한다. 장면 파일과 컷별 그림·애니매틱·실행 결과가 같은 리비전에 연결된다.

작업 바에는 저장 위치와 상태를 항상 표시한다. 로컬 폴더 연결, 브라우저 임시 저장, 서버 저장을 혼동하지 않는다. 다른 창에서 변경되면 기준 리비전을 비교하고 사용자 편집 내용을 보존한 상태로 충돌을 해결한다. 이번 설계안은 메모리에서만 조작하며 저장 기능은 없다.

## 9. 빈 상태·실패·반응형

씬 없음: 새 씬 만들기와 파일 열기. 컷 없음: 콘티 작성 전. 그림 없음: 생성 대기·실패·연결 누락을 구분. 모션 없음: 필요 자산과 대체 가능성 표시. 영상 무음: 음성 분석 제외와 근거 표시. 실행 실패: 실패 단계·원인·남은 결과·재시도 범위. 기존 씬: 마이그레이션 전 원본 보관과 미확인 상태.

1440px 이상: 씬 목록 + 작업 공간 + 단이 패널. 1100~1439px: 단이 패널 기본 접힘. 그 이하: 왼쪽 씬 목록도 접어서 열고, 카드 한 열·선택 컷 확대를 우선한다. 정밀 3D·시간축은 데스크톱 기준이며 모바일은 검토 중심이다. 200% 확대에서도 내용과 버튼이 겹치지 않아야 한다. 모든 선택·패널·분할 조절에 키보드 경로를 둔다.

## 10. 구현 순서와 수락 기준

1. 이 화면 설계 검토: 씬→단계→컷 이동, 콘티와 결과 비교, AI 지시 범위가 이해되는가.
2. 공통 화면·씬 파일 관리·저장 어댑터: 새 씬·복제·복원·다른 창 충돌 검증.
3. 컷 데이터·빈 그림 카드·리비전별 이미지 연결: 실제 콘티는 이 시점부터 제작.
4. 지식 조회·제작 실행 기록·마일스톤 의존성 연결.
5. 애니매틱과 기존 편집기 연결, 촬영/공간 분할과 독립 트랙 유지.
6. 전체 재생 검수·비교·내보내기. 기존 다섯 종류 씬을 손실 없이 열 수 있는지 확인.

화면 설계의 수락 기준: 씬을 바꾸면 컷·상태·작업 기록도 해당 씬으로 바뀐다. 단계 탐색은 완료 상태를 바꾸지 않는다. 빈 컷 카드의 그림·대사·모션은 꾸며내지 않는다. 실제 기능이 없는 버튼을 눌러 완료를 흉내내지 않는다. 콘티 변경 후 재검토할 결과를 추적할 수 있도록 명세되어 있다.

## 11. 설계안 조작 범위

index.html에서 화면 8종 이동, 씬 2종 선택, 단이 패널·씬 목록 접기, 빈 카드 배치 예시 켜기, 카드 선택과 시작/중간/끝 프레임 보기, 촬영/작업 높이 조절이 가능하다. 요청 입력은 현재 열린 페이지 안에서 씬별로 보존되고 새로고침 시 초기화된다. 예시 카드 추가는 레이아웃 확인이며 콘티나 실제 씬 데이터 작성이 아니다.

screen-map.json은 단계·설계 씬·상태 목록의 원본이다. HTML에는 동일 데이터를 내장하여 네트워크 없이 열 수 있게 한다. 검토 후 실제 앱에서는 하나의 공통 데이터 모듈로 옮긴다.
