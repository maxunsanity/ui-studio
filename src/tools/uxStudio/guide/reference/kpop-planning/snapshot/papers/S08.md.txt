# S08 · 표 구조와 연결 지도 — 표가 어떻게 이어지나 (이식)

**이 문서는** 표가 어떤 열쇠로 이어지는지 읽는 시스템 연결 지도입니다. 당시 등록부·기획 근거와 현재 등록·로더의 역할을 구분해 설명합니다.

**보는 법** 간략에서 연결의 큰 흐름을 보고 세부의 규칙·선 목록으로 내려갑니다. 아래 현재 읽기 기준을 먼저 확인하고, 개별 표 구조는 관련 정본과 함께 읽습니다.

**지금 상태** 기획 연결 지도와 등록·코드 역할을 정적으로 대조한 제안(검수 대기) 문서입니다. 전체 값·참조·게임 구동의 정상이나 운영수치 확정을 뜻하지 않습니다.

**현재 등록·로더를 읽는 기준 — 정적 관측**

**관측 대상·시점** — 2026-11-04 05:14 감사 마감 기준 등록 메타는 `table_registry.csv` 94행(`both` 87 · `tool` 7)입니다. `schema_table.csv` 전체 619기록은 보관·미등록 기록도 포함합니다. 생성된 `GAME_SCHEMAS` 94개, `GAME_MASTER_TABLES` 7개, `GAME_REF_TABLES` 15개는 각각 다른 필터의 대상입니다. 아래 37 · 47 · 83은 본문에 적힌 날짜의 등록부 기록으로 보존합니다.

**생성 정본·생성물** — 원본 `schema_table.csv` · `schema_column.csv` · `schema_config_key.csv`를 `scripts/schema-generate.mjs`가 읽어 `src/data/schema.ts` · `data/game/table_registry.csv` · `data/planning_csv_table.csv`를 만듭니다. 생성물은 손으로 고치지 않습니다. 아래 「등록부 생성 스크립트 없음」은 이전 근거이며, 현재 생성기 소스와 구분합니다. 생성 비교·머리줄 확인을 전체 참조·운영 검수로 보지 않습니다. 이번에는 생성기나 `--check`를 실행하지 않았습니다.

**논리 이름·실제 경로** — 등록부의 `rel_path`는 생성기에서 표 논리키로 쓰입니다. 실제 파일은 `schema_table.rel_path` 및 로더 경로를 함께 봅니다. 예를 들어 논리키 `facility_level`은 `GAME_TABLE_PATHS`를 통해 `data/core_proposal/facility_growth_level.csv`를 읽도록 되어 있습니다. `wire` · `read_game` 표시는 실제 호출·화면 연결·정상 구동의 증명과 구분합니다.

**공통 칸·예외** — 아래 공통 `resource_id` · `resource_stage` · `check_id` 등의 설명은 당시 관리 원칙입니다. 현재 생성스키마에는 관리·툴·옛 표 등의 예외가 있으며 모든 표에 같은 칸이 있거나 모두 같은 검사를 통과했다는 뜻은 아닙니다.

**연결선·검사 범위** — 게임 검사기는 `GAME_SCHEMAS`의 PK 이름과 접미사로 대상을 추론하고 명시 예외를 적용합니다. `board_tile`의 시설·잭팟·지도 선은 이 규칙으로 추론할 수 있지만 실제 행 참조 정상은 이번에 재검사하지 않았습니다. `commonLoader`는 명시된 `fk_target` 중 같은 호출에서 함께 읽은 대상만 확인하며, 머리줄·범위·참조 문제는 기본 경고입니다. 게임 로더의 CRIT 차단과 같은 범위로 합치지 않습니다.

**CSV 호출 계약** — `src/toolkit/csv.ts`의 `parseCsv(text, sourceName?)`에는 별도 `strict` 옵션이 없습니다. 파일명 인자가 있을 때 셀 수 불일치를 오류로 처리합니다. `commonLoader`는 `parseCsv(..., name)`을, 게임 로더는 `parseGameCsv(..., name, parseCsv)`를 쓰고 그 안에서 `parseRows(..., tableName)`으로 이름을 넘깁니다. 이 두 호출 경로의 확인을 모든 파서·호출부의 전수 검수로 확대하지 않습니다.

**이전 근거의 읽기 범위** — 아래 원형 도식·표의 숫자, 빈 `card` 예시, 풀네임 후보와 날짜 붙은 결정 인용은 당시 기획·설명 역할을 보존합니다. 새 운영값·새 이름 변경 승인으로 집행하지 않습니다. 기존 선택 37 CSV · 14 ID 관계의 부분 감사도 전체 표·FK·전환·게임 운영 검수와 구분합니다.
