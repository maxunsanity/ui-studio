<p>오디션은 도시에서 만난 후보를 알아보고, 함께할 아이돌을 골라 같은 이름·배경·이야기를 가진 멤버로 성장 화면에 이어 보내는 과정입니다.</p>

<section class="part" id="part-1"><h2>1. 개요</h2><p>오디션은 멤버를 선택하고 합류시키며 몬스를 지급하지 않습니다. 첫 몬스는 게임 시작 튜토리얼에서 받고, 이후에는 기획사가 몬스 팩으로 모읍니다. 몬스의 보유와 편성은 <a href="몬스보유_핵심제안서.html">P223 몬스 보유</a>와 <a href="몬스_기획서.html">P96 몬스와 악귀</a>를 따릅니다.</p>

<p>출처: (합침) <a href="/docs/planning/proposal-concept/audition.html" data-paper-path="docs/planning/proposal-concept/audition.html">오디션 제안</a>과 현재 오디션·후보 생성·공통 인물정보 소스 및 실제 표.</p>

<p>플레이어는 기획사 대표가 되어 보드에서 후보를 만납니다. 후보의 그림·성격·재능뿐 아니라 왜 지원했는지, 무엇이 약점인지 읽고 캐스팅·명함·패스를 고릅니다. 명함은 상대를 더 알아가는 조작이고, 아이돌 캐스팅 대진은 함께할 사람을 비교해 정하는 조작입니다. 합류한 뒤에는 새 인물을 다시 만드는 대신 그 후보의 정체성과 서사를 그대로 성장 시스템에 넘깁니다.</p>

<p>이 흐름에서 후보를 <b>만드는 시점</b>, 이야기를 <b>공개하는 조건</b>, 성장을 <b>저장하는 책임</b>을 나눕니다. 명함을 줬다는 이유로 능력이 오르거나, 대진에서 골랐다는 이유로 후보의 배경이 바뀌지는 않습니다.</p>

<h3 id="콘텐츠-경계">콘텐츠 경계</h3>

<ul>
<li>오디션은 후보 생성과 만남, 명함 기록, 대진 선택, 멤버 확정, 팀 이름과 성장 전달을 맡습니다.</li>
<li><a href="/docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EC%95%84%EC%9D%B4%EB%8F%8C%EB%8A%A5%EB%A0%A5_%EA%B8%B0%ED%9A%8D%EC%84%9C.html" data-paper-path="docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EC%95%84%EC%9D%B4%EB%8F%8C%EB%8A%A5%EB%A0%A5_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">아이돌 성장 P107</a>은 합류 뒤의 실제 능력·학습·승급과 진행 저장을 맡습니다. 오디션의 이야기 검토 버튼은 승급 조작이 아닙니다.</li>
<li><a href="/docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EB%9E%9C%EB%8D%A4%EB%A9%A4%EB%B2%84%EC%83%9D%EC%84%B1_%EA%B8%B0%ED%9A%8D%EC%84%9C.html" data-paper-path="docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EB%9E%9C%EB%8D%A4%EB%A9%A4%EB%B2%84%EC%83%9D%EC%84%B1_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">랜덤 멤버 생성 P170</a>은 이름·성격·배경·이야기의 생성 재료를 설명합니다. 이 문서는 그 결과가 오디션에서 어떻게 보이고 다음 화면까지 이어지는지를 설명합니다.</li>
</ul>

<p>이 문서에서 <b>run</b>은 한 번 시작해 이어가는 플레이 기록 묶음입니다. <b>seed</b>는 같은 후보 조합을 다시 만들기 위한 시작값이고, <b>handoff</b>는 합류 정보를 다음 화면에 넘기는 전달 자료입니다.</p>

<h3 id="한눈에-보기">한눈에 보기</h3>
<ul><li>후보는 캐스팅할 때마다 새로 랜덤 생성합니다. 고정 후보 16명은 쓰지 않습니다(현중 10/22).</li><li>아이돌은 최대 30명이고, 엔터파워가 오를 때마다 자리가 열립니다. 팀은 최대 10명입니다.</li><li>캐스팅 전에는 큰 능력 6개의 등급만 보이고, 캐스팅한 뒤에 자세한 능력을 보여 줍니다.</li><li>오디션에서는 몬스를 주지 않습니다. 자세한 설정값은 <a href="#audition-settings">6장 오디션 설정값</a>에 있습니다.</li></ul>

</section><section class="part" id="part-3"><h2>3. 구동 방법·시뮬레이션</h2>

<p>화면 흐름: 공용 시뮬레이터의 오디션 → 보드 도착과 후보 소개 → 명함·직접 캐스팅 또는 아이돌 캐스팅 → 영입 확인 → 메인 → 아이돌 성장·인물정보. 이번 문서 수정의 새 화면 캡처는 미완이며, 이식 비교는 해당 없음입니다.</p>

<p><a href="/docs/planning/game-simulator.html?module=simulator_module_audition" data-paper-path="docs/planning/game-simulator.html">눌러서 오디션의 실제 보드·명함·대진 확인</a> · <a href="/docs/planning/game-simulator.html?module=simulator_module_idol_growth" data-paper-path="docs/planning/game-simulator.html">눌러서 같은 멤버의 성장 화면 확인</a></p>

<ol>
<li>오디션을 열면 현재 저장의 run과 생성 기록을 먼저 읽습니다. 같은 진행은 이미 만난 후보와 명함 기록을 이어 보여 주고, 캐스팅을 열 때마다 새 후보를 랜덤 생성합니다(현중 10/22). 지금 코드는 새 테스트를 시작할 때만 후보 묶음을 만듭니다.</li>
<li>주사위를 굴리면 도착 위치·소모·경로를 먼저 기록합니다. 현행 엔터 파워 연결판은 시작 멤버도 24개 <code>building</code> 대지 도착에서 후보를 만납니다. 사옥 출발 칸은 이 대지 조건에 포함하지 않습니다.</li>
<li>도착 카드에서 후보의 이름·특기·성격, 소개와 배경을 읽습니다. 상세를 펼치면 추가 소개와 이미 열린 이야기 조각을 볼 수 있습니다.</li>
<li>명함을 주면 찜 목록에 넣고 그 후보의 다음 이야기 조각을 하나 엽니다. 목록이 차면 교체할 후보를 고릅니다. 패스는 합류나 이야기 개방 없이 보드로 돌아갑니다.</li>
<li>직접 캐스팅하면 그 후보를 확정하며 몬스는 지급하지 않습니다. 첫 멤버를 직접 정했으면 첫 바퀴 끝의 첫 멤버용 대진은 생략합니다. 추가 멤버의 직접 캐스팅은 합류 권한과 정원이 열렸을 때 가능합니다.</li>
<li>첫 바퀴 뒤에도 첫 멤버가 없거나 추가 합류 권한이 열렸다면 아이돌 캐스팅을 엽니다. 명함 후보가 먼저 들어가고, 부족한 자리는 미합류 후보에서 중복 없이 채웁니다. 명함 후보가 대진 자리보다 많으면 참가자를 직접 고릅니다.</li>
<li>첫인상 후보를 고른 뒤 두 카드를 비교합니다. 카드 뒤집기·이야기 열기는 선택 버튼과 별개입니다. 고른 후보는 같은 자리에 남고 다음 도전자가 들어옵니다. 최종 후보는 영입 확인 뒤 합류합니다.</li>
<li>두 번째 멤버가 들어오면 팀 이름을 입력하고 확인합니다. 팀 이름을 나중으로 미루는 동작은 작업전입니다.</li>
<li>메인 진입을 선택하면 현재 멤버와 보드 진행을 전달합니다. 몬스 보유는 별도 시스템에서 읽습니다. 성장 화면에서는 인물정보의 이야기 메뉴로 같은 멤버의 원래 서사를 읽습니다. 여기에서 실제 성장 단계와 명함 공개 횟수를 혼동하지 않습니다.</li>
</ol>

<p>시뮬레이터 오른쪽의 강제 도착·엔터 파워 입력·빠른 검토는 검토용 조작입니다. 보드의 자연스러운 진행이나 본편 발란스가 검증됐다는 뜻은 아닙니다.</p>

<p>후보는 캐스팅할 때마다 랜덤 생성하며, 모든 처음 값은 <code>member_init_rule.csv</code> 기준으로 균등하게 뽑습니다(현중 10/22 11:07~11:08). 명함을 준 후보는 생성 기록에 남아 다시 만나도 같은 사람의 다음 이야기를 읽습니다. 위 그림은 지금 코드 흐름(run 준비 때 한 번 생성하고 추가 캐스팅은 미합류 후보 재사용)이며, 캐스팅마다 생성하도록 고칠 곳입니다.</p>

<p>생성 보조 기록에는 seed와 생성기 버전을 두고, 보드 저장에는 후보 스냅샷·선택 이벤트·열린 이야기 수·합류 결과를 둡니다. 같은 seed의 재현은 같은 원본 표와 생성 로직을 전제로 합니다. 원본이 달라 저장 지문이 맞지 않으면 정상 복원으로 간주하지 않습니다. 생성 기록이 없는 옛 저장은 옛 고정 후보 자료로 구분해서 이어 보며 새 생성 후보로 위장하지 않습니다.</p>

<h3 id="4-3-소개와-성장-이야기를-만드는-방식">4-3. 소개와 성장 이야기를 만드는 방식</h3>

<p>서사는 실시간 AI 호출로 새 소설을 쓰는 방식이 아니라, <b>원본 틀 한 개와 이미 뽑힌 배경 조각을 결합하는 방식</b>입니다. 서사를 만들 때 배경을 다시 뽑지 않으므로 소개의 약점과 성장 후 회고가 같은 사람을 가리킵니다.</p>

<ol>
<li><code>member_story_template.csv</code>에는 8개 장마다 틀 3개씩, 총 24개 원본 틀이 있습니다. 각 장의 틀 안에서 seed와 후보 순번으로 하나를 고릅니다.</li>
<li><code>〔family〕</code> 같은 표기는 그 후보의 짧은 배경 칩, <code>〔family_말〕</code>은 그 조각의 원래 대사로 바꿉니다. <code>〔weakness|이〕</code> 같은 표기는 끝 글자의 받침에 맞춰 조사를 붙입니다.</li>
<li>생성 결과에는 단계 코드·선택한 틀 ID·문장·대사·공개 단계가 함께 남습니다. 원래 서사 배열이 이미 있으면 부분 배열이라도 그 배열을 우선하고 부족한 문장을 새로 꾸며 넣지 않습니다.</li>
<li>필요한 조각·문구가 없거나 치환 표기가 풀리지 않으면 문장을 <code>null</code>로 남깁니다. 임의의 이름·사연·보상으로 빈칸을 채우지 않습니다.</li>
<li>소개문은 만들어진 소개 문장의 인용 대사에서 최대 세 줄을 추려 후보 카드에 표시합니다. 칩·소개·긴 이야기 모두 같은 배경에서 나옵니다.</li>
</ol>

<p>서사 8장은 멤버 성장 등급 8개를 뜻하지 않습니다. 실제 멤버 성장은 0~4의 5단계이고, 소개·합격 프롤로그·월드스타 회고를 함께 묶어 서사 8장을 구성합니다.</p>

<p>공개 단계는 현재 서사 표의 값입니다. 문장에 약점을 극복했다고 적혀 있다는 이유로 실제 능력·승급·외국어 등급을 올리지 않습니다. 실제 성장 판정은 P107이 맡습니다.</p>

<h3 id="4-4-실제-원본으로-읽는-문장-조합">4-4. 실제 원본으로 읽는 문장 조합</h3>

<p>원본 소개 틀 <code>member_story_template_audition_intro_01</code>의 문장은 <code>〔family_말〕 〔motive_말〕 〔weakness_말〕</code>입니다. 대사는 원본의 “꼭 붙고 싶어요!”를 사용합니다. 여기에 해당 후보가 이미 가진 집안·동기·약점 조각의 원래 대사가 들어갑니다.</p>

<p>예를 들어 집안 조각 표의 <code>narrative_piece_family_02</code>는 칩이 “보통 집”, 원래 대사가 “「평범한 우리 집 첫 연예인이 될래요.」”입니다. 이 문구는 실제 표에 있는 재료이며 이 문서가 새 인물의 사연을 창작한 예시가 아닙니다. 어떤 후보에게 이 조각이 배정되는지는 그 run의 생성 결과가 정합니다.</p>

<p>원본 <code>member_story_template_step_1_01</code>에는 “데뷔 무대 조명이 켜지자 〔weakness|이〕 다시 숨을 조였다.”가 들어 있습니다. 이 자리에는 소개 때 이미 정한 약점을 넣습니다. 단계별 장면이 달라도 배경을 공유하는 것이 조합형 이야기의 연결 원리입니다.</p>

<p>성장 쪽에서는 합류 당시 handoff에 담긴 원래 문장을 우선합니다. 템플릿 표가 나중에 바뀌거나 현재 서사가 일부 비었다고 다른 후보의 문장을 붙이지 않습니다. 잠긴 문장은 인물정보 화면에 전달하기 전에 제거하며 제목·열리는 단계만 안내합니다.</p>

<h3 id="4-6-선택이-남기는-기록과-스킬의-경계">4-6. 선택이 남기는 기록과 스킬의 경계</h3>

<p>대진 선택은 양쪽 후보와 승자·선택 사유를 기록합니다. 승자는 자리를 유지하고 패자 자리에 다음 도전자가 들어옵니다. 시간 종료는 이미 남아 있던 후보를 유지하는 규칙이며, 처음부터 아무 후보나 자동 선택하지 않습니다. 마지막 비교 뒤에는 최종 영입 확인과 다시 비교가 가능합니다.</p>

<p>첫인상 ID와 후보별 승리 기록은 기존 스킬 요약에 전달됩니다. 보드에서 직접 캐스팅한 경우에도 그 후보를 첫인상으로 기록하되 가짜 대진 승리 기록을 만들지 않습니다. 선택을 바꾸면 새 후보는 자기 승리 기록을 사용합니다.</p>

<p>현재 생성기 어댑터는 처음 스킬 정의를 <code>t1</code>에 옮기고 <code>t2a</code>·<code>t2b</code>·<code>t3</code>의 이름·효과는 빈칸으로 남깁니다. 대진의 기존 3슬롯 UI·획득 조건과 생성 후보용 전체 스킬 정의를 채우는 일은 다릅니다. 빈 상위 스킬을 임의 이름·효과로 채우거나 모든 스킬 효과가 성장에 적용된다고 표시하지 않습니다. 생성 후보의 상위 스킬·대진 슬롯 연결은 작업전입니다.</p>

<p>대진의 선택·탈락 반응은 기존 후보 대사 또는 공통 대체 문구를 표시합니다. 반응을 보여 주는 것과 그 선택에 맞춰 장문 서사를 다시 쓰는 기능을 구분합니다. 현재 생성 소개와 성장 서사는 선택 때마다 재작성하지 않습니다.</p>

<h3 id="4-7-합류이름짝-몬스">4-7. 합류·이름·몬스 지급의 경계</h3><p>오디션은 멤버를 선택하고 합류시키며 몬스를 지급하지 않습니다. 첫 몬스는 게임 시작 튜토리얼에서 받고, 이후에는 기획사가 몬스 팩으로 모읍니다. 몬스의 보유와 편성은 <a href="몬스보유_핵심제안서.html">P223 몬스 보유</a>와 <a href="몬스_기획서.html">P96 몬스와 악귀</a>를 따릅니다.</p>

<ul>
<li><b>합류:</b> 첫 멤버를 직접 골랐다면 첫 바퀴 끝 대진을 생략합니다. 추가 합류는 엔터 파워로 열린 자리와 최대 정원을 검사합니다. 이미 합류한 후보를 대진이나 도착 후보로 다시 넣지 않습니다.</li>
<li><b>팀 이름:</b> 두 번째 멤버가 들어온 뒤 입력 → 확인 또는 다시 쓰기 → 공개 순서로 진행합니다. 빈 이름은 저장하지 않습니다. 팀 이름을 나중으로 미루는 동작은 작업전입니다.</li>
<li><b>본명과 예명:</b> 생성 본명은 고정입니다. 독립 오디션 결과 화면에는 예명 입력·본명 그대로·내 팀 중복 검사가 있습니다. 일반 생성기는 추천 예명도 만들지만 오디션 후보 변환은 추천 배열을 넘기지 않아 생성 후보의 추천 버튼 연결은 작업전입니다. 현재 보드의 대진은 <code>duelOnly</code>로 열어 이 입력을 숨기며 직접 캐스팅 결과도 예명 입력을 연결하지 않습니다. 따라서 예명을 모든 보드 합류 경로에서 입력·저장·전달하는 일은 작업전입니다.</li>
<li><b>몬스 지급:</b> 새 합류 결과에는 몬스를 넣지 않습니다. 옛 저장의 짝 몬스 정보는 호환 자료로만 유지하고 새 획득이나 추가 지급으로 처리하지 않습니다.</li>
<li><b>합류 보정:</b> <code>join_catchup_pct</code>의 50%는 표에 있지만 현재 합류 처리에서 사용하지 않습니다. 늦게 합류한 멤버를 평균으로 끌어올리는 적용은 작업전이고 보정량은 비앙카 장부 산정 항목입니다.</li>
</ul>

<p>handoff에는 이름만 보내지 않습니다. 후보 ID·첫 영입 결과 ID, 4축 호환값과 생성기 6축·18세부 원본, 영어·중국어·일본어 시작값, 배경, 첫인상·대진 요약, 원본 생성 멤버와 <code>story[]</code>를 함께 보냅니다. 현재 보드 위치·굴림·바퀴·배수·주사위 진행도 같이 전달합니다.</p>

<p>한 run에서 멤버가 더 들어오면 첫 멤버의 결과 ID를 계속 기준으로 씁니다. 성장 계약은 기존 멤버의 진행을 보존하고 새 멤버만 추가하도록 구분합니다. 후보의 재능을 다시 뽑거나 명함 공개 수를 실제 성장 단계로 저장하지 않습니다.</p>

<p>오디션 보드는 자기 저장과 handoff를 쓰고, 실제 성장 상태는 성장 시스템이 씁니다. 다른 탭에서 생성 기록이나 보드 저장이 바뀌었으면 오래된 전달을 중단합니다. 전달 실패는 재시도 대상으로 표시하며 정상 연결로 꾸미지 않습니다. 현재 연결은 브라우저의 같은 테스트 범위 안이며 서버 계정 저장은 작업전입니다.</p>

<h3 id="수락-기준">수락 기준</h3>

<ul>
<li>본문은 고정 7장의 이름·순서를 유지하고 서사 설명을 4장, 시스템 책임을 2장, 표의 입력·출력을 6장에 둡니다.</li>
<li>새 run 생성과 같은 run 재사용, 생성 원본 8장와 보드 명함 5토막·대진 6행·성장 인물정보 8장의 차이를 설명합니다.</li>
<li>후보를 고를 때 성격·배경·서사를 새로 쓰는 기능과 기존 기록을 읽는 기능을 구분합니다.</li>
<li>같은 후보 ID·첫 결과 ID와 원본 서사를 성장까지 보존하며, 실제 성장 단계가 확인되지 않은 문장을 공개 완료로 표시하지 않습니다.</li>
<li>현재 호출·표에서 확인한 기능만 현재 동작으로 적고 미연결 기능은 작업전, 비어 있는 수치는 비앙카 장부 산정 항목로 남깁니다.</li>
</ul>

<h3 id="뺀-것옮긴-것보존한-것">뺀 것·옮긴 것·보존한 것</h3>

<p>새 후보가 추가 캐스팅마다 모두 다시 생긴다는 표현, 선택 결과가 현재 오디션에서 성격을 다시 만든다는 표현, 후보마다 새 조합 외형을 렌더한다는 표현을 현재 소스의 동작으로 바로잡았습니다. 이전 본문과 이력은 짝 로그의 접힌 원문에 그대로 보존합니다. 게임 소스·CSV·저장 상태는 이 문서 작업에서 바꾸지 않습니다.</p>
