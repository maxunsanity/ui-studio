# 게임 UX 기획 스튜디오 · 기획과 제작 계획

**이 문서는** 게임 화면의 배치·기능 설명·UI 연결을 작성하고 직접 시험하는 공통 스튜디오의 기준 기획서입니다.

**보는 법** 목차 → 간략 → 제작 단계 → 요구사항 점검 순서로 읽습니다. 기존 자료 분석과 기술 조사는 연결 자료로 보존합니다. 현재 실행판은 [모노폴리 GO 샘플 열기](http://127.0.0.1:7007/docs/planning/ux-studio.html?workspace=workspace-8e0f09e7-4699-4ac6-81b3-d545c7046ef6&project=ux-gjs-0d80d7fe) 또는 [카피바라고 샘플 열기](http://127.0.0.1:7007/docs/planning/ux-studio.html?workspace=workspace-ac9e2a9e-65c0-4fe8-b67a-79a5a9ae42d7&project=ux-gjs-4e64eb72)에서 사용합니다. 두 입구는 독립 UI 스튜디오의 최근 저장판을 엽니다. 최신 사용법과 제작 규칙은 도구 안의 가이드에서 확인합니다.

**지금 상태** 개발됨(도구의 화면 편집·저장·미리보기): 전체 캔버스의 화면 목록·5열/연결 보기와 상세 편집·디자인 가이드, 기본 와이어프레임·세부 와이어프레임·본 UI를 제공합니다. 샘플의 최종 시각 동등성과 실제 게임 연결은 미완료입니다.

## 1. 개요
### 간략
**배치된 화면을 누르면 기능·연결·결과를 함께 확인하는 UX 기획 스튜디오**를 만듭니다. 모바일 세로 게임을 먼저 지원하고 다른 게임의 화면과 데이터도 불러올 수 있는 구조로 잡습니다. 로비는 첫 검증 샘플입니다.

| 사용자가 하는 일 | 도구가 보여줄 것 |
|---|---|
| 화면이나 버튼을 고릅니다 | 목적·표시 정보·가능한 행동·연결 대상 |
| 요소를 움직이고 크기를 조절합니다 | 부모 기준 위치·크기·여백·기기별 배치 |
| 행동과 조건을 설정합니다 | 다음 화면·같은 화면의 변화·팝업·실패·복귀 |
| 실제처럼 눌러봅니다 | 현재 상태·실행 경로·조건 결과·출현/퇴장 |
| 저장하고 다시 엽니다 | 같은 배치·설명·연결과 저장 버전 |

기본 보기는 상세 와이어프레임입니다. 게임 그래픽 적용 보기는 같은 데이터로 전환하거나 비교하는 보조 보기입니다. ComfyUI나 특정 디자이너의 도구를 필수로 삼지 않습니다. 미정값을 확정 숫자나 0으로 채우지 않습니다.

### 첫 제작 범위
첫 사용 가능한 판은 **로비 + 연결 대상 화면 + 모달 + 성공/실패 안내 + 복귀**입니다. 배치 조절만 되는 로비 한 장으로 첫 판을 완료 처리하지 않습니다. 샘플은 스튜디오 시험용이며 실제 게임의 로비 도입·경제·운영 정책을 확정하지 않습니다.

<a id="part-3"></a>
## 3. 구동 방법·시뮬레이션
### 작업 화면
| 위치 | 역할 |
|---|---|
| 왼쪽 목록 | 화면 이름·요소 계층·검색. ID는 보조 표시 |
| 중앙 미리보기 | 세로 게임 화면, 영역·번호·상태. ‘배치 편집’과 ‘동작 시험’ 전환 |
| 오른쪽 | ‘설명·기능’ 기본, ‘연결·조건’, ‘배치’, ‘연출’ 탭. 숫자 상세는 필요할 때 펼침 |
| 하단 접이식 관계도 | 현재 UI의 진입/이동/중첩/복귀와 조건. 전체 보기로 확대 |
| 상단 | 문서/시험 상태·기기·와이어프레임/그래픽·되돌리기/다시하기·저장 상태 |

### 첫 판의 샘플
| 구성 | 첫 판에서 다룰 내용 |
|---|---|
| 로비 | 현재 화면·정보 영역·상점 진입 버튼. 영역/요소 선택과 설명 편집 |
| 상점 목록 | 시험용 상품 목록·선택·필터·스크롤과 로비 복귀 |
| 상품 상세 모달 | 선택 상품 전달·설명·시험 실행·취소/닫기. 부모 상점 상태 유지 |
| 공통 도움말 | 설명 열기/닫기와 다른 UI 위 표시 범위 |
| 결과 안내 | 시험 성공/실패/잔액 부족 안내와 상점 복귀 |

‘로비→상점→상품 상세→시험 결과→상점→로비’를 첫 수직 흐름으로 제안합니다. 상품/잔액/가격/응답은 명확하게 표시된 시험 데이터이며 실제 결제나 원표·게임 장부를 사용하지 않습니다. 선택 없음, 취소, 성공, 잔액 부족, 요청 실패를 각각 시험합니다. 로비/상점의 최종 구성과 자료 출처는1단계에서 최신 공개 원본에 맞추고 시험 제안을 표시합니다.

### 현중과 AI가 함께 쓰는 순서
화면/요소를 선택 → 필요한 변경을 말함 → 선택 ID·기기·상태·저장 버전·미저장 변경을 파일로 공유 → AI가 같은 정본을 읽음 → 변경 전후 비교 → 적용 → 저장·재열기 확인 순서입니다. 외부 AI에 자동 메시지를 보내는 기능으로 해석하지 않습니다. 오래된 수정안은 충돌을 표시하고 최신 사용자 변경을 덮어쓰지 않습니다.

### 첫 검증 흐름
로비에서 연결 요소 선택 → 관련 화면 열기 → 대상 선택 → 모달 열기 → 시험 조건 선택 → 성공/실패 안내 → 닫기 → 원래 화면의 선택·필터·스크롤 복원 순서입니다. 연결에 쓰는 실제 콘텐츠는 1단계에서 최신 공개 기획 원본을 대조해 명시하며, 원본이 없는 부분은 ‘시험용 제안’으로 표시합니다.

툴 탐색의 이전/다음과 게임 UX의 뒤로/닫기/취소를 구별합니다. 관계도를 열어도 현재 선택과 미저장 수정이 없어지지 않습니다.

<a id="part-4"></a>
## 4. 상세 기획
### 공통 설계 원본
화면·요소·동작·연결·상태·데이터 참조·시험 데이터·연출 프리셋·기기 프로필·출처·버전을 하나의 설계 JSON으로 연결합니다. 화면 미리보기, 설명표, 관계도, 저장/내보내기가 이 원본을 공유합니다. 그래프 배치 좌표와 실제 UI 좌표는 분리합니다.

요소는 고유 ID와 사람이 보는 이름/번호를 갖습니다. 표시 번호를 바꿔도 설명과 연결이 끊기지 않아야 합니다. 미정 조건은 미정으로 남고 시험에서도 확인 필요로 표시합니다.

### 단계별로 만들 결과와 통과 기준
| 단계 | 만드는 것 | 실제로 확인할 것 | 단계가 끝나면 보여드릴 것 |
|---|---|---|---|
| 1. 설계·기술 검증 | 설계 파일 구조, 로비 샘플 범위, 좌표·저장 방식, 검증용 최소 화면 | 확대 상태의 끌기/중첩 부모 좌표, 저장→재열기 일치, 실패 시 원본 보존 | 샘플 구성 목록·실제 저장 파일·기술 검증 결과. 결과에 따라 세부 방법 보정 |
| 2. 배치와 기능 설명 | 왼쪽 화면/요소 목록, 중앙 편집, 오른쪽 설명, 이동/크기/정렬/간격·되돌리기 | 요소↔설명 양방향 선택, 키보드 미세 이동, 원복, 저장 후 배치/설명 유지 | 현중이 직접 위치·크기·설명을 바꿔 저장할 수 있는 판 |
| 3. 연결과 동작 시험 | 연결 대상/조건/전달값/복귀 양식, 관계도, 상태 실행기, 시험 기록 | 로비→연결 UI→모달→성공/실패/취소→복귀, 같은 화면 정보 변경, 다중 진입점 | 첫 사용 가능한 UX 시뮬레이터. 버튼 선택 시 설명·선·대상 동시 강조 |
| 4. 공통 UI와 연출 | 모달·토스트·스낵바·바텀시트·도움말, 공통 등장/퇴장, 용어집 | 뒤 화면 입력/초점 처리, 중첩/연타/중단/재열기, 이벤트 하나로 여러 UI 변화 | 공통 동작을 재사용하고 효과를 눌러 시험하는 판 |
| 5. 기기·보기 비교 | 폰/폴드/태블릿 규칙, 와이어프레임↔그래픽, 동일 상태 비교 | 넘침·잘림·터치영역·안전 영역·스크롤, 두 보기의 배치/상태/연출 시점 일치 | 다른 기기와 그래픽 적용 전후를 비교하는 판 |
| 6. 협업·출력·범용 검증 | 선택 정보 공유, AI 변경안 비교/적용, 기획서·연결표·JSON 출력, 두 번째 샘플 | 버전 충돌 거부, 기획/설명/연결 출력 일치, 다른 콘텐츠에서도 같은 편집 기능 사용 | 다른 AI/기획자에게 넘길 수 있는 설계 묶음과 사용법 |

서로 다른 단계라도 ‘저장·복원·오류 보존’은 처음부터 유지합니다. 첫 단계에서 실측한 결과 없이 제작 시간이나 라이브러리 성능을 확정하지 않습니다. 각 단계 완료 때 현중이 볼 수 있는 실행판과 남은 요구 목록을 함께 제출합니다. 요청 범위나 저장/연결 정책이 크게 바뀌면 기획서를 먼저 갱신하고 해당 변경을 확인받습니다.

### 연결과 상태
연결 종류는 화면 이동, 겹쳐 열기/닫기, 같은 화면 안 변화, 조건 분기, 외부/비동기 작업, 데이터/콘텐츠 관계입니다. 관계도는 ‘전체 주요 화면→선택 화면의 연결→선택 버튼의 분기’로 좁혀 보여줍니다. 행동과 결과를 선에 표기하며 선 색만으로 구별하지 않습니다. 도달 불가·대상 없음·복귀 미정·미연결 버튼을 목록으로 보여줍니다. 의도한 순환은 허용합니다.

동작은 입력 사건→조건→동작 종류→대상→전달값→결과→복귀 정책으로 작성합니다. 대기/성공/실패/취소/시간 초과는 구별하고, 실제 서버·결제 대신 시험 데이터를 사용합니다. 같은 화면의 탭/선택/패널도 상태 변경으로 표현합니다. 다중 화면 동시 표시(MR·키오스크)의 데이터 참조 가능성은 모델에 남기되 3D 편집 기능은 후속으로 둡니다.

### 배치와 반응형
부모 기준 위치/크기, 앵커, 고정/가변, 최소/최대, 여백/정렬, 줄바꿈, 넘침/스크롤, 안전 영역, 시각 크기와 터치 영역을 나눕니다. 실제 저장 좌표와 화면의 확대 표시를 구별합니다. 기기 프로필 치수는 시험 설정이며 제품 비율로 확정하지 않습니다. 비교 보기는 같은 설계와 시험 상태를 공유합니다.

### 공통 양식과 출현 연출

### 함께 사용할 때 지킬 계약
- 레이아웃·설명·연결·실행·저장은 기존 설계 JSON 하나를 읽습니다. 라이브러리별 별도 설계 문서를 만들지 않습니다. 그래프 노드를 움직인 좌표와 실제 게임 요소 좌표는 별개입니다.
- 편집 중 임시 DOM transform은 미리보기에만 사용하고, 확정 시 부모 기준 x/y/w/h로 환산합니다. 확대율·스크롤·안전영역·중첩 부모를 함께 계산합니다. 동일 변화를 두 번 transform하지 않습니다.
- 기존 pointer 드래그와 Moveable이 같은 요소를 동시에 조작하지 않도록 기존 경로를 교체합니다. 선택/요소 이동/Space 이동/오른쪽 드롭/관계도 조작의 입력 범위를 나눕니다. 동작 시험에서는 편집 조작을 끕니다.
- 기존 render()는 DOM을 통째로 교체합니다. 편집기 인스턴스 destroy/재연결·선택 ID 복원 또는 해당 영역의 부분 렌더가 필요합니다. 기존 저장·모달 초점·키보드 동작을 유지합니다.
- 다중 선택 첫 범위는 같은 부모의 요소입니다. 서로 다른 부모를 묶는 기능은 좌표/부모 재지정 정책을 검증한 뒤 확장합니다. 잠금/숨김/그룹 상태는 모델/저장/검증을 함께 확장하고 표시만 구현하지 않습니다.
- 드래그 한 번/프리셋 추가 한 번은 undo 한 번으로 되돌립니다. 취소/유효하지 않은 드롭은 원본을 바꾸지 않습니다. 기기·와이어프레임/그래픽 보기도 같은 원본을 사용합니다.
- 관계도에는 실제 명시 연결만 표시합니다. 닫기/이전은 호출 경로와 복귀 정책을 나타내고 고정 목적지를 추정해 확정선으로 만들지 않습니다. 공유 도움말의 여러 진입점은 보존합니다.

### 목표와 현재 상태
기획서 툴 안에서 UI를 배치하고 기능/연결/연출을 작성하면, 게임 시뮬레이터의 왼쪽 게임 화면도 같은 UI 설계를 사용하도록 만듭니다. UI 스튜디오는 AI 게임 제작 시뮬레이터의 가벼운 UI·UX 제작 모듈입니다. 게임 계산·3D·게임 진행 엔진을 UI 편집기에 복제하지 않습니다.

현재 전용7018 실행판에는41종 유닛·색상/도형/크기·Moveable 이동/리사이즈·Selecto 선택·공통 연출/버튼 연결·확대/이동·undo/redo의 첫 구현이 있습니다. 독립 시험23개가 통과했으며 실제 확인과 미확인은 작업 보고에서 구별합니다. 게임 시뮬레이터 자동 반영과 다중 프레임 스토리보드는 아직 구현하지 않았습니다. 기존 샘플 ‘로비·상점 UX 검토’는 현재 게임 로비의 복제판이 아닙니다.

### 한 설계, 세 가지 사용처
| 사용처 | 공통 데이터로 하는 일 | 각 사용처가 맡는 부분 |
|---|---|---|
| UI 스튜디오 | 화면/요소 배치·모양·설명·연결·연출 편집 | 편집 손잡이·유닛 메뉴·시험 데이터·되돌리기 |
| 게임 시뮬레이터 왼쪽 | 같은 UI 렌더러로 화면 표시, 기존 게임 기능 호출 | 실제 진행/보드/재화/저장과 결과 제공 |
| 기획서 툴 | 같은 화면/요소 ID의 설명·스토리보드·연결 표시 | 기획 본문·원본 출처·작성/검수 기록 |

UI 구조·스타일·트리거/허용 행동/대상·연출 설정은 동일 설계 파일의 revision을 참조합니다. 게임 상태와 경제 원표를 UI 파일에 복사하지 않습니다. 처음에는 현재390×844를 관측 기준으로 삼고 기기별 규칙은 별도로 다룹니다.

### 1. 현재 기능을 먼저 목록화합니다
확인한 등록 원본은 `data/simulator/simulator_module.csv`39행, `menu.json`의 주요/성장/보조와 하위 메뉴·별칭, `mobile-frame.json`의 공통 화면 구성입니다.39행은 등록 기능 수이며,39개 기능의 모든 UI/동작을 검수했다는 뜻은 아닙니다.

- 공통: 주사위/보석/돈,나쁜 기운/팬/엔터파워,팀/멤버/능력,도시/보드·필러·진행 버튼,기록장/소식,하단 게임 메뉴와 공통 창.
- 게임 기능: 로비/보드,오디션,성장·능력·관계,카드/몬스,모험/미션/상점/건설,쟁탈/디펜스/이벤트/찬스,음원·앨범·공연·차트·크루·주간/월드 페스티벌,제작/검토 보조.

- 등록만 확인/화면 확인/연결 시험/미구현을 구별합니다. 미확인 동작을 작동하는 버튼으로 만들어 제공하지 않습니다.

오른쪽은 **유닛 / 게임 기능 / 속성**으로 나눕니다. 유닛에는 백판·도형 버튼·입력·목록·정보와 공통 연출이 있고, 게임 기능에는 등록 기능 전부를 검색/분류로 제공합니다. 기본은 현재 화면에 쓰는 기능만 펼치고 ‘전체 기능’으로 나머지를 찾습니다. 속성은 선택한 것만 설명합니다. 모든 설정을 한꺼번에 긴 목록으로 펼치지 않습니다.

### 2. 현재 로비를 편집용 설계로 재구성합니다
게임 시뮬레이터 P94 목록→카드→실행에서 ‘로비 허브’ 등록과 진입을 확인했습니다. 이 로비의 내부 프레임 주소가 보호 원본을 가리키므로 내부 문서/DOM/소스의 추가 열람·계측은 하지 않았습니다. 공통 화면 설정만으로 현재 로비 전체를 분석 완료했다고 주장하지 않습니다.

다음 구현에서는 허용된 현재 로비의 화면 자료와 관련 공통 UI 자료를 대조해 보이는 사각형·텍스트·버튼·슬롯을 설계 요소로 정의합니다. 실제 소스 전체 복사나 게임 엔진 탑재를 하지 않습니다. 치수는 확인된 실측/공식 레이아웃 설정과 설계 제안을 구별하고 임의로 정확한 현재값이라고 쓰지 않습니다.

먼저 로비 한 화면과 확인된 연결대상 한 개,팀 정보 같은 공통 창 한 개로 수직 검증합니다. 전체 기능은 목록에 먼저 제공하되 모든 기능 화면을 한꺼번에 만들거나 실행하지 않습니다.

### 3. 가벼운 공통 렌더러와 기능 연결 계약을 만듭니다
현재 `main.mjs`에 함께 있는 표시 부분을 재사용 가능한 DOM/SVG 렌더러로 분리합니다. 편집기 도구와 게임 기능 코드를 렌더러에 넣지 않습니다.

- `screenId / elementId / moduleId / actionId / docId / revision`으로 세 도구를 연결합니다.
- `mount / updateDesign / updateState / dispose`와 `onAction` 정도의 작은 인터페이스를 검증합니다. 이는 제안 계약이며 구현 완료 API가 아닙니다.
- UI 스튜디오는 시험용 상태/가짜 응답 adapter를 연결합니다. 게임 시뮬레이터는 기존 모듈의 허용 행동 adapter를 연결합니다. 임의 JS·파일 경로를 설계에서 실행하지 않습니다.
- ‘상점 열기’는 기존 상점 모듈 호출에 대응하고,‘굴리기’의 계산은 기존 게임이 담당합니다. 오른쪽에서 게임 기능을 배치했다고 엔진 기능을 새로 구현했다고 표시하지 않습니다.
- 모달·바텀시트·토스트는 현재 게임 화면 범위의 공통 UI이며 별도 최상위 게임 화면을 늘리지 않습니다. 공통 정의를 바꾸면 적용 대상들을 표시합니다.

### 4. 저장하면 게임 화면에도 같은 수정이 보이게 합니다
목표는 **UI 스튜디오 저장 완료→공통 설계 revision 갱신→게임 시뮬레이터 UI 갱신→기획서 미리보기 갱신**입니다. 연결되기 전에는 이미 자동 반영된다고 말하지 않습니다.

처음에는 미저장 드래그 매 순간을 전송하지 않고,안전한 파일 저장이 끝난 변경을 반영합니다. 같은 기획서 툴 origin에서 버전 알림을 보낸 뒤 소비자가 해당 revision을 읽는 방식을 우선 검토합니다. 현재7018은 독립 개발 주소이며,영구 연동을 이 전용 서버의 상시 실행에 의존시키지 않습니다.

게임의 전체 재시작/모듈 재생성이 아니라 UI의 바뀐 부분을 갱신합니다. 현재 보드 진행·선택·스크롤·모달 초점·재화 상태를 보존합니다. 오래된 수정안은 충돌로 거부하고 최신 UI 변경을 덮어쓰지 않습니다. 미지원 변경은 적용 실패/미반영으로 표시하고 기존 UI를 유지합니다.

최종 반영 기준은 저장된 버전입니다. 추후 미저장 실시간 보기까지 추가할지는 별도로 정합니다. 자동 감시·예약을 새로 켜는 계획은 아닙니다.

### 5. 스토리보드와 간단 흐름을 같은 연결로 보여줍니다
기본 ‘화면 편집’은 한 모바일 프레임입니다. ‘스토리보드’에서는 같은390×844 프레임을 옆에 배치합니다. 다음 화면을 추가한다고 폰 화면 크기 자체가 늘어나지 않습니다.

기본 흐름은 작은 화면 미리보기와 행동 이름의 화살표만 보여줍니다. 버튼/연결을 고르면 설명·조건·실패·복귀 상세를 펼칩니다. 별도 플로우차트 정본을 만들어 중복 작성하지 않습니다. 그래프 좌표는 UI 좌표와 구별합니다. 실제 연결이 없는 분기를 추정해 그리지 않습니다.

모달은 해당 화면 위 상태로 시험하고,필요할 때 ‘모달이 열린 상태’를 비교용 상태 카드로 펼칩니다. 이는 같은 UI 정의의 상태 보기이며 독립 게임 페이지가 아닙니다. 전체화면/선택 주변/간단 흐름을 나눠 화면마다 모든 선을 그리지 않습니다.

### 제작 순서와 단계마다 보여드릴 것
1. **기능 목록·공통 연결 계약**: 현재 등록39와 공통 UI를 오른쪽 검색 목록에 연결하고 현재/미연결을 표시합니다.
2. **로비 기반 설계**: 허용된 화면 자료로 로비를 재구성하고 단일 화면·공통 창·확인된 대상 하나를 UI 모드에서 시험합니다.
3. **공통 렌더러**: 스튜디오와 엔진 없는 독립 소비 화면에서 동일 설계·동작 사건 전달을 검증합니다.
4. **게임 시뮬레이터 한 화면 연동**: 현재 로비 UI에 제한 적용해 저장 반영과 게임 상태 보존을 확인합니다. 보호 원본을 수정하는 경로는 사용하지 않으며 적용 위치/담당을 먼저 확정합니다.
5. **기획서와 가벼운 스토리보드**: 기획서 ID별 화면/요소 설명·작은 미리보기·간단 연결을 같은 설계에서 표시합니다.
6. **다른 화면 확장**: 검증된 공통 틀로 기능별 UI를 순차 확대합니다.39개 등록 기능 전체의 구현/검수를 한꺼번에 완료 처리하지 않습니다.

현재는 새 통합 방향의 계획 제출 단계입니다. 이미 제작한 유닛 기능은 보존하고,통합 계약을 확정한 후 그 구조에 맞춰 이어갑니다. 게임/기획서 실제 자동 반영은 아직 연결 전입니다.

### 11:36 구현 반영 · 기능 목록·로비 슬롯·공통 소비 화면
