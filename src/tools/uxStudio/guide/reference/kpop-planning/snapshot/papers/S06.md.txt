# S06 · 인게임 화면 틀 · 화면 이동 · 도착 연출 (이식)

**이 문서는** 인게임 화면의 공통 틀, 화면 이동, 도시 도착 연출의 설계와 현재 구현 범위를 설명합니다.
**보는 법** 현재 구현 → 간략 B → 세부 A → 보드 화면 방향 → 확인 범위 순서로 읽습니다. 함께 보기: [게임 시뮬레이터](../../../game-simulator.html) · [보드 프로토타입](../../../game-prototype.html).
**지금 상태** 개발됨(공통 모바일 프레임·모듈 이동·프로토타입 화면 전환의 소스 경로). 도시 도착 연출 전체와 실제 플레이 검수는 아래 확인 범위에서 구분합니다.

## 현재 구현과 기획 방향

| 구분 | 현재 확인한 구조 | 확인 경계 |
|---|---|---|
| [게임 시뮬레이터](../../../game-simulator.html) | 등록된 모듈을 같은 host에서 열고 활성·숨김·복귀 요청을 처리합니다. 세션과 독립 시험 범위를 유지합니다 | 등록·실행 경로를 확인한 것이며 모든 모듈의 실제 왕복 검수는 별도입니다 |
| 공통 모바일 프레임 | 상단 정보·현재 값, 콘텐츠 연출, 필러, 조작, 하단 메뉴를 나눕니다. 메뉴는 설정에서 읽고 사용 가능한 모듈만 엽니다 | normal·inline·popup 배치가 구분됩니다. 설정 치수를 모든 화면의 고정 크기로 보지 않습니다 |
| [보드 프로토타입](../../../game-prototype.html) | 로비·인게임을 바꾸며 같은 보드 무대를 옮깁니다. 굴림 경로 순서대로 위치를 표시하고 도착 결과를 반영합니다 | 공용 host와 다른 진입 화면입니다. 소스에 있는 전환을 실제 화면 검수 통과로 확대하지 않습니다 |
| 도시 도착 연출 | 아래 간략 B·세부 A의 T0~T3는 확대·성장 연출의 설계입니다. 보상 칸과 이벤트 칸의 표현 방향은 아래 「보드 화면 방향」도 함께 봅니다 | 모든 도착의 줌·배지·필러 동시 연출과 T2 완성을 이번에는 확인하지 않았습니다 |

현재 구현 설명을 먼저 읽고, 아래의 도시 화면·이식 설계와 구별합니다. [화면 구조](S06a_화면구조_모노이식.md) · [보드 연출](S06b_보드연출계승.md) · [문서 읽기 규칙](S17_기획서툴_제작기본양식_v02.md)을 함께 봅니다.

## 간략

**머리표** 시스템 기획 · S06 · 화면 · 모노 F24 화면 틀 · F25 화면 이동 · F26 칸 연출 이식(바꿔서 옮김)

**제목** 인게임 화면 틀 — 도시가 화면 대부분, 도착한 순간만 그 건물을 크게

**훅** 평소엔 도시 전체, 착지하면 그 건물 하나. 숫자 팝으로 끝내지 않는다.

**두 줄 요약**
- v6 B안은 도시 패널 중심의 화면 설계입니다. 당시 하단 5탭안과 현재 설정 기반 공통 모바일 메뉴는 구별합니다. 실제 메뉴의 이름·연결·활성 상태는 공통 프레임 설정에서 읽습니다.
- 착지하면 도시 패널 안에서 그 건물을 확대하고(T0), 판정 배지 · 필러 첫 카드 · 도착 수입 칩이 같은 프레임에 뜬다. 정체 변신(T2)만 전체 화면.

```mermaid
flowchart TB
  subgraph 화면층[v6 B안 화면 층]
    H[상단 HUD · 팬 점 · 칸 n/40 · 다음 무대]
    C[도시 패널 · 기울어진 3D]
    L[필러 로그 · 반투명 겹침]
    R[자원칩 · 일정 버튼]
    T[하단 5탭]
  end
  C -->|착지| Z[T0 도착 줌 · 그 건물 확대]
  Z --> B[판정 배지 · 필러 첫 카드]
  Z --> I[도착 수입 칩 × 배수]
  B --> S{방송 · 공연 칸?}
  S -->|예| F[필러 세로 슬롯 P72]
  Z -.투자하면.-> G[T1 몸집 · T2 정체 변신 전체 화면 · T3 꾸밈]
```

1. **본다** — 도시 패널 중심의 설계에서는 위아래 정보 띠와 메뉴를 둡니다. 현재 공통 모바일 프레임의 메뉴 개수는 설정 배열을 따릅니다.
2. **떨어진다** — 착지한 칸의 건물로 도시 패널 안에서 확대(T0, 약 1.5초 가안 · 탭 스킵).
3. **받는다** — 판정 배지(방송 · 공연만) · 필러 첫 카드 · 도착 수입 칩이 같은 프레임.
4. **자란다** — 투자해서 정체가 바뀔 때만 전체 화면(T2).

| 왜 지금 | 이게 핵심 | 이게 아닌 것 |
|---|---|---|
| 프로토 화면(로비 · 인게임 · 건설 시트)이 W03 B안과 어긋난 곳(「건설」 탭 · 번영 · 잭팟 통 표시)이 있어, 화면 기준을 한 장으로 묶어야 한다 | 화면 층 = v6 B안 · 도착 줌은 도시 패널 안 · 숫자 팝으로 끝내지 않음 | 새 화면 설계가 아니다 · 전환 규칙 문서가 아니다(기획서 없음) · 전투 연출이 아니다 |

## 보드 화면 방향 (신규)

- 와이번·헬기를 타고 날아가는 이동 연출은 경로가 안 보여서 반대한다.
- 칸이 고정되어 몇 칸 가면 어디 서는지 예측할 수 있어야 한다(「다음 굴림이 끔찍한 결과를 낼 수 있다는 걸 알게」).
- 마리오 파티 방식이 최선이다: 칸과 길이 또렷하고, 건물은 칸 옆에 크게, 비슷한 건물끼리 모아도 된다.
- 화살표 분기(윷놀이 느낌). 분기 위치·개수 **미정**.
- 칸이 빽빽하면 모바일에서 지글거린다. 칸은 아이콘(말풍선처럼)으로 확실히 구분한다.
- 보상만 있는 칸은 그냥 지나가고, 이벤트 칸에서만 연출한다.
- 건물은 LOD로 작게 보여 주다가 누르면 크게. 누르면 그 건물에 투자도 가능하다.
- 참고: 모노폴리고의 「말 고르기」.
