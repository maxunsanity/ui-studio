<h3 id="지켜야-할-선-7개-new-110102">지켜야 할 선 7개 (NEW · 11/01~02)</h3>

<ol>
<li>순위를 만드는 길은 하나: 성장 → 데뷔곡 → 도착 피드 → 홍보 · 투표 → 페스티벌 → 보상 → 다시 성장</li>
<li>돈은 속도 · 꾸밈 · 소장만 — 투표 · 채점 · 순위에는 닿지 않음</li>
<li>배수는 돈 · 성장에만 — 피드 · 팬 · 투표 · 순위 · 증축 비용엔 안 붙음</li>
<li>팬이 생기는 길은 시설 · 능력뿐 — 곡 · 페스티벌은 등급만</li>
<p>5. 시즌은 모두 같은 63일(9주) — 끝나면 건물 단계 · 맵 위 팬 · 건물 악개 · 도착 팬 돈만 초기화하고, 아이돌 · 카드 480장 · 능력 · 엔터파워 · 기획사 스탯 · 총 팬 · 재화는 이월</p>
<li>투표권 · 공유권 · 입장권 · 맞불은 팔지도 주고받지도 않음</li>
<li>서버가 정본 — 여럿이 얽히는 기록은 서버에서</li>
</ol>


<p>주사위를 굴려 보드에 도착하면 해당 칸의 규칙에 따라 수익과 성장 결과를 계산합니다. 번 돈으로 건물을 증설하면 시설 단계가 바뀌고, 시설 단계는 엔터파워·레슨·수익의 입력이 됩니다. 아이돌 활동에 따른 팬 변화도 경제와 연결해 비교합니다. 하나의 수치가 바뀌면 다른 곳의 진행 속도도 달라지므로 같은 입력·표·정책에서 결과를 살펴봐야 합니다.</p>

<h3 id="서로-다른-시험의-역할">서로 다른 시험의 역할</h3>

<div class="table-scroll"><table><thead><tr><th>경로</th><th>무엇을 살펴보나요</th><th>해석할 때의 경계</th></tr></thead><tbody><tr><td>발란스 시뮬레이터</td><td>주사위 시나리오, 하루 진행, 시설·팬·성장·콘텐츠 시험</td><td>시험 화면의 정책과 표를 확인; 계정 운영 결과가 아님</td></tr><tr><td>발란스 툴·기존 시즌 경제</td><td>표와 60일 경제, 충전·배수·돈·건설의 비교</td><td>설정과 시드가 있는 경제 실험; 결과는 해당 실행 조건의 관측값</td></tr><tr><td>핵심제안 계산 모델</td><td>보드·시설·팬·도시 방문을 굴림 단위로 계산</td><td>시간 대신 굴림 예산을 사용하고 이전 보드·성장 가정이 남은 참고 모델</td></tr><tr><td>공용 시뮬레이터의 성장·건설</td><td>같은 팀의 성장과 시설 거래·저장을 검토</td><td>시험 세션과 실제 운영 계정은 별도</td></tr></tbody></table></div>

</section><section class="part" id="part-3"><h2>3. 구동 방법·시뮬레이션</h2>

<p>화면 흐름: 입력 시나리오와 표 확인 → 시험 실행 → 굴림·시설·팬·성장 결과 → 같은 조건의 비교 · 이번 문서 수정의 새 실행·캡처 미실시 · 이식 비교는 S02의 기존 경제 자료를 참고합니다.</p>

<p><a href="/docs/planning/idle-sim.html" data-paper-path="docs/planning/idle-sim.html">눌러서 발란스 시뮬레이터 실행</a> · <a href="/docs/planning/balance-tool.html" data-paper-path="docs/planning/balance-tool.html">눌러서 발란스 툴 실행</a> · <a href="/docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EB%B0%9C%EB%9E%80%EC%8A%A4/core_balance_v01.html" data-paper-path="docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EB%B0%9C%EB%9E%80%EC%8A%A4/core_balance_v01.html">눌러서 기존 핵심제안 결과 보기</a></p>

<ol>
<li>발란스 시뮬레이터에서 현재 팀과 일차, 주사위 입력 시나리오를 확인합니다. 무료·평균·헤비는 같은 지급 기록이 아니라 서로 다른 시험 입력입니다.</li>
<li>배수와 시험 조건을 확인하고 실행합니다. 진행 중 입력을 바꾸면 새 지급량은 다음 날부터 적용됩니다. 이미 지급한 오늘의 값과 구분합니다.</li>
<li>굴림·시설·팬·성장·카드 등 화면의 결과를 읽고, 같은 표와 정책·진행 조건에서 비교합니다. 현재 시험 결과와 본게임 계정 지급은 별개입니다.</li>
<li>발란스 툴은 주제별 표와 기존 경제 실험을 살펴보는 곳입니다. 화면의 시험 조작이 원본 CSV를 고치는 행동인지, 시험 입력만 바꾸는 행동인지 각 화면의 안내를 확인합니다.</li>
<li>핵심제안 결과 페이지는 별도 굴림 단위 계산이 만든 결과 자료입니다. 생성 당시 표·시드·정책과 현행 표가 같은지 확인하기 전에는 지금 실행한 결과로 취급하지 않습니다.<ul><li>11/17 현중(질문 12): 핵심제안 계산 스크립트(<code>scripts/core-proposal-sim.mjs</code>)도 발란스 툴과 같은 재능 표(<code>idol_ability_talent</code> · 단계 문턱 · 단계 성장 3표 · <code>idol_growth_stat</code>)를 붙입니다. 판마다 그 판 시드로 멤버 재능을 만들고(툴과 같은 생성기), 재능이 없으면 능력이 오르지 않던 문제(능력 · 팬덤 0)를 없앱니다. 새 결과는 작업 폴더에만 내고, 결과 페이지 원본(<code>core_sim_v01.json</code>)은 현중이 숫자를 본 뒤 승인하면 바꿉니다.</li></ul></li>
</ol>

<p>도구를 열거나 실행하는 동작은 사용자가 직접 선택합니다. 표를 고치거나 결과 파일을 다시 만드는 명령은 이 문서를 읽는 것만으로 실행되지 않습니다.</p>

<h3 id="주사위-공급과-배수">주사위 공급과 배수</h3>

<p>하루에 들어오는 주사위와 한 번에 거는 배수는 다른 값입니다. 설계 조건은 보유량·엔터파워 문턱·해당 일차 상한이며 <code>maxOpenMultOn</code> helper가 이 셋을 함께 계산합니다. 현재 수동 성장 허브의 <code>growthEcon.openMult</code>·<code>roll</code>은 보유량·엔터파워만 검사하고 일차 상한을 적용하지 않습니다. 현재 표는 배수별 최소 보유량을 두고, 1일차·2일차의 상한을 별도로 둡니다. 주사위 공급 총량이나 배수 선택 조건을 문서에서 새로 정하지 않습니다.</p>

<h3 id="돈-단위와-도착-수익">돈 단위와 도착 수익</h3>

<p>기존 경제와 핵심제안 모델은 각각 <b>S</b>라는 시설 비용 기준을 사용해 비율을 돈으로 바꿉니다. 그러나 각 모델이 읽는 시설 행·비용·보드 연결과 비용 배율이 같다는 보장은 없습니다. S를 비교할 때는 어느 모델의 표와 계산으로 만든 값인지 먼저 확인합니다. <code>economy_config</code>의 시설 단계별 수익 시안과 현재 시설 단계 표의 수익 열도 같은 이름만으로 혼합하지 않습니다.</p>

<p>핵심제안 모델은 칸의 시설·단계, <code>board_tile_reward</code>의 수익 종류와 판정·배수 적용 여부, 팬 곡선과 시설 정보를 사용해 수익을 계산합니다. 별도 경제 엔진도 도착 종류·시설 상태·판정에 따라 수익과 장부를 처리합니다. 팬 항과 이벤트 보정 등은 각 계산 경로의 계약을 따르므로, 한 줄의 ‘모든 수익 × 배수’로 뭉치지 않습니다.</p>

<p>도착 필러의 3D 룰렛은 별도의 <b>표시 전용</b> 결과입니다. 그 화면에 표시한 코인은 경제 수익의 실제 지급 증거가 아닙니다. 필러 확률과 경제 판정의 가중치도 별개입니다.</p>

<h3 id="건물-비용과-엔터파워">건물 비용과 엔터파워</h3>

<p>현재 건설 거래는 시설 ID와 다음 단계의 <code>building_master_level.cost</code>를 읽어 견적을 만들고, 돈과 저장 상태를 확인해 구매합니다. 여러 단계 구매는 각 단계 비용을 합친 하나의 거래입니다. 시설 선택이나 필러의 건물 연출만으로 자동 증설되지는 않습니다. 경제 실험의 자동 증설 정책은 실제 건설 화면의 사용자 선택과 구분합니다.</p>

<p>핵심제안 모델은 <code>facility_growth_level</code>의 비용·팬·능력·기본 수익 열과 합쳐진 <code>building_master_level</code>을 함께 읽습니다. 능력 시설의 기본 레슨 배수는 합쳐진 표를 사용하고, <span class="yr-old">옛 <code>lesson_mult</code>를 쓰는 선택은 비교 경로입니다.</span> 같은 표 이름이나 ‘비용’이라는 말만으로 모든 열이 같은 정본에서 온다고 단정하지 않습니다. 비용·수익·레슨 효과는 비앙카 장부 산정 항목입니다.</p>

<p>엔터파워는 같은 시설에 연결된 여러 칸이나 세 동의 그림을 중복하지 않고 시설별 전체 단계를 합해 눈금으로 변환합니다. 배수·자동 충전 상한·캐스팅권의 문턱은 관련 표에서 각각 읽습니다. 자세한 현행 값과 예외는 <a href="/docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EC%97%94%ED%84%B0%ED%8C%8C%EC%9B%8C_%EA%B8%B0%ED%9A%8D%EC%84%9C.html" data-paper-path="docs/planning/%EC%82%BC%EC%A4%91AI_%EA%B3%B5%EC%9A%A9_20260929/%EC%82%B0%EC%B6%9C/%EA%B0%9C%EB%B0%9C%EC%A7%84%ED%96%89%EA%B8%B0%ED%9A%8D_v01/%EC%BD%98%ED%85%90%EC%B8%A0%EB%B3%84_v03/%EC%97%94%ED%84%B0%ED%8C%8C%EC%9B%8C_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">P172</a>를 따릅니다.</p>

<h3 id="아이돌-성장과-팬">아이돌 성장과 팬</h3>

<p>현재 아이돌 성장은 같은 멤버의 18세부 능력·재능·학습과 단계표를 기준으로 봅니다. 여섯 대표 축은 세부 능력의 평균이며 언어는 별도 학습값입니다. 한 시험의 옛 축 이름이나 시험 합류 보정을 현재 성장의 자동 승인값으로 옮기지 않습니다.</p>

<p>핵심제안의 <code>lessonArrival</code>은 해당 칸의 성장 대상·기본량·레슨 배수를 사용합니다. 코드 주석은 이 경로에서 칸 무게를 아직 곱하지 않는다고 설명합니다. 같은 프로젝트의 다른 성장 화면에서 주사위 배수나 아이템이 적용되는 방법과 같다고 가정하지 않고 성장 출처별 설정을 확인합니다.</p>

<p>팬 수익 시험은 팬층·시설·칸별 입력과 팬 곡선을 사용합니다. 일부 마일스톤·카드 연결은 선택적으로 읽는 표가 없으면 꺼질 수 있습니다. <b>선택적 연결이 꺼진 것</b>과 0을 지급하도록 결정된 것은 다릅니다. 팬층 이동량·수익·마일스톤 지급량은 비앙카 장부 산정 항목입니다.</p>

<h3 id="도시-방문과-이전-보드-가정">도시 방문과 이전 보드 가정</h3>

<p>핵심제안 모델은 지역 열림과 입장권을 시험하고 방문 굴림·수익·종료 보너스를 계산합니다. 지역·조건·수익은 시험 자료이며 현재의 별도 도시 방문 플레이 화면·계정 복원까지 완성된 뜻은 아닙니다. 현지 6축 보상을 세부 능력으로 변환할 기준이 없어 해당 증가는 대기로 남깁니다.</p>

<p>현재 핵심제안 <code>sim.ts</code>는 보드 표의 <code>group=corner_jail</code>을 읽어 그 자리에서 한 턴 쉬고, 도시 입장 기회는 <code>core_proposal_config.city_ticket_tile_id</code>를 읽습니다. 현재 그 설정값은 <code>board_tile_36</code>이며 31→11 순간이동이 소스에 고정돼 있지는 않습니다. 다만 한 턴 쉬는 굴림 모델과 실제 허브의 감옥 상태·더블 탈출·벌금 경로는 같지 않습니다. 전체 현행 보드 재현으로 표현하지 않고 남은 계산 차이의 비교는 작업 전으로 남깁니다.</p>

<h3 id="목표결과를-읽는-방법">목표·결과를 읽는 방법</h3>

<p><code>core_proposal_balance_target.csv</code>는 데뷔·성장에 닿는 굴림, 시설 평균 단계, 수익 구성 등 목표 범위의 시안을 담습니다. 핵심제안 실행은 여러 시드의 중앙값과 범위로 목표 통과 여부를 표시합니다. 이 PASS·FAIL은 <b>해당 시뮬레이션 정책과 목표표의 비교</b>이며 사용자 승인이나 실제 63일 플레이 통과가 아닙니다.</p>

<p>기존 시안은 기본 정책과 배수 변경, 도시 방문 제외를 비교합니다. 비교할 때는 시드 수·입력 주사위·배수·건설 정책·표 판본·계산 모델을 함께 기록합니다. 값이 바뀌거나 자료가 빠졌다면 과거 생성 결과를 현재 결과로 단정하지 않습니다.</p>
