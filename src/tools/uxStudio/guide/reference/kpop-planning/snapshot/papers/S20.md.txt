# S20 · 유저 스테이터스 저장 구조 v01

**이 문서는** 현재 브라우저 저장의 키·읽기·쓰기 경계와 유저 정보 표 구조안을 설명합니다.
**보는 법** 현재 저장 → 필요한 정보 → 미등록 표·열 구조안 → 서버 목표와 확인 범위 순서로 읽습니다. 함께 보기: [오디션·메인](../../../game-simulator.html?module=simulator_module_audition) · [P173 현재 저장](../개발진행기획_v01/콘텐츠별_v03/유저저장정보_기획서.html).
**지금 상태** 개발됨(분리된 브라우저 저장·인계·스냅샷·체크포인트 경로). 통합 계정·서버 저장과 아래 유저 표의 실제 저장 연결은 현재 개발되지 않음, 진행 중이며 화면·복원 전수 검수는 별도입니다.

## 0. 현재 저장과 권한

현재 확인한 구현은 브라우저 저장을 여러 묶음으로 나눕니다. 기본 키, 지도별 키, 독립 시험 접두를 함께 확인해야 같은 진행인지 알 수 있습니다. [P173 현재 저장](../개발진행기획_v01/콘텐츠별_v03/유저저장정보_기획서.html)과 [P222 서버 저장 목표](../개발진행기획_v01/콘텐츠별_v03/유저저장_핵심제안서.html)는 구현과 목표를 나누어 읽습니다.

| 기록 | 기본 키 또는 현재 설정 | 읽기·쓰기 경계 |
|---|---|---|
| 보드 경제 프로토타입 | `kpm:game:prototype:v1` (`profile.save_key`) | 경제 store가 읽기·묶어 쓰기·손상/이전 보존을 처리합니다. 시뮬 성장 저장과 같은 키가 아닙니다 |
| 오디션 단독 판 | 현재 profile의 `kpopmonsters.audition.simulator.v01` | 앱이 주어진 storage에서 세션을 읽고 씁니다. duelContext이면 전달받은 별도 키를 사용합니다 |
| 오디션 보드 판 | `kpopmonsters.audition.board.v01` | board_flow 설정을 읽습니다. `.generator`는 생성 기록이며 run과 함께 현재 원문 대조 후 교체합니다. 검토 모드·자식 대결은 별도 접미 범위입니다 |
| 오디션 보조 기록 | 판 키의 `.team`·`.stage-names`·`.duel-clock`·`.first-impression`·`.viewport-mode`, 성장 키 `kpopmonsters.audition.growth.v01` | 앱과 판의 저장 범위 안에서 읽고 씁니다. 이 목록은 전체 기능 키의 전수 목록이 아닙니다 |
| 합류 인계 | `kpopmonsters.handoff.audition_to_board.v1` | 오디션은 선택한 멤버의 인계만 발행합니다. 성장 스냅샷·체크포인트를 여기서 직접 소유하지 않습니다. 새 몬스 지급은 없습니다 |
| 시험 세션 | `kpopmonsters.simulator.test-session.v1` | test-session 관리자가 현재 팀·출처·run을 만들고 초기 스냅샷·시설 기록을 준비합니다. 같은 세션인지 확인합니다 |
| 성장 스냅샷 | `kpopmonsters.simulator.shared.v1` | 공유 표시용 현재 팀·능력·시설·위치를 검증합니다. 예상 revision과 현재 revision을 대조합니다 |
| 성장 체크포인트 | `kpopmonsters.simulator.growth.checkpoint.v1` | 전체 이어하기 상태는 run·자료 지문·revision·checksum·구조를 대조합니다. 스냅샷만으로 지갑이나 보상 영수증을 새로 만들지 않습니다 |
| 현재 지도 범위 | `kpopmonsters.simulator.shared.campus9.v1` · `kpopmonsters.simulator.growth.checkpoint.campus9.v1` · `kpopmonsters:board-map:campus9:facility-levels:v1` | 지도 runtime 설정과 scoped growth 어댑터가 성장 두 키를 바꿉니다. 오디션 인계와 예전 저장 전체를 한꺼번에 바꾸지 않습니다 |
| 독립 시험 범위 | `kpopmonsters.simulator.page-test.v1:{testPage}:` + 기본 키 | 유효한 모듈 ID 범위의 get/set/remove/clear만 처리합니다. host 메뉴 이동은 현재 run·scope를 유지하며 별도 진입 URL의 독립 범위와 구분합니다 |
| 팬·허브 및 쟁탈 흐름 | `kpopmonsters.simulator-hub.v1` · `kpopmonsters.casting-live-flow.v1` | 기능별 상태·요청 기록입니다. 전체 저장의 단일 정본이라고 보지 않습니다 |
| 발란스 시뮬 이어하기 | `kpopmonsters.idle-sim.run.v1` | idle-sim 전용 검증·checksum·자료 지문의 단일 기록입니다. 공용 게임 키와 분리합니다 |

### writer와 관측의 구분

- 오디션 인계는 `publishBoardRecruitment` → `writeHandoff`가 담당합니다. 인계 자료와 실제 성장 상태를 구분합니다.
- 시험 세션 관리자는 새 입력을 시작할 때 허용된 범위의 초기 스냅샷·시설·세션을 씁니다. 따라서 스냅샷의 모든 쓰기를 성장 화면 하나만의 작업이라고 설명하지 않습니다.
- 성장 공유 API는 스냅샷 발행과 전체 체크포인트 저장·검증을 제공합니다. 실제 성장 화면 내부의 모든 호출·정책은 이번에 열람하지 않았습니다.
- 건설 거래는 같은 run·차수·시설·지갑을 검사하고 변경을 임시 준비한 뒤 스냅샷·체크포인트·시설 기록을 함께 반영합니다. 실패 시 복구와 별도 오류를 구분합니다.
- 능력·관계 허브의 source reader는 setter 없는 storage를 받아 관찰합니다. 다른 scope로 넘어가거나 누락값을 임의 확정하지 않습니다.

## 1. 유저가 들고 있어야 할 정보

| 정보 | 현재 확인 또는 설계 경계 | 표 구조안 |
|---|---|---|
| 계정·기획사 | 계정 서버 저장은 목표이며 현재 브라우저 묶음과 구별 | user_account |
| 재화·시설·보드·팬·시즌 | 경제 상태와 전체 체크포인트 등 분리된 묶음에 있습니다. 모든 항목의 서버 통합은 미구현 | user_wallet · user_building · user_board_progress · user_fan · user_season |
| 보유 멤버·능력·스킬 | 생성 결과·합류 인계와 현재 성장 상태를 구분합니다. 스킬 정의와 실제 획득 슬롯도 구분 | user_member · user_member_stat · user_member_skill |
| 카드·아이템 | 정적 표는 보유 원장이 아니며 실제 진행 기록과 구별합니다. 항목별 영속 저장 전수 검수는 별도 | user_card · user_item |
| 라포 | 현재 허브는 유효한 같은 진행의 snapshot/checkpoint 등에서 읽는 경로가 있습니다 | user_rapport_pair |
| 미션·출석·오디션 기록 | 프로토타입 기능별 상태와 판 기록이 있으며 아래 유저 표로 통합 저장된 것은 아닙니다 | user_mission · user_attendance · user_casting_history |

구조안의 아이템 지속/스킬 즉시 연결 자리와 보임·숨김·간접 구분은 보존합니다. 시즌에 남길 항목과 정리할 항목은 [P222](../개발진행기획_v01/콘텐츠별_v03/유저저장_핵심제안서.html) 및 콘텐츠별 최신 기획의 범위를 따르며 아래 과거 초안의 초기화 메모를 새 확정 결정으로 적용하지 않습니다.
