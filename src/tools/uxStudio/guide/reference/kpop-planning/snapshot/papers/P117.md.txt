## 1. 개요

콘텐츠 하나를 개발할 때 필요한 문서·리소스·실행·데이터·진행 상태를 한곳에 모으는 작성 기준입니다. 어떤 AI든 이 문서와 [P88 악귀 디펜스 대표 샘플](../콘텐츠별_v03/악귀디펜스_기획서.md)을 읽고 같은 순서로 작성합니다. HTML은 요약·이미지·조작 설명·리소스·표를 바로 보여주며 짝 MD는 동일한 기준과 상세 근거를 보존합니다.

| 콘텐츠 | 기획 경계 | 현재 관련 문서 |
|---|---|---|
| 보드 기본 구성 | 칸 순서·도시 자리·보드와 화면의 연결 | P87 작성 예시 / P72 기반 |
| 보드 주사위 구동 | 주사위 입력·소비·이동·도착·저장 | P72 기반 / P74 현재 시연 |
| 보드 건물 유닛 | 건물 선택·증설 단계·외형·방어 전환 | P81 툴 / P76 변형 |
| 필러 구동 | 도착 상황·대화 상자·행동 버튼·문구 조건 | P72 실행 표 / 필러 문구 미정 |
| 악귀 방어전 구동 | 침입·변형·드론/쌍포·잔적 처치·승리 | P76 현재 / P77 설계 |

왼쪽은5개 콘텐츠를 선택합니다. 오른쪽은 대표 기획서와 그 콘텐츠의 관련 자료를 보여줍니다. P88 악귀 디펜스를 현재 대표 샘플로 지정하고 P87은 보드 기본 구성 작성 예시로 보존합니다. 주사위·건물 유닛·필러의 새 상세 양식 전환은 후속 대상이며 기존 자료와 결정 대기 상태를 표시합니다.

책갈피의 각 문서에 콘텐츠와 역할을 붙입니다. 공용 카탈로그의 content는 문서당 한 값으로 유지합니다. 개발 진행 기획에서는 planning_development_plan.csv와 planning_development_reference.csv로 여러 콘텐츠가 같은 원문을 참조합니다. 문서의 현재/근거/리소스/테이블/검수·이전 역할을 관계 표에 적습니다. 원문 복제와 왼쪽 개별 자료 나열을 하지 않습니다.

## 3. 구동 방법·시뮬레이션

실제 모듈 주소 확인 → 문서에 입력·조작·판정·연출 설명 → 공용 시뮬레이터 링크 → 결과·중단·복원 검수 순서입니다.

- 카탈로그 path에 HTML을 등록하면 문서 선택 즉시 자동 미리보기가 나옵니다.
- 실제 구동 방법을 상세히 설명하고 P94 모듈 실행/새 창 링크를 연결합니다. 시뮬레이터와 기획서 툴을 문서 안에 iframe으로 넣지 않습니다.
- 전투·자원 소비는 이용자가 시작할 때만 실행합니다.
- 시작·입력·결과·저장·복원·중단 중 구현된 조작만 안내합니다. 미구현이면 상태를 명시합니다.
- 시안 예시와 본게임 값, 검수 저장과 계정 저장을 구분합니다.
- 같은 문서에 관련 표 보기를 표시합니다. 필요하면 원본 크게 보기 링크를 둡니다.
- :7007 서버가 꺼져 있으면 보고하고 기다립니다. 재가동하지 않습니다.

대표 실행 주소는 `/docs/planning/p58-defense-proto-v01.html?embed=p88`이며 P88의 3장에서 조작합니다. P87에는 기존 보드 기반 실행을 보존합니다.

## 4. 상세 기획

시작·종료 조건 / 입력·출력·단위·키 / 상태 전환·중복 입력 / 성공·실패·미정·예외 / 저장·복원·호환성 / 다른 모듈 연결·담당 경계를 반드시 작성합니다. 기능마다 구현·제안·미정·제외 상태를 구분합니다.

분리된 기능으로 설계하고 콘텐츠·규칙·값은 CSV에서 읽습니다. 임시 고정값을 사용한 시연이면 그 위치와 대체할 표를 적습니다. 필러 문구·밸런스·다른 담당 리소스를 지시 없이 변경하지 않습니다.

## 6. 관련 CSV·테이블 데이터

파일 경로·역할·주키·참조·자료형·단위·미정 항목·담당을 실제 머리줄과 등록표에서 확인합니다. 미정값을 0이나 기본값으로 채우지 않습니다. 새 인덱스·키는 CSV 파일명 전체 규칙을 따르고 직접 유지하기로 한 도시 city_ 등의 예외는 원문대로 기록합니다.

- 등록된 공용 표: `/docs/planning/game-table-tool.html#실제_표이름`을 문서 안에 표시합니다. CSV 받기는 복사본입니다.
- 이름 있는 iframe에서 표를 바꿀 때는 `?table=표이름#표이름`처럼 조회 주소도 바꿔 화면이 재로딩되게 합니다. 이 툴은 초기 hash를 읽으며 외부 hash 변경만으로 표를 바꾸는 기능은 없습니다.
- 별도 실행 표: 해당 전용 보기 또는 CSV 원문을 연결합니다. 공용 표 보기의 지원 목록을 확인합니다.
- 현중이 지정한 `/docs/planning/game-table-tool.html#festival_ticket`은 관련 표 보기의 참고 예시입니다. 보드 기본 구성의 필수 참조로 지정하지 않습니다.
- 새 표가 필요한 경우 제안 스키마·필요 이유·담당과 실제 파일 존재 여부를 구분합니다.

### 등록 절차

1. 기존 카탈로그에서 미사용 문서 번호와 콘텐츠 키를 확인합니다. 이번 규칙은 P86, 대표 샘플은 P88, 보드 예시는 P87입니다. 다음 문서는 이 번호를 재사용하지 않습니다.
2. HTML·짝 MD·리소스·실제 실행 화면을 검증합니다. HTML은 짧은 화면 요약과 실제 보기, MD는 동일한 기준과 상세 근거를 담습니다.
3. data/planning_doc_catalog.csv에 새 행을 추가합니다. 실제 머리줄은 path,no,title_ko,aliases,content,shelf,status,pair_html,pair_tool,pair_ops,parent_constitution,one_liner입니다. path에 HTML을 등록하면 선택 즉시 자동 미리보기가 나옵니다. pair_html은 짝 화면, pair_tool은 실제 제작 툴 주소, pair_ops는 운영 문서가 있을 때만 씁니다. parent_constitution은 실제 상위 기준 문서를 참조합니다. 없는 주소를 채우지 않습니다.
4. data/planning_development.csv에 새 행을 추가합니다. 실제 머리줄은 development_id,doc_no,group_key,group_ko,title_ko,state_ko,summary,sort_order입니다. development_id는 planning_development_로 시작하는 고유키를 씁니다. 기존 행과 정렬값을 지우지 않습니다.
5. 현재 P86·P87은 콘텐츠 devprogress / 책갈피 concept / 카탈로그 상태 draft로 등록합니다. 화면의 산출 상태는 제안(검수 대기)입니다. 콘텐츠 key가 없다면 planning_content.csv의 실제 머리줄과 기존 분류를 먼저 확인합니다. 기존 콘텐츠가 있으면 새 중복 분류를 만들지 않습니다.
6. 툴 ?face=development&doc=문서번호에서 등록과 자동 미리보기를, ?face=shelf&doc=문서번호에서 책갈피와 기준 문서를 확인합니다. 새 제작 툴을 별도로 등록할 때만 planning_surface.csv의 실제 규칙을 확인합니다.
7. 링크·이미지·CSV·iframe의 정상 내용을 확인하고 1440×900/430px 캡처를 남깁니다. 수정 파일은 먼저 백업하고 공용 보고 후 STATUS에 보고 경로를 포함해 완료 줄을 추가합니다. 이전 담당자 줄을 덮어쓰지 않습니다.

## 2026-10-07 · 기획별 CSV 목록과 공용 테이블 등록

전체 테이블 P73은 특정 콘텐츠에 소속되지 않는 공용 도구입니다. 현재 등록96파일을 보이며 새 CSV는 아래 등록표에 추가합니다. 실제 실행에서 읽는 표, 기획 참고, 리소스 제작 설정을 구분합니다. 등록하지 않은 과거 버전을 현재 실행 표로 표시하지 않습니다.

### 1. 전체 CSV를 한 번 등록합니다

`data/planning_csv_table.csv`의 머리줄은 다음과 같습니다.

```csv
planning_csv_table_id,table_key,label_ko,group_ko,rel_path,url,primary_key,schema_url,schema_table,foreign_keys,state_ko,summary,sort_order
```

- planning_csv_table_id는 planning_csv_table_ 접두어의 풀네임 고유키입니다. table_key는 같은 파일명이 충돌하지 않도록 영역·버전을 포함합니다. 예: planning_csv_table_defense_proto_v05_entity_config / defense_proto_v05_entity_config입니다. 기존 공용 게임의 mons_skill·festival_ticket 주소 키는 유지합니다.
- rel_path는 실제 프로젝트 상대 원본 경로입니다. url은 현재 서버에서 CSV 원문을 반환하는 주소입니다. HTTP200이어도 오류 HTML이면 실패입니다.
- primary_key는 실제 존재하는 고유 열을 적습니다. 단일 고유 열이 없으면 비워 두고 행 순서로 표시합니다. 데이터의 열 이름과 기존 키를 임의로 바꾸지 않습니다.
- schema_url/schema_table은 실제 JSON 스키마가 있을 때만 연결합니다. foreign_keys는 열에서 `table_key.column`으로 연결하는 JSON 객체입니다. 없으면 `{}`입니다. 예: model_id → defense_proto_v05_model.model_id입니다.
- state_ko와 summary에는 시안 예시·미정·원본 참고·툴 등록 등 실제 상태와 용도를 씁니다. 데이터 행 수는 원본을 읽어 자동으로 표시합니다. 빈 표를 구현 완료로 표시하지 않습니다.

### 2. 기획별 사용 관계를 등록합니다

`data/planning_csv_usage.csv`의 머리줄은 다음과 같습니다.

```csv
planning_csv_usage_id,planning_development_plan_id,planning_csv_table_id,usage_kind,purpose,source_ref,sort_order
```

- planning_csv_usage_id는 planning_csv_usage_ 접두어의 풀네임 고유키입니다. 두 참조 키는 실제 콘텐츠 등록표와 전체 CSV 등록표의 행을 가리킵니다.
- usage_kind는 runtime(실행 로더에서 읽음), reference(기획 참고), resource(리소스·제작 설정) 중 하나입니다. 읽기만 하는 표의 빈 대사·빈 수치를 기능 완성으로 해석하지 않습니다.
- purpose에는 해당 기획에서 필요한 이유를 씁니다. source_ref에는 실제 로더·실행 모듈·기획 문서 경로를 적습니다. 여러 근거는 세미콜론으로 나눕니다. 추측으로 관련 표를 늘리지 않습니다.
- 여러 기획이 같은 CSV를 쓰면 전체 등록은 한 행이며 관계만 여러 행으로 연결합니다. 같은 콘텐츠+CSV 관계는 중복 등록하지 않습니다.

### 3. 기획서 툴과 내용판에 연결합니다

기존5기획은 P89 보드 기본 구성(33표), P90 주사위(14표), P91 건물(32표), P92 필러(17표), P93 악귀 디펜스(45표)를 사용합니다. 수는 현재 등록 스냅샷이며 화면의 수는 관계 표에서 계산합니다.

새 기획에는 공용 `game-table-tool.html?plan=실제콘텐츠풀네임키#table_key`를 사용합니다. 독립 CSV 페이지가 필요하면 공용 화면 양식의 body에 data-plan=실제콘텐츠키를 설정하고 같은 game-table-tool.ts 모듈을 연결합니다. 표를 하드코딩한 별도 뷰어를 만들지 않습니다. CSV 등록과 관계만 바꾸면 실제 목록·경로·용도·빈 표·데이터 행은 함께 반영됩니다.

페이지 HTML/짝MD를 실제 CSV 경로·용도 목록과 함께 제공하고 planning_doc_catalog.csv·planning_development.csv에 등록합니다. planning_development_reference.csv에는 role=csv로 해당 기획과 연결합니다. 오른쪽 사용 CSV 버튼이 이 문서를 바로 엽니다. category=common의 전체 테이블 P73은 왼쪽 공용 도구에 유지합니다. 콘텐츠가 늘어날 때 공용 도구를 특정 콘텐츠 안으로 옮기지 않습니다.

### 4. 확인과 보고

등록 고유키·연결·머리줄·행 수·실제 CSV 원문·참조 버튼·기획 필터·빈 표·검색·열 선택·페이지 이동·CSV/ZIP 복사본을 확인합니다. 1440×900와430px에서 페이지 가로 넘침과 표 내부 스크롤을 확인합니다. 원본 데이터·이전 문서를 보존하고 공용 완료 보고·증거·STATUS를 남깁니다. 변경된 CSV 목록의 짝MD도 동기화합니다.

### 뺀 것·옮긴 것

기획서마다 흩어진 CSV 진입점을 동일 공용 뷰어로 연결합니다. 기존 전용26표 뷰어·공용32표 원본 데이터·이전 시안·게임 로더는 삭제하지 않습니다. 이 등록은 게임 데이터의 확정이나 본게임 배포를 뜻하지 않습니다.

CSV 관계의 sort_order=0은 처음 보여 줄 대표 CSV 한 건을 지정합니다. 나머지는1부터 순서를 정합니다. 처음 열 표를 화면 코드에 하드코딩하지 않습니다. 내장 화면은 실제 표가 먼저 보이도록 안내·검사·원본 정보는 접어 제공하며, 모바일에서는 CSV 선택 목록을 제공합니다.
