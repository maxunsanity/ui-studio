# 컷씬 에디터 진행 기획서 · 2026-09-21

사용자 요구와 실제 구현을 구분한 진행 기록. 정밀 캐릭터 자동 제작이나 원작 수준 연기 완성을 의미하지 않는다.

## 목표와 제작 방식

준비된 캐릭터·배경·모션을 사용자의 콘티에 맞춰 배치하고, 단이가 구조화한 지시를 웹에서 편집·재생한다. 카툰으로 보이는 3D와 직교 촬영을 함께 지원한다. 자유 문장 해석 AI와 Blender 실시간 동기화는 아직 연결하지 않았다.

## 연구에서 현재까지

Flow Studio의 리소스·카메라·시간 편집 방식을 참고해 웹 편집기를 제작했다. 로봇과 카드 기반 초기 모델은 원하는 품질에 못 미쳐, 완성된 플로우 VRM을 활용하는 방향으로 전환했다. 텀블링 시험 후 가벼운 인사·웃으며 손 흔들기·얼굴 클로즈업을 실험했다.

## 캐릭터와 모션

플로우 일반판 VRM의 원본 카툰 재질을 사용한다. VRoid 공식 무료 VRMA 7종을 불러와 재생했고 Blender 작업 파일도 준비했다. 기존 공식 모션과 이번 두 배우의 작은 대화 동작은 구분한다. 새 대화 동작은 웹에서 뼈대를 조절하는 시험 연기이며 새 Blender 모캡 결과가 아니다.

## 편집 화면과 저장

중앙에 큰 촬영 화면, 아래에 높이를 조절하는 작업 캔버스를 배치했다. 휠 확대, 가운데 버튼 이동, 우클릭 회전 및 키보드 이동을 지원한다. 컷·카메라·대사 수정, 잠금, 되돌리기, JSON 전달을 지원한다. 파일은 브라우저에 저장되며 다른 브라우저에는 전체 프로젝트 JSON으로 옮긴다.

## 1인 시네마틱 보존

기존 약 29.3초·10컷 시네마틱과 7.8초짜리 360도 회전 촬영을 보존한다. 같은 공식 모션의 시작 구간을 조정해 컷이 바뀌어도 동작을 이어 사용한다. 모션 모음도 별도 종류로 보관해 비교할 수 있다.

## 두 영상에서 가져온 연출

2026-09-21 사용자가 제공한 약 68.94초와 41.69초 영상을 분석했다. 투샷, 어깨 너머 구도, 청자 반응, 얼굴과 넓은 공간의 교차가 핵심이다. 두 파일에는 오디오 트랙이 없어 음성·효과음은 평가하지 않았다. 360도 회전은 강조용으로 두고 대화의 거리와 시선을 우선한다.

## 추가한 2인 대화

같은 플로우 모델을 독립된 두 배우로 불러오고 B의 머리와 옷 재질을 푸른색으로 변경한다. 눈 원본의 연한 홍채는 작은 동공을 렌더링 단계에서 보강했다. 28초·8컷으로 서로 바라보기, 작은 손짓, 미소, 끄덕임과 자막 대화를 구성했다. 배우별 위치·몸 방향·머리색과 컷별 연기·시선 대상·미소를 편집할 수 있다. 음성과 립싱크는 아직 없다.

## 장면 종류와 보존 규칙

왼쪽 장면 종류에서 기존 시네마틱, 2인 대화, 공식 모션 모음을 선택한다. 전환할 때 현재 장면의 수정도 저장하며 각 장면의 컷과 배우 배치는 분리된다. 캐릭터와 모션 원본 데이터는 프로젝트에서 공유한다. JSON 내보내기에 모든 종류의 장면을 함께 포함한다.

## 다음 제작 과제

Blender에서 대화용 작은 동작을 정교하게 다듬고 배우별 연속 모션 트랙과 동작 전환을 확장한다. 음성·입 모양, 눈동자 정밀 시선, 초점 효과, 영상 출력, 게임 시작·스킵·종료 연결은 후속 범위다. 현재 연습실은 동작 검증용 공간이다.

## 결론

이번 레퍼런스의 핵심은 두 사람의 관계를 찍는 것이다. 카메라 이동량보다 인물의 거리, 시선, 손동작, 듣는 사람의 반응과 컷 전환의 타이밍이 중요하다. 현재의 1인 모션 시연을 두 인물의 상호작용 장면으로 확장해야 한다.

360도 회전은 별도의 강조 구간으로 유지할 수 있지만, 이 두 영상의 대화 연출을 재현하는 첫 번째 우선순위는 아니다. 대화용 기본 장면은 투샷 → 어깨 너머 구도 → 반응 얼굴 → 다시 투샷으로 구성하는 편이 적합하다.

## 분석 범위와 근거

- 영상 1: 화면 기록 2026-09-21 오후 3.30.49.mov, 약 68.94초.
- 영상 2: 화면 기록 2026-09-21 오후 3.32.35.mov, 약 41.69초.
- 파일 검사상 두 파일 모두 영상 트랙만 있고 오디오 트랙이 없다. 음성 연기, 음악, 효과음, 음성과 입 모양의 일치는 평가하지 않았다.
- 전체 구성을 3초 간격으로 추출하고, 영상 1의 54~68초와 영상 2의 15~26초는 1초 간격으로 추가 관찰했다. 아래 시간은 구간을 찾기 위한 근사치이며 프레임 단위 컷 편집표가 아니다.

## 현재 에디터에서 달라져야 하는 것

소스의 Project에는 characterId가 하나이고 Shot에도 action, from, to가 각각 하나다. speaker는 자막용 문자열이다. 따라서 지금 구조에서는 화자 이름을 바꾸는 것만으로 두 사람이 따로 움직이며 대화하는 씬을 만들 수 없다.

| 우선순위 | 필요한 기능 | 이유 |
|---|---|---|
| 1 | 배우 목록과 배우별 위치·방향·크기 | 두 인물을 한 공간에 배치하고 각각 제어 |
| 1 | 배우 A/B의 독립 모션 트랙 | 화자는 손짓하고 청자는 듣거나 반응해야 함 |
| 1 | 컷과 분리된 장면 시간축 | 카메라를 바꿔도 인물 동작과 대사는 계속 이어져야 함 |
| 1 | 시선 대상: 상대 얼굴 / 특정 지점 / 시선 피하기 | 카메라 대신 상대를 보고 말하도록 함 |
| 1 | 두 사람 구도와 어깨 너머 구도 프리셋 | 매 컷마다 좌표를 직접 맞추는 작업 감소 |
| 1 | 화자와 촬영 대상을 별도 지정 | A가 말할 때 B의 반응 얼굴을 보여주기 |
| 2 | 표정 트랙, 눈 깜빡임, 고개 끄덕임 | 큰 전신 동작 없이도 대화가 살아 보이게 하기 |
| 2 | 동작 사이 전환 시간과 손·머리 부분 동작 | 전신 모션을 갑자기 교체할 때 생기는 튐 완화 |
| 2 | 대사 구간과 무언 반응 구간 | 답하기 전 잠깐의 망설임, 말이 끝난 뒤의 반응 표현 |
| 3 | 음성·입 모양·초점 효과 | 기본 상호작용과 프레이밍이 된 다음 추가 |

### 카메라 설계 제안

- 두 사람을 잇는 선을 기준으로 기본 촬영 방향을 정하고, 컷이 바뀌어도 좌우 관계가 갑자기 뒤집히지 않게 한다.
- 얼굴 주시점은 고정 높이 숫자 대신 해당 배우의 머리/눈 위치를 기준으로 계산한다.
- 어깨 너머 구도는 전경 배우의 어깨와 후경 배우의 얼굴을 함께 지정한다. 전경 머리가 얼굴을 가리면 경고하거나 구도를 보정한다.
- 카툰 표현과 카메라 투영 방식을 분리한다. 이 레퍼런스처럼 전경과 후경의 거리감을 살리려면 원근 카메라를 먼저 시험하는 것이 좋다. 카툰 재질은 그대로 유지할 수 있다.
- 모든 컷을 움직이지 않는다. 표정이 중요한 컷은 고정하거나 아주 조금만 이동한다.
- 360도 회전을 쓸 때는 두 사람과 배경의 가림, 시선 방향을 전체 경로에서 확인한다. 기본 대화 실험이 완성된 뒤 강조 구간 하나에 선택적으로 넣는다.

### Blender와 웹의 역할 제안

Blender는 배우의 기본 자세, 작은 대화 손짓, 고개 움직임과 동작 전환을 다듬는 데 사용한다. 웹 에디터는 두 배우 배치, 모션 구간 선택, 대사, 시선 대상, 카메라 컷과 타이밍을 조립한다. Blender만 사용한다고 자연스러운 상호작용이 자동으로 생기는 것은 아니다.

기존 VRoid 7종은 인사·브이 사인·포즈 등 개별 동작 시험에 활용할 수 있다. 이번 레퍼런스의 듣기, 미세한 망설임, 상대를 보며 작은 손짓을 하는 연기까지 충족하는지는 별도로 확인해야 한다. 우선 필요한 동작은 대화 대기, 작은 설명 손짓, 듣기, 짧은 끄덕임, 몸 방향 전환이다.

## 첫 두 명 대화 씬 제안: 「기다리고 있었어」

아래는 원작 대사 복제가 아닌 새 시험 콘티다. 약 28초, 8컷. A와 B는 시작부터 같은 공간에 있고 서로를 본다. 음성이 없으면 자막 길이에 맞춰 시간을 조정한다.

| 시간 | 카메라 | A의 연기 | B의 연기 | 대사·의도 |
|---|---|---|---|---|
| 0~3초 | 두 사람 전신, 짧은 접근 | B를 향해 고개 돌림 | 발을 멈추고 A를 봄 | 공간과 두 사람 위치 소개 |
| 3~7초 | B 어깨 너머 A 상반신 | 작은 미소, 한 손으로 가벼운 인사 | 듣기 유지 | A: “왔네. 조금 기다렸어.” |
| 7~10초 | A 어깨 너머 B 얼굴 | 이전 동작 마무리 | 짧게 시선 내렸다가 A를 봄 | B: “많이 기다렸어?” |
| 10~14초 | 옆쪽 투샷 | 고개를 작게 젓고 B 쪽으로 몸을 향함 | A를 따라 시선 이동 | A: “아니. 같이 걷고 싶어서.” |
| 14~17초 | B 얼굴 클로즈업 | 화면 밖에서도 대기 유지 | 망설임 후 미소 | 0.7초 무언 반응 뒤 B: “나랑?” |
| 17~21초 | B 어깨 너머 A 얼굴, 미세 접근 | 눈맞춤 뒤 짧게 끄덕임 | 듣기 | A: “응. 너랑.” |
| 21~24초 | 두 얼굴이 함께 보이는 가까운 투샷 | B의 반응을 기다림 | 미소와 끄덕임 | B: “좋아. 가자.” |
| 24~28초 | 두 사람 전신으로 전환, 느린 후퇴 | 길 쪽으로 몸을 돌림 | 같은 방향으로 돌림 | 여운. 걷기 리소스가 준비되면 함께 이동 |

콘티의 한 행에는 화자뿐 아니라 청자의 행동도 기록해야 한다.

## 구현 순서와 검증

1. 프로젝트 데이터를 복수 배우와 독립 모션 트랙으로 확장하고 기존 1인 프로젝트를 변환한다.
2. 임시로 같은 모델을 두 배우로 배치해 위치·방향·독립 재생을 검증한다. 최종 외형은 구별되는 두 캐릭터를 사용한다.
3. 투샷과 양방향 어깨 너머 구도부터 만들고 시선 맞추기를 검증한다.
4. 위 8컷 콘티를 적용한 다음 표정과 동작 사이 전환을 다듬는다.
5. 음성·입 모양·초점 효과와 선택적 회전 촬영을 추가한다.

완료 기준: 두 배우가 독립적으로 움직인다 / 서로 눈높이가 맞는다 / 컷이 바뀌어도 모션이 처음으로 돌아가지 않는다 / 청자의 반응을 보여줄 수 있다 / 얼굴과 손이 가려지지 않는다 / 저장·다른 브라우저로 가져오기 후 두 배우와 시간축이 유지된다.

## 리소스는 그림이나 모델 파일만으로 충분한가

캐릭터가 ‘걸어온다’는 지시를 실행하려면 사용할 수 있는 걷기 표현도 필요하다. 움직임을 새로 만드는 기능까지 포함할지는 별도 결정이다. 첫 실험은 준비된 동작을 조합하는 범위로 제안한다.

| 대상 | 공통으로 기록할 것 | 2D에서 추가할 것 | 3D에서 추가할 것 |
|---|---|---|---|
| 캐릭터 | ID·파일·버전·미리보기·별칭·가능한 행동 | 기준점·원본 크기·좌우 방향·표정·레이어·애니메이션 방식 | 크기 단위·앞 방향·뼈대 구조·애니메이션 클립·표정 지원 |
| 배경/공간 | ID·장소 설명·등장/도착 기준점 | 전경/중경/후경·가림 순서·카메라 이동 가능 영역 | 좌표계·이동 가능 영역·장애물·조명·카메라 배치 영역 |
| 소품 | ID·크기·사용법·연결 대상 | 겹침 순서·손 위치 | 부착 지점·충돌·물리 적용 여부 |
| 소리 | ID·파일·길이·반복 여부·기본 음량 | 공통 항목 사용 | 공간음 사용 여부 |
| 대사 | 대사 ID·화자·본문·언어·음성 연결 | 표정 및 입 모양 지원 여부 | 표정 및 입 모양 지원 여부 |

이름이 비슷한 파일을 추측해서 쓰지 않도록 고유 ID를 붙인다. 필요한 동작이 없을 때는 누락을 보고하고 대체 가능한 표현을 제시하도록 설계한다.

## 콘티에 담을 내용 — 첫 양식 제안

사용자가 모든 좌표와 시간을 직접 적는 방식은 목표가 아니다. 사용자에게는 의도를 표현하기 쉬운 양식을 제공하고, 구체적인 실행 값은 단이가 정리하되 가정한 내용을 표시한다.

| 단위 | 적을 내용 |
|---|---|
| 장면 | 목적·장소·등장인물·감정 흐름·대략적인 길이 |
| 컷 | 컷 ID·보여줄 대상·구도·행동·대사·소리·다음 컷으로 넘어갈 조건 |
| 필수 지시 | 꼭 지켜야 하는 행동·표정·순서·대사 |
| 재량 범위 | 자동으로 정해도 되는 구도·시간·전환 |
| 참고 자료 | 이미지·스케치·영상 구간과 참고하려는 요소 |
| 수정 지시 | 대상 컷 ID·바꿀 것·유지할 것 |

### 가상 시험 콘티

실제 게임 내용이나 리소스 보유 여부를 뜻하지 않는 시험 예시다. 10~15초는 초기 시험용 제안값이다.

장면 의도: 주인공이 연습실에 도착해 첫 연습을 앞두고 마음을 다잡는다. 처음은 조용하고 마지막에 기대감이 느껴진다.

| 컷 ID | 연출 지시 | 다음으로 넘어갈 조건 |
|---|---|---|
| C01 | 연습실 전체를 보여준다. 주인공이 입구에서 지정된 자리로 이동한다. 이동하는 동안 화면도 주인공을 따라간다 | 이동과 카메라 움직임이 모두 끝남 |
| C02 | 얼굴을 가까이 보여준다. 주인공이 미소 짓고 “시작해 볼까?”라고 말한다 | 대사 표시 또는 음성 재생이 끝남 |
| C03 | 주인공과 연습 공간이 함께 보이도록 넓게 보여주고 서서히 어둡게 전환한다 | 전환 완료 후 종료 |

2D에서는 레이어 이동·크기 변화·표정 교체 등을 사용할 수 있다. 3D에서는 공간 이동·카메라 위치·애니메이션 등을 사용한다. 같은 감정과 사건을 표현하되 두 방식의 구현 값은 별도로 정한다. 표정이나 걷기 리소스가 없으면 그 사실을 먼저 드러내야 한다.

## 툴이 이해할 연출 단위

| 기능 | 표현해야 할 내용 |
|---|---|
| 배치 | 어떤 리소스를 어느 기준점에 놓는가 |
| 이동 | 출발·도착·경로·속도 또는 소요 시간 |
| 동작/표정 | 준비된 동작 ID·반복·전환·완료 시점 |
| 카메라 | 보여줄 대상·구도·이동·확대·컷 전환 |

첫 시험에서는 선형 장면과 동시 실행·완료 대기를 우선 검증한다. 복잡한 분기·전투 중 연출·절차적 동작 생성 등은 별도 후속 범위로 제안한다.

| 모듈 | 책임 |
|---|---|

콘티 원문·정리된 지시·실행 데이터·수동 수정 내역을 연결해 보관한다. 재생성을 해도 사용자가 고친 컷을 보존할 방법이 필요하다.

5. 3D 캐릭터에 리깅과 필요한 동작이 준비돼 있는가?
6. 단이가 정해도 되는 연출 범위와 반드시 사용자 의도를 확인해야 하는 범위는 무엇인가?
7. 생성 뒤 직접 편집할 항목은 어디까지인가?

지금 모두 답할 필요는 없다. 첫 장면·리소스·실행 환경부터 정하면 나머지를 실제 결과를 보며 좁힐 수 있다.

## 첫 실험 순서와 통과 기준

1. 장면 의도를 하나 고르고 2D·3D 최소 리소스 묶음을 준비한다.
2. 같은 의도를 자유 서술과 컷별 표로 각각 적어본다.
3. 단이가 리소스 ID와 실행 지시로 정리하고 누락·가정을 표시한다.
4. 두 표현 방식으로 구성·재생해 콘티와 결과를 비교한다. 작업 순서는 정하되 양쪽 지원 여부를 각각 기록한다.
5. “C02의 미소만 늦춰줘”처럼 한 부분을 수정해 다른 컷과 수동 편집이 유지되는지 확인한다.
6. 결과와 실패 사례를 [연구 목차의 실험 양식](./087_컷씬에디터_연구목차.md)에 남긴다.

| 확인 항목 | 통과 기준 제안 |
|---|---|
| 의미 일치 | 필수 사건·행동 순서·대사가 콘티와 일치 |
| 리소스 연결 | 등록된 리소스를 정확히 사용하고 누락을 표시 |
| 동시 실행 | 이동과 카메라가 함께 진행되고 완료 조건이 맞음 |
| 재현성 | 같은 실행 데이터와 리소스 버전으로 재생 결과가 유지됨 |
| 부분 수정 | 대상 컷만 바뀌고 보존 대상으로 정한 편집이 유지됨 |
| 탐색/재시작 | 중간 시점 이동과 재시작 때 상태가 깨지지 않음 |
| 스킵/종료 | 잔여 소리·카메라·입력 잠금이 남지 않고 게임에 복귀 |
| 2D/3D | 각각 위 항목을 검증하고 지원 차이를 기록 |

성능 목표·작업시간 절감 목표·허용 수정 횟수는 대상 기기와 시험 장면을 정한 뒤 수치로 정한다.
