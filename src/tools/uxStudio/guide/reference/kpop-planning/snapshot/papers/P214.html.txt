<p><span class="yr-old">하단 작업 기록에 보존한 이전 구현 시안은 기존 앨범·크루·활동합계 차트·단일 파이널 모듈을 비교하는 메모리 시험입니다.</span> 최신 성장 차트·주간/월드 기획의 시험은 5장의 새 시안을 사용합니다. 두 시안 모두 실제 저장·지갑을 변경하지 않으며 미공급값을 운영값으로 채우지 않습니다.</p>
</section><section class="part" id="part-4"><h2>4. 상세 기획</h2><h3>앨범 소규모 차트 연결</h3>
<p>앨범 발매로 열리는100명·약1일 순위 이벤트 게임입니다. 현재 로컬은 본인+가상99명을 명시합니다. 첫100위에서 출발하고 후속은 현재 보유 팬·계층과 직전 마감 최종성적으로 시작합니다. 보드 신규 팬 증가를 주력으로, 주사위 소모를 보조로 점수를 쌓아 현재 순위별 돈·팬·기존 능력을 적립하고 다음1번START에서 정산합니다. 만료 뒤 신규 효과는 끝나며 얻은 성장·미정산 적립·최종 성적은 보존합니다. 보통 활동은4<del>5번째 첫1위 도전, 성장 좋은5</del>8번째 입장1위도 가능하며 차수별 고정 등수는 없습니다. 메인 차트 말풍선·활동/다음 시작 예상 게이지는 같은 규칙을 읽습니다. <a href="%EC%9D%8C%EC%95%85%EB%B0%A9%EC%86%A1%EC%B0%A8%ED%8A%B8_%EA%B8%B0%ED%9A%8D%EC%84%9C.html">앨범 차트 정본</a>에서 성장곡선·원본·계산·저장·실제 구현을 봅니다. 실제 유저 매칭 서버는 미구현이며 유저 투표는 없습니다.</p>
<h3>시즌과 콘텐츠의 시간 기준</h3>

<h3>앨범 차트와 페스티벌의 분리</h3>
<p>앨범 차트는 유저 투표 없이 무작위 소규모 그룹에서 팬·성장·앨범 실적을 비교하는 콘텐츠입니다. 발매별 약1일 리그·성장 유사 매칭·보드 실적과 돈 효과 종료를 정의하며 정확한 기간/지급 방식은 별도로 정합니다. 주간·월드페스티벌은 실제 유저의 참여·조회/추천·투표·유저 채점단 등 평가를 조합하는 별도 콘텐츠입니다. 팬 투표100%로 처리하지 않습니다. 두 콘텐츠의 순위ID·결과·보상 원장을 섞지 않습니다.</p>
<p>데뷔곡을 포함해 최대8개의 싱글을 발매할 수 있습니다. 모든 유저에게8곡을 의무 지급하지 않습니다. 주차가 바뀌어도 개인 제작의 기간·미션·성장 문턱을 건너뛰지 않습니다. 9주차 월드는 이미 발매한 곡 중 한 곡으로 출전하며, 상세 참가 자격과 마감은 페스티벌 정본을 따릅니다.</p>

<h3>현재 구현과 필요한 변경</h3>
<p>season_config.season_days는 63(11/04 현중 확정, <span class="yr-old">이전 값 60</span>)이고 reset_items는 건물 단계·맵 위 팬·건물 악개·도착 팬 돈입니다. 기존 구현은 같은 실행의 앨범·크루·차트·파이널 기록 보존 시험과 기존 보드 정산 연결이 있습니다. 주간/월드 회차 타입·9주 달력·계정 보존 후 전환 조정은 미구현입니다. 63일 시즌 리셋은 개발됨이며, 주간/월드 회차와 계정 보존 연결이 끝나기 전에는 전체 전환 완료로 표시하지 않습니다.</p>
<p>공용 season_days 63을 읽는 게임·자동 발란스·툴이 일치하는지 검증합니다. 별도의 음악 전용60/63일 원본을 중복 운영하지 않습니다. 현황판은 전환 결과를 읽으며 수동 초기화·회차 생성 기능을 추가하지 않습니다.</p>

<h3>구현 원본과 운영 원본의 경계</h3>
<ul>
<li>기능 조작은 게임 시뮬레이터에서 수행합니다. 모바일 하단에는 크루·페스티벌·앨범·차트 바로 가기를 기존 메뉴 아래에 배치하며, 최종 UI 기획에 맞춰 재배치할 수 있습니다. 오토플레이는 자동 시험, 현황판은 결과 조회입니다.</li>
<li><a href="../../../../../../data/music_career/music_career_rules.json">음악 규칙 원본</a>의 비어 있는 수치는 null로 유지합니다. 원본·단위·기준 사건이 없으면 대기하며 시험값을 운영값으로 저장하지 않습니다.</li>
<li><a href="../../../../../../src/simulator/music-career/game-bridge.mjs">실제 보드 연결</a>은 관측한 방송·공연과1번 START 통과만 받아 기존 지갑·팬·능력 입구에 적용합니다. UI의 출발점 통과 시험은 시험 정산 기록만 만들며 실제 지갑에 지급하지 않습니다.</li>
<li>앨범 능력 보상 계수/원본 영수증은 canonical_score 최종점수입니다. 각 합류 멤버에 전량을 배분하고, 공용 게임은 그대로, 오토플레이는 검증된 기존 표시 배율 K를 한 번 적용합니다. 재능·주사위·포지션 배율은 다시 곱하지 않으며 기존 개인 단계 상한·일일 제한을 지킵니다. 조건 판정은 별도로 관측값과 문턱의 단위를 맞춥니다.</li>
<li>실제 지역 방문·현지 공연 원장, 운영 파이널 자격/달력, 수상별 reward_group 매핑, 계정 명예 기록 인터페이스는 미공급입니다. 지역 선택 시험과 결과 보존을 실제 방문·시상 지급·계정 영구 저장 완료로 처리하지 않습니다.</li>
</ul>
<h3>수락 기준</h3>
<p>같은 실행과 곡 참조를 사용하고, 비어 있는 값을 확정0이나 임의 보상으로 바꾸지 않습니다. 실제 보드 사건과 시험 조작을 구분하며 같은 활동·표·정산은 한 번만 반영합니다. 기획과 계산·실제 화면 검수 범위를 나눠 기록합니다.</p>
<h3>뺀 것·옮긴 것·보존한 것</h3>
<p>이전 본문과 변경 근거는 하단 로그에서 보존합니다. 다른 콘텐츠 전체 준비중 목록과 전체 기획·표 재검수는 이 기능 개발 범위에 포함하지 않습니다.</p>
<h3>후속 로컬 구현과 남은 연결</h3>
<p>readFestivalCalendar는 운영 seasonDays와 config의 totalWeeks×daysPerWeek를 먼저 대조합니다. 일치한 명시 입력에서만 정수일차 양끝 포함의 현재 주/주간/월드 창을 파생합니다. 시즌 시작0도 그대로 유지하며 종료 뒤 다음 시즌을 자동 생성하지 않습니다. 9주차 중복 정책 null은 회차 수와 추가 주간창을 비어 있음으로 둡니다. 공용 표는 63으로 바뀌었고, 보상/보존 뒤 reset 실행 연결은 현재 개발되지 않음, 진행 중입니다.</p>
<p>관련 통합시험과 별도 팬 단조 경계3,751건을 통과했습니다. 정확한 최신 통과 수와 명령은 공용 보고·검증 로그에 기록합니다. 실제 공용게임의 명시 시험 조건으로 신규 발매 자동 연결·메뉴 왕복·새로고침 보존을 확인했습니다. 새 주간/월드 참여집계·운영 순위/지갑지급·63일 초기화를 완료한 검수가 아닙니다. <a href="../../../%EC%A6%9D%EA%B1%B0/20261103_142753_%EB%8B%A8%EC%9D%B4_9%EC%B0%A8_%EC%95%A8%EB%B2%94%ED%81%AC%EB%A3%A8_%EC%9B%94%EB%93%9C%ED%8E%98%EC%8A%A4%ED%8B%B0%EB%B2%8C_%ED%86%B5%ED%95%A9%EA%B0%9C%EB%B0%9C/release-followup-actual.jpg">실제 발매 자동 연결 검수 화면</a></p>
<p><a href="/docs/planning/balance-tool.html?topic=balance_topic_music">음악 발란스 주제</a>는 같은 음악 원본을 읽는8행 상태표입니다. 로컬 이벤트는 팬/보드 목표와1회 반영 한도를 원표에서 표시하고 실제 저장 결과를 조회합니다. 현황판은 자동 결과 조회이며 제작·발매·투표 조작을 넣지 않습니다.</p>
