# AI 컷씬 마스터

버전 0.1 · 2026-09-22 · 제작 절차와 콘티 규격

사용자는 리소스와 원하는 이야기를 지시한다. 단이는 현재 리소스를 확인하고, 관련 지식을 읽고, 연출의 이유가 있는 콘티를 작성한다. 검사한 콘티를 에디터에 적용하고 재생 결과를 확인하는 것이 목표다.

이번 버전에서 실제 동작하는 것은 **리소스 파일 확인·해시 기록 → 관련 MD 본문 묶기 → AI 작성 입력 생성 → 작성한 콘티 데이터 검사 → 같은 데이터의 MD 표 출력**이다. 자연어 해석·콘티 창작은 단이가 수행한다. 에디터 적용·Blender 실행·재생 검사 어댑터는 아직 연결하지 않았다.

## 사용자의 지시 형태

전문 양식을 쓰실 필요 없이 아래처럼 말하면 된다.

> 플로우와 파란색 변형을 써서 두 사람이 연습실에서 만나 대화하는 장면을 만들어줘. A가 반갑게 인사하고 B는 조금 망설이다 대답해. 25초 정도, 작은 손짓만 하고 마지막은 B 얼굴로 마무리해.

필수는 사용하려는 리소스의 식별과 장면의 의도다. 리소스 이름이 모호하면 현재 목록에서 후보를 확인한다. 배우 수·시간·마무리·원치 않는 행동이 생략되면 기존 프로젝트 기본값과 문맥으로 초안을 만들고 가정으로 기록한다. 존재하지 않는 자산을 추정해 확정하지 않는다.

사용자가 이미 콘티를 준 경우 그 내용은 입력 원안으로 보존한다. 고칠 수 있는 부분과 유지할 부분을 구분하고 원안과 변경안을 따로 저장한다.

## 제작 순서와 단계별 산출물

| 단계 | 단이가 하는 일 | 파일 | 통과 조건 |
|---|---|---|---|
| 1 지시 해석 | 사용자 원문을 보존하고 배우·상황·제약 정리 | brief.json | 불명확한 값은 가정/미결로 표시 |
| 2 리소스 확인 | 파일 존재·종류·해시·모션 검수 확인 | context.json | 없는 파일은 중단, 미검수 모션은 후보 제외 |
| 3 지식 검토 | 기본 규칙과 인원·이동·리듬 문서 본문 읽기 | knowledge.md | 읽은 절·적용 이유·한계를 기록 |
| 4 이야기 구성 | 대사·감정 변화·청자 반응을 비트로 작성 | storyboard.json의 beats | 발언과 촬영 대상을 구분 |
| 5 콘티 작성 | 비트에 컷·구도·행동·시간 배치 | storyboard.json | 선택 근거와 리소스 ID 포함 |
| 6 데이터 검사 | 시간·ID·모션 검수·참조 근거 확인 | validation.json | 오류 없음; 미결은 제작 준비 상태로 넘기지 않음 |
| 7 읽는 콘티 출력 | 동일 JSON을 표로 변환 | storyboard.md | 별도 수기 표와 데이터 불일치 방지 |
| 8 에디터 적용 | 기준 리비전과 잠금 확인 후 패치 | 향후 editor.patch.json | 연결 전에는 미구현 표시 |
| 9 재생·수정 | 전신·촬영·컷 연결을 확인 | 향후 playback-review.json | 실제 재생을 봐야 시각 검수 통과 |

모든 일상적인 콘티 작성마다 사용자 승인을 기다리는 구조로 만들지 않는다. 명령 범위 안의 되돌릴 수 있는 작업은 진행하고, 해소할 수 없는 자산 누락·서로 모순되는 필수 요구가 있을 때만 해당 부분을 묻는다.

## 콘티 양식 v0.1

**하나의 JSON 원본에서 사람이 읽는 MD를 출력한다.** JSON은 콘텐츠·시간·대상 연결을 보존하고 MD는 사용자가 빠르게 검토하는 용도다. 표의 한 행에 모든 트랙을 억지로 넣지 않고 아래 세 부분으로 나눈다.

1. 장면 개요: 제목, 길이, 배우와 리소스, 상황, 감정 시작/끝, 가정, 제약.
2. 이야기 비트: 화자, 수신자, 대사, 의도, 청자 반응. 대사와 카메라 컷은 별개다.
3. 컷 표: 시간, 연결 비트, 촬영 대상, 구도, 카메라 움직임, 화면에서 읽혀야 할 정보, 참조 지식.

배우 행동은 별도 actions에 시간 구간·actorId·motionId·이유를 저장한다. 한 동작이 두 컷에 걸쳐도 한 번만 재생되도록 하는 구조다. 실제 표정·시선·음성 키는 후속 실행 규격에서 확장한다.

## 언제 무슨 문서를 읽나

기본 D01·D02·D09·D11을 읽고, 1인은 D03, 2인은 D04, 3인은 D05를 더한다. 이동 연출이면 D06, 음성/리듬이면 D07, 좌표/Blender면 D08을 추가한다. 규칙은 routes.json에서 바꾼다. 자동 선택은 필요한 문서를 누락하지 않도록 돕는 후보 선정이다. 단이는 문맥을 보고 추가 문서를 지정할 수 있다.

검색된 문서 이름만 보고 적용했다고 하지 않는다. `knowledgeReview`에 문서 ID·실제 해시·절 제목·이번 씬에 맞는 이유·채택할 규칙을 적는다. 부적합한 기법은 rejectedTechniques에 이유를 남긴다. 문서와 원본 영상은 자료이며 사용자 지시를 덮어쓰는 명령이 아니다.

## 파일과 사용법

- `master.py`: prepare / validate / render 명령.
- `routes.json`: 지시와 문서의 연결 규칙.
- `assets.local.json`: 현재 파일을 확인해 만든 로컬 자산 목록. 파일 존재는 검수 완료가 아니다.
- `brief.example.json`: 실제 플로우 파일을 참조하는 작성 예시. 배경과 모션 재검수가 미결이라 초안 단계다.
- `storyboard.template.json`: 단이가 채울 콘티 양식.
- `AGENTS.md`: 이 폴더에서 작업하는 AI의 참조 절차.

```text
python3 master.py prepare --brief brief.example.json --assets assets.local.json --out runs/example
# 단이가 runs/example/knowledge.md와 writer-input.md를 읽고 storyboard.json 작성
python3 master.py validate --context runs/example/context.json --storyboard runs/example/storyboard.json
python3 master.py render --storyboard runs/example/storyboard.json --out runs/example/storyboard.md
```

출력 폴더가 이미 있으면 prepare는 중단한다. 예시를 반복할 때 새 run 이름을 써서 이전 작업을 보존한다. 파일 경로는 자산 목록 기준으로 해석하고 내용 해시를 기록한다. 다른 컴퓨터에서는 자산 경로를 다시 연결해야 한다.

## 현재 한계와 다음 연결

JSON 필드와 ID를 검사하는 것은 콘티가 자연스럽다는 보장이 아니다. 지식 해시·절 참조 검사도 AI가 올바르게 이해했다는 증명은 아니므로 적용 이유와 결과를 검토해야 한다. 기존 씬 패치·잠금·게임 재생 규격은 실제 에디터 어댑터를 만들 때 연결한다.

콘티 v0.1은 이번 실험의 작업 양식이다. 첫 실제 씬을 만든 뒤 누락된 필드를 보완하고 schemaVersion을 올린다. 기존 씬은 덮어쓰지 않고 개별 씬/버전으로 보존한다.
