## 제1장 게임 기조 — 무엇을 만드나

| 조 | 규칙 | 이게 아닌 것 |
|---|---|---|
| **제1조 성장축과 영구 축적** | 중심 성장축은 내가 영입한 **아이돌(최대 30자리 · 360장)**이며, **스태프(9자리 · 108장)·팬클럽 회장(1자리 · 12장)·엔터파워(잠금/상한 해제)·기획사 스탯(영구 회사 성능)**이 함께 누적된다. 활성 40자리(480장)와 졸업 명예의 전당→스태프 전직이 이어진다. 시점은 전지적 하나 | 「빠순이 → 사장」 시나리오(09-30 폐기) · 이미 뜬 스타 따라다니기 · 주인공 둘 |
| **제2조 장치는 성장을 보여 준다** | 보드·건물·도시·카드 40자리·스케줄·몬스·주간/월드 페스티벌·외부 음악 앱은 모두 그 아이돌과 기획사가 얼마나 컸는지 **보여 주는 장치**다. 보드 건물은 시즌 안에 쓴 돈을, 엔터파워·기획사 스탯은 영구 축적을 보여 준다 | 처음부터 무거운 경영 시뮬 |
| **제3조 모노카피바라가 기본** | 모노카피바라·모노폴리 GO의 **확장**이지 새 게임이 아니다. 모노 기능을 다 알고 나서 기획한다. 본문을 쓰기 전에 모노와 같은 점·다른 점부터 나눈다. **구조만 옮기고 수치는 복사하지 않는다** | 모르는 기능으로 기획 · 모노 수치 그대로 이식 · 새 시스템 발명 |
| **제4조 시즌제 (63일 · 건물만 초기화)** | 한 시즌 = **63일(9주)** — 주간 페스티벌 1~8주 + 9주차 월드 페스티벌. 시즌이 끝날 때 **초기화되는 것은 건물 단계·맵 위 팬·건물 악개·도착 팬 돈뿐**이다. **아이돌(최대 30명)·스태프 9자리·팬클럽 회장 1자리·카드 덱 480장·카드로 올린 능력·돈·주사위·엔터파워·기획사 스탯·총 팬·명예의 전당은 전부 영구 이월**한다 | 시즌마다 아이돌/카드까지 전부 초기화(11/12 폐기) · 시즌마다 판 규칙 자체를 새로 만듦 |
| **제5조 건물 성장이 기본** | 시즌 안 보드 건물은 **쓴 돈으로만** 큰다(몸집·정체·꾸밈 세 층). 건물은 시즌 안 계기판이자 초기화 대상이며, 영구 회사 바탕 등급은 **기획사 스탯**이 맡는다 | 새 게이지 발명 · 대박으로 건물이 큼 |
| **제6조 대박은 그날만 (100% 필러 룰렛)** | 보드 28칸 착지 판정은 **대박(올킬)·중박(차트인)·운망(광탈) 필러 룰렛**(1차 15/50/35%, 1차 대박 시 5% 확률 단발 2차 룰렛: 대박 50%/중박 30%/운망 20%, 연속 없음, 8·23·38 강제 점프 차단, 「올킬 돌림판」 이름 유지). 대박은 **그날만 한 급 위**이고, 칸 급이 영구로 바뀌는 건 성장 투자뿐이며 칸 급은 하나씩 오른다 | 복권식 찬스 · 숫자 팝만 있는 착지 · 3차 이상 연속 룰렛 |
| **제7조 보드와 도시는 다르다** | 행보판은 **40칸**(9주차 월드 변신). 보드 = 일정 순서, 도시 = 장소. 시즌 전환으로 맵(도시)이 바뀌어도 40칸 보드 뼈대는 유지되고 건물 단계는 시작 단계로 돌아가며 맵 위 팬·건물 악개·도착 팬 돈만 초기화된다. 40칸을 줄 세워 GO식 집→호텔 쌓기를 하지 않는다 | 칸마다 GO식 집→호텔 쌓기 |
| **제8조 막지 않는다** | 늦게 온 유저도 자기 무대가 있다(주간 동레벨 100명 구역, 월드 실력별 리그·상위 4~10% 동시 차트 인→파이널 1,000·5탭). 리드젠·창작곡·크루 협업은 **선택**이며, 안 해도 기본 보상과 핵심 진행은 절대 막지 않는다 | 카드북 완성자 전용 입장 · 연결해야만 진행되는 게이트 · 동의 없는 연락 |
| **제9조 안전과 따로 두기** | 아바타는 파츠로만 만들고 실존 인물·실존 IP를 닮게 하지 않는다. 아이돌 성장 / 총 팬 / 맵 팬 / 도시 건물 성장은 **각자 따로** 둔다. 아이돌 카드는 ★ 합성을 금지하고 **몬스(27종)만 1~10단 자동 합성**을 쓴다. 내부 발주곡(4장르 32~36곡)과 창작곡(`mp3` 3분)을 이원화하고 창작곡은 사람/AI 검수를 거쳐 등록한다 | 사진 업로드·AI 얼굴 · 확률형 곡 뽑기 · 아이돌 ★ 합성 |

## 제2장 기획서의 성격 — 무엇을 쓰고 무엇을 안 쓰나

| 조 | 규칙 |
|---|---|
| **제10조 컨셉과 1차 개발 기준의 연결** | 기획서는 컨셉·시스템·UI를 하나로 잇는다. 1차 개발과 발란스 시뮬레이터·게임 시뮬레이터, UX 스튜디오(T04 `W→P→U→S`, 430/1440px 기준)에 바로 반영할 수 있게 기준을 맞춘다. 글과 보여 줄 화면이 한 쌍이다 |
| **제11조 상태는 사실대로 쓴다** | 문서 상태는 「개발됨」 또는 「현재 개발되지 않음, 진행 중」 둘 중 하나로 쓴다. 임의의 보류·대기 문구로 채우지 않고, 누구도 임의로 승인이라 쓰지 않으며 확정은 현중만 한다 |
| **제12조 숫자는 현재 세팅값 또는 0동작** | 모든 수치는 발란스 기준표·시뮬레이터에 실제 들어간 **현재 세팅값**을 적고, 값이 비어 있으면 **「비어 있음(0으로 동작)」**처럼 사실대로 적는다. 추측 숫자를 지어내지 않는다 |
| **제13조 선택지는 현재 안을 함께 적는다** | 확정 전 선택지는 원문 라벨과 **현재 세팅한 초안**을 함께 적어 시뮬·구현이 멈추지 않게 한다. 모호한 보류 표기를 남기지 않는다 |
| **제14조 근거가 있어야 한다** | 회의록 원문·책갈피(P240)·현중 지시와 모순되지 않는다. 근거 링크를 적는다. 채택된 것만 기준이고, 씨앗 문서는 기준이 아니다 |

## 제3장 쓰는 양식 — 어떻게 보이게 쓰나

| 조 | 규칙 |
|---|---|
| **제15조 간략 먼저, 세부는 연결** | 간략이 먼저다. **현중은 간략만 본다.** 세부는 간략에 연결되고, 간략이 바뀌면 세부를 같이 고친다. 한쪽만 있으면 미완이다 |
| **제16조 읽는 길** | 아래 그림 순서로 읽고 고친다 |
| **제17조 그림 중심, 글자 최소** | 장마다 그림이 중심이고 글은 캡션과 짧은 요약만 둔다. **시퀀스·플로우 그림을 장마다 1개 이상** 넣는다. 게임 루프·보드 한 턴·경제 순환·카드 흐름·보상 지급·페스티벌 진행은 반드시 흐름도로 그린다 |
| **제18조 간략 양식 (B)** | 장마다 한 화면: 머리표 → 제목 → 훅 한 줄 → 두 줄 요약 → [왼쪽 그림 · 오른쪽 1·2·3·4 흐름] → 「왜 지금 · 이게 핵심 · 이게 아닌 것」. 문단 금지 |
| **제19조 세부 양식 (A)** | 머리 블록 → 0. 한 줄 → 컨셉 / 시스템(규칙 ID `R-장-번호`) / 화면(`V-장-번호`) 칸을 섞지 않는다 → 표 위주 → 「이게 아닌 것」 한 줄 필수 → 맨 아래 「아직 안 한 것 · 현재 세팅 기준」 |
| **제20조 목차가 먼저 보인다** | 문서를 열면 **목차가 제일 먼저** 나온다. 작성 이력 같은 문서 정보는 맨 아래로 내린다 |
| **제21조 같은 말을 쓴다** | 공통 용어표를 따른다(아래). 「레벨」이라 쓰지 않고 단계·등급으로 표기한다 |
| **제22조 말하는 순서로 놓는다** | 문서는 남한테 설명하는 차례로 놓는다. 한 시즌 흐름 순서(영입·40자리 → 카드북 → 보드·건물 → 스케줄·몬스 → 음원·주간(1~8주)·월드(9주) → 시즌 전환)를 따른다 |


## 제4장 고치고 보관하기 — 어떻게 바꾸나

| 조 | 규칙 |
|---|---|
| **제23조 결정은 한 번에 흐른다** | 변경 후속 확인 항목은 11장에 모은다. 현중이 정하면 해당 장의 간략·세부·핵심제안·책갈피를 **같이** 고친다 |
| **제24조 이력은 로그로 옮긴다** | 변경 이력·지난 기록·지시 기록은 본문에서 빼서 같은 폴더의 `문서이름.log.md`(「변경 이력」·「지난 기록」 두 칸, 최신이 위)로 옮긴다. 기획서 툴은 이 파일이 있으면 「로그」 버튼을 보인다 |
| **제25조 바꾸기 전에 백업** | 문서·목록·툴을 바꾸기 전에 `docs/planning/_backup/날짜_시각_이유/` 에 원본을 둔다 |
| **제26조 중복도 일단 쓴다** | 겹치는 기획이라도 일단 산출한다. 조율은 산출 뒤에 한다. 겹친다는 이유로 멈추지 않는다 |
| **제27조 중복·사본은 백업 후 정리** | 불필요한 중복 문서·사본은 백업한 뒤 책갈피에서 빼고 정리한다. 안 쓰는 콘텐츠는 이유를 적어 로그나 서랍(미사용 · 재료)에 둔다 |
| **제28조 툴에서 만들고 잇는다** | 기획서는 기획서 툴에 등록하고 서로 연결한다. 단독 md나 단독 세부만 있으면 미완 |

## 제6장 모든 기획서의 틀 — 맨 위 세 줄과 맨 아래 접힌 칸

| 조 | 규칙 |
|---|---|
| **제29조 맨 위 필수 틀** | 모든 기획서는 제목 바로 아래에 세 줄을 둔다. **이 문서는**(무슨 기획서인지 한 줄) · **보는 법**(읽는 순서, 같이 열 시뮬레이터 링크 또는 「시뮬레이터 없음」) · **지금 상태**(「개발됨」 또는 「현재 개발되지 않음, 진행 중」). 표로 만들지 않고 굵은 글자로 시작하는 세 줄로 쓴다 |
| **제30조 본문에 쓰지 않는 것** | 변경 이력, 지시 기록, 줄 번호, 임의의 보류·대기 문구, 봇 이름을 본문에 쓰지 않는다. 사람이 처음부터 끝까지 읽어 이해할 수 있게 쓴다 |
| **제31조 로그 파일** | 이력은 같은 폴더의 `문서이름.log.md`로 옮긴다(확장자를 떼고 `.log.md`). 안은 「## 변경 이력」(최신이 위, `날짜 시각 · 누가 · 무엇 · 왜 · 근거`)과 「## 지난 기록」(본문에서 뺀 옛 내용을 보관) 두 칸이다. 짝 md와 html은 로그 하나를 같이 쓴다. 카탈로그에는 등록하지 않는다 |
| **제32조 작업 기록 접힌 칸** | 「읽은 원본」·「계기」·상태 줄·경로·줄 번호 목록 같은 짧은 작업 메모는 본문 맨 아래 접힌 칸에 둔다. md는 `<details><summary>작업 기록</summary> … </details>`, html은 같은 내용을 `<details>`로 넣는다 |
| **제33조 책갈피가 메인** | 모든 기획 내용은 책갈피에 있어야 한다. 핵심제안 개발과 제안서 카드는 책갈피와 같은 내용·같은 숫자로 맞춘다. 숫자는 표 값을 읽어 쓴다 |
| **제34조 핵심제안 카드 개요는 고정** | 핵심제안 개발의 콘텐츠 카드 설명(`planning_development_plan.csv`의 `summary`)은 1~2문장 개요만 두고, 현중 지시 없이 고치지 않는다. 세부와 변경 내용은 기획서와 로그에만 쓴다. 날짜 · 옛 안 · 결정 내역 · 임의의 보류 문구는 카드에 쓰지 않는다 |
| **제35조 가리키는 말에는 링크** | 본문은 짧게 쓰고, 다른 문서나 개념을 가리키는 낱말(문서 번호 · 능력 · 배경 · 이야기 · 성격 · 라포 · 팬 등)마다 상세 내용이 있는 책갈피 대표 문서로 가는 마크다운 링크를 건다. 주소는 그 문서 파일로 가는 상대 경로(html 짝이 있으면 html, 없으면 md. 예: `[P147](../개발진행기획_v01/콘텐츠별_v03/팀결성_팀스탯_기획서.html)`, 같은 폴더면 `[S07b 상점](S07b_상점.md)`)로 통일한다. 기획서 툴 자체의 화면 주소(`/docs/planning/planning-docs-tool.html?face=…&doc=…`)만은 화면 이동 계약이라 query와 hash를 그대로 둔다([P86](../개발진행기획_v01/작성기준_v02/작성규칙.html) 「문서 독서와 core 조작 주소」). 검수 때는 링크가 빠진 곳을 찾아 고치고 7007에서 열리는지 확인한다. 책갈피에 대표 문서가 없는 말은 목록으로 보고한다 |
