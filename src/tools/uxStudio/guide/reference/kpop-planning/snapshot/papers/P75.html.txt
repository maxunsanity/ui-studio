</section><section class="part" id="part-3"><h2>3. 데이터 기준</h2>
<p>성장 규칙은 <code>data/idol_ability_sim/v02/</code>, 오디션 생성은 <code>data/audition_sim/v01/</code>, 방어 규칙은 <code>data/bad_energy/v06/</code>를 각 영역의 기준으로 사용합니다. 연결은 <code>data/simulator/shared/v01/</code> 계약을 거칩니다. 같은 이름이라는 이유로 서로 다른 단위의 숫자를 합치지 않습니다.</p>
<p>성장이 쓰는 상태를 건설·방어는 복사해서 읽습니다. 3D 건설 시험값·전투 피해·전투 보상은 성장 경제에 되쓰지 않습니다. 기존 60일 경제 실험은 비교 자료이며 최신 성장의 대체 실행 경로가 아닙니다.</p>
</section><section class="part" id="part-4"><h2>4. 제안 카드 읽는 법</h2>
<p><a href="/docs/planning/proposal-concept/idol.html">아이돌</a>, <a href="/docs/planning/proposal-concept/audition.html">오디션</a>, <a href="/docs/planning/proposal-concept/growth.html">건물 성장</a>, <a href="/docs/planning/proposal-concept/bad-data.html">악귀와 몬스</a>, <a href="/docs/planning/proposal-concept/mons-skill.html">몬스 스킬</a> 카드에 현재 구현·실행 링크를 보완했습니다. 카드의 콘셉트 그림과 실제 플레이 화면은 구분하며, 구형 설명용 수치를 실행 데이터로 사용하지 않습니다.</p>
</section><section class="part" id="part-5"><h2>5. 전체 정리 원칙</h2>
<p>대표 기획서의 앞부분에는 현재 실행 기준을 둡니다. 이전 상세 설계·작업 로그는 접힌 기록으로 보존하고, 공용 보고와 증거는 삭제하지 않습니다. 중복되는 성장 메뉴와 오래된 「시뮬 없음」 설명을 최신 메뉴로 모읍니다.</p>
</section><section class="part" id="part-6"><h2>6. 아직 별도인 영역</h2>
<p>출연권 대전·게릴라 공연·새 도시 진출·시즌·운영 경제는 각 기획서의 개발 상태를 유지합니다. 이벤트 게임도 기존 항목·데이터·코드를 유지합니다. 이번 연결은 전체 게임 완성이나 계정 서버 연동을 뜻하지 않습니다.</p>

<h2>간략</h2>
<p>기획서 툴 「핵심제안 시스템 개발」 탭은 <strong>바뀌어 가는 제안서를 바탕으로 만든 개발 기획서</strong>를 담습니다. 모든 대표 기획서는 <a href="%EC%9E%91%EC%84%B1%EA%B8%B0%EC%A4%80_v02/%EC%9E%91%EC%84%B1%EA%B7%9C%EC%B9%99.html">P86 작성 규칙</a>의 같은 장 이름 · 같은 순서(1 개요 → 7 개발 진행·검수 → 문서 정보·변경 이력)를 씁니다. 첫 장은 언제나 지금 제안서와 시뮬 기준이고, 이전 기획은 「이 콘텐츠의 자료 › 히스토리 · 이전 기획」에 있습니다. 시뮬에 들어간 값은 확정이고, 모노 이식 결과는 책갈피 S 문서에만 두고 여기서는 링크만 겁니다.</p>
