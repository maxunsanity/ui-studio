# 089 · AI 컷씬 제작 — 기존 사례 조사

> 조사일: 2026-09-21 · 연구 초안 · 공식 제품 설명·연구 논문·개발자 저장소 기준. 설치 및 실제 제작 시험은 하지 않았다. 아래 ‘확인’은 문서 확인을 뜻한다.

## 결론

**이미 유사한 사례가 있다. 특히 Cutscene Agent는 ‘준비된 리소스 + 자연어 지시 → 수정 가능한 게임 엔진 컷씬’이라는 목표에 매우 가깝다.** 2D에는 Warp Studio의 AI 리깅·동작 생성·장면 구성 기능이 인접 사례다. 다만 이번 조사에서 두 방식을 동일한 콘티로 완성하고 게임 연동까지 검증한 통합 제품은 확인하지 못했다. [Cutscene Agent](https://kuaishou-gamemind.github.io/projects/cutscene_agent/) · [Warp Studio](https://crockiestar.itch.io/warp-studio)

단이의 판단: 새로운 영상 생성 모델을 만드는 것보다, **기존 리소스를 찾고 연출 데이터로 조립하며 결과를 검사하는 제작 도구**를 중심에 두는 방향을 먼저 검증할 가치가 있다.

## 조사 기준

우리 목표와 같은 점은 기존 리소스 활용·콘티 기반 연출·결과 수정 가능성이다. 다른 점은 도구마다 자동화 범위와 출력 형태가 다르다는 것이다. 기존 기획서의 모노카피바라 비교 규칙과 관련해, 해당 프로젝트의 컷씬 구현 자체는 이번 조사 대상이 아니다.

- 엔진형: 캐릭터·카메라·동작·시간 정보가 게임 엔진에서 편집 가능한가?
- 제작 보조형: 움직임·카메라·콘티 등 일부 작업을 돕는가?
- 영상형: 완성 영상이나 이미지가 주된 결과물인가?
- 2D라는 표현이 실제 2D 캐릭터·레이어인지, 단순히 화면 위의 작업 공간인지를 구분한다.
- 연구 공개·판매 중·베타를 구분한다. 공개 코드가 있다고 제작 안정성이 검증된 것으로 보지 않는다.

## 사례 비교

각 행의 이름은 원문으로 연결된다. 적합도는 사용자 목표에 대한 단이의 해석이다.

| 사례 | 성격 / 범위 | 확인한 핵심 | 우리 목표와의 거리 |
|---|---|---|---|
| [Cutscene Agent](https://github.com/KuaishouGameMind/cutscene_agent) | 공개 연구·코드 / 3D Unreal | 자연어로 편집 가능한 Level Sequence 구성 | 가장 가까운 구조 참고 |
| [FilmAgent](https://filmagent.github.io/) | 공개 연구 / 3D Unity | 미리 만든 공간에서 대본·배우 행동·카메라를 자동 계획 | 리소스 기반 자동 연출 참고 |
| [Cine-AI](https://arxiv.org/html/2208.05701v1) | 연구 / 3D Unity | 타임라인의 컷 지점과 감독 스타일을 이용한 카메라 자동화 | 연출 규칙과 편집 방식 참고 |

| [CiGYL](https://cigyl.com/) | 공개 베타 / 콘티·3D 사전 제작 | 콘티·캐릭터·장면·엔진 전달 | 콘티에서 공간으로 연결하는 구조 참고 |
| [Motorica](https://motorica.com/) | 제품 / 3D 움직임 | 모션·스타일 제어 및 제작 프로그램 연계 | 컷씬 전체가 아닌 동작 모듈 |
| [LTX Studio](https://ltx.io/blog/ltx-studio-tutorial) | 상용 / 이미지·영상 | 샷 생성·스토리보드 배열·영상 수정 | 움직이는 콘티와 영상 제작 참고 |

## 1. Cutscene Agent — 가장 가까운 사례

Kuaishou GameMind Lab이 공개한 연구다. 자연어 대본에서 캐릭터 애니메이션·카메라·대사·소리를 조합한 Unreal Level Sequence를 만든다. 이 결과는 Unreal의 컷씬 편집기에서 다시 수정할 수 있다. 시연은 MetaHuman을 사용했고 조명·렌더링은 아티스트가 작업했다고 명시한다. [프로젝트 및 시연](https://kuaishou-gamemind.github.io/projects/cutscene_agent/)

공개 저장소에는 Python 3.10+, Unreal Engine 5.6, CutsceneProvider 플러그인이 필요하다고 적혀 있다. 준비된 음성과 애니메이션으로 실행하는 데모도 제공한다. 음성 생성·얼굴 애니메이션·영상 이해 서비스는 연결 지점을 제공하며, 필요한 서비스를 별도로 붙이는 구조다. 저장소 코드는 MIT 라이선스로 표시되지만 사용 에셋과 외부 서비스 조건까지 같은 것은 아니다. [설치 조건과 공개 범위](https://github.com/KuaishouGameMind/cutscene_agent)

MCP는 여기서 AI가 엔진 기능을 호출하고 장면 상태를 읽는 연결 통로다. 핵심 흐름은 다음과 같다.

1. 사용할 수 있는 캐릭터와 동작을 조회한다.
2. 대본에 맞춰 배치·애니메이션·카메라·소리를 구성한다.
3. 현재 시퀀스 상태와 화면을 읽는다.
4. 잘못된 부분을 고치고 편집 가능한 시퀀스를 남긴다.

논문은 현재 범위를 대화 중심 장면으로 설명한다. 액션 안무·군중·역동적인 환경 상호작용은 후속 과제다. 오류 사례로 없는 리소스 이름 사용, 시간 불일치, 일부 구간의 카메라 누락 등을 보고한다. Unity·Blender 이식은 가능성/후속 방향으로 제시되며, 이미 지원된 것으로 판단하면 안 된다. [논문 §3·§4.5·§5](https://arxiv.org/html/2604.25318v1)

단이의 적용 판단: ‘지시 → 실행’뿐 아니라 **리소스 조회 → 실행 → 상태 및 화면 검사 → 수정**을 갖춰야 한다. 첫 실험은 대화 장면으로 제한하면 이 사례와 비교하기 쉽다.

## 2. FilmAgent — 준비된 Unity 공간에서 자동 연출

연구팀은 감독·작가·배우·촬영 역할의 AI가 이야기를 발전시키고 대본과 촬영 계획을 수정하는 구조를 제시한다. 사전에 만든 Unity 3D 공간을 사용한다. [연구팀 프로젝트](https://filmagent.github.io/)

공개 실행 안내는 `script.json`, 배우 프로필, 음성 파일을 만든 뒤 제공된 Unity 프로젝트에서 대본을 실행하는 순서다. 배우의 위치·행동·대사·카메라 샷이 정리된다. 준비된 공간과 실행 코드에 맞춰 연결해야 하므로 임의의 프로젝트에 바로 꽂는 범용 컷씬 편집기로 확인된 것은 아니다. [공개 코드와 실행 안내](https://github.com/HSwotch/FilmAgent)

단이의 적용 판단: 콘티와 엔진 사이에 구조화된 대본을 두는 방식이 참고된다. 다만 우리 도구에서 필요한 컷별 재생성·수동 수정 보존·게임 복귀는 별도 검증해야 한다.

## 3. Cine-AI — 연출 규칙으로 카메라를 자동 구성

2022년 논문이다. Unity 타임라인에서 사용자가 컷 지점, 대상, 극적 강도와 속도감을 지정하면 감독 스타일 데이터와 촬영 규칙으로 카메라 기법을 선택한다. 스토리보드에서 컷별 구도와 설정을 검토·수정하며, 장면의 충돌 정보도 사용한다. 자연어 대본 전체를 해석하는 최신 LLM 도구와는 작동 방식이 다르다. [논문과 편집 인터페이스](https://arxiv.org/html/2208.05701v1)

단이의 적용 판단: 콘티 입력에 ‘대상·감정 강도·속도감·구도’를 두고, 구체 좌표는 검증 가능한 연출 규칙으로 계산하는 방식이 유용하다. AI에게 모든 카메라 좌표를 직접 추측하게 할 필요는 없다.

## 4. Autodesk Flow Studio — 3D 장면을 먼저 연출하고 AI로 정제

2026년 8월 4일 공식 발표된 3D Editor + Canvas는 캐릭터·환경·애니메이션·카메라를 편집 가능한 3D 공간에서 구성하고 타임라인으로 조정한 뒤 AI 이미지·영상 작업으로 이어진다. 자유롭게 움직이는 카메라와 캐릭터를 따라가는 카메라를 설명한다. [공식 발표](https://blogs.autodesk.com/media-and-entertainment/2026/08/04/introducing-3d-editor-canvas-in-autodesk-flow-studio/)

공식 페이지의 ‘2D 작업 공간’은 곧바로 2D 게임용 캐릭터·이벤트 실행 지원을 의미하지 않는다. 이번에 확인한 자료만으로 콘티 한 번에 게임용 전체 시퀀스를 자동 조립하거나 게임 상태까지 연결한다고 판단할 수 없다.

단이의 적용 판단: 배치·카메라·타이밍을 유지한 채 시각 결과를 개선하는 작업 흐름이 참고된다. 우리 게임 리소스 가져오기와 최종 엔진 출력 범위는 직접 시험할 항목이다.

## 5. Warp Studio — 2D 쪽 인접 사례

개발자의 판매 페이지에 따르면 Warp Puppet은 캐릭터 그림을 움직이는 부품으로 나누고 AI로 리깅하며, 문장으로 동작을 생성·반복 수정한다. Warp Director는 외부 그림·영상·소리를 레이어와 타임라인으로 구성하고 AI가 편집 가능한 장면 초안을 만들 수 있다. [개발자 설명](https://crockiestar.itch.io/warp-studio)

주의할 구분: Puppet/Animate의 `.warpstudio` 애니메이션 출력과 Director의 MP4 장면 출력은 서로 다르다. 전체 컷씬이 게임용 데이터로 전달된다고 확인한 것은 아니다. 문서상 Windows 전용이며 AI 기능은 사용자의 Gemini 키를 이용한다. 실제 게임 엔진 가져오기와 복잡한 콘티 정확도는 미시험이다. [출력·실행 조건](https://crockiestar.itch.io/warp-studio)

단이의 적용 판단: 2D 준비 그림을 편집 가능한 동작으로 바꾸는 접근을 먼저 살펴볼 가치가 있다. 개발자 설명을 실제 제작 품질로 단정하지 않는다.

## 6. CiGYL — 콘티와 3D 사전 제작 연결

공개 베타로 소개된다. 캐릭터·장소·스토리보드를 관리하고 콘티 시트를 샷으로 나누며 2D 타임라인에서 길이를 정하는 기능을 설명한다. 자체 모델 업로드도 안내한다. [공식 기능 소개](https://cigyl.com/)

Blender/Unreal 연결은 개발 중 표시가 있으며 현재 브라우저에서 엔진으로 보내는 단방향이라는 설명이다. 양방향 동기화는 계획 단계다. 따라서 완성된 왕복 편집 파이프라인으로 평가하지 않는다.

단이의 적용 판단: 리소스·컷·카메라를 한 자료 구조에 묶는 방향이 참고된다. 실시간 게임 컷씬까지 전달되는 정확한 범위는 미확인이다.

## 7. Motorica — 컷씬 안에 넣을 움직임 제작

공식 제품은 모션캡처 기반 동작 합성, 이동과 스타일 제어, Unreal·Unity·Maya·Blender 등과의 연계를 설명한다. 컷씬의 전체 대본·편집·대사·카메라 조립을 수행하는 사례로 분류하지 않는다. [공식 제품](https://motorica.com/)

단이의 적용 판단: 필요한 걷기·이동 동작이 부족할 때 연결할 수 있는 별도 모듈 후보로 기록한다.

## 8. LTX Studio — 콘티와 영상 제작 참고

공식 안내는 이미지에서 영상 생성, 움직임 프롬프트, 스토리보드에서 클립 배열·전환·시간·음향 편집을 설명한다. 생성 원본을 유지하며 샷을 교체하거나 순서를 바꾸는 방식이다. [공식 튜토리얼](https://ltx.io/blog/ltx-studio-tutorial)

단이의 적용 판단: 움직이는 콘티를 빠르게 확인하는 데 참고할 수 있다. 이번 자료에서는 게임 엔진의 캐릭터·카메라·이벤트 트랙으로 출력하는 기능을 확인하지 못했다. 영상 속 카메라 이동과 게임 엔진의 편집 가능한 카메라 경로를 구분해야 한다.

## 우리 설계에 반영할 연구 항목

아래는 조사에서 얻은 제안이며 확정 사양이 아니다.

| 항목 | 이유 | 확인할 실험 |
|---|---|---|
| 리소스 검색과 능력 목록 | 없는 행동·파일을 지시하는 오류를 줄임 | 걷기 없는 캐릭터에 걷기를 요청했을 때의 처리 |
| 공통 연출 데이터와 2D/3D 실행 분리 | 같은 의도를 각 표현 방식으로 옮김 | 같은 3컷 콘티를 두 방식으로 제작 |
| 카메라·이동 템플릿 | 공간과 구도 오류를 줄일 기준 확보 | 얼굴 클로즈업·따라가기·두 사람 대화 |
| 데이터 검사와 화면 검사 병행 | 값이 유효해도 대상이 가려질 수 있음 | 가림·카메라 빈 구간·타이밍 오류 탐지 |
| 컷별 수정과 변경 보존 | 반복 작업에서 사람의 수정이 사라지지 않아야 함 | 한 컷의 표정만 바꿔 나머지 유지 |
| 결과물 종류 명시 | 영상과 엔진 데이터는 후속 작업이 다름 | 게임 재생·편집·영상 출력 각각 확인 |

## 후속 조사 우선순위

1. Cutscene Agent: 공개 데모의 에셋 등록·카메라 템플릿·시퀀스 생성 구조를 분석한다. 우리 엔진을 Unreal로 확정한다는 뜻은 아니다.
2. Warp Studio: 2D 레이어·동작·장면 편집 데이터가 어떻게 보존되는지, 게임 가져오기가 어디까지 가능한지 확인한다.
3. FilmAgent/Cine-AI: 구조화 대본과 규칙 기반 카메라 설계를 비교한다.
