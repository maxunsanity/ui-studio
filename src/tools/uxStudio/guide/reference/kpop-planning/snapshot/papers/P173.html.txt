<p><b>이 문서는</b> 유저가 이어서 플레이할 때 필요한 팀·성장·재화·시설 기록이 어디에 남고, 같은 진행인지 어떻게 확인하는지 설명합니다.</p>

<p><b>보는 법</b> <a href="#part-3">3장</a>의 진입 순서와 <a href="#part-4">4장</a>의 저장 묶음·복원·거래를 읽고, <a href="#part-6">6장</a>에서 정적 정의 자료와 <a href="#part-7">7장</a>에서 미검수 범위를 확인합니다. 서버 저장 목표는 <a href="유저저장_핵심제안서.html">P222</a>, 승인 전 결정안은 <a href="../../기획서/산출_기획서_유저저장_보완판_v1_클로드.html">P203</a>에서 구분해 읽습니다.</p>

<p><b>지금 상태</b> 분리된 브라우저 저장·인계·스냅샷·이어하기·건설 거래는 부분 구현입니다. 서버 정본·계정/시즌 통합 저장은 기획 중·작업전이며 실제 저장·복원·동시 저장의 전수 검수는 하지 않았습니다. 확인 범위는 <a href="#part-7">7장</a>에 적었습니다.</p>

<section class="part" id="part-1"><h2>1. 개요</h2>

<p>출처: (합침) <a href="/docs/planning/proposal-concept/audition.html" data-paper-path="docs/planning/proposal-concept/audition.html">오디션 제안서</a>의 팀 이어가기 방향과 현재 보드·시뮬레이터 저장 코드.</p>

<p>현재 확인한 프로토타입은 브라우저 저장을 사용합니다. 보드 경제, 성장 스냅샷과 이어하기, 오디션 인계, 팬 허브는 각각 다른 저장 묶음입니다. 화면은 현재 진행의 식별자와 기록을 확인한 후 필요한 묶음을 읽습니다. 계정 기반 서버 저장과 여러 묶음의 단일 통합은 <b>작업전</b>입니다.</p>

</section><section class="part" id="part-3"><h2>3. 구동 방법·시뮬레이션</h2>

<p>화면 흐름: 오디션에서 합류 → 메인 진입 → 같은 진행의 성장·건설·팬 정보를 읽음 → 다시 열 때 저장 대조. 별도의 저장 정보 시뮬레이터는 없습니다.</p>

<h3 id="오디션과-팀-인계-화면-열기"><a href="/docs/planning/game-simulator.html?module=simulator_module_audition" data-paper-path="docs/planning/game-simulator.html">▶ 오디션과 팀 인계 화면 열기</a></h3>

<h3 id="같은-진행의-건설-화면-열기"><a href="/docs/planning/game-simulator.html?module=simulator_module_building" data-paper-path="docs/planning/game-simulator.html">▶ 같은 진행의 건설 화면 열기</a></h3>

<ol>
<li>오디션의 합류 결과를 메인으로 넘기면 멤버와 해당 진행의 식별자를 확인합니다.</li>
<li>성장 화면은 같은 진행의 스냅샷과 이어하기 기록을 대조합니다. 건설은 연결된 지갑과 시설 단계를 읽고 견적을 표시합니다.</li>
<li>다른 메뉴로 이동하거나 다시 열 때 기존 진행을 읽습니다. 저장이 없거나 조건이 맞지 않으면 연결 대기 또는 오류로 구분합니다.</li>
<li>독립 시험 페이지는 저장 범위를 분리합니다. 시험 화면의 결과를 실제 진행의 보상으로 취급하지 않습니다. 이번 문서 작업에서 실행·화면 캡처는 하지 않았습니다.</li>
</ol>
