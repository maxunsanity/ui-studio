# S00 · 기획서 툴 정리 기획

**이 문서는** 기획서 툴(7007 `/docs/planning/planning-docs-tool.html`)을 케이팝 몬스터즈 전용이 아니라 **다른 게임에도 쓸 수 있는 「게임 기획·개발 툴」**로 정리하기 위한 기획입니다. 메뉴 구조, 기능 목록, 데이터 구조, 범용화 방법, 플로우차트 내비 설계를 담습니다.

**보는 법**
- 0~1장: 툴의 원칙과 메뉴 전체 그림
- 2~4장: 기능 목록·데이터 구조·하위 툴([시뮬레이터](../../../game-simulator.html) 등) 연결
- 5~6장: AI 협업 방식, 케이팝 전용으로 박힌 부분을 떼는 방법
- 7~9장: 10/22에 찾은 정리할 것, 추가 기능 후보, 현중 결정 필요
- 10장: 왼쪽 플로우차트 내비 설계
- 시뮬레이터 없음 (툴 자체 기획). 툴 열기: [기획서 툴](/docs/planning/planning-docs-tool.html)

**지금 상태 (10/30 코드 기준)**
- **개발됨**: 2장 기능 목록의 현행 기능, 상단 face 8개(제안서 카드·리스트·[핵심제안](../개발진행기획_v01/목차.html) 개발·책갈피·지도·공백·게임·[발란스 툴](S02_발란스툴.md)), 왼쪽 플로우차트 내비(`src/tools/planningDocs/flow.ts`·`flow-panel.ts`)와 그 표 `data/simulator/flow_node.csv`(29행)·`flow_edge.csv`(28행), 출발 경로 저장(`flow_trail`)·시뮬레이터 이동 알림(`flowVisit`), 문서별 「로그」 버튼(10/30).
- **바뀐 점**: 시뮬레이터 모듈은 10/22의 17개에서 지금 **22개**입니다(`data/simulator/simulator_module.csv`). 메뉴(`menu.json`)는 기본 메뉴 10개 · 성장 도구 6개 · 보조 묶음으로 나뉘고, 능력 허브·관계 허브·여정도 메뉴에 들어 있습니다(10-2 1번 해결).
- **현재 개발되지 않음, 진행 중**: 흐름도 표에 새 모듈 5개([뉴런](../개발진행기획_v01/콘텐츠별_v03/뉴런_기획서.html)·상점·미션·찬스 이벤트·[팬 증가](S05_팬덤.md))가 아직 없음, 프로젝트 설정 파일로 범용화(6장), 상단 face 버튼 숨김(10-6 2·3단계), 8장 추가 기능 후보.
- 7장 숫자와 3장 개수는 10/22 점검 값이라 지금과 다를 수 있습니다.

## 0. 목적 · 원칙
툴 = 틀, 게임 내용 = 데이터. 케이팝 몬스터즈는 이 틀에 들어간 첫 데이터 묶음이다. 다른 게임은 데이터 폴더만 바꿔 같은 틀을 쓴다.

지금 쓰는 규칙을 툴 규칙으로 옮김:
| 툴 규칙 | 지금 근거 |
|---|---|
| R1 7007 원본이 기준. 생각대로 새 페이지 만들지 않음 | [헌법](../전체기획서/00_헌법_기획서기조.md) 기조 띠 `planning-docs-tool.html` |
| R2 목록에서 열어 확인해야 완료(카드 주소 직접 열기는 미완료) + 캡처 | 작업방식_v2 「확인」 |
| R3 문서 1개 = 카탈로그 1줄(카드 중복 금지) | `planning_doc_catalog.csv` path 유일 |
| R4 숫자는 「발란스 대기」(value_status: temp/fixed) | 카탈로그 value_status 칸 |
| R5 새 안은 「제안」 | 시스템기획 S 문서 머리, 스키마 registry_note |
| R6 고치기 전 `파일.HHMMSS전_작성자` 백업 | 작업방식_v2 「백업과 표」 |
| R7 생성 파일은 손으로 안 고침, 원본 표 → 생성기 | `schema-generate.mjs` |
| R8 이전 리소스 백업 폴더는 서빙·감시 안 함 | `vite.config.ts` |

## 4. 하위 툴 연결 방식
- 7007 개발 face → 시뮬레이터 도크(`game-simulator.html?module=&testPage=&hubSource=main`, main.ts).
- host.mjs가 simulator_module(17)을 menu.json 묶음(primary/auxiliary)으로 띄움. 상세 보기 요청은 view·member·axis·returnModuleId만 통과(host.mjs). 하위 화면은 끝나면 `ctx.navigate(returnModuleId)`로 돌아감(bad_energy_views.mjs).
- 허브(능력·관계)는 `hubSource=main`일 때만 메인 데이터를 읽음(main.ts isMainGrowthInspector).
- 오디션 → 메인 허브 → 메뉴 데이터 흐름은 [S16](S16_오디션허브메뉴_데이터흐름.md)에서 다룹니다.

### 10-2c 범용화(다른 게임)

### 10-3 표 설계 제안 (스키마 변경은 schema_table/schema_column + 생성기로만)
