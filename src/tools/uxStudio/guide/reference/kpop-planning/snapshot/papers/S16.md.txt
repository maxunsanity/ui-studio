# S16 · 오디션 → 메인 허브 → 메뉴 데이터 흐름

**이 문서는** [오디션](../개발진행기획_v01/콘텐츠별_v03/오디션_기획서.html)에서 뽑은 멤버가 **[카드북](../개발진행기획_v01/콘텐츠별_v03/카드_기획서.html)·클릭 성장·능력/관계 허브·[아이돌 성장](../개발진행기획_v01/콘텐츠별_v03/아이돌능력_기획서.html)·[여정](../개발진행기획_v01/콘텐츠별_v03/라포AI탐험_기획서.html)·[쟁탈전](../개발진행기획_v01/콘텐츠별_v03/캐스팅권대전_기획서.html)에서 「같은 사람」으로 보이게 하는 데이터 길**을 설명하는 시스템 기획서예요. 메뉴 사이를 오갈 때 무엇을 넘기고 어디에 저장하는지 정해요. 아래의 단일 허브·저장 시점·쓰기 권한은 기획 목표이며, 공개 코드의 부분 연결과 실제 최종 reader·저장 검수는 나눠 봐요.

**보는 법** 1장(한눈에 그림) → 2장(이동 규칙) → 3장(저장과 쓰기 권한) 순서로 보고, 4장에서 아직 안 맞는 곳을 확인하세요. 같이 여는 시뮬레이터: [오디션](/docs/planning/game-simulator.html?module=simulator_module_audition) → [로비 허브](/docs/planning/game-simulator.html?module=simulator_module_dice) → [카드북](/docs/planning/game-simulator.html?module=simulator_module_cardbook) · [능력 허브](/docs/planning/game-simulator.html?module=simulator_module_growth_ability). 오디션 내용은 [P100](../개발진행기획_v01/콘텐츠별_v03/오디션_기획서.md), 멤버 생성은 [P170](../개발진행기획_v01/콘텐츠별_v03/랜덤멤버생성_기획서.md)을 보세요.

**지금 상태** **공개 코드로 확인한 부분**: 생성 후보 adapter, 생성 조건에 맞는 멤버 payload의 clone·이름·배경·팀 이름 인계, 카드북의 성장 snapshot/testSession·멤버 읽기와 조건부 공통 상세창 open 코드가 있어요. URL·보기 상태 전달과 저장 payload는 다른 층이며, payload가 있다고 저장에 성공한 것은 아니에요. **기획 목표·현재 미검수**: 단일 허브를 유일한 원본으로 쓰기, 필드별 쓰기 권한의 전체 시행, 보호된 최종 reader·실제 저장 성공, 여정 라포·클릭 성장·전체 상세 허용목록·아이템 보정의 현재 전체 연결이에요.

## 1. 한눈에

**기획 목표: 멤버는 허브에 한 벌, 메뉴는 번호만 들고 오가요.**

```mermaid
flowchart LR
  AU[오디션 · 아이돌 캐스팅] -->|합류 확정 · 예명| HUB[(메인 허브<br>멤버 한 벌)]
  HUB --> CB[카드북]
  HUB --> CG[클릭 성장]
  HUB --> AB[능력 허브 · 관계 허브]
  HUB --> SIM[아이돌 성장 · 팀 탭]
  HUB --> JR[여정 · 출동]
  HUB --> CA[쟁탈전]
  CG & SIM & JR & CA -.정해진 칸만 되돌려 씀.-> HUB
```

> 화면 그림 자리: 오디션 → 메인 허브 → 각 메뉴로 가는 실제 화면 이동 그림이 들어가요(UI 기획 담당). 현재 개발되지 않음, 진행 중.

- 공개 코드에는 오디션 인계·시험 세션·성장 snapshot/checkpoint·카드북 owned처럼 여러 저장층이 있어요. 클릭 성장·라포·쟁탈전 등 모든 소비 경로까지 한 원본으로 통일됐는지는 이번 범위에서 확인하지 않았어요.
- 목표는 **메인 허브의 멤버 정보 하나만 원본**으로 두는 거예요.

## 2. 메뉴 이동 규칙

| 이동 | 넘기는 것 | 지금 상태 |
|---|---|---|
| 오디션 → 메인 | 결과 번호는 URL 탐색 규약 · 멤버 payload는 별도 저장 인계 | payload writer 코드 있음 · 현재 URL producer/최종 reader·실저장 미검수 |
| 메뉴 → 성장 상세 | 보기 종류 · 멤버 번호 · 능력 축 · 돌아갈 메뉴(기존 모듈 왕복 규약) | 별도로 공통 상세창 open 코드 있음 · 현재 UI/reader 미검수 |
| 상세 → 돌아가기 | 돌아갈 메뉴가 허용 목록에 있으면 그곳, 없으면 메인 | 목적별 공개 목록 있음 · 최종 상세 허용목록·실제 왕복 미검수 |
| [보드](../개발진행기획_v01/콘텐츠별_v03/P74_설명.html) 칸 → 콘텐츠 | 콘텐츠 요청 · 끝나면 메인으로 | 공개 wrapper 접점 있음 · 전체 콘텐츠 실구동은 이번 미검수 |
| 아이돌 성장 → 쟁탈전 → 아이돌 성장 | 도착 정보 · 끝나면 돈·팬 결과 | 공개 요청/응답 wrapper 코드 있음 · 최종 정산 writer·실저장은 이번 미검수 |
| 카드북 · 여정 → 성장 상세 | 기존 모듈 왕복 규약 · 카드북은 별도 공통 정보창 요청 | 카드북 조건부 open 코드 있음 · 여정 상세/실제 왕복 미검수 |

- **탐색 규약(기획 목표)**: 이동할 때는 **번호와 보기 상태만** 넘겨요. 이름·능력·[이야기](../서사_조합형/서사100선_전문.md) 같은 멤버 데이터는 넘기지 않고, 받은 메뉴가 허브에서 다시 읽어요. 넘긴 값과 허브 값이 갈라지면 어느 쪽이 맞는지 알 수 없기 때문이에요. URL의 번호·보기 상태와 달리, 오디션의 저장 인계 payload에는 멤버 데이터도 담겨요.
- **아이템 연결 목표**: 아이템 효과도 들고 다니지 않아요. 각 메뉴가 허브에서 장착·버프를 다시 읽어요. 현재 장착·버프 reader의 전체 연결은 이번 미검수예요.

## 3. 저장과 쓰기 권한

현재 로컬 저장의 부분 구현과 서버 정본 목표는 [P173 유저 저장 정보](../개발진행기획_v01/콘텐츠별_v03/유저저장정보_기획서.md)와 함께 읽어요. 이 장의 시점·권한표는 구현 완료표가 아니에요.


### 3-1. 언제 저장하나

아래는 저장 시점의 기획 목표예요. 공개 writer의 호출·검증/실패 반환과 실제 저장 성공·최종 화면 반영은 별도로 확인해야 해요.

| 때 | 저장하는 것 |
|---|---|
| 합류 확정 | 실명, 생성 결과(능력·성격·꼬리표·배경·이야기·라포 처음 값) |
| 예명 확정 | 예명 |
| 두 번째 멤버 합류 | 팀 이름 |
| 성장이 일어난 순간 | 성장 기록 한 줄 + 성장 상태 갱신 |
| 콘텐츠 결과 받기(여정·쟁탈전) | 돈·팬·라포 변화를 한 번 |
| 메뉴를 떠날 때 | 따로 저장하지 않음 |

### 3-2. 누가 어떤 칸을 고치나

아래는 허브의 필드별 쓰기 권한 목표예요. 일부 인계·snapshot/checkpoint·카드 commit 접점은 있지만, 모든 메뉴에서 이 권한이 강제되는지와 최종 caller는 미검수예요.

| 칸 | 오디션 | 예명·팀명 창 | 카드북 | 클릭 성장 | 능력·관계 허브 | 아이돌 성장 | 여정 | 쟁탈전 |
|---|---|---|---|---|---|---|---|---|
| 실명 · 생성 결과 | 씀(한 번) | 읽기 | 읽기 | 읽기 | 읽기 | 읽기 | 읽기 | 읽기 |
| 예명 · 팀 이름 | — | 씀 | 읽기 | 읽기 | 읽기 | 읽기 | 읽기 | 읽기 |
| 능력 · 성장 기록 | — | — | 씀(카드 효과) | 씀 | 읽기 | 씀 | — | — |
| 카드 보유 | 첫 카드 | — | 씀 | — | 읽기 | 읽기 | 읽기 | 씀(보상) |
| 라포 | 처음 값 | — | — | — | 읽기 | 씀 | 씀 | — |
| 돈 · 팬 · 주사위 | — | — | — | — | — | 씀 | 씀(받기) | 결과를 아이돌 성장이 씀 |
| 이야기 열린 단계 | 씀 | — | 읽기 | — | 읽기 | 씀 | — | — |

양은 모두 값 미정이에요. 「씀」은 허브의 그 칸만 고친다는 뜻이에요.

## 4. 아직 맞지 않는 곳 (현재 개발되지 않음, 진행 중)

제목의 미개발 분류는 10/30 정리 당시 진단을 보존한 것이며, 현재 모든 항목에 코드가 없다는 뜻은 아니에요. 아래 1·4·7·8은 현재 공개 코드의 부분 경로를 구분했고, 2·3·5와 전체 상세 허용목록은 현재 미검수로 남겨요.


| # | 내용 |
|---|---|
| 1 | 10/30 진단의 「오디션 넘김에 실명·예명·이야기·그림 번호 칸이 없어요」와 달리, 현재는 생성 조건이 맞으면 generated clone·name_ko·background·그림 정보 등이 payload에 실려요. 별도 이름 필드의 필수성·최종 reader 반영은 미확인이에요 |
| 2 | 시험 세션과 아이돌 성장이 배경을 예전 고정 표에서 붙여요 |
| 3 | 성장 기록이 여러 곳에 따로 있어요 |
| 4 | 10/30 진단의 「카드북이 탭을 닫으면 사라지는 저장소를 쓰고, 멤버를 몰라요」에서 owned의 sessionStorage 경로는 남아 있어요. 현재 snapshot/testSession·멤버 reader도 있으며, 상위 공급·장기 저장 성공은 미확인이에요 |
| 5 | 여정 라포가 멤버·판 구분 없이 하나로 저장돼요 |
| 6 | 돌아갈 메뉴 허용 목록이 여러 곳에 따로 있고, 카드북·여정이 빠져 있어요 |
| 7 | 10/30 진단의 「카드북에서 성장 상세로 가는 길이 없어요」와 달리, 현재는 공통 characterInfo.open으로 멤버/팀·축을 여는 조건부 코드가 있어요. 실제 정보창·최종 reader·모듈 왕복은 미검수예요 |
| 8 | 10/30 진단의 「팀 이름이 아이돌 성장 화면 안에만 있고 허브 칸이 아니에요」와 달리, 현재 인계 payload에도 team_name·team_formed_at가 있어요. 단일 허브의 팀명 정본·보호된 최종 소비는 미확인이에요 |

기존 확인: 새 생성 경로는 고정 16명 대신 생성 후보를 쓰고, 생성기 기록이 없는 옛 저장은 legacy 경로가 있어요. 예명은 비운 채 시작하고 플레이어가 짓는다는 기존 기획·확인은 P170과 함께 보며, 이번 실제 입력 화면은 미검수예요.

## 5. 아이템 · 스킬 연결 자리

아래는 효과를 연결할 기획 자리예요. 현재 전체 reader·계산·장착/버프 반영이나 보정표 공급 완료를 뜻하지 않아요.


| 자리 | 바꾸는 대상 | 계속/즉시 |
|---|---|---|
| 합류 확정 직후 | 라포 처음 값 · 성격 꼬리표 | 즉시 |
| 예명 확정 | 칭호·꼬리표 지급 | 즉시 |
| 클릭 성장 · 아이돌 성장 정산 | 받는 능력 양 | 계속(장착·버프) · 즉시(스킬) |
| 카드북 카드 | 카드 효과 → 능력 | 계속(보유) · 즉시(사용) |
| 여정 결과 | 라포 · 팬 · 기분 | 즉시 |
| 쟁탈전 판정 | 판정 · 기분 | 스킬 · 버프 |

기존 기획 목표는 효과 표를 새로 만들지 않고 성장 관계([P169](../개발진행기획_v01/콘텐츠별_v03/성장관계_기획서.html))의 성장 보정 표 하나를 쓰는 것이에요. 양은 값 미정이며, P169 원표·코드와 현재 전체 reader는 이번 범위에서 확인하지 않았어요.
