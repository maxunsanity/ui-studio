<p><b>이 문서는</b> 상대의 공연장에 게릴라 무대 트럭이 나타나고, 관객석을 하나씩 열어 같은 종류의 팬을 먼저 모으는 공연을 설명합니다. 돈과 팬, 카드 또는 기분 간식이 어떻게 연결될지를 살펴보는 기획입니다.</p>
<p><b>보는 법</b> 1장 개요 → 3장 구동 방법·시뮬레이션 → 4장 상세 기획 → 6장 표·7장 검수 순서로 읽습니다. 기존 제안 링크와 출연권 대전 시뮬레이터는 별도 참고로 구분합니다.</p>
<p><b>지금 상태</b> 현재 개발되지 않음, 진행 중(이 문서의 게릴라 공연 진입·정산 연결 기준). 실제 게릴라 공연 구동·정산·저장은 미검수이며, 수치·확률·보호선은 발란스 대기입니다.</p>

<p><a href="/docs/planning/proposal-fansim-casting.html" data-paper-path="docs/planning/proposal-fansim-casting.html">눌러서 게릴라 공연 제안 확인</a></p>

<section class="part" id="part-1"><h2>1. 개요</h2>

<p>트럭이 멈추고 해치가 열리면 팬들이 관객석으로 몰려옵니다. 플레이어는 자리를 열며 어떤 팬이 나왔는지 확인하고, 같은 종류가 세 명 모이면 공연 결과와 보상을 봅니다. 두 명이 모였을 때 다음 자리가 반짝이는 연출과 숨은 응원봉 배수 자리는 기대감을 높이는 장치입니다.</p>

<p>이 문서의 트럭·좌석·서버 선결정·팬 이동은 <b>구현을 위한 기획</b>입니다. 현재 쟁탈 시뮬레이터는 출연권 대전으로 진행하며 게릴라 공연의 실제 진입·정산은 연결되지 않았습니다. 팬 이동과 돈 지급도 게임에서 이미 일어나는 일로 읽지 않습니다.</p>

</section><section class="part" id="part-3"><h2>3. 구동 방법·시뮬레이션</h2>

<p>화면 흐름 계획: 쟁탈 도착 → 공연 진입 → 트럭·관객석 → 결과·정산 → 보드 복귀 · 현재 게릴라 공연 실행 모듈 없음 · 화면 캡처 미완 · 이식 비교 해당 없음.</p>

<p>이 기획의 실제 실행 버튼은 아직 없습니다. <a href="/docs/planning/game-simulator.html?module=simulator_module_stage_battle" data-paper-path="docs/planning/game-simulator.html">쟁탈전 시뮬레이터</a>는 현재 출연권 대전을 살펴보는 도구이며 게릴라 공연이 구현됐다는 증거가 아닙니다. 서버 결과 생성·관객석 선택·팬 이동을 연결한 뒤 실제 한 판과 복귀를 검수합니다.</p>

<h3 id="트럭과-관객석">트럭과 관객석</h3>

<ol>
<li>무대 트럭이 도착하고 짐칸 해치가 열리면 상대 팬들이 앞쪽 좌석에 모입니다.</li>
<li>플레이어가 닫힌 좌석을 누를 때마다 조명이 해당 팬을 공개합니다. 한 번 연 자리는 다시 열지 않습니다.</li>
<li>같은 종류가 두 명이면 일부 좌석에 반짝임을 보여 줍니다. 이는 다음 선택의 긴장감을 만드는 연출입니다.</li>
<li>같은 종류 세 명이 먼저 모이면 해당 종류와 등급으로 판을 마치고, 모인 팬들이 우리 팀을 응원하며 무대로 올라옵니다.</li>
<li>보상과 팬 이동 결과를 확인하고 트럭이 떠난 뒤 보드로 돌아갑니다.</li>
</ol>

<p>좌석 수, 팬 종류의 이름·모양, 3명이 모이지 않는 경우와 연출 시간은 결정 대기입니다. 서버가 등급·종류·배치·공개 순서를 저장한다는 설계는 작업전이며, 좌석 선택의 위치와 공개 순서가 어떻게 결합되는지는 개발 전에 구체화해야 합니다.</p>

<h3 id="숨은-응원봉과-돈-계산">숨은 응원봉과 돈 계산</h3>

<p>일부 좌석에는 팬 대신 숨은 응원봉을 놓는 안입니다. 응원봉을 열면 주사위 배수와 함께 돈 보상에 적용하며 한 판의 합계 상한을 둡니다. 배수 크기·상한·출현 확률과 선택 횟수를 쓰는지는 발란스 대기입니다. 응원봉과 조명은 다른 요소입니다. 조명은 팬을 공개하는 연출이고 응원봉은 보상에 영향을 주는 별도 자리입니다.</p>

<p>공연을 연 사람의 보상과 상대가 잃는 돈은 각각 계산합니다. 상대가 가진 돈을 기준으로 삼는 방향은 있으나, 두 값의 차이와 보호선·하루 한도·새 돈 발생 여부는 정해야 합니다. 상대 잔액이 없을 때 임의 금액을 만들지 않고 그 경계의 처리 방식을 결정해야 합니다.</p>

<h3 id="팬-이동과-상대-알림">팬 이동과 상대 알림</h3>

<p>공연으로 데려오는 팬은 상대 팬이며, 기획은 내 팬 수 증가와 상대 계정의 팬 수 감소를 같은 이동으로 다룹니다. 관객석의 <b>세 명</b>은 결과를 보여 주는 상징이며 실제 이동 인원을 세 명으로 확정하지 않습니다. 실제 이동량은 등급·종류에 따라 발란스 대기입니다. 팬 수에 주사위 배수를 적용할지, 어떤 팬층에서 이동할지, 최소 보호선과 하루 한도는 결정 대기입니다.</p>

<p>상대가 다음에 접속하면 공연을 당한 내용을 확인하도록 계획합니다. 여러 판을 묶는 방법, 접속 중 상대 처리, 봇의 팬 보관과 기존 알림과의 통합은 작업전입니다. 돈과 팬을 각각 따로 중복 반영하지 않도록 저장·복구 경계를 설계해야 합니다.</p>
