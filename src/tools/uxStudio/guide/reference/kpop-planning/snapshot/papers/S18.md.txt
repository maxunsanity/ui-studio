## 0. 생성 원칙

- 성격 유형의 네 자리를 먼저 정한 뒤, 해당 유형 범위 안에서 축 속값을 뽑습니다.
- 월드컵에서 고른 성향과 무작위를 함께 쓰며, 고향은 성격 추첨에 넣지 않습니다.
- 현재 A안 구조는 움직임·말투·표정·태도를 유형 축으로, overall을 유형 밖의 겉 성향으로 둡니다. 새 축 체계를 이번 정비에서 결정하지 않습니다.
- 같은 유형 안에서도 속값은 달라질 수 있습니다. 유형 이름과 내부 숫자의 노출은 구분합니다.

## 1. 현재 구조

| 항목 | 현재 표·소스에서 확인한 내용 |
|---|---|
| 유형 | `personality_type`의 유형 행에 네 자리 조합 `type_code`가 있습니다. 기존 묶음·유형 이름도 함께 남아 있습니다 |
| 축 | `personality_slider`의 움직임·말투·표정·태도는 `type_axis`, overall은 `surface`입니다 |
| 범위 | `personality_slider`와 `personality_slider_map`에 수치가 채워져 있습니다. 표에 임시 상태가 붙은 값은 확정값으로 보지 않습니다 |
| 현재 생성 경로 | `casting.mjs`의 `generateMembers` → `idol-generator.mjs`의 `createIdolGenerator`를 사용합니다. 유형 글자 → type_code 조회 → 속값 순서입니다 |
| 월드컵 | 고른 후보 유형 코드의 글자 비율과 라운드 무게를 읽어 유형 글자 확률을 기울입니다. 현재 생성기에서 overall은 유형 밖 균등 추첨입니다 |
| 남아 있는 다른 계산 | `worldcup-carry.mjs`에는 속값을 섞고 유형을 찾는 독립 계산이 남아 있습니다. 현재 `generateMembers`는 그 결과로 유형을 다시 덮어쓰지 않습니다 |
| 기록 | `candidate_personality`·`candidate_personality_slider`·`candidate_trait`는 현재 머리줄만 있습니다. 메모리 생성과 실제 영속 저장은 구분합니다 |

## 2. 생성 순서

```mermaid
flowchart TD
  W[월드컵 선택 유형과 라운드 무게] --> P[유형 축별 글자 확률]
  R[무작위] --> P
  P --> C[type_code로 성격 유형 선택]
  C --> V[그 유형 범위 안에서 4축 속값]
  R --> O[유형 밖 overall 겉 성향]
  V --> M[멤버 성격 데이터]
  O --> M
```

1. `worldcup_carry_rule`의 유형 축 반영 몫·무작위 몫과 라운드 무게를 읽습니다. 값이 없을 때의 임시 대체는 생성기 설정에 출처를 남깁니다.
2. 유형 축마다 글자를 뽑고 `type_code`로 유형 행을 찾습니다. 없는 코드라면 진단을 남기므로 항상 유형이 있다고 가정하지 않습니다.
3. 유형별 범위가 있으면 그 범위를, 없으면 축 범위·경계를 읽어 속값을 만듭니다.
4. overall은 별도 범위에서 뽑습니다. 고향은 유형 확률의 입력에 없고, 배경의 고향 가중도 제외됩니다.
5. 꼬리표는 유형별 후보와 개수 규칙을 읽습니다. 숫자가 없는 항목을 새 확정값으로 채우지 않습니다.

## 3. 사용하는 표와 생성 소스

| 표·소스 | 역할 |
|---|---|
| `personality_type`·`personality_group` | 유형 코드·이름·설명과 묶음 |
| `personality_slider`·`personality_slider_map` | 유형 축·겉 성향 역할, 글자, 범위·경계 |
| `worldcup_carry_rule` | 글자 기울기 반영 몫과 라운드 무게 |
| `personality_type_trait` | 유형별 꼬리표 후보 |
| `personality_source_map` | 배경과 축의 연결 자료. 고향 연결의 표 값과 실제 제외 처리는 구분 |
| `member_init_rule` | 생성 대상과 범위·분포 설명 |
| `casting.mjs`·`idol-generator.mjs` | 메모리 생성과 항목별 출처·대기 진단 |
| `data.mjs` | schema 등록 경로를 우선 읽고 필수·선택 목록을 나누는 로더 |

표와 코드에 값이 들어 있다는 사실은 발란스 확정이나 전체 UI 검수 완료를 뜻하지 않습니다. 유형 축의 비율·범위는 각 행의 상태와 연결 근거를 따릅니다.

## 4. 화면 노출

| 항목 | 현재 확인 또는 기획 경계 |
|---|---|
| 기본 유형 배지 | 현재 배지 함수는 색 점·묶음명·유형명을 표시하고 코드는 기본으로 숨깁니다 |
| 코드 확인 | `showCode` 옵션이 있는 기획·상세 표시에서 코드를 덧붙일 수 있습니다. 실제 각 화면의 노출 검수는 별도입니다 |
| 속값·겉 성향 숫자 | 내부 값을 설명 문장으로 읽게 하는 기획을 유지합니다. 숫자 전수 노출로 바꾸지 않습니다 |
| 꼬리표·상성 | 꼬리표는 간접 표현, 유형 상성은 숨김 방향을 유지합니다 |
| 생성 연출 | 축이 차례로 정해지는 연출은 기획 범위이며 이 소스 대조만으로 완성으로 표시하지 않습니다 |

화면의 자체 명칭과 설명 문구는 연결된 유형·묶음 자료를 따릅니다. 이름 후보와 과거 UI 분담 기록은 짝 로그에 보존합니다.

## 5. 아이템·스킬 변경 구조 (계획)

- 연결 기획은 `growth_modifier` + `modifier_owner`를 사용합니다. 새 효과 표를 이번에 만들지 않습니다.
- 속값은 아이템의 지속 효과와 스킬의 즉시 효과로 바꾸는 구조입니다. target_kind·조건·효과량은 연결 표와 해당 기획의 범위입니다.
- 유형 자체 변경은 긴 누적 또는 특별 아이템 방향을 보존합니다. 글자 변경 방식은 실제 구현·결정 범위를 별도로 확인해야 합니다.
- [아이돌 능력](../개발진행기획_v01/콘텐츠별_v03/아이돌능력_기획서.html) · [성장·관계](../개발진행기획_v01/콘텐츠별_v03/성장관계_기획서.html)와 함께 봅니다.

## 6. 발란스와 남은 결정

- 유형 축 경계·범위, 월드컵 반영 몫·무작위 몫·라운드 무게, 유형별 속값 범위와 출현 분포는 해당 표 상태를 확인합니다. 현재 임시로 채운 수치를 새 확정값으로 해석하지 않습니다.
- 표현 축 범위·배경 기울기, 꼬리표 개수와 유형 변경 조건·효과량은 발란스 확인 범위입니다.
- 배경 조각이 글자 확률 또는 표현 축에 영향을 주는 별도 안과 자체 화면 명칭은 과거 제안과 실제 생성기 경로를 구별합니다. 이번 문서 정비에서 새 결정을 만들지 않습니다.

## 7. 확인 범위

- 현재 표의 축 역할·유형 코드·수치 상태와 로더, 유형 우선 생성 함수, 오디션 어댑터와 배지 함수를 대조했습니다.
- 분포 시험·실제 화면·유형 변경 아이템·스킬의 전체 적용, 영속 저장과 성장의 전수 연결은 이번에 실행 검수하지 않았습니다.
- [S19](S19_캐릭터조합생성_구조_v01.md)는 배경·서사·능력·재능·스킬·그림까지 조합하는 흐름, [S20](S20_유저스테이터스_저장구조_v01.md)은 현재 저장과 구조안을 설명합니다.
