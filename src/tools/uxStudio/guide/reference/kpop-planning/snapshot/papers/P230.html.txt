</section><section class="part" id="part-3"><h2>3. 구동 방법·시뮬레이션</h2><h3>공용 게임 상단 메뉴</h3>
<p>상위에는 <strong>앨범 발매·페스티벌·응원 크루</strong>를 둡니다. 앨범 발매 또는 그 하위 화면을 열면 바로 아래 관련 행에 <strong>음원 제작·방송·공연·음악 차트·시티 투어</strong>가 보입니다. 다른 메뉴를 열면 해당 행을 숨깁니다. 직접 음악 차트 주소로 들어와도 앨범 가족과 현재 하위 메뉴를 표시합니다. 관계·순서·문구는 <a href="/data/simulator/menu.json">공용 메뉴 데이터</a>를 읽으며, 다른 보조 도구의 정리는 별도입니다.</p>
<p>화면 흐름: <a href="/docs/planning/game-simulator.html?module=simulator_module_album_release">공용 게임</a> → 기존 보드 → 하단 앨범 → 제작·발매 → 하단 차트 → 보드 플레이 → 차트 복귀 → 만료 → 다음 앨범.</p>
<ol>
<li>게임 시뮬레이터의 같은 팀·같은 실행에서 진행합니다. 실제 보드 기록을 가진 전체 체크포인트가 있어야 제작/실제 정산을 시험합니다.</li>
<li>기존 조건을 충족해 싱글을 발매하면 크루 공유/차트 등록과 같은 저장에서 로컬 이벤트가 열립니다. 크루가 없어도 이벤트 입장은 가능합니다.</li>
<li>차트 보기를 누르면 상단 순위표의 내 행으로 한 번 이동하고 부드럽게 강조합니다. 주기 갱신으로 스크롤을 다시 움직이지 않습니다. 남은 시간·다음 순위까지 점수·현재 효과를 이어서 보고, 전체 명단·계산 근거·이전 결과는 접어 둡니다.</li>
<li>주동작은 기존 보드로 돌아가는 버튼입니다. 실제 굴림은 이벤트 실적을 쌓고, 다음 START에서 이전 굴림의 적립분을 정산합니다.</li>
<li>명시적인 단독 시험창에는 발매 시험조건·실적1회·시간 진행·종료 시험을 둡니다. 조건 시험은 현재 팀 원본을 수정하지 않으며 실제 미션 완료로 저장하지 않습니다.</li>
<li>시험 실적은 별도 원장입니다. 시험 적립을 실제 보드 START 지급에 합치지 않습니다. 시험 명령의 순위 변화는 로컬 시나리오 검토용입니다.</li>
<li>새로고침은 기존 명단·점수·마감 시각·정산 영수증을 복원합니다. 현재 페이지 초기화 등 기존 공통 조작의 범위를 새로 넓히지 않습니다.</li>
</ol>
<p><a href="../../../%EC%A6%9D%EA%B1%B0/20261103_142753_%EB%8B%A8%EC%9D%B4_9%EC%B0%A8_%EC%95%A8%EB%B2%94%ED%81%AC%EB%A3%A8_%EC%9B%94%EB%93%9C%ED%8E%98%EC%8A%A4%ED%8B%B0%EB%B2%8C_%ED%86%B5%ED%95%A9%EA%B0%9C%EB%B0%9C/planning-ui/album-chart-peer-concept.html">이전 비교 목록 시안</a>은 과거 메모리 UI입니다. 현재 이벤트 게임·실제 보드 정산의 구현 검수로 사용하지 않습니다.</p>
</section><section class="part" id="part-4"><h2>4. 상세 기획</h2><h3>연계 데이터와 단독 시험</h3>
<p>연계 실행은 기존 메인 세션의 오디션 팀·동일 ID·진행을 재사용합니다. 이미 지정된 <code>testPage</code>는 유지하며, 메뉴 이동으로 다른 팀이나 새 저장 범위를 만들지 않습니다.</p>
<p><strong>이 화면을 단독 시험으로 열기</strong> 링크는 별도의 테스트팀·저장 범위로 엽니다. 명시된 단독 화면 안에서는 그 팀·관측 능력과 최초 지원 환경을 재사용합니다.</p>
<p><strong>시험곡으로 앨범 판매 시작</strong>을 누르면 기존 발매곡·회차를 재사용하거나 음원·결제 없는 메타데이터 시험곡을 준비합니다. 기존 제작·발매 명령과 시험조건 적용기를 사용하며, 고정 참여 명단이 없는 시험곡의 능력보상 연결은 대기로 둡니다.</p>
<p>사용자 초안·편집본은 덮어쓰지 않고, 기존 발매 데이터·회차를 보존합니다. 종료된 리그를 다시 시작하지 않습니다. 팬이 양수인데 계층이 확인되지 않으면 대기하며, 미정 계층을 0으로 만들지 않습니다.</p>
<p>페스티벌의 시험 자격·순수 투표 점수는 이전 파이널 시험에 한정한 별도 메모리 정책입니다. 정식 주간·월드, 자격·가중치·보상, 60/63일 달력 정합성과 실제 시즌 전환의 기존 미구현·검수 대기는 그대로 유지합니다.</p>
<p>구조의 단일 정본은 <a href="../../%EC%8B%9C%EC%8A%A4%ED%85%9C%EA%B8%B0%ED%9A%8D/S17_%EA%B8%B0%ED%9A%8D%EC%84%9C%ED%88%B4_%EC%A0%9C%EC%9E%91%EA%B8%B0%EB%B3%B8%EC%96%91%EC%8B%9D_v02.md#game-simulator-data-contract">공용 게임·시뮬레이터 데이터 계약</a>입니다. 이 절의 검수 범위는 <strong>소스 연결, 최신 직접 플레이는 사용자 확인</strong>입니다.</p>

<h3>1일 차트 버프와 신규 이벤트 재화 — 로컬 구현</h3>
<p>앨범 이벤트의 추가 현금은0이며 신규 <strong>앨범 이벤트 재화</strong>를 별도 원장에 적립합니다. 실제 보드 사건의 순위/배수를 동결한 뒤 기존1번 출발점 통과에서 재화·팬·고정 참여자 능력과 함께 처리합니다. 기존 보드 돈·일반 방송/공연 보상은 유지합니다.</p>
<p>순위1/2<del>10/11</del>25/26<del>50/51</del>100위의 배수1 재화량은10/6/4/2/1의 <strong>로컬 임시값</strong>입니다. 차트 점수·money·경제S와 단위가 다릅니다. 시티 투어 참가비로 사용합니다. 직접 현금 교환·시즌 보존과 정식 재화표 등록은 별도입니다.</p>
<p>게임 START의 전용 원장·기존 팬/멤버 성장 callback·중복 영수증·복구 연결을 구현했습니다. 자동 발란스는 개별 멤버 writer가 없어 신규 앨범 정산 전체를 대기로 둡니다. 일부 재화만 지급하거나 합류 전원에게 임의 배분하지 않습니다. 최신 실제 정산 화면은 사용자 확인 항목입니다.</p>
<h3>앨범 참여자에게만 주는 1일 추가 능력 — 게임 소스 구현</h3>
<p>리그는 발매한 앨범의 <strong>고정 참여 명단·파트·참여도</strong>를 함께 사용합니다. 순위와 보드 실적에서 나온 멤버별 기본 능력량에 각 참여자의 계수를 적용하고, 보컬·랩·제작 역할에 맞는 기존 세부 능력으로 보냅니다. 미참여 멤버의 이 앨범 추가 능력량은0입니다. 기본량을 인원수나 참여도 합계로 나누지 않는 <a href="%EC%A0%95%EC%82%B0%EA%B8%B0%EC%A4%80_%EB%B0%9C%EB%9E%80%EC%8A%A4%EA%B5%AC%EC%A1%B0_%EA%B8%B0%ED%9A%8D%EC%84%9C.md">P179 정산 기준</a>을 유지합니다.</p>
<p>기간중 추가 효과를 적립하고 기존1번 출발점을 통과할 때 정산합니다. 기간이 끝나면 새 적립은 멈추며 이미 적립된 미정산분도 그 곡의 고정 명단으로 처리합니다. 현재 대표곡이나 현재 팀 명단으로 대상을 바꾸지 않습니다. 새 멤버·이름 변경·성장 상한 도달로 남은 양을 다른 멤버에게 옮기지 않습니다.</p>
<p>전용 이벤트 재화와 직접 팬은 기존 팀 소유 범위에 한 번 처리하며, 일반 보드 성장과 앨범 추가 성장을 화면과 영수증에서 구분합니다. 미참여자가 일반 레슨으로 성장한 것을 앨범 보상 오류나 앨범 참여로 해석하지 않습니다. 기존 팬/계층·활동량·차트 점수의 산식은 이번 대상 기획에서 변경하지 않습니다.</p>
<p><strong>현재 구현:</strong> 리그는 albumId/memberId/statId별 대상·요청량을 만들고 게임은 기존 멤버별 성장 callback에 연결합니다. 고정 ID가 현재 팀에 없으면 임의 다른 멤버에게 보내지 않습니다. 자동 발란스 targeted API와 최신 실제 정산 검수는 대기입니다.</p>

<h3>제작 전에 보는 대략의 시작 순위</h3>
<p><strong>누구의 싱글인지 선택 → 현재 멤버 능력·팬으로 예상 순위 확인 → 음악/재킷 → 발매 때 실제 시작 순위 확정</strong> 순서입니다. 첫 음반도 현재 팀과 참여 멤버의 능력을 반영합니다. 다음 음반은 같은 계산에 직전 앨범의 최종 성적을 더합니다. 화면의 예상은 대략의 범위이며 발매 때의 능력·팬·새 상대에 따라 달라집니다.</p>
<p>팀 평균과 참여자 평균이 모두 원점수500이고 팬이 없는 수학 예시는 <strong>대략40~53위</strong>입니다. 음반 차수로 등수를 강제하지 않으며 2번째부터도 같은 공통 계산을 씁니다. 가중치·곡선·상한·예상 범위 폭은 <a href="/data/music_career/music_career_rules.json">음악 규칙 데이터</a>의 <code>albumLeague.entry</code>에서 조절합니다.</p>

<p>예상 순위는 새 상대 구간의 독립 균등 분포 가정으로 평균과 분산을 구하고, 예상 등수 ±ceil(1.65×표준편차)를 가능한 등수 안에 제한한 <strong>대략의 모델 범위</strong>입니다. 전체 가능한 최소/최대 범위도 근거에 별도 보존하며, 이 예상을 실제 배정/보상 보장으로 쓰지 않습니다.</p>
<p>최고 순위와 최종 순위는 다릅니다. 현재 리그를 렌더할 때 팬·능력이 늘었다고 F를 다시 계산하지 않습니다. 다음 발매의 현재 팬·현재 참여 멤버 능력·직전 최종 결과에 반영합니다. 기존 리그는 저장한 구식 규칙과 순위를 유지하고, 새 입장 정책은 별도 entryPolicyVersion으로 동결합니다. 직전 점수의 원단위 재사용은 scoreRuleVersion이 같을 때만 허용하며 버전이 다르면 자동 이월하지 않습니다.</p>
<p>팬은 L+C+K와 기존 계층 원단위를 보존합니다. 정상 승격은 가중치가 줄지 않게 구성했고 수익용 income_weight를 복사하지 않았습니다. 화면용 층별 floor 팬 수를 원본 입력으로 쓰지 않습니다. 새로운 라이트 팬·정상 계층 승격이 동일 조건의 시작 성적을 낮추지 않아야 합니다. 상대가 바뀌면 실제 시작 순위가 무조건 좋아지는 것은 아닙니다.</p>

<h3>공통 시간 버프와 오른쪽 상세</h3>
<p>시간 버프는 타입·출처·현재 저장 범위·기준 시계·시작/종료 시각·남은 시간·효과를 공통 형식으로 표시합니다. 앨범은 <code>album_rank</code> 타입입니다. 게임 상단 연출 영역에는 현재 순위·<strong>시:분:초</strong>만 작은 한 줄 칩으로 겹쳐 표시하고, 누르면 같은 곡의 차트로 이동합니다. 차트 화면에서는 이 칩을 숨기고 오른쪽 상세는 유지합니다. 적립 기준·긴 설명은 오른쪽에 둡니다. 크기·위치·여백과 차트 숨김 대상은 공통 UI JSON에서 조절합니다. 오른쪽에는 곡·현재 순위·남은 시간·주요 효과의 대표 요약이 항상 보입니다. 참여자별 능력·미정산·시계와 상세 계산은 기본 접힌 상세 보기에 두고 펼칠 때 확인합니다. 처음 표시·화면/메뉴 이동·오른쪽 host 이동·숨김 후 복귀 때는 상세를 접습니다. 같은 화면에서 사용자가 펼친 상세는 초 단위 남은 시간 갱신으로 닫지 않습니다.</p>
<p>활성 버프가 없거나 만료·세션/진행/원본 기록 변경으로 유효하지 않으면 상단 표시와 오른쪽 상세를 함께 숨깁니다. 캐시 재사용 때 원본 변경 여부를 확인하고 정기 재투영에서도 원본을 다시 읽습니다. 변경 알림을 놓친 경우에도 이전 캐시를 원래 만료까지 계속 쓰지 않습니다. 이 처리는 표시 검증이며 효과·기간·지급·미정산 기록은 바꾸지 않습니다. 하단 차트는 실제 차트 화면에서만 선택 표시를 하고, 버프가 켜져 있다는 이유로 선택 표시하지 않습니다.</p>
<p>오른쪽에는 곡·고정 참여자·현재 순위·유효 남은 시간, <strong>활동1회·배수1의 적립 기준</strong>, <strong>이 곡의 실제 START 미정산 합계</strong>를 구분해 표시합니다. 시험 적립은 별도입니다. 화면 숫자는 한 바퀴의 고정 지급량이 아니며, 유효 활동에서 쌓인 적립을 기존 출발점 정산에서 지급합니다. 만료되면 신규 적립과 활성 표시가 끝나며 이미 적립한 기록은 정산 대상으로 남습니다.</p>
<p>공통 표시는 캐시된 시간만 매초 갱신하고 저장 전체를 매초 검증하지 않습니다. 숨은 화면은 타이머를 멈추고 복귀 시 원본을 확인합니다. 기존 멤버 시간 버프는 원래 <code>ends_at</code>과 계산을 유지하며, 명시한 시계 변환기를 통해 같은 표시 계약에 연결합니다. 비어 있는 기존 표에서 버프를 만들거나 다른 시계의 날짜를 임의로 합치지 않습니다.</p>
<h3>출발점 추가 보상 필러·자동 결과 연결 — 후속 기획, 미구현</h3>
<p><strong>출발점 통과 → 기존 정산 확정 → 일반 보상 → 앨범 버프 추가 보상</strong> 순서의 필러 연출이 필요합니다. 별도 앨범 줄에 실제 영수증의 전용 재화·팬·참여 멤버별 능력을 표시합니다. 클릭 전부터 정산 결과를 이해할 수 있어야 하며, 연출 재생이 지급을 다시 실행하면 안 됩니다.</p>
<p>발란스 시뮬레이터도 같은 계산·정산 영수증을 결과로 내보내고, 현황판은 그 결과를 읽어 일반 보상/앨범 추가 보상과 실제 지급/대기를 나눠 표시해야 합니다. 현황판에서 별도 보상을 계산하거나 수동 지급하지 않습니다. 필러 연출·개별 writer·자동 결과 내보내기·현황판 상세 반영은 각각 후속 개발/검수 항목입니다.</p>
<h3>남은 결정·운영 연결</h3>
<p>실제 매칭 서버·공유 리그의 첫 진입 정책·공통 마감/부족 인원·회원 공개 범위·차단/탈퇴·운영 정정이 남습니다. 팬 소유/정밀도와 공용 시즌60일 대9주 정합은 기존 담당 연결 대기입니다. 로컬 수치는 시험 결과를 보고 조정하며 운영 승인으로 표시하지 않습니다. 주간/월드의 투표 비중·자격·한도는 이 이벤트의 완료와 별개입니다.</p>
<h3>솔로·유닛·팀의 참여와 보상</h3>
<p><strong>한 명이 참여하면 솔로, 팀 일부의 두 명 이상이 참여하면 유닛, 팀 전원이 참여하면 팀 앨범</strong>입니다. 5명 팀에서 3명이 부르는 앨범은 유닛입니다. 한 명뿐인 팀의 첫 싱글도 솔로입니다. 처음 곡을 만들 때 고른 참여 멤버·파트를 앨범에 고정하며, 이 명단이 추가 능력을 받을 대상을 정합니다.</p>
<p><strong>능력은 참여자 각자의 몫, 이벤트 재화는 팀에 한 번</strong>입니다. 같은 순위·활동량·배수·파트·개인 상태라면 한 멤버의 요청량은 솔로·유닛·팀에서 같습니다. 개인 보상을 참여 인원이나 참여계수 합계로 나누지 않습니다. 기존 파트 계수·세부 능력 비율·개인 성장 상한은 적용하며, 미참여자는 그 앨범의 추가 능력을 받지 않습니다.</p>

<h3>시티 투어에서 이벤트 재화 사용</h3>
<p><a href="%EC%8B%9C%ED%8B%B0%ED%88%AC%EC%96%B4_%ED%95%B5%EC%8B%AC%EC%A0%9C%EC%95%88%EC%84%9C.html">시티 투어: 앙코르 레이스</a>는 <strong>발매 앨범의 참가 버튼 → 현재 앨범 차고 → 급유 →5팀10바퀴 경기 →주사위·아이돌 카드 수령</strong>으로 연결합니다. 앨범 하위 시티 메뉴도 같은3D 게임입니다. 기존2D 비교 시험의 입장비/돈상금과 구분합니다.</p>
<p>추가 참가비는0, 급유 때만 기존 albumEventWallet의 재화를 사건 영수증으로 차감합니다. 재화1개=¼랩이고 인원수/속도로 거리를 바꾸지 않습니다. 현재 앨범의 고정 참여 멤버 raw18/보유 성향 평균으로 속도를 계산하고, 같은 원본 리그의24시간 마감/시험 상대 ID·seed를 사용합니다. 메뉴 이동/재접속으로 시간·재화를 보충하지 않습니다. 재화가 없으면 보드에서 모으기로 이어집니다.</p>
<p>정상 경기의 본인1랩·연료4소모 이상이면 참가 기본+순위 추가 주사위/아이돌 카드 보상입니다. 제안 수량은 <a href="/event/cityTour/data/racing3d-rewards.json">보상 데이터</a>에서 읽습니다. 앨범 경로는 소유 full checkpoint/카드 보유 원천 확인 후 기존 held/카드 효과 원장과 career 수령 영수증을 복구 journal로 묶습니다. 독립URL은 시험 영수증만 기록합니다. 데이터가 부족하면 실제 지급 완료를 표시하지 않습니다.</p>
<p>경주 결과를 차트1등으로 직접 대입하거나 가짜 보드 사건으로 변환하지 않습니다. 검증 resultId별 차트 기여량·반복 상한·경제 순환/서버 실유저 동기화는 후속 연결입니다. 기존 보드 돈·팬·고정 참여자 능력 START 정산은 변경하지 않습니다.</p>

<li>내 유효 점수 증가가 동일 상대 점수에서 순위를 나쁘게 하지 않습니다. 상대 시간 점수 변화와 동점이 설명됩니다.</li>

<li>전용재화·팬·참여자능력·적립 소비의 실패는 함께 복원하고 저장 후 표시 오류는 journal로 복구합니다.</li>
<li>기간 종료는 신규 적립/효과를 끝내며 기존 성장·미정산 적립·최종 성적은 보존합니다.</li>
