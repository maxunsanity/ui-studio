<p>배속 ×1, 준비·스킬 자동 선택을 사용한 기본 검수 프로필의 목표입니다. 초 단위 값은 모두 시안 예시이며 2단계 자동 시뮬 결과로 조정합니다. 사람이 카드를 오래 고민하거나 리포트를 계속 읽으면 실제 벽시계 시간은 늘어납니다. ×2는 전투 시간만 줄이며 같은 5분을 보장하는 모드로 표시하지 않습니다.</p>

<h3>3-2. 이동·카메라·강화 제한<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<ul>
<li>기존 시안처럼 짧은 시간에 전체 길을 통과하는 연출을 재사용하지 않습니다. <code>elapsedMs / clipDurationMs</code>로 적을 화면 끝까지 보내는 방식 대신 차도 길이와 <code>speed_mps</code>로 이동 거리를 계산합니다.</li>
<li>작은 악귀 기본 이동 속도 <strong>2.4m/s</strong>, 보스 <strong>1.8m/s</strong>, 일반 악귀 속도 상한 <strong>3.4m/s</strong>를 첫 조정안으로 둡니다. 모두 시안 예시입니다. 실제 모델 크기와 1440·430px에서 보는 이동 속도를 함께 검수합니다.</li>
<li>같은 종류의 악귀는 길이 긴 루트라는 이유로 더 빠르게 움직이지 않습니다. 짧은 루트의 압박은 출발 시각·수량·몬스 배치로 조절합니다. 이동 중 방향 전환은 위치를 순간 이동시키지 않습니다.</li>
<li>웨이브가 강해지는 주된 축은 체력·수량·큰 구름 비중입니다. 속도 배율은 시안 예시 <code>1.00 → 1.05 → 1.10</code> 정도로 제한하며 최종 속도는 상한 이하입니다. 빠르기만 높여 난도를 올리지 않습니다.</li>
<li>경로 길이 <code>L</code>, 실제 속도 <code>v</code>이면 무방어 도착 시간은 <code>L/v</code>입니다. 짧은 길조차 충분히 읽을 시간이 있는지 검사합니다. 모든 악귀가 종점까지 걸어야 하는 것은 아니며 길목에서 퇴치됩니다.</li>
<li>배속 ×1이 기본입니다. ×2는 사용자가 고를 때만 적용합니다. 화면 주사위·보드 턴 속도와 디펜스 속도를 공유하지 않습니다. 스폰·이동·공격·게이지·웨이브 타이머는 같은 전투 시계를 사용합니다.</li>
<li>처음에는 전체 맵에서 다섯 입구를 보여 주고, 교전 중에는 주요 길목과 랩 스튜디오를 함께 보여 줍니다. 건물 가까이 보기와 카메라 이동이 시뮬 속도를 바꾸지 않습니다.</li>
</ul>
<h3>3-3. 승리 프로필의 검증 조건<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<p>기본 검수 프로필은 몬스 다섯·예능 방송국 방공포·건물별 순찰 드론의 배치를 준비합니다. 함정은 생성하지 않습니다. 첫 웨이브 초반에는 적이 다섯 길목에 먼저 보이고, CSV의 등장·활성 시점부터 몬스와 건물 방어가 함께 가동됩니다. 자동 선택도 CSV의 상황 힌트를 사용합니다. CSV의 체력·공격·사거리·스폰 일정을 조정해 실제 공격 계산으로 이기도록 합니다. 보스 체력을 표시만 줄이거나, 시간 종료 시 적을 지우거나, 무대 체력을 몰래 무한대로 만드는 처리는 사용하지 않습니다.</p>
<p>2단계에서 여러 고정 시드와 후보 선택 조합을 돌려 <strong>모든 계획 스폰 완료·모든 악귀 퇴치·보스 퇴치·무대 생존·기본 프로필 유출 0·모든 필수 연출 이벤트 발생</strong>을 확인합니다. 연출을 다 보여 주려고 죽은 보스를 무적으로 유지하지 않습니다. 너무 빨리 끝나면 스폰 일정과 밸런스를 조정하고 다시 시뮬합니다. 목표 시간 허용 범위는 시안 예시 270~330초입니다. 이것은 검수용 승리 구성이고 본게임 난도·경제 보상 확정이 아닙니다.</p>

<h3>5-1. 계산 순서와 모듈<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<p>고정 시간 간격의 순수 시뮬 <code>tick(state, tables, dt, input)</code>을 만들 계획입니다. 한 tick은 예정 스폰·우리 편 활성 조건 처리 → 기존 투사체 명중 → 피격·사망 확정 → 살아 있는 적의 이동·종점 도달 → 사거리·표적 갱신 → 새 공격 → 점수·게이지 → 스킬 기회·승패 판정을 순서대로 처리합니다. 동일 tick의 순서는 고정하고 사망한 적이 무대에 중복 피해를 주지 않게 합니다. 이동 경로와 투사체 명중은 경계 통과·거리 누적으로 계산해 배속 때문에 충돌을 놓치지 않습니다.</p>

</tr>

<p>렌더러가 공격 피해나 보상을 결정하지 않습니다. 3D를 불러오지 않는 자동 시뮬과 브라우저 플레이가 같은 전투 모듈을 사용합니다. x1/x2, 일시 정지, 카메라 프레임 수가 결과를 바꾸지 않아야 합니다.</p>
<h3>5-2. 경로·배치·목표<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<ul>
<li>실제 도로 기준은 v06 <code>navigation_surface.json</code>의 <code>traffic_rects</code>와 <code>street_source.json</code>입니다. 월드 좌표는 <strong>x·z가 바닥, y가 높이</strong>입니다. <code>data/game/map_node.csv</code>의 Blender 좌표를 쓸 때는 <code>(x,y,z) → (x,z,-y)</code> 변환을 어댑터 한 곳에서만 적용합니다.</li>
<li>차도 중심선은 기존 <code>-250, -106, 106, 250</code>입니다. 교차점과 경계 입구를 노드로, 차도 위 구간을 edge로 구성합니다. 이는 기존 공간 값이며 전투 밸런스 값이 아닙니다. 적의 중심뿐 아니라 충돌 반지름을 포함한 이동 띠가 차도 안인지 검사합니다.</li>
<li>다섯 진입 방향은 북·북동·동·남·서입니다. 같은 출발점을 복제해서 다섯 루트로 세지 않습니다. 경로는 병합할 수 있지만 입구와 앞쪽 진행 구간은 구분되고 몬스 길목도 다섯 곳으로 나눕니다.</li>
<li>제안 목표는 <code>city_35</code> 무대입니다. 무대 건물 중심까지 악귀를 보행로로 이동시키지 않습니다. 인접 차도 위에 <code>target_approach_node_id</code>를 두고, 그 점 도달 시 무대 피해 이벤트를 보냅니다. 구름이 인도를 가로질러 랩 스튜디오 안으로 들어가는 경로를 만들지 않습니다.</li>
<li><code>city_35</code>의 현재 월드 중심 <code>(-153,215)</code>와 가까운 차도 위 <code>(x=-153,z=250)</code>를 <strong>후보 접근점</strong>으로 제안합니다. 실제 입구·모델 외곽·마지막 길목·시야는 2단계 공간 검사 후 정합니다. 물리 ID와 최종 게임 시설 매핑을 확정하지 않습니다.</li>
<li>몬스는 차도 밖 안전한 길목 슬롯에서 공격합니다. 준비 시간에만 슬롯을 바꿉니다. 각 슬롯은 어느 차도 edge를 담당하는지 연결합니다. 팬 보행면을 악귀 route로 연결하지 않습니다. 몬스가 없거나 아직 등장하지 않은 슬롯에서는 활성 조건을 채운 건물 방어만 작동하며 실제 게임의 멤버 해금은 읽기용 어댑터 후속 범위입니다.</li>
</ul>

<h3 id="building-defense">건물별 배치와 드론 순찰 계약<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<ul>
<li><code>building_defense.city_id</code>로 각 장치를 실제 건물에 귀속합니다. 방공포는 예능 방송국 계열 지붕 소켓, 드론은 연습실·녹음실 계열 건물 주변의 공중 순찰 영역을 우선 사용합니다. 모든 건물에 같은 장치를 자동 배치하지 않습니다. 랩 스튜디오·중앙 숲·팬 통로를 가리지 않는 배치를 제안합니다.</li>
<li>방공포는 고정 장착 위치에서 사거리 안의 표적을 바라보고 발사합니다. 드론은 담당 건물을 중심으로 계속 돌며, 방어 범위 안으로 오는 악귀를 현재 드론 위치에서 공격합니다. 공격 때만 잠깐 생겼다 사라지는 드론으로 만들지 않습니다.</li>
<li><strong>순찰 반경과 방어 반경은 별개입니다.</strong> 드론의 방어 범위는 건물 앵커를 중심으로 정의하며 방공포보다 넓게 제안합니다. 순찰 각도에 따라 담당 차도를 놓치지 않습니다. 실제 발사 원점과 탄의 비행은 드론의 현재 위치에서 계산합니다. 표적이 방어 범위를 벗어나면 새 발사를 중단하고 이미 날아간 탄의 명중 정책을 따릅니다.</li>
<li>첫 버전은 <code>movement_kind=orbit</code>, <code>range_origin=home</code>을 사용합니다. 적을 따라 지도 끝까지 쫓는 추격은 넣지 않습니다. 궤도 중심·반경·높이·속도·초기 위상은 CSV에서 읽습니다. 공격 중에도 완만한 순찰을 유지하며 몸체만 적 쪽으로 회전합니다. 스킬 카드 정지 중에는 순찰·투사체도 멈춥니다.</li>
<li>2단계에서 건물 외곽과 소켓을 읽어 안전한 궤도를 정합니다. 건물 안을 가로지르는 궤도, 겹쳐 보이는 장착, 맡은 차도에 닿지 않는 방어 범위를 검사합니다. 여러 건물의 방어 범위는 교차로를 서로 보완하게 배치하고, 넓은 범위 대신 드론의 한 발 피해·공격 간격을 조정합니다. 정확한 수치·건물 목록은 시안 데이터와 공간 검수에서 정합니다.</li>
<li>함정 모델·슬롯·스폰·공격 enum·연출 요구는 이번 새 데이터에서 만들지 않습니다. 기존 기획의 함정 내용과 원본 자산은 삭제하지 않고 12절의 제외 목록에 남깁니다. 블루 몬스의 감속 스킬은 함정과 구분해 유지합니다.</li>
</ul>
<h3>5-4. 점수·노래·스킬 기회<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<ul>
<li>스폰 인스턴스마다 <code>alive → killed</code> 또는 <code>alive → leaked</code> 중 하나만 확정합니다. 퇴치 점수·노래 보너스·처치 수는 <code>killed</code> 이벤트 한 번에만 적용합니다. 유출된 적에게 퇴치 점수나 퇴치 보너스를 주지 않습니다.</li>
<li>아이돌 노래는 초당 기본량을 채우고, 퇴치 보너스는 별도 값으로 더합니다. 최대 게이지 도달 시 후렴 이벤트가 발생합니다. 초과량 처리·후렴 유지 시간·재발동 간격은 gauge 표에서 정합니다. 후렴은 몬스들의 자동 강공이며 아이돌이 직접 쏘는 공격이 아닙니다.</li>
<li>기존 P59 관련 추가 절의 한 판 네 번 기회는 시작값 예시로 채택합니다. 웨이브별 퇴치 점수 기준 한 번씩과 보스 직전 한 번입니다. 각 기회에는 고유 토큰이 있고 중복 팝업·재선택을 막습니다.</li>
<li>후보는 같은 기회 안에서 서로 다른 몬스 세 마리입니다. 각 몬스의 다음 스킬 단계가 있는 경우만 후보로 뽑습니다. 첫 선택은 0→1입니다. 최대 단계 몬스는 제외합니다. 다른 기회에서 같은 몬스가 다시 나오는 것은 허용합니다.</li>
<li>eligible 몬스가 세 마리보다 적으면 남은 수만 보여 주고, 전부 최대 단계면 카드 없이 기회를 소비해 전투를 이어 갑니다. 없는 몬스나 가짜 카드를 만들어 세 장을 채우지 않습니다. 이 예외 정책은 단이 제안으로 확인 항목에 남깁니다.</li>
<li>카드가 열리면 이동·스폰·공격·게이지·웨이브 타이머 모두 정지합니다. 자동 검수에서는 시안 예시 5초 뒤 CSV 힌트 우선순위로 선택합니다. 수동에서는 사용자가 고를 때까지 기다립니다. 정지 시간의 계산과 자동 선택 대기 시간을 구분합니다.</li>
</ul>
<h3>5-5. 압박 → 등장 → 역전<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<ol>
<li>경보·준비에는 우리 편 배치 계획과 건물 마크를 보여 줍니다. 첫 웨이브가 시작하면 다섯 입구에 악귀를 동시에 등장시키고 차도를 어둠 구름과 느린 떼로 압박합니다. 실제 도로 데이터의 통행 가능 상태나 팬 경로는 변경하지 않습니다.</li>
<li>첫 전투의 <strong>12초 부근</strong>을 몬스 등장·건물 방어 가동의 초기 목표로 제안합니다(시안 예시). 등장 직전 다섯 루트 모두에 살아 있는 적이 보이도록 스폰 일정을 조정합니다. 가장 짧은 루트라도 가동 전에 랩 스튜디오 종점에 닿지 않는지 도착 시간을 검사합니다. 이 지연은 1웨이브 50초 안에 포함하며 5분 시간표에 덧붙이지 않습니다.</li>
<li>몬스가 밝게 나타나 길목에 자리 잡고 기본 빛 총알 공격을 시작합니다. 같은 활성 시점에 예능 방송국 마크가 방공포로 변신하고 드론이 담당 건물에서 떠올라 순찰·공격합니다. 빛·발사·실제 명중을 순서대로 보여 줍니다. 몬스만, 건물만 공격하는 구성이 되지 않도록 양쪽의 발사·퇴치 관여를 로그로 확인합니다.</li>
<li>이후 웨이브에는 적 수·큰 구름 비중이 올라 잠시 밀집도와 진입 거리가 증가합니다. 스킬 성장·후렴·몬스 기본 공격·방공포·드론의 실제 화력으로 밀집도가 줄어드는 역전 흐름을 제안합니다. 악귀를 갑자기 삭제하거나 모든 HP를 연출 신호로 0으로 바꾸지 않습니다. 등장 시점·강화·스폰 일정은 표에서 읽고 피해 판정은 같은 전투 모듈을 사용합니다.</li>
<li>기본 승리 검수는 무대 생존·모든 적과 보스 퇴치로 마무리합니다. 압박은 다섯 루트의 적 존재·진입률·동시 생존 수로 기록합니다. 무대 HP를 강제로 낮췄다가 복구하거나 실패 판을 승리로 바꾸지 않습니다. 별도 패배 검수는 유지합니다.</li>
</ol>
<h2 id="section-6">6. CSV 표 목록·ID·연결 설계<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h2>
<p>예정 데이터 위치는 <code>data/defense_proto/v01/</code>입니다. 이번 1단계에서는 아래 스키마만 설계합니다. 아직 폴더에 시안 숫자나 CSV 행을 생성하지 않습니다. 공통 메타 칸은 <code>source_ref</code>, <code>value_kind</code>, <code>status</code>, <code>note</code>입니다. 시안 데이터는 <code>value_kind=시안 예시</code>, <code>status=제안(검수 대기)</code>로 기록합니다. 필수 값의 빈칸은 0으로 바꾸지 않고 시작을 막습니다.</p>
<h3>6-1. ID 공통 규칙<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<p>새 시안 ID는 <code>dp_종류_의미</code> 형태의 소문자 영문·숫자·밑줄을 사용합니다. 예: <code>dp_enemy_small</code>, <code>dp_wave_01</code>, <code>dp_spawn_w01_north</code>, <code>dp_slot_north</code>, <code>dp_skill_pink_01</code>. 이름·색·표시 순서가 바뀌어도 ID를 다시 만들지 않습니다. 행 삭제 후 같은 ID를 다른 의미로 재사용하지 않습니다. 경로 단계·스폰·이벤트에는 각각 자체 ID를 부여하고 순서는 별도 정수 칸에 둡니다.</p>
<p>기존 <code>city_35</code>, <code>mons_pink</code>, <code>res_mons_pink</code> 등은 <strong>읽기 참조</strong>입니다. 실제 미정 <code>idol_id</code>, <code>root_msk_id</code>, 시설 확정 ID를 대신 채우지 않습니다. 런타임 인스턴스 ID는 <code>battle_id + spawn_id + spawn_index</code>에서 만듭니다. CSV 정의 ID와 화면 객체 인스턴스 ID를 섞지 않습니다. 단위는 <code>_ms</code>, <code>_s</code>, <code>_m</code>, <code>_mps</code>, <code>_ratio</code>로 명시합니다.</p>

<h3>6-3. 칸 이름과 값의 형식<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<p>아래 CSV 헤더는 예정 형태입니다. <code>*_id</code>는 문자열 참조, <code>*_ms</code>·<code>*_count</code>·<code>*_index</code>·<code>*_order</code>는 음수가 아닌 정수, 거리·속도·비율은 유한 숫자, <code>enabled</code> 등은 <code>true/false</code>, 경로는 로컬 상대 경로입니다. 정확한 필수·선택 칸과 범위는 같은 스키마 정의를 loader와 CLI 검사기에서 공유합니다.</p>
<p><strong>profile.csv</strong></p>
<pre><code class="language-text">profile_id,target_city_id,target_approach_node_id,stage_max_hp,gauge_id,reward_rule_id,tick_ms,time_scale,prepare_ms,intermission_ms,victory_ms,report_preview_ms,target_total_ms,min_total_ms,max_total_ms,checkpoint_ms,opening_wave_id,opening_required_route_count,opening_min_alive_per_route,showcase_mode,source_ref,value_kind,status,note
</code></pre>
<p><code>opening_*</code>는 우리 편 가동 직전 다섯 루트 압박 검수 조건이며 적 삭제나 승리를 발생시키지 않습니다. <code>target_city_id</code>는 시각 목표, <code>target_approach_node_id</code>는 차도 종점입니다. <code>showcase_mode</code>는 검수 구성 구분이며 무적·강제 승리 플래그가 아닙니다. 무대 HP·공격 수치는 2단계에서 시안 값으로 채웁니다.</p>
<p><strong>enemy_type.csv</strong></p>
<pre><code class="language-text">enemy_id,kind,base_hp,speed_mps,max_speed_mps,collision_radius_m,stage_damage,kill_score,kill_gauge,asset_id,hit_fx_id,death_fx_id,source_ref,value_kind,status,note
</code></pre>
<p><code>kind=small/large/boss</code>로 분류합니다. <code>kill_gauge</code>는 퇴치별 보너스이며 gauge의 기본 노래 충전과 구분합니다.</p>
<p><strong>wave.csv / wave_spawn.csv</strong></p>
<pre><code class="language-text">wave_id,profile_id,wave_order,hp_multiplier,speed_multiplier,spawn_window_ms,max_resolve_ms,intro_text_id,outro_text_id,source_ref,value_kind,status,note
spawn_id,wave_id,phase,enemy_id,route_id,start_ms,count,interval_ms,source_ref,value_kind,status,note
</code></pre>
<p><code>phase=swarm/boss</code>, <code>start_ms</code>는 해당 구간의 전투 시간입니다. interval은 양수입니다. 수량과 큰 구름 비중은 spawn 행으로 명시합니다. 마지막 웨이브에만 boss 행을 둡니다.</p>
<p><strong>road_node.csv / road_edge.csv</strong></p>
<pre><code class="language-text">node_id,x,y,z,node_kind,source_geometry_ref,source_ref,value_kind,status,note
edge_id,from_node_id,to_node_id,width_m,length_m,direction,source_geometry_ref,source_ref,value_kind,status,note
</code></pre>
<p><code>node_kind=intersection/entry/target_approach</code>, <code>direction=both/forward</code>입니다. length는 좌표에서 재계산한 값과 대조합니다. graph에서 없는 점 사이에 길을 연결하지 않습니다.</p>
<p><strong>route.csv / route_step.csv</strong></p>
<pre><code class="language-text">route_id,entry_direction,start_node_id,end_node_id,label_text_id,source_ref,value_kind,status,note
step_id,route_id,step_order,edge_id,travel_direction,source_ref,value_kind,status,note
</code></pre>
<p><code>travel_direction=forward/reverse</code>입니다. step의 끝과 다음 step의 시작은 같은 노드여야 합니다. 루트 ID를 셀 안의 쉼표 목록으로 저장하지 않습니다.</p>
<p><strong>defense_slot.csv</strong></p>
<pre><code class="language-text">slot_id,slot_kind,route_id,guard_edge_id,city_id,socket_id,x,y,z,enabled,source_ref,value_kind,status,note
</code></pre>
<p><code>slot_kind=mons/building</code>입니다. 몬스는 월드 좌표를, 건물은 city/socket 참조를 사용합니다. 건물 슬롯에 중복 좌표와 별도 회전을 덧씌우지 않습니다. occupied인 지붕 소켓은 사용할 수 없습니다.</p>
<p><strong>attack_profile.csv / target_rule.csv</strong></p>
<pre><code class="language-text">attack_id,attack_kind,target_rule_id,range_m,damage,cooldown_ms,projectile_speed_mps,burst_count,burst_interval_ms,area_radius_m,slow_ratio,slow_ms,buff_ratio,buff_ms,asset_id,shot_fx_id,hit_fx_id,source_ref,value_kind,status,note
target_rule_id,target_side,priority_primary,priority_secondary,tie_break,source_ref,value_kind,status,note
</code></pre>
<p><code>attack_kind=projectile/beam/area/support</code>입니다. <code>target_side=enemy/ally</code>를 구분하며 응원이 악귀를 강화하지 않게 합니다. 각 attack kind의 필수 칸만 사용하고 안 쓰는 효과 칸은 빈칸을 허용하되 parser가 0으로 임의 치환하지 않습니다. 감속·응원 중첩은 2단계에서 정책 enum과 한도를 명시합니다.</p>
<p><strong>mons_combat.csv / building_defense.csv</strong></p>
<pre><code class="language-text">unit_id,source_mons_id,slot_id,attack_id,first_skill_id,color_text_id,asset_id,activation_wave_id,activation_start_ms,arrival_fx_id,source_ref,value_kind,status,note
binding_id,city_id,slot_id,defense_kind,level,attack_id,transform_fx_id,idle_asset_id,combat_asset_id,eligible,activation_wave_id,activation_start_ms,movement_kind,range_origin,patrol_radius_m,patrol_height_m,patrol_speed_mps,patrol_start_angle_rad,source_ref,value_kind,status,note
</code></pre>
<p>몬스 원본 ID는 읽기만 합니다. building의 <code>eligible</code>과 시안 <code>level</code>은 본게임의 시설 해금이나 v15 건물 증설 단계로 자동 대체하지 않습니다. <code>defense_kind=drone/anti_air</code>만 허용하며 함정은 제외합니다. <code>activation_wave_id</code>와 <code>activation_start_ms</code>로 등장·가동 시점을 지정하고, 해당 전투 시계 이전에는 발사하지 않습니다. 몬스와 장치의 첫 활성은 한 번만 확정합니다. 방공포는 <code>movement_kind=stationary</code>, <code>range_origin=unit</code>이며 순찰 칸은 빈칸입니다. 드론은 <code>movement_kind=orbit</code>, <code>range_origin=home</code>이고 순찰 네 칸을 필수로 검사합니다. 방어 반경은 연결된 <code>attack_profile.range_m</code>, 건물 앵커는 slot의 city/socket 변환을 읽습니다. 궤도 위상은 순찰 속도/반경과 전투 시간으로 계산하고 프레임마다 다른 난수를 넣지 않습니다.</p>
<p><strong>skill.csv / skill_effect.csv</strong></p>
<pre><code class="language-text">skill_id,unit_id,skill_level,parent_skill_id,name_text_id,description_text_id,max_level,source_ref,value_kind,status,note
effect_id,skill_id,attack_id,stat_key,operation,value,duration_ms,source_ref,value_kind,status,note
</code></pre>
<p>첫 단계의 parent는 빈칸입니다. 단계가 오르면 같은 몬스의 직전 단계로 연결합니다. <code>operation=add/multiply/set</code>를 허용 목록으로 제한하며 효과를 누적 재적용하지 않고 기본 능력과 현재 스킬 단계에서 재계산합니다. skill ID는 시안 전용이며 실제 미정 msk_id가 아닙니다.</p>
<p><strong>skill_offer.csv / gauge.csv</strong></p>
<pre><code class="language-text">offer_rule_id,profile_id,wave_id,trigger_kind,score_threshold,offer_count,pick_count,once_per_wave,auto_wait_ms,hint_policy,maxed_policy,source_ref,value_kind,status,note
gauge_id,max_value,base_gain_per_s,chorus_attack_id,chorus_duration_ms,chorus_cooldown_ms,overflow_policy,chorus_fx_id,source_ref,value_kind,status,note
</code></pre>
<p><code>trigger_kind=score/before_boss</code>입니다. score는 웨이브별 누적 퇴치 점수입니다. 노래 보너스는 enemy_type에서 읽고 중복 칸에 다시 더하지 않습니다. <code>hint_policy</code>는 boss/fast/dense/support 상황의 허용 정책을 사용합니다.</p>
<p><strong>reward_rule.csv / report_field.csv</strong></p>
<pre><code class="language-text">reward_rule_id,apply_scope,win_text_id,lose_text_id,source_hint_text_id,source_ref,value_kind,status,note
field_id,display_order,label_text_id,metric_key,unit_text_id,source_ref,value_kind,status,note
</code></pre>
<p>첫 시안의 <code>apply_scope=report_only</code>입니다. 게임 재화·팬 수·아이돌 능력·보드 잔액을 변경하지 않습니다. <code>metric_key</code>는 spawned/killed/leaked/stage_damage/combat_elapsed_ms/choice_elapsed_ms/boss_killed 등 명시한 로그 값만 표시합니다.</p>
<p><strong>asset.csv / fx.csv / ui_text.csv</strong></p>
<pre><code class="language-text">asset_id,asset_kind,local_path,source_resource_id,tint,scale,source_ref,value_kind,status,note
fx_id,event_kind,asset_id,duration_ms,delay_ms,color,intensity,ui_text_id,source_ref,value_kind,status,note
text_id,text_ko,source_ref,value_kind,status,note
</code></pre>
<p>새 구름·변신 자산 제작은 3·4단계입니다. 기존 몬스 자산은 밝은 시안 GLB를 재사용하되 원본을 덮어쓰지 않습니다. 렌더 코드는 지원하는 fx 종류의 공통 알고리즘만 가지며 색·강도·시간·문구는 표에서 읽습니다.</p>
<p><strong>simulation_case.csv</strong></p>
<pre><code class="language-text">case_id,profile_id,seed,selection_policy,expected_outcome,expected_leaked_count,min_total_ms,max_total_ms,required_event_set,source_ref,value_kind,status,note
</code></pre>
<p><code>required_event_set</code>은 문서화한 이벤트 묶음 이름이며 임의 코드 실행 문자열이 아닙니다. 기본 <code>showcase_win</code>과 별도 <code>qa_defeat</code>를 분리합니다. 실제 사용자 플레이와 테스트 실패 주입은 다른 저장 공간을 사용합니다.</p>
<h2 id="section-7">7. 웨이브 강화 곡선과 검사기<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h2>
<h3>7-1. 계산과 난도 표시<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<ul>
<li>실제 HP = <code>enemy_type.base_hp × wave.hp_multiplier</code>입니다. 실제 속도 = <code>min(enemy_type.speed_mps × wave.speed_multiplier, enemy_type.max_speed_mps)</code>입니다. 코드 안에서 웨이브 번호에 맞춘 추가 배율을 붙이지 않습니다.</li>
<li>스폰 수 = 해당 wave_spawn 행의 count 합계입니다. 평균 스폰 밀도는 총 스폰 수/스폰 구간, 큰 구름 비중은 large 수/일반 떼 수로 표시합니다. 동시 루트 수는 겹치는 스폰 시간 구간으로 계산합니다.</li>
<li>웨이브 HP 총량은 실제 HP×수량의 합입니다. 속도 상승이 작아도 HP 총량·수량·큰 구름 비중으로 체감 압박이 오르게 합니다. <strong>최대 압박만 높이고 읽을 시간을 빼앗는 방식은 사용하지 않습니다.</strong></li>
<li>보스의 HP는 큰 구름의 HP와 별도입니다. 3웨이브 비교표는 선행 떼 압박과 보스 압박을 나눠 보여 줍니다. 같은 wave에 이미 적용한 HP 배율을 보스에 두 번 적용하지 않습니다.</li>
<li>검사기는 수량·HP 총량이 뒤 웨이브에서 낮아지는지, 속도 상한을 넘는지, 너무 짧은 도착 시간이 생기는지 검사합니다. 난도 값의 증가만으로 실제 승리나 재미를 주장하지 않고 전투 시뮬 결과와 함께 검수합니다.</li>
</ul>

<h2 id="section-8">8. 저장·일회 처리·자동 시뮬<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h2>
<h3>8-1. 저장 계약<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<p>예정 키는 <code>p58:defense-proto:v01</code>로 보드 시안 저장과 분리합니다. 저장 상태는 <code>version</code>, <code>fingerprint</code>, <code>battle_id</code>, <code>revision</code>, <code>phase</code>, <code>wave_id</code>, <code>phase_clock_ms</code>, <code>rng_state</code>, 몬스 슬롯/스킬 단계, 무대 HP, 살아 있는 적의 HP/route/거리/상태 효과, 공격 쿨타임, 비행 중 탄, 우리 편 등장·활성 토큰, 드론 궤도 위상·건물 앵커 참조, 노래 게이지, 스폰 커서, 사용한 기회 토큰, 열린 카드 후보, 웨이브 집계와 결과 토큰을 포함합니다.</p>
<p>일정 간격·상태 전환·스킬 적용·결과 확정 때 체크포인트를 저장합니다. 전투를 재시작해서 보상을 반복 계산하지 않고 마지막 저장 지점에서 같은 seed와 상태로 복원합니다. 저장 간격 이내 표시 연출은 다시 재생될 수 있지만 원본 게임 재화는 연결하지 않습니다. 스킬 선택·결과 확정은 저장 성공 뒤 화면에 확정합니다. 저장 실패·손상 JSON·fingerprint 불일치는 원본 저장을 보존하고 재개를 막으며 오류를 표시합니다. 정상 시작값으로 덮어쓰지 않습니다.</p>
<p>두 탭이 같은 판을 진행하지 않도록 실행 락과 revision을 확인합니다. 락을 못 얻은 탭은 읽기 전용입니다. 결과 리포트는 <code>battle_id + result_token</code>으로 한 번만 확정합니다. 새로운 판을 시작할 때만 스킬 단계를 0으로 초기화하며 같은 판 새로고침에는 현재 단계를 유지합니다.</p>
<h3>8-2. 자동 시뮬과 재현 로그<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<p>GUI 없는 고정 tick 시뮬에서 여러 시드·자동 선택 정책을 돌립니다. 로그는 wave별 <code>spawned</code>, <code>killed</code>, <code>leaked</code>, <code>stage_damage</code>, <code>max_alive</code>, <code>combat_elapsed_ms</code>, <code>choice_elapsed_ms</code>, <code>resolved_elapsed_ms</code>, <code>route_counts</code>, <code>boss_killed</code>, 방어 가동 직전 <code>opening_route_alive_counts</code>, <code>activation_elapsed_ms</code>, 몬스/방공포/드론별 <code>shots</code>, <code>hits</code>, <code>damage</code>, 웨이브별 최대 압박과 해소 시점 및 필수 이벤트 발생 수를 남깁니다. 시뮬 전체 시간과 실제 CPU 실행 시간은 구분합니다.</p>
<p>회귀 검사는 같은 시드의 결과 재현, ×1/×2 동일 결과, 새로고침 후 같은 판 이어가기, 후보 재추첨 방지, 처치/기회/결과 중복 방지, 저장 실패 보호, 마지막 tick의 사망·유출 순서, 모든 몬스 최대 단계, 빈 후보, 짧은 루트, 보스 미퇴치, HP 0, 의도적 패배 프로필을 포함합니다. 표 수치와 테스트용 기대 결과를 같은 상수로 복사해 의미 없는 통과를 만들지 않습니다.</p>

<h3>10-3. 1440·430px·성능<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<p>데스크톱은 상단 웨이브·타이머·퇴치·무대 상태, 중앙 도시, 하단 노래 게이지로 구성합니다. 모바일은 도시를 최대 폭으로 유지하고 카드는 하단 선택 패널에 세로/가로 적응 배치합니다. 긴 문구·카드가 화면 밖으로 밀리지 않아야 합니다. 세 카드 모두 스크롤/포커스로 접근할 수 있고 선택 패널이 무대를 완전히 덮지 않도록 합니다.</p>
<p>여러 루트를 한 화면에서 읽는 전체 보기와 주요 길목 확대 보기를 제공합니다. ×1/x2 상태가 분명해야 하고 기본 진입은 ×1입니다. 빛·꼬리 구름·투사체·피해 숫자는 객체 재사용과 동시 표시 한도를 적용합니다. 여러 적의 몸체는 공유 모델/머티리얼을 재사용합니다. 한도 때문에 <strong>화면 입자</strong>를 줄일 수 있어도 스폰 수·공격·피해를 생략하지 않습니다. 3D 60fps를 보장했다고 표시하지 않고 실제 측정값을 보고합니다.</p>
<h2 id="section-11">11. 현중 확인 항목과 다음 단계 수락 기준<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h2>
<h3>현중 확인 필요<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<ol>
<li>최신 직접 지시의 <strong>함정 제외·건물 주변 넓은 드론 방어·방공포와 몬스 기본 공격</strong>을 기준으로 적용합니다. 예능 방송국 방공포와 연습/녹음 건물 드론을 우선 배치하는 안입니다. 다른 건물로 확대하는 범위만 확인 대상입니다.</li>
<li>시각 목표를 현재 고품질 랩 스튜디오 <strong>city_35</strong>로 연결하고 옛 시안 목표 city_32를 보존하는 안을 확인합니다. 본게임 시설 ID 확정과는 분리합니다.</li>
<li>기본 검수는 <strong>약 5분·느린 이동·다섯 루트 압박 뒤 몬스/방공포/드론 등장과 역전·실제 계산으로 전부 퇴치하고 승리</strong>를 반영합니다. 첫 활성 12초 등 세부 시간은 시안 예시로 2단계에서 검증합니다. 별도 패배 프로필은 연출 검사만 합니다.</li>
<li>카드 후보 부족 시 남은 후보만 표시/모두 최대 시 넘어가는 예외와 자동 검수 5초 힌트 선택은 단이 제안입니다.</li>
</ol>
<p>핵심 체력·공격·시간은 다음 단계의 시안 조정 대상입니다. 본게임 경제·공성전 트리거·멤버 해금·실제 준비 주사위 소비·원정 효과·패배 수익 감소·최종 스킬 이름은 이번 설계로 승인하거나 구현하지 않습니다.</p>
<h3>2단계 · 현중 확인 뒤 수행합니다<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<ul>
<li>이 스키마를 CSV·공유 검사 함수·CLI로 구성하고 값의 근거/시안 표기를 붙입니다.</li>
<li>실제 차도에서 다섯 route와 몬스 슬롯·랩 스튜디오 접근점·broadcast 소켓·드론 건물 앵커·궤도·넓은 방어 범위를 검사합니다. 함정 데이터는 생성하지 않습니다.</li>
<li>약 5분 승리 자동 시뮬과 패배 검수 로그·웨이브 강화 비교표를 작성합니다. 가동 전 다섯 루트 압박, 동시 등장·활성, 몬스/방공포/드론의 실제 공격, 압박 해소를 함께 확인합니다.</li>
<li>중복 처치/선택/리포트·저장 실패·새로고침·×2 결과 일치를 검사합니다.</li>
<li>통과 결과와 표 경로를 공유 보고하고 다시 멈춥니다. 새 그림은 3단계입니다.</li>
</ul>
<h3>3~5단계 계획<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h3>
<p>3단계는 여러 루트·악귀 구름 떼·몬스 등장과 기본 빛 공격·피격·상승 소멸을 만듭니다. 4단계는 마크 변신·드론 출격/건물 주변 순찰·타이머·보스·역전·승패를 만듭니다. 5단계는 기본 약 5분 승리 한 판·별도 패배·새로고침·1440/430px·모든 연출을 연속 캡처/영상으로 검수합니다. 각 단계의 보고 후 현중 확인을 받습니다.</p>
<h2 id="section-12">12. 뺀 것·옮긴 것·보존<span class="origin-tag" style="font-size:.5em;font-weight:500;opacity:.55;margin-left:.4em;white-space:nowrap;vertical-align:middle">(신규)</span></h2>
<ul>
<li>옛 한 갈래 임시 경로는 새 디펜스 설계에서 다섯 루트로 대체하는 안으로 옮깁니다. <code>data/game/map_path.csv</code>와 v15 프리뷰는 삭제하지 않습니다.</li>
<li>옛 야간 시안의 색감은 새 낮 파스텔 기준에서 제외합니다. 기존 스토리보드 PNG·HTML·MD는 보존합니다.</li>
<li>옛 임시 목표 city_32는 새 시각 랩 스튜디오 city_35 제안과 구분해 남깁니다. 원본 siege_config는 고치지 않습니다.</li>
<li>함정은 최신 직접 지시에 따라 이번 프로토타입의 배치·공격 종류·연출·CSV 대상에서 제외합니다. v0.1.3의 함정 기획과 <code>data/game/defense.csv</code> 등 원본 행·모델은 그대로 남깁니다. 감속 역할은 블루 몬스 스킬에 남습니다.</li>
<li>전 건물 대공포·드롭 후보·팬 수에 따른 화력·실제 패배 손해는 확인/후속 목록에 둡니다. 원문을 지우거나 실제 game CSV를 채우지 않습니다.</li>
<li>도시숲 툴의 두 캐릭터는 새 디펜스에서 사용하지 않습니다. 원본 모델은 보존합니다.</li>
<li>이전 보드 시안의 주사위·증설·저장·필러·왼쪽 건물 선택·갤러리·접기 기능, 숲 세부·차도/인도 구분·랩 스튜디오 원본 품질을 유지합니다.</li>
</ul>
