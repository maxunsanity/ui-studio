# P110 · 시즌 경제 참고 · 대표 개발 기획서

**이 문서는** 한 시즌(63일 · 9주) 동안 주사위 · 보드 수익 · 건물 · 아이돌 성장 · 팬 · 데뷔곡 · 페스티벌 · 카드 · 몬스가 어떻게 맞물리는지 한 장으로 잇는 시즌 경제 기획서입니다. 11/01~02에 정한 결정을 1장 그림과 4장 「11/01~02 결정」 표에 모았습니다.

**보는 법** 1장 그림 → 1장 「지켜야 할 선」 → 4장 「11/01~02 결정 — 시즌 경제에 닿는 것」 → 기존 모델 설명(4장 나머지) 순서로 읽습니다. 세부는 각 책갈피와 핵심제안서 링크로 엽니다.

**지금 상태** 현재 개발되지 않음, 진행 중. 기존 경제 · 핵심제안 계산은 개발 중이고, 11/01~02 결정(페스티벌 · 카드 · 몬스 등)은 기획 단계입니다.

## 1. 개요

> **핵심** 순위와 시즌 경제를 만드는 고리는 하나입니다: **아이돌 성장(카드 · 시설 · 레슨) → 데뷔곡 → 보드 도착 피드 → 홍보 · 투표 → 페스티벌 → 보상 → 건물 · 엔터파워 → 다시 성장.** 주사위와 배수는 이 고리를 빨리 돌리고, 몬스는 무대 대결 · 디펜스로 돕습니다. 돈 · 배수 · 몬스 힘은 순위에 직접 닿지 않습니다.

```mermaid
flowchart TB
  Z[주사위 · 배수] --> A[아이돌 성장 · 카드 · 시설 · 레슨]
  M[몬스 · 합성 · 무대 · 디펜스] --> A
  A --> B[데뷔곡 · 도착 피드]
  B --> C[홍보 · 투표 · 페스티벌]
  C --> D[보상 · 건물 · 엔터파워]
  D --> A
```

### 지켜야 할 선 7개 (NEW · 11/01~02)

1. 순위를 만드는 길은 하나: 성장 → 데뷔곡 → 도착 피드 → 홍보 · 투표 → 페스티벌 → 보상 → 다시 성장
2. 돈은 속도 · 꾸밈 · 소장만 — 투표 · 채점 · 순위에는 닿지 않음
3. 배수는 돈 · 성장에만 — 피드 · 팬 · 투표 · 순위 · 증축 비용엔 안 붙음
4. 팬이 생기는 길은 시설 · 능력뿐 — 곡 · 페스티벌은 등급만
5. 시즌은 모두 같은 63일(9주) — 끝나면 건물 단계 · 맵 위 팬 · 건물 악개 · 도착 팬 돈만 초기화하고, 아이돌 · 카드 480장 · 능력 · 엔터파워 · 기획사 스탯 · 총 팬 · 재화는 이월
6. 투표권 · 공유권 · 입장권 · 맞불은 팔지도 주고받지도 않음
7. 서버가 정본 — 여럿이 얽히는 기록은 서버에서


주사위를 굴려 보드에 도착하면 해당 칸의 규칙에 따라 수익과 성장 결과를 계산합니다. 번 돈으로 건물을 증설하면 시설 단계가 바뀌고, 시설 단계는 엔터파워·레슨·수익의 입력이 됩니다. 아이돌 활동에 따른 팬 변화도 경제와 연결해 비교합니다. 하나의 수치가 바뀌면 다른 곳의 진행 속도도 달라지므로 같은 입력·표·정책에서 결과를 살펴봐야 합니다.

```mermaid
flowchart LR
 A[주사위와 배수] --> B[보드 이동과 도착]
 B --> C[수익 계산]
 B --> D[성장 입력]
 C --> E[건설과 시설 단계]
 E --> F[엔터파워와 레슨 조건]
 F --> D
 D --> G[팬 변화]
 G --> C
```

### 콘텐츠 경계

이 문서는 경제 모델이 읽는 입력, 계산 순서, 실험 결과의 해석과 비앙카 장부 산정 항목 항목을 설명합니다. 플레이어가 실제로 시설을 고르고 구매하는 조작은 [건물 성장](../콘텐츠별_v03/건물성장_기획서.html), 현재 같은 멤버의 성장과 단계는 [아이돌 성장](../콘텐츠별_v03/아이돌능력_기획서.html), 시험 화면 사용은 [발란스 시뮬레이터](../콘텐츠별_v03/발란스시뮬레이터_기획서.html)가 맡습니다.

### 서로 다른 시험의 역할

| 경로 | 무엇을 살펴보나요 | 해석할 때의 경계 |
|---|---|---|
| 발란스 시뮬레이터 | 주사위 시나리오, 하루 진행, 시설·팬·성장·콘텐츠 시험 | 시험 화면의 정책과 표를 확인; 계정 운영 결과가 아님 |
| 발란스 툴·기존 시즌 경제 | 표와 60일 경제, 충전·배수·돈·건설의 비교 | 설정과 시드가 있는 경제 실험; 결과는 해당 실행 조건의 관측값 |
| 핵심제안 계산 모델 | 보드·시설·팬·도시 방문을 굴림 단위로 계산 | 시간 대신 굴림 예산을 사용하고 이전 보드·성장 가정이 남은 참고 모델 |
| 공용 시뮬레이터의 성장·건설 | 같은 팀의 성장과 시설 거래·저장을 검토 | 시험 세션과 실제 운영 계정은 별도 |

같은 이름의 ‘시즌’이나 ‘능력’이 있어도 입력과 단위가 다를 수 있습니다. 한 경로의 결과를 다른 경로에 자동으로 옮겨 쓰거나, 화면에 없는 값을 확정 발란스로 바꾸지 않습니다.

## 3. 구동 방법·시뮬레이션

화면 흐름: 입력 시나리오와 표 확인 → 시험 실행 → 굴림·시설·팬·성장 결과 → 같은 조건의 비교 · 이번 문서 수정의 새 실행·캡처 미실시 · 이식 비교는 S02의 기존 경제 자료를 참고합니다.

[눌러서 발란스 시뮬레이터 실행](../../../../idle-sim.html) · [눌러서 발란스 툴 실행](../../../../balance-tool.html) · [눌러서 기존 핵심제안 결과 보기](core_balance_v01.html)

1. 발란스 시뮬레이터에서 현재 팀과 일차, 주사위 입력 시나리오를 확인합니다. 무료·평균·헤비는 같은 지급 기록이 아니라 서로 다른 시험 입력입니다.
2. 배수와 시험 조건을 확인하고 실행합니다. 진행 중 입력을 바꾸면 새 지급량은 다음 날부터 적용됩니다. 이미 지급한 오늘의 값과 구분합니다.
3. 굴림·시설·팬·성장·카드 등 화면의 결과를 읽고, 같은 표와 정책·진행 조건에서 비교합니다. 현재 시험 결과와 본게임 계정 지급은 별개입니다.
4. 발란스 툴은 주제별 표와 기존 경제 실험을 살펴보는 곳입니다. 화면의 시험 조작이 원본 CSV를 고치는 행동인지, 시험 입력만 바꾸는 행동인지 각 화면의 안내를 확인합니다.
5. 핵심제안 결과 페이지는 별도 굴림 단위 계산이 만든 결과 자료입니다. 생성 당시 표·시드·정책과 현행 표가 같은지 확인하기 전에는 지금 실행한 결과로 취급하지 않습니다.
   - 11/17 현중(질문 12): 핵심제안 계산 스크립트(`scripts/core-proposal-sim.mjs`)도 발란스 툴과 같은 재능 표(`idol_ability_talent` · 단계 문턱 · 단계 성장 3표 · `idol_growth_stat`)를 붙입니다. 판마다 그 판 시드로 멤버 재능을 만들고(툴과 같은 생성기), 재능이 없으면 능력이 오르지 않던 문제(능력 · 팬덤 0)를 없앱니다. 새 결과는 작업 폴더에만 내고, 결과 페이지 원본(`core_sim_v01.json`)은 현중이 숫자를 본 뒤 승인하면 바꿉니다.

도구를 열거나 실행하는 동작은 사용자가 직접 선택합니다. 표를 고치거나 결과 파일을 다시 만드는 명령은 이 문서를 읽는 것만으로 실행되지 않습니다.

```mermaid
flowchart TD
 A[시나리오와 표 판본 확인] --> B[시험 정책과 시드 확인]
 B --> C[선택한 모델로 실행]
 C --> D[굴림 시설 팬 수익 결과]
 D --> E[같은 조건의 다른 결과와 비교]
 E --> F[차이의 입력과 모델 확인]
 F --> G[발란스 검토]
```

## 4. 상세 기획

### 한 판 순서

| 점검 | 내용 |
|---|---|
| 시작·종료 | 시험에 필요한 표와 입력을 읽고, 선택한 모델의 기간 또는 굴림 예산이 끝날 때 결과를 확인합니다. |
| 입력·출력 | 주사위 입력·배수·시드·보드·건물·성장·팬 표를 사용해 수익·시설·성장·팬·진행 기록을 만듭니다. |
| 상태와 전이 | 입력 준비 → 굴림·도착 → 수익·성장 → 비용을 내는 증설 또는 다른 활동 → 다음 굴림·결과입니다. |
| 판정 | 도착 칸과 해당 모델의 판정·배수·보상 설정을 따릅니다. 모델마다 같은 항목의 계산 범위가 다릅니다. |
| 오류·예외 | 필수 표·숫자 칸이 없으면 대기 또는 오류를 보여 줍니다. 선택적 연결이 빠지면 해당 기능의 범위와 중단 여부를 별도로 확인합니다. |

### 주사위 공급과 배수

하루에 들어오는 주사위와 한 번에 거는 배수는 다른 값입니다. 설계 조건은 보유량·엔터파워 문턱·해당 일차 상한이며 `maxOpenMultOn` helper가 이 셋을 함께 계산합니다. 현재 수동 성장 허브의 `growthEcon.openMult`·`roll`은 보유량·엔터파워만 검사하고 일차 상한을 적용하지 않습니다. 현재 표는 배수별 최소 보유량을 두고, 1일차·2일차의 상한을 별도로 둡니다. 주사위 공급 총량이나 배수 선택 조건을 문서에서 새로 정하지 않습니다.

| 입력·설정 | 표에서 읽는 내용 | 구분 |
|---|---|---|
| 무료 하루 입력 | 통째 800 지급은 없앰(`free-dice-daily-config` 통째 지급 0 · `dice_input_scenario.free_dice_per_day`는 이전 시험 입력) | 무료는 실제 지급만 셈 = 모든 무료 일일 보상 합(60일 평균 835.6 · 기준 800~900) |
| 평균·헤비 입력 | 구매액·가격과 무료분을 조합한 표의 시나리오 | 현재 세팅값·재결정 재료; 운영 비앙카 장부 산정 항목 |
| 배수 목록과 보유 문턱 | `item_master_dice_mult.mult`, `min_dice` | 현재 표의 현재 세팅값 |
| 배수 해금·일차 상한 | `dice_mult_unlock_rule`, `dice_mult_day_cap` | 엔터파워 문턱과 일차 상한 표; 상한 helper와 현재 수동 허브 미적용을 구분, 비앙카 장부 산정 항목 |
| 자동 충전 | `economy_config`·`dice_cap_level`·`enter_power_level`(auto_charge) | 시작량·주기, 자동 충전 상한, 엔터 파워 단계별 하루 충전량(60 · 90 · 120 · 현재 세팅값); 모든 지급을 자르는 한도와 구분 |

현재 `dice_cap_level`에는 눈금 1에 상한 40과 50인 행이 함께 있고, 경제 코드의 현재 눈금 이하 마지막 해당 행은 50입니다. 엔터파워 모델을 읽지 못하면 첫 단계 30을 사용합니다. 이것은 현재 표와 코드의 시험 동작이며 최종 지급 정책을 새로 정한 뜻은 아닙니다.

```mermaid
flowchart LR
 A[하루 주사위 입력] --> B[현재 보유량]
 C[시설 단계와 엔터파워] --> D[배수 문턱]
 E[현재 일차] --> F[일차별 상한]
 B --> G[배수 선택 가능 여부]
 D --> G
 F --> G
 G --> H[굴림당 선택 배수 소비]
```

### 돈 단위와 도착 수익

기존 경제와 핵심제안 모델은 각각 **S**라는 시설 비용 기준을 사용해 비율을 돈으로 바꿉니다. 그러나 각 모델이 읽는 시설 행·비용·보드 연결과 비용 배율이 같다는 보장은 없습니다. S를 비교할 때는 어느 모델의 표와 계산으로 만든 값인지 먼저 확인합니다. `economy_config`의 시설 단계별 수익 시안과 현재 시설 단계 표의 수익 열도 같은 이름만으로 혼합하지 않습니다.

핵심제안 모델은 칸의 시설·단계, `board_tile_reward`의 수익 종류와 판정·배수 적용 여부, 팬 곡선과 시설 정보를 사용해 수익을 계산합니다. 별도 경제 엔진도 도착 종류·시설 상태·판정에 따라 수익과 장부를 처리합니다. 팬 항과 이벤트 보정 등은 각 계산 경로의 계약을 따르므로, 한 줄의 ‘모든 수익 × 배수’로 뭉치지 않습니다.

도착 필러의 3D 룰렛은 별도의 **표시 전용** 결과입니다. 그 화면에 표시한 코인은 경제 수익의 실제 지급 증거가 아닙니다. 필러 확률과 경제 판정의 가중치도 별개입니다.

```mermaid
flowchart TD
 A[칸 ID와 시설 단계] --> C[선택한 경제 모델]
 B[판정과 배수 적용 설정] --> C
 D[해당 모델의 팬과 비용 기준] --> C
 C --> E[수익과 장부 결과]
 F[도착 필러 예시 판정] --> G[표시 전용 보상]
```

### 건물 비용과 엔터파워

현재 건설 거래는 시설 ID와 다음 단계의 `building_master_level.cost`를 읽어 견적을 만들고, 돈과 저장 상태를 확인해 구매합니다. 여러 단계 구매는 각 단계 비용을 합친 하나의 거래입니다. 시설 선택이나 필러의 건물 연출만으로 자동 증설되지는 않습니다. 경제 실험의 자동 증설 정책은 실제 건설 화면의 사용자 선택과 구분합니다.

핵심제안 모델은 `facility_growth_level`의 비용·팬·능력·기본 수익 열과 합쳐진 `building_master_level`을 함께 읽습니다. 능력 시설의 기본 레슨 배수는 합쳐진 표를 사용하고, 옛 `lesson_mult`를 쓰는 선택은 비교 경로입니다. 같은 표 이름이나 ‘비용’이라는 말만으로 모든 열이 같은 정본에서 온다고 단정하지 않습니다. 비용·수익·레슨 효과는 비앙카 장부 산정 항목입니다.

엔터파워는 같은 시설에 연결된 여러 칸이나 세 동의 그림을 중복하지 않고 시설별 전체 단계를 합해 눈금으로 변환합니다. 배수·자동 충전 상한·캐스팅권의 문턱은 관련 표에서 각각 읽습니다. 자세한 현행 값과 예외는 [P172](../콘텐츠별_v03/엔터파워_기획서.html)를 따릅니다.

```mermaid
flowchart LR
 A[시설 현재 단계] --> B[다음 단계 비용 확인]
 C[현재 보유 돈] --> D[구매 가능 여부]
 B --> D
 D --> E[구매와 저장]
 E --> F[시설별 단계 합]
 F --> G[엔터파워 눈금과 문턱]
 E --> H[해당 모델의 레슨과 수익 입력]
```

### 아이돌 성장과 팬

현재 아이돌 성장은 같은 멤버의 18세부 능력·재능·학습과 단계표를 기준으로 봅니다. 여섯 대표 축은 세부 능력의 평균이며 언어는 별도 학습값입니다. 한 시험의 옛 축 이름이나 시험 합류 보정을 현재 성장의 자동 승인값으로 옮기지 않습니다.

핵심제안의 `lessonArrival`은 해당 칸의 성장 대상·기본량·레슨 배수를 사용합니다. 코드 주석은 이 경로에서 칸 무게를 아직 곱하지 않는다고 설명합니다. 같은 프로젝트의 다른 성장 화면에서 주사위 배수나 아이템이 적용되는 방법과 같다고 가정하지 않고 성장 출처별 설정을 확인합니다.

팬 수익 시험은 팬층·시설·칸별 입력과 팬 곡선을 사용합니다. 일부 마일스톤·카드 연결은 선택적으로 읽는 표가 없으면 꺼질 수 있습니다. **선택적 연결이 꺼진 것**과 0을 지급하도록 결정된 것은 다릅니다. 팬층 이동량·수익·마일스톤 지급량은 비앙카 장부 산정 항목입니다.

```mermaid
flowchart TD
```

### 도시 방문과 이전 보드 가정

핵심제안 모델은 지역 열림과 입장권을 시험하고 방문 굴림·수익·종료 보너스를 계산합니다. 지역·조건·수익은 시험 자료이며 현재의 별도 도시 방문 플레이 화면·계정 복원까지 완성된 뜻은 아닙니다. 현지 6축 보상을 세부 능력으로 변환할 기준이 없어 해당 증가는 대기로 남깁니다.

현재 핵심제안 `sim.ts`는 보드 표의 `group=corner_jail`을 읽어 그 자리에서 한 턴 쉬고, 도시 입장 기회는 `core_proposal_config.city_ticket_tile_id`를 읽습니다. 현재 그 설정값은 `board_tile_36`이며 31→11 순간이동이 소스에 고정돼 있지는 않습니다. 다만 한 턴 쉬는 굴림 모델과 실제 허브의 감옥 상태·더블 탈출·벌금 경로는 같지 않습니다. 전체 현행 보드 재현으로 표현하지 않고 남은 계산 차이의 비교는 작업 전으로 남깁니다.

### 목표·결과를 읽는 방법

`core_proposal_balance_target.csv`는 데뷔·성장에 닿는 굴림, 시설 평균 단계, 수익 구성 등 목표 범위의 시안을 담습니다. 핵심제안 실행은 여러 시드의 중앙값과 범위로 목표 통과 여부를 표시합니다. 이 PASS·FAIL은 **해당 시뮬레이션 정책과 목표표의 비교**이며 사용자 승인이나 실제 63일 플레이 통과가 아닙니다.

기존 시안은 기본 정책과 배수 변경, 도시 방문 제외를 비교합니다. 비교할 때는 시드 수·입력 주사위·배수·건설 정책·표 판본·계산 모델을 함께 기록합니다. 값이 바뀌거나 자료가 빠졌다면 과거 생성 결과를 현재 결과로 단정하지 않습니다.

### 필요 시스템

주사위 입력과 경제 표 로더, 보드·시설·성장·팬 계산, 시뮬레이션 정책·시드·결과 기록, 입력 결측과 선택적 기능의 상태 표시가 필요합니다. 본게임의 계정 지급·서버 저장·각 콘텐츠 정산은 이 참고 모델과 별도의 책임입니다.

### 수락 기준

- 시나리오·시드·표·정책과 모델을 함께 보여 주고, 기존 결과와 새 실행 결과를 구분합니다.
- S·시설 비용·주사위·성장·팬의 단위와 해당 모델의 입력을 확인해 서로 다른 계산을 섞지 않습니다.
- 필수 값 누락과 선택적 연결 미공급을 구분하고 임의 수치를 지급하지 않습니다.
- 현재 보드와 다른 시험 가정, 화면 시험과 본게임 실제 지급의 차이를 명확히 설명합니다.
