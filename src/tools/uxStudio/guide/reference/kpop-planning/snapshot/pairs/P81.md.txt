# P81 · 건설 · 증설

**이 문서는** 플레이어가 도시 지도에서 시설을 고르고, 가진 돈을 써서 그 시설을 한 단계 또는 가능한 만큼 증설하는 과정을 설명합니다.

**보는 법** 목차 → 1~7장 순서로 읽습니다. 시설 성장·비용·효과는 [P106](건물성장_기획서.html), 대전은 [P98](캐스팅권대전_기획서.html)과 함께 봅니다. 같이 여는 도구: [건설 시뮬레이터](../../../../game-simulator.html?module=simulator_module_building).

**지금 상태** 개발됨(시설 선택·견적·거래·저장 코드의 부분 구현 기준). 가격이 미공급된 단계는 구매 대기이며 비용·효과는 발란스 대기입니다. 수리·방어 전환 연결은 작업 전이고, 이번 실제 구동·거래·저장은 미검수입니다.

## 1. 개요

출처: (합침) [건물 성장 제안서](../../../../proposal-concept/growth.html), 현재 건설 화면과 보드·시설 표.

건설은 말이 해당 칸에 도착할 때만 열리는 행동이 아닙니다. 공통 하단의 「건설」에서 9시설을 지도나 목록으로 고르고 비용을 확인한 뒤 구매합니다. 시설 선택은 돈을 쓰지 않으며 실제 구매와 보드 도착의 레슨·수익은 서로 다른 행동입니다.

```mermaid
flowchart LR
 A[공통 하단 건설] --> B[도시 지도]
 B --> C[시설 또는 빈 부지 선택]
 C --> D[견적 확인]
 D --> E[증설 구매]
 E --> F[저장 후 조립]
```

시설의 세 동이 자라는 규칙과 효과 표는 [P106 건물 성장](건물성장_기획서.html)이 맡고, 이 문서는 지도 선택·거래 조작과 보드의 연결 위치를 설명합니다.

## 3. 구동 방법·시뮬레이션

화면 흐름: 다른 공용 시뮬레이터의 하단 건설 → 시설 선택 → 견적·구매 → 조립 → 도시. 이전 화면 확인은 7장의 보고를 참고합니다. 이번 문서 수정에서 새 실행·캡처는 하지 않았습니다.

### [▶ 건설 시뮬레이터 열기](../../../../game-simulator.html?module=simulator_module_building)

1. 3D 도시 지도에서 건물이나 부지를 누릅니다. 지도 우상단 「시설 모두 보기」로 폰 안의 2열 목록을 열어 같은 시설을 선택할 수도 있습니다.
2. 선택 상세의 현재→다음 단계, 비용과 예상 잔액을 확인합니다. 한 단계와 최대 증설은 각각의 견적이 표시됩니다.
3. 「한 단계 증설」 또는 「최대 증설」을 누르면 표시된 견적으로 구매를 시도합니다. 성공하면 조립 장면을 보여 주고 도시로 돌아옵니다.
4. 같은 진행에서 새로고침하거나 다른 메뉴에서 돌아오면 저장된 단계와 잔액을 읽습니다. 연결이 준비되지 않았거나 돈이 부족하면 구매할 수 없습니다.

```mermaid
flowchart LR
 A[지도에서 직접 선택] --> C[같은 시설 ID]
 B[시설 모두 보기] --> C
 C --> D[현재 단계와 비용]
 D --> E[한 단계 증설]
 D --> F[최대 증설]
 E --> G[거래와 저장]
 F --> G
```

## 4. 상세 기획

### 한 판 순서

| 점검 | 내용 |
|---|---|
| 시작·종료 | 공통 하단 건설에서 열고 시설을 고르거나 다른 메뉴로 돌아갑니다. |
| 입력·출력 | 시설 선택과 구매 버튼을 받아 견적·잔액·시설 단계를 표시합니다. 성공하면 거래 기록과 단계가 저장됩니다. |
| 상태와 전이 | 선택 전 → 선택·견적 → 거래 중 → 성공 연출 또는 오류 안내입니다. |
| 판정 | 구매 전 지갑·단계·비용·저장 버전·상한을 확인합니다. |
| 오류·예외 | 돈 부족·연결 대기·오래된 견적은 구매하지 않습니다. 같은 요청의 중복 차감은 막습니다. |
| 저장·복원 | 같은 진행의 지갑과 시설·성장 기록을 사용합니다. 저장 오류 시 되돌리며 복구 불가 오류는 따로 알립니다. |
| 다른 모듈 | 시설 선택은 대전 시작이 아니며, 건설 구매는 도착 레슨·수익·팬 이동을 다시 실행하지 않습니다. |

### 보드와 시설 위치 · 현재 표

보드는 40칸이고 시설은 길 사이의 부지에 표시됩니다. `board_tile.csv`에는 24개 건물 칸과 사옥 출발 칸이 시설에 연결됩니다. 같은 시설에 연결된 칸이 여러 개여도 구매하는 대상은 시설 하나입니다.

| 시설 | 연결 칸 |
|---|---|
| 사옥 | 1 |
| 아카데미 | 2 · 37 · 39 |
| 댄스 연습실 | 4 · 24 · 25 |
| 보컬 녹음실 | 7 · 9 · 22 |
| 프로듀싱 스튜디오 | 10 · 13 · 29 |
| 팬샵 | 12 · 14 · 15 |
| 뷰티 스튜디오 | 17 · 19 · 20 |
| 예능 방송국 | 27 · 28 · 30 |
| 콘서트장 | 32 · 33 · 35 |

지도 데이터는 콘서트장의 짧은 이름을 「랩」으로도 표시합니다. 시설 ID는 `facility_concert`입니다. 6·16·26·36은 [쟁탈](캐스팅권대전_기획서.html), 11·21은 숙소, 31은 감옥 도착 칸입니다. 자세한 칸 규칙은 [보드 기본 구성](../작성기준_v02/보드기본구성_샘플.html)을 봅니다.

```mermaid
flowchart LR
 A[시설에 연결된 보드 칸] --> B[보드 도착 처리]
 C[하단 건설 메뉴] --> D[시설 선택]
 D --> E[증설 거래]
 E --> F[공통 시설 단계]
 F --> G[도시 외관]
 F --> H[성장과 경제에서 단계 읽기]
```

### 구매와 저장 · 현재 실행

견적은 현재 단계에서 목표 단계까지의 비용을 더하며 선택만으로는 지갑을 바꾸지 않습니다. 거래는 예상 단계와 저장 버전을 확인합니다. 요청 ID가 같으면 기존 결과를 돌려주고, 이전 견적이나 돈 부족은 거절합니다. 여러 단계를 구매할 때는 한 거래로 저장합니다. 조립은 거래가 성공해 저장된 뒤의 표시이며 취소하거나 나가는 행동이 구매를 다시 실행하지 않습니다.

### 필요 시스템

지도와 시설 ID, 단계별 비용, 공통 지갑, 시설·성장 저장, 조립 자산이 필요합니다. 같은 지도 선택을 사용하는 대전의 전투와 보상 처리는 [P98](캐스팅권대전_기획서.html)이 담당합니다. 시설 수리는 파손 읽기와 복구 거래가 건설에 연결되지 않아 작업 전입니다.

### 화면·연출 목록

| 화면·연출 | 역할 |
|---|---|
| 도시 지도 | 9시설의 이름·현재 단계·선택 상태 표시 |
| 시설 모두 보기 | 폰 안 2열 시트에서 시설 선택 |
| 선택 상세 | 현재→다음 단계·비용·예상 잔액 표시 |
| 증설 버튼 | 한 단계 또는 지갑으로 가능한 최대 단계 구매 |
| 조립 장면 | 저장 성공 뒤 해당 시설의 조립 표시 |
| 오른쪽 개발 정보 | 단계별 견적, 출처와 저장 상태 확인 |

### 남은 결정

시설별 증설비와 단계별 효과는 **발란스 대기**입니다. 수리와 방어 전환의 본게임 연결은 작업 전입니다.

## 7. 개발 진행·검수

아래 실구매·새로고침·메뉴 왕복·연출 관측은 짝 로그에 보존된 10/29 작업 기록의 범위입니다. 이번에는 표·소스만 대조했으며 실제 거래·저장·화면을 다시 검수하지 않았습니다.

| 요소 | 상태 | 확인 범위·다음 작업 |
|---|---|---|
| 지도·목록 선택과 한 단계·최대 구매 | 개발 중 | 실구매·새로고침·일부 메뉴 왕복 확인 |
| 조립 연출 | 개발 중 | 구매 후 연출과 재로드 확인 |
| 수리·방어 전환 본게임 연결 | 기획 중 | 작업 전. 소유 파손·수리 거래와 연결 검수 필요 |
| 비용·효과 | 기획 중 | 실행값은 임시, 발란스 대기 |

### 수락 기준

- 지도와 목록의 선택이 같은 시설을 가리키고 선택만으로 돈이 차감되지 않는지 확인합니다.
- 표시 견적과 실제 구매·저장·재진입 결과가 맞는지, 돈 부족과 오래된 견적에서 거래하지 않는지 확인합니다.
- 실화면과 자동 시험의 확인 범위를 구분하고 수리·방어 전환을 미리 완료로 표시하지 않습니다.
