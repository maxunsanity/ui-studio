## 1. 개요

출처: (합침) [건물 성장 제안서](../../../../proposal-concept/growth.html), 건설 시뮬레이터와 시설·단계 표.

9시설은 사옥, 보컬 녹음실, 댄스 연습실, 콘서트장, 뷰티 스튜디오, 예능 방송국, 프로듀싱 스튜디오, 팬샵, 아카데미입니다. 각 시설은 전체 0~30단계로 표현하고, 본관과 부속 A·B의 세 동이 차례로 자랍니다. 플레이어는 보드 위치와 관계없이 건설 화면에서 시설을 고르고 돈으로 증설합니다.

```mermaid
flowchart LR
 A[보드 활동] --> B[돈과 시설 상태]
 B --> C[시설 선택과 증설]
 C --> D[시설 단계 저장]
 D --> E[도시 외관]
 D --> F[성장과 경제에서 단계 읽기]
```

시설 단계와 동의 단계는 다릅니다. 전체 단계가 오를 때 본관 → A → B 순서로 한 동씩 성장합니다. 0단계는 빈 부지이고 30단계는 세 동이 각각 10단계인 상태입니다. 비용과 효과량은 현재 실행에 임시값이 들어 있지만 최종 수치는 **발란스 대기**입니다.

## 3. 구동 방법·시뮬레이션

화면 흐름: 공용 하단 건설 → 도시 지도와 선택 상세 → 견적 확인·구매 → 조립 연출 → 저장된 도시. 이전 화면 확인은 아래 진행표의 연결 보고에서 볼 수 있습니다. 이번 문서 수정에서 새 실행·캡처는 하지 않았습니다.

### [▶ 건설 시뮬레이터 열기](../../../../game-simulator.html?module=simulator_module_building)

1. 지도에서 건물이나 빈 부지를 누르거나 우상단 「시설 모두 보기」의 2열 목록에서 시설을 고릅니다. 선택만으로 돈을 쓰지 않습니다.
2. 현재 단계와 다음 단계, 비용과 예상 잔액을 확인합니다. 「한 단계 증설」은 한 단계 비용을, 「최대 증설」은 가능한 단계 수와 총비용을 보여 줍니다.
3. 원하는 버튼을 누르면 거래를 시도합니다. 성공 후 조립 장면을 보여 주고 지도에 돌아옵니다. 오른쪽 정보는 출처·견적·저장 상태를 확인하는 개발용 영역입니다.
4. 같은 진행으로 다시 열 때 저장된 단계와 잔액을 읽습니다. 지갑 또는 성장 기록을 안전하게 연결하지 못하면 구매를 잠급니다.

```mermaid
flowchart LR
 A[지도 또는 시설 목록] --> B[시설 선택]
 B --> C[단계와 견적 확인]
 C --> D[한 단계 또는 최대 증설]
 D --> E[저장 성공]
 E --> F[조립 연출과 지도 복귀]
```

## 4. 상세 기획

### 한 판 순서

| 점검 | 내용 |
|---|---|
| 시작·종료 | 공용 건설 메뉴에서 들어와 지도 선택과 증설을 반복하고 다른 메뉴로 이동합니다. |
| 입력·출력 | 시설 ID와 구매 수량을 받아 견적을 계산하고, 성공하면 단계·잔액·거래 기록을 저장합니다. |
| 상태와 전이 | 선택 → 견적 → 거래 중 → 저장 결과 → 연출입니다. 선택만으로 거래하지 않습니다. |
| 판정 | 현재 단계·잔액·비용과 저장 버전을 확인합니다. 돈 부족·상한·연결 대기는 구매하지 않습니다. |
| 오류·예외 | 오래된 견적은 거절하고 다시 확인합니다. 같은 요청의 재전송은 기존 영수증을 사용합니다. |
| 저장·복원 | 시설 단계와 지갑·성장 기록을 같은 진행에서 읽습니다. 저장 중 오류는 되돌리며 복구 실패는 별도 오류입니다. |
| 다른 모듈 | 보드 도착을 다시 만들지 않으며 도착 레슨·수익이나 팬 이동을 중복 실행하지 않습니다. |

### 시설과 세 동의 성장 · 현재 실행

| 전체 단계 | 본관 | 부속 A | 부속 B | 뜻 |
|---|---:|---:|---:|---|
| 0 | 0 | 0 | 0 | 빈 부지 |
| 1 | 1 | 0 | 0 | 본관 등장 |
| 2 | 1 | 1 | 0 | A 등장 |
| 3 | 1 | 1 | 1 | B 등장 |
| 4 | 2 | 1 | 1 | 본관부터 순환 성장 |
| 6 | 2 | 2 | 2 | 세 동이 2단계 |
| 30 | 10 | 10 | 10 | 세 동의 최대 외관 단계 |

```mermaid
flowchart LR
 A[빈 부지] --> B[본관 등장]
 B --> C[부속 A 등장]
 C --> D[부속 B 등장]
 D --> E[본관 성장]
 E --> F[부속 A 성장]
 F --> G[부속 B 성장]
 G --> E
```

### 비용·성장·수익의 경계 · 발란스 대기

건설 거래의 견적은 `building_master_level.csv`의 시설·단계별 비용을 읽어 목표 단계까지 합칩니다. 예를 들어 이전 화면 보고에서 보컬 녹음실 1→2단계 거래는 3,000이었지만 이는 **당시 실행값**이며 최종 가격이 아닙니다. 표의 비용과 효과는 발란스 대기입니다.

공통 핵심제안 모델의 기본 레슨 배수는 능력 시설에 대해 `building_master_level.csv`의 `effect_lesson_mult`를 읽고, legacy 선택은 `facility_growth_level.csv`의 `lesson_mult` 비교 경로입니다. 다만 현재 아이돌 성장 허브는 `buildBook`과 `lessonMultFor`를 통해 아직 `facility_growth_level.csv.lesson_mult`를 읽습니다. 지도 어댑터는 같은 시설 단계를 연결하며 배수 원천을 master로 교체하지 않습니다. 문서의 기본 계약과 현재 허브 연결 차이를 구분하고, 두 배수 중 하나를 새 최종값으로 결정하지 않습니다. 보드 경제의 시설별 수익 열과 도착 화면의 임시 표시 보상도 역할이 다릅니다. 도착 필러 설정은 표시 보상을 실제 보유량에 더하지 않는 시안이라고 명시합니다. 최종 수익·레슨량·확률은 발란스 대기입니다.

```mermaid
flowchart LR
 A[시설 단계] --> B[레슨 배수 표]
 A --> C[보드 보상 표]
 B --> D[아이돌 성장 계산]
 C --> E[보드 경제 계산]
 F[도착 필러 표시] --> G[임시 표시 보상]
```

### 필요 시스템

건설은 같은 진행의 시설 저장과 돈 지갑, 지도 시설 ID, 단계별 비용과 조립 자산이 필요합니다. 여러 단계 구매는 각 단계의 비용을 합쳐 한 거래로 처리합니다. 수리는 비용 계산 함수가 있으나 소유 시설의 파손 읽기·구매 버튼·차감·복구 저장이 연결되지 않아 **작업 전**입니다. 건설 경로의 시즌 처리 연결도 작업 전입니다. 별도 공통 경제의 `startNewSeason` 함수나 허브의 새 테스트 초기화를 건설의 시즌 연결 완료로 읽지 않습니다.

### 남은 결정

증설 비용, 레슨·수익 효과, 수리비 및 단계별 수치: 임시(나중에 결정). 보드 건물 칸 25칸(출발 1 사옥 포함)은 모두 도착 돈을 주며 차등은 기타 0.470 < 방송국 0.988 < 콘서트홀 1.034(총량 유지 · `building_master_level.csv` effect_income_pct에 곱함) × 판정 배율 × 주사위 배수. 건물 도착 즉시 팬도 켜고(fan_open_choice.csv building_arrival_fan_factor = on), 도착 → 능력 → 팬 증가를 그 건물 아이돌 NPC 데이터로 기록합니다. NPC는 아이돌마다 따로 세고, 팬은 멤버별로 기록하고 건물 합계는 멤버 합으로 계산(현중 11/04 14:53 결정 · 14:55 확정 · 건물 한 번 기록안은 쓰지 않음)합니다(NPC 1명 = 팬 5,000 · 상한 100 · 임시(나중에 결정)). 건물 위에 아이돌 NPC를 직접 그리지 않고, 보드(발란스 시뮬·현황판)의 각 건물 위 말풍선에 그 건물 팬 수(멤버별 기록의 합)를 표시하며, 말풍선을 누르면 멤버별 팬 수가 나옵니다(현중 11/04 15:08). 10단계 보너스 bonus_money_pct 0.0046(10·20·30단계)·level_money_pct는 계산값으로 켭니다. 수리와 시즌 리셋의 실제 연결은 작업 전입니다.
