## 1. 사용자 동선과 적용 범위

모든 게임 시뮬레이터의 **모바일 폰 내부**에서 같은 캐릭터 정보창을 사용합니다. 컴퓨터에서 실행해도 폰 바깥의 오른쪽 자료 패널로 열리지 않습니다.

**모바일 상단 팀·멤버 카드 → 팀/선택 멤버 정보 → 능력 선택 → 세부 확인 → 닫기** 순서입니다. 상단 정보 카드는 팀 한 자리와 현재 합류한 멤버만 표시합니다. 오디션에 아직 합류한 멤버가 없으면 팀 카드와 빈 상태를 보여주며, 다른 시험팀을 대신 표시하지 않습니다.

창은 폰 내부를 덮습니다. 제목·닫기·팀/개별 선택을 고정하고 본문 한 곳만 세로 스크롤합니다. 닫으면 기존 카드·덱·페이지·게임 진행 위치와 초점을 보존합니다. Escape는 정보창만 닫으며 폰의 팝업 보기를 유지합니다.

| 실제 모바일 화면 | 적용 경로 |
|---|---|
| 공통 기본 폰 | 카드·상점·미션·모험·이벤트·보드·건설·몬스·디펜스·보조 성장 등15개 등록 ID |
| 오디션 별도 폰 | 현재 오디션 run의 실제 합류 정보 |
| 쟁탈전 별도 폰 | 시설 선택·전투·보상 화면의 같은 정보창 |
| 내부 페이지의 실제 폰 | 로비·아이돌 성장·도착 필러·쟁탈 칸4개 등록 ID |

등록은 총21ID이며 쟁탈전의 기존두ID와 공유 instance도 포함합니다. 게임 실행기의 메뉴 수와 등록 ID 수는 구분합니다. 발란스 P171은 구성 참고이며 이번에 발란스 앱 자체를 고치지 않았습니다.

## 2. 개별·팀 배치

| 개별 보기 | 팀 보기 |
|---|---|
| 작은 초상·이름·성장 단계·개인18세부 합 | 팀 이름·결성 상태·합류 인원 |
| 실제 합류 멤버 선택 | 실제 합류 멤버 확인 |
| 개인6축을2열3행으로 표시 | 팀전용6축을2열3행으로 표시 |
| 현재값·재능·현재 단계 한도·흡수율 | 현재 팀 능력과 개인 기여·함께 성장 |
| 선택한 축의 현재3세부·세부별 기준 성장량 | 선택한 팀 축의 설명·기여 근거 |
| 아카데미5종·성장 설명은 접어서 확인 | 팀 능력 근거는 접어서 확인 |

개인6축은 보컬·댄스·랩·비주얼·끼·예능감·프로듀싱입니다(끼·예능감은 한 축입니다). 팀6축은 호흡·포메이션·화음·콘셉트 조화·케미·단합도입니다. 개인6축 평균·개인18세부 합·팀6축·복합 등급을 같은 값으로 취급하지 않습니다.

현재·재능·한도·합계 등은 **소수점 최대 한 자리**로 표시하고 원본 정밀도를 저장·변경하지 않습니다. 실제0은0이며 누락값은 — 또는 연결 대기입니다. 작은 모달에서는 여백·초상 크기를 줄이고 글자를 과도하게 줄이지 않습니다. 6축과 선택3세부를 우선 표시하며 긴 안내·펼친 내용에는 본문 스크롤을 허용합니다.

## 2-1. 개별 멤버의 아이돌 서사

개별 정보의 **이름 옆 아이돌 서사 → 이야기 선택 → 능력 보기**로 같은 창 안에서 이동합니다. 팀/개별과 멤버 선택은 유지하며 별도 팝업을 겹치지 않습니다. 기본 능력6축·흡수율 화면의 높이는 늘리지 않습니다.

서사에서는 기존 공개 배경(가족·고향·동기·약점·경력·특기), 오디션 소개와 원문 대사를 읽습니다. 긴 이야기8개를 한꺼번에 펼치지 않고 한 장씩 선택합니다. 기본은 마지막으로 열린 장이며, 능력/서사에서 읽던 위치는 현재 창의 메모리에만 보존합니다.

| 현재 정보의 출처 | 이야기 공개 기준 |
|---|---|
| 같은 세션의 현재 성장 기록 | 검증된 현재 stage_index·stage_id와 성장 단계 표를 대조하고 원본 unlock_step 이하인 장만 공개합니다. |
| 현재 오디션 보드 | 해당 멤버의 기존 storyOpened와 실제 board stories를 사용합니다. 소개와 기존 열린 조각만 공개하며 성장 단계 기준으로 우회하지 않습니다. |
| 초기 인수만 있고 현재 단계가 없음 | 공개 소개·배경만 표시합니다. 나머지는 진행 연결 대기입니다. 초기 정보로 성장 단계를 지어내지 않습니다. |

원문은 현재 멤버와 연결된 generated_member.story를 재사용합니다. 배열이 빈 경우나 일부만 있는 경우도 그대로 보존하며 고정 후보 예시로 채우거나 문장을 다시 추첨하지 않습니다. 생성 서사가 전혀 없는 기존 멤버만 같은 candidate_id의 이야기 표를 읽습니다. 이름만으로 다른 멤버의 서사를 연결하지 않습니다.

story_status=ready는 문장 생성 완료이며 해금 상태가 아닙니다. story_unlocked는 기존 화면의 읽은 목록이며 이 정보창은 읽음·해금·성장·저장을 갱신하지 않습니다. 잠긴 장과 미연결 장의 본문·대사는 표시 모델에도 전달하지 않고 상태·단계만 표시합니다. background_hidden_chip은 기존 공개 **특기** 칩이며 숨은 능력 수치를 공개한다는 뜻이 아닙니다.

오디션 보드는 현재 stories 원본의 소개와 piece가0 이상인 실제 행을 기존 순서로 읽습니다. 생성 보드의 파생 이야기는 기존 intro와 step0~4 범위이며 원본8단계에서 새 장을 보충하지 않습니다. 기존 후보에 에필로그 행이 실제로 있으면 해당 조각까지 열렸을 때만 표시합니다. 일반 성장 기록의8단계 원본과 챕터 수가 다를 수 있으며 이 차이로 공개 규칙이나 저장 계약을 통합하지 않습니다.

## 3. 능력 아래 흡수율의 뜻

각 개인 능력 아래 **흡수율 a / b / c**를 표시합니다. 세 값은 그 축의 세부 능력3개 순서와 같습니다. 축 평균 흡수율을 새로 계산하지 않습니다.

현행 성장 표가 step_table이므로 이 표시는 **기존 stepGain 계산기의 주사위1·건물 배수1 기준 성장량**입니다. 퍼센트, 예전 재능 구간 곡선, 최근 실제 오른량으로 표현하지 않습니다. 선택한3세부 아래에서도 각 기준 성장량을 확인합니다.

- 실제 세부 현재값과 실제 부모 축 재능을 기존 순수 계산기에 넣습니다.
- 0보다 크고0.1보다 작은 값은 <0.1로 표시하여 작은 양을 실제0으로 보이지 않게 합니다.
- 필수 입력·표가 없으면 흡수율 연결 대기로 남깁니다.
- 설명을 펼치면 기준과 단위를 명시합니다.
- 이 조회는 실제 성장·주사위 소모·보상 적용을 실행하지 않습니다.

## 4. 현재 데이터·읽기 호환·미연결

현재 testPage/저장 범위의 session과 run, 전체 candidate_id/mons_id·합류 목록을 대조합니다. 현재 성장값·처음 인수 정보·오디션 합류 정보를 각각 구분합니다. 다른 멤버를 임의로 대입하지 않습니다.

성장 snapshot은 일반 계약 검증과 현재 run·세션·전체 멤버 대조를 통과해야 합니다. test_session_id가 명시적으로 다른 기록은 거부합니다. ID가 없는 기존 기록은 현재 세션 재대조·같은run·전체 멤버 일치가 확인될 때만 읽기 호환합니다. data_signature는 원본 데이터 지문이므로 새 상태 seed/복원용 서명과 같다는 조건을 조회에 추가하지 않습니다. 저장/복원 계약은 수정하지 않습니다.

팀 능력은 현재 공급된 개인 기여와 함께 성장 근거만 표시합니다. 함께 성장·팀 총합이나 숨은 능력이 미연결이면 —로 남깁니다. 현재 확인되는 개인 기여만으로 총합을 완성하거나 기본0을 확정하지 않습니다.

카드북은 덱 모음→12장→카드 상세를 유지하고 카드/아이돌 능력 탭 대신 이 공통 모달을 사용합니다. 멤버 덱은 실제 연결 멤버, 사업 덱은 팀을 열며 빈 멤버 자리는 다른 멤버로 바꾸지 않습니다. 기존 cardView=ability 주소도 모달로 한 번 연결합니다.

## 5. 공통 모듈·수명·수정 범위

- character-info-model/data가 실제 원본을 읽고 순수 표시 모델을 만듭니다.
- character-info-view/style 및 character-info-ui.json이 모든 폰의 같은 UI·문구·순서를 제공합니다.
- character-info-binding이 폰 단위로 하나만 연결합니다. 같은 출처의 부모/자식 문서도 같은 DOM 소유자를 재사용합니다.
- 별도 폰은 공통 mobile-frame 생성에서 연결합니다. 내부 페이지는 상위 character-info-frame-bridge가 실제 자식 폰에 붙습니다.
- 오디션은 character-info-source가 현재 run을 직접 읽으며 handoff를 발행하거나 게임 저장을 만들지 않습니다.
- 모듈/세션 전환 때 이전 정보창·구독을 정리합니다. 비동기 로드·닫기·실패 재시도에서 오래된 요청이 다시 열리지 않게 합니다.
- 팩 확인 중에는 공통 진입도 잠깁니다. 확인 조작만 기존 다음 카드 진행을 담당합니다.
- 오디션/쟁탈전 실행 입구는 기존 mount export를 유지한 소스 연결 방식입니다. 빌드·서버 재시작은 하지 않았습니다.

표시용 JSON만 추가했으며 게임 CSV·발란스 값·저장 계약·보호 play 원본·모노 프로젝트는 고치지 않았습니다. 성장·보상·새 게임/초기화 버튼을 실행하지 않았습니다.

## 6. 검수와 실제 화면

등록21ID의 실행 완료 제목을 확인하고 실제 모바일 폰에서 팀·개별 전환·닫기·흡수율·폰 경계·가로 넘침을 확인했습니다. 오디션 합류0명의 빈 상태는 별도로 확인했습니다. 공통 폰390×844와 내부 페이지 폰, 폰 팝업을 확인했습니다. 이번 회차의375/430px 브라우저 viewport 실측은 성공으로 기록하지 않습니다.

- 데이터88검증, UI/바인딩 메모리13건, 프레임11건, 공통 카드연결4건, 기존 카드 controller6건을 통과했습니다.
- 팝업에서 Escape 후 정보창만 닫히고 팝업이 유지되는 것을 확인했습니다.
- 실행기에서 게임 굴림·전투·보상·성장 적용을 시험한 것으로 확대하지 않습니다.
