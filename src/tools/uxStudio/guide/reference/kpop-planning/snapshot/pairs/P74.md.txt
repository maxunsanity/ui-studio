# P74 · 보드 주사위 · 배수 걸기 · 대표 개발 기획서

**이 문서는** 주사위 배수를 고르고 40칸 보드를 이동해 도착한 칸의 활동을 만나는 한 굴림을 설명합니다. 주사위는 이번 굴림에 쓰는 자원이며, 받은 수익은 시설을 짓고 키우는 데 사용합니다.

**보는 법** 1장 개요 → 3장 시험 진입 → 4장 배수·공급 경계 순서로 읽고, 임시값과 실제 호출 경로를 구분합니다.

**지금 상태** 보드·경제 시험 경로는 있으며 일차 상한은 현재 수동 허브에 연결되지 않았습니다. 본게임 계정·서버 저장과 최종 발란스는 작업 전 또는 대기입니다.

## 1. 개요

### 콘텐츠 경계

배수를 먼저 선택하고 주사위를 굴리면 도착 위치가 정해집니다. 도착 칸이 무엇인지에 따라 해당 콘텐츠로 이어지고, 칸 수익을 계산할 때 선택한 배수를 사용합니다. 건설은 주사위를 직접 쓰는 행동이 아니라 별도의 돈과 건물 규칙을 따릅니다.

현재 공용 시뮬레이터는 보드 이동과 경제 계산을 시험하는 경로입니다. 개발된 시뮬레이터와 표의 임시값이 본게임의 계정 저장이나 최종 발란스까지 완성됐다는 뜻은 아닙니다.

```mermaid
flowchart LR
 A[보유 주사위와 배수 확인] --> B[배수 선택]
 B --> C[주사위 굴림]
 C --> D[40칸 보드 이동]
 D --> E[도착 칸 판정과 콘텐츠]
 E --> F[수익 계산과 배수 적용]
 F --> G[다음 굴림 또는 시설 건설]
```

## 3. 구동 방법·시뮬레이션

화면 흐름: 공용 시뮬레이터 로비 허브 → 배수 선택·굴림 → 도착 콘텐츠 → 메인 복귀 · 이번 문서의 새 화면 캡처는 미완 · 이식 비교는 해당 없음.

[눌러서 메인 보드와 주사위 실행](../../../../game-simulator.html?module=simulator_module_dice)

1. 공용 시뮬레이터의 로비 허브를 엽니다. 현재 팀과 저장된 진행이 있다면 같은 진행을 확인합니다.
2. 열려 있는 배수를 고르고 굴립니다. 현재 수동 허브는 보유 주사위와 엔터파워 문턱을 검사합니다. 일차 상한 표·별도 계산 함수와 이 허브의 연결 차이는 4장에서 구분합니다.
3. 이동 경로와 도착 칸을 보고 해당 칸의 콘텐츠를 확인합니다. 건물 칸의 표시용 룰렛은 [P72](../필러룰렛_v01/필러룰렛_기획서.html), 실제 수익 계산은 경제 시스템이 맡습니다.
4. 콘텐츠를 마치고 같은 메인으로 돌아가 다음 굴림을 이어갑니다. 문서를 여는 것만으로 무거운 시뮬레이터를 자동 실행하지 않습니다.

실행 링크는 시험 입구입니다. 이번 문서 작업에서 실제 화면 진입·플레이는 확인하지 않았습니다.

## 4. 상세 기획

### 한 판 순서

| 점검 | 내용 |
|---|---|
| 시작·종료 | 메인에서 배수를 선택해 굴리고, 도착 처리를 마친 뒤 다음 굴림으로 이어집니다. |
| 입력·출력 | 현재 위치·보유 주사위·배수·표와 주사위 결과를 읽고 이동 경로·도착 칸·경제 결과를 만듭니다. |
| 상태와 전이 | 선택 → 굴림 → 이동 → 도착 처리 → 복귀 순서입니다. |
| 판정 | 현재 수동 허브는 배수 문턱을 검사하고 도착 칸별 처리를 사용합니다. 일차 상한은 설계 조건·별도 helper와 수동 허브 미연결을 구분합니다. |
| 오류·예외 | 필요한 배수 문턱 표가 없거나 값이 잘못되면 임의 숫자를 만들지 않고 오류를 확인합니다. |
| 저장·복원 | 시뮬레이터는 진행 기록을 사용합니다. 본게임 계정·서버 저장은 작업전입니다. |
| 다른 모듈 연결 | 건물 도착 표시, 건설, 이벤트와 같은 콘텐츠에 도착 맥락을 전달합니다. |

### 배수 선택과 열림

현재 `item_master_dice_mult.csv`는 배수와 최소 보유량을, `dice_mult_unlock_rule.csv`는 엔터파워 문턱을, `dice_mult_day_cap.csv`는 일차별 최대 배수를 담습니다. 코드의 현재 배수 문턱은 `enter_power_level`이 아니라 `dice_mult_unlock_rule`을 읽습니다. 표 값은 임시 시안이며 최종 발란스는 대기입니다.

공급원을 구분합니다. 공통 경제는 시작 50·12분당 1·기본 충전 상한 30 설정을 읽습니다. 성장 허브에서 real 스위치를 켠 시험은 `idol_growth_sim_config`의 `REAL_DAILY` 120·`REAL_STORE` 360을 읽으며, 끈 시험은 보유량 소비 제한을 분리합니다. balance import로 전달된 같은 진행의 경제 상태는 별도로 읽습니다. 서로 다른 시험의 수치를 무료 하루 총량이나 최종 운영 지급으로 합치지 않습니다.

| 배수 | ×1 | ×2 | ×5 | ×10 | ×20 | ×50 | ×100 | ×200 | ×500 | ×1000 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 최소 보유 주사위 | 10 | 20 | 50 | 100 | 200 | 500 | 1000 | 2000 | 5000 | 10000 |
| 엔터파워 문턱 | 0 | 0 | 0 | 50 | 100 | 180 | 260 | 340 | 420 | 500 |

제안서는 처음 ×1·×2·×5를 열고 ×5를 기본으로 제시하며 1일차 ×10, 2일차 ×20 상한을 설명합니다. 이는 현재 임시 표와 설계 조건입니다. `maxOpenMultOn`은 보유량·엔터파워·일차 상한을 함께 계산하지만, 현재 수동 허브의 `growthEcon.openMult`와 `roll`은 `multOptions`의 보유량·엔터파워만 검사합니다. 아래 그림은 일차 상한까지 포함한 설계 조건이며 수동 허브에 모두 적용됐다는 뜻은 아닙니다.

```mermaid
flowchart TD
 A[배수 행 선택] --> B[최소 보유량 확인]
 B --> C[엔터파워 문턱 확인]
 C --> D[일차 상한 확인]
 D --> E[사용 가능한 배수]
 B --> F[조건 부족이면 잠김]
 C --> F
 D --> F
```

### 이동과 도착

주사위 두 개의 합으로 보드의 2~12칸을 이동하고 40칸을 순환합니다. 도착 칸과 배수는 다음 콘텐츠의 입력이 됩니다. 같은 도착을 재생할 때 새 지급이나 새 추첨으로 취급하지 않도록 도착 기록과 각 콘텐츠의 계약을 확인합니다. 도착의 표시용 영수증은 경제 지갑 자체가 아닙니다.

```mermaid
flowchart LR
 A[현재 칸과 굴림] --> B[이동 경로와 도착 칸]
 B --> C[칸 종류 확인]
 C --> D[건물 도착 표시]
 C --> E[다른 칸의 콘텐츠]
 D --> F[기록 확인과 메인 복귀]
 E --> F
 F --> G[다음 굴림]
```

### 주사위 공급과 충전 상한

| 항목 | 현재 표의 값과 의미 | 구분 |
|---|---|---|
| 무료 선물 | 10개, 8시간 간격, 받기 전까지 쌓이지 않음 | `dice_grant_config` 임시 시안 |
| 출석 | 1~7일차 21·23·27·31·35·40·42개, 이후 7일차 값 | 같은 표의 임시 시안 |
| 충전 상한 | `dice_cap_level` 13행 중 1단 30, 3단 50. 표에는 9~13단 사용 안 함으로 표기 | 현재 로더는 엔터파워가 있는 13행을 읽으며 note의 사용 안 함 문구로 제외하지 않음 |
| 시작·시간 충전 | `economy_config`의 시작량·간격·충전량 | 시뮬레이터 설정; 최종 공급량 발란스 대기 |

충전 상한은 해당 충전 규칙에 쓰는 값입니다. 모든 주사위 지급을 일률적으로 잘라낸다는 뜻으로 확대하지 않습니다. 현재 `dice_cap_level`은 엔터파워 1에 상한 40·50인 행이 함께 있어 해당 눈금의 마지막 행은 50입니다. note의 비활성 설명은 코드의 활성 조건이 아닙니다. 미션·이벤트 지급과 하루 총량은 [P110](../발란스/핵심제안_발란스구조_기획서.html)의 경제 기준에서 확인합니다.

### 필요 시스템

보드 칸과 굴림, 경제 계산, 배수 열림, 충전 및 진행 저장, 칸별 콘텐츠 인계가 필요합니다. 표는 각 역할의 원본을 읽으며 없는 발란스 수치를 문서에서 새로 채우지 않습니다.

### 남은 결정

- 업그레이드액과 배수의 관계: 결정 대기. 주사위로 건물을 직접 키우지 않는 제안과 최종 계산을 구분합니다.
- 높은 배수가 실제 공급량과 사용 구간에서 적절한지: 발란스 대기.
- 최종 배수 단계·상한, 칸 기본 수익과 공급량: 발란스 대기.
