### 0. 한 줄

우리 몬스가 상대 시설을 공격하고 실제 수비 몬스들이 공용 유리 방패로 막는다. 수비가 소진된 뒤에는 시설이 한 판에 한 단계씩 손상되고 다음 공격을 계속할 수 있다.

### 콘텐츠 경계

| 구분 | 현재 문서의 범위 |
| --- | --- |
| 담당 | 교차 비행·이동 사격·수비 대형·순간 방패·탈진·시설 단계 손상·수동 진행·시연 DB |
| 본게임 연결 | 보드 진입·상대 매칭·결과 판정·기분 비용·돈·팬·계정 저장은 기존 코드와 별도 |
| 같은 점 | 모노폴리 GO의 건물 공격·순간 방어와 반복 공격·수리의 원리를 참고 |
| 다른 점 | 방패 소모품 대신 실제 몬스가 방어하고 외형 스킨을 장착 |
| 이게 아닌 것 | 보스 몬스 처치·아이돌 캐스팅·한 번에 시설 전체 붕괴 |

### 현재 기준과 목표

확정(현재 시연·사용자 10/20): 수동 10초 공격, 한 판에 수비 한 명 탈진, 수비 0명의 직접 공격은 시설 표시를 1단계 낮춘다. 독립 시연 개발은 끝난 범위이며 본게임 연동은 미구현이다.
흐름도: 공격 버튼 → 10초 이동 사격 → 탈진 또는 시설 1단계 손상 → DB 유지·대기

## 3. 구동 방법·시뮬레이션

화면 흐름: P94 공용 시뮬레이터 → 신규 섭외권 쟁탈전 표현 → 수동 공격 → 결과 반영·대기 → 다음 공격 · 스샷 [웹 확인 이미지](/docs/planning/_previews/casting-battle-v06/battle-demo-web.png) · 이식 비교 해당 없음(기존 원문은 P159 링크).

- 실행: [P94 신규 전투 시연](/docs/planning/game-simulator.html?module=simulator_module_casting_battle). 기존 simulator_module_stage_battle의 30초 실행과 구분한다.
- 공격 버튼은 한 판만 실행한다. 일시정지·이어 재생은 해당 시간과 카메라를 함께 멈추고 잇는다.
- 수비가 남으면 10초 후 탈진 한 명을 저장하고 초기 대기로 돌아온다. 자동 다음 판은 없다.
- 수비가 0명이 된 직후에도 건물을 자동 공격하지 않는다. 다음 버튼을 눌러야 무방패 직접 공격이 시작된다.
- 직접 공격 한 판은 시설 표시 1단계만 낮춘다. 남은 모델·국소 잔재를 두고 다음 공격을 받을 수 있다.
- 랜덤 뷰·동선은 새 시드로 표현을 바꾼다. 같은 시드의 다음 공격은 같은 경로를 재현한다.
- 화면·시점·외형 변경과 표현 초기화는 진행을 보존한다. 훈련 초기화만 수비 5명·시설 30단계를 복원한다.
- 저장 매체는 IndexedDB → localStorage → memory다. memory 모드는 새로고침 뒤 보존하지 못하며 실제 저장 모드를 표시한다.

흐름도: 대기 → 사용자가 공격 → 공격·탈진 또는 1단계 손상 → 저장·대기

## 4. 상세 기획

### 한 판 순서 · 확정(사용자 10/20·현재 독립 시연)

| 점검 | 내용 |
| --- | --- |
| 시작·종료 | 버튼 시작 → 10초 공격 → 수비 한 명 탈진 또는 시설 1단계 손상 → 저장 → 대기 |
| 입력·출력 | 실제 아군 5명·수비 0~5명·탈진 순서·시설 단계·시드 → 같은 ID 기반 표현과 진행 |
| 상태와 전이 | idle → attack → exhausting 또는 stage_damage → save → idle. 시설 단계 0만 종료 |
| 판정 | 수비가 있던 판은 한 명 탈진. 0명에서 시작한 판만 시설 1단계 감소. 실제 본게임 결과 계산 아님 |
| 오류·예외 | 중복 완료 차감 금지. 로드 실패는 저장 대체 모드 표시. 시설 0단계는 다음 공격 제한 |
| 저장·복원 | 탈진 ID·공격 횟수·buildingStage를 저장. 화면·시점 변경은 유지, 훈련 초기화만 기본 상태 |
| 다른 모듈 연결 | 공격·수비 모션·카메라·시설 단계·부분 손상·DB를 독립 모듈로 연결 |

흐름도: 수비 있음 → 방어 → 공격 종료·1명 탈진 → 수비 0에서 다음 버튼 → 직접 적중·시설 1단계

### 필요 시스템

공격 대본·시드 경로, 수비 모션과 방패, 카메라, 탈진, 시설 단계 매핑, 부분 손상과 잔재, 수비 배치·진행 저장을 독립 모듈로 유지한다. P94는 정식 CSV 6표와 마스터를 읽어 시연에 필요한 설정을 만든다. 본게임 경제·기분 계산은 별도 책임이다.

### 현재 시연과 정식 게임의 구분

이 시연의 수동10초 진행과 IndexedDB 상태는 본게임 서버 판정이 아니다. 기존30초 보드 전투·기분35/합계30·매칭·돈·팬·복수·보상은 P159 원문과 기존 src/game/stage-battle 자료로 보존한다. 이를 최신 시연의 현재 규칙에 혼합하거나 실제 게임에 적용했다고 기록하지 않는다.

### 남은 결정

- 본게임의 판정·기분·매칭·결과 대본 연결.
- 수리 방법·회복량·가격·시간과 실제 성장 기록 보존 방식.
- 유료 방패의 가격·통화·판매 일정·무료 기본 제공.
- 실제 상점·보유·장착·서버 DB 연결.

이게 아닌 것: 원본 기하를 거대 파편으로 모두 붕괴시키거나 화면 탄환마다 실제 손상을 추가하는 규칙이 아니다.

### 마스터 연결 · 확정(공통 데이터 원칙)

정식 원본은 data/casting_battle/의 CSV 6개다. 카메라 시점·높이·자동 움직임 기본값과 UI 문구도 presentation_value 표에서 읽는다. P94 모듈은 활성화할 때마다 6CSV와 기존 공용 마스터를 읽고 ID를 해석해 시연 설정으로 변환한다. 값을 바꾼 뒤 모듈을 다시 선택하거나 새로고침한다. 독립 시연의 JSON은 컴파일된 산출물로 남는다. 본게임 아이템·스킬·캐릭터·시설 ID를 재사용하고 중복 콘텐츠를 만들지 않는다. CSV 기본 편성의 서명이 바뀌면 저장된 공격 횟수·시설 단계·같은 몬스의 탈진을 유지하며 기본 편성을 동기화한다. CSV가 같으면 사용자가 저장한 방어 순서를 보존한다. 방패 외형은 정의 ID로 연결해 표시 순서를 바꿔도 형태가 섞이지 않는다.

표 목록·열·참조는 schema_table/schema_column에 등록하고 공용 생성기로 기획 도구 목록을 만든다. [P99 사용 CSV](/docs/planning/planning-docs-tool.html?face=development&plan=planning_development_plan_casting&doc=P99)와 [P73 전체 테이블](/docs/planning/game-table-tool.html?plan=planning_development_plan_casting)에서 실제 행·원본 경로·마스터 참조를 확인한다.

주사위 환산: 현재 독립 시연은 해당 없음. 주사위·돈·팬을 지급하거나 차감하지 않는다. 본게임 보상 환산은 결정 대기이며 이 문서에서 새 숫자를 계산하지 않는다.

### 수락 기준

- 한 번 누르면10초 한 판만 실행하고, 수비한명 탈진 뒤 다음 입력까지 기다린다.
- 1→0 판은 시설을 자동 공격하지 않는다. 다음 버튼부터 무방패 한 판당1단계 낮춘다.
- 30→29→28 실제 구성 모델과 국소 잔재·저장을 유지하고0단계에서만 종료한다.
- 몬스 비행 기준점1~5m·정면60도·전원 교차를 지킨다. 정면·좌쿼터·우쿼터 고정과 자동 카메라 옵션을 나누고 기본은 정면 고정이다.
- 같은 시드 재현·다른 시드 변경·정지·초기화 복원과 중복 완료 방지를 지킨다.
- HTML·MD 간략/세부의 고정7장과 문서 정보·이력을 맞추고 이전 P98을 history로 보존한다.
- Node VM·DB프로토콜 대역 검사와 실제 브라우저·서버 검수를 혼동하지 않는다.
