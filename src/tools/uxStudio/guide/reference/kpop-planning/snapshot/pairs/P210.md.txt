# P210 · 잭팟 · 대표 개발 기획서

**이 문서는** 콘서트장 · 예능 방송국 도착 대박 중 드물게 터지는 잭팟이 어떻게 쌓이고 터지는지 정리한 대표 개발 기획서입니다.

**보는 법** 1장 그림 → 4장 「한 판 순서」 → 핵심제안 개발의 「잭팟 통 시뮬레이터」 순서로 읽습니다. 세부 결정과 근거는 책갈피 [P199 잭팟 보완판](../../기획서/산출_기획서_잭팟_보완판_v1_클로드.html)에 있습니다.

**지금 상태** 통 누적·판정·지급의 공통 경제 코드와 독립 문서 시안이 있습니다. 전용 통합·실제 화면·운영 저장·피드 연결의 전체 검수는 남아 있습니다.

## 1. 개요

출처: (합침) 제안서 [잭팟](/docs/planning/proposal-concept/jackpot.html) · 책갈피 [P199 잭팟 보완판](../../기획서/산출_기획서_잭팟_보완판_v1_클로드.html) · 현중 11/01~11/02 지시

> **핵심** 잭팟은 **통**입니다. 굴릴 때마다 조금씩 쌓이고, 콘서트장 · 방송국에서 **대박이 났을 때 드물게** 통 전부를 받습니다. 팬 수는 늘지 않고, 데뷔 이후에는 그 무대가 피드 맨 위에 오릅니다.

```mermaid
flowchart LR
  A[굴림마다 통 쌓임] --> B[콘서트장 · 방송국 도착]
  B --> C{대박?}
  C -->|드물게| D[잭팟 · 통 전부]
  D --> E[데뷔 이후 피드 맨 위]
```

### 콘텐츠 경계

- 맡는 것: 잭팟 통 · 발동 조건 · 연출 · 피드 연결.
- 다른 문서에 맡기는 것: 배수 → [P209 배수 걸기](배수걸기_핵심제안서.html) · 팬 → [P211 팬덤 게이지](팬덤게이지_핵심제안서.html).

### 현재 기준과 목표

| 무엇 | 기준 |
|---|---|
| 금액 | 잭팟 통(쌓인 만큼) · 상한 없음 · 표 값 그대로 |
| 발동 | 대박 안에서 통 추첨(chance). 올킬 뒤 후속 룰렛(second_roulette_chance_pct)은 별도 |
| 콘서트장 vs 방송국 | 보상 같고 연출만 다름(떼창 / 화제 클립) |
| 배수 | 붙음 |

<a id="part-3"></a>

## 3. 구동 방법·시뮬레이션

화면 흐름: 보드 도착 → 필러 대박 → 잭팟 룰렛 → 연출 → 피드 · 스샷 미완 · 이식 비교 해당 없음

- 전용 잭팟 정책 모듈의 별도 등록은 없습니다. 다만 공통 경제의 통 누적·지급 결과를 성장 허브가 받는 코드 경로는 있습니다. 아래 문서 시안과 구분하며 이번 정정에서 실제 화면·지급·저장을 실행 검수한 것은 아닙니다.
- 핵심제안 개발의 **잭팟 통 시뮬레이터**에서 굴릴 때마다 통이 쌓이고 대박 안에서 드물게 터지는 흐름을 봅니다. 숫자는 모두 임시 시안입니다.

<a id="part-4"></a>

## 4. 상세 기획

### 한 판 순서 (임시 시안)

| 점검 | 내용 |
|---|---|
| 시작·종료 | 독립 문서 시안은 지급 뒤 0. 공통 경제는 표의 시작 통 금액으로 복원 |
| 입력·출력 | 입력 = 도착 칸 · 필러 판정 / 출력 = 코인 · 연출 · 피드 |
| 상태와 전이 | 누적 → 대박 → 통 추첨 → 지급. 후속 룰렛 표시는 별도 |
| 판정 | 통 지급 chance와 올킬 후속 룰렛 확률을 따로 읽음. 독립 시안 입력은 운영값과 구분 |
| 오류·예외 | 팬 수 · 투표 · 점수에는 안 들어감 |
| 저장·복원 | 통 금액은 저장(시즌 끝 리셋) |
| 다른 모듈 연결 | 보드 · 필러 · 피드 · 배수 |

### 연출 (확정 근거: jackpot.csv · 현중 10/04 「잭팟은 팬을 늘리지 않음」)

콘서트장 = 팬이 무대로 몰려드는 떼창 · 방송국 = 시청률 · 화제 클립 폭발. 지금 있는 곳의 팬으로 연출합니다(방문 중이면 현지 팬).

### 필요 시스템

잭팟 통 저장 · 발동 판정 · 두 연출 · 피드 맨 위 올리기.

### 화면·연출 목록

잭팟 룰렛 · 떼창 연출 · 화제 클립 연출 · 피드 카드.

### 남은 결정

- 통 쌓이는 비율 · 발동 확률 — 표 값 · 발란스 대기

### 현재 코드와 독립 시안의 경계

공통 경제는 굴림마다 `jackpot_pot_add_pct`만큼 배수 없이 통에 쌓고, `hit_big` 뒤 `jackpot.csv.chance`로 통 지급을 추첨합니다. 지급 때만 `dice_mult_apply` 조건의 주사위 배수와 해당 돈 버프를 적용합니다. 지급 뒤에는 `jackpot_pot_start_pct`의 시작 통 금액으로 복원합니다. 표 note에 남은 누적 배수 설명과 현재 실행이 다른 점은 표 담당의 후속 대조 항목이며 여기서 숫자나 원표를 고치지 않습니다.

올킬 후속 룰렛의 `second_roulette_chance_pct`는 통 지급과 별도입니다. 독립 문서 시안은 자체 입력으로 확률·누적을 보여 주고 지급 뒤 0이 되는 메모리 예시이며 CSV·지갑·운영 저장을 읽지 않습니다. 이전 팬 집결 시연의 팬×배수도 현재 통 계산식이 아닙니다.

팬이 많을수록 큰 수익이라는 방향과 현재 연결을 구분합니다. 공통 엔진의 잭팟 팬 항은 `fan_income_modifier_jackpot` 계수 0.000068(`data/fan_tier/fan_income_modifier.csv:3` · 임시(나중에 결정))이고 통 지급은 별도로 남습니다(11/04 비앙카 고침: 이전 문구 「계수가 비어 현재 0」). 팬 집결 연출·음악 피드·시즌 통 저장의 기획과 실제 전체 연결 완료는 같은 뜻이 아닙니다. 피드와 음악의 현재 범위는 P208을 따르며 이번 문서 정정에서 완료로 승격하지 않습니다.
