# P211 · 팬덤 게이지 · 대표 개발 기획서

**이 문서는** 팬의 생김·바뀜·옮김과 한 막대 표시의 제안을 정리하고, 문서 표시 시안·공통 팬 코드·남은 연결을 구분하는 대표 개발 기획서입니다.

**보는 법** 1장 그림 → 4장 「한 판 순서」 → 핵심제안 개발의 「팬덤 게이지 시뮬레이터」 순서로 읽습니다. 세부 제안과 근거는 책갈피 [P196 팬덤 게이지 보완판](../../기획서/산출_기획서_팬덤게이지_보완판_v1_클로드.md)에 있습니다.

**지금 상태** 문서 표시 시안과 공통 팬 계산·세 활성층 HUD 표시 코드가 있습니다. 전용 눈금·악개·지역 표시의 연결과 실제 게임·저장은 검수 대기입니다.

## 1. 개요

출처: (합침) 제안서 [팬덤 게이지](/docs/planning/proposal-concept/gauge.html) · 책갈피 [P196 팬덤 게이지 보완판](../../기획서/산출_기획서_팬덤게이지_보완판_v1_클로드.md) · 현중 11/01~11/02 지시

> **핵심** 아래는 P196의 제안 방향(검수 대기)입니다. 팬이 **생기는** 길은 시설과 능력뿐입니다(10/04 원칙). 곡 · 피드 · 페스티벌은 새 팬을 만들지 않고 **머글 → 라이트 전환과 등급 올리기**만 합니다. 게이지는 이 결과를 등급 색으로 쌓은 한 막대입니다.

```mermaid
flowchart LR
  A[시설 · 능력 성장] --> B[팬 생김]
  C[곡 · 피드 · 페스티벌] --> D[등급 올림]
  B --> E[팬덤 게이지 · 한 막대]
  D --> E
```

### 콘텐츠 경계

- 맡는 것: 팬 생김 · 등급 바뀜 · 옮김 세 길 · 게이지 모양 · 마일스톤 눈금.
- 다른 문서에 맡기는 것: 팬 수익 → [P213 도시](도시_핵심제안서.html) · 게릴라 팬 이동 → [P220 게릴라 공연](게릴라공연_핵심제안서.html).

### 현재 기준과 목표

다음 표는 P196의 제안 방향입니다. 현재 원표·공통 코드의 세 활성층과 같은 운영판으로 합치지 않습니다.

| 길 | 무엇이 | 결과 |
|---|---|---|
| 생김 | 시설 단계 · 능력 상승 | 머글 인원에서 새 팬 |
| 바뀜 | 곡 · 피드 · 페스티벌 · 투표 | 라이트 → 팬 → 코어 → 콘크리트 |
| 옮김 | 게릴라 공연 | 라이트 · 코어만 이동(콘크리트는 안 옮김) |

- P196은 본진 팬과 지역 현지 팬을 따로 세고, 지금 있는 곳의 팬을 보여 주는 방향을 제안합니다. 지역별 실제 연결은 미확인입니다.
- P196은 악개를 수익에서 빼고 빨간 줄로 따로 표시하는 방향을 제안합니다. 현재 원표의 수익 입력·팬 합과는 차이가 있어 정책 확인 대기입니다.

P196에는 시설·능력만 생김이라는 설명과, 건물 도착·피드 찜(P10 후보)을 생김에 넣은 분류가 함께 있습니다. P11·P12도 후보이며, 생김·전환 용어와 후보 범위는 정합 확인 대기입니다. 현재 코드만으로 원정책을 결정하지 않습니다.

## 3. 구동 방법·시뮬레이션

화면 흐름: 보드 · 시설 → HUD 팬덤 게이지 → 마일스톤 보상 · 스샷 미완 · 이식 비교 해당 없음

- 공통 코드: 팬 계산·세 활성층 HUD·마일스톤 수령 계산 경로가 있습니다. 이 문서의 전용 표시·보상 화면과 상위 게임 진입의 직접 연결은 미확인입니다.
- 문서 시안: 팬덤 게이지 시뮬레이터는 시설·능력의 팬 생김과 피드·페스티벌의 등급 바뀜을 별도 메모리로 보여 줍니다. 인원·비율은 임시이며, 원표·게임 지갑·상대 팬 기록과 연결되지 않습니다.
- 조회·저장: 현재팀 조회는 읽기 전용입니다. 공통 팬 계산의 writer는 선택한 로컬 저장 공간과 테스트 scope 조건에 따라 팬 기록에 닿을 수 있습니다. 이 문서 시안의 메모리와 같은 저장 방식이 아니며, 실제 저장 성공은 미검수입니다.

## 4. 상세 기획

### 한 판 순서 (임시 시안)

| 점검 | 내용 |
|---|---|
| 시작·종료 | 게이지는 늘 HUD에 있음 |
| 입력·출력 | 입력 = 시설 · 능력 · 곡 · 페스티벌 / 출력 = 등급별 팬 수 · 눈금 보상 |
| 상태와 전이 | 팬 생김 · 바뀜 · 옮김 |
| 판정 | 생김은 머글 인원 안에서만 |
| 오류·예외 | 팬이 0이면 빈 막대 · 악개는 따로 |
| 저장·복원 | 팬 수는 시즌 범위(시즌 끝 리셋) |
| 다른 모듈 연결 | 시설 · 능력 · 피드 · 게릴라 · 페스티벌 |

한 판 표의 상시 HUD·시즌 리셋·지역 연결은 기존 기획 범위입니다. 이번 대조로 실제 적용이나 최신 시즌 정책을 확정하지 않습니다. 실제 팬이 없는 상태와 팬 값 미공급은 구분해 검수해야 합니다.

### 게이지 모양 (임시 시안)

한 막대를 등급 색(라이트 · 팬 · 코어 · 콘크리트)으로 쌓고, 막대 위 눈금 = 마일스톤 단(기존 8단 시안). 사람 수가 많아지면 무리 단위(1 → 10 → 100 …)로 바꿔 그립니다.

위 네 층은 P196·문서 시안의 제안입니다. 현재 `fan_tier` 원표의 별도 팬 층은 라이트로 합침/removed이고, 공통 HUD는 라이트·코어·콘크리트만 합합니다. 원문의 여덟 단계 문턱과 현재 보상 그룹, 문서 시안의 다섯 후보 눈금은 서로 다른 자료입니다. 현재 보상 항목은 보상 마스터를 읽으며, 원 제안의 옛 금액을 현재 지급값으로 사용하지 않습니다.

### 필요 시스템

팬 생김 · 등급 전환 · 이동 계산 · 게이지 그리기 · 마일스톤 보상.

### 화면·연출 목록

HUD 게이지 · 마일스톤 보상 팝업 · 도시 군중.

### 남은 결정

- 원인 건물 가중 비율 · 무리 단위 상한 — 발란스 · 개발

원인 건물 가중 배정은 P196의 제안이며 비율은 발란스 대기입니다. 현재 배정 함수는 호출 자리가 있어도 건물별 팬을 쓰는 기능은 비어 있습니다. 도착·잭팟 팬 계수도 빈칸이며, 코드의 추가항 없음 처리는 계수를 최종 0으로 정한 뜻이 아닙니다. 머글 인구와 화면 군중 상한도 값 대기입니다.

### 수락 기준

다음 문장은 기존 제안의 검수 목표입니다. 생김·전환 및 악개 범위는 앞의 확인 대기를 함께 읽습니다. 실제 팬 0명과 미공급, 전용 마일스톤·도시 군중·실제 저장과 상위 게임 연결은 이번 문서 대조만으로 정상이라고 판정하지 않았습니다.

곡 · 피드 · 페스티벌이 새 팬을 만들지 않고 등급만 바꿔야 합니다. 콘크리트 팬은 게릴라로 옮겨 가지 않아야 합니다.
