# P220 · 게릴라 공연 · 대표 개발 기획서

**이 문서는** P195의 G1~G9를 제안(검수 대기)으로 요약하고, 게릴라 공연의 관객석·팬·돈 흐름을 설명하는 대표 개발 기획서입니다. 기존 상세 기획 P102와 현재 출연권 대전의 코드·실행 범위는 구분합니다.

**보는 법** 1장 그림 → 4장 「한 판 순서」 → 핵심제안 개발의 「관객석 시뮬레이터」 순서로 읽습니다. 세부 결정과 근거는 책갈피 [P195 게릴라 공연 보완판](../../기획서/산출_기획서_게릴라공연_보완판_v1_클로드.md)에 있습니다. 1·4장의 진행·보상안은 P195 제안이며, 6·7장은 원표·코드 확인 범위와 대기를 함께 봅니다.

**지금 상태** 제안(검수 대기) · 승인 아님. 관객석 표시 시안 코드는 있으나 현행 출연권 대전과 독립 게릴라의 실행 연결은 대기입니다. 실제 게임 진입·돈/팬 정산·알림·저장은 미검수이며 값은 발란스 대기입니다.

## 1. 개요

출처: (합침) 기존 개발 기획서 [P102 게릴라 공연](게릴라공연_기획서.md) · 책갈피 [P195 게릴라 공연 보완판](../../기획서/산출_기획서_게릴라공연_보완판_v1_클로드.md) · 현중 11/01~11/02 지시

> **핵심 · P195 제안(검수 대기)** 쟁탈전 칸에 도착하면 **출연권 대전과 게릴라 공연 중 하나가 무작위**로 열립니다. 게릴라 공연은 같은 부문 상대의 공연장에서 관객석을 열어 **같은 팬 셋을 먼저 모으고**, 그 **팬 등급이 곧 결과 등급**입니다.

```mermaid
flowchart LR
  A[쟁탈전 칸 도착] --> B{무작위}
  B --> C[출연권 대전]
  B --> D[게릴라 공연]
  D --> E[관객석 열기 · 같은 팬 셋]
  E --> F[돈 + 팬 이동 · 상대 알림]
```

### 콘텐츠 경계

- 맡는 것: 진입 · 상대 고르기 · 관객석 · 결과 등급 · 보상 · 상대 알림 · 맞불.
- 다른 문서에 맡기는 것: 출연권 대전 → P98(핵심제안 개발 9번) · 팬 등급 → [P211 팬덤 게이지](팬덤게이지_핵심제안서.html).

### 현재 기준과 목표

이 절은 P195 G1~G9 결정안의 목표를 요약합니다. 현재 쟁탈 도착의 출연권 대전 실행과 같은 기능으로 읽지 않습니다.

| 모은 셋 | 결과 | 팬 이동 |
|---|---|---|
| 라이트팬 셋 | 소 | 상대 라이트팬 일부 |
| 코어 셋 | 대 | 라이트팬 · 코어 일부 |
| 콘크리트 셋 | 대박 | 라이트팬 · 코어 일부 · 콘크리트 이동 없음 |

위 팬 이동은 P195 2장의 제안 요약입니다. 현재 팬 원표와 공개 이동 함수는 라이트팬만 옮기므로 코어 이동과의 정합은 결정 대기입니다. 콘크리트 팬 자체를 옮기지 않는다는 제안과, 대박 때 라이트팬·코어 일부를 옮긴다는 제안을 구분합니다.

- 결정안은 같은 부문 안 무작위 상대 · 최근에 당한 유저 잠시 제외 · 봇 상대 허용을 제안합니다. 현재 매칭 연결을 확인한 규칙은 아닙니다.
- 서버 선결정은 기획입니다. 현재 관객석 표시 시안은 메모리에서 좌석을 섞고 공개 결과를 계산하며 서버 결과를 받지 않습니다.
- 결정안은 데뷔 이후 게릴라 직캠 피드와 페스티벌 점수 직접 제외를 제안합니다. 이 표시 시안에서 해당 운영 연결을 확인한 것은 아닙니다.

## 3. 구동 방법·시뮬레이션

기획 흐름: 보드 쟁탈전 칸 → 무작위 → 관객석 → 결과 → 다음 접속 상대 알림 · 스샷 미완 · 이식 비교 해당 없음

- 실행 등록: `data/simulator/catalog.csv`의 게릴라는 문서로 등록되어 전용 게임 실행 모듈 연결 대기입니다. 현재 출연권 대전의 실행과 구분합니다.
- 핵심제안 개발의 **관객석 시뮬레이터**는 메모리에서 좌석을 무작위로 섞고 같은 팬 셋의 등급 문구를 표시합니다. 좌석 수·배치는 임시 시안이며 서버 선결정이나 운영 분포를 재현하지 않습니다.
- 이 시안 파일에는 CSV/API 호출과 돈·팬 writer·알림·저장 처리가 없습니다. 결과의 돈·팬·맞불·피드 문구를 실제 지급·저장 완료로 읽지 않습니다.

## 4. 상세 기획

### 한 판 순서 (임시 시안)

| 점검 | 내용 |
|---|---|
| 시작·종료 | 쟁탈전 칸 도착 · 셋이 모이면 끝 |
| 입력·출력 | 입력 = 응원봉 · 관객석 / 출력 = 돈 · 팬 이동 · 피드 |
| 상태와 전이 | 무작위 → 관객석 → 결과 → 알림 |
| 판정 | 모은 셋의 팬 등급 = 결과 등급 |
| 오류·예외 | 셋이 안 모이면 가장 많은 종류 등급(실제로는 서버가 정한 결과) |
| 저장·복원 | 결과 · 알림 · 맞불 기회는 시즌 범위 |
| 다른 모듈 연결 | 보드 · 팬 · 피드 · 친구 |

### 상대 알림 · 맞불 (임시 시안)

당한 유저는 다음 접속 때 묶어서 알림을 받고 그 상대에게 맞불 공연 기회를 얻습니다(수량 발란스 대기). 맞불 기회는 팔지 않습니다.

### 필요 시스템

진입 무작위 · 상대 고르기 · 서버 선결정 · 관객석 연출 · 알림 · 맞불.

### 화면·연출 목록

관객석 · 결과 · 상대 알림 · 맞불.

### 남은 결정

- 출연권 대전 : 게릴라 비율 · 좌석 수 · 이동량 — 발란스 대기

`stealRules`는 `fan_dice_mult_apply`를 flag로 읽지만, 확인한 `resolveBattle`의 팬 계산은 그 flag를 사용하지 않습니다. 팬층 이동 함수도 `layerSteal` 조건에서만 호출됩니다. 원표·reader·실제 지급 소비를 구분하며 기존 대전 값을 게릴라 정책으로 채택하지 않습니다.

주사위 환산: 발란스 툴 인용.

## 7. 개발 진행·검수

| 요소 | 상태 | 확인 방법·증거 | 다음 작업 |
|---|---|---|---|
| 기획(이 문서 · 책갈피 상세) | 제안(검수 대기) · 승인 아님 | P195 G1~G9 · 이 문서 | 기존 원표·기획과 정합 판단 |
| 관객석 시뮬레이터 | 메모리 표시 시안 코드 있음 | 좌석 공개·등급 문구 · 실제 조작은 별도 검수 | 원표·서버 결과 연결 검토 |
| 게임 시뮬레이터 모듈 · 본게임 | 전용 실행 연결 대기 · 실구동 미검수 | 게릴라 문서 등록과 현재 대전 분리 | 진입·정산·저장 경계 연결 검토 |

이번 코드 확인은 공개 등록·reader와 표시 시안의 정적 범위입니다. 서버 선결정, 돈·팬 지급과 상대 손실, 알림·맞불·피드·저장 연결 및 보호 상위의 실제 동작은 확인하지 않았습니다. 관객석 시안의 팬 이동 문구도 위 제안 표·현재 원표와 구분해 읽습니다.

### 수락 기준

팬 등급이 결과 등급과 같고, 콘크리트 팬이 옮겨 가지 않으며, 게릴라 결과가 페스티벌 점수에 직접 들어가지 않아야 합니다.

### 뺀 것·옮긴 것·보존한 것

세부 결정과 근거는 책갈피 P195에 둡니다. 기존 개발 기획서 P102는 그대로 보존하고 2장에서 연결합니다.
