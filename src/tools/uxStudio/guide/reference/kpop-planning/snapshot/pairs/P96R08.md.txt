> **2026-10-30 확장:** 기본 실행은 12대의 「몬스 미니 뽑기방」입니다. [최신 상세 기획](./몬스_미니뽑기방_12기계_v01.html)을 기준으로 방·기계 선택·카메라·실시간 자동 진행을 확인합니다. 아래 단일 기계의 진열 16개·7,070ms 설명은 `?solo=1` 비교용을 기록한 내용입니다.

## 1. 이 게임에서 느끼게 할 것

플레이어는 기계를 조종하지 않는다. 시작을 누르고 어떤 몬스가 선택되는지, 집게가 제대로 잡는지, 이동하는 동안 버티는지, 출구 직전까지 놓치지 않는지를 지켜본다. 긴장감은 결과 글자가 아니라 **인형이 들리고, 기울고, 집게가 벌어지고, 떨어지는 실제 3D 움직임**에서 만든다.

성공 직전처럼 보이는 모든 움직임을 같은 실패 영상으로 처리하지 않는다. 일찍 놓치는 장면과 마지막까지 버티다 놓치는 장면의 높이·위치·기울기·지속 시간을 다르게 한다. 한 번의 뽑기에서 정한 결과를 연출 중간에 다시 추첨하거나 뒤집지 않는다.

## 2. 사용자 조작

| 상황 | 플레이어가 하는 일 | 기계가 하는 일 |
| --- | --- | --- |
| 대기 | 「뽑기 시작」 한 번 | 다음 뽑기 준비 |
| 시작 후 | 지켜보기 | 몬스 선택, 자동 조준, 이동, 하강, 조임 |
| 들어 올림 이후 | 지켜보기 | 들기, 흔들리는 운반, 출구 앞 이동, 낙하 또는 배출 |
| 결과 | 「한 번 더」 | 새로운 자동 뽑기 시작 |

수동 방향키, 조이스틱, 드래그 조준은 제공하지 않는다. 기계에 보이는 조작판은 장식이고, 화면 아래에는 자동 진행 상태와 버팀 게이지, 시작 버튼을 둔다. 모바일에서 기계 화면 위를 쓸면 문서/스튜디오를 스크롤할 수 있다.

## 3. 기계와 몬스의 모양

### 블렌더 제작 원본

기계 본체, 창틀, 유리, 상부 캡, 2축 레일, 이동부, 케이블, 삼발 집게, 조작판, 수취구를 Blender에서 제작한다. 편집용 `.blend`와 게임용 `.glb`를 분리한다. 기계의 이름과 색은 `claw-config.json`을 읽어 만든다. 현중의 추가 요청 「지금 그래픽 분위기 맞춰」에 따라 기존 몬스·보드 건물과 같은 모형형 입체감과 색을 기준으로 한다. 원본 몬스 제작의 거친 재질(roughness 0.86)을 참고해 실사 금속광택을 낮추고, 유리·금색은 작은 포인트로 제한한다.

- 편집 원본: `data/res/mons_claw_v01/mons_claw_machine.blend`
- 실행 모델: `data/res/mons_claw_v01/mons_claw_machine.glb`
- 제작 스크립트: `scripts/mons-claw/build_machine.py`
- 출처·노드·용량·제작 조건: 같은 자산 폴더의 `manifest.json`

제작 방향은 민트 본체, 크림 창틀, 피치색 조작판, 금색 집게, 따뜻한 내부 조명이다. 둥근 모서리가 있는 작은 수집용 장난감처럼 보이게 한다. 유리와 기둥이 인형의 얼굴이나 집게 끝을 가리지 않아야 한다.

블렌더 원본에는 인형 배치 미리보기와 카메라·조명을 포함한다. 게임용 기계 GLB에는 인형을 중복 넣지 않는다. 게임은 기존 몬스 원본을 별도로 불러와 공유한다. 모델 제작/출력의 실제 완료 여부는 작업 보고와 manifest로 확인한다.

### 실제 몬스 원본

`data/audition_sim/mons_pool.csv`에서 켜진 기본 10종을 읽고, `data/mons_proto/mons_catalog.csv`의 이름·색·가벼운 GLB 경로와 조합한다.

아홀로틀, 피그미하마, 나무늘보, 슈가글라이더, 레서판다, 페넥여우, 친칠라, 천산갑, 카피바라, 쿼카를 사용한다. 임의의 새 캐릭터를 대신 넣지 않는다. 원본 파일은 수정하지 않는다.

기본 진열은 설정의 `machine.toyPositions`에 있는 16개다. 같은 종이 여러 개 있을 수 있으며, 같은 GLB의 지오메트리를 공유하고 배치와 자세만 달리한다. 비행 애니메이션은 재생하지 않고 인형처럼 집게에 들린다.

## 4. 자동 뽑기의 한 판

| 단계 | 화면에서 일어나는 일 | 확인해야 할 점 |
| --- | --- | --- |
| 자동 이동 | 선택한 몬스 위로 레일과 집게 이동 | 이동부와 케이블이 집게 위치를 따라갈 것 |
| 하강 | 인형 높이까지 집게 내려옴 | 인형/집게의 크기와 높이가 맞을 것 |
| 조임 | 삼발 집게 닫힘 | 손가락이 인형 둘레를 감싸는 것처럼 보일 것 |
| 들기 | 인형이 바닥을 떠남 | 들리는 순간의 연결과 무게감 |
| 운반 | 출구 쪽으로 이동 | 기울기, 흔들림, 집게 벌어짐 |
| 출구 앞 | 테두리를 지나 마지막 이동 | 정말 들어갈 듯한 공간 관계 |
| 낙하·배출 | 내부 바닥으로 떨어지거나 수취구로 내려감 | 실패와 획득 경로가 다를 것 |
| 복귀·결과 | 집게 복귀, 결과와 몬스 표시 | 결과가 한 번만 처리될 것 |

현재 체험 타임라인은 `timing`으로 분리한다. 기본 합계는 7,070ms이며, **검수용 임시 연출값**이다. `tuning.speed`는 전체 연출 길이를 바꾸며, 운영 확률을 결정하는 값으로 쓰지 않는다. 실제 운영에 맞는 시간은 별도 검수한다.

## 5. 다단계 니어미스

| 결과 코드 | 장면 | 플레이어가 읽는 차이 |
| --- | --- | --- |
| `empty` | 집게가 제대로 감싸지 못해 빈손으로 올라옴 | 시작부터 아쉬운 헛집기 |
| `lift_slip` | 살짝 들자마자 손가락 사이로 빠짐 | 잡은 줄 알았는데 손끝에서 빠짐 |
| `carry_slip` | 공중에서 한쪽으로 기울다 낙하 | 잘 가져오다 중간에 놓침 |
| `rim_slip` | 출구 테두리 바로 앞에서 놓침 | 마지막 한 뼘을 버티지 못함 |
| `success` | 출구까지 버텨 수취구로 배출 | 마지막까지 불안하다가 안도 |

니어미스마다 인형의 회전, 낙하 시작 위치, 집게의 벌어짐, 그림자, 카메라 집중이 서로 맞아야 한다. 인형이 손과 떨어져 있는데 붙잡힌 것으로 보이거나, 이미 떨어졌는데 성공 글자가 뜨면 안 된다.

들기·운반·출구에서는 집게와 인형을 약간 크게 보여 주고, 대기·결과에서는 전체 기계가 보이는 기본 시점으로 복귀한다. 과도한 화면 흔들림이나 시야를 가리는 문구보다 인형 자체의 움직임을 우선한다.

## 6. 자동 판정과 연출 시험의 구분

### 자동 체험

`chooseAutomaticClawAim()`이 시드로 인형과 조준 오차를 고른다. `createClawRound()`가 그 위치, 집게 힘, 흔들림, 인형 조건과 시드로 **한 번만 결과를 정한다.** `sampleClawRound()`는 정해진 판을 시간별로 조회할 뿐 새 결과를 만들지 않는다.

현재 `judging`, `automation.aimJitter`, `tuning` 수치는 조작·연출을 비교하기 위한 임시 시안이다. 확정된 운영 성공률이나 보상률로 해석하지 않는다.

### 다섯 장면 비교

발란스 툴의 연출 스튜디오에는 헛집기, 들자마자 미끄러짐, 운반 중 빠짐, 출구 직전 빠짐, 획득을 각각 고르는 버튼을 둔다. 이 버튼은 명확히 **연출 시험**으로 표시한다. 같은 기준 몬스와 조건으로 장면 차이를 확인하는 용도다. 플레이어의 실제 확률 결과로 가장하지 않는다.

## 7. 발란스 툴에서 볼 것

운영 묶음의 「이벤트 게임」에서 같은 게임 원본을 연다. 기존 「이벤트 운영」의 시즌 경제 계산과 분리한다.

- 집게 힘: 버틸 수 있는 정도의 체험 판정 조건.
- 흔들림: 운반 자세와 임시 판정 조건.
- 연출 속도: 전체 타임라인 길이.
- 현재 단계, 조준 정밀도, 결과: 자동 체험과 강제 연출의 차이 확인.
- 이번 체험에서 만난 몬스: 메모리에만 남는 성공 표시.

새 주제를 떠나면 해당 iframe과 WebGL 장면을 해제한다. 게임 전체를 시작할 때마다 미리 읽어 두지 않는다.

## 10. 성능과 수명

몬스 원본은 종별로 한 번 로드하고 인형끼리 공유한다. 기계 GLB는 현재 게임을 열 때만 로드한다. DPR 상한, 그림자 크기, 장면별 자원은 코드와 자산 manifest에서 확인한다.

문서가 숨겨지거나 부모 발란스 화면이 숨겨지면 렌더와 진행 시간을 정지한다. 돌아왔을 때 숨긴 시간을 건너뛰어 결과를 바로 보여 주지 않는다. 화면을 떠나면 RAF, 관찰자, 이벤트, 지오메트리, 재질, 텍스처, 렌더러를 해제한다. 부모 메시지는 같은 origin과 실제 부모 창에서 온 boolean 값만 받는다.

## 11. 제작·검수 기준

1. 실제 Blender `.blend`와 출력 GLB, 제작 스크립트, manifest가 있어야 한다.
2. 기본 10종 원본을 읽어 16개 인형을 보여야 한다.
3. 사용자는 시작만 눌러야 하며 수동 조준 없이 결과까지 이어져야 한다.
4. 다섯 결과의 들림·낙하 위치/시점이 구분되어야 한다.
5. 성공/실패가 실제 집게·인형의 위치와 맞고 결과는 한 번만 처리되어야 한다.
6. 발란스 툴의 「이벤트 게임」과 P94 이벤트 선반에서 같은 원본이 실행되어야 한다.
7. 390×844 공통 프레임에서 버튼과 기계가 잘리지 않아야 한다.
8. 숨김 정지·복귀·화면 이탈·다시 열기를 확인해야 한다.
9. 운영 비용/확률/보상의 미정을 확정 숫자로 채우지 않아야 한다.
10. 기존 사용자 진행·원본 몬스·다른 게임의 표와 정산은 보존해야 한다.

이 문서는 개발 제안이다. 실제 구현·시험·화면 확인은 연결된 공용 작업 보고와 증거에서 구분한다.

## 12. 게임 시뮬레이터 공통 화면 연결 (2026-10-29 후속)

게임 시뮬레이터의 「이벤트 게임」은 모바일 화면·세로 게임 목록·개별 설정의 3열로 표시하며 처음에는 몬스 인형뽑기를 선택한다. 검색·종류 필터와 신규 태그를 사용하고, 선택해도 목록 위치와 스크롤을 유지한다. 공통 진행정보·예상성장·검수 안내는 이 페이지에서 빼고 전체 미니게임 시험 목적만 한 문장으로 안내한다. 별도의 휴대폰을 겹쳐 넣지 않는다.

- 왼쪽 상단: Blender 기계와 실제 몬스 3D 장면만 표시한다.
- 왼쪽 필러: 집기·들기·운반·출구의 진행, 집게 버팀, 한 판의 결과를 표시한다.
- 왼쪽 조작: 뽑기 시작/다시 뽑기 한 번. 직접 이동 조작은 없다.
- 가운데 목록: 검색과 종류 필터로 게임을 찾는다. 목록 자체에서 스크롤하고 선택 시 행만 강조한다.
- 오른쪽 설정: 선택한 인형뽑기의 집게 힘·흔들림·연출 속도와 자연 판정/다섯 연출 시험을 설정한다.

`src/simulator/mons-claw-host.mjs`는 화면 연결만 담당한다. `?embed=1&simulator=1` 앱은 장면만 채우고, 실제 판정과 시간은 기존 앱/순수 판 모델이 소유한다. 시작·설정 명령은 같은 출처의 실제 부모 창만 받을 수 있다. 준비 전/진행 중 조작은 양쪽에서 잠근다. 결과는 완료 뒤 전달하며, 지급은 하지 않는다.

메시지는 `monsClawHostControl`(상태 요청/시작/설정), `monsClawHostState`(진행 스냅샷), 기존 `monsClawHostVisibility`를 사용한다. 설정은 JSON의 허용 항목·범위·간격만 받는다. 운영 비용·보상 필드는 설정 대상으로 받지 않는다.

다른 시뮬레이터 탭으로 가거나 창이 숨겨지면 같은 판을 멈추고, 돌아오면 이어간다. 다른 이벤트 선택이나 최종 해제 때만 iframe·통신·로딩·임시 표시를 정리한다. 단독 페이지와 발란스 툴은 기존 스튜디오 구성을 유지한다.

공통 일반 보기에서 모바일은 내부 390×844 전체의 비율을 유지하며 창의 가로·세로 가용 공간에 맞춰 작아진다. 오른쪽 글과 기능의 내용을 축소하거나 없애지 않고 폭에 맞춰 줄바꿈·세로 확장한다. 오른쪽을 내려 보아도 왼쪽 모바일을 함께 확인할 수 있도록 화면 안에 머물게 한다. 크게 보기/팝업은 기존 전용 조작을 유지한다.

좁은 창에서는 게임 목록 열기 버튼으로 옆 목록을 열고, 선택·닫기·Escape 후 설정으로 돌아온다. 검색·필터·목록 스크롤을 유지하며 창이 넓어지면 열린 패널 상태를 해제한다. 기본 선택은 새 진입에만 적용하며 실제 게임에서 전달된 이벤트 요청과 사용자의 현재 선택을 덮지 않는다.

## 13. 몬스 미니 뽑기방 12기계 확장 (2026-10-30)
