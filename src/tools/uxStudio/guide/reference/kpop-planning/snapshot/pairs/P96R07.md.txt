상태: 제안(검수 대기) · 자동 3D 체험용 · 운영 발란스 대기. 작성: codex(단이), 2026-10-30. 현중 직접 요청: 최소 열 대의 다양한 기계를 둔 방, Blender 제작, 기존 기계·몬스 활용, 선택 시 카메라 접근. 추가 정정: 발란스 툴처럼 자동 진행과 기계 동작이 실시간으로 보이게 한다.

## 1. 확장 방향

기존 「몬스 인형뽑기」 한 대를 **열두 가지 뽑기 장치가 놓인 작은 방**으로 확장한다. 같은 기본 몬스와 민트·크림 장난감 분위기를 유지하면서, 기계의 지붕 모양·색·내부 도구·움직이는 방식이 구분되게 한다. 플레이어는 방에서 마음에 드는 기계를 고르고 시작을 한 번 누른다. 이후 겨냥·집기 또는 밀기·운반·낙하·결과는 자동으로 진행된다.

기존 모듈의 시작 한 번, 자동 타겟 선택, 다단계 니어미스, 실제 지급 발란스 대기 원칙을 유지한다. 기존 `mons_claw` 모듈 키와 실행 주소를 유지하고, 이벤트 선반과 발란스 주제의 설명을 뽑기방으로 갱신한다. 각 기계를 별도의 전역 미니게임 행으로 늘리지 않는다.

## 2. 방과 열두 기계

방은 좌우 다섯 대씩과 뒤쪽 두 대로 구성한다. 기계는 중앙 통로를 향한다. 전면 벽과 천장을 만들지 않고 좌우 벽을 낮춰 전체 보기에서 기계가 가려지는 것을 줄인다. 크림 바닥, 연한 민트·피치 타일, 뒤 벽의 클럽 간판, 중앙 벤치와 따뜻한 펜던트 조명으로 작은 장난감 가게 같은 분위기를 만든다.

외관은 기존 캐비닛의 본체·유리·조작판·실제 수취구를 재사용한다. 색만 바꾸는 대신 표준 지붕, 와이드 캡, 둥근 돔, 높은 크라운, 낮은 캡, 쌍봉 지붕의 여섯 형태로 나눈다. 수동 조이스틱 조작은 제공하지 않는다.

| 번호·ID | 기계 이름 | 보이는 핵심 장치와 자동 동작 | 화면의 네 단계 | 지붕 형태 |
| --- | --- | --- | --- | --- |
| 01 `claw` | 세 손 집게 | 삼발 집게가 닫혀 몬스를 들고 출구까지 운반 | 집기 → 들기 → 운반 → 출구 | 표준 |
| 02 `bridge` | 브리지 밀기 | 두 팔 도구가 막대 위 몬스를 밀어 기울이고 틈으로 이동 | 겨냥 → 밀기 → 기울기 → 틈새 | 와이드 캡 |
| 03 `scoop` | 바구니 스쿱 | 망 바구니로 떠 올린 뒤 바구니를 기울여 옮김 | 다가가기 → 뜨기 → 올리기 → 받침 | 둥근 돔 |
| 04 `hook` | 고리 걸기 | J자 후크가 회전·하강해 고리를 거는 동작 후 들어 올림 | 겨냥 → 걸기 → 당기기 → 출구 | 높은 크라운 |
| 05 `ball_hole` | 공 쏙 넣기 | 두 갈래 집기 도구, 공과 구멍판을 사용한 운반·낙하 동작 | 공 집기 → 운반 → 낙하 → 구멍 | 낮은 캡 |
| 06 `capsule` | 캡슐 회전 | 캡슐 회전판이 돌고 대상이 회전 경로를 따라 출구로 이동 | 회전 → 선택 → 구르기 → 열기 | 둥근 돔 |
| 07 `key_push` | 키 밀어 넣기 | 열쇠 모양 도구가 구멍판 쪽으로 전진하고 회전 | 높이 맞춤 → 겨냥 → 밀기 → 열림 | 높은 크라운 |
| 08 `press` | 톡 눌러 떨구기 | 피스톤과 눌림판이 하강해 몬스를 기울이고 밀어냄 | 이동 → 누르기 → 버티기 → 낙하 | 낮은 캡 |
| 09 `scissors` | 리본 자르기 | 고정 날과 움직이는 날이 맞물리고 리본 아래 대상이 낙하 | 접근 → 맞물림 → 자르기 → 낙하 | 높은 크라운 |
| 10 `ramp` | 데굴데굴 경사로 | 밀대가 몬스를 밀고 경사로 위 이동·회전·턱 넘기 연출 | 밀기 → 굴리기 → 턱 넘기 → 도착 | 와이드 캡 |
| 11 `magnet` | 자석 낚시 | 말굽 자석이 내려와 대상을 붙이는 동작 후 운반 | 내리기 → 붙기 → 들기 → 옮기기 | 표준 |
| 12 `swing` | 흔들 바구니 | 매달린 바구니가 좌우로 흔들린 뒤 크게 기울어 배출 | 받기 → 흔들기 → 기울기 → 출구 | 쌍봉 |

이 표의 이름·순서·설명·단계·배치는 `arcade-config.json`이 원본이다. 장치의 다른 모양은 Blender 기하에, 다른 움직임은 `arcade-round.mjs`의 방식별 경로에 있다. 구멍 통과·열쇠 삽입·리본 절단 등을 별도 충돌 해석으로 계산하는 물리 게임은 현재 구현 범위가 아니다. 현재 열두 방식은 공통 체험 판정을 받아 각 장치의 동작으로 보여 준다.

## 3. 플레이 흐름

| 순서 | 플레이어와 화면 | 잠금·다음 동작 |
| --- | --- | --- |
| 방 전체 | 열두 대의 방을 보고 기계 또는 옆 목록을 선택 | 기계를 고르기 전에는 뽑기 시작 비활성 |
| 기계 선택 | 선택 기계의 이름·설명·네 단계가 표시됨 | 이전 판 표시를 정리하고 카메라 이동 시작 |
| 카메라 이동 | 선택 기계가 화면에 들어오도록 부드럽게 접근 | 이동 중 시작·기계 변경·방 복귀 잠금 |
| 시작 한 번 | 「자동 뽑기 시작」을 누르면 대상 몬스·시드·결과를 한 번 생성 | 수동 조준 없이 자동 진행 |
| 자동 실시간 진행 | 장치와 몬스의 위치·회전·손가락 벌어짐을 시간에 따라 갱신 | 진행 단계·진행량·버팀 정도 표시, 판 진행 중 조작 잠금 |
| 낙하·결과 | 성공은 출구 좌표로 이동한 뒤 대상이 숨겨지고, 실패는 실내 쪽으로 떨어짐 | 완료 뒤 결과와 대상 몬스 표시, 결과 처리는 같은 판에서 한 번 |
| 다음 선택 | 같은 기계에서 한 번 더 하거나 「방 전체」로 복귀 | 방 복귀 시 판 표시를 비우고 전체 시점으로 이동 |

기계를 누르는 행위는 기계 선택과 카메라 이동이다. 판 시작은 별도의 버튼 한 번이다. 결과는 미리 만든 동영상 재생이 아니라, 현재 시간의 도구·보조 기구·몬스 자세를 3D 장면에 적용해 보인다. 결과를 연출 중간에 다시 추첨하지 않는다.

내부 타임라인은 `approach → engage → transfer → deliver → return → result` 여섯 구간이며, 플레이어에게는 기계마다 정한 네 단계 문구를 표시한다. 현재 각 기계의 기본 길이 7,800ms와 낙하 650ms는 **검수용 임시 연출값**이다. 연출 속도로 나누어 실제 판 길이를 바꾸며 확정 운영 시간이 아니다. 카메라 기준 이동값은 방 복귀 1,000ms, 기계 접근 1,050ms이고, 실제 프레임은 화면 비율과 모델의 크기에 맞춰 계산한다.

## 4. 자연 판정과 다섯 결과

자연 판정은 `round-model.mjs`의 기존 자동 조준·시드 판정을 재사용한다. 기계 ID와 시드로 대상을 고른 뒤, 조준 오차·대상과의 정렬·집게 힘·흔들림·인형 조건·시드 오차를 이용해 한 번 결과를 정한다. 같은 판을 시간별로 조회하는 `sampleArcadeRound()`는 결과를 변경하지 않는다.

현재 장치마다 고유한 운영 성공률을 계산하는 구조는 아니다. 공통 판정에서 나온 다섯 결과를 열두 가지 동작 경로로 표현한다. 장치별 정식 성공 조건·확률·비용·보상은 발란스 대기로 남긴다.

| 결과 코드 | 체험에서 읽는 차이 |
| --- | --- |
| `empty` | 잡기나 연결에 실패해 대상이 원래 자리에 남음 |
| `lift_slip` | 관여를 시작한 초반에 빠지거나 놓침 |
| `carry_slip` | 옮기거나 움직이는 중간에 이탈 |
| `rim_slip` | 출구에 거의 도착한 단계에서 놓침 |
| `success` | 마지막까지 이어져 출구 좌표로 배출 |

‘다섯 단계’는 **실패 네 종류와 성공 한 종류를 포함한 다섯 결과**다. 각 기계의 정확한 표현은 집기·밀기·회전·가위질·굴리기 등 해당 장치의 움직임을 따른다.

자연 판정과 별개로 헛집기·들자마자 미끄러짐·운반 중 빠짐·출구 직전 빠짐·획득을 직접 실행하는 다섯 연출 시험 버튼이 있다. 이 버튼은 장면 비교용이며 해당 판에 `reviewOnly`를 표시한다. 일반 시작 버튼은 자연 판정으로 새 판을 실행한다. 힘·흔들림·속도 슬라이더 역시 체험 검수용이다.

## 5. 몬스와 Blender 자산 재사용

기존 기본 몬스 원본의 얼굴·색·기하를 바꾸지 않는다. 앱은 `mons_pool.csv`에서 활성화된 몬스를 읽고 `mons_catalog.csv`의 이름·GLB와 연결한다. 현재 제작 자산은 기본 열 종을 그대로 재사용하며 종별 원본을 한 번 로드한 뒤 진열과 선택 대상이 공유한다. 방에는 기계마다 미리보기 세 개씩, 총 36개를 진열한다.

Blender 원본은 기존 `mons_claw_machine.blend`를 읽어 만든다. 본체의 정적 기하를 재질별 열 개 메시로 합쳐 열두 기계가 공유하고, 반복되는 기본 도형도 같은 크기·재질이면 기하를 공유한다. 지붕과 내부 도구는 기계 방식에 맞춰 구성한다.

- 제작 스크립트: `scripts/mons-claw/build_arcade.py`
- 편집 원본: `data/res/mons_claw_arcade_v01/mons_claw_arcade.blend`
- 게임용 방 모델: `data/res/mons_claw_arcade_v01/mons_claw_arcade.glb`
- 실제 Blender 미리보기: 같은 폴더의 `preview.png`
- 원본 해시·출력 해시·노드 계약·통계: 같은 폴더의 `manifest.json`

게임용 GLB에는 몬스·카메라·조명을 넣지 않는다. 편집용 `.blend`에는 원본을 공유하는 몬스 미리보기와 카메라·조명을 남긴다. 기존 원본 `.blend`와 열 종 GLB의 생성 전후 해시가 같은지 생성기에서 검사하며, 이번 결과는 동일했다.

노드는 기계 루트 `STATION_<id>`, 움직이는 도구 `TOOL_<id>`, 기계에 고정된 보조 기구 `SECONDARY_<id>`로 분리한다. 도구는 기계 기준 절대 위치·회전을, 보조 기구는 초기 자세에 대한 이동·회전 차이를 받는다. 삼발 집게는 기존 레일·이동부·단위 길이 케이블·세 손가락 피벗을 이름에 기계 ID를 붙여 재사용한다.

## 6. 성능과 수명

2026-10-30 제작 manifest 기준으로 Blender 5.2.1 LTS, Cycles CPU 16샘플, 1600×1300 미리보기다. `.blend` 1,974,119바이트, 방 GLB 2,815,328바이트다. GLB는 노드 486개, 메시 185종을 426개 객체에 사용하며 재질은 27개다. 화면에 그리는 기하 합계는 509,408삼각형이고 중복을 제외한 기하는 111,492삼각형이다. 이 값은 방 자산 자체의 통계이며 런타임에 별도 로드하는 몬스의 비용은 포함하지 않는다.

현재 렌더 설정은 DPR 상한 1.4, 최대 30fps, 그림자 맵 1024, 방 전체 보기 그림자 끔이다. 이는 제한 설정이지 실제 장치에서 30fps를 보장한다는 뜻은 아니다. 한 WebGL 렌더러로 방과 선택 기계를 보여 주고, 몬스 원본과 반복 기하·재질·텍스처를 공유한다. 변화가 없을 때 불필요한 렌더 요청을 멈추는 구조다.

브라우저 문서나 부모의 표시 신호가 숨김 상태이면 진행 시간과 렌더를 정지한다. 복귀 시 숨겨진 시간을 한꺼번에 더하지 않고 같은 판을 이어간다. 게임 시뮬레이터의 다른 모듈로 실제 전환하여 이 모듈이 해제되는 경우에는 iframe과 임시 체험을 정리하며, 다시 들어오면 방 전체에서 새로 시작한다. 장면 해제 시 진행 RAF, 카메라 이동, 로딩, 관찰자, 이벤트, 스켈레톤, 소유 자원과 WebGL 렌더러를 정리한다. 부모 제어·상태 메시지는 기존 호스트 계약을 사용하며 같은 출처의 실제 부모 창만 받는다.

## 7. 운영 발란스와 지급

| 항목 | 현재 상태 |
| --- | --- |
| 기계별 한 판 비용 | 발란스 대기 · 각 `economy.cost=null` |
| 기계별 운영 성공률 | 발란스 대기 · 각 `economy.probability=null` |
| 기계별 보상 | 발란스 대기 · 각 `economy.reward=null` |
| 장치별 고유 판정식·확률 분포 | 현재 공통 체험 판정 사용, 정식 운영 정의·검수 필요 |
| 한 판 결과 | 현재 페이지의 체험 결과 |
| 성공 몬스 표시 | 페이지 메모리의 임시 목록 |
| 실제 재화 차감·아이템 지급·소유권 저장 | 연결 없음 |

체험 상태는 `presentationOnly:true`, `granted:false`를 전달한다. 화면에서 몬스를 만났다는 결과가 떠도 실제 재화나 보상을 지급하지 않는다. 운영 수치의 `null`을 확정 0이나 예시 숫자로 바꾸지 않는다. 정식 지급 연결은 기존 이벤트 정산 계약에 맞춘 별도 작업으로 다룬다.

## 8. 게임 시뮬레이터 연결과 검수

게임 시뮬레이터의 기존 모바일·세로 게임 목록·설정 3열을 유지한다. 왼쪽에는 방/선택 기계의 실제 3D 장면과 현재 기계에 맞는 단계·진행량·한 번 시작 조작이 나온다. 오른쪽 설정에 12대의 선택 목록, 방 전체 복귀, 기존 체험 설정과 연출 시험을 둔다. 준비 전·카메라 이동 중·판 진행 중에는 충돌하는 조작을 양쪽에서 잠근다.

같은 출처의 실제 부모에서만 `selectStation`, `backToRoom`, `start`, `setTuning`, `getState`를 받는다. 기계 ID는 등록 목록으로 검증한다. 작은 단독 화면에서 아래 기계 목록이나 연출 시험을 선택하면 실제 장면이 보이는 위치로 화면을 이동한다. 부모는 선택/방 복귀 완료 응답을 기다린 뒤 시작 버튼을 연다. 구형 단일 기계 패킷은 기존 계약을 유지한다. `?solo=1`은 기존 단일 기계 비교용이며 기본 주소는 뽑기방을 연다.

검수 항목은 열두 기계의 전면과 전체 크기, 카메라 가림, 방식별 실제 도구·몬스 움직임, 네 단계 동기화, 다섯 결과, 화면 비율 변경, 숨김/복귀, 기계·게임 전환 해제다. 자동 시험과 실제 화면 확인 범위는 아래 공용 보고에서 구분한다.
