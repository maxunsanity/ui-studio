# P104 · 나쁜 기운 디펜스 · 대표 개발 기획서

**이 문서는** 보드에서 쌓이는 나쁜 기운과 시설을 지키는 몬스의 방어전을 설명합니다. 상시 방어 P104, 이벤트 전투 [P88](악귀디펜스_기획서.html), 몬스 자체의 정의 [P96](몬스_기획서.html)은 서로 다른 문서입니다.

**보는 법** 1장의 전체 흐름을 보고 3장에서 방어 시뮬레이터를 연 뒤 4장의 시설·몬스·스킬·보스와 승패를 읽어 주세요. 이전 상세와 변경 내역은 로그에 있습니다.

**지금 상태** 방어 시뮬레이터에는 최대 세 동의 시설, 몬스 협동 전투, 자동 스킬·팀 피니시, 난이도와 보스 3구간이 들어 있습니다. 전체 게임의 운영 게이지·보상·30단계 연동과 전 조합 발란스 검증은 현재 개발되지 않음, 진행 중입니다. 기존 디펜스의 실제 엔진·CombatVisuals·MotionAssets 원GLB/flight로 회전·타격33회·저장 접근0을 동작시험 화면에서 확인했습니다. 고HP 훈련용 fixture의 결과이므로 보상·승패·실제 발란스 검수와 구분합니다.

## 1. 개요

출처: (신규) [악귀와 몬스 제안](../../../../proposal-concept/bad-data.html) · [몬스 스킬 제안](../../../../proposal-concept/mons-skill.html). 이식 책갈피: 해당 없음.

나쁜 기운이 쌓이면 시설을 위협하는 습격이 생기고, 출전한 몬스가 건물 주변에서 악귀를 막는 흐름입니다. 플레이어는 방어하는 몬스들의 스킬을 고르고 팀 기술을 사용할 수 있습니다. 본관을 지키면서 남은 악귀와 보스까지 정리하는 것이 한 판의 목표입니다. 아래 그림은 게임의 관계를 설명하며, 게이지에서 전투·정산까지 정식으로 모두 연결되었다는 뜻은 아닙니다.

```mermaid
flowchart LR
 A[보드 활동] --> B[나쁜 기운 누적 기획]
 B --> C[습격]
 C --> D[몬스와 시설 방어]
 D --> E[남은 악귀와 보스 정리]
 E --> F[결과 확인]
```

### 콘텐츠 경계

P104는 상시 방어의 전투와 시험 범위를 다룹니다. 몬스의 종류·획득은 P96, 건물의 일반 성장과 수익은 [P106](건물성장_기획서.html), 이벤트 전투는 P88에 맡깁니다. 발란스 툴에서 나쁜 기운을 계산하는 모델과 실제 전투 시뮬레이터는 같은 화면이나 같은 승패 규칙이 아닙니다.

[나쁜 기운 디펜스 시뮬레이터](/docs/planning/game-simulator.html?module=simulator_module_bad_energy)를 열고 시설·편성·난이도를 확인한 뒤 전투를 시작합니다. 악귀의 진입과 몬스의 자동 대응을 보고 선택 카드가 나올 때 스킬을 고릅니다. 팀 피니시는 배운 뒤 버튼으로 사용하며, 선택 자체가 발동은 아닙니다. 본관이 파괴되거나 남은 적을 모두 정리하면 결과를 확인합니다.

이 시험은 전투의 동작을 보는 화면입니다. 전투에서 배운 스킬은 그 판의 것이며 영구 시설 성장과 구분합니다. 전투 중 저장·복원과 실제 게임 경제에 피해·보상을 되쓰는 일은 완료로 표시하지 않습니다. 이전 검수의 범위와 증거는 [통합 명세](../../20261015_방어진지보스3단_개발기획/05_통합개발명세.html)를 확인합니다.

### 4-1. 게이지와 전투의 연결

기존 기획은 주사위 굴림과 루머로 기운이 모이고 가득 차면 습격하는 흐름을 설명합니다. 시간·사건 경로와 하루 발생 횟수는 운영 발란스 대기입니다. 별도로 발란스 툴의 게이지 계산 모듈은 표에 값이 있는 굴림·루머·시간·날짜 경로와 상한을 사용하며, 그 툴 안에서는 습격을 항상 성공으로 계산합니다. 이는 실제 방어전의 승패와 파손 규칙을 확정한 것이 아닙니다.

```mermaid
flowchart LR
 A[굴림과 사건] --> B[게이지 계산]
 B --> C{기준에 도달}
 C -- 아니요 --> B
 C -- 예 --> D[습격 처리]
 D --> E[전투와 정산 연결은 별도 확인]
```

### 기획사 보유와 디펜스의 실제 편성

기획사에서 **실제 보유하고 선택한 몬스0~10마리**와 선택 순서를 읽습니다. 운영 정원은10이며 빈 보유·명시0을 다른 종으로 채우지 않습니다. 0마리일 때에도 기존 건물 지원 방어는 유지합니다. 보유 몬스 종을 재화처럼 소모하지 않습니다.

현재 몸 크기와 간격9.25를 보존하고 실제 공격·탐지를110으로 맞췄습니다. 몬스별 합성 횟수·공용 행복 재화·전투 중 자동 스킬 단계는 서로 다른 기록입니다. 행복은 합성 성공 때 적립하며 전투력이나 스킬 단계로 자동 환산하지 않습니다. 지급·교환·다른 사용처는 [P223](몬스보유_핵심제안서.html#mons-three-uses)을 따릅니다. 전체 전투 조합·희귀 모델의 화면 검수·실기기 성능은 별도 확인 범위입니다. 획득·합성 시험은 [기존 몬스 획득·합성 툴](/docs/planning/balance-tool.html?topic=balance_topic_mons_pack)에서 확인합니다.

### 4-2. 시설과 몬스의 행동

시험 방어 시설은 본관 하나와 부속 최대 두 동으로 구성됩니다. 각 건물은 체력·보석·파괴 상태가 따로 있습니다. 본관이 파괴되면 패배하고, 부속이 파괴되면 그 건물의 지원을 잃지만 전투는 이어집니다. 현재 시험에서는 시설 단계에 따라 부속이 붙는 구조를 사용하며, 9시설 30단계 기준으로 다시 맞추는 단계와 수치는 발란스 대기입니다.

몬스는 담당 건물 주변에서 기다리다가 열린 길목을 경계합니다. 악귀를 찾으면 안전한 공격 위치를 잡아 공격하고, 표적을 놓치거나 전투가 끝나면 담당 위치로 돌아갑니다. 다른 몬스와 표적을 나누는 협동 판단도 시험에 들어가 있습니다.

```mermaid
flowchart LR
 A[건물 주변 대기] --> B[길목 경계]
 B --> C[표적 추적]
 C --> D[위치 조정과 공격]
 D --> E{표적 유지}
 E -- 예 --> D
 E -- 아니요 --> F[건물로 복귀]
```

### 4-3. 자동 스킬과 팀 피니시

전투 시작 후 출전 몬스에게 서로 다른 자동 스킬을 하나씩 배분하고, 이후에는 각 몬스가 이미 배운 스킬을 강화하는 방식입니다. 팀 피니시는 별도의 후보에서 하나를 배워 팀 전체가 함께 사용합니다. 버튼을 누르면 연출 후 복귀하고 재사용 대기 시간이 지나야 다시 쓸 수 있습니다. 전투 종료 때 이번 판의 습득·강화·사용 상태는 초기화되며, 영구 시설 성장 값을 지우는 뜻은 아닙니다.

### 4-4. 악귀 무리·보스와 한 판 종료

쉬움·일반·도전은 시험에서 주로 악귀의 수와 동시에 열리는 길목의 수를 달리합니다. 보스는 하나의 체력을 세 구간으로 표시하고 구간에 따라 공격과 몬스 약화 효과가 달라집니다. 수치는 시험값이며 최종 승률은 아직 정해지지 않았습니다.

현재 시험의 240초는 전투가 무조건 끝나는 시간이 아니라 **일반 악귀의 새 출현을 정리하는 기준**입니다. 이미 살아 있는 적을 계속 상대하고, 예약된 늦은 보스와 호위의 예외도 처리한 뒤 모두 정리해야 승리합니다. 같은 순간 본관 파괴와 마지막 처치가 겹치면 패배가 우선입니다.

```mermaid
flowchart LR
 A[악귀 무리 출현] --> B[몬스와 시설이 방어]
 B --> C[보스 세 구간]

```

### 필요 시스템

시설별 체력과 파괴 상태, 몬스 편성과 협동 행동, 악귀 무리·보스·스킬 및 결과 표시가 필요합니다. 발란스용 게이지 계산과 실제 전투 승패는 각자의 규칙을 따릅니다.
