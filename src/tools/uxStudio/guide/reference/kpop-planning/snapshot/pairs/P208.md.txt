# P208 · 음원 제작 · 핵심제안

**이 문서는** 곡이 두 갈래(유저 창작곡 · 내부 발주곡 4장르 32~36곡)로 들어오고, 정규 앨범을 팀 칸 멤버 전원으로 발매하며, 솔로 · 유닛은 뮤비 제작 때만 고르는 음원 제작 흐름을 보여 줍니다. 규칙 원문은 [06 음원 이원화 · 앨범 · 음악 앱 연동](../../../인계/20261114_음악앱_클로드/01_기획서/06_음원정령음방_클로드.md)입니다.

**보는 법** 1장 흐름 → 3장 실행 → 5장 화면·상태를 보고, 저장/계산은 연결된 P191 상세에서 확인합니다.

**지금 상태** 현재 개발되지 않음, 진행 중. 파트 · 간편/프로 옵션 · 유료 시험 샘플 생성 · 다시 만들기 · 기존 제작/발매 · 앨범 목록/상단 상세는 소스에 연결되어 있습니다. 음원 이원화 · 발주곡 카탈로그 · 정규 앨범 팀 전원 고정 · 뮤비 솔로/유닛 선택은 현재 개발되지 않음, 진행 중이며 지금 앨범 화면에는 멤버 선택 UI가 남아 있습니다. 실제 AI 모델 · 회원 매칭 서버는 연결하지 않았습니다.

## 1. 개요

**곡을 고르고(창작곡 · 내부 발주곡) → 팀 전원으로 앨범을 내고 → 뮤비에서 솔로 · 유닛을 골라요.**

~~~mermaid
flowchart LR
 A["창작곡 · 유저 등록 .mp3"] --> C["곡 고르기"]
 I["내부 발주곡 · 4장르 32~36곡"] --> C
 C --> D["제작비 확인 · 만들기"] --> AL["앨범 발매 · 팀 칸 전원"]
 AL --> MV["뮤비 · 솔로 · 유닛 · 팀 선택은 여기만"]
~~~

한 곡이 한 장의 싱글입니다. 데뷔곡을 포함한 시즌 최대 8곡은 팀이 함께 사용합니다. 곡은 유저가 직접 등록하는 창작곡(`.mp3` 3분 이내, 검수 중 · 통과 · 반려)과 외부 음원 제작사에 발주한 내부곡(4장르 × 각 8곡 = 32곡, 댄스 팝 12곡이면 36곡) 두 갈래입니다(R-06-1 · R-06-2). 발주곡이 들어오기 전까지는 출처가 있는 샘플 10곡(`music_samples.json`)으로 동작하고, 발주곡이 들어오면 대체합니다(R-06-3).

## 3. 구동 방법·시뮬레이션

### 공용 게임 상단 메뉴

상위에는 **앨범 발매·페스티벌·응원 크루**를 둡니다. 앨범 하위에는 **음원 제작·시티 투어**, 페스티벌 하위에는 **방송·공연·음악 차트·음악 앱·배점/투표 시험**을 둡니다. 현재 공용 메뉴 데이터의 소속을 따르며 다른 메뉴를 열면 해당 하위 행을 숨깁니다. 관계·순서·문구는 [공용 메뉴 데이터](/data/simulator/menu.json)를 읽으며, 다른 보조 도구의 정리는 별도입니다.


[7007 P208 목록·카드](/docs/planning/planning-docs-tool.html?face=development&doc=P208&plan=planning_development_plan_todo_song) → 실행 → [공용 게임의 음원 제작](/docs/planning/game-simulator.html?module=simulator_module_music_production) 또는 하단 **앨범**입니다.

1. 정규 앨범은 팀 칸 멤버 전원으로 고정되어 멤버를 고르지 않습니다. 솔로 · 유닛 · 팀은 뮤비 제작 때 고릅니다(R-06-7).
2. 보컬·랩·코러스·제작 파트를 고릅니다. 확인되지 않은 목소리 정보는 이 앨범용으로 확인하며 실제 멤버 프로필은 바꾸지 않습니다.
3. 간편의 콘셉트 하나를 고르거나 프로에서 스타일·언어·빠르기·길이·가사를 조절합니다.
4. 제작비와 보유 돈을 보고 **만들기**를 누릅니다. 연결 중에는 중복 생성을 막습니다.
5. 완료되면 공연 이미지와 연결된 곡을 공통 영상 플레이어로 보고 이어지는 재킷·앨범 정보 화면에서 곡명·소개·재킷을 다듬습니다. **다시 만들기**는 같은 곡을 유료 재생성합니다.
6. 기존 기간·성장·미션·엔터파워 조건을 채우면 **앨범 제작 완료**로 넘어갑니다. 샘플 완료만으로 발매되지 않습니다.

직접 플레이·8곡 연속 발매·실제 정산 화면 검수는 사용자 확인 항목입니다. 이번 변경 후 자동 플레이나 브라우저 조작 시험을 새로 실행하지 않습니다.

## 4. 상세 기획

### 모바일은 현재 단계부터 보여 줍니다

앨범 진행 표시는 작은 점과 현재 단계 이름으로 줄입니다. **팀 전원 고정 · 곡 고르기 → 파트 → 간편/프로 음악 → 재킷·정보 → 제작/발매**에서 현재 선택과 필수 버튼을 먼저 보이며, 이전·다음·제작·발매 버튼은 기존 하단 공통 슬롯에 둡니다. 본문만 세로로 스크롤하고 가로 잘림이나 버튼 내부 스크롤을 만들지 않습니다.

멤버와 음악 옵션은 읽을 수 있는 크기를 유지합니다. 제작비 상세·발매 전 예상 순위·참여 파트의 계산 설명은 선택 영역 뒤에 배치하며, 참여자 상세는 요약 아래에서 펼칩니다. 재킷은 작은 정사각형 미리보기와 편집 필드를 함께 보여 주고 긴 소개·부가정보는 아래로 이어집니다. 비용·부족 사유·실패 안내를 생략하거나 임의로 잘라 숨기지 않습니다.

### 영상 미리보기와 뮤직비디오 제작 상태

**현재 미리보기:** 10차의 공통 영상 플레이어와 공연 이미지3종을 재사용합니다. 동영상 파일을 새로 만드는 기능이 아니라, 공연 이미지와 해당 앨범에 연결된 검증 샘플을 함께 보여 주는 시험 시뮬레이터입니다. 별도의 audio/video 플레이어를 중복 생성하지 않습니다.

샘플 준비 후 **영상으로 미리보기**를 누르면 이미 생성된 music controller의 openAlbumVideo(album,current,{preview:false})를 호출합니다. 앨범 초안·제작·발매 원장, 생성 작업·제작비·환불을 쓰지 않습니다. 같은 공통 플레이어로 복귀/닫기를 처리하며 원곡·저작자·라이선스 링크는 유지합니다.

**뮤직비디오 제작: 기획 준비중.** 실제 동영상 생성·동작 영상 공급은 추가 기획/연결 대상입니다. 10차의 현재 결과는 정지 공연 이미지와 지속 미디어 플레이어이며 실제 영상 생성 완료로 표시하지 않습니다. 나중에 실제 파일이 공급되면 기존 album.media.videoSrc 또는 album.video.src의 검증된 /assets/ 경로로 연결합니다.

| [공통 음악/영상 UI](/src/simulator/music-career/music-app-panel.mjs) | 기존 controller 1개·openAlbumVideo·닫기/복귀 |
| [미디어 엔진](/src/simulator/music-career/music-player.mjs) | 지속 media element 하나 |

### 제작 전에 보는 대략의 시작 순위

**팀 칸 전원 고정 · 곡 고르기 → 현재 멤버 능력·팬으로 예상 순위 확인 → 음악/재킷 → 발매 때 실제 시작 순위 확정** 순서입니다. 첫 음반도 현재 팀과 참여 멤버의 능력을 반영합니다. 다음 음반은 같은 계산에 직전 앨범의 최종 성적을 더합니다. 화면의 예상은 대략의 범위이며 발매 때의 능력·팬·새 상대에 따라 달라집니다.

팀 평균과 참여자 평균이 모두 원점수500이고 팬이 없는 수학 예시는 **대략40~53위**입니다. 음반 차수로 등수를 강제하지 않으며 2번째부터도 같은 공통 계산을 씁니다. 가중치·곡선·상한·예상 범위 폭은 [음악 규칙 데이터](/data/music_career/music_career_rules.json)의 `albumLeague.entry`에서 조절합니다.


### 음악 다음에 재킷, 발매 다음에 차트

**음악 완성 → 재킷·앨범 정보 확인 → 제작 완료 → 발매 → 약2.8초 순위 공개 → 이 곡 차트** 순서입니다.

| 단계 | 보이는 것·행동 |
|---|---|
| 음악 준비 | 샘플을 듣고 이번 앨범의 고정 참여자를 확인 |
| 재킷·앨범 정보 | 기존 구성3종·색상3종을 바꾸며 크게 미리보기. 곡명/앨범명/소개도 수정 |
| 고정 버튼 | 앨범으로 / 이 재킷으로 다음. 반영 후 같은 앨범 ID에 저장 |
| 제작·발매 | 기존 조건을 검사하고 제작 완료·발매. 재킷 확인이 비용을 다시 청구하지 않음 |
| 발매 연출 | 참여 멤버·저장 재킷→발매 표시→재킷이 차트 행으로 이동→계산된 순위·남은 시간 |
| 차트 이동 | 연출 종료 또는 고정구역 차트 보기로 같은 곡 차트에 자동 이동 |
| 크루 공유 | 실제 공유 게시물이 연결됐을 때만 작은 완료 한 줄 |

재킷은 기존 템플릿·팔레트 기능을 연결한 것이며 AI 이미지 생성이 아닙니다. 편집 후 목록·차트·상단 상세와 연출에서 같은 저장값을 사용합니다. 발매한 앨범의 과거 재킷을 소급 변경하지 않습니다.


### 공용 고정 버튼 구역

이전·다음·음악 만들기·재생성·앨범 제작/발매의 주동작은 **기존 게임 공용 버튼 구역**에 둡니다. 내용·멤버 목록·파트·옵션만 스크롤합니다. 버튼을 찾으려고 맨 아래로 내려갈 필요가 없습니다.

| 위치 | 표시 |
|---|---|
| 본문 | 멤버/파트/음악 옵션·샘플·곡 정보·조건·상세 설명 |
| 고정 버튼 위 | 필요한 돈·보유 돈 한 줄과 차단/처리/오류 요약 |
| 고정 버튼 | 현재 단계의 이전/다음/제작. 생성 중 잠금·미충족 비활성화 유지 |
| 메뉴 이동 | 음악 버튼은 숨기고 기존 다른 기능의 버튼 구역을 복원 |


### 단독 실행과 연계 실행

| 실행 | 데이터·돈·조건 |
|---|---|
| 음악 도구 단독·메인/다른 메뉴에서 진입 | 기존 생성 테스트팀을 유지하고 **돈99,999,999**로 시작합니다. 최초1회 지원이며 사용한 돈은 재접속해도 유지합니다 |
| 연계 팀/오디션/발란스 전송 | 전달된 팀·지갑·성장·조건을 사용합니다. 단독 지원금과 조건 변경을 적용하지 않습니다 |
| 이전 단독 저장 | 유효한 저장이면 진행·영수증을 유지하고 최초지원 기록만 남깁니다. 검증된 초기 카드 투영은 카드/멤버/원장을 보존해 연결. 손상/출처충돌 저장은 덮어쓰지 않고 사유 표시 |
| 제작 조건 시험 | 단독에서는 기존 시험조건 적용기를 사용해 현재 성장/시설로 제작을 시험합니다. 실제 엔터파워·미션을 올리거나 운영 조건 통과로 기록하지 않습니다 |

단독 초기화는 현재 테스트팀의ID·보드위치·시설을 그대로 사용하고 지갑/스냅샷을 기존 공통 저장 경로로 연결합니다. 생성/제작/발매 상태와 최대8곡은 유지합니다. 단독환경의 보유 팬이 실제0일 때만 명시 테스트용0계층 입력을 사용합니다. 연계 팬이나 미관측 값을0으로 꾸미지 않습니다.

### 화면 단계와 공용 UI

음악을 고른 뒤에는 **앨범 활동 준비** 단계를 유지하고 해당 음악 폼으로 이어집니다. 멤버 선정으로 되돌아가거나 데뷔 준비 첫 화면을 다시 보여 주지 않습니다. 실제 방송·공연은 발매 후에 열립니다. 스크롤 밖 공용 고정 버튼 바로 위에 필요/보유 돈·차단 사유·처리중/오류를 표시합니다. 단계 전환/사용자 조작 결과 때만 해당 안내를 보여 주고 주기 갱신은 스크롤을 유지합니다.

본문에는 단독 테스트·지원금·시험조건 안내 박스를 추가하지 않습니다. 현재 잔액과 제작비·진행을 막는 이유만 해당 위치에 표시합니다.

화면은 기존 시뮬레이터와 같은 **크림 배경·보라색 정보/선택·민트색 완료 표시·둥근 카드/버튼**을 사용합니다. 참여 멤버 이름·선택 테두리·입력·오류 안내와 상단 앨범 상세도 같은 대비로 맞춥니다.


### 누구의 싱글인가요?

정규 앨범은 **팀 칸 멤버 전원**이 참여하고 크레딧에 오르며, 앨범에서 멤버를 골라 넣는 옵션은 숨깁니다(R-06-7). 파트에 따라 여성/남성/혼성·솔로/다인·랩 구성을 계산하고 음악 설명에 반영합니다. 제작만 맡은 멤버는 노래 인원에서 뺍니다. 이름·그림으로 성별을 추측하지 않습니다.

앨범 참여계수는 보컬100%·랩60%·코러스40%·제작70%의 **로컬 현재 세팅값**을 데이터에서 읽습니다. 복수파트는 가장 큰 계수를 쓰고 대상 능력 비율을 그 멤버 안에서 나눕니다. 플레이어가 보상 숫자를 직접 입력하지 않습니다.

### 어떤 음악인가요?

| 모드 | 선택 |
|---|---|
| 간편 생성 | 청량한 데뷔·강렬한 퍼포먼스·감성 팬송·몽환적인 밤 |
| 프로 생성 | 댄스 팝/힙합/R&B/발라드·콘셉트·한국어/영어/일본어·빠르기·30/60/180초·선택 가사 |

보컬은 앞에서 정한 구성으로 계산합니다. 제작 참여만 고르면 연주곡입니다. 두 모드는 같은 샘플 연결기를 사용합니다. 저장한 옵션은 ACE-Step의 Python/REST 입력으로 변환할 준비만 하며 실제 요청을 보내지 않습니다. 선택한 목소리·가사·길이가 무료 샘플에서 그대로 구현되는 것은 아닙니다.

### 음악 만들기 비용

| 싱글 차수 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 첫 음악 만들기 · 기존 돈 | 5,000 | 7,500 | 10,000 | 12,500 | 15,000 | 17,500 | 20,000 | 22,500 |
| 다시 만들기 · 기존 돈 | 2,500 | 3,750 | 5,000 | 6,250 | 7,500 | 8,750 | 10,000 | 11,250 |

실행자가 정한 **로컬 시험 발란스**입니다. 기존 게임 돈을 사용하고 만들기 전에 **필요·보유·부족 금액**을 보여 줍니다. 돈이 부족하거나 현재 지갑 원본을 읽지 못하면 시작하지 않습니다. 다시 만들기는 성공한 샘플이 있는 같은 앨범에 적용하며 비용은50%입니다. 첫 생성이 실패해 샘플이 없으면 다음 시도는 첫 제작비입니다.

요청/작업이 같으면 한 번만 결제합니다. 샘플 파일을 연결하지 못해 작업이 실패하면 해당 제작비를 한 번 환불합니다. 제목 수정·샘플 듣기·제작 완료·발매 버튼은 이 제작비를 다시 청구하지 않습니다. 실제 AI 토큰이나 현금 결제는 없습니다.

### 다시 만들기와 완료

발매 전의 초안·제작 완료 앨범은 다시 만들 수 있습니다. 기존 앨범 ID·차수·수정한 제목·소개를 유지하고 새 작업을 만듭니다. 새 샘플이 성공하기 전까지 기존 샘플을 보존합니다. 제작 완료였더라도 다시 만들면 초안으로 돌아가 조건을 다시 검사합니다. 발매한 앨범은 재생성하지 않습니다.

| 싱글 차수 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 필요 엔터파워 | 50 | 100 | 130 | 160 | 190 | 220 | 250 | 280 |

위 엔터파워는 로컬 시험 기준입니다. 기간·미션·성장과 함께 제작/발매 때 검사하며 현재값 미공급을0으로 바꾸지 않습니다.

### 발매 후1일 추가 성장

차트 순위에 따른 추가 효과는 **앨범 이벤트 재화·팬·고정 참여자 능력**입니다. 다음1번 출발점 통과 때 정산합니다. 앨범 추가 현금은0이며 기존 보드 돈은 유지합니다. 능력은 멤버별 기본량×참여계수×파트별 능력 비율이며 인원수로 나누지 않습니다. 게임 연결 코드는 구현했고 자동 발란스의 개별 멤버 writer는 연결 대기입니다.


### 솔로·유닛·팀의 참여와 보상

**정규 앨범은 팀 칸 전원 참여입니다.** 솔로 · 유닛 · 팀 선택은 뮤비 제작 때만 고르고 뮤비 크레딧에만 표시합니다(R-06-7, 11/13 #35). 아래 솔로 · 유닛 보상 설명은 앨범에 멤버 선택 UI가 있던 구 계산 구조의 기록이며, 정규 앨범의 추가 능력 대상은 팀 칸 멤버 전원입니다.

**능력은 참여자 각자의 몫, 이벤트 재화는 팀에 한 번**입니다. 같은 순위·활동량·배수·파트·개인 상태라면 한 멤버의 요청량은 솔로·유닛·팀에서 같습니다. 개인 보상을 참여 인원이나 참여계수 합계로 나누지 않습니다. 기존 파트 계수·세부 능력 비율·개인 성장 상한은 적용하며, 미참여자는 그 앨범의 추가 능력을 받지 않습니다.

| 설명용 예시 · 같은 파트·조건, 개인 상한 여유 있음 | 개인 능력 증가 | 기존 팀 평균 능력 증가 | 이벤트 재화 |
|---|---|---|---|
| 1명 팀의 솔로 | 그 멤버 +10 | +10 | 팀에 10개 |
| 5명 팀의 전원 참여 | 각자 +10 | +10 | 팀에 10개 |
| 5명 팀 중 3명의 유닛 | 참여자 각자 +10, 나머지 0 | +6 | 팀에 10개 |
| 5명 팀 중 한 명의 솔로 | 참여자 +10, 나머지 0 | +2 | 팀에 10개 |

표의 +10·재화10개는 단위를 설명하는 예시이며 새 발란스 값이 아닙니다. 기존 팀 능력은 현재 팀 전체 멤버의 평균으로 다시 읽습니다. 개인 증가 합계를 팀 능력에 한 번 더 더하지 않습니다. 유닛 전용 가산 보상은 없으며, 참여자가 많다는 이유만으로 재화·직접 팬을 늘리지 않습니다. 실제 순위·활동 실적·파트·개인 상한이 다르면 결과가 달라질 수 있습니다.

오른쪽 상세에서 순위별 적립 기준과 고정 참여자별 능력 요청량을 구분합니다. 실제 지급은 START 영수증의 개인별 증가량으로 확인하고, 상한 때문에 못 받은 능력을 다른 멤버에게 옮기지 않습니다. 자동 발란스의 개별 멤버 writer는 연결 대기이며, 이번 확인은 소스 대조입니다.


### 시티 투어에서 이벤트 재화 사용

앨범 활동으로 정산받은 이벤트 재화는 [시티 투어](새도시진출_핵심제안서.html) 참가비로 소비합니다. 기존 하늘길 계산/봇을 재사용한 투어 밴5팀 가로 레이스이며, 1등의 공연 수익은 기존 돈 영수증으로 한 번 지급합니다. 앨범 추가 능력·팬 보상과 별도이고 실유저 대결은 서버 검증 결과만 정산합니다. 현재 로컬 시험은 기존 봇4팀으로 표시하며 실제 서버는 연결하지 않았습니다.


### 현재 팀 연계와 시험 자료의 경계

앨범 제작·발매·차트·시티 투어는 같은 현재 session/run/season/team의 관측을 사용합니다. 같은 창의 성장 알림으로 지갑·능력을 다시 읽고, 우측 앨범 데이터 연결에서 입력 상태와 조건 대기를 구분합니다. 원시 팬층 누락/손상은0으로 바꾸지 않습니다. 선택 공급자의 데뷔 기준일·미션 완료 영수증·팬층은 동일 revision/checkpoint 증거일 때만 메모리에서 채택하며 돈·능력·멤버·전체 저장을 교체하지 않습니다. 공급 API·현재 빠진 원천과 비어 있음 조건은 [앨범 연계 계약](앨범발매_기획서.html)을 따릅니다.

명시 시티 단독 시험은 현재 시험 멤버로 고정 참여자 있는 시험곡·리그·최초 급유 재화를 준비합니다. 이 시험 준비를 실제 연계 팀에 적용하지 않습니다. 실제 노래 생성/제작비 청구는 생략한 메타데이터 시험이며, 기존 초안·편집·종료 이벤트는 보존합니다.

기존 비용 그림은 기능 설명용이며 최신 화면의 색상은 공용 크림·보라·민트 테마입니다.

그림은 설명용 UI 시안입니다. 실제 조작은 [게임의 앨범](/docs/planning/game-simulator.html?module=simulator_module_album_release)에서 합니다. [멤버·간편/프로 옵션 시안](../../../증거/20261103_142753_단이_9차_앨범크루_월드페스티벌_통합개발/planning-ui/album-generation-options.html)은 저장하지 않는 비교 자료입니다.

| 범위 | 현재·남은 일 |
|---|---|
| 멤버/파트·간편/프로·샘플 생성·재생성·제작비/환불 | 로컬 구현. 최신 직접 플레이는 사용자 확인 |
