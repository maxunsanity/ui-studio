# P222 · 유저 저장 정보 · 대표 개발 기획서

**이 문서는** 게임이 무엇을 어디에 저장하고, 시즌이 바뀔 때 무엇이 남는지 정리한 대표 개발 기획서입니다.

**보는 법** 1장 그림 → 4장 「한 판 순서」 → 핵심제안 개발의 「시즌 끝 저장 시뮬레이터」 순서로 읽습니다. 세부 결정과 근거는 책갈피 [P203 유저 저장 보완판](../../기획서/산출_기획서_유저저장_보완판_v1_클로드.md)에 있습니다.

**지금 상태** 서버 정본·계정/시즌 통합 저장은 기획 중·작업전입니다. [P173](유저저장정보_기획서.md)의 로컬 저장은 부분 구현이며, 시즌 끝 저장 시뮬레이터는 저장·API 없이 범위를 보여 주는 표시 시안입니다. 확인 범위와 남은 작업은 [7장](#part-7)에 적었습니다.

## 1. 개요

출처: (합침) 기존 개발 기획서 [P173 유저 저장 정보](유저저장정보_기획서.html) · 책갈피 [P203 유저 저장 보완판](../../기획서/산출_기획서_유저저장_보완판_v1_클로드.md) · 현중 11/01~11/02 지시

이 문서의 서버 정본·계정/시즌 범위는 P203의 제안 결정안을 정리한 기획 목표입니다. 현재 로컬 구현과 실구동 검수 범위는 P173과 7장에서 구분합니다.

> **핵심** **정본은 서버 하나**이고 기기 저장은 임시 캐시입니다. 저장 항목은 **계정 범위(시즌이 바뀌어도 남음)**와 **시즌 범위(60일째 정리)**로 나누고, 투표 · 순위 · 크루 · 게릴라처럼 여러 유저가 얽히는 기록은 반드시 서버에서 정합니다.

```mermaid
flowchart LR
  A[기기 저장 · 캐시] --> B[서버 · 정본]
  B --> C[계정 범위 · 남음]
  B --> D[시즌 범위 · 60일째 정리]
  E[연락처 · 마케팅 동의] -.->|따로| B
```

### 콘텐츠 경계

- 맡는 것: 정본 · 두 범위 · 충돌 복구 · 새 기획 저장 항목 · 연락처 분리.
- 다른 문서에 맡기는 것: 시즌 끝 표 → [P214 시즌](시즌_핵심제안서.html) · 자원 → [P212 게임 경제](게임경제_핵심제안서.html).

### 현재 기준과 목표

| 범위 | 무엇 |
|---|---|
| 계정 | 유료 재화 · 보관함 카드 · 명예의 전당 · 크루 소속 · 곡 권리 동의 기록 · 기획사 몬스 인벤토리(모은 종) |
| 시즌 | 보드 경제 · 지갑 · 시설 · 아이돌 성장 · 아이돌 전용 카드 · 중복 장수 · 카드 트레이드 기록 · 몬스 합성 단계 · 팬 · 곡 · 피드 · 투표 · 채점 · 지역 방문 · 입장권 |
| 따로 | 연락처 · 마케팅 동의(게임 저장과 분리 · 철회 바로 반영) |

- 충돌하면 서버 우선. 구매 · 투표 · 증축 · 카드 트레이드처럼 한 번만 일어나야 하는 일은 요청 ID로 두 번 반영하지 않습니다.
- 자리 비운 동안 진행은 서버가 오프라인 보상으로 계산합니다.

## 3. 구동 방법·시뮬레이션

화면 흐름: 접속 → 서버와 맞춤 → 플레이 → 저장 · 스샷 미완 · 이식 비교 해당 없음

- 실행: 이 기획의 서버 정본·계정/시즌 통합 저장은 작업전입니다. P173의 로컬 인계·저장 경로와 구분합니다.
- 핵심제안 개발의 **시즌 끝 저장 시뮬레이터**에서 시즌 끝을 누르면 계정 범위는 남고 시즌 범위는 정리되는 것을 봅니다. 숫자는 모두 임시 시안입니다.

## 4. 상세 기획

### 한 판 순서 (임시 시안)

| 점검 | 내용 |
|---|---|
| 시작·종료 | 접속하면 서버와 맞춰 봄 |
| 입력·출력 | 입력 = 플레이 결과 / 출력 = 서버 저장 |
| 상태와 전이 | 플레이 → 요청 → 서버 반영 → 기기 캐시 |
| 판정 | 서버 우선 |
| 오류·예외 | 같은 요청 두 번 반영 막기 · 오프라인은 서버 계산 |
| 저장·복원 | 계정 범위 · 시즌 범위 |
| 다른 모듈 연결 | 모든 콘텐츠 |

### 지금 저장 묶음과의 관계 (임시 시안)

지금 저장 묶음 6개(보드 경제 · 성장 스냅샷 · 체크포인트 · 오디션 인계 · 허브 · 시험 세션)를 시즌 범위 안의 칸으로 묶는 기획안입니다. 현재 로컬 저장을 서버 계정·시즌 통합 기록으로 전환하는 구현은 작업전입니다.

### 필요 시스템

서버 계정 · 동기화 · 요청 ID · 오프라인 계산 · 시즌 끝 처리 · 연락처 별도 저장.

### 화면·연출 목록

해당 없음(저장은 화면 없이 동작).

### 남은 결정

- 투표 기록 · 개인정보 보관 기간 — 운영 · 법무
- 서버 기술 · 저장 형식 — 개발

## 7. 개발 진행·검수

확인 범위: 시즌 끝 저장 시뮬레이터는 메모리 상태와 문구만 바꾸며 저장이나 서버 API를 호출하지 않습니다. 성장 화면의 보호된 직접 호출부와 실제 저장·복원·시즌 전환·동시 저장·실패 복구는 검수하지 않았습니다.

| 요소 | 상태 | 확인 방법·증거 | 다음 작업 |
|---|---|---|---|
| 기획(이 문서 · 책갈피 상세) | 기획 중 | P203 · 이 문서 | 현중 확인 |
| 시즌 끝 저장 시뮬레이터 | 개발 끝(표시 시안) | 메모리 상태와 범위 문구만 변경 · 저장·API 없음 | 실제 표 연결 |
| 서버 정본·계정/시즌 통합 저장 | 기획 중 · 작업전 | 로컬 저장·표시 시안과 분리 | 표 확정 뒤 |

### 수락 기준

서버가 정본이고, 계정 범위 항목이 시즌 끝에도 남으며, 연락처가 게임 저장과 분리되어야 합니다.

### 뺀 것·옮긴 것·보존한 것

세부 결정과 근거는 책갈피 P203에 둡니다. 기존 개발 기획서 P173은 그대로 보존하고 2장에서 연결합니다.
