### 목록과 phone 프레임 안 전체 연출 분리 · 최신 본게임 UX

**현중 직접 결정:** 목록은 목록만 표시하고, 이야기에 들어가면 공통 모바일 phone 프레임 안 전체로 연출합니다. 프레임 밖 시뮬레이터 메뉴·설명은 그대로 두며 여정·가상 뉴스·몬스 출동·대결에 공통 적용합니다.

1. 처음에는 모드와 이야기 카드 목록만 보여 줍니다. 캔버스·상시 폰 화면·옆 컷목록을 목록과 함께 펼치지 않습니다.
2. 이야기 카드를 선택하면 같은 모바일 phone 프레임 안을 채우는 연출로 전환합니다. 웹뷰 전체 또는 `100dvh`를 본게임 기준으로 삼지 않으며, 프레임 밖 시뮬레이터 메뉴·설명은 유지합니다.
3. 장면이 화면의 주역이 되고, 하단에는 얇은 HUD로 마일스톤·참가자·재생/다음/장면 스킵/콘티 조작을 모으는 방향입니다. 장문 설명과 기술 정보는 접힌 콘티 정보에서 읽습니다.
4. 본게임 목록 복귀·재진입은 기존 run의 실제 시각·저장·정산 계약과 표현 생명주기를 분리해 연결합니다. 독립 시안의6/39초 보존·정지 재진입·첫 진입 자동재생 확인은 이전 UI 이력이며 현재 본게임의 최종 동작을 검수한 기록이 아닙니다.

390×844 폰 안 상시 미리보기와 옆 컷목록은 **이전 버전 검수 이력**입니다. 09:49:28의 대표 시안 확인 기록도 보존하지만, 최신 큰 연출 화면의 실측·검수 완료를 뜻하지 않습니다. 현재 시안의 대표 실화면 QA는 7장 후속절에서 확인하며, 그 범위를 넘어서는 접근성·로딩 실패 복구·전체 모바일 프레이밍 확인은 별도입니다.

### 아이돌과 분신 몬스의 관계를 명확히 하기

여정에서 친해지는 주체는 아이돌입니다. 도시 화면에는 해당 아이돌의 몬스 분신을 보여 줍니다. 참가 줄은 **아이돌 이름 → 연결 몬스 얼굴** 순서로 읽히게 하며, 주목쌍도 실제 아이돌 두 명의 `candidate_id`로 선택합니다. 성격·배경·라포는 그 아이돌의 원본을 읽고, 몬스 종족의 성격을 새로 붙이지 않습니다.

이전 독립 시안은 실제 합류팀을 읽지 않아 `예시 아이돌 A~E`를 사용했습니다. 현재 본게임은 실제 합류 ID·이름·연결 몬스를 사용하며 이전 예시를 현재 팀으로 대체하지 않습니다. 몬스 종류는 현재 원본 자산을 검토하기 위한 것으로 아이돌 성격·종족 능력·라포 보정을 뜻하지 않습니다.

같은 몬스 외형을 쓰는 서로 다른 아이돌도 이름과 참가 ID로 구분해야 합니다. 필요한 아이돌·몬스 연결 자료가 없으면 임의 친구나 대체 종족으로 채우지 않고 연결 대기로 표시합니다. 한 run 안의 중복 아이돌 ID는 막고, 여러 run 간 같은 아이돌·같은 경로는 기존 계약대로 허용합니다.

출동 참가 정산은 기존 `adventureMons()`의 `ownerId`와 receipt의 원래 아이돌 ID 연결을 유지합니다. 출동 연출에서 몬스들이 협력해도 아이돌 라포를 자동 올리지 않습니다.

### 모노 연출과 최신 도시 연출의 우선순위

기존 P152의 모노 출발 비행·이동 스택·배경 슬라이드 재사용은 **이전 구현 이력**으로 보존합니다. 이번 최신 방향은 현재 40칸 3D 도시·뒤에서 낮게 따라가는 카메라·아이돌 분신 몬스의 보행입니다. 모노 폴더를 수정하거나 현재 도시 대신 옛 숲·다른 도시 배경을 현행 정본으로 되살리지 않습니다.

초기 도시 콘티의 모노 연출 이력은 P152 설명을 근거로 보존했습니다. 후속 기록장 작업에서는 모노 AdventureView/SocialFeedView 원본을 직접 읽어 내부 진입·목록·기억 연결 경험을 참고했으며, 원본 수정·수치/종/카드 복사는 하지 않았습니다. 기존 실행 모듈과 새 검토 시안을 병행 구현 정본으로 운영하지 않습니다. 검토 후 본게임 반영을 맡길 때 현재 모듈의 표시 계층을 교체하는 범위를 별도로 정해야 합니다.

## 2. 도시와 건물에 맞춘 여정 아이디어 9개

아래 아이디어 전부 **제안(검수 대기)**입니다. 목적 건물과 활동의 의미를 연결하되, 보드의 해당 칸을 밟았을 때 주는 성장·돈을 여정에도 자동 중복 지급하지 않습니다. 활동 문구는 실제로 제공된 성격·배경으로 조합하며 빈 정보를 임의 작성하지 않습니다. 기념은 검토 중인 비재화 기록 아이디어이며 신규 아이템 지급 확정이 아닙니다.

40칸 길은 이동을 위한 공통 공간입니다. 여정이 5번 정산·6번 쟁탈전 등 비목적 칸을 지나더라도 그 칸의 보드 턴 효과·돈·전투·자동 레벨업을 발생시키지 않습니다. 건물 내부 장면은 현재 시안의 필수 리소스가 아니며 문 앞 도착과 건물 외관으로 의미를 전달합니다.

## 3. 같은 도시에서 일어나는 출동 아이디어 4개

아래의 사건과 해결은 **게임 내 가상 사건 / 제안(검수 대기)**입니다. 나쁜 기운은 기존 세계관의 시각적 표현이며 실제 뉴스·현실 재난·도시 안전 정보가 아닙니다. 상금·승패·피해 수치·확률·희귀도는 정하지 않습니다.

| 현장 | 사건·가상 속보 | 출동 뒤 현장에서 하는 일 | 평온·기록 |
|---|---|---|---|
| 예능 방송국 / `broadcast` / `city_27` | 방송국 앞 나쁜 기운 포착, 현장 도움 요청 접수 | 기존 공격 자세·발사·복귀 동작으로 현장 기운 정리. 방송국 건물은 배경에 남음 | 평소의 방송국 불빛과 길의 색이 돌아옴 → 현장 안정 기록. 이번 8컷 대표 시나리오 |
| 콘서트장 / `rap` / `city_32` | 리허설을 앞둔 콘서트장 앞에 기운이 모임 | 몬스들이 무대 진입로 앞에서 기운을 정리하는 연출 | 현장 안내등이 안정되고 파티가 무대 방향을 바라봄 → 리허설 길 정리 기록 |
| 팬샵 / `fanshop` / `city_12` | 팬샵 앞 응원 장식 주변에 나쁜 기운 출현 | 진열대를 파괴·복구하는 경제 이벤트 없이, 건물 앞 국소 기운만 정리 | 팬샵의 밝은 분위기가 돌아옴 → 응원 거리의 평온 기록 |
| 보컬 녹음실 / `vocal` / `city_07` | 녹음실 앞 이상 신호, 작업을 도울 몬스 요청 | 기존 공격 시퀀스를 녹음실 앞 동일 도시 공간에 배치 | 문 주변 빛과 거리 환경음이 안정 → 녹음실 앞 지원 기록 |

뉴스를 보자마자 강제 출동하지 않습니다. 뉴스에서 **자세히 보기 / 몬스 출동 선택 / 즉시 스킵**을 제공하는 방향입니다. 미확인 선택·클릭만으로 티켓을 소모하지 않고, 기존 출동 준비와 명시적인 시작 절차를 통과한 경우에만 본게임 run을 시작합니다. 시안 버튼은 콘티 이동만 수행합니다.

## 4. 전체 컷별 콘티

아래 14컷의 본게임 표시 기준은 이야기 선택 뒤 **공통 모바일 phone 프레임 안 전체 연출**입니다. 독립 preview의 기존 컷 재생은 이전 참고 이력으로 구분합니다. 목록에서 컷과 무대를 상시 함께 노출하지 않습니다. 각 컷의 카메라·동작·전환·오디오·하단 UI 설명은 제작/검토용 콘티이며, 장면에는 짧은 이야기 자막을 표시하고 상세는 접힌 콘티 정보로 읽는 방향입니다.

이전 독립 시안의 `reviewDurationSeconds`와 컷별 임시 초 값은 **이전 연출 검토 이력**입니다. 현재 본게임은 원래 run의 시작/종료 시각과 원본 시간을 사용합니다. 검토용 컷 버튼·일시 정지·스킵으로 실제 활동 종료·티켓·보상·수령을 바꾸지 않습니다.

현재 본게임은 기존 자동 진행을 보거나 phone 안 목록으로 복귀하는 흐름입니다. 결과의 받기는 기존 정산 경로를 사용합니다. 이전 독립 시안의 컷 이동·일시 정지·스킵은 그 시안의 검토 조작 이력으로 보존합니다. 동작 줄이기·짧은 자막·접근성은 같은 정보가 읽히도록 유지하며, 미수행 조합을 모두 검수했다고 쓰지 않습니다.

### 도시 여정 · 녹음실 심부름

기존 40칸 3D 도시의 길을 아이돌 분신 몬스가 최대 5명씩 함께 걸어요. 발견과 동행을 거쳐 목적 건물인 보컬 녹음실 도착으로 여정 연출을 끝냅니다.

### 1. 오늘의 심부름 · 녹음실로 · `journey_prepare`

- 화면·자막: 사옥에서 받은 가이드 노트를 녹음실에 전하러 가요. 오늘은 친구들의 걸음과 소리에 귀를 기울여 볼까요?

- 카메라: 사옥 간판과 목적지 핀을 먼저 보여 준 뒤, 아이돌 분신 몬스 뒤의 낮은 시점으로 내려온다.
- 동작: 예시 아이돌 A~E와 연결된 몬스가 길 입구에 모인다. 이번 활동의 주목쌍은 A와 B임을 이름표로 연결한다.

## 5. 현재 본게임 진행·수령·기록 연결 계약

### 자동 진행·스킵·목적 건물 도착

- 본게임의 진행 기준은 기존 run의 `startedAt / endsAt / durationSeconds`입니다. 시안의 재생 시간·컷 버튼을 이 값에 덮어쓰지 않습니다.
- 본게임에서 스킵은 표현만 건너뛰고 실제 활동의 남은 시간을 없애지 않습니다. 이미 시간이 끝난 run은 목적지 결과를 바로 보여 줄 수 있으나, running인 run을 ready로 바꾸기 위한 버튼으로 사용하지 않습니다.
- 최신 **목적 건물 도착 종료**는 장면과 문구의 기준입니다. 정산 상태는 기존 `running → ready → claiming → claimed`와 receipt를 유지합니다. 목적지에 섰다는 영상 이벤트만으로 claiming/claimed를 만들지 않습니다.
- 현재 runtime의 기본 마일스톤에는 `homeward / 돌아오는 길`이 있습니다. 향후 반영 시 이 표시·장면 매핑을 목적지 도착형으로 교체해야 합니다. 이번 시안이 그 기존 값을 이미 바꿨다고 표현하지 않습니다.
- 화면을 나가거나 탭을 숨기면 3D/RAF 표현을 정리하고, 재진입 때 run의 실제 현재 시각과 참가 snapshot으로 현 위치를 복원하는 기존 경계를 유지합니다.

### 동시 여정과 아이돌 중복

목록 복귀로 멈추는 것은 이번 시안의 장면 재생입니다. 향후 본게임 run을 연결할 때는 기존 자동 진행 시각과 run별 정산을 유지하며, 시안의 일시 정지·이어 보기와 혼동하지 않습니다.

- 여러 여정·출동은 각 run의 참가 snapshot·시작/종료 시각·목적지·결과·미수령·receipt를 따로 갖습니다. 현재 보는 장면을 바꿔도 다른 run을 덮어쓰지 않습니다.
- 여러 run에서 같은 아이돌·같은 경로 선택을 기존 결정대로 허용합니다. 도시 화면에서 분신이 보인다는 이유로 신규 busy 제한·스태미나·쿨다운·최대 동시 건수를 만들지 않습니다.
- 한 run 안의 같은 아이돌 ID 중복, 경로 인원 조건 불일치, 현재 세션/실제 아이돌 연결 실패는 기존 기준으로 처리합니다.
- 현재 시안의 5명은 화면 검토용 예시입니다. 실제 참가 상한 5명 이외의 최소 인원·예시 멤버 이름·파티 고정 구성을 본편에 확정하지 않습니다.

### 티켓과 선택·수령 경계

| 시점 | 현재 본게임 계약 | 표시와 정산의 경계 |
|---|---|---|
| 뉴스·장소·편성·목표 선택 | 선택만으로 차감하지 않음 | 도착·수령·기념 획득을 미리 확정하지 않음 |
| 출발/출동 확정 | 기존 start가 현재 티켓·인원·세션을 검증하고 독립run 생성 | 새 도시 메타데이터가 추가 비용/시간/보상을 만들지 않음 |
| 연출·목적 건물 도착 | run의 실제 시각 기준 ready인지 확인 | 도착/미수령이며 아직 보상 지급이 아님 |
| 보상 확인 | 해당run의 frozen receipt와 기존 관계/예정 내역 조회 | 빈값을0이나 임의 증가량으로 채우지 않음 |
| 받기 | 해당receipt를 claiming→성장 writer 저장/ACK 확인→claimed | 실제 수령 후 applied/claimedAt/receipt 근거와 함께 기록 표시 |
| 소식·기록·도감 재열람 | 실제 저장된 상태·기념·출처 조회 | 읽기·필터·왕복으로 재지급/라포/방문횟수 재적용 없음 |

현재 지갑·라포·기념 수집의 writer는 기존 성장 측입니다. 장면 렌더러나 뉴스 컴포넌트가 직접 재화·관계·성장 저장을 쓰지 않습니다. 지갑 미공급을 0으로 만들거나 미정 보상량을 확정 0·임의 예시 수치로 메우지 않습니다.

여정의 관계 표현은 기존 주목쌍 1쌍과 원본 행동 사건을 연결하며, 신뢰·이해·협력·긴장 4축의 새로운 증감량을 만들지 않습니다. 출동은 기존 계약대로 아이돌 라포를 자동 증가시키지 않습니다. 돈·주사위·관계·기념의 실제 지급량과 환산은 **발란스 대기**입니다.

### 소식 · 기록장 · 기념 도감 연결

현재 소식은 실제 저장된 출발·도착·수령 사실을 읽고 해당 run 기록으로 연결합니다. 출동 장면의 가상 속보와 구분합니다. 기록장은 전체 run을 읽고 실제 참가 아이돌/분신 몬스·서사·목적지·미수령/확인 중/수령 상태를 보여 줍니다. 확인된 수령 기억은 applied·claimedAt·receipt.id와 대응하는 내역이며, 미공급 내역을 예상 보상이나0으로 채우지 않습니다.

기념 도감은 기존 성장 정본의 비재화 collections를 읽고 firstReceiptId/lastReceiptId와 원run을 대조해 **소식→기록→기념→원run**을 오갑니다. 같은 기념 ID만으로 확정 출처를 꾸미지 않으며 원run이 없으면 기념을 보존하고 출처 미확인을 안내합니다. 기본/직접 추가/선택형 구성은 frozen receipt, 실제 받은 총합은 applied로 구분하고 pendingItems는 실제 아이템 획득이 아닌 지급 연결 대기입니다.

모노에서 재사용한 것은 모험 내부 기록장 열기/복귀·날짜별 카드·참가자/본문/장면·원기억 ID 연결입니다. 종·카드·별·성공/부상·경제/공유 수치와 직접 지급 함수를 복사하지 않습니다. 친구 우편·외부 공유는 미이식입니다. 콜드/재방문/뒤로/닫기/모듈 복귀, 정산 거부·ACK 지연·다중 receipt·원출처 누락은 구분 검수하며 이번 실제 확인 범위는7장을 따릅니다.

## 6. 데이터와 자산의 분리

### 현재 본게임 도시·기록 데이터

`data/simulator/adventure-city.json`은 origin/destinations와 기존77여정/10출동의 표시 메타데이터, phase6/8·마일스톤5개를 제공합니다. 원래 ID·보상·시간·인원·rulesSignature는 보존합니다. 기록장은 `records.mjs`의 읽기 투영과 기존 run/receipt·성장 collections를 사용하며 새 지급 writer가 아닙니다.

### 이전 독립 시안 JSON · 이력 보존

`version / status / title / party / modes / viewerCopy`를 갖습니다. party에는 실제 원본 자산의 `id / name / ownerLabel / portrait / model / assetId`를 담고, ownerLabel은 `예시 아이돌 A~E`로 제한합니다. 실제 candidate_id와 현재 팀은 담지 않습니다.

각 mode는 `id / title / summary / milestones / shots`를 갖습니다. shot에는 `id / title / caption / location / stageLabel / camera / action / transition / audio / ui / reviewDurationSeconds / milestoneIndex`, 필요 시 `news / result`가 있습니다. UI 카피는 `ui.eyebrow / title / body / primary / secondary / hint`, 뉴스는 `tag / headline / ticker`, 결과는 `title / body`입니다.

JSON은 연출 검토용 데이터이며 실제 CSV·schema·등록 모듈과 별개입니다. 렌더러는 화면 원고와 컷 정보를 읽되 게임 경제값이나 성공 판정을 해석하지 않습니다. 새 게임 수치·보상량·티켓 비용·능력·성장량 필드는 넣지 않습니다.
