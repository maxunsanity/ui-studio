# P94 · 공용 게임 시뮬레이터 v01

상태: 제안(검수 대기)입니다. 수치는 시안 예시입니다.

## 상위 게임 탭 · 기존 이식 게임 연결 (2026-10-21)

기획서 툴의 상위 「게임」 탭은 [모노카피바라 이식 게임](/docs/planning/game-prototype.html?mode=economy)을 엽니다. 로비·보드·건설·상점·카드북 등 기존 이식 화면의 진입 주소를 명시합니다. 쿼리가 없는 기본 게임 주소의 신맵 플레이와 기존 게임 소스·저장 데이터는 변경하지 않습니다.

「게임」·「발란스 툴」·제안서·지도처럼 전체 화면 탭으로 이동하면 공용 시뮬레이터를 숨기고 일시 정지합니다. 주소에 이전 P94 문서 선택이 남아 있어도 게임 탭에서 시뮬레이터를 다시 불러오지 않습니다. 탭 안의 새 창 링크도 같은 이식 게임 주소를 사용합니다. 확인 범위는 소스·빌드·경로 연결까지이며 실제 플레이 검수는 별도입니다.

##### ★ 현중 결정 C 10:45 (원문 「보드가 먼저 정하기」)

- 막는 문제: ① 지급이 7곳 이상으로 갈라짐 ② 화면 결과와 실제 보상 불일치 ③ 발란스 툴이 게임별 표를 따로 세야 함.
- 연결되는 곳: 행사 재화 얻기(`data/game/event_acquire.csv`), 보상 패킷, 지급 한 곳(`src/game/economy/session.ts`), 발란스 툴 반영 단계. 게임 안 보상 표 숫자는 지우지 않고 「발란스 대기」 참고값으로 둔다.

연결 안(순서)

```mermaid
flowchart LR
  A[보드 도착] --> B[판정 대박·중박·운망]
  B --> C[보상 패킷 확정<br/>돈·주사위·이벤트 재화]
  B -- 대박 --> D[2차 룰렛 결과 확정<br/>카드는 여기서만]
  D --> C
  C --> E[이벤트 게임 고르기<br/>칸·행사에 따라]
  E --> F[결과 공급부에 패킷 넘김<br/>setResultProvider 같은 입구]
  F --> G[연출만 재생<br/>정해진 칸에 멈춤]
  G --> H[받기 → 지갑 지급<br/>보드 쪽 한곳에서]
```

1. 보드가 판정(대박·중박·운망)과 돈·주사위·이벤트 재화 양을 먼저 정한다. 대박이면 2차 룰렛 결과(카드 포함)도 이때 정한다. 카드는 2차 룰렛에서만(현중 10:35).
2. 정한 결과를 「보상 패킷」 하나로 묶는다(받는 것·양·카드 번호·연출 키). 콘서트 룰렛 `reward-contract12.mjs`의 패킷 모양(돈·주사위·카드 수량, 레벨·배수 맥락)을 본보기로 쓴다.
3. 이벤트 게임은 패킷을 받아 그 결과에 멈추는 연출만 한다. 룰렛형 7개도 `Math.random` 대신 받은 칸 번호로 멈추게 바꿔야 한다(커서 몫).
4. 지급은 연출 뒤 「받기」에서 보드 쪽 한곳만 한다. 이벤트 게임은 지갑을 만지지 않는다.
5. 재화로 진행하는 6개는 보드에서 모은 행사 재화(`event_acquire`)로 들어가고, 그 안의 보상도 같은 방식(먼저 정하고 연출)으로 맞춘다.
숫자(확률·양·재화 개수)는 모두 모노 값 임시 시안 또는 「발란스 대기」. 지어낸 숫자 없음.

### 아이폰형 공통 화면 · 필러와 하단 메뉴 · v22 최신 직접 지시

오디션·메인·성장·쟁탈 칸·섭외권·기존 네이티브 도구에 같은 아이폰형 390×844 세로 틀(약 9:19.5)을 사용합니다. 상단은 콘텐츠 이름·재화·크게 보기와 공통 게이지 중심으로 얇게 표시합니다. 계정 카드·시안 재화의 반복 안내는 칩의 설명에 보존하고, 연결되지 않은 상단 이벤트 자리와 내용이 없는 정보 버튼은 숨깁니다. 하단의 카드북·상점·모험·건설·미션은 아이콘과 함께 항상 표시하며 미연결 기능은 준비 중 상태를 유지합니다. 실제 연결된 팀·멤버·능력 자료와 우측 검토 자료는 유지합니다.

공통 순서는 **상단 정보 → 고정 지도·3D 연출 → 필러 → 기록장·현재 위치·소식 → 주사위·진행 버튼 → 하단 공통 메뉴**입니다. 필러 높이는 공통 설정 `data/simulator/mobile-frame.json`의 `layout.review.fillerHeight`에서 읽으며 현재 검토값은 196px에서 240px로 늘립니다. 버튼 공간은 96px, 하단 공통 메뉴는 52px로 분리합니다. 메인·성장·쟁탈 칸의 외부 폰 측정 설정도 같은 390:844 비율을 사용합니다. 숨긴 자리표시는 DOM에 보존하며 게임 기능을 새로 붙이거나 삭제하지 않습니다.

기존 판정명·문장·확률·성장·보상·저장·게임 연출 함수는 변경하지 않습니다. 클릭 성장과 이벤트·경제·라포의 커서 진행 작업은 별도 범위입니다. 현재 실행 중인 모듈의 코드와 대조한 소스에 UI 네 파일만 반영합니다. UI 구현 두 묶음과 연결 경로만 갱신하며, 나머지 실행 코드는 본문을 보존하고 진행 중인 다른 담당의 미반영 로직을 함께 발행하지 않습니다. 실제 플레이와 가독성 검수는 현중이 수행합니다.

### 지도 고정 · 필러 채팅창과 버튼 공간 · v19 공통 구조 기준

상단 지도·3D 장면은 고정하고, 그 아래에 도착 정보·성장 선택 설명·대사·결과를 보여 주는 필러 채팅창을 둡니다. 필러 아래에는 조작 버튼 공간을 따로 둡니다. 필러가 나타나도 지도를 필러 화면으로 교체하지 않습니다.

팀·멤버·능력 자료는 필러 대사에 섞지 않고 상위 정보 메뉴에서 확인합니다. 원래 DOM과 데이터·선택 상태를 옮겨 재사용하며 우측 공통 성장 자료·설정도 보존합니다. 기존 버튼·선택 조작은 새로 만들지 않고 원래 요소를 별도 버튼 공간으로 옮겨 이벤트와 위임 연결을 유지합니다.

기존 도착 필러는 아래 채팅창에서 판정·대사·성장 요약을 표시하고, 진행·계속 버튼은 별도 버튼 공간에 둡니다. 필러 진행 중 필요한 지도·설정·다른 조작은 잠그되 진행 버튼과 그 조상 영역을 함께 잠가 멈추지 않게 합니다. 현재 페이지 초기화와 단독/메인 연결 범위는 v18 계약을 유지합니다.

「연출 크게 보기」와 「원래 크기」는 같은 페이지에서 동일한 DOM·현재 진행·설정된 세로 비율을 유지한 채 화면 크기만 바꿉니다. 확대 때문에 화면을 복제하거나 새 테스트를 시작하지 않으며, 돌아오면 같은 지도·필러·버튼 상태를 이어서 확인합니다.

나쁜 기운·팬 게이지는 모든 도구의 공통 표시로 연결합니다. 성장 화면은 기존 state.badGauge와 공통 규칙의 최대값, readFanState().layers 및 기존 popGaugeTotal로 읽은 팬 수를 전달합니다. 팬 층별 구성은 기존 자료를 표시하며 미정인 팬 목표치·최대치·별도 비율 기준을 만들지 않습니다. 표시 연결은 팬 경제·성장식·판정·보상 정산을 바꾸지 않습니다.

이번 범위는 UI 배치와 읽기 전용 표시입니다. 기존 판정명·문구·확률·보상 수치와 판정 변환 함수는 원문을 보존합니다. Cursor의 별도 문구 복구는 해당 담당 작업으로 구분하며, 최종 원본 변경이 있으면 겹치지 않는 구간만 확인해 보존합니다. 구현·문법·파일·빌드·연결 확인과 실제 플레이 검수를 구분하며 실제 게임·브라우저·VM 플레이는 현중 검수 대기입니다.


### 24대지 도착 필러 · v16 최신 직접 지시

기본 필러 대상은 정식 board_tile.csv의 tile_kind=building인 24칸입니다. 8시설×3칸이며 사옥 1칸과 합쳐 시설 종류는 9개입니다. 이전 land_lot의 22대지나 hit_roulette=1인 6칸을 대상 필터로 사용하지 않습니다. 보드 원본의 칸·시설 배치는 바꾸지 않습니다.

24대지 기본 판정은 대박 30%·중박 30%·운망 40%로 고정합니다. /data/simulator/building-arrival.json의 outcomes.weight에서 읽으며 단계·스킬·찬스로 확률을 보정하지 않습니다. 메인 도착에서 결과 기록을 한 번 만들고 기존 판정 칸의 성장 계산에도 같은 판정을 공급합니다. 전용 건물 툴은 받은 결과를 돌아가는 3D 복셀 휠로 표현하며 다시 추첨하지 않습니다. 독립 도착 테스트도 같은 고정 규칙을 사용합니다.

표시 보상은 board_tile.base_income이 있으면 그 값을 사용하고, 빈칸이면 building-arrival.json의 temporaryBaseMoney를 사용합니다. 현재 24칸의 base_income은 모두 미정이며 임시 기준값 1000은 시안 예시입니다. 표시량은 기준값×굴림 배수×판정 계수를 한 번 계산한 정수 내림 값입니다. 계수는 기존 economy_config의 hit_big/mid/miss_factor_pct(200/100/50)를 읽는 임시 표시 기준이며, 같은 표의 확률 15/50/35는 변경하거나 이번 필러에 사용하지 않습니다. 실제 돈·주사위·카드 잔액이나 운영 보상을 지급하지 않습니다.

기존 도착 성장식은 유지합니다. 고정 판정을 기존 판정 칸에 한 번 공급한 뒤 계산된 성장 요약을 전달하며, 툴에서 성장 재추첨·재계산·중복 적용이나 추가 판정 배율을 넣지 않습니다. 룰렛→판정·표시 보상→현재 저장 단계의 건설 연출 순서로 진행하고 0단계는 빈땅을 유지합니다. 도착만으로 건물 단계를 임의로 1 올리지 않습니다.

건물 툴은 24칸 선택과 「선택한 칸 도착 테스트」로 오디션 없이 검토합니다. 메인에서 받은 도착은 같은 시설·배수·단계·성장 요약으로 확인합니다. 상단 메인 이동과 내부 「메인으로 돌아가기」는 같은 건물 도착 기록을 닫으며, 중간에 나가면 cancelled로 한 번 기록해 해당 pending을 해제하고 다음 굴림을 허용합니다. 나쁜 기운·섭외권 대전을 임의 완료 처리하지 않습니다.

이벤트 전용 툴도 원래 운영 설정과 도착 문맥을 보존한 로컬 시험 어댑터로 연결합니다. 예시 연출·보상은 검토용이며 실제 지급을 하지 않습니다. 완료 결과가 있으면 reviewed, 준비·재생 중 복귀는 cancelled로 한 번 반환합니다. 운영 금지·미정 상태를 이번 시연으로 완료 처리하지 않습니다.

이번 v16 연결은 구현·파일·빌드 확인 진행 단계입니다. 아래 이전 버전의 완료·캡처·수치 기록은 v16 실제 플레이 통과 근거가 아닙니다. 실제 플레이·화면 체감은 현중 검수 대기이며 단이는 자동 플레이·긴 시연·반복 성능 측정을 하지 않습니다.


### 현재 페이지 초기화와 메인 연결 · v18 초기화 기준

상단 공통 버튼은 「현재 페이지 초기화」로 통일합니다. 이 버튼은 현재 선택한 도구의 검토를 처음부터 시작하는 동작입니다. 오디션을 먼저 실행할 필요는 없으며 샘플 팀·몬스·시설·테스트 재화는 별도 설정의 시안 예시를 사용합니다. 원본 게임 데이터·정식 발란스·보상 확률·지급량은 바꾸지 않습니다.

연결 상태는 초기화 버튼과 따로 표시합니다. 「단독 테스트」는 해당 페이지용 샘플 검토, 「메인 연결 중 · 도착칸/배수」는 메인에서 전달한 실제 도착 검토, 「메인」은 공용 보드의 테스트 진행을 뜻합니다. 메인 연결 여부를 보고 어느 상태를 검토하는지 알 수 있게 합니다.

모바일 화면은 프로필·보유 재화·이벤트 자리 3칸·현재 도시·하단 메뉴 5칸을 갖춘 공통 390×844 세로 틀을 사용합니다. 지도·3D 장면은 상단에 고정하고, 그 아래의 별도 필러 채팅창과 버튼 공간에서 도착·대사·결과·조작을 확인합니다. 기존 지도와 주사위·성장 조작 DOM은 이벤트를 유지해 공통 틀로 옮기고, 우측 공통 성장 자료·설정은 그대로 확인합니다. 실제 보유값이 없는 항목은 시안 예시를 구분하며 연결하지 않은 메뉴·이벤트는 준비 중으로 표시합니다. 공통 틀은 재추첨·성장 계산·보상 지급을 하지 않습니다.

메인이 아닌 페이지에서 초기화하면 testPage=moduleId로 구분한 페이지 전용 저장 공간에 샘플을 넣고 그 도구만 초기화합니다. 메인의 팀·주사위 진행·시설·성장·미완료 요청은 보존합니다. 단독 샘플 결과를 메인 결과나 메인 보상으로 합치지 않습니다. 카메라 위치·미리보기 작업만 되돌리는 조작은 「현재 페이지 초기화」와 구별되는 이름으로 유지합니다.

메인 연결 상태에서 해당 페이지를 초기화한 뒤에는 「메인 연결로 돌아가기」로 원래 메인의 미완료 도착을 다시 검토합니다. 메인에서 명시적으로 넘긴 미완료 요청이 없을 때 직접 전용 도구 메뉴를 열면 단독 테스트로 시작합니다. 초기화나 단독 테스트를 원래 미완료 요청의 완료·취소로 처리하지 않습니다.

메인 페이지에서 「현재 페이지 초기화」를 누르면 메인 테스트 세션을 새로 시작합니다. 별도 페이지의 단독 샘플 저장은 지우지 않습니다. 일반 탭 이동·메인 복귀·새로고침은 현재 선택한 저장 공간의 같은 테스트를 유지하며 자동 초기화로 처리하지 않습니다.

오디션 결과에서 메인 진입을 명시적으로 선택하면 해당 페이지의 오디션 인계값(scoped handoff)을 공용 메인으로 넘겨 기존 메인 테스트를 교체합니다. 이전 메인의 snapshot·checkpoint·시설·hub·casting 상태와 메모리를 새 인계로 시작하되, 오디션 원본 결과·원본 게임 데이터와 다른 페이지의 단독 샘플은 보존합니다.

도구 안에 중복된 「샘플 데이터로 새 테스트」·「처음부터」 같은 전체 테스트 초기화 버튼은 공통 상단 조작으로 모읍니다. 선택된 도구를 별도 화면으로 열 때도 game-simulator.html?module=선택된 툴 ID의 공용 host와 같은 페이지 저장 범위를 사용합니다. 성장 원본 play.html을 별도 창으로 여는 레거시 안내는 사용하지 않습니다. 새로고침 때는 모드·페이지 범위를 먼저 적용하고 준비 완료 전 이전 화면을 숨깁니다.

전용 도구의 역할과 계산·정산/ACK 경계는 유지합니다. 이 문서는 v18 초기화·연결 상태의 현재 계약을 정리하며, 구현·파일·빌드·연결 확인은 개발 결과와 따로 기록합니다. 실제 게임·브라우저·VM 플레이를 수행하거나 완료했다고 기록하지 않으며 실제 플레이는 현중 검수 대기입니다.

왼쪽 고정 게임 시뮬레이터에서 실행합니다. 기획서는 조작·연출·판정·리소스·CSV·검수 설명을 유지하고 모듈 실행/새 창 링크를 연결합니다. 문서만 읽을 때 시뮬레이터를 불러오지 않습니다. 실행한 시뮬레이터는 유지하고 문서를 읽는 동안 멈춥니다.

## v24 콘서트 룰렛 메뉴·장면·진행 버튼 분리

이벤트 게임에서 콘서트 룰렛을 선택하면 전용 설정을 우측 메뉴에 표시하고 폰 상단에는 룰렛 장면을 표시합니다. 설명·결과는 필러, 준비·재생·다시 보기·중지·받기는 별도 하단 버튼 공간에 둡니다. 연출·확률/배치·데이터/설명 탭도 우측에서 원래 도구를 조작합니다.

## v25 콘서트 우측 설명·설정의 펼침 상태 연결

우측 메뉴의 설명·설정 접힘 영역을 누르면 원본 도구의 같은 영역을 열고 닫습니다. 원본 상태를 모든 접힘 영역에 다시 반영하여 다른 설정을 바꾸거나 결과가 갱신되어도 선택한 펼침 상태가 되돌아가지 않게 합니다. 원본에서 열 때 불러오는 내용은 원래 toggle 처리로 이어집니다. 접힘 제목 안에 있는 별도 버튼·입력·링크는 해당 조작을 유지합니다.

원본 콘서트 도구·확률·seed·보상·지급·메인 복귀와 전체 프레임 크기는 바꾸지 않습니다. 실제 플레이·브라우저/DOM 검수는 수행하지 않습니다.
