# P213 · 도시 · 대표 개발 기획서

**이 문서는** 본진 도시의 시설과 도착 수익, 그리고 곡 · 피드 · 페스티벌이 도시에 어떻게 보이는지 정리한 대표 개발 기획서입니다.

**보는 법** 1장 그림 → 4장 「한 판 순서」 → 핵심제안 개발의 「도착 수익 시뮬레이터」 순서로 읽습니다. 세부 결정과 근거는 책갈피 [P201 도시 보완판](../../기획서/산출_기획서_도시_보완판_v1_클로드.md)에 있습니다.

**지금 상태** 기존 도시맵·시설 단계 표시와 공통 경제의 도착 계산은 코드 경로가 있습니다. P213의 전광판·군중·순위판·HUD 통합은 확인 대기이며, 도착 수익 시뮬레이터는 실제 경제표·저장/API와 연결하지 않은 표시 시안입니다. 실구동 미검수 범위는 [7장](#part-7)에 적었습니다.

## 1. 개요

출처: (합침) 제안서 [도시](/docs/planning/proposal-concept/city.html) · 책갈피 [P201 도시 보완판](../../기획서/산출_기획서_도시_보완판_v1_클로드.md) · 현중 11/01~11/02 지시

> **핵심** 도착 수익은 **건물 단계와 그 건물 팬을 입력으로 삼는 기획**입니다. 곡 · 피드 · 페스티벌은 새 장소를 만들지 않고, **방송국 전광판 · 콘서트장 군중 · 광장 순위판**처럼 이미 있는 장소에 보입니다.

P201은 제안(검수 대기)인 상세 결정안입니다. 도식의 ‘단계 × 팬’과 C1의 ‘단계 + 팬’은 원문 안에서도 다르며, 이 문서의 입력 설명을 최종 운영식으로 확정하지 않습니다.

```mermaid
flowchart LR
  A[보드 칸 도착] --> B[그 시설]
  B --> C[건물 단계]
  B --> D[그 건물 팬]
  C --> E[도착 수익]
  D --> E
```

### 콘텐츠 경계

- 맡는 것: 9시설 · 칸 대응 · 도착 수익 기준 · 새 기획이 보이는 자리 · HUD.
- 다른 문서에 맡기는 것: 다른 지역 → [P219 새 도시 진출](새도시진출_핵심제안서.html) · 팬 → [P211 팬덤 게이지](팬덤게이지_핵심제안서.html).

### 현재 기준과 목표

| 자리 | 보이는 것 |
|---|---|
| 방송국 앞 전광판 | 방송 클립 피드 |
| 콘서트장 앞 군중 | 직캠 · 잭팟 떼창 |
| 광장 순위판 | 데일리 · 위클리 순위 |
| 도시 장식 | 월드 페스티벌 기간 |

- 본진 = 한국. 다른 지역은 언어권 3개(P219).
- 칸과 시설 대응은 board_tile.csv 그대로입니다.

## 3. 구동 방법·시뮬레이션

화면 흐름: 보드 → 도착 → 도시 연출 → 수익 · 스샷 미완 · 이식 비교 해당 없음

- 실행: 기존 도시맵·시설 단계 표시와 공통 경제의 도착 계산 경로를 확인했습니다. P213 전용 표시의 통합·실제 운영 수익은 별도 확인 대상입니다.
- 핵심제안 개발의 **도착 수익 시뮬레이터**에서 건물 단계와 그 건물 팬을 바꿔 도착 수익이 어떻게 달라지는지 봅니다. 숫자는 모두 임시 시안입니다.

## 4. 상세 기획

### 한 판 순서 (임시 시안)

| 점검 | 내용 |
|---|---|
| 시작·종료 | 칸 도착 때마다 |
| 입력·출력 | 입력 = 건물 단계 · 그 건물 팬 / 출력 = 코인 · 연출 |
| 상태와 전이 | 건물 단계는 증축으로만 오름 |
| 판정 | 아이돌 능력은 수익식에 직접 안 들어감 |
| 오류·예외 | 건물이 없으면 기본 수익(기존 규칙) |
| 저장·복원 | 시즌 범위 |
| 다른 모듈 연결 | 보드 · 건물 · 팬 · 피드 |

계산 경로를 나눠 읽습니다. 공통 경제는 건물 단계 수익의 S 대비 %에 판정·주사위 배수·이벤트 버프를 적용한 뒤 팬 항을 더하고 파손 계수를 반영합니다. core 계산은 단계 수익과 칸 팬 곡선·칸 가중을 사용합니다. 표시 시안의 단계값·팬값을 곱하는 가중합과 모두 같은 식은 아닙니다.

아이돌 능력은 독립 수익항으로 더하지 않는 기획입니다. core의 판정 플래그가 켜진 칸은 능력이 판정 가중에 간접 영향을 줄 수 있습니다. 공통 경제의 건물팬 계수는 미공급이고 배정 방식은 발란스 대기입니다. 현재 추가 팬 항은 계산상 0이며 실제 건물별 배정은 하지 않습니다. 이 0은 미정 계수의 확정값이 아닙니다.

표의 ‘건물이 없으면 기본 수익’은 기존 기획을 보존한 표현입니다. 현재 공통 경제의 workplace는 시설 단계가 0이면 도착 수익을 0으로 처리하므로 이 예외와 구별합니다. 기본 수익 적용 정책은 확인 대기입니다.

### HUD (임시 시안)

상단 = 엔터파워 · 팬덤 게이지(한 막대) · 오늘 데일리 내 부문 순위 칩 하나를 더합니다.

### 필요 시스템

도착 수익 계산 · 전광판 · 군중 · 순위판 연출 · HUD 칩.

### 화면·연출 목록

도시 화면 · 전광판 · 군중 · 순위판.

### 남은 결정

- 시설 단계별 연출 크기 — 아트 · 발란스

## 7. 개발 진행·검수

확인 범위는 관련 원문·표·공통 계산과 도시 렌더 코드의 정적 대조입니다. 보호된 상위 게임 직접 호출과 실제 이동·도착 수익·지갑 반영·저장, 전광판·군중·순위·HUD 통합은 검수하지 않았습니다. 다른 콘텐츠의 최신 표시 통합은 별도 검수입니다.

| 요소 | 상태 | 확인 방법·증거 | 다음 작업 |
|---|---|---|---|
| 기획(이 문서 · 책갈피 상세) | 기획 중 | P201 · 이 문서 | 현중 확인 |
| 기존 도시맵·시설 단계 표시·공통 경제 | 부분 코드 확인 | 관련 로더·계산·도시 렌더 정적 대조 | 실구동·연결 검수 |
| 도착 수익 시뮬레이터 | 표시 시안 | 메모리 DOM · 실제 경제표·저장/API 미연결 | 실제 표 연결 확인 |
| P213 전광판·군중·순위판·HUD 통합 | 기획·확인 대기 | 계획·관련 참조만 확인 | 해당 범위 통합 검수 |

### 수락 기준

도착 수익의 기획 입력과 실제 계산·대기 계수·예외를 구분하고, 새 기획은 새 장소 없이 기존 장소에 보여야 합니다.

### 뺀 것·옮긴 것·보존한 것

세부 결정과 근거는 책갈피 P201에 둡니다. 제안서 원문 city.md는 그대로 보존합니다.
