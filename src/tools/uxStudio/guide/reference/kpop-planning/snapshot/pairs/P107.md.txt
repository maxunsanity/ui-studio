# P107 · 아이돌 성장 · 대표 개발 기획서

**이 문서는** 오디션에서 만난 같은 아이돌의 능력·재능을 이어받아 성장 입력·승급·이야기 공개가 연결되는 방식을 설명하는 기획서입니다.

**보는 법** 1장 능력의 범위 → 3장 실행 → 4장 계산·승급·서사 → 7장 개발·검수 순서로 읽습니다. [공용 시뮬레이터 실행](/docs/planning/game-simulator.html?module=simulator_module_idol_growth)

**지금 상태** 단계표 계산·시험 사본·서사 연결의 코드 확인과 실제 화면 미검수, 카드 장수와 승급 판정의 정합 확인 전 항목을 7장에서 구분합니다. [개발·검수 범위](#part-7)

**컨디션 개발 현황: 성장 정산·몬스 배정 화면·현재 컨디션 단계의 게임·진행률 회복과 배정 몬스의 실제3D 모델을 연결했습니다. 발란스 몬스 탭과 게임 몬스 화면에서 돌봅니다. 출현·초반XP·비정지 FIFO·원GLB 전투와 본게임 공용 연결을 적용했고 일반1배속 전투·선택 누적·성공 결과를 확인했습니다. 레이저 머리 위 드론은 별도11항 소스와 실제 이동·총구를 확인했으며, 기존 승리 기록과 변경 시점을 구분합니다. 이전 설정의 화면 확인과 구분합니다. 현황판의 멤버 칩·선택 아이돌 요약에는 짧은 컨디션 수치와 게이지를 연결하고 작은 화면까지 확인했습니다. 이번 후속은 기존 엔진의 조회 표시이며, 다른 아이돌 화면 전체 통일과 장기·물리 기기 검수는 별도입니다.**

## 1. 개요

### 콘텐츠 경계

아이돌 한 명은 **6축 18세부 능력**을 가집니다. 세부 능력이 직접 오르고, 같은 축의 세부 3개 평균이 육각형의 꼭짓점이 됩니다. 재능은 그 축이 얼마나 쉽게 자라는지를 가르는 값이며 현재 능력과 별도로 보존합니다. 같은 카드와 같은 연습을 받아도 현재 단계와 재능선이 다르면 증가량이 달라집니다.

| 육각형 축 | 직접 성장하는 세부 능력 | 플레이어가 읽는 뜻 |
|---|---|---|
| 보컬 | 음정 · 발성 · 곡 해석 | 정확하게 부르고 곡의 감정을 전하는 힘 |
| 댄스 | 칼군무 · 리듬감 · 표현력 | 동작을 맞추고 박자와 분위기를 살리는 힘 |
| 랩 | 플로우 · 딕션 · 무대 장악력 | 리듬과 발음으로 관객을 끌어당기는 힘 |
| 비주얼 | 표정 연기 · 카메라 시선 · 스타일 | 카메라와 콘셉트에 맞게 자신을 보여 주는 힘 |
| 끼·예능감 | 스타성 · 예능감 · 화술·소통 | 눈길을 끌고 사람들과 교감하는 힘 |
| 프로듀싱 | 작사 · 작곡 · 편곡 | 음악을 직접 만들고 완성하는 힘 |

**영어·중국어·일본어**는 육각형 밖의 학습값입니다. 무대 능력 합에 넣지 않고 언어별 등급과 승급 조건에서 읽습니다. 태도·성실성 같은 숨긴 값, 성격과 라포는 각각의 원본을 사용하며 새 능력 축으로 합치지 않습니다. 메인 보컬·센터 같은 칭호와 팀 능력은 [팀 결성](팀결성_팀스탯_기획서.html)의 역할입니다.

이 문서는 개인 성장 계산과 결과 표시, 멤버 승급과 서사 공개의 연결을 맡습니다. 후보를 만드는 규칙은 [랜덤 멤버 생성](랜덤멤버생성_기획서.html), 누구를 합류시킬지는 [오디션](오디션_기획서.html), 카드의 소유와 지급은 [카드](카드_기획서.html), 건설 비용과 시설 기능은 [건물 성장](건물성장_기획서.html)에서 정합니다.

### 현재 기준과 목표

기준 제안서는 [아이돌 성장 제안서](../../../../proposal-concept/idol.html)입니다. 멤버가 바뀌지 않은 채 생성 때의 재능·배경·서사를 이어받고, 성장 기록만 누적합니다. 성장 계산은 `step_table`의 공통 계산기를 사용합니다. 값이 있는 표는 그 숫자로 읽고, 빈 칸은 0으로 채우지 않고 비어 있음으로 표시합니다.

```mermaid
flowchart LR
  A[오디션에서 같은 멤버 합류] --> B[배경·재능·처음 능력·서사 보존]
  B --> C[카드·도착·시설의 성장 입력]
  C --> D[단계표 계산과 상한·이월]
  D --> E[능력·학습 조건 확인]
  E --> F[승급과 성장 기록 저장]
  F --> G[해당 단계의 이야기 공개]
  D --> H[시험 사본에서 성장 속도 비교]
```

그림의 실제 진행은 메인 보드와 공통 저장이 맡습니다. 아이돌 성장 메뉴의 시험 작업대는 그 기록을 복사해 조건을 비교하는 별도 관측 경로입니다. 시험에서 숫자가 오른 것만으로 실제 승급이나 이야기 공개를 처리하지 않습니다.

## 3. 구동 방법·시뮬레이션

화면 흐름: 오디션 합류 → 메인 보드 → 아이돌 성장 시험 또는 공통 캐릭터 정보 → 같은 메인으로 복귀 · 스샷: 기존 자료는 로그에서 확인 · 이식 비교: 해당 없음.

### 같은 팀에서 시작하기

저장 범위(scope)는 서로 다른 테스트가 섞이지 않게 나누는 칸입니다. 세션(session)은 지금 이어가는 테스트 묶음을, 진행 번호(run)는 같은 팀의 오디션 결과와 성장 기록을 구별하고 연결합니다. 현재 상태 기록(snapshot)에는 능력·학습·단계 등이 담기고, 복원 기록(checkpoint)은 그 진행을 다시 이어 열 때 사용합니다. 도구는 이 기록들이 같은 테스트와 같은 팀을 가리키는지 먼저 확인합니다.

공용 시뮬레이터에서 오디션 또는 이미 연결된 테스트 팀을 사용합니다. 성장 도구는 현재 scope·session/run과 맞는 저장을 읽습니다. 멤버 ID와 저장 버전이 다르면 다른 팀의 값을 가져와 채우지 않고 연결 사유를 보여 줍니다. 유효한 저장이 없고 인계 자료만 있으면 인계 당시 값과 실제 진행을 구분합니다.

[눌러서 메인 보드와 실제 성장 진행 확인](../../../../game-simulator.html?module=simulator_module_dice)

### 아이돌 성장 시험하기

아이돌 성장 메뉴는 공통 시험 작업대로 열립니다. 대상 멤버 또는 전체 멤버, 세부 능력, 성장 입력, 시험 단계, 레슨 시설과 단계를 선택합니다. 시작 능력과 재능을 직접 넣는 칸은 시험 조건이며 생성된 멤버의 원본을 바꾸지 않습니다.

1. 데이터 출처에서 지금 팀과 저장 버전을 확인합니다.
2. 대상과 조건을 고른 뒤 **1회 진행**으로 전후값을 비교합니다.
3. **시작**을 누르면 직전 시험 결과에서 한 회씩 이어 계산합니다.
4. **정지**하면 그 값에서 멈추고 다시 시작하면 이어집니다.
5. 세부 조건을 바꾸면 멈추고 새 시험을 준비합니다. 속도와 시험 주사위 배수는 다음 회차부터 바뀝니다.

왼쪽 모바일은 육각형과 현재값을 보여 줍니다. 오른쪽 위에는 현재값·시작과 차이·최근 곡선, 가운데에는 조건과 전체 세부 수치, 아래에는 시작·정지·속도·배수가 있습니다. 속도는 화면의 진행 간격이고 성장량 배수가 아닙니다. 주사위 배수는 원본 목록을 읽으며 관계·팬 시험에 없는 효과를 덧붙이지 않습니다.

시험 사본은 같은 세션의 성장 메뉴 사이에서 메모리로 이어집니다. 원래 저장 버전이 바뀌면 사본을 버리고 새 원본을 읽습니다. 탭 이동과 페이지 숨김 때 자동 정지하며 밀린 회차를 한꺼번에 계산하지 않습니다. 원래 지갑·보상·저장 revision은 시험으로 바뀌지 않습니다.

### 서사와 단계 확인하기

합류 멤버의 공통 캐릭터 정보에서 능력·재능·외국어와 이야기를 봅니다. 이야기 장 선택 목록은 열림·잠김·자료 대기를 구분하고, 공개된 장만 본문과 대사를 보여 줍니다. 성장 저장의 단계가 확인되지 않은 경우에는 공개 소개와 단계가 필요한 장을 나눠 표시합니다.

시험 단계 강제 선택이나 옛 오디션 화면의 성장 버튼은 검토용 입력입니다. 실제 학습으로 승급했거나 실제 이야기가 새로 열린 증거와 구분합니다. 이 문서를 열 때 시뮬레이터·3D·원본 화면은 자동 실행하지 않습니다.

## 4. 상세 기획

### 한 판 순서

같은 멤버를 유지하면서 **성장 입력을 받음 → 현재 단계에서 계산함 → 변화를 저장함 → 승급 조건을 판정함 → 공개 가능한 이야기를 표시함** 순서로 이해합니다. 시험 작업대에서는 성장 입력과 계산 결과까지만 사본에 누적합니다.

| 점검 | 실제 처리와 경계 |
|---|---|
| 시작·종료 | 현재 테스트 팀을 읽고 대상을 선택합니다. 시험은 정지·탭 이동·페이지 숨김으로 멈춥니다 |
| 입력·출력 | 세부 현재값·축 재능·성장 출처·주사위·레슨·단계 → 증가량·상한·이월·전후값 |
| 상태와 전이 | 능력 증가와 멤버 승급은 별도입니다. 준비 조건을 충족한 뒤 승급 칸에서 단계가 바뀝니다 |
| 판정 | 성장량은 공통 단계표, 승급은 다음 단계의 능력 합·학습 조건을 읽고 카드 장수는 조건에 넣지 않습니다 |
| 오류·예외 | 필수 표·현재값·재능·단계 상한이 없으면 해당 계산을 자료 대기로 남깁니다 |
| 저장·복원 | 실제 진행은 공통 성장 스냅샷과 checkpoint를 사용하고, 시험 사본은 원래 저장에 쓰지 않습니다 |
| 다른 모듈 연결 | 카드·시설의 결과는 같은 멤버 ID로 받고, 팬·뉴런·캐릭터 정보는 확인된 성장 기록을 읽습니다 |

### 같은 아이돌을 이어받는 방법

멤버 생성은 배치 시드와 멤버 인덱스로 재현됩니다. 능력·재능, 성격, 배경 조각과 서사를 생성할 때 각각의 추첨 경로를 나눠 사용합니다. 성장 화면을 다시 열었다는 이유로 이 재료를 새로 뽑지 않습니다.

합류 자료에는 멤버 ID, 이름과 예명, 옛 저장의 몬스 ID, 현재 능력·재능, 배경 조각, 서사 등이 연결됩니다. 실제 성장 스냅샷은 현재 세부값·외국어·단계와 시설·위치를 내보냅니다. 공통 정보창은 같은 세션과 같은 멤버 구성을 확인한 다음, 서사는 인계된 원본에서, 수치는 현재 성장 저장에서 읽습니다. 원본에 부분 서사나 빈 서사 배열이 저장되어 있으면 다른 표에서 몰래 다시 뽑아 보충하지 않습니다.

```mermaid
flowchart LR
  A[생성 멤버와 원본 서사] --> B[오디션 합류 인계]
  B --> C[현재 세션과 명단 검증]
  C --> D[현재 성장 저장 읽기]
  D --> E[능력과 학습과 단계]
  B --> F[보존된 서사 원문]
  E --> G[같은 멤버 정보창]
  F --> G
```

이 경로에서는 생성 원본이 인물과 글의 주인이고, 성장 저장은 현재 수치와 단계의 주인입니다. 정보창을 다시 열 때 둘을 같은 멤버로 연결하며 한쪽이 없다고 다른 멤버의 자료로 대신하지 않습니다.

### 성장량을 계산하는 방법

성장은 `stepGain` 한 계산기를 사용합니다. 먼저 어떤 출처가 어느 세부 능력에 입력을 주는지 읽고, 주사위 입력과 레슨 효과를 반영한 뒤 현재 점수가 속한 성장 단계의 필요량을 계산합니다. 입력이 단계 경계를 넘으면 남은 입력으로 다음 단계도 차례로 계산합니다.

| 순서 | 계산 재료 | 결과 |
|---|---|---|
| 출처 선택 | 성장 출처의 세부 ID·기본량·배수 적용 여부 | 이번에 계산할 능력과 입력량 |
| 성장 단계 찾기 | 현재값·공통 단계 시작/끝·단계 계수 | 현재 구간을 채우는 데 필요한 입력 |
| 재능 경계 확인 | 단계 시작점과 축 재능 | 일반 구간 또는 재능 이후 구간 |
| 시설 효과 | 시설 단계의 레슨 배수와 구간별 지수 | 해당 구간에 적용할 유효 레슨 효과 |
| 증가량 계산 | 필요 입력과 실제 입력 | 상한 적용 전 증가량 |
| 제한 적용 | 세부 성장 한도·도착 상한·기존 이월·이월 한도 | 실제 증가·다음 이월·버린 양 |

재능은 점수를 막는 벽이 아니라 일반 성장과 느린 성장을 나누는 선입니다. **현재 구간의 시작점이 재능 이상이면 재능 이후 구간**입니다. 재능선이 구간 한가운데 있으면 그 구간 전체는 일반 성장으로 처리하고 다음 구간부터 다시 판단합니다. 같은 값이면 재능 이후 구간에 들어갑니다.

**만렙 100 벽(1인 1,800)은 없습니다.** 재능선을 넘으면 속도만 아주 느리고 예측하기 어렵게 바뀌고, 능력은 계속 자랍니다. 플레이타임은 60일이 아니라 1년 가까운 RPG 페이스로 봅니다(현중 11/19 10:37). 성장 계수(`step_coef`)는 무료 유저 기준 약 1년(현중 11/19 14:44, 유르넷 전달)에 맞춰 1.2 · 1.5 · 1.8 · 2.2 · 2.7 · 4.9 · 5.9 · 7.2 · 8.8 · 10.8입니다. 이 값에서 무료 유저 재능선 첫 멤버 도달일 p50은 378일입니다(30판 · 흡수 표 켬 · 가장 높은 재능 축).

아이돌이 재능선에 닿았는지 판정할 때는 그 아이돌의 **가장 높은 재능 축 하나만** 봅니다(현중 11/19 13:55). 그 축의 **세부 3칸 합 ≥ 재능선×3**이면 도달입니다. 평균을 내지 않고 정수로 판정합니다(유르넷 11/19 15:10 전달 · 아론에게 같은 지시). 가장 높은 재능 축이 둘 이상이면 앞 축(표 축 순서상 앞)으로 판정합니다. 축 순서는 보컬 · 댄스 · 랩 · 비주얼 · 끼·예능감 · 프로듀싱입니다(`data/idol_ability_sim/idol_growth_stat.csv` `sort_order` 1~6). 코드는 `src/game/core-proposal/ceiling.ts`에서 재능이 같으면 배열에서 먼저 나온 쪽을 고릅니다. 지금 코드(`ceiling.ts:51`, 아론 15:09)는 세부 3칸 합 > 재능선×3(같으면 아직)입니다. ≥로 맞출지는 보고/20261119_1517_비앙카_정수단위로더_답변.md 「현중께 여쭐 것」에 적었습니다.

필요 입력은 능력별 기본 필요량 × 단계 계수 × 단계 보정으로 계산하고, 얻는 양에 그 축의 흡수율을 곱합니다. 재능선 아래 흡수율은 그 축의 재능 칸으로 정합니다(현중 11/19 13:54 · `data/core_proposal/idol_ability_absorb_band.csv`).

| 축 재능 | 20~29 | 30~39 | 40~49 | 50~59 | 60~69 | 70~79 | 80~90 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 재능선 아래 흡수율 | 70% | 85% | 100% | 115% | 130% | 145% | 160% |

재능선 위 흡수율 = 그 축의 재능선 아래 흡수율 × 굴림 %입니다. 굴림은 1~9% 정수(기댓값 5%)이고, 축마다 7일에 한 번 굴립니다. 서버 날짜와 시드로 굴려 접속·교체·저장 되돌리기로 다시 뽑을 수 없습니다(현중 11/19 13:54 · `data/core_proposal/idol_ability_step_config.csv` `over_roll_basis`=absorb_band · `over_roll_min`=1 · `over_roll_max`=9 · `over_roll_period_day`=7). 예: 재능 40~49 축은 재능선 아래 100%, 위 1~9%입니다.

이 규칙이 옛 재능 이후 가중치 `second_weight` 2.0을 대신합니다. 표 연결 끝(11/19 아론). 재능선 위 「?」 게이지는 HUD 방에서 만듭니다(개발 안 됨).

표시 점수는 공통 `ability_score_mult`로 변환합니다. 현재 표의 배율은 `1000`이고 내부 계산·저장은 원점수를 유지합니다. 현재값·재능선·천장·증가량은 같은 표시 단위로 비교합니다. 실제 0과 값 없음은 다릅니다. 값이 없으면 0을 넣어 계산하지 않고 빈 값으로 표시합니다. 정수 규칙은 보이는 숫자뿐 아니라 연출·좌표·시간·정렬·작은 비율까지 모든 값에 적용하고, 작은 값은 표마다 단위를 새로 정해 정수로 둡니다. 소수는 첫째 자리까지만 씁니다(현중 11/19 13:56 · 13:57).

```mermaid
flowchart TD
  A[출처의 세부 대상과 입력] --> B[현재 점수의 성장 구간]
  B --> C[구간 시작과 재능선 비교]
  C --> D[구간 필요량과 시설 효과]
  D --> E[상한 전 증가량]
  E --> F[도착 상한과 기존 이월]
  F --> G[실제 증가와 다음 이월과 버림]
```

입력량이 커도 맨 끝 점수에 배수만 곱하지 않습니다. 먼저 현재 구간을 얼마나 채울 수 있는지 계산하고, 구간을 넘으면 다음 구간의 필요량으로 계산을 이어 갑니다. 이후 도착 상한과 남은 성장 공간을 적용합니다.

### 출처마다 같은 계산에 들어가는 길

| 출처 | 들어가는 길 | 구분할 점 |
|---|---|---|
| 보드 칸 도착 | 현재 칸의 성장 대상과 입력 → 팀 멤버별 단계표 계산 | 팀이 같은 칸에 있어도 각자의 재능·현재값으로 계산합니다 |
| 카드 | 카드의 대상·별·나눔 몫 → 멤버별 성장 입력 | 카드 성장은 도착이 아니므로 도착 판정과 주사위 배수를 그대로 붙이지 않습니다 |
| 레슨 시설 | 시설 단계의 효과 → 단계표의 건물 유효 배수 | 투자 행위와 주사위 굴림은 별개입니다. 시설 단계는 재추첨하지 않습니다 |
| 클릭 성장 시험 | 출처·지속 효과·첫 회 즉시 효과 → 기존 성장 순서 | 즉시 효과는 첫 회만, 지속 효과는 매 회 적용합니다. 실제 카드 보상 지급으로 기록하지 않습니다 |
| 학습 | 외국어 1칸의 시작값과 학습 출처 → 외국어 현재값·등급 · 그 안의 속성 3개(영어 50 · 중국어 30 · 일본어 20, 표 `foreign_language_attr`)는 외국어가 오른 양을 비중대로 나눠 보여 줌 | 무대 능력 18세부 합과 나눠 읽습니다. 전용 입력이 없는 시험에서 0을 만들지 않습니다 |

실제 도착 결과는 메인에서 한 번 정한 문맥을 전용 도구로 넘깁니다. 전용 연출이 같은 성장을 다시 계산해 두 번 지급해서는 안 됩니다. 예상 비교도 지급 기록이 아닙니다. 오른쪽 예상은 같은 조건을 계산한 값이고, 실제 증가는 같은 run·멤버·세부의 전후값이 맞는 기록만 표시합니다.

### 멤버 단계와 학습이 연결되는 방법

멤버 단계는 **연습생 → 데뷔조 → 라이징 스타 → 톱스타 → 월드스타**입니다. 이 단계는 성장 계산 구간과 다릅니다. 성장 계산 구간은 점수가 오를 때의 속도를 정하고, 멤버 단계는 세부 최대와 다음 승급 조건, 화면의 단계명, 이야기 공개에 쓰입니다.

승급 준비는 다음 단계의 18세부 능력 합과 학습 조건을 읽습니다. 카드 장수는 승급 조건이 아니며, 처음 획득한 카드의 효과는 해당 멤버의 능력 성장에 반영합니다. 학습 등급은 영어·중국어·일본어 각각의 점수를 등급표와 비교하고 그중 가장 높은 등급을 사용합니다. 다음 단계에 학습 조건이 있으면 함께 충족해야 준비 상태가 됩니다. 문서에 숫자를 복사해 별도 판정식을 만들지 않습니다.

실제 보드의 승급은 굴림 전부터 준비되어 있던 멤버가 승급 칸에 도착할 때 진행됩니다. 후보를 능력 합 순으로 확인하고 **준비된 각 멤버가 한 단계씩** 오릅니다. 이번 도착에서 막 조건을 채운 멤버는 다음 승급 기회를 기다립니다. 승급 무대 칸 목록은 화면 표에서 읽으며, 능력·학습 조건만 차자마자 자동으로 단계를 올리는 방식은 아닙니다.

단계가 바뀌면 성장 스냅샷의 단계 ID·순서가 갱신됩니다. 공통 캐릭터 정보는 이 단계가 현재 팀의 유효한 기록인지 검증한 뒤 이야기를 공개합니다. 학습은 이 과정의 승급 조건으로 들어갈 수 있지만 서사 공개 함수가 언어 점수를 직접 읽어 장을 여는 것은 아닙니다. 현재 학습 조건 표와 제안서 사이의 차이는 7장에 분리합니다.

### 서사를 만드는 재료와 조합 규칙

서사는 매번 새 글을 쓰는 방식이 아니라 **이미 뽑은 배경 조각을 단계별 문장 틀에 넣어 한 번 만들어 보존하는 방식**입니다. [랜덤 멤버 생성](랜덤멤버생성_기획서.html)이 만든 집안·사는 곳·지원 동기·약점·경력·숨은 특기, 여섯 조각이 재료입니다. 각 조각에는 짧은 칩 이름과 그 인물이 말하는 원문이 함께 있습니다.

배경 조각은 `audition_background_piece`에서 선택합니다. 성격 유형과 맞는 조각에 가중치를 주는 경로가 있고, 사는 곳은 그 가중치에서 제외합니다. 서사 생성 함수는 이 배경을 다시 뽑지 않고 받은 `backgroundPieces`만 사용합니다. 성격과 배경의 연결은 `audition_background_piece` 등 원본 표를 읽고, 능력·재능 생성 범위는 `member_init_rule` 재능 20~90 · 능력 4~16으로 세팅합니다.

`member_story_template`는 장 코드·본문 틀·대사·공개 단계로 구성됩니다. 생성 함수 `buildMemberStory()`는 소개, 합격 프롤로그, `step_0`부터 `step_4`, 월드스타 에필로그의 여덟 장을 대상으로 각 장의 유효한 틀 하나를 고릅니다. 같은 배치 시드·같은 멤버·같은 장이면 같은 추첨 경로를 사용합니다. 결과에 장 코드·선택한 틀 ID·해금 단계·완성 본문·대사를 저장합니다.

| 틀의 표현 | 채우는 재료 | 뜻 |
|---|---|---|
| `〔weakness〕` | 약점 조각의 `chip_label` | 짧은 약점 이름 |
| `〔weakness_말〕` | 약점 조각의 `text` | 생성 때 고른 원문 발언 |
| `〔weakness\|이〕` | 약점 이름과 한국어 조사 | 받침에 맞게 이/가를 붙인 문구 |
| `unlock_step` | 장에 저장된 공개 단계 | 화면에서 이 장을 보여 줄 수 있는 조건 |

예를 들어 원본의 약점 조각 **무대공포**에는 「조명만 켜지면 다리가 굳어요.」라는 발언이 있습니다. 이 조각과 `step_1_01` 틀이 선택되면 **“데뷔 무대 조명이 켜지자 무대공포가 다시 숨을 조였다.”**처럼 약점 이름과 조사가 결합합니다. 뒤의 첫 팬 편지 장면과 대사는 선택된 틀의 내용입니다. 이것은 원본을 조합한 설명 예이며 특정 멤버에게 실제로 발생한 새 플레이 기록이 아닙니다.

배경 조각이나 필수 문구가 없거나 알 수 없는 변수가 남으면 해당 장은 자료 대기로 남깁니다. 임의의 사연을 써서 채우지 않습니다. 이미 저장된 서사는 일부만 있거나 비어 있어도 다시 추첨하지 않습니다. 따라서 같은 멤버의 배경과 이야기는 화면을 오갈 때 바뀌지 않습니다.

```mermaid
flowchart LR
  A[이미 뽑힌 배경 여섯 조각] --> B[장 코드별 문장 틀 선택]
  B --> C[원문 변수와 조사 치환]
  C --> D[멤버 서사 배열 보존]
  D --> E[오디션 보드로 장 변환]
  E --> F[찜한 만큼 장 공개]
  D --> G[공통 정보의 원본 서사]
  G --> H[검증된 성장 단계로 공개]
```

왼쪽은 글을 만드는 과정이고 오른쪽은 저장한 글을 보여 주는 과정입니다. 장을 공개할 때 배경이나 틀을 다시 뽑지 않습니다. 오디션 보드 변환에서 빠지는 특수 장은 아래의 화면별 전달 설명처럼 따로 구분합니다.

### 선택과 성장에 따라 다음 이야기가 열리는 방법

**오디션의 찜과 합류 후 성장 단계는 공개 기준이 서로 다릅니다.** 두 경로 모두 저장된 이야기를 보여 주며, 선택할 때마다 다른 결말을 새로 만드는 구현은 아닙니다.

| 경로 | 행동·입력 | 공개 판정 | 화면 결과 |
|---|---|---|---|
| 오디션 보드 | 만난 후보를 찜 | 그 후보의 `storyOpened`를 하나 늘리고 실제 장 개수까지만 허용 | 공개한 개수만큼 장을 보여 주고 최신 장을 펼침 |
| 합류 후 공통 정보 | 같은 팀의 검증된 성장 단계 | 장의 `unlock_step` ≤ 실제 `stage_order` | 해당 단계까지 열린 장·대사 표시 |
| 성장 저장 연결 전 | 공개 소개와 인계 자료 | 공개 소개는 허용하고 단계가 필요한 장은 확인 대기 | 임의로 성장 단계를 추정하지 않음 |
| 성장 시험 작업대 | 시험 능력·시험 단계 | 시험 사본의 계산과 관측 | 원래 멤버의 서사 공개 기록은 바꾸지 않음 |

반복해서 찜하면 그 후보의 다음 장이 더 열립니다. 이것은 후보에 대한 관심이 늘면서 이야기를 알아가는 규칙입니다. 합류 뒤에는 실제 성장 단계가 공개 기준입니다. 예를 들어 `step_1` 장은 검증된 단계 순서가 1 이상일 때, `step_4` 장은 4 이상일 때 표시할 수 있습니다. 이름이 비슷한 두 상태값을 합치거나 찜 횟수로 실제 승급을 만들지 않습니다.

서사는 생성 재료에 여덟 장이 있어도 모든 화면이 여덟 장을 받지는 않습니다. 현재 오디션 보드로 바꾸는 함수는 공개 소개와 `step_0~4`를 넘깁니다. 합격 프롤로그와 에필로그는 그 변환에서 빠집니다. 공통 정보창은 보존된 원본 서사와 실제 연결 상태를 기준으로 보여 주므로 각 화면이 받은 장 목록을 확인해야 합니다.

학습과 다음 이야기의 관계도 이 순서로 읽습니다. **언어 현재값 → 학습 등급 → 다음 승급의 조건 확인 → 실제 승급 저장 → 그 단계 이하의 이야기 공개**입니다. 학습량만 늘었다고 장이 바로 열리거나, 약점이 수치상 해소되어 결말이 바뀌는 규칙은 이 경로에 없습니다. 이야기의 “약점 극복”은 단계별 틀에 담긴 표현이며 별도의 약점 상태 판정과 보상으로 연결하려면 추가 규칙이 필요합니다.

```mermaid
flowchart TD
  A[언어별 현재 점수] --> B[학습 등급표와 비교]
  B --> C[다음 단계의 능력과 학습 조건]
  C -->|준비 조건 충족| D[다음 승급 칸 기회]
  D --> E[실제 승급과 단계 저장]
  E --> F[세션과 단계의 유효성 검증]
  F --> G[장별 공개 단계 비교]
  G --> H[열린 본문과 대사 표시]
```

학습은 다음 단계 행에 조건이 있을 때 승급 준비에 참여합니다. 승급하지 않은 학습 변화가 이 도식의 뒤쪽으로 바로 건너뛰지는 않습니다. 장의 공개 판정은 검증된 실제 단계로 하며 현재 표의 조건 정합 문제는 7장의 작업 항목으로 남깁니다.

### 서사가 화면에 보이고 다음 시스템으로 전달되는 방법

공통 정보창은 배경 칩과 소개·대사를 먼저 보여 주고 장 선택 목록으로 이야기를 바꿉니다. 각 장에는 열림·잠김·자료 대기, 필요한 단계명을 표시합니다. 잠긴 장과 대기 장의 본문은 화면을 그리기 전 모델에서 제거하므로, 잠금 문구 뒤에 실제 본문을 숨겨 넣지 않습니다.

서사는 현재 능력과 나란히 읽는 설명 정보입니다. 문장에 “극복했다”, “세계 무대”가 나와도 그것만으로 능력·팬·학습·라포·보상을 바꾸지 않습니다. 수치 변화는 성장 출처와 정산 기록, 공개 여부는 이야기 조건이 각각 맡습니다. 다른 시스템에는 멤버 ID와 원본 서사, 현재 성장 스냅샷의 단계와 능력을 나눠 전달합니다.

### 필요 시스템

동일 멤버를 유지하는 세션 reader, 단계표 순수 계산기, 실제 성장 저장 adapter, 카드 소유·효과 기록, 언어 등급표, 서사 생성기와 공개 모델이 필요합니다. 시험 도구는 이 원본 계산기를 재사용하고 메모리 사본만 바꿉니다. 서로 다른 저장이나 다른 세션을 대신 읽지 않도록 식별값과 버전을 확인합니다.

서사의 “생성”은 `casting.mjs`와 `member-story.mjs`, “공개 판정”은 `character-info-story.mjs`, “표시”는 `character-info-view.mjs`로 나뉩니다. 능력과 학습을 내보내는 `growth-adapter.mjs`가 서사 본문을 새로 만들지는 않습니다. 이 경계를 유지해야 글 내용 변경과 성장 계산 변경을 서로 독립적으로 다룰 수 있습니다.

### 화면·연출 목록

| 화면 | 보여 주는 것 | 조작과 값의 경계 |
|---|---|---|
| 모바일 성장 | 현재 능력 육각형·재능·선택 대상 | 공식과 원본 경로 장문보다 현재 상태를 먼저 보여 줌 |
| 오른쪽 시험 작업대 | 시작/현재/변화·곡선·세부 조건·계산 과정 | 예상 계산과 실제 지급 기록을 구분 |
| 공통 캐릭터 정보 | 멤버의 능력·외국어·배경·서사 장 | 같은 멤버의 검증된 저장과 공개 조건 사용 |
| 승급 연출 | 이전/다음 단계·무대 이름·출전권 표시 | 실제 보드에서 승급한 결과를 표현 |
| 3D 뉴런 | 능력 구체·재능 띠·이번 성장 신호·관계선 | 실제 기록과 `displayOnly` 시험 사본을 구분 |

3D 뉴런에서 굵은 띠는 현재 능력, 점선 띠는 재능, 끊긴 띠는 기록 대기, 번지는 빛은 이번 성장입니다. 세부 → 대표 축 → 아이돌의 증가 경로를 보여 줍니다. 이해는 선 굵기, 협력은 수평 거리, 긴장은 높이, 신뢰는 바깥 빛무리로 읽습니다. 실제 0과 미확인을 같은 선으로 표현하지 않습니다.

```mermaid
flowchart LR
  A[현재 팀의 실제 저장] --> B[같은 세션을 읽음]
  B --> C[메모리 시험 사본]
  C --> D[원본 계산기로 반복 시험]
  D --> E[현재값과 차이와 시험 뉴런]
  A --> F[메인 보드의 실제 진행]
  F --> G[실제 성장 저장 갱신]
  G --> H[실제 단계로 이야기 공개]
```

위쪽 관측 결과는 시험 사본 안에서 이어지고, 아래쪽 진행 결과만 실제 성장 저장을 갱신합니다. 시험 화면의 단계 선택이나 뉴런 표시를 실제 승급과 이야기 해금으로 기록하지 않는 이유가 이 저장 경계입니다.

### 남은 결정

생성 범위와 성장량, 단계별 카드·능력·학습 문턱, 시설 효과의 발란스 값은 원본 표에서 정합니다. 값이 없는 칸은 0으로 채우지 않고 비어 있음으로 표시합니다. 경험에 따른 특화, 서사 선택의 갈래와 수치 효과, 성장 이후 시즌 결산은 이 문서에서 임의로 새 규칙을 붙이지 않습니다.

### 컨디션에 따른 능력 획득과 몬스 관리

**신규 기획 · 지금 정책 v6**(`idol-condition.care.v6.20261109`). 상세 원본: [P96 몬스](몬스_기획서.html#mons-inner-plan-20261105) · [P223 보유·배정](몬스보유_핵심제안서.html#mons-inner-plan-20261105) · [P107 개인 성장](아이돌능력_기획서.html#mons-inner-plan-20261105) · [P169 성장 연결](성장관계_기획서.html#mons-inner-plan-20261105)

#### 컨디션 게임으로 정리한 기준

아이돌별 컨디션을 몬스가 돌보는 구조입니다. 기획사 보유 몬스를 아이돌에게 배정하고, 배정 몬스로 현재 컨디션 단계에 대응하는 게임을 플레이해 회복합니다. 사용자가 지정한 이름은 ‘컨디션 게임’이며, 아이돌 컨디션 5단계와 게임 5단계를 연결합니다.

능력이 실제 오르면 컨디션이 감소하고 이후 새 능력 획득 배율에 반영합니다. 기존 스퀘어 전투·몬스와 배경3D·이동형 보스를 재사용하며, 정책 v6의 단계별 보스 시간과 진행률 회복을 적용합니다. 구현과 실제 화면 검수 범위는 아래 연결 현황에서 구분합니다.

앞선 일상/사건 누적 나쁜 영향 게이지와 별도 영구 5단계 해금 초안은 이 설계로 대체합니다. 새 개인 게이지는 컨디션 하나이며, 기획사 나쁜 기운·몬스 공용 행복·전투 체력과 구분합니다.

#### 아이돌 컨디션 5단계

컨디션은 아이돌별 0~100, 신규 합류 초기값은 100입니다. 저장은 0.01포인트 정수 단위로 하고 5단계는 설정표에서 계산합니다. 단계 값을 별도로 저장해 현재 수치와 어긋나게 만들지 않습니다. 아래 범위·배율은 지금 정책 v6(`idol-condition.care.v6.20261109`)으로 세팅합니다.

| 컨디션 단계 | 범위 | 능력 획득 배율 | 대응 컨디션 게임 |
|---|---|---|---|
| 5 · 최상 | 80 이상~100 | 100% | 5단계 · 맑은 무대 |
| 4 · 좋음 | 60 이상~80 미만 | 95% | 4단계 · 집중의 무대 |
| 3 · 보통 | 40 이상~60 미만 | 85% | 3단계 · 흔들리는 무대 |
| 2 · 피곤 | 20 이상~40 미만 | 70% | 2단계 · 잡음의 무대 |
| 1 · 지침 | 0 이상~20 미만 | 50% | 1단계 · 휴식의 입구 |

이번 행동을 시작할 때의 컨디션으로 그 행동 전체의 획득 배율을 한 번 정합니다. 같은 행동이 18개 세부 능력으로 나뉘어도 뒤쪽 항목만 낮은 배율을 받지 않습니다. 기존 능력·재능·천장을 깎지 않고 새로 획득하는 증가량을 조정합니다.

실제 증가가 없으면 감소도 없습니다. 현실 시간·접속 종료·일차 변경만으로 감소시키지 않습니다. 컨디션 0에서도 성장 배율 50%를 유지하고 게임 입장을 막지 않습니다.

#### 능력 획득과 피로의 비율(지금 정책 v6)

| 대상 | 최종 실제 증가 기준 | 컨디션 소모 |
|---|---|---|
| 18세부 능력 | 정규화 점수 합 1점 = 현재 표시 1,000점 | 0.25 |
| 영어·중국어·일본어 | 정규화 언어 점수 합 10점 | 0.25 |
| 태도·성실성·6축 평균·팀 능력 | 18세부에서 계산되는 값 | 추가 소모 0 · 원래 세부 증가에 포함 |
| 초기 능력·불러오기·동기화·시험 강제값 | 새 성장 지급이 아님 | 소모 0 |

소모 = 0.25 × (최종 실제 18세부 증가 합 + 최종 실제 언어 증가 합 ÷ 10). 입력에 단위 태그를 붙여 정규화합니다. 실제 게임 person.got/snapshot은 이미 정규화 단위여서 그대로 읽고, 발란스의 표시 증가량만 ability_score_mult로 나눕니다. TalentSide 내부 값은 tm.scale로 표시값으로 바꾼 후 공통 배율로 나눕니다. 이미 정규화된 값을 다시 나누지 않습니다.

예: 실제 표시 능력 합 +20,000이면 컨디션 -5, 정규화 언어 +20점이면 -0.5입니다. 예상 +20,000 중 상한 때문에 실제 +4,000만 받았다면 -1만 적용합니다. 0.01 미만 반올림 잔량만 누적 보존해 작은 성장 여러 번과 한 번의 큰 성장이 같은 비용이 되게 합니다. 컨디션0을 넘는 소모는 부채로 이월하지 않고 바닥 도달 시 소모 잔량도 비웁니다. 예: 컨디션1에서 소모5가 발생하면0으로 끝내며 다음 보스 처치 성공 시 컨디션100까지 회복합니다.

정규화 언어 1,000은 5등급 문턱이며 성장 상한이 아닙니다. 그 이후 실제 증가도 같은 비율을 사용합니다. 태도·성실성은 현재 각 9세부의 평균이므로 독립 성장으로 다시 차감하지 않습니다.

현재 일일 제한은 daily_cap_kind=step의 세부별 단계 제한이 먼저 적용됩니다. 초반 세부별 10×11.5%×18=20.7일 때 피로 5.175가 되는 산술 예이며, 모든 단계·언어까지 포함한 고정 일상한이라는 뜻이 아닙니다. 현재 약 9.5 정규화점 성장 예시라면 하루 피로 약2.375입니다. 보상 폭증 시 피로도 실제 획득량에 비례합니다.

#### 모든 성장 출처의 공통 최종 정산

1. 실제 지급 행동을 sourceEventId와 candidate_id로 묶고 같은 행동의 시작 컨디션을 한 번 읽습니다.
2. 각 출처의 기존 재능·시설·관계·단계표 또는 카드 고정점수 규칙으로 새 증가 후보를 계산합니다. 정규화된 새 증가분에 컨디션 배율을 한 번 적용합니다. 이미 조건이 적용된 옛 이월량에는 다시 곱하지 않습니다.
3. 도착 상한·이월·능력 천장·아카데미 누계 제한·현재 일일 단계 상한을 모두 반영해 최종 실제 증가량을 정합니다.
4. 실제 양수 증가에서만 피로를 계산하고 능력·컨디션·영수증을 한 번에 확정합니다. 상한 후 취소된 성장·중복 카드·재연출은 피로0입니다.
5. 실제 최종 전후값을 정보창·현황판·뉴런·발란스에 전달합니다. 관측 콜백이나 애니메이션 완료를 새 지급의 근거로 사용하지 않습니다.

보드/레슨·카드/사업 카드 최초 효과·찬스 고정점수·시설 완공·아카데미·언어·합류 뒤 실제 성장 보너스·앨범/모험 등 콘텐츠 정산·방치/오프라인 계산을 포함합니다. 팀 평균·태도·성실성·재능·초기 생성·승급 단계 재표시를 별도 획득으로 더하지 않습니다.

카드의 명목 점수 예산·최초 지급 여부와 실제 획득량은 별도로 기록합니다. 컨디션으로 줄어든 양을 새 카드 지급이나 이월 보상으로 다시 만들지 않고, 카드 원래 대상·분할·단계 예산은 유지합니다.

이월은 앞서 배율이 반영된 새 증가에서 생기는 잔량으로 유지하고, 실제 능력으로 수령될 때 피로를 한 번만 냅니다. 옛 이월은 값 그대로 보존하고 새 증가만 조정합니다. 정산 전에 남아 있던 이월에는 배율을 다시 적용하지 않습니다.

stepGain/preview는 순수 계산으로 유지합니다. 성장 writer가 현재 여러 곳에 있으므로 실제 최종 정산 계층을 새 공통 모듈로 분리하고 모든 경로가 통과하도록 연결해야 합니다.

| 구분 | 제안 필드·책임 |
|---|---|
| 아이돌 상태 | candidate_id, condition_value_bp(0~10000), condition_cost_remainder, revision. 최초 생성/이행 때만10000 부여 |

아이돌 상태·배정·성장/회복 영수증은 같은 진행의 저장과 checkpoint에 함께 반영합니다. 한쪽 저장이 실패하면 모두 되돌립니다. 파생 UI 모델은 값을 읽기만 하고 새 초기값을 생성하지 않습니다.

기존 저장에 필드가 없을 때만 버전 이행으로 컨디션100·미배정을 채웁니다. 이미 저장된0은 유효한 값입니다. 저장된 배정이 실제 보유와 어긋나면 배정만 해제하고 새 몬스를 지급하지 않습니다.

새 표로 dataSignature가 달라져도 현재 팀·능력·지갑·팩·영수증을 유지하는 명시적 버전 이행을 먼저 구현합니다. 기존의 서명 불일치→clearRunRecord/새 캐스팅 경로로 사용자의 현재 진행을 초기화하면 안 됩니다.

첫 합류 handoff, snapshotMember, growth-adapter, 카드 투영·복구, 생성 기반 복원, 뉴런, 발란스 전송, 전체 저장·복원 모두 같은 상태를 보존합니다. 시험 사본은 사본의 컨디션만 바꾸고 원래 게임에는 쓰지 않습니다.

같은 아이돌 또는 같은 몬스의 컨디션 게임 동시 입장은1판으로 제한합니다. 새로고침 뒤 유효한 전투 checkpoint가 있으면 같은 입장 영수증으로 재개하고, 없으면 회복 없이 안전 종료해 잠금을 해제합니다. 다른 세션/실행의 결과는 수령하지 않습니다.

피로 잔량은0.01 미만 정밀도 보존만 맡습니다. 컨디션0 아래의 초과 소모를 저장하거나 회복을 상쇄하는 부채로 만들지 않습니다. 0인 채 성장한 뒤 성공하면 현재0→100으로 회복되어야 합니다.

#### 현황판의 컨디션 조회 표시

컨디션 엔진을 이번에 새로 개발한 것이 아닙니다. 성장 보정·몬스 배정·전투/승리 회복과 현재 v6 정책은 기존 구현을 유지하고, 현황판이 그 값을 읽어 보여 주도록 연결했습니다. 실제 회복 지급·원본 저장 왕복이나 모든 아이돌 화면의 통일을 이번 표시 검수 완료로 넓히지 않습니다.

| 구분 | 현재 표시와 경계 |
|---|---|
| 개인 컨디션 | 현재 아이돌 ID의 저장된 컨디션을 짧은 수치와 게이지로 표시. 원본 snapshot 변경을 그대로 따라감 |

| 정산·나쁜 기운 | 조회 화면에서 성장·피로·회복·영수증·저장을 실행하지 않음. 개인 컨디션과 기존 기획사 나쁜 기운은 별도 |

기준 원본은 [컨디션 정책 v6](/data/simulator/idol-condition.json)와 [기존 전투 설정](/data/simulator/idol-condition-game.json), 조회 표시는 [현황판 공통 표시](/src/tools/growthBoard/condition-view.mjs)입니다. 단계별 보스 시간·진행률 회복·단계 경계는 원본을 읽으며 이번 작업에서 새 수치를 정하지 않습니다.

#### 현재 컨디션 규칙과 캐릭터 정보 연결

컨디션 전투는 이동형 CRUSHER와 TITAN을 사용합니다. 고정형 NEXUS는 이 모드에서 제외하고 기존2·5단계를 CRUSHER로 연결합니다. 원래 스퀘어 게임의 NEXUS·벽 패턴과 원본 자산·CSV는 변경하지 않습니다.

개인 컨디션은0~100이며 기획사 나쁜 기운과 별개입니다. 캐릭터 정보의 개별 능력에서 컨디션·배정 몬스·게임 입장 상태를 확인합니다. 미배정은 기존 몬스 배정 화면으로, 배정됨은 같은 아이돌의 기존 컨디션 게임으로 연결합니다. 사용한 몬스는 게임 종료 후24시간 쉬며 다른 아이돌에게 옮겨도 제한을 유지합니다. 패배도 사용으로 세고 나가기·안전 취소는 회복0·사용 횟수 제외입니다.

현재 회복 방식은 정책 v6의 fill_by_progress입니다. 전투 설정의 웨이브 표는3단계 기준이며, 다른 단계는 보스 등장 시간의 비율로 웨이브·종대 시각을 늘리거나 줄입니다. 스킬 선택 카드는 전투 화면 크기를 바꾸지 않고 하단에 겹쳐 표시하며 전투·선택권 누적은 계속됩니다. 보스 처치는100까지, 패배는 정산 시점의 빈 만큼×진행률을 회복합니다. 고정 회복값 recovery_bp와 기본 보스 시간은 fixed 방식의 값이므로 현재 방식의 회복량·단계별 시간으로 쓰지 않습니다. 실제 결과와 중복 지급 검사는 기존 계산·저장 어댑터가 맡습니다.

발란스 자동 진행에서만 컨디션50% 이하이고 배정 몬스가 쉬지 않을 때 자동 사용합니다. 현재 자동 판은 완주를 가정한 시험 계산이며 실제3D 플레이 결과가 아닙니다. 시뮬 하루는86400초로 계산하고 주사위 한 번 또는 오프라인 계산이 끝난 뒤 검사합니다. 여러 날 오프라인 계산은 마지막에 한 번만 검사합니다. 본 게임 수동 플레이에 자동 완주를 적용하지 않습니다.

`src/game/core-proposal/stepTable.ts`는 순수 성장량을 계산하고, `src/simulator/shared/growth-step-runtime.mjs`는 실제 입력·상한·이월을 연결합니다. `growth-adapter.mjs`는 현재 수치와 단계를 공통 저장 모양으로 바꿉니다. `growth-lab/model.mjs`와 `live.mjs`는 원래 계산기를 시험 사본에서 반복합니다. `member-story.mjs`는 글을 만들고 `character-info-story.mjs`는 공개 여부를 판단합니다.

- 같은 세션·멤버의 처음 재료가 성장·정보창·서사 화면에서 유지되어야 합니다.

- 잠긴 장의 본문은 화면 모델에 들어가지 않아야 합니다.
