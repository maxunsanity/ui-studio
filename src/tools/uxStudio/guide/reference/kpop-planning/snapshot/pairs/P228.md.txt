**2026-11-10 17:01 KST** 찜 선택·출전곡 상세 투표 보정: 찜한 곡은 채운 하트와 ‘찜 완료’로 표시합니다. 감상용 시험곡의 찜은 점수 원장과 분리한 개인 보관함에 실행·세션·시즌·내 팀 범위로 보관합니다. 데이터 갱신·화면 이동·새로고침으로 사라지지 않으며 전체 초기화는 새 범위를 엽니다. 찜한 출전곡은 보관함과 곡 상세/재생 화면 모두에서 투표 확인창을 열 수 있습니다. 음원 목록에서 바로 투표를 쓰지는 않습니다. 감상용 곡에는 ‘감상용·투표 대상 아님’을 표시하고 주간·월드 출전곡 입구를 제공합니다. 출전곡이 아닌 곡을 실제 대회 후보로 만들지 않습니다.

**구현과 정책의 구분:** 자유 시험에서는 가져온 데이터도 인기 재화를 무제한으로 사용하며, 사용 영수증·곡별 기여를 공통 실행/세션/시즌/내 팀 범위로 보관합니다. 화면 재진입·새로고침으로 재사용하지 않고 기존 전체 초기화가 새 범위를 엽니다. 인기 기여 차트는 사용한 인기의 누적량을 비교하는 시험 순위입니다. 실제 활동의 인기 획득 공급·유한 지갑·지급량·상한·최종 우승 점수 비중은 발란스/운영 연결 대기입니다. 인기 기여 순위와 기존 월드 종합 시험 순위를 같은 점수라고 표시하지 않습니다.

### 세 차트 보상·앨범 누적·월드 보드 전환

**2026-11-10 15:16 KST - 현중 직접 지시 반영 · 제안(검수 대기)**

| 차트 | 보상 종류 | 용도 |
|---|---|---|
| 일반 랭킹 | 한 바퀴 보상 | START 통과 정산·일반 성장 |
| 주간 페스티벌 | 레이싱 연료 | 레이싱 사용 |
| 월드 페스티벌 | 인기 재화 | 월드 출전곡 인기 기여 |

**현중 직접 정정:** 일반 차트·주간 차트·월드 차트의 세 개로 구분합니다. 주간과 월드는 개최 기간이 겹치지 않습니다. 일반은 한 바퀴 보상, 주간은 레이싱 연료, 월드는 인기 재화로 획득 내역과 표시를 분리합니다. 지급 수량·상한·정확한 획득 사건은 발란스 대기이며 인기 재화를 연료로 대체하지 않습니다.

**앨범 누적 기여:** 대표곡 한 곡을 우대하고 지난 발매곡들도 낮은 가중치로 기여하는 기존 기획을 일반 한 바퀴 보상에 명확히 연결하는 제안입니다. 1개와 8개의 차이를 보유곡 기여·직전 성적 계승·출전곡 선택 폭으로 구분합니다. 앨범 수만으로 활성 버프를 8중 적용하지 않습니다. 대표곡/구작/시간 감쇠 계수는 정본 미정값을 보존합니다.

**월드 신청과 보드 복귀:** 성공한 월드 신청의 출전곡·현재 팀을 확인한 뒤 게임으로 돌아오면 같은 보드의 연습실·녹음실 등에 공연용 간판과 월드 표시를 적용합니다. 표시가 준비된 뒤 폰 내부 모달 「월드 공연 보드로 전환됐어요」와 「공연 보드 확인」 버튼을 보여 줍니다. 신청 실패·취소·보기만 한 경우·주간에는 표시하지 않습니다. 확인한 같은 시즌/팀의 전환 알림은 재진입·새로고침·개인/크루 중복 출전으로 반복하지 않습니다. 표시가 준비되기 전에 알림을 소비하지 않습니다.

**기간·보존:** 일반 연결은 실제 월드 기간의 유효 신청을 확인합니다. 단독 테스트는 명시적으로 선택한 월드 시험만 전환하며 주간 시험으로 바꾸면 일반 보드로 복원합니다. 개인/크루 성공 기록은 보존합니다. 다음 시즌·새 공통 시험 데이터는 별도 범위로 처리합니다. 월드 종료 시 원래 시설 간판을 복원합니다.

**현재 구현 범위:** 월드 간판·표시 프로필과 1회 복귀 모달은 이번 로컬 연결 대상입니다. 건물 위치·레벨·기존 경제 writer를 바꾸거나 공연 결과·인기 재화·상금을 이 표시만으로 새 지급하지 않습니다. 실제 공연 조작/정산·월드 일반 성장 효과의 유지/대체·세 보상의 최종 지급표·누적 기여 계수는 후속 연결/발란스 대기입니다.


**현재 단독 테스트 · 2026-11-10 13:58 KST · 제안(검수 대기)**

게임 시뮬레이터 단독 테스트는 상위 메뉴를 주간 페스티벌과 월드 페스티벌로 나눕니다. 폰 하단도 주간·월드로 바로 엽니다. 일반 월드 입구는 개인 출전이며, 크루 출전은 응원 크루의 고정된 크루장 전용 신청 버튼에서만 시작합니다. 크루 화면에는 앨범의 데뷔 준비·앨범 활동·차트·파이널 단계표를 표시하지 않습니다. 주간 신청 뒤에는 레이싱 입장과 주간 진행·레이싱 기록을 바로 볼 수 있습니다. 레이싱 입장은 같은 발매 앨범의 기존 시티 투어 자동차 레이싱으로 연결합니다. 기록은 기본 펼침으로 표시합니다.

단독 테스트에서 월드 메뉴(개인·크루)에 진입하면 현재 주간 신청·버프·자동 연료/레이싱 진행을 새 시험 상태로 초기화합니다. 원본 신청 영수증은 이력으로 보존하고 현재 유효한 신청에서 제외합니다. 다시 주간에 들어오면 앨범 선택·신청부터 시작합니다. 앨범·공통 팀·이미 지급된 공통 재화·월드 신청·크루 투표는 지우지 않습니다. 이전 자동 진행 기록은 다음 실제 보드 저장에서 보관하며 활성 기록과 분리합니다. 이 초기화는 단독 테스트만의 조작이며 실제 운영 일정·게임 일차·일반 연결 플레이의 버프 정책을 바꾸지 않습니다.

자유 테스트에서는 이전 앨범의24시간 차트가 진행 중이어도 새 앨범을 먼저 발매할 수 있습니다. 기존 차트·실적·제작비 결제·발매곡을 보존하고 새 곡의 이벤트 참가는 순서대로 대기합니다. 기존 순차 차트 진입 경로를 사용하며 일반 연결 플레이의 차트 잠금과 운영 수치는 변경하지 않습니다.

주간·월드의 일반 입구는 모두 개인 신청입니다. 내 발매 앨범을 선택하고 같은 화면에서 신청하며, 월드는 성공 뒤 내 출전곡 참여 로비를 엽니다. 개인/크루 선택·선택되지 않은 곡 확인·별도 준비 단계를 두지 않습니다. 크루 소속·직책과 관계없이 크루장과 멤버도 개인 월드에 출전할 수 있습니다.

크루 월드 신청은 크루 페이지에서 크루장에게만 켭니다. 현재 멤버가 공유된 발매곡 한 곡에 내부 투표합니다. 한 번 투표하면 바꾸거나 취소할 수 없습니다. 투표 결과는 참고용이며, 크루장이 득표와 무관하게 최종 공유곡·원소유자 사용 동의를 확인해 신청합니다. 원소유자는 일반 크루원이어도 크루 페이지에서 자기 곡의 회차 사용 동의·철회를 할 수 있습니다. 내부 곡 투표는 관객의 공식 페스티벌 투표·점수·재화와 별개입니다. 개인 출전과 크루 출전을 서로 잠그지 않습니다.

주간 버프는 신청한 경우에만 해당 주의7일째부터 공통 주간 마감까지 적용합니다. 7일째 중간에 신청하면 신청 이후 남은 기간만 받습니다. 신청일부터24시간을 새로 주지 않으며, 신청 전 활동을 소급하지 않습니다. 미신청·다음 주·월드 기간에는 주간 버프가 없습니다. 다음 주에는 새로 신청합니다. 게임 시뮬레이터의 표시는 현재 게임 일차·실제 굴림 시계를 사용하며 실제 서버 시계와 구분합니다.

## UI 기획 · 개별 화면 시험과 연동 제작 계획

앨범·공연·음악 앱·페스티벌은 각각 열어 시험할 수 있는 모듈로 만듭니다. 연동에서는 같은 팀·곡·공연·대회 정보를 사용하고 각 모듈의 진행 결과를 공유합니다. 감상 입구는 음악 앱에 모으며, 제작·활동·신청 UI를 하나의 거대한 화면으로 합치지 않습니다.

현재 개발되지 않음, 진행 중 · 이번에는 UI 기획과 메모리 시안을 작성했습니다. 기존 앨범/신청/음악 앱은 재사용하고 실제 공연 공급·공식 평가/인기 경제는 후속 제작으로 구분합니다.

### 주간·월드의 별도 UI

주간·월드 신청 UI는 별도로 제작합니다. 실제 플레이는 현재 주간 기간이면 주간만, 월드 기간이면 월드만 신청할 수 있게 표시합니다. 시뮬레이터의 개별 시험 입구에서는 두 화면을 각각 열어 해당 기간·미개막 상태를 시험합니다. 월드는 시즌 피날레용 무대·포스터·색/빛 연출과 출전 방법·참여 경험·시즌 기록 안내를 강화합니다. 내 출전곡 소개·시즌 순위 경쟁은 기존 흐름을 사용하고, 베스트 컷·발견 노출·시즌 회고 혜택은 기존 후속 기획으로 구분합니다. 추가 보상 종류·수량·인기 경제는 결정/발란스 대기입니다.

### 메뉴별 시험 시작점

앨범 발매 상위 메뉴의 기본 진입은 음원 제작입니다. 새 공통 테스트에서는 음원 제작 전 음악 선택 화면으로 시작하고 자동 시험 발매를 실행하지 않습니다. 작성 중인 초안은 이어가고 기존 발매곡은 보존합니다. 시티 투어는 제작·발매된 곡과 필요한 리그를 준비한 뒤 차량 선택·급유로 바로 시험합니다. 곡이 필요한 하위 콘텐츠의 준비와 제작 메뉴의 미제작 출발을 구분합니다.

### 화면 구성·주동작·복귀

| 화면 | 먼저 보는 내용 | 버튼·배치 | 이동/복귀 |
| --- | --- | --- | --- |
| 앨범 제작 | 현재 단계·선택 음악·참여 팀·큰 재킷 | 음악/재킷/제작·발매 주동작과 비용·오류를 하단 고정. 참여 옵션은 접기 | 음악→재킷→제작 완료→발매. 같은 초안 보존 |
| 앨범 활동 | 발매곡·앨범 이벤트 차트·남은 시간·현재 활동 | 보드에서 활동 / 같은 곡 감상 / 페스티벌 신청. 자세한 계산은 접기 | 선택 이동은 모바일 내부 확인, 같은 곡으로 복귀 |

| 주간 신청 UI | 개인 전용·내 발매 앨범 목록·선택 상태 | 앨범 선택과 주간 신청 버튼만 | 신청 완료·보드 복귀 → 해당 주7일째에 상단 버프 |
| 월드 신청 UI | 월드 기간·시즌 무대·내 앨범·참여 경험/혜택, 크루 입구 별도 | 화려한 무대·내 앨범 선택과 신청, 상세 안내 접기 | 월드의 성공 출전곡만 월드 활동 로비 |
| 페스티벌 참여 | 현재 회차·등록곡·참여 중·순위 또는 집계 전 | 순위·다른 곡 듣기 / 대회 보기. 재신청 폼 숨김 | 같은 회차 음악 앱→같은 출전곡 로비로 복귀 |

| 개별 진입 | 앨범·공연·음악 앱·페스티벌 어디든 바로 열기 | 이전 메뉴 완료 요구 없음. 누락된 시험 준비만 1회 수행, 초안 보존 |
| 앨범↔보드 | 발매곡의 활동 입구→보드→곡 차트 | 같은 팀·곡·기존 활동/START 영수증. 왕복으로 새 발매/지급 없음 |
| 보드↔공연 | 해당 장소의 실제 공연 시작→PIP→확인→관람→복귀 | 같은 공연 ID·채널·곡·종료 상태. 취소는 이동만 취소, PIP 닫기는 공연 취소 아님 |
| 대회↔음악 앱 | 신청 성공→활동 로비→확인→같은 회차 차트→복귀 | 같은 round/entry·개인/크루·곡. 조회/재생이 투표 제출이 아님 |
| 누락·오류 | 곡 없음·사용자 초안·공연 없음·미개막·동의 없음·원본 연결 대기 | 없는 원본은 대기/빈 화면. 다른 공연·곡·회차로 대신 채우지 않음 |
| 공유·복원 | 발란스 가져오기→여러 메뉴 조작→재접속→전체 초기화 | 가져온 데이터/결과 공통 유지·시험 재화 무제한. 초기화 전 새 수신/메뉴 진입이 덮어쓰지 않음 |

시험 조작·상태 선택은 오른쪽/외부 검수 패널에 둡니다. 모바일 본문에는 현재 행동·대상·비용/실패 사유를 먼저 보입니다. 다른 콘텐츠 이동은 모바일 내부 확인을 거치며, 같은 음악 앱의 곡/공연 상세 이동은 직접 처리합니다. 페스티벌 점수 설정·투표 시험·월드 인기·우승은 기존의 접힌 보조 도구 안에 함께 둡니다. 음악 앱의 하위 메뉴는 음원·공연·숏츠이며 같은 음악 앱 안에서 각각 시험합니다.

### 화면마다 무엇을 누르나요

| 화면 | 보여 줄 흐름 | 주동작·다음/복귀 |

| 앨범 준비 | 현재 팀·음악·참여 옵션 → 재킷·제작 조건 | 제작 완료 → 앨범 발매 · 이전으로 가면 같은 초안 유지 |
| 발매 직후 | 같은 곡의 발매 결과·앨범 이벤트 차트 | 보드로 복귀 / 음악 앱에서 감상 / 페스티벌 신청을 선택 |

| 주간 신청 | 개인 전용·내 발매 앨범 선택/신청 | 성공 후 게임 상단 버프 중 표시·보드 복귀 |

| 페스티벌 활동 로비 | 내 등록곡·현재 회차·순위 또는 집계 전 | 순위·다른 곡 듣기 → 같은 회차 음악 앱 / 대회 보기 → 대회 선택 |
| 음악 앱 | 음악·차트·보관함을 기본으로 공연·숏츠 연결 | 곡 상세 → 이 곡의 스테이지 / 홈 → 지금 공연 중 / 상단 → 숏츠 발견 |
| 감상 후 복귀 | 같은 곡·공연·회차와 원래 위치 | 뒤로는 직전 곡·목록, 게임 복귀는 보드 또는 진입한 대회 로비를 유지하는 기획 |

### 같은 곡으로 연결할 기준

| 기준 | UI·데이터 관계 |
| --- | --- |
| 같은 곡 | 앨범 ID·곡 참조·고정 참여자를 유지합니다. 실제 곡에 공연이 없으면 연결 없음으로 표시하고 다른 시안 공연으로 채우지 않습니다. |
| 같은 공연 | 장소/채널·공연 ID·시작/종료·매체/공연 상태를 함께 연결하는 기획입니다. 인터뷰만 한 사건은 노래 공연으로 자동 환산하지 않습니다. |
| 같은 대회 | 대회 유형·회차·개인/크루·출전곡 ID를 보존합니다. 일반 곡 감상에 임의 대회/투표 대상을 붙이지 않습니다. |
| 세 차트 | 일반 차트·주간 차트·월드 차트를 각각 표시합니다. 일반은 앨범 활동·팬 중심이고 주간/월드는 해당 대회에 접수된 곡의 평가입니다. 주간과 월드의 기간·기록·재화는 구분하며 앨범 등수나 이전 주간 점수를 월드 점수로 옮기지 않습니다. |
| 시험 도구 | 페스티벌 점수 설정·투표 시험·월드 인기·우승은 기존 보조 도구 안에 함께 둡니다. 이용자의 감상·허용 반응/투표는 음악 앱에 연결합니다. 음원·공연·숏츠는 음악 앱의 하위 메뉴이며 별도 검수 그룹을 만들지 않습니다. |
| 시뮬레이터 이동 | 모든 메뉴는 같은 팀·수신 데이터·결과를 공유합니다. 자동 콘텐츠 이동을 멈추고 다른 콘텐츠로 가야 할 때는 모바일 내부 이동 확인을 거칩니다. 음악 앱 안의 곡·공연 전환은 같은 앱의 상세 이동입니다. |
| 시험 시작·초기화 | 발란스 수신 데이터는 전체 초기화 전까지 보존하며 재화 무제한은 시험 환경에 적용합니다. 발매곡이 없으면 기존 시험곡을 준비하고 작성 중인 앨범·기존 발매곡은 보존합니다. 본게임의 제작·발매 조건을 폐지하는 정책이 아닙니다. |

### 공연은 어디까지 만들어졌나요

| 범위 | 현재 구분 |
| --- | --- |
| 앨범 제작·발매 / 음악 앱 연결 | 로컬 구현. 실제 AI 제작·외부 음원 유통과 구분 |
| 방송·공연 사건 → 앨범 활동·START 정산 | 기존 보드 활동 기록/정산 연결과 공연 관람 기능을 구분 |
| 음악 앱 내부 스테이지·숏츠 / 공연 관람·PIP | 로컬 시안 제작. 현재 목록·내 공연 표시는 임시 데이터·시안 조작 |
| 실제 장소 도착 → 공연 생성 → 내 PIP·공연 목록 공급 | 현재 개발되지 않음, 진행 중. 시안 연결만으로 구현 완료로 표시하지 않음 |
| 실제 공연 결과 → 주간/월드 공식 인정·최종 평가 | 현재 개발되지 않음, 진행 중. 공식 유효표·인기 경제·비중/보상은 별도 결정/연결 대기 |

## 3. 구동 방법·시뮬레이션

### 공용 게임 상단 메뉴

상위에는 **앨범 발매·페스티벌·응원 크루**를 둡니다. 앨범 발매 또는 그 하위 화면을 열면 바로 아래 관련 행에 **음원 제작·방송·공연·음악 차트·시티 투어**가 보입니다. 다른 메뉴를 열면 해당 행을 숨깁니다. 직접 음악 차트 주소로 들어와도 앨범 가족과 현재 하위 메뉴를 표시합니다. 관계·순서·문구는 [공용 메뉴 데이터](/data/simulator/menu.json)를 읽으며, 페스티벌 점수 설정·투표 시험·월드 인기·우승도 기존 보조 도구에 함께 둡니다.


[7007 P228 목록·카드](/docs/planning/planning-docs-tool.html?face=development&doc=P228&plan=planning_development_plan_album_release) → 실행 → [공용 게임의 앨범](/docs/planning/game-simulator.html?module=simulator_module_album_release).

1. 음악·장르를 고르면 현재 팀 전원이 기본 참여합니다. 필요할 때 추가 옵션을 펼쳐 멤버·파트·음성·간편/프로를 조정하고, 제작비를 확인해 샘플과 재킷을 준비합니다.
2. 제목·소개·재킷을 다듬고 필요하면 **다시 만들기**를 사용합니다.
3. 기존 제작 조건을 채워 **앨범 제작 완료**를 누릅니다.
4. 발매 조건을 다시 확인해 **앨범 발매**를 누릅니다.
5. 상단💿을 눌러 멤버·곡 정보·샘플을 봅니다. **앨범 목록/이 곡의 차트**는 선택한 곡으로 이동합니다.
6. 하단 **앨범**은 발매 목록, **차트**는 곡별 순위/남은 시간/효과, **크루**는 자동 공유 결과를 확인합니다.
7. 이후2~8번째는 같은 팀의 다음 차수로 준비하며9번째 발매는 막힙니다.

직접 플레이와 연속 발매 확인은 사용자가 진행합니다. 실제 테스트를 대신 실행하거나 사용자 저장을 초기화하지 않습니다.

## 4. 상세 기획

### 앨범 버프·보드·급유 연결

```mermaid
flowchart LR
 A["앨범 발매"] --> B["앨범 이벤트 버프 1일"]
 B --> C["보드 활동 실적 적립"]
 C --> D["출발점 통과 정산"]
 D --> E["앨범 이벤트 재화"]
 E --> F["내 차 급유 · 1개당 ¼바퀴"]
 F --> G["5팀 · 5바퀴 레이스"]
 G --> H["최종 순위 · 주사위/카드"]
```

| 항목 | 현재 기획 |
|---|---|
| 획득 기간 | 선택 앨범의 원본 차트 이벤트 시작부터 1일. 참가나 메뉴 이동으로 연장하지 않음 |
| 적립/지급 | 기간 내 유효 보드 활동분을 적립하고 기존 출발점 통과 정산에서 전용 재화 지급 |
| 재화 | 기존 albumEventWallet를 급유와 함께 사용. 현금 수익에 더하지 않고 두 번째 연료 재화를 만들지 않음 |
| 거리 | 재화 1개=¼바퀴, 4개=1바퀴, 20개=5바퀴. 속도와 멤버 수로 단위 거리를 바꾸지 않음 |
| 속도 | 같은 능력 입력 기준 기존 주행 속도의 50%. 기본 한 바퀴 시간 6초→12초, 초·중·후반 능력 배율은 유지 |
| 종료 | 버프 마감 후 새 활동 적립·새 급유·새 참가를 중단. 만료 전에 생긴 미정산분은 기존 START 계약을 따름. 잔여 재화를 임의 삭제하지 않음 |
| 담당 | 보상 수량·획득량·경제 균형·보드 연계 후속은 그룩 담당. 발란스 시뮬과 현황판 복구 소스는 별도 담당 보호 |

**구현 구분:** 앨범 재화 급유와 보드 START 적립/정산 경로는 소스에 있습니다. 속도 50%는 기본 랩 시간 12000ms로 설정에 반영했습니다. 새 설정을 불러와 만든 경기부터 적용하고 기존 경기는 저장된 원래 속도를 유지합니다. 실제 목표는 10바퀴이며 기획의 5바퀴 전환은 별도 후속입니다. 보드 획득→급유 전체 검증은 남아 있습니다. 저장된 기존 경기는 원래 목표·속도·영수증으로 복원하고, 새 경기에서 최신 규칙을 채택합니다. 검증을 끄거나 기존 저장을 새 규칙으로 덮어쓰지 않습니다.


### 모바일은 현재 단계부터 보여 줍니다

앨범 진행 표시는 작은 점과 현재 단계 이름으로 줄입니다. **음악·장르 → 현재 팀 전원 기본 참여 → 재킷·정보 → 제작/발매**에서 현재 선택과 필수 버튼을 먼저 보이며, 이전·다음·제작·발매 버튼은 기존 하단 공통 슬롯에 둡니다. 본문만 세로로 스크롤하고 가로 잘림이나 버튼 내부 스크롤을 만들지 않습니다.

음악·장르와 현재 팀 요약을 먼저 보여 줍니다. 솔로·유닛 선택, 멤버·파트·음성 확인과 간편/프로 기능은 삭제하지 않고 기본 접힘 추가 옵션에 보존합니다. 긴 샘플 설명·참여 요약·제작 조건·발매 전 예상 순위는 기본 접힘 참여·제작 정보에서 펼칩니다. 재킷은 기존 구성·색상 선택을 유지한 큰 정사각형 미리보기로 보여 줍니다. 비용·부족 사유·실패 안내와 필수 조작은 하단 공통 구역에서 바로 확인합니다.


### 연계 데이터와 단독 시험

현재 공용 게임 시뮬레이터의 시험 기준은 [앞의 UI 흐름](#album-stage-festival-ui-flow)을 따릅니다. 오디션을 필수로 거치지 않으며 모든 메뉴가 같은 팀·발란스 수신 데이터·진행 결과를 공유합니다. 메뉴별 재진입으로 데이터를 교체하지 않고 전체 초기화 전까지 유지합니다. 시험용 재화 보충과 시험곡 자동 준비를 본게임의 운영 조건·정식 발매로 해석하지 않습니다. 작성 중인 앨범·발매곡·영수증은 보존하며 원본 연결 오류는 별도 사유로 표시합니다.

### 제작 전에 보는 대략의 시작 순위

**음악·장르 선택 → 기본 팀 또는 조정한 참여자의 능력·팬으로 예상 순위 확인 → 재킷 → 발매 때 실제 시작 순위 확정** 순서입니다. 첫 음반도 현재 팀과 참여 멤버의 능력을 반영합니다. 다음 음반은 같은 계산에 직전 앨범의 최종 성적을 더합니다. 화면의 예상은 대략의 범위이며 발매 때의 능력·팬·새 상대에 따라 달라집니다.

팀 평균과 참여자 평균이 모두 원점수500이고 팬이 없는 수학 예시는 **대략40~53위**입니다. 음반 차수로 등수를 강제하지 않으며 2번째부터도 같은 공통 계산을 씁니다. 가중치·곡선·상한·예상 범위 폭은 [음악 규칙 데이터](/data/music_career/music_career_rules.json)의 `albumLeague.entry`에서 조절합니다.


### 음악 선택과 기본 팀 제작

| 기본 화면 | 행동과 경계 |
|---|---|
| 기본 제작 | 현재 팀 전원과 기존 파트 기본값으로 바로 준비. 원본 팀·멤버가 없으면 연결 대기 |
| 선택곡 | 실제 팀 이름과 함께 등장하고 기존 단일 플레이어로 자동 미리듣기. 새 선택은 이전 재생을 교체 |
| 추가 옵션 | 멤버·솔로/유닛·파트·목소리 확인·간편/프로를 펼쳐 조정. 음성 유효성 검사는 유지 |
| 재킷·결제 | 기존 재킷 선택을 크게 표시. 샘플 생성/환불·제작/발매 권한과 중복 결제 검사를 유지 |

선택곡은 라이선스 시험 음원이며 실제 AI 생성이나 참여 멤버의 실제 음색을 뜻하지 않습니다. 재킷에 신규 업로드 기능을 추가하지 않습니다.

실제 100위 컷 원본이 공급되지 않아 자동 차트아웃 판정은 대기합니다. 현재 비교군의 마지막 행이나 화면상의 100위를 실제 운영 탈락선으로 대신하지 않습니다.

### 음악 다음에 재킷, 발매 다음에 차트

**음악 완성 → 재킷·앨범 정보 확인 → 제작 완료 → 발매 → 약2.8초 순위 공개 → 이 곡 차트** 순서입니다.

| 단계 | 보이는 것·행동 |
|---|---|
| 음악 준비 | 팀 이름과 선택곡 등장·자동 미리듣기, 기본 팀과 펼친 추가 옵션의 참여자 확인 |
| 재킷·앨범 정보 | 기존 구성3종·색상3종을 바꾸며 크게 미리보기. 곡명/앨범명/소개도 수정 |
| 고정 버튼 | 앨범으로 / 이 재킷으로 다음. 반영 후 같은 앨범 ID에 저장 |
| 제작·발매 | 기존 조건을 검사하고 제작 완료·발매. 재킷 확인이 비용을 다시 청구하지 않음 |
| 발매 연출 | 참여 멤버·저장 재킷→발매 표시→재킷이 차트 행으로 이동→계산된 순위·남은 시간 |
| 차트 이동 | 연출 종료/차트 보기 → 같은 곡의 상단 순위표 → 내 행1회 자동 이동·강조 |
| 크루 공유 | 실제 공유 게시물이 연결됐을 때만 작은 완료 한 줄 |

재킷은 기존 템플릿·팔레트 기능을 연결한 것이며 AI 이미지 생성이 아닙니다. 편집 후 목록·차트·상단 상세와 연출에서 같은 저장값을 사용합니다. 발매한 앨범의 과거 재킷을 소급 변경하지 않습니다.


### 공용 고정 버튼 구역

이전·다음·음악 만들기·재생성·앨범 제작/발매의 주동작은 **기존 게임 공용 버튼 구역**에 둡니다. 내용·멤버 목록·파트·옵션만 스크롤합니다. 버튼을 찾으려고 맨 아래로 내려갈 필요가 없습니다.

| 위치 | 표시 |
|---|---|
| 본문 | 멤버/파트/음악 옵션·샘플·곡 정보·조건·상세 설명 |
| 고정 버튼 위 | 필요한 돈·보유 돈 한 줄과 차단/처리/오류 요약 |
| 고정 버튼 | 현재 단계의 이전/다음/제작. 생성 중 잠금·미충족 비활성화 유지 |
| 메뉴 이동 | 음악 버튼은 숨기고 기존 다른 기능의 버튼 구역을 복원 |


### 단독 실행과 연계 실행

현재 공용 게임 시뮬레이터의 시험 기준은 [앞의 UI 흐름](#album-stage-festival-ui-flow)을 따릅니다. 오디션을 필수로 거치지 않으며 모든 메뉴가 같은 팀·발란스 수신 데이터·진행 결과를 공유합니다. 메뉴별 재진입으로 데이터를 교체하지 않고 전체 초기화 전까지 유지합니다. 시험용 재화 보충과 시험곡 자동 준비를 본게임의 운영 조건·정식 발매로 해석하지 않습니다. 작성 중인 앨범·발매곡·영수증은 보존하며 원본 연결 오류는 별도 사유로 표시합니다.

### 화면 단계와 공용 UI

음악을 고른 뒤에는 **앨범 활동 준비** 단계를 유지하고 해당 음악 폼으로 이어집니다. 멤버 선정으로 되돌아가거나 데뷔 준비 첫 화면을 다시 보여 주지 않습니다. 발매곡에 연결되는 앨범 방송·공연 활동은 발매 후에 시작하며, 발매 전에도 기존6칸의 홍보·버스킹과 기본 보드 활동·성장은 유지하는 기획입니다. 스크롤 밖 공용 고정 버튼 바로 위에 필요/보유 돈·차단 사유·처리중/오류를 표시합니다. 단계 전환/사용자 조작 결과 때만 해당 안내를 보여 주고 주기 갱신은 스크롤을 유지합니다.

본문에는 단독 테스트·지원금·시험조건 안내 박스를 추가하지 않습니다. 현재 잔액과 제작비·진행을 막는 이유만 해당 위치에 표시합니다.

화면은 기존 시뮬레이터와 같은 **크림 배경·보라색 정보/선택·민트색 완료 표시·둥근 카드/버튼**을 사용합니다. 참여 멤버 이름·선택 테두리·입력·오류 안내와 상단 앨범 상세도 같은 대비로 맞춥니다.

| 다시 만들기 · 기존 돈 | 2,500 | 3,750 | 5,000 | 6,250 | 7,500 | 8,750 | 10,000 | 11,250 |

실행자가 정한 **로컬 임시 발란스**입니다. 기존 게임 돈을 사용하고 만들기 전에 **필요·보유·부족 금액**을 보여 줍니다. 돈이 부족하거나 현재 지갑 원본을 읽지 못하면 시작하지 않습니다. 다시 만들기는 성공한 샘플이 있는 같은 앨범에 적용하며 비용은50%입니다. 첫 생성이 실패해 샘플이 없으면 다음 시도는 첫 제작비입니다.

요청/작업이 같으면 한 번만 결제합니다. 샘플 파일을 연결하지 못해 작업이 실패하면 해당 제작비를 한 번 환불합니다. 제목 수정·샘플 듣기·제작 완료·발매 버튼은 이 제작비를 다시 청구하지 않습니다. 실제 AI 토큰이나 현금 결제는 없습니다.

**샘플 대기 시계:** 보드 진행이 멈춰 있어도 샘플 연결은 실제 경과 시간으로 완료합니다. 기존 진행 중 작업은 같은 작업·결제·참여자를 보존해 짧게 재대기하며, 복원이나 새로고침으로 제작비를 다시 청구하지 않습니다. 게임 시계·리그 시간·보드 진행을 앞당기지 않습니다.

제작 완료와 발매는 추가 제작비를 청구하지 않습니다. 다시 만들기는 같은 앨범 차수여서8곡 한도를 늘리거나 소모하지 않습니다.

### 멤버·곡 데이터 연결

앨범은 고정 ID로 연결합니다. 현재 팀에서 고른 참여자·파트·계수와 목소리 구성, 음악 옵션·sampleId·제목/소개·재킷을 같은 앨범에 저장합니다. 명단을 바꾸려면 발매 전 새 생성 작업을 거칩니다. 발매 이후 대상·파트·계수를 바꾸지 않고 신규 합류 멤버를 지난 곡의 버프에 끼우지 않습니다.

### 발매 후 자동 처리

- 소속 크루가 있으면 그 크루 내부에 앨범을 한 번 공유합니다. 없으면 공유를 생략하고 차트 등록은 이어갑니다.
- 차트 등록과 발매별 이벤트 입장은 같은 발매 처리에 연결합니다. 단, 자유 테스트에서 앞 차트가 진행 중이면 새 곡은 발매를 저장하고 이벤트 참가만 대기합니다. 로컬은 본인+가상99명이며 실제 회원 매칭 서버는 없습니다.
- 첫 발매 뒤 상단💿아이콘이 표시됩니다. 클릭하면 발매곡을 골라 멤버·파트·음악 옵션·샘플·원곡 크레딧을 봅니다.
- 하단 앨범 목록과 차트는 동일한 albumId를 사용합니다. 지난 곡은 지난 리그를 보여 주고 현재 활동곡으로 몰래 바꾸지 않습니다.
- 발매 자체가 돈·팬·능력·전용재화를 즉시 주지는 않습니다.1일 이벤트 실적에 따른 추가 효과를 기존START에서 정산합니다.

### 첫 앨범 발매 · 방송/공연 6칸의 이름과 불빛

**제안(검수 대기) · 기획만.** 첫 유효 앨범 발매를 계기로, 같은6개 칸의 신인 홍보·버스킹이 정식 방송·공연으로 보이게 바뀝니다. 건물의 성장 단계와 이 전환은 별개입니다.

| 칸 | 첫 발매 전 · 신인 활동 | 첫 발매 후 · 정식 활동 | 역할 방향 |
|---|---|---|---|
| 27 · 방송 | **거리 인터뷰** | **예능 방송국** | 얼굴과 이름 알리기 → 앨범을 내건 예능·토크 출연 |
| 28 · 방송 | **온라인 홍보방송** | **라디오 방송국** | 짧은 자기소개·소통 → 신곡 소개·보이는 라디오 |
| 30 · 방송 | **신인 소개방송** | **음악 방송국** | 신인 소개·가벼운 무대 → 발매곡의 정식 음악방송 |
| 32 · 공연 | **거리 버스킹** | **라이브 공연장** | 가까운 관객과 연습 무대 → 내 발매곡 라이브 |

발매 전도 닫힌 시설처럼 보이지 않게 합니다. 기본 로비·연습 조명은 유지하고 정식 간판/메인무대 조명만 준비 상태로 둡니다. 발매 전6칸에서도 **기존 보드 활동·성장·기본 보상**은 유지합니다. 발매곡에 연결되는 앨범 활동 기록/추가 정산만 발매 후에 시작합니다.

현재 지도에는 시설별 공통 이름/짧은 이름이 있으므로 이 표는 **6개 위치별 칸·활동 간판의 표시명** 제안입니다. 공통 건물명·시설ID·0~30단계 성장을 대체하지 않습니다. 작은 칸에서는 짧은 이름을, 도착 안내/상세에서는 전체 이름을 표시하는 안입니다.

### 공통 시간 버프와 오른쪽 상세

시간 버프는 타입·출처·현재 저장 범위·기준 시계·시작/종료 시각·남은 시간·효과를 공통 형식으로 표시합니다. 앨범은 `album_rank` 타입입니다. 게임 연출 영역 **오른쪽 아래 구석**에 현재 순위·**시:분:초**만 작은 한 줄 칩으로 겹쳐 표시하고(11/18 클로드 · 현중 「앨범 버프 UI 다른 위치로 옮기면서 사이즈도 줄여줘」 · 전에는 오른쪽 위라 화면마다 맨 위 갈래 버튼을 가림 · 칩 높이 34→24px · 폭 160→120px), 누르면 같은 곡의 차트로 이동합니다. 차트 화면에서는 이 칩을 숨기고 오른쪽 상세는 유지합니다. 적립 기준·긴 설명은 오른쪽에 둡니다. 크기·위치·여백과 차트 숨김 대상은 공통 UI JSON에서 조절합니다. 오른쪽에는 곡·현재 순위·남은 시간·주요 효과의 대표 요약이 항상 보입니다. 참여자별 능력·미정산·시계와 상세 계산은 기본 접힌 상세 보기에 두고 펼칠 때 확인합니다. 시간/상태 갱신·오른쪽 host 이동에서도 펼친 상태를 유지합니다. 하단 차트는 실제 차트 화면에서만 선택 표시를 하고, 버프가 켜져 있다는 이유로 선택 표시하지 않습니다.

오른쪽에는 곡·고정 참여자·현재 순위·유효 남은 시간, **활동1회·배수1의 적립 기준**, **이 곡의 실제 START 미정산 합계**를 구분해 표시합니다. 시험 적립은 별도입니다. 화면 숫자는 한 바퀴의 고정 지급량이 아니며, 유효 활동에서 쌓인 적립을 기존 출발점 정산에서 지급합니다. 만료되면 신규 적립과 활성 표시가 끝나며 이미 적립한 기록은 정산 대상으로 남습니다.

공통 표시는 캐시된 시간만 매초 갱신하고 저장 전체를 매초 검증하지 않습니다. 숨은 화면은 타이머를 멈추고 복귀 시 원본을 확인합니다. 기존 멤버 시간 버프는 원래 `ends_at`과 계산을 유지하며, 명시한 시계 변환기를 통해 같은 표시 계약에 연결합니다. 비어 있는 기존 표에서 버프를 만들거나 다른 시계의 날짜를 임의로 합치지 않습니다.


### 출발점 추가 보상 필러·자동 결과 연결 — 후속 기획, 미구현

**출발점 통과 → 기존 정산 확정 → 일반 보상 → 앨범 버프 추가 보상** 순서의 필러 연출이 필요합니다. 별도 앨범 줄에 실제 영수증의 전용 재화·팬·참여 멤버별 능력을 표시합니다. 클릭 전부터 정산 결과를 이해할 수 있어야 하며, 연출 재생이 지급을 다시 실행하면 안 됩니다.

발란스 시뮬레이터도 같은 계산·정산 영수증을 결과로 내보내고, 현황판은 그 결과를 읽어 일반 보상/앨범 추가 보상과 실제 지급/대기를 나눠 표시해야 합니다. 현황판에서 별도 보상을 계산하거나 수동 지급하지 않습니다. 필러 연출·개별 writer·자동 결과 내보내기·현황판 상세 반영은 각각 후속 개발/검수 항목입니다.


### 솔로·유닛·팀의 참여와 보상

**한 명이 참여하면 솔로, 팀 일부의 두 명 이상이 참여하면 유닛, 팀 전원이 참여하면 팀 앨범**입니다. 5명 팀에서 3명이 부르는 앨범은 유닛입니다. 한 명뿐인 팀의 첫 싱글도 솔로입니다. 처음 곡을 만들 때 고른 참여 멤버·파트를 앨범에 고정하며, 이 명단이 추가 능력을 받을 대상을 정합니다.

**능력은 참여자 각자의 몫, 이벤트 재화는 팀에 한 번**입니다. 같은 순위·활동량·배수·파트·개인 상태라면 한 멤버의 요청량은 솔로·유닛·팀에서 같습니다. 개인 보상을 참여 인원이나 참여계수 합계로 나누지 않습니다. 기존 파트 계수·세부 능력 비율·개인 성장 상한은 적용하며, 미참여자는 그 앨범의 추가 능력을 받지 않습니다.

| 설명용 예시 · 같은 파트·조건, 개인 상한 여유 있음 | 개인 능력 증가 | 기존 팀 평균 능력 증가 | 이벤트 재화 |
|---|---|---|---|
| 1명 팀의 솔로 | 그 멤버 +10 | +10 | 팀에 10개 |
| 5명 팀의 전원 참여 | 각자 +10 | +10 | 팀에 10개 |
| 5명 팀 중 3명의 유닛 | 참여자 각자 +10, 나머지 0 | +6 | 팀에 10개 |
| 5명 팀 중 한 명의 솔로 | 참여자 +10, 나머지 0 | +2 | 팀에 10개 |

표의 +10·재화10개는 단위를 설명하는 예시이며 새 발란스 값이 아닙니다. 기존 팀 능력은 현재 팀 전체 멤버의 평균으로 다시 읽습니다. 개인 증가 합계를 팀 능력에 한 번 더 더하지 않습니다. 유닛 전용 가산 보상은 없으며, 참여자가 많다는 이유만으로 재화·직접 팬을 늘리지 않습니다. 실제 순위·활동 실적·파트·개인 상한이 다르면 결과가 달라질 수 있습니다.

오른쪽 상세에서 순위별 적립 기준과 고정 참여자별 능력 요청량을 구분합니다. 실제 지급은 START 영수증의 개인별 증가량으로 확인하고, 상한 때문에 못 받은 능력을 다른 멤버에게 옮기지 않습니다. 자동 발란스의 개별 멤버 writer는 연결 대기이며, 이번 확인은 소스 대조입니다.



### 영상 미리보기와 뮤직비디오 제작 상태

**현재 미리보기:** 10차의 공통 영상 플레이어와 공연 이미지3종을 재사용합니다. 동영상 파일을 새로 만드는 기능이 아니라, 공연 이미지와 해당 앨범에 연결된 검증 샘플을 함께 보여 주는 임시 시뮬레이터입니다. 별도의 audio/video 플레이어를 중복 생성하지 않습니다.

샘플 준비 후 **영상으로 미리보기**를 누르면 이미 생성된 music controller의 openAlbumVideo(album,current,{preview:false})를 호출합니다. 앨범 초안·제작·발매 원장, 생성 작업·제작비·환불을 쓰지 않습니다. 같은 공통 플레이어로 복귀/닫기를 처리하며 원곡·저작자·라이선스 링크는 유지합니다.

**뮤직비디오 제작: 기획 준비중.** 실제 동영상 생성·동작 영상 공급은 추가 기획/연결 대상입니다. 10차의 현재 결과는 정지 공연 이미지와 지속 미디어 플레이어이며 실제 영상 생성 완료로 표시하지 않습니다. 나중에 실제 파일이 공급되면 기존 album.media.videoSrc 또는 album.video.src의 검증된 /assets/ 경로로 연결합니다.

### 시티 투어에서 이벤트 재화 사용

[시티 투어: 앙코르 레이스](시티투어_핵심제안서.html)는 **발매 앨범의 참가 버튼 → 차량 선택 → 현재 앨범 차고 → 급유 →5팀5바퀴 경기 →주사위·아이돌 카드 수령**으로 연결합니다. 앨범 하위 시티 메뉴도 같은3D 게임이며 차량→급유→레이스→시상의 작은 진행 표시를 씁니다. 확대 시점/PIP·전원 순위/랩·미니맵은 표시 전용입니다. 기존2D 비교 시험의 입장비/돈상금과 구분합니다.

추가 참가비는0, 급유 때만 기존 albumEventWallet의 재화를 사건 영수증으로 차감합니다. 재화1개=¼랩이고 인원수/속도로 거리를 바꾸지 않습니다. 현재 앨범의 고정 참여 멤버 raw18/보유 성향 평균으로 속도를 계산하고, 같은 원본 리그의24시간 마감/시험 상대 ID·seed를 사용합니다. 메뉴 이동/재접속으로 시간·재화를 보충하지 않습니다. 재화가 없으면 보드에서 모으기로 이어집니다.

정상 경기의 본인1랩·연료4소모 이상이면 참가 기본+순위 추가 주사위/아이돌 카드 보상입니다. 제안 수량은 [보상 데이터](/event/cityTour/data/racing3d-rewards.json)에서 읽습니다. 앨범 경로는 소유 full checkpoint/카드 보유 원천 확인 후 기존 held/카드 효과 원장과 career 수령 영수증을 복구 journal로 묶습니다. 독립URL은 시험 영수증만 기록합니다. 데이터가 부족하면 실제 지급 완료를 표시하지 않습니다.

경주 결과를 차트1등으로 직접 대입하거나 가짜 보드 사건으로 변환하지 않습니다. 검증 resultId별 차트 기여량·반복 상한·경제 순환/서버 실유저 동기화는 후속 연결입니다. 기존 보드 돈·팬·고정 참여자 능력 START 정산은 변경하지 않습니다.


### 앨범 전반의 연계 자료 계약

**현재 팀·멤버 → 전체 성장 저장과 제작비 → 멤버를 고정한 곡 → 발매 → 크루 자동 공유/차트 등록 → 앨범 리그 → 시티 투어** 순서로 같은 session/run/season/team을 유지합니다. 기능 이동이 새 팀·새 지갑을 만들지 않습니다. 같은 창의 성장 저장 알림도 구독하므로 제작비/능력 변경을 다시 읽습니다.

우측 「앨범 데이터 연결」은 멤버·전체 성장·지갑·원시 팬 계층·엔터파워·18개 능력·시즌/일차의 연결 상태와 추가 제공자 상태를 접기/펼치기로 보여 줍니다. 입력 연결 완료와 제작/발매 조건 통과를 구분합니다. 요약만 있는 projection은 돈·일차를 가진 full checkpoint로 간주하지 않습니다. 원본이 누락되면 기존 보드 진행을 연결해야 합니다.

| 입력 | 채택 기준 | 미공급 처리 |
|---|---|---|
| 멤버·현재 능력 | 현재 handoff와 snapshot의 candidate_id·run/session 일치, 18개 원단위 | 명칭으로 합치거나 가짜 멤버로 대체하지 않음 |
| 돈·보드 진행 | 동일 소유 full checkpoint의 money/day/season | 제작비 지갑·조건 관측 대기 |
| 팬 | 원시 light/core/concrete 숫자 또는 아래 검증된 공급자 자료 | 손상/누락/화면0을 원시0으로 변환하지 않음 |
| 기간 기준/미션 완료일 | 날짜가 기록된 실제 사건/영수증 | 현재일이나 시즌1일로 과거 사실을 만들지 않음 |
| 제작·발매 문턱 | 음악 규칙의 실제 값과 원표 참조 | null·미정 조건은 대기, 단독 preset과 분리 |

### 선택 연계 공급자 API와 처리 순서

호스트가 dataSource.musicCareerObservation(request)를 제공할 수 있습니다. 현재 기본 host에는 이 공급자가 자동 설치되어 있지 않습니다. [수신 모듈](/src/simulator/music-career/linked-observation.mjs)과 source.prepareMusicCareerObservation({refresh})가 수신 입구이며, 반환 자료는 메모리에서만 사용합니다. 음악 mount/활성화·현재 원본 갱신 때 준비하고, 동기 read()가 요청이나 쓰기를 시작하지 않습니다.

| 필드 | 요청/응답 계약 |
|---|---|
| request.version | 1 |
| request.scope | 현재 runId/sessionId/seasonId |
| request.actorId/teamId | 현재 소유 actor/team |
| request.sourceRevision/sourceSignature/dataSignature | 현재 snapshot 버전·일치하는 full checkpoint signature·입력 signature |
| request.day/memberIds/missionIds | 관측 게임 일차·현재 멤버·활성 미션 ID |
| 응답 version/status/request | version=1, status=ready, 요청 내용을 값 기준으로 정확히 되돌림 |
| debutStartDay | 선택 {day,sourceRef}; 시즌 게임일차1 이상·현재일 이하의 실제 기준 사건 |
| missionCompletionReceipts | 선택 배열 {receiptId,missionId,completedDay,sourceRef}; 고유 영수증·등록 미션·현재일 이하 |
| fanLayers | 선택 {unit:raw_fan_amount,layers:{light,core,concrete},sourceRef}; 음수/문자열/누락/범위초과 거부 |

처리: 요청 소유/버전 동결→선택 공급자 호출→응답 whitelist/동일 요청/값 검증→현재 원본 다시 읽기→같은 증거일 때 메모리 채택→화면 갱신입니다. 멤버/세션/버전이 바뀐 늦은 응답은 폐기합니다. 요청 중복은 같은 promise를 재사용하며 dispose 후 응답은 채택하지 않습니다.

이 입구는 돈·능력·멤버·시즌·일차 자체·전체 체크포인트를 받거나 덮어쓰지 않습니다. 미션 완료 증거로 completedDay/completed만 보완하고 claimed를 참으로 만들지 않습니다. 원시 팬층은 리그 계산 입력만 보완하며 허브 팬 저장이나 실제 팬 보상 writer가 되지 않습니다. 실패/미공급은 현재 원본을 유지하고 대기 사유를 표시합니다.

기존 자료에는 최초 데뷔 기준일과 일부 미션 게임 완료일이 기록/전달되지 않았습니다. 실제 사건 생산자와 영수증 전송은 후속 공급 대상입니다. 음악 규칙의 미정 기간/성장/시설 문턱, 비활성인 이전 개인 growth_band 차트의 정밀도·운영 설정은 이번 수신 준비로 확정하지 않습니다.

### 명시 시티 단독 시험

[시티 투어 단독](/docs/planning/game-simulator.html?module=simulator_module_music_city&testPage=simulator_module_music_city)은 현재 시험 멤버로 고정 참여자 있는 음원 미연결 싱글·차트 리그·최초 급유 재화80개를 자동 준비합니다. 실제 샘플 생성/제작비 청구는 생략합니다. 기존 초안/종료 리그/소모 재화는 보존하고 연계 팀에는 적용하지 않습니다. 상세 준비·중복·만료 정책은 [시티 투어 P232](../../기획서/산출_기획서_시티투어_상세_v1.html)를 따릅니다.

### 단독 시험 진행의 멤버 상태 보존

단독 시험의 전체 진행을 만들 때 현재 snapshot 멤버의 컨디션·몬스 배정·배정 revision도 그대로 보존합니다. 이를 빠뜨리면 공통 저장의 멤버 동일성 검사에서 거절되므로 제작 지갑/일차를 연결할 수 없습니다. 초기값을 새로 정하지 않고 기존 copyIdolConditionFields를 사용하며, 앨범과 시티 투어는 같은 준비 경로를 사용합니다.

### 최신 기획 UI와 간단한 시험

기존 비용 그림은 기능 설명용이며 최신 화면의 색상은 공용 크림·보라·민트 테마입니다.

![제작비·샘플·다시 만들기의 UI 설명 시안](ui/core-album-generation-cost.svg)

| 위치 | 첫 표시·상세 |
|---|---|
| 게임 상단💿 | 첫 발매 후 등장·발매 수. 클릭하면 앨범 선택과 참여 멤버/파트/곡/샘플 |
| 하단 앨범 | 발매 목록·제작 중 곡·다음 싱글·정보/샘플 상세 |
| 하단 차트 | 선택 곡의 순위·잔여시간·활동/다음 시작 게이지·미정산 효과 |
| 하단 크루 | 발매 후 소속 크루 내부 공유. 생성/제작만 한 곡은 자동 공유하지 않음 |
| 공용 고정 버튼 구역 | 이전·다음·제작/발매와 비용/오류 요약. 본문 스크롤과 분리 |
| 생성 비용 영역 | 필요·보유·부족 돈과 다시 만들기 비용 |
| 실패/대기 | 이유·같은 작업 재확인·환불 상태. 중복 차감 금지 |

그림은 설명 시안이며 최신 실제 화면은 사용자가 확인합니다. 기존 재킷 템플릿과 실제 샘플10곡의 크레딧을 사용합니다. 실제AI 생성·외부 유통 완료라고 표시하지 않습니다.

## 7. 개발 진행·검수

| 범위 | 현재·남은 일 |
|---|---|
| 제작·발매·목록·대표곡·자동 공유 | 로컬 구현, 실제 회원 서버 제외 |
| 멤버/음악/비용·재생성·샘플 | 로컬 UI 확인: 음악 우선·기본 팀·접기·같은 샘플·1회 결제·큰 재킷·제작/발매·새로고침 보존 |
| 상단 상세·선택곡 목록/차트 연결 | 기존 연결 보존. 최신 음악 목록·1회 조작 전체 플레이어·미디어 왕복·내 발매곡 BGM을 로컬 UI 확인 |
| 1~8번째/9번째 차단 | 기존 상한 유지·검증 코드 작성. 최신 직접 시나리오는 미실행 |
| 운영 | 제작 간격/일부 성장·미션·실제AI/회원 서버·새 재화 사용처 대기 |

수락 순서: 첫 앨범 생성/결제→재생성→제작/발매→상단 상세→하단 앨범/해당 곡 차트→2~8번째→9번째 차단→가입 크루에 발매곡 자동 공유입니다. 코드 구현과 실제 화면 통과를 구분합니다.
