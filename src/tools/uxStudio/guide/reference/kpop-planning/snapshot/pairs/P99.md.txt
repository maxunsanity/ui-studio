## 1. 개요 · 표를 읽는 순서

정식 전투6표·흐름3표의 기존9표와 추가 보상 시험1표를 구분합니다. [P98 실행 흐름](/docs/planning/삼중AI_공용_20260929/산출/개발진행기획_v01/콘텐츠별_v03/캐스팅권대전_기획서.html) → [P158 수식·상태·원장](/docs/planning/삼중AI_공용_20260929/산출/개발진행기획_v01/콘텐츠별_v03/캐스팅권대전_세부_기획서_v06.html) → 이 문서의 열/FK/등록 순서로 읽습니다.

상태는 구현·일부 보상 화면 확인 · 정식 보드 도착 검수 대기입니다. 이 본문은 개발 계약과 확인할 기준을 정리합니다. 실제 브라우저·게임 플레이 검수와 운영 승인은 별도 근거가 있어야 기록하며 이전 버전의 빌드 결과를 이번 시험 통과로 바꾸지 않습니다.

## 4. 추가 시험표 · 8열·3행·FK

| 열 | 형식 | 검증·의미 |
| --- | --- | --- |
| `casting_battle_reward_test_case_id` | 문자열 PK | 전체 파일명 접두사 `casting_battle_reward_test_case_`를 유지합니다. |
| `label_ko` | 표시 이름 | 상황 이름을 표시합니다. |
| `bot_profile_id` | scalar FK | `casting_battle_bot_profile.casting_battle_bot_profile_id`를 참조합니다. |
| `expected_outcome` | blocked 또는 hit | 돈·보상 연출 경계의 기대값입니다. 전투·원장의 원본은 blocked/building-hit이며 expected_outcome=hit를 원장 outcome 원본값으로 저장하지 않습니다. 실제 판정을 강제로 바꾸지 않습니다. |
| `bot_coins_override` | optional numeric | 빈칸은 원본 유지, 명시적 0은 잔액 없는 상대입니다. 0 이상 안전한 정수만 허용합니다. |
| `multiplier` | 기본 1 | 기존 도착 범위인 최소 1·최대 1000000을 따릅니다. 1배는 경계 시험값입니다. |
| `enabled` | 0 또는 1 | 0은 시험 목록 제외, 1은 사용입니다. 정식 운영 활성화 플래그가 아닙니다. |
| `note` | 설명 | 시험 경계와 임시 상태를 보존합니다. |

| 상황 ID 끝부분 | 표시 이름 | 기존 봇 | 기대 판정 | 상대 잔액 override | 배수 |
| --- | --- | --- | --- | --- | --- |
| `_blocked` | 몬스 방어 | `casting_battle_bot_profile_aurora` | `blocked` | 빈칸: 원래 봇 잔액을 사용합니다. | 1 |
| `_hit` | 기분 소진·건물 파손 | `casting_battle_bot_profile_nova` | `hit` | 빈칸: 원래 봇 잔액을 사용합니다. | 1 |
| `_empty` | 잔액 없는 상대 | `casting_battle_bot_profile_nova` | `hit` | 명시적 0: 잔액 없는 경계를 시험합니다. | 1 |

기존 봇 수치·ID·편성을 복제하지 않고 scalar FK로 참조합니다. 빈 override와 명시적 0을 구분하며 expected_outcome은 돈·연출 경계의 기대값입니다.

## 5. 원본 변경·생성물 경계

schema_table/schema_column은 추가 시험표만 등록하고 planning_csv_usage는 P94 simulator·P98 casting에 시험표 사용을 연결합니다. schema.ts·planning_csv_table·table_registry는 손으로 수정하지 않고 생성기로 반영합니다. 봇 수치·ID·편성은 보존하고 value_status만 시험 프리셋으로 설명합니다. flow_config는 숫자·플래그를 보존하며 단위·시험 경계 note만 현행 계약에 맞춥니다.

flow_copy의 reward_test_28키는 시험 화면 문구입니다. source CSV를 고친 뒤 스키마 생성기로 반영하며 JSON·schema.ts·planning_csv_table·table_registry를 손으로 고치지 않습니다. 이전 정식9표를 새 운영 경제10표로 부르지 않습니다.

## 6. 등록·검증 순서

1. 기존 PK와 봇 FK를 확인합니다.
2. 시험표8열·3상황·빈칸/0·배수1~1000000·enabled0/1을 확인합니다.
3. schema_table/schema_column에 시험표만 등록하고 P94/P98 사용 참조를 연결합니다.
4. 생성기로 산출물 차이를 검토하고 --check를 확인합니다.
5. 제품 테스트와 P94 기존 메뉴의 실제 화면 검수를 구분해 확인합니다.

~~~text
node scripts/schema-generate.mjs --check
~~~

제품 소스를 직접 import하는 [보상 모델 테스트](/tests/casting-reward-model.test.mjs) 10건과 [흐름 테스트](/tests/casting-reward-flow.test.mjs) 17건의 재현 명령은 [P158 검증](/docs/planning/삼중AI_공용_20260929/산출/개발진행기획_v01/콘텐츠별_v03/캐스팅권대전_세부_기획서_v06.html#part-7)에 모읍니다.

- PK·key 중복이 없고 bot_profile_id FK가 존재하는지 확인합니다.
- optional override의 빈칸2개·명시0한개를 보존하는지 확인합니다.
- 기존9표의 수치·플래그·ID와 다른 메타 행을 보존하는지 확인합니다.
- 생성물 검사와 실제 표 뷰어·검색·다운로드를 각각 확인합니다.

기존 casting_battle_bot_profile_id를 유지하며 sns_avatar_url·sns_nickname을 확장했습니다. 원형 얼굴 공간·닉네임·소속사명을 입장·선택·전투·결과에서 유지합니다. 사진이 없거나 로드에 실패하면 기본 얼굴을 표시하고 공간은 유지합니다. 외부 SNS 조회·계정 연동은 이번 범위가 아닙니다.

## rewardItems · 카드 정보·표현 계약과 지급 경계

rewardItems는 kind·refId·amount·cards·presentationOnly를 전달하며 카드에는 name/imageUrl/rarity/isNew/ownedCountBefore/amount를 전달할 수 있습니다. 돈 refId는 경제 ID 미확정으로 비워 두며 기존 money_pct_s 비율 ID를 절대 금액 표시에 매핑하지 않습니다. 주사위 예시는 currency_master_currency_dice, 카드 예시는 5테마의 실제 card_id·star_grade에서 읽은 별 1~5성 예시 5장과 item_master_card_pack_pink를 참조합니다. 받은 종류·수량·카드 내용만 보여주며 이 데이터는 시안 예시입니다. 보상 표현 모듈이 금액·확률·지급 조건을 계산하거나 없는 보상을 만들지 않습니다.

- 확정(현중 직접 지시): 성공(건물 적중)과 실패(방패 방어) 모두 돈을 얻습니다.
- 결정 대기: 돈 지급량·성공/실패 차등, 주사위·카드 지급 조건/수량/등급/확률, 실제 수익·보유함 연결입니다.
- 임시 시안: 돈과 주사위를 별도 큰 장면 뒤 실제 배지로 수집하고 봉인팩 탭→찢기→모든 카드 개별 공개→최고/전체 요약·상세→확인→실제 카드 배지 수집→최종 목록을 유지합니다. 3.2초 강제 종료·최대 5개 항목 잘림을 폐기합니다.
- 없는 주사위·카드는 표시하지 않습니다. 금액 미정은 결정 대기로 표시하며 0이나 기본 지급값으로 확정하지 않습니다. 오른쪽 패널의 예시 보상은 연출 검토용입니다.
- 현재 presentation_only는 기존 성장 자동보상 계산값을 보존하고 대전 추가 money/fans 정산을 0으로 두며 주사위·카드 보유량을 추가 지급하지 않습니다. 기분·건물·receipt·checkpoint/ACK·메인 복귀는 유지합니다. 재생·다시 보기는 같은 결과의 표현입니다.

기존 로컬 경제 시험 분기는 레거시로 보존합니다. casting-flow의 requests/bots/ledger와 key kpopmonsters.casting-live-flow.v1, 성장 state.castingRewardReceipts·checkpoint 성공 후 ACK는 새 presentationOnly 요청에서도 유지합니다. 이때 실제 보상/피해 재화는 0이며 기분·시설 피해·완료 상태만 정상 연결합니다. 기존 금액 지급 분기는 별도 시험이며 새 전체 ACK를 삭제하지 않습니다. 서버 DB나 정식 경제도 아닙니다.

casting은 왼쪽의 성장 카드를 숨기고 정식 4쟁탈을 크게 표시하며 전용 굴림을 사용합니다. growth는 보드 그림을 숨겨 능력·팀 성장 중심으로 보여주고, all 메인은 40칸 보드를 크게 보여주며 기존 랜덤 이동·공통 수치/조건/환경과 전용 툴 인계 상태를 관리합니다. 기존 우측 성장 노드는 복사하지 않고 「공통 성장데이터」 접이식으로 이동합니다. 팀 저장 상태는 공통 상세로 정리하고 g-board/g-build/g-sim/g-dice의 이전 내부 설정은 현재 화면에서 숨깁니다. 메인에는 raw 0~360의 환경 입력과 3눈금 게이지를 별도로 둡니다.

### 메인 허브 · 최신 직접 지시

「메인」은 오디션 바로 다음에 두는 상위 허브이며 별도 강조색으로 구분합니다. 정식 40칸의 주사위 이동과 공통 수치·조건·환경만 관리합니다. 쟁탈·건물 성장·이벤트·나쁜 기운 디펜스의 연출과 기획 확인은 각 전용 툴로 정보를 넘겨 진행하고 결과를 같은 메인에 돌려받습니다. 메인 안에서 모든 콘텐츠 연출을 중복 실행하지 않습니다.

공용 허브 상태·문맥 전달 계약으로 현재 팀·도착 칸·배수·조건/환경·결과의 대응을 유지합니다. 개별 툴은 받은 문맥으로 자기 연출을 확인하고 결과를 반환합니다. 기존 정상 성장/자동보상 계산값·쟁탈 receipt/ACK·presentationOnly·중복 지급 금지 경계는 유지합니다. 허브에 별도 보상 추첨·새 재화 지갑을 만들지 않습니다.

나쁜 기운 원본의 360 상한·굴림 +1·루머 카드당 +15·배수 직접 곱/중복 가산 금지와 실제 디펜스 게이지 결과 반환을 연결해 파일·빌드를 확인했습니다. 실제 플레이는 현중 검수 대기입니다.

## 성장 도착 전달·임시 보상·중복 지급 금지

아이돌 성장 시뮬레이터에서 쟁탈 보드에 도착하면 같은 도착 요청의 정보가 섭외권 대전 탭으로 전달되어야 합니다. 기존 성장 자동보상은 이미 계산된 값을 보존하며 다시 추첨·계산·지급하지 않습니다. 현재 돈·주사위·카드는 임시 입력으로 연출하고, 실시간 대전에 따른 보상 변동·실제 지갑 정산은 추후 연결합니다. 같은 도착·결과를 다시 보아도 중복 지급하지 않습니다.

현재 검토 기본 입력은 돈 125,000·주사위 20·카드 5장입니다. 5테마의 실제 카드 데이터에서 읽은 별 1~5성을 예시로 사용하며 사용자가 값을 바꿀 수 있습니다. 이 수량은 임시 연출 입력이며 고정 드롭·카드 수 상한이 아닙니다. NEW/중복도 시안 입력이고 실제 보유 판정이 아닙니다. 테마 그림은 개별 카드 원화가 아닌 공용 그림 예시입니다.
