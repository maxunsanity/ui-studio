# P96 부록 · 기본 몬스 10종 · 디펜스 모델·애니메이션 v01

상태: 제작 시안 · 검수 대기. 기본 동물 10종을 사용하고, 먼저 만든 12지신은 그 외 제작물로 보존합니다. 본게임 플레이 검수는 현중이 진행합니다.

## 01 개요·제작 범위

기존 드론 역할을 하는 공중 방어 유닛을 귀여운 복셀 몬스로 표현합니다. 원소마다 2종이며 기본 목록은 아홀로틀·피그미하마·나무늘보·슈가글라이더·레서판다·페넥여우·친칠라·천산갑·카피바라·쿼카입니다. 날개를 일괄 추가하지 않고 몸이 떠 있는 정령으로 표현합니다.

이번 제작 범위는 모델10종, 공중 대기·이동·공격 대기·발사 반동·복귀 5클립, 추가 공중 부유·주변 빛 입자·이동 빛 꼬리, 뷰어 8자 비행 시연입니다. 획득·교감·기분·대화·섭외권·필살기·피격·쓰러짐·승패 동작은 후속 기획이며 이번 구현으로 표시하지 않습니다. 섭외권 동작은 현중의 별도 제시 뒤 제작합니다.

10종은 기본 도감의 종 수입니다. 현재 방어전의 공중 유닛 7자리와 쌍포 15기를 유지합니다. 보유 몬스 최대 5마리와 방어 시뮬레이터 7자리 사이의 편성 규칙은 이 모델 시안으로 확정하지 않습니다. 12지신 12종과 이전 5색 임시 모델은 기본 후보에서 제외하고 별도로 보존합니다.

## 04 디펜스 애니메이션 기획

| 클립 ID | 길이 | 반복 | 연출 | 엔진 연결 |
| --- | --- | --- | --- | --- |
| idle_fly | 2.40초 | 반복 | 느린 상하 부유·귀/아가미/꼬리의 작은 보조 움직임 | docked |
| move_fly | 0.72초 | 반복 | 전방 기울임·비행 리듬 | launch / orbit / hunt |
| attack_idle | 1.40초 | 반복 | 표적 주시·몸 중심 모으기·준비 자세 | attack 상태의 발사 사이 |
| attack | 0.58초 | 단발 | 시작 시 발사 자세 → 짧은 반동 → 회복 | 본체 laser 이벤트 |
| return_fly | 1.20초 | 반복 | 힘을 푼 비행 자세·안정된 보조 동작 | return / 종료 복귀 |

발사 준비는 `attack_idle`에서 보여줍니다. `attack`의 0초는 이미 발사한 순간이므로 애니메이션을 기다리느라 피해 판정을 늦추지 않습니다. 기본 혼합 시간은 0.12초, 공격 재시작 최소 간격은 0.08초이며 `visual.csv`에 둡니다.

- 매 프레임 같은 상태를 다시 요청해도 재생 시간을 초기화하지 않습니다.
- 단발 공격 중 새 이동·대기 요청은 공격 뒤 돌아갈 상태만 갱신합니다. 공격이 끝나면 가장 최근 상태로 돌아갑니다.
- 정지·숨김·모듈 전환 중에는 애니메이션 시간을 진행하지 않습니다. 재개 시 숨긴 시간을 한꺼번에 따라잡지 않습니다.
- 저장을 복원했을 때 지난 발사 이벤트를 다시 재생하지 않습니다.
- 모델 root의 월드 이동·방향은 게임이 관리합니다. 기본5클립은 rig 이하에서 재생하며, 기본10종의 추가 부유는 root와 rig 사이에 실행 중 삽입하는 guardian_hover 노드에서 적용합니다. 기존 rig 위치에 부유값을 매 프레임 더해 누적시키지 않습니다.

## 05 리소스·다른 팀 재제작 규격

![기본 몬스 10종 복셀 콘셉트](/docs/planning/삼중AI_공용_20260929/산출/몬스_기본10종_시안_v01/mons-basic-10-voxel-concept-v01.png)

그림은 이미지 생성 도구로 만든 콘셉트입니다. 실행 모델은 코드로 제작한 복셀 메시 시안이며 블렌더 원본 `.blend` 파일은 없습니다. 그림과 실행 모델을 동일한 완성도나 동일한 메시로 간주하지 않습니다.

- 기본 모델: `data/res/mons_basic_v01/<mons_id>.model.json`과 `.glb`.
- 기본 목록·색: `data/mons_proto/v01/mons_catalog.csv`. 이름·종·원소·대표색·몸색·파일 연결을 관리합니다.
- 부위 형상: `.model.json`의 부위별 복셀 색상·부모·피벗.
- 애니 길이·반복: `animation.csv`. 키프레임: 별도 `animation_tracks.json`.
- Y 위, Z+ 정면, 발밑 원점. 복셀 한 칸은 0.32 장면 단위입니다. 실제 모델 높이는 약 5.12~7.68 장면 단위이며 종별 바운드는 `manifest.json`을 따릅니다.
- `root`는 게임의 월드 배치이고 기본5클립은 내부 `rig`부터 재생합니다. 기본10종 런타임에서는 중간 `guardian_hover` 노드로 추가 부유를 더합니다. `emitter`는 빈 공격 발사 원점 노드이며 메시가 아닙니다.
- 부위별 강체 메시를 회전하는 구조입니다. 공통 이름은 `rig`, `body`, `head`, `ear_l/r`, `eye_l/r`, `paw_fl/fr/bl/br`, `tail`, `crest`, `mane`, `emitter`입니다. 종에 불필요한 부위는 빈 노드로 유지할 수 있습니다. 추가 파츠는 아홀로틀 gill_l/r, 슈가글라이더 membrane_l/r, 천산갑 armor/head_scales, 카피바라 fruit이며 부모 연결을 유지합니다.
- 키는 [정규시간,x,y,z]이며 시간에 클립 길이를 곱합니다. 위치는 rest+입력값×factor, 회전은 rest+degToRad(입력값×motion_factor)를 쿼터니언으로 변환하고, 스케일은 rest×(1+(입력값−1)×motion_factor)입니다. factor는 rig.position만 hover_factor이고 나머지는 motion_factor입니다. 모델 기준 회전은 라디안입니다.
- part.pivot은 부모 기준 로컬 이동, part.rotation은 Euler 라디안입니다. voxel.position은 해당 부위 기준 로컬 장면 좌표이며 voxel.size도 장면 단위입니다. 개별 voxel.color가 sRGB HEX이고 별도 팔레트 사전은 없습니다.
- 큐브의 내부면을 제외한 메시와 vertex color를 사용합니다. GLB에는 5개 클립이 포함됩니다.

### 교체 절차

1. 기본10종의 식별 특징과 실제 모델 정면·측면·뒤태를 확인합니다. 12지신을 기본 목록에 섞지 않습니다.
2. `mons_id`와 원소 매핑을 유지하고 형상·복셀 색상·부위 피벗을 제작합니다. 날개를 모든 종에 붙이지 않습니다.
3. Y-up/Z+ 정면, 발밑 기준, root/rig 분리, emitter 위치를 맞춥니다. 공중 경로를 root 애니메이션에 굽지 않습니다.
4. 위 5클립의 ID·길이·반복·0초 발사 계약을 유지합니다. 귀·꼬리 등 종별 파츠는 공통 리그 이름과 역할에 연결합니다.
5. 현 웹 시뮬레이터는 GLB 대신 모델 JSON을 읽어 공통 라이브러리로 모델을 생성합니다. GLB는 다른 엔진 전달용입니다. JSON과 GLB를 함께 갱신하거나 별도 GLB 로더 연결부를 작성해야 합니다. GLB만 교체하면 현재 뷰어에는 반영되지 않습니다.
6. 데이터만 수정할 때는 exporter → check → 시뮬레이터 build 순서로 확인합니다. generator는 기본 데이터를 다시 만드는 도구여서 수작업 수정값을 덮어쓰므로 원본 제작 규칙을 바꿀 때만 사용합니다.
7. 새 모델의 루프 경계·공격 후 복귀·정지/재개·emitter 위치를 검수합니다. 피해를 발생시키는 새 애니 이벤트를 추가하지 않습니다.

### 원본 수정과 파일 생성 범위

영속 조형·색 변경은 generate.mjs의 creatures·C·종별 switch를 수정합니다. catalog.color/body_color만 바꿔도 실제 복셀 색은 바뀌지 않습니다. JSON을 직접 수정할 경우 voxel.color를 바꾸고 generate는 생략합니다.

generate는 활성 catalog.csv·animation.csv·animation_tracks.json·visual.csv·copy.csv·schema.json 6개와 기본10종 모델 JSON을 덮어씁니다. export-assets는 이 입력과 공통 모델/애니 모듈에서 기본10종 GLB와 manifest를 만듭니다. 기본 GLB 합계는 2,821,400바이트, 종마다 759~1,237복셀·9~13메시입니다.

### 재생성 명령

프로젝트 루트에서 실행하며 기존 프로젝트의 Three.js·esbuild 의존성을 사용합니다. 전체 게임 저장이나 서버를 재시작할 필요는 없습니다.

```sh
node scripts/mons-proto-v01/generate.mjs
node scripts/mons-proto-v01/export-assets.mjs
node scripts/mons-proto-v01/check.mjs
node src/simulator/v01/build.mjs
```

12지신 보존 원본은 `data/mons_zodiac_extra/v01/`, 실행 리소스는 `data/res/mons_v01/`입니다. 기본10종 생성 명령은 이 리소스를 덮어쓰지 않습니다. 보존 생성기 원본은 data/mons_zodiac_extra/v01/source/*.original.mjs이며 재생성이 필요하면 scripts/mons-zodiac-extra-v01/generate.mjs --regenerate-extra와 export-assets.mjs --regenerate-extra를 사용합니다.

### 수호신 기본 동작 · 공중 부유와 빛 꼬리

현중 2026-10-07 직접 지시입니다. **몬스는 아이돌 곁을 날아다니는 수호신입니다.** 팅커벨처럼 빛을 남기며 떠 있는 관계와 움직임을 참고합니다. 동물의 복셀 실루엣을 유지하고 날개는 일괄 추가하지 않습니다. 기본 idle은 공중 대기이며 기본 이동은 드론의 이동과 같습니다.

| 구분 | 애니메이션·이펙트 기준 | 현재 적용 |
| --- | --- | --- |
| 기본 공중 대기 · idle_fly | 발을 땅에 붙이지 않습니다. 느린 상하 부유·미세한 좌우 흔들림에 귀·아가미·꼬리 보조 동작을 겹칩니다. 몸 주위 원소색 빛 입자가 부드럽게 맴돌고 아래·뒤로 작은 빛 가루가 흩어집니다. | 기본10종 뷰어·디펜스 시각 모듈 |
| 기본 이동 · move_fly | 드론처럼 이동 방향을 바라보고 몸을 기울입니다. 이동한 실제 경로 뒤에 빛 꼬리와 빛 가루가 남습니다. 빠르게 이동하면 더 길게 보이고 정지하면 자연스럽게 사라집니다. | 뷰어 8자 비행 시안·디펜스 실제 이동 연결 |
| 복귀 · return_fly | 속도와 기울임이 부드러워지고 빛 꼬리도 약해집니다. 멈춘 뒤 공중 대기로 돌아갑니다. | 기존 복귀 클립과 효과 연결 |
| 아이돌 동행 | 아이돌 어깨·머리 주변의 공중 공간에서 따라다니는 수호신이 기본입니다. 감정·성향·터치 반응도 이 공중 자세를 출발점으로 제작합니다. | 관계·제작 기준 반영. 아이돌 추종 경로와 생활 동작은 후속 |
| 캐스팅권 아육대 | 달리기·박치기·양궁은 종목 전용 동작입니다. 달리기 때는 착지→지상 달리기→종료 후 부유 복귀가 필요합니다. 기본 공중 대기를 지상 대기로 바꾸지 않습니다. | 필요 애니메이션 기재. 이번 제작에는 종목 동작을 포함하지 않습니다. |

원소색은 수 파랑·목 민트·화 빨강·금 분홍·토 노랑을 사용합니다. 움직임이 다른 동물도 빛의 원리는 같습니다. 몸 주변 입자와 이동 궤적을 함께 사용하되 눈·얼굴·동물 특징을 가리지 않습니다. 동물의 실제 꼬리를 늘리는 것이 아니라 **몸 뒤에 남는 빛의 꼬리**입니다.

뷰어에서 「선택한 몬스 확대」→「공중 대기」 또는 「비행 이동」으로 봅니다. 「빛 입자 · 꼬리 보기」로 효과를 끄고 켤 수 있습니다. 효과 확인용 배경은 어둡게 두며, 8자 이동은 뷰어용 시연 경로입니다. 본게임의 위치·속도·표적·피해는 기존 드론 계산을 따릅니다. 별도의 자동 전투 검수는 진행하지 않습니다.

### 제작팀 전달 · 비행 이펙트 규격

수치는 모두 조절 가능한 시안입니다. `data/mons_fx/v01/flight.json`이 효과와 추가 부유의 원본 데이터이고 `src/ui/mons-proto-v01/flight-fx.mjs`가 공용 실행 모듈입니다.

- 기존 5클립 위에 상하 3.6초·좌우 7.2초 주기의 부유를 더합니다. 공중 대기에서 추가 높이 진폭 ±0.34, 좌우 진폭 ±0.12 장면 단위이며 이동·공격에서는 상태별 비율로 줄입니다. 종별 위상 간격은 0.71라디안입니다. 기본 클립의 부유와 더해지므로 전체 높이 진폭을 ±0.34로 해석하지 않습니다.
- 몸 주변 입자 18개와 최대128개의 빛 가루를 재사용합니다. 대기 초당12개, 이동 초당48개를 방출합니다. 최대2초 뒤 사라집니다.
- 빛 꼬리는 월드 좌표 이동 이력을 최대64개, 최대1.8초 보존합니다. 바깥 빛 띠와 밝은 중심 띠를 겹치고 뒤쪽으로 가늘고 투명해집니다. 궤적에 남긴 입자를 몬스의 자식으로 이동시키지 않습니다.
- 뷰어의 비행은 5.8초 8자 경로, 복귀 보기는 8초 경로입니다. 출발·정지·방향 전환을 부드럽게 연결합니다. 뷰어 경로는 다른 팀의 게임 이동 규칙으로 복사하지 않습니다.
- 일시정지·숨김·모듈 전환에서는 시간을 멈춥니다. 분류·모델 변경, 순간 위치 이동, 효과 끄기에서는 이전 궤적을 비웁니다. 해제 시 그래픽 메모리도 반환합니다.
- 기존 GLB는 모델·기본5클립 전달용 v01을 보존합니다. **새 부유 덧입힘·입자·빛 꼬리는 GLB에 들어 있지 않은 런타임 효과**이므로 다른 엔진에서는 JSON 규격으로 별도 제작해야 합니다.
- 캐스팅권 제작 전 `land_sport`(착지), `takeoff_guardian`(부유 복귀), `race_ready/run/finish/tired`를 종목 담당 팀이 이어 제작합니다. 경기 중 빛 꼬리를 어느 정도 유지할지는 종목별 연출에서 정하며 지금 확정하지 않습니다.

### 상태별 부유·빛 효과 수치

아래는 현재 `flight.json`의 시안 값입니다. 시간은 초, 각도는 라디안, 거리는 모델 기준 장면 단위이며 배치 크기에 따라 효과 크기도 달라집니다. `hover_scale`은 추가 부유의 진폭, `orbit_scale`은 주변 입자의 궤도 크기, `trail_scale`은 꼬리 띠 폭의 비율입니다.

| 상태 | 빛 가루 방출/초 | 추가 부유 비율 | 주변 궤도 비율 | 꼬리 폭 비율 |
| --- | --- | --- | --- | --- |
| idle_fly | 12 | 1 | 1 | 0.16 |
| move_fly | 48 | 0.35 | 0.75 | 1 |
| attack_idle | 14 | 0.5 | 0.8 | 0.22 |
| attack | 20 | 0.2 | 0.7 | 0.3 |
| return_fly | 24 | 0.65 | 0.85 | 0.7 |

- 색: 수 `#61a9f1`, 목 `#66cfad`, 화 `#ee6756`, 금 `#ef85ac`, 토 `#edbd53`. 입자·중심 빛은 대표색에 흰색 45%를 섞습니다. 별 모양 반짝임과 부드러운 빛 번짐을 사용하며 화면 입자 크기는 2~38px 범위입니다.
- 주변 입자: 18개, 궤도 반경 2.75, 높이 흔들림 1.65, 회전 속도 0.85, 크기 0.75입니다. 눈·아가미·귀·갑옷·머리 위 귤의 식별성을 가리지 않습니다.
- 빛 가루: 최대128개, 수명 1.3~2초, 기준 크기 0.62, 발생 범위 0.62, 위로 흐르는 속도 0.38입니다. 무작위 크기·수명으로 일률적인 점선을 피합니다.
- 빛 꼬리: 최대64개 위치, 0.032초 간격, 최소 이동 0.025, 수명 1.8초, 바깥 띠 폭 0.95·불투명도 0.8, 중심 띠 폭 0.27입니다. 중심 띠 재질 불투명도 0.9는 현재 코드 상수이며 재제작 시 조절 항목으로 옮깁니다. 꼬리의 길이는 고정 길이가 아니라 속도와 이력 시간으로 만들어집니다.
- 효과 중심은 몸 중심을 기준으로 잡고, 가루·꼬리는 뒤쪽 아래에서 나옵니다. 공격 발사용 `emitter` 노드와 빛 꼬리 발생점은 별개입니다. 카메라를 향하는 띠 두 겹과 별 입자를 사용하며 현재 외부 이펙트 텍스처·음향 파일은 없습니다.
- 뷰어 시연은 가로 진폭 4.1, 앞뒤 진폭 1.4(`radius_z` 2.8의 절반), 높이 0.35인 8자 경로입니다. 이동 5.8초·복귀 보기 8초, 전환 완화 0.6초, 기울임 0.15입니다. 본게임 경로는 드론의 월드 위치를 사용합니다.
- `root → guardian_hover → rig → body/parts` 구조에서 root는 이동·방향, guardian_hover는 추가 부유, rig는 기본5클립을 담당합니다. 부유 위상은 `2π×시간/3.6 + (display_order−1)×0.71`, 좌우는 이 위상의 절반을 사용합니다. 해제할 때 rig를 원래 부모에 돌려놓습니다.
- 빛 가루·꼬리 이력은 월드 좌표에 남깁니다. 모델을 돌릴 때 이미 생긴 궤적까지 함께 회전시키지 않습니다. 한 번에 18×모델 배율을 넘게 이동하면 옛 궤적을 비웁니다. 효과 끄기·분류/모델 교체에서도 이력을 비웁니다. ‘빛 입자 · 꼬리 보기’를 꺼도 기본 공중 부유는 유지합니다.

### 다시 제작한 결과의 전달·확인 목록

1. 제작팀은 사용한 도구의 편집 가능한 원본, 정면·측면·후면 보기, 모델·리그, 5클립과 효과 설정을 함께 전달합니다. 현재 없는 `.blend`나 종목 애니를 이미 제공된 자료로 표시하지 않습니다.
2. 기본10종의 종 구분·멤버 색과 동물의 몸색을 확인합니다. 날개는 일괄 부착하지 않으며 날개 없이도 빛과 부유로 수호신임을 읽을 수 있어야 합니다.
3. idle에서는 발이 땅에 닿지 않고 주변 빛이 보입니다. move에서는 방향 전환·몸 기울임과 실제 위치 이동 뒤의 꼬리가 보입니다. 멈추면 꼬리가 자연스럽게 사라지며 부유는 이어집니다.
4. 기본5클립의 연결·공격 뒤 복귀·발사 0초·루프 경계·정지/재개·카메라별 가독성·모델 크기별 효과 크기를 확인합니다. 정지한 시간만큼 재개 프레임이 튀지 않아야 합니다.
5. 재제작 JSON과 GLB를 함께 바꾸고 모델 명세도 갱신합니다. 효과는 별도로 연결합니다. 부유를 새 클립에 완전히 구워 넣었다면 기존 추가 부유와 이중 적용되지 않게 연결 담당자가 조정합니다.
6. 아이돌 실제 추종, 성향/기분/교감, 획득 컷씬, 아육대 착지·달리기·박치기·양궁·부유 복귀, 기술/필살·승패는 후속입니다. 일반 상태는 공중 자세에서 시작하고, 지상 동작에는 착지·부유 복귀 전환을 별도로 설계합니다. 현재 기본5클립·빛 효과만으로 후속 작업을 완료 처리하지 않습니다.

| src/ui/mons-proto-v01/viewer.mjs | 공용 시뮬레이터 확인 화면 |
| src/ui/defense-proto-v07/preview.mjs | v05 계산과 모델 시각 연결 |

기본 모델은 `loadMonsBundle()` → `createMonsModel(bundle, monsId)`로 생성합니다. 기본10종은 `loadMonsFlightConfig()`로 읽은 설정을 `createMonsAnimator(model, bundle, {flightConfig})`에 전달하고 `createMonsFlightEffects(model, {parent, config:flightConfig, color:row.color})`를 별도로 생성합니다. 보존12종은 추가 설정 없이 기존 애니메이션만 재생합니다.

`bundle.byId`는 Map이고 `model.parts.get('emitter')`는 공격 발사 노드입니다. 프레임 순서는 게임이 root 위치/방향 갱신 → `animator.setState(id)`·필요 시 `playAttack()` → `animator.update(deltaSeconds)` → `flightFx.update(deltaSeconds, {state:animator.state, camera, viewportHeight, visible})`입니다. 효과 부모는 월드 좌표를 그대로 쓸 수 있는 별도 그룹이며 모델의 자식으로 두지 않습니다. 정지 중 두 update를 진행하지 않습니다.

효과는 `setEnabled(boolean)`·`reset()`·`dispose()`로 관리합니다. 모델 교체 시 효과 → 애니메이터 → 모델 순서로 해제합니다. 클립 이름을 바꿀 때는 바인딩도 함께 변경해야 합니다.

[P97 사용 CSV](/docs/planning/planning-docs-tool.html?face=development&doc=P97&plan=planning_development_plan_mons)에 기존 기획2표와 시각·방어·뷰어8표를 연결했습니다. `data/game/mons.csv`(이전5색)와 빈 `mons_skill.csv`는 보존합니다. 계정 소유·기분·스킬과 시각 catalog 병합은 후속 데이터 기획입니다.

현재 방어 7자리는 아홀로틀·피그미하마·나무늘보·슈가글라이더·레서판다·페넥여우·카피바라의 임시 매핑입니다. 친칠라·천산갑·쿼카도 모델과 클립이 있어 뷰어에서 확인하고 바인딩으로 교체할 수 있습니다. 편성·수치·보유량을 확정하는 매핑이 아닙니다.

## 07 개발 진행·검수

완료 보고에는 모델·GLB·클립·데이터·빌드·화면 표시의 실제 확인 결과와 증거 경로를 남깁니다. 기본10종과 보존12종은 각각 검증하며 기본 목록에 중복 혼합하지 않습니다. 최종 전투 플레이·밸런스·체감 검수는 현중이 진행합니다.

이번에 제작하지 않는 내용: 기분별 전용 클립·간식/쓰다듬기·획득 컷씬·캐스팅권의 달리기/박치기/양궁·종별 스킬과 필살기·계정 편성/서버 저장. 현재5클립이 이 기능의 구현 완료를 뜻하지 않습니다.
