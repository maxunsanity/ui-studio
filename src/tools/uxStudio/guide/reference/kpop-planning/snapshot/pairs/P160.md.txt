## 1. 개요

몬스가 막고, 비면 건물 한 단계에 흔적이 남습니다.

우리 몬스 5명이 교차 비행하며 공격합니다.
상대 수비는 유리 방패 하나로 선택한 시설을 지킵니다.

출처: (신규) 현중 2026-10-19~10-20 직접 지시 · 현재 독립 시연 · [세부 근거](./캐스팅권대전_세부_기획서_v06.html#part-1)

![현재 동물형 몬스·시설을 사용한 웹 전투 3D 확인 이미지입니다.](/docs/planning/_previews/casting-battle-v06/fixed-quarter-left-web.png)
현재 동물형 몬스·시설을 사용한 웹 전투 3D 확인 이미지입니다.

1. 캐스팅 보드의 섭외권 쟁탈전입니다. 아이돌 캐스팅 입장권과 구분합니다.
2. 공격 대상은 건물입니다. 상대 몬스를 조준하거나 처치하지 않습니다.
3. 방어 가능한 실제 수비 0~5명과 공용 방패 하나를 표시합니다.
4. 본게임 30초 판정·기분·경제는 기존 코드와 별도 연동 대상입니다.

- 왜 지금: 공격·방어·건물 손상의 역할을 한눈에 읽어야 합니다.
- 이게 핵심: 공격 목표는 시설 하나, 수비 주체는 실제 몬스입니다.
- 이게 아닌 것: 보스 몬스전이나 아이돌 오디션이 아닙니다.

## 2. 필요 관련 시스템 기획서

원문·시연·데이터를 한 콘텐츠에서 잇습니다.

간략 P98을 먼저 읽고 세부 P158에서 규칙을 찾습니다.
이전 P98은 P159 이력으로 보존합니다.

흐름도: P98 간략 → P158 규칙·화면 → P94 독립 전투 시연 → P99·P73 정식 표

1. 최신 직접 지시와 현재 시연을 대표 문서의 기준으로 삼습니다.
2. 몬스·시설·디펜스의 기존 원문은 필요한 역할만 연결합니다.
3. 이전 30초·미니게임·통째 붕괴 안을 최신 본문에 섞지 않습니다.
4. 간략·세부·HTML·MD를 같은 변경에서 함께 고칩니다.

- 왜 지금: 서로 다른 버전이 한 규칙처럼 읽히는 문제를 줄입니다.
- 이게 핵심: 새 콘텐츠를 다시 만들지 않고 실제 공통 자산을 사용합니다.
- 이게 아닌 것: 자동 요약이나 사용자 메모를 저장한 화면이 아닙니다.

## 3. 구동 방법·시뮬레이션

한 번 누르면 한 판, 다음 공격은 다시 누릅니다.

수비가 있으면 10초 공격 뒤 한 명이 지쳐 빠집니다.
대기로 돌아와도 5→4→3→2→1→0의 진행은 남습니다.

화면 흐름: P94 → 독립 전투 시연 → 수동 공격 → 결과·대기 · 스샷 현재3D이미지 · 이식 비교 해당 없음

흐름도: 공격 버튼 → 10초 이동 사격 → 수비 1명 탈진·DB 저장 → 대기 → 다음 공격 버튼

1. P94의 신규 전투 시연 모듈에서 공격을 시작합니다.
2. 정지·이어 재생과 랜덤 뷰·동선으로 표현을 비교합니다.
3. 0명이 된 판은 방어로 끝납니다. 다음 버튼부터 건물을 직접 공격합니다.
4. 훈련 초기화만 수비 5명과 시설 30단계를 복원합니다.

- 왜 지금: 수비 감소를 본 뒤 사용자가 다음 판을 직접 확인합니다.
- 이게 핵심: 자동으로 여러 판을 이어 돌리지 않습니다.
- 이게 아닌 것: 버튼 한 번에 수비 다섯 명을 모두 소진하지 않습니다.
- [이 장 세부](./캐스팅권대전_세부_기획서_v06.html#part-3)


## 4. 상세 기획

계속 날고 쏘며, 한 판에 건물은 한 단계만 낮아집니다.

5명은 높이 1~5m·정면 60도 안에서 간격을 두고 교차합니다.
0명 수비에 적중하면 30→29→28, 수리 전에도 다시 공격합니다.

![실제 본관 표면을 목표로 삼는 건물 피격 확인 이미지입니다.](/docs/planning/_previews/casting-battle-v06/building-hit-stage30-web.png)
실제 본관 표면을 목표로 삼는 건물 피격 확인 이미지입니다.

1. 유도 5연발 → 기관총 22발 → 화염 5연발 → 번개 → 레이저, 각 2초입니다.
2. 수비는 현재 방패 윤곽에 몸 중심을 맞추고 정면 발광한 뒤 막습니다.
3. 카메라는 기본 정면 고정입니다. 왼쪽·오른쪽 쿼터뷰를 고를 수 있고, 자동 카메라를 켰을 때만 10초 동안 한 차례 느리게 왕복합니다.
4. 34개 발사 신호는 표현입니다. 시설 감소는 판당 1, 0단계에서만 종료합니다.

- 왜 지금: 실제 타격 지점과 방어 주체, 손상 결과가 이어져야 합니다.
- 이게 핵심: 실제 한 단계 낮은 모델과 작은 국소 잔재를 유지합니다.
- 이게 아닌 것: 30층을 한 번에 무너뜨리는 연출이 아닙니다.
- [이 장 세부](./캐스팅권대전_세부_기획서_v06.html#part-4)


## 5. 필요 리소스·이미지 설명

새 캐릭터 대신 우리 몬스와 실제 단계 자산을 씁니다.

시설은 본관·별관 A·별관 B의 각 10단계를 합친 30단계입니다.
방패 4종은 투명 유리 외형이며 성능은 같습니다.

![29단계는 실제 [10,10,9] 조합과 작은 국소 잔재를 사용합니다.](/docs/planning/_previews/casting-battle-v06/building-damage-stage29-web.png)
29단계는 실제 [10,10,9] 조합과 작은 국소 잔재를 사용합니다.

1. 아군은 현재 동물형 5명, 수비도 실제 편성 0~5명만 사용합니다.
2. 30=[10,10,10], 29=[10,10,9], 28=[10,9,9]를 데이터로 선택합니다.
3. 방패는 일반형·판타지형·황금빛 원형·캡틴 참고형의 유리 실루엣입니다.
4. 유료 방패는 외형만 바뀌는 영구 스킨입니다. 가격·통화·판매 일정은 결정 대기입니다.

- 왜 지금: 연출 시안과 실제 생산 자산이 같은 형태여야 합니다.
- 이게 핵심: 남은 실제 건물 모델을 보존하고 국소 손상만 더합니다.
- 이게 아닌 것: 스킨 가격으로 방어 성능이나 기분 비용이 달라지지 않습니다.
- [이 장 세부](./캐스팅권대전_세부_기획서_v06.html#part-5)


## 6. 관련 CSV·테이블 데이터

표와 DB가 순서·진행을 보관합니다.

정식 CSV 6개가 규칙·편성·단계·방패·표현의 원본입니다.
탈진 순서와 buildingStage 0~30 진행은 브라우저 DB에 남습니다.

흐름도: 기본 배치·설정 데이터 → 독립 시연 모듈 → 진행 DB 저장 → 로드 → 같은 상태 복원

1. 6CSV와 기존 마스터 ID를 모듈 활성화 때 읽어 표현 설정으로 변환합니다.
2. 남은 실제 ID 중 탈진 순서가 가장 빠른 한 명과 시설 단계를 한 판 완료에서 반영합니다.
3. IndexedDB → localStorage → memory 순으로 저장 매체를 선택합니다.
4. 생산용 SQL은 연동 준비 자료이며 실제 서버·경제 DB에는 연결하지 않습니다.

- 왜 지금: 한 번의 표현 초기화가 누적 수비·시설 상태를 지우면 안 됩니다.
- 이게 핵심: 시점·화면·외형을 바꿔도 저장된 진행을 유지합니다.
- 이게 아닌 것: 소모 순서를 전투 코드에 종별로 고정하지 않습니다.
- [이 장 세부](./캐스팅권대전_세부_기획서_v06.html#part-6)

주사위 환산: 해당 없음(독립 시연은 재화 지급·차감 없음). 본게임 보상은 결정 대기.


## 7. 개발 진행·검수

독립 시연의 완료와 본게임 연동을 구분합니다.

실제 GLB·시연 모듈·Node VM에서 현재 흐름을 검사했습니다.
브라우저 UI·실제 IndexedDB·본게임 경제는 별도 확인 범위입니다.

![모바일 전장의 실제 3D 렌더입니다. 정보 패널을 포함한 UI 캡처는 아닙니다.](/docs/planning/_previews/casting-battle-v06/fixed-quarter-right-mobile.png)
모바일 전장의 실제 3D 렌더입니다. 정보 패널을 포함한 UI 캡처는 아닙니다.

1. 5→0 수동 대기·중복 완료 방지·사용자 설정 탈진 순서를 검사합니다.
2. 실제 시설 30종·31단계·단계 전환과 잔재 복원을 검사합니다.
3. 전체 붕괴 시안은 보관하고 최신 단계 손상으로 바꿉니다.
4. 정식 보드의 판정·기분·경제·계정 소유권 연결은 아직 하지 않습니다.

- 왜 지금: 사용자가 본 장면과 실제 반영 범위를 정확히 알아야 합니다.
- 이게 핵심: 독립 시연 개발 끝, P94 실행 연결·본게임 연동은 별도입니다.
- 이게 아닌 것: Node 검사를 실제 브라우저 플레이 완료로 쓰지 않습니다.
