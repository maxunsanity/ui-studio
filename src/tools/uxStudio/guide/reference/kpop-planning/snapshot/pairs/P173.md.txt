# P173 · 유저 저장 정보

**이 문서는** 유저가 이어서 플레이할 때 필요한 팀·성장·재화·시설 기록이 어디에 남고, 같은 진행인지 어떻게 확인하는지 설명합니다.

**보는 법** [3장](#part-3)의 진입 순서와 [4장](#part-4)의 저장 묶음·복원·거래를 읽고, [6장](#part-6)에서 정적 정의 자료와 [7장](#part-7)에서 미검수 범위를 확인합니다. 서버 저장 목표는 [P222](유저저장_핵심제안서.md), 승인 전 결정안은 [P203](../../기획서/산출_기획서_유저저장_보완판_v1_클로드.md)에서 구분해 읽습니다.

**지금 상태** 분리된 브라우저 저장·인계·스냅샷·이어하기·건설 거래는 부분 구현입니다. 서버 정본·계정/시즌 통합 저장은 기획 중·작업전이며 실제 저장·복원·동시 저장의 전수 검수는 하지 않았습니다. 확인 범위는 [7장](#part-7)에 적었습니다.

## 1. 개요

출처: (합침) [오디션 제안서](../../../../proposal-concept/audition.html)의 팀 이어가기 방향과 현재 보드·시뮬레이터 저장 코드.

현재 확인한 프로토타입은 브라우저 저장을 사용합니다. 보드 경제, 성장 스냅샷과 이어하기, 오디션 인계, 팬 허브는 각각 다른 저장 묶음입니다. 화면은 현재 진행의 식별자와 기록을 확인한 후 필요한 묶음을 읽습니다. 계정 기반 서버 저장과 여러 묶음의 단일 통합은 **작업전**입니다.

```mermaid
flowchart LR
 A[오디션 합류] --> B[팀 인계]
 B --> C[현재 세션과 성장 기록]
 C --> D[성장 스냅샷]
 C --> E[이어하기 기록]
 F[보드 경제와 지갑] --> C
 G[팬과 허브 기록] --> C
 C --> H[화면별 현재 진행 표시]
```

그림은 기록을 연결해 읽는 관계입니다. 모든 자료가 이미 하나의 서버 저장으로 합쳐졌다는 뜻은 아닙니다. 건설은 연결된 진행의 `money`를 사용하며 주사위·보석은 별도 재화입니다.

## 3. 구동 방법·시뮬레이션

화면 흐름: 오디션에서 합류 → 메인 진입 → 같은 진행의 성장·건설·팬 정보를 읽음 → 다시 열 때 저장 대조. 별도의 저장 정보 시뮬레이터는 없습니다.

### [▶ 오디션과 팀 인계 화면 열기](../../../../game-simulator.html?module=simulator_module_audition)

### [▶ 같은 진행의 건설 화면 열기](../../../../game-simulator.html?module=simulator_module_building)

1. 오디션의 합류 결과를 메인으로 넘기면 멤버와 해당 진행의 식별자를 확인합니다.
2. 성장 화면은 같은 진행의 스냅샷과 이어하기 기록을 대조합니다. 건설은 연결된 지갑과 시설 단계를 읽고 견적을 표시합니다.
3. 다른 메뉴로 이동하거나 다시 열 때 기존 진행을 읽습니다. 저장이 없거나 조건이 맞지 않으면 연결 대기 또는 오류로 구분합니다.
4. 독립 시험 페이지는 저장 범위를 분리합니다. 시험 화면의 결과를 실제 진행의 보상으로 취급하지 않습니다. 이번 문서 작업에서 실행·화면 캡처는 하지 않았습니다.

```mermaid
flowchart LR
 A[진행 진입] --> B[세션과 진행 ID 확인]
 B --> C[스냅샷과 이어하기 대조]
 C --> D[같은 기록 표시]
 C --> E[불일치 또는 저장 오류]
 E --> F[연결 대기 또는 오류]
```

## 4. 상세 기획

### 한 판 순서

| 점검 | 내용 |
|---|---|
| 시작·종료 | 합류·게임 진행·성장·구매의 결과를 해당 저장 묶음에 기록하고 재진입 때 읽습니다. |
| 입력·출력 | 멤버·위치·재화·시설·팬·성장 상태를 받아 저장하고 화면과 다른 모듈에 전달합니다. |
| 상태와 전이 | 진행 생성·인계 → 기록 갱신 → 재진입 시 일치 여부 확인 → 복원 또는 대기입니다. |
| 판정 | run·세션·버전·저장 지문과 변경 차수를 확인합니다. |
| 오류·예외 | 손상·불일치·저장 공간 부족은 정상 저장으로 꾸미지 않고 대기나 오류로 처리합니다. |
| 저장·복원 | 성장 스냅샷과 이어하기의 run·지문·차수·내용 검증이 맞아야 같은 기록으로 읽습니다. |
| 다른 모듈 | 오디션, 보드 경제, 건설, 성장, 팬과 관측 화면이 각 자료의 책임을 나눕니다. |

### 현재 저장 묶음

| 묶음 | 기본 키 또는 설정 | 주로 담는 내용 |
|---|---|---|
| 보드 경제 | `kpm:game:prototype:v1` | 위치·돈·주사위·보석·시설 단계·장부와 기능별 기록 |
| 성장 스냅샷 | `kpopmonsters.simulator.shared.v1` | 현재 팀·성장 단계·능력·시설 등 다른 화면에 전달할 기록 |
| 성장 이어하기 | `kpopmonsters.simulator.growth.checkpoint.v1` | 이어서 진행하는 상태와 검증 정보 |
| 오디션 인계 | `kpopmonsters.handoff.audition_to_board.v1` | 합류 멤버·생성 자료·몬스 ID 호환 정보와 진행 인계 |
| 팬·허브 | `kpopmonsters.simulator-hub.v1` | 팬층과 허브에서 관리하는 관련 정보 |
| 시험 세션 | `kpopmonsters.simulator.test-session.v1` | 실행 중 시험 세션·인계의 식별과 출처 |

독립 시험은 기본 키 앞에 시험 페이지의 범위가 붙을 수 있습니다. 같은 기본 이름이라도 범위가 다르면 같은 저장으로 취급하지 않습니다. 위 표는 확인한 주요 묶음이며 모든 기능의 저장 키 전체 목록은 아닙니다.

현재 지도는 성장 스냅샷·체크포인트의 기본 키를 지도 runtime 설정의 키로 대응합니다. 독립 시험 접두와 지도별 키를 함께 확인해야 같은 진행인지 구분할 수 있습니다.

### 성장 기록을 안전하게 읽는 순서

```mermaid
flowchart LR
 A[성장 스냅샷] --> C[같은 run과 지문 확인]
 B[이어하기 기록] --> C
 C --> D[변경 차수와 내용 검증]
 D --> E[일치하면 복원]
 D --> F[맞지 않으면 대기]
```

스냅샷 발행은 예상한 차수와 현재 차수를 대조해 오래된 쓰기를 막습니다. 이어하기 기록은 내용 검증값과 멤버 수, 시설 자료를 확인합니다. 기록이 부분 표시용인지 전체 이어하기용인지도 구분합니다. 이 확인은 저장 오류를 숨기거나 다른 진행의 값을 가져오는 절차가 아닙니다.

현재 공통 복원 어댑터는 정상 이어하기와 검증된 마지막 전체 기록·초기 시험 투영의 조건부 복원을 나눕니다. 같은 세션·멤버·자료와 내용 이력을 확인하며, 스냅샷만으로 지갑·보상 영수증을 새로 만들지 않습니다.

### 건설 거래와 저장

시설 선택만으로는 돈을 쓰지 않습니다. 구매 요청은 선택 시설·단계·예상 차수와 요청 ID를 확인한 뒤 지갑·시설·스냅샷·이어하기·거래 결과를 준비합니다. 같은 요청의 재전송은 기존 결과를 사용하고 오래된 견적은 거절합니다. 쓰기 중 오류가 나면 이미 쓴 값을 되돌리려 하며, 복구까지 실패하면 별도 오류를 남깁니다.

경제 프로토타입에는 손상·이관 전 원문을 백업하는 경로가 있습니다. 시험 진입 가드는 손상된 시험 세션·허브·섭외전 흐름의 지정 키를 제거하는 별도 복구 경로를 둡니다. 성장의 복수 기록 저장은 원문 값 대조와 자기 쓰기 복구를 사용하며, 로컬 보호 장치의 범위를 서버 동기화와 구분합니다.

```mermaid
flowchart LR
 A[시설 견적] --> B[단계와 차수 확인]
 B --> C[지갑과 시설 결과 준비]
 C --> D[저장과 영수증]
 D --> E[성공 후 화면 갱신]
 C --> F[저장 오류 시 복구]
```

### 서로 다른 저장의 경계

오디션 인계는 처음 함께하기로 한 후보의 정체성과 서사, 성장 기록은 현재 능력·단계의 출처입니다. 팬 허브의 층별 값이 전달되지 않았다면 팬 총수를 임의로 나눠 채우지 않습니다. 시설 단계와 캐스팅 관련 자료는 여러 묶음에 표현될 수 있어 현재 연결 경로별 대조가 필요합니다. 화면 설정이나 CSV에 적힌 기준값은 플레이어가 획득한 재화·능력 기록과 구분합니다.

### 필요 시스템

브라우저 저장 어댑터, 세션·run 식별, 스냅샷과 이어하기 검증, 지갑·시설 거래, 인계와 팬 기록의 연결이 필요합니다. 계정 ID·서버 저장·기기 간 동기화와 모든 묶음의 단일 정본은 작업전입니다.

### 화면·연출 목록

| 화면·안내 | 역할 |
|---|---|
| 오디션 합류·메인 진입 | 선택한 팀과 진행을 전달 |
| 성장·건설 화면 | 연결된 현재 기록·지갑·시설을 표시 |
| 연결 대기·저장 오류 | 누락·불일치·저장 실패를 구분 |
| 독립 시험 | 지정된 별도 저장 범위와 시험 출처 표시 |

### 남은 결정

서버 계정과 동기화 방식, 저장 묶음의 단일화 및 충돌 복구 정책은 결정 대기입니다. 저장되는 게임의 보상·성장 수치는 각 표에서 관리하며 **발란스 대기**입니다.

## 6. 관련 CSV·테이블 데이터

저장 내용은 CSV 자체가 아니라 브라우저 기록입니다. 아래 자료는 저장된 ID와 값을 해석하거나 연결할 때 쓰는 정적 원본입니다.

| 파일 | 역할 | 주의 |
|---|---|---|
| `data/game_prototype/profile.json` | 보드 프로토타입 기본 저장 키·화면 설정 | 계정 서버 저장이 아님 |
| `data/simulator/shared/contract.json` | 인계·스냅샷·이어하기의 공통 계약과 키 | 실제 세션과 저장 범위도 확인 |
| `data/game/board_tile.csv` | 저장된 보드 위치와 시설의 정의 | `tile_id`, `pos`, `fac_id` |
| `data/master/building_master_level.csv` | 시설·단계별 비용과 효과 | 저장된 현재 단계가 아님 · 값은 발란스 대기 |
| `data/idol_ability_sim/idol_growth_stat.csv` · `idol_growth_stage_gate.csv` | 능력과 성장 단계의 정의 | 멤버의 현재 능력·단계 저장과 구분 |
| `data/fan_tier/fan_tier.csv` | 팬층의 종류와 ID | 현재 팬 인원 기록이 아님 |

주사위 환산: 해당 없음 · 저장 정보 자체가 재화를 지급하거나 소비하지 않습니다.

### 유저 서버 저장 표

서버가 유저마다 들고 있어야 할 정보입니다. `account`는 시즌이 끝나도 남고, `season`은 시즌 끝(63일)에 비우며, `separate`는 따로 보관합니다. 표 원본: `data/user_server_save_table.csv` (HTML 화면은 이 CSV를 읽어 그립니다.)

## 7. 개발 진행·검수

확인 범위: 공통 저장·복원·거래 래퍼의 소스 경로를 대조했습니다. 성장 화면의 보호된 직접 호출부와 실제 게임 저장·복원·동시 창 충돌·저장 실패 및 복구 동작은 검수하지 않았습니다. 계정 서버·기기 간 동기화는 P222의 기획 목표와 분리합니다.

| 요소 | 상태 | 확인 범위·다음 작업 |
|---|---|---|
| 브라우저 저장 묶음과 성장 복원 검증 | 개발 중 | 세션·run·차수·지문 대조 경로 존재. 모든 화면의 전수 검수는 별도 |
| 건설 지갑·시설 거래 | 개발 중 | 같은 진행의 견적·영수증·저장·복구 경로 존재 |
