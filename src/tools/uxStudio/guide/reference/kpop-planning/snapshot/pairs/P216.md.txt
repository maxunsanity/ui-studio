# P216 · 친구 매칭 · 대표 개발 기획서

**이 문서는** 친구를 맺고 함께 노는 방법, 그리고 친구 관계가 순위에 닿지 않게 하는 선을 정리한 대표 개발 기획서입니다. P205의 FM1~FM9는 클로드의 제안(검수 대기)이며 사용자 승인으로 읽지 않습니다.

**보는 법** 1장 그림 → 4장 「한 판 순서」 → 핵심제안 개발의 「파트너 이벤트 시뮬레이터」 순서로 읽습니다. 세부 제안과 근거는 책갈피 [P205 친구 매칭 제안](../../기획서/산출_기획서_친구매칭_제안_v1_클로드.md)에 있습니다.

**지금 상태** 친구 매칭 기획은 진행 중입니다. 독립 메모리 시안과 LOCAL 부분 함수는 있으나 실제 호출자(caller)·서버·운영 저장 연결과 실구동 검수는 미확인입니다.

## 1. 개요

출처: (합침) 이전 작성 당시 기획원문 미확인(핵심제안 목록 한 줄 · 옛 모노 262의 ‘이식 안 됨’은 당시 기록) · 현재 상세 제안: 책갈피 [P205 친구 매칭 제안](../../기획서/산출_기획서_친구매칭_제안_v1_클로드.md) · 현중 11/01~11/02 지시

> **핵심** 관계는 **세 겹**(친구 1:1 · 크루 여럿 · 무작위 상대)입니다. 친구끼리는 소식을 보고, 작은 응원 선물을 주고받고, **파트너 이벤트**로 같은 목표를 함께 채웁니다. 투표권 · 순위 점수는 주고받지 않습니다.

```mermaid
flowchart LR
  A[나] --> B[친구 · 서로 수락]
  B --> C[소식 피드]
  B --> D[작은 응원 선물]
  B --> E[파트너 이벤트]
  B -.->|주고받지 않음| F[투표권 · 순위]
```

### 콘텐츠 경계

- 맡는 것: 친구 맺기 · 소식 · 선물 · 카드 트레이드 상대 · 파트너 이벤트 · 친구 추천.
- 다른 문서에 맡기는 것: 크루 → [P221 응원 크루](응원크루_핵심제안서.html) · 게릴라 상대 → [P220 게릴라 공연](게릴라공연_핵심제안서.html).

### 현재 기준과 목표

| 관계 | 무엇 |
|---|---|
| 친구 1:1 | 서로 수락 · 친구 코드 · 초대 링크 |
| 크루 여럿 | 응원 크루(P221) |
| 무작위 상대 | 게릴라 · 무대 대결(서버 매칭) |

- 친구에게 투표 부탁은 알림으로만 보내고 하루 횟수를 제한합니다. 친구 수는 순위에 직접 들어가지 않습니다.
- 친구 추천 = 같은 언어권 · 비슷한 단계 · 비슷한 활동 시간대. 연락처 불러오기는 별도 동의일 때만.

## 3. 구동 방법·시뮬레이션

화면 흐름: 친구 탭 → 친구 맺기 · 소식 → 파트너 이벤트 · 스샷 미완 · 이식 비교 해당 없음

- 실행: 하단 friend.mjs는 메모리·DOM에서 움직이는 독립 시안입니다. 실제 파트너 기여·보상·선물 API·저장은 이 시안에 연결되지 않습니다.
- 핵심제안 개발의 **파트너 이벤트 시뮬레이터**는 한 번 굴리면 표시된 인원 모두에게 임시 난수를 더해 목표 막대를 채웁니다. 숫자는 모두 임시 시안이며 실제 각자의 기여 수신을 검수한 결과가 아닙니다.

별도의 socialFriend/localMatch.ts에는 친구 코드·요청·수락/거절·제거·초대 stub의 LOCAL 상태 함수가 있습니다. 이 부분 함수의 존재와 현재 본게임의 실제 호출자·서버·운영 저장 연결은 구분하며, 후자는 이번 읽기 감사에서 확인하지 않았습니다.

## 4. 상세 기획

### 한 판 순서 (임시 시안)

| 점검 | 내용 |
|---|---|
| 시작·종료 | 이벤트 기간에 친구와 짝 |
| 입력·출력 | 입력 = 각자 굴림 / 출력 = 함께 채운 목표 · 보상 |
| 상태와 전이 | 짝 → 각자 굴림 → 목표 채움 → 보상 |
| 판정 | 각자 몫을 더함 |
| 오류·예외 | 친구가 쉬어도 내 몫은 쌓임 |
| 저장·복원 | 친구 목록은 계정 · 이벤트 진행은 시즌 |
| 다른 모듈 연결 | 크루 · 게릴라 · 페스티벌 |

### 선물 · 카드 트레이드 (임시 시안 · 현중 11/02 「카드는 트레이드」)

작은 응원 선물만 주고받습니다(횟수는 발란스 대기). 투표권 · 지분 · 입장권은 선물할 수 없습니다. 아이돌 카드는 **중복분만** 다른 유저와 **같은 단계 카드 1장 ↔ 1장**으로 바꿀 수 있습니다(현중 11/02 · 돈 · 코인 · 유료 재화 없음 · 누구와 · 하루 몇 번은 이 친구 기획이 끝난 뒤 정함). 능력에 쓴 1장은 그 아이돌 전용이라 옮기지 않습니다. 규칙은 [P225 카드](../../../../_이전기획_보관/20261116_카드옛구조/삼중AI_공용_20260929/산출/개발진행기획_v01/콘텐츠별_v03/카드_핵심제안서.html).

### 필요 시스템

친구 목록 · 수락 · 소식 피드 · 선물 · 파트너 이벤트 · 추천.

### 화면·연출 목록

친구 탭 · 소식 · 파트너 이벤트 화면.

### 남은 결정

- 친구 수 상한 · 이벤트 인원 · 보상 — 발란스 대기
- 옛 262 친구 매칭 원문을 찾으면 다시 맞춤

## 6. 관련 CSV·테이블 데이터

| 파일·보기 | 역할 | 주키·참조 | 값 | 담당 |
|---|---|---|---|---|
| friend_partner_event (후보) | 파트너 이벤트 목표 · 보상 | 이벤트 id | (신규) 결정 대기 | 표 담당 |

friend_partner_event는 기존 후보명과 결정 대기를 유지합니다. 이 이름만으로 실존 CSV 공급·로더 연결을 확인한 것은 아니며, friend.mjs의 임시 목표·난수는 운영 표값이 아닙니다.

주사위 환산: 해당 없음.

## 7. 개발 진행·검수

| 요소 | 상태 | 확인 방법·증거 | 다음 작업 |
|---|---|---|---|
| 기획(이 문서 · 책갈피 상세) | 기획 중 | P205 · 이 문서 | 현중 확인 |
| 파트너 이벤트 시뮬레이터 | 개발 끝(시안) | 핵심제안 개발 미리보기 | 실제 표 연결 |
| 게임 시뮬레이터 모듈 · 본게임 | 기획 중 · 작업전 | — | 표 확정 뒤 |

위 ‘개발 끝(시안)’은 독립 화면 시안의 상태입니다. 시안의 ‘완성·모두 보상’과 ‘보냈어요’는 화면 문구이며 실제 보상 지급·선물 전송의 증거가 아닙니다. P205 FM1~FM9의 제안 상태와 기존 날짜 있는 정책·발란스 대기를 유지하며, 현재 운영 API·저장 writer 연결과 실제 구동·저장 검수는 미확인으로 남깁니다.

### 수락 기준

친구끼리 투표권 · 순위 점수를 주고받을 수 없고, 친구 곡이 채점단에 배정되지 않아야 합니다.

### 뺀 것·옮긴 것·보존한 것

세부 결정과 근거는 책갈피 P205에 둡니다. 원문이 없어 새로 씁니다.
