## 2026-10-29 · 탑뷰 직접 터치 선택 · 전투·영수증·복귀 보존 계약



공통 모바일 하단의 카드북·상점·모험·건설·미션 구성을 유지하며, 각 시뮬레이터의 「건설」은 같은 simulator_module_building으로 연결합니다. 호스트 공통 프레임은 기존 activate 경로를, 성장 iframe은 공개 wrapper의 hubToolNavigate 경로를 사용합니다. 이동만으로 현재 testPage·run·팀·돈·시설을 초기화하거나 다시 생성하지 않습니다. 실제 지갑 정본이 없는 상태의 연결 대기 경계도 유지합니다.

건설과 쟁탈의 시설 선택은 3D 지도를 거의 탑뷰로 내려다보며 9시설을 한 화면에 보는 방향입니다. 건물과 넓은 부지를 직접 터치하는 조작이 주선택입니다. 지도에 짧은 시설명·현재 단계·선택 표시를 상시 함께 두어 1단계의 작은 건물도 구별하도록 합니다. 상시 큰 9시설 버튼 그리드는 없앱니다. 보조 「시설 모두 보기」 버튼은 3D 지도 우상단의 화면 오버레이에 두고, 누르면 폰 안에 2열 선택 시트를 엽니다. 지도와 시트는 같은 시설 ID를 선택하며 선택만으로 비용 차감·전투 시작·보상을 실행하지 않습니다. 건설의 고정 하단에는 「한 단계 증설」과 「최대 증설」 두 직접 구매 버튼을 둡니다. 한 단계 버튼에는 필요한 비용을, 최대 버튼에는 현재 지갑으로 가능한 N단계와 총비용을 먼저 표시합니다. 선택 상세는 한 단계 기준의 현재→다음 단계·동별 변화·비용·잔액을 표시하고, 최대 견적은 해당 버튼의 N단계·총비용으로 확인합니다. 각 버튼을 누르면 해당 견적으로 바로 구매하며 별도 수량 조절 UI는 두지 않습니다.

- 선택 UI는 기존 요청의 facility ID·단계를 선택해 전달합니다. 선택 이벤트만으로 정산·보상·ACK를 생성하지 않습니다. 터치와 2열 보조 시트는 같은 선택 상태를 사용하고, 새 요청을 만들지 않은 채 기존 공격 진입·10초 전투·보상 단계로 이어집니다.

- 정식 도착의 실제 지급·영수증·checkpoint·ACK는 기존 flow/bridge가 담당합니다. UI 연출은 영수증 숫자를 읽으며 별도 지급하지 않습니다. 기존 판정·기분·파손·메가·배수·보상 수식과 동일 run/scope의 중복 방지 경계를 유지합니다.

- direct inner에서 현재 run의 유효 요청이 없으면 waiting으로 남고 정식 도착 경로를 안내합니다. 자동 setupDemo·가짜 참여자·가짜 보상으로 대체하지 않습니다. 이미 완료·ACK한 요청을 다시 정산하지 않으며 기존 명시적 offline/entryReview 시연은 그 별도 경계를 유지합니다.

- stage_battle 보드를 가리던 잔존 CSS의 숨김 조건을 수정했습니다. 보드 진입→시설 선택→전투→보상→ACK→dice 메인 복귀는 같은 요청을 유지하며 메뉴 전환과 다시 보기가 돈·팬을 재적립하지 않습니다.

왼쪽 모바일은 유저가 실제 플레이할 게임 UI입니다. 시설 이름·선택·돈·단계·행동을 표시하고, 출처·요청 ID·run/scope·revision·장부·오류 원인은 오른쪽 내부 정보에서 확인합니다. 외관 시험의 슬라이더·즉시 완성·전체 성장·복원은 오른쪽의 별도 창 링크로 열며 실제 구매 화면의 조작과 섞지 않습니다.

## 2026-10-29 · 보상 수식과 배수 증폭 연출

다음 상세 문단에 포함된 실측값·시험 수는 당시 원문 기록입니다. 현재 표현·설정 계약과 구분해 읽으며, 이번 정적 문서 대조가 새 실게임·지급·저장 검수나 운영 승인을 뜻하지는 않습니다.



현재 돈 정산은 `floor(base_arrival_r × 주사위 배수 × 결과 계수 × 메가 계수)`입니다. 원본 `casting_battle_flow_config.csv`는 R100, 건물 적중15, 몬스 방어7.5, 메가3을 임시값으로 기록합니다. 적중 계수는 공격에 성공했을 때의 보상 배율이며, 수치15의 산정 근거는 원본에 없습니다. 기존 `stage_battle_steal_rule.csv`에도 비앙카의 임시 시안으로 기재돼 있습니다. 새 확정값으로 취급하지 않습니다.

유저 화면의 **전투 보상**은 `R × 결과 계수 × 메가 계수`까지 반영한 주사위 배수 전 금액입니다. **전투 보상 × 주사위 배수 → 최종 획득** 순으로 표시합니다. 내부 `baseRewardR`는 주사위 배수가 이미 곱해진 값이므로 다시 기본금액으로 쓰지 않습니다. VM은 원래 request/receipt/원장/표시 아이템·지갑 합계를 대조하며 최종 숫자는 영수증 값을 그대로 읽습니다. 0·누락·불일치·floor 순서 불일치에는 억지 수식을 만들지 않고 기존 최종금액 표시를 유지합니다.

연출은 1,460ms의 전투 보상→오른쪽 배수 충돌→카운트업→확대·발광→서로 다른 두 충격→잠깐 유지 뒤 기존 동전 날아가기로 이어집니다. 전용 DOM은 절대위치이며 기존 필러·폰 높이는 바꾸지 않습니다. 단계 높이의60% 안에 전체 수식을 맞추고 첫 실행·취소 후 재생도 같은 높이로 측정합니다. 작은 창에서 재보기 조작으로 수식이 화면 밖이면 해당 시뮬레이터 문서만 한 번 정렬합니다. 이미 보이면 이동하지 않습니다. 동작 줄이기에서는 수식·최종액을 정적으로 보여줍니다. 숨김/중단/취소/재보기는 기존 연출 시계와 토큰을 따릅니다.

렌더러의 `presentationOnly:true`는 화면 연출이 돈을 지급하지 않는다는 뜻이며 실제 영수증의 지급 여부와 다릅니다. 정식 정산·복귀 ACK는 기존 코드가 담당합니다. 실제 같은 전송 세션에서 방어 보상750 × 주사위2 = 1500, 재보기 동안 지갑12575 유지, 복귀 후14075 한 번 지급, 끝 연출 카운터1500을 확인했습니다. 효과 자체는 이미지 추가 없이 숫자·폰트·선·발광으로 표현하며 기존 동전 이동은 유지합니다.

관련 구현: `casting-reward-multiplier-vm.mjs`, `casting-money-impact.mjs`, `casting-reward-presentation.mjs`, `casting-entry-view.mjs`. 표시 copy/timing/motion은 `/data/simulator/casting-reward-impact.json`을 읽습니다. 최종 관련 통합 회귀290/290 PASS, 실제 UI와 메모리 시험의 구분·캡처는 공용 완료보고를 따릅니다.

## 1. 개요 · 개발 계약

P98의 흐름을 구현하는 수식·공용 기분·원장·ACK·오류·복원 계약을 정의합니다. [P98 흐름](/docs/planning/삼중AI_공용_20260929/산출/개발진행기획_v01/콘텐츠별_v03/캐스팅권대전_기획서.html)과 [P99 표·열·등록](/docs/planning/삼중AI_공용_20260929/산출/개발진행기획_v01/CSV별_v03/casting-csv.html)을 함께 읽습니다.

상태는 구현·일부 보상 화면 확인 · 정식 보드 도착 검수 대기입니다. 이 본문은 개발 계약과 확인할 기준을 정리합니다. 실제 브라우저·게임 플레이 검수와 운영 승인은 별도 근거가 있어야 기록하며 이전 버전의 빌드 결과를 이번 시험 통과로 바꾸지 않습니다.

## 3. 원장·ACK·중복 복원

| 단계 | 저장·정산 계약 |
| --- | --- |
| 비교 | 순수 계산 결과만 읽습니다. 요청·봇·기분·시설·일일 장부·지갑·receipt는 바꾸지 않습니다. |
| 시작·선택 | 기존 pending을 덮어쓰지 않습니다. 요청별 시험 봇 스냅샷·선택 시설로 한 판의 결과를 계획합니다. |
| playing | 기존 10초 전투가 계획한 판정·기분·시설 결과를 표현합니다. |
| settled | request와 receipt를 처음 한 번만 확정합니다. 계산된 돈을 공개하고 rewardTest 시험 지갑에 한 번만 반영합니다. |
| acknowledged·복귀 | 기존 수신 확인·메인 복귀를 유지합니다. 재개·새로고침·다시 보기·중복 완료는 재적립하지 않습니다. |

일반 봇과 시험 봇의 저장 범위를 섞지 않습니다. 일반 run 상태의 잔액·기분·손상 누적을 시험 스냅샷으로 덮어쓰지 않습니다.

## 4. 수익 식 · 공격 보상과 상대 손실

~~~text
battleOutcome = blocked 또는 building-hit (전투·원장 원본)
moneyOutcome = (battleOutcome == building-hit) ? hit : blocked
megaFactor = (moneyOutcome == hit && mega) ? mega_coin_mult : 1
attackerMoney = floor(base_arrival_r * multiplier
  * (moneyOutcome == blocked ? block_coin_mult : hit_coin_mult)
  * megaFactor)

victimPct = (moneyOutcome == blocked) ? victim_block_pct : victim_hit_pct
rawVictimLoss = bot.coins * victimPct / 100
dailyRemaining = day.startCoins * victim_daily_cap_pct / 100 - day.lostCoins
protectedSpendable = bot.coins - day.startCoins * victim_protect_pct / 100
victimLoss = (day.hits >= victim_daily_hits) ? 0
  : floor(max(0, min(rawVictimLoss, dailyRemaining, protectedSpendable)))
~~~

- `base_arrival_r`는 주사위 배수를 곱하기 전의 기본 R입니다. R에 배수를 먼저 반영한 뒤 다시 곱하지 않습니다.
- 공격 보상은 상대 보유금이나 `victimLoss`로 제한하지 않습니다. 상대 잔액 0에서도 내 돈은 R 식으로 계산합니다.
- 상대 손실은 상대 현재 잔액·일 시작 잔액·누적 손실·보호선·유효 피격 횟수로 별도 계산합니다. multiplier와 메가 계수를 상대 손실에 곱하지 않습니다.
- 메가는 hit에서만 코인 계수를 적용합니다. 팬·기분 비용·보호 수치의 기존 임시 설정은 이번 작업에서 새로 확정하지 않습니다.
- 현재 기본 R 100, 적중 15배, 방어 7.5배는 기존 CSV의 임시 시험값입니다. 메가가 아닌 R 100·1배는 방어 750·적중 1,500이며 hit에 기존 메가 3배가 붙으면 4,500입니다. 기존 메가 확률 2%와 3배를 보존하며 확정 지급량을 뜻하지 않습니다.

`growth_money`·`growth_fans`는 단위 태그입니다. 정식 단위 환산과 성장 실제 보유금·팬 연결은 대기이며 시험 숫자를 실보유금의 확정 단위로 해석하지 않습니다.

v10은 돈·주사위를 각각 크게 보여준 뒤 실제 DOM 배지로 모으고, 카드팩 탭 개봉부터 모든 카드의 개별 공개·그림/등급/신규·중복·읽기·최고/전체 요약·상세·확인·카드 배지 수집·최종 목록 유지까지 이어갑니다. v09의 3.2초 동시 종료와 5개 항목 제한은 폐기합니다. 보상 전체 길이는 카드 수·등급·사용자 입력에 따라 달라지고 사격 본편 10초는 유지합니다.

확정(현중 직접 지시): 성공(건물 적중)과 실패(방패 방어) 모두 돈을 얻습니다. 카드·주사위 보상이 있는 결과도 표현합니다. 상대 SNS 얼굴 공간을 입장부터 마련합니다. 9시설을 Blender의 실제 모델로 배치합니다. 현재 게릴라는 준비 중으로 섭외권 쟁탈전이 100% 결정되지만, 앞단 콘텐츠 결정 화면은 유지합니다.

확정(기존 표현 구현): 사격 본편은 10초입니다. 유저 공용 기분 하나와 원래 편성 N으로 수비를 계산합니다. 시작 수비가 있던 마지막 방어 판도 건물 피해는 없고, 다음 무수비 판부터 시설 한 단계에 피해를 줍니다. 새 도입·보상 시간을 위해 기존 사격을 줄이지 않습니다.

쟁탈 위치는 data/game/board_tile.csv의 content_kind=casting 4행 6·16·26·36입니다. 표시 눈·합·이동·도착을 맞추고 매칭할 수 없으면 준비 오류를 표시합니다. tile_kind의 임시 불일치는 테스트 분류 보정 안내로만 표시하며 정식 보드 표 원본은 수정하지 않습니다.

### 전체 흐름 · 성장 도착 연동 필수 / 보상 전체 연출 v10 구현·파일·빌드 확인 완료

- 아이돌 성장 시뮬레이터에서 쟁탈 보드에 도착하면 같은 도착 요청의 정보가 섭외권 대전 탭으로 전달되어야 합니다. 기존 성장 자동보상은 이미 계산된 값을 보존하며 다시 추첨·계산·지급하지 않습니다. 현재 돈·주사위·카드는 임시 입력으로 연출하고, 실시간 대전에 따른 보상 변동·실제 지갑 정산은 추후 연결합니다. 같은 도착·결과를 다시 보아도 중복 지급하지 않습니다.
- 같은 도착 요청에서 콘텐츠 결정부터 복귀까지 이어집니다. 현재는 섭외권 100%를 표시하고 게릴라는 준비 중으로 둡니다.
- 상대 프로필을 먼저 보여준 뒤 9시설의 건물 또는 이름표를 눌러 고릅니다. 선택 링·시설명·현재 단계가 함께 바뀝니다. 시설 0단계는 잔재로 표시하고 공격 선택을 잠급니다.
- 선택 정보를 기존 전투 입력에 넘깁니다. 외부 전투는 실제 편성·기분·시설 단계·시드로 한 판을 표현하며, 훈련 입력·초기화·추가 공격을 잠급니다.
- 전투 판정 뒤 supplied rewardItems를 공통 보상 모듈로 전달합니다. 성공·실패 모두 돈 장면부터 시작하고 주사위·카드는 해당 보상이 있을 때 순차 표현합니다. 팩 탭·요약 확인은 자동 통과하지 않으며 마지막 수집 도착까지 기다립니다. 실제 지급 미연결 상태는 오른쪽 검토 정보에 표시합니다.
- 미완료 이탈은 같은 도착 요청을 재개하는 구조로 연결합니다. 다시 보기와 재개는 같은 결과의 표현이며 새 지급·새 확률 판정을 만들지 않습니다. 이 연결의 실제 브라우저 검수는 대기입니다.

### 보상 전용 보기 · 구현·파일·빌드 확인 완료

오른쪽 검토 패널에서 전투 없이 같은 예시 보상 전체를 재생합니다.

현재 검토 기본 입력은 돈 125,000·주사위 20·카드 5장입니다. 5테마의 실제 카드 데이터에서 읽은 별 1~5성을 예시로 사용하며 사용자가 값을 바꿀 수 있습니다. 이 수량은 임시 연출 입력이며 고정 드롭·카드 수 상한이 아닙니다. NEW/중복도 시안 입력이고 실제 보유 판정이 아닙니다. 테마 그림은 개별 카드 원화가 아닌 공용 그림 예시입니다. 이 버튼은 도착·전투·기분/시설 정산이나 지급을 추가 실행하지 않습니다. 모드 이름과 입력은 문구·설정 데이터에서 관리합니다.

### 기존 독립 전투 훈련 · 보존

- 내 몬스 0~5·지원 포함 총 1~10, 상대 원래 편성 N 1~10을 설정합니다. 무수비 테스트는 N 0도 허용합니다. 기분%와 판당 비용은 표시된 훈련 입력값입니다.
- 공격 버튼 한 번은 출격 준비→별도 10초 사격→대상 파손→기분/몬스 정산→완료 저장 한 판입니다. 완료 후 대기로 돌아오고 다음 공격은 다시 누릅니다.
- N 선택은 남은 수비 수로 덮어쓰지 않습니다. N 10·기분 90%면 원래 편성 10/실제 수비 9입니다. 편성·화면·시점·외형 변경은 공용 기분을 보존합니다.
- 일시정지/이어 재생은 모든 표현 단계를 함께 멈추고 잇습니다. 기본 정면·자동 꺼짐이며 좌우 쿼터 고정·선택 시점 복원·선택적 자동 왕복을 제공합니다.
- 명시 훈련 초기화만 훈련 기분·편성·시설 30단계·공격 수·중복 기록을 초기화합니다. 훈련 초기화가 본편 봇·원장을 지우는 계약은 없습니다.

### 메인 허브 · 최신 직접 지시

「메인」은 오디션 바로 다음에 두는 상위 허브이며 별도 강조색으로 구분합니다. 정식 40칸의 주사위 이동과 공통 수치·조건·환경만 관리합니다. 쟁탈·건물 성장·이벤트·나쁜 기운 디펜스의 연출과 기획 확인은 각 전용 툴로 정보를 넘겨 진행하고 결과를 같은 메인에 돌려받습니다. 메인 안에서 모든 콘텐츠 연출을 중복 실행하지 않습니다.

공용 허브 상태·문맥 전달 계약으로 현재 팀·도착 칸·배수·조건/환경·결과의 대응을 유지합니다. 개별 툴은 받은 문맥으로 자기 연출을 확인하고 결과를 반환합니다. 기존 정상 성장/자동보상 계산값·쟁탈 receipt/ACK·presentationOnly·중복 지급 금지 경계는 유지합니다. 허브에 별도 보상 추첨·새 재화 지갑을 만들지 않습니다.

나쁜 기운 원본의 360 상한·굴림 +1·루머 카드당 +15·배수 직접 곱/중복 가산 금지와 실제 디펜스 게이지 결과 반환을 연결해 파일·빌드를 확인했습니다. 실제 플레이는 현중 검수 대기입니다.

### 카드별 실제 정보·신규/중복 · 데이터 기반 표현

- 카드 refId·name·imageUrl·rarity·isNew·ownedCountBefore·amount를 전달할 수 있습니다. 실제 그림·이름·별 등급·장수만 표시하며 장식 별을 등급으로 사용하지 않습니다.
- 예시의 card_theme_01~05는 등록된 테마 공용 그림입니다. 각 카드의 개별 원화가 아니며 오른쪽 검토 정보에 공용 그림 예시라고 표시합니다. 실제 개별 그림은 imageUrl로 교체합니다.
- isNew가 true면 NEW, false면 중복입니다. 미제공은 보유 확인 대기이며 임의로 신규·중복을 만들지 않습니다. imageUrl·rarity가 없거나 그림을 불러오지 못하면 그림/등급 준비 상태를 표시합니다.
- 5개 항목 상한을 폐기합니다. 카드 배열과 각 amount의 전체 장수를 끝까지 공개합니다. 같은 카드 여러 장도 실제 수량을 누락하지 않으며 전체 요약 합계에 맞춥니다.
- 「나머지 한 번에 보기」는 사용자가 눌렀을 때만 남은 개별 공개를 건너뛰고 전체 카드 요약으로 갑니다. 카드를 버리거나 수량을 줄이지 않습니다.
- 최고 카드는 공급된 별 등급을 우선하고, 동률이면 확인된 신규 정보·안정된 카드 순서로 고릅니다. 알 수 없는 등급·신규 상태를 임의 보완하지 않습니다.

### 실제 배지 앵커·완료·취소 · 임시 시안

돈·주사위·카드의 화면 목적지는 보상 host 안 가상 좌표가 아닌 실제 상단 DOM 배지의 getBoundingClientRect 중심입니다. 화면/모바일 크기가 바뀌면 실제 앵커를 다시 계산합니다. 도착 반응과 숫자는 같은 도착 신호에 맞추고, 마지막 입자/카드 수집이 끝나기 전에 완료를 반환하지 않습니다.

팩 탭·요약 확인을 자동 타이머로 넘기지 않습니다. 모든 카드 공개 또는 사용자의 요약 이동, 요약 확인, 마지막 카드 수집 도착을 끝낸 뒤에만 완료 Promise로 부모 복귀를 엽니다. 모노 walletRewardFly는 void 함수이므로 그대로 완료 신호로 사용하지 않습니다. itemFlyFx의 async 도착 대기 구조를 참고합니다.

보상 다시 보기·보상 전용 보기는 같은 결과의 표현이며 실제 돈·팬·주사위·카드 잔액·기분·시설 정산을 바꾸지 않습니다. 중단·취소는 지급·정상 완료가 아닙니다. 비활성화·다시 재생 요청에서 관련 소품·이벤트를 정리하고 최종 목록은 정상 완료 뒤 유지합니다. 모션 줄이기는 이동·회전만 줄이고 모든 카드 정보·읽기·확인 대기를 유지합니다.

### 기존 전투·공용 기분 · 확정(사용자 직접 지시·기존 표현 구현)

유저 공용 userMoodPercent는 0~100이며 N은 선택한 원래 편성입니다. 남은 수비는 ceil(N×userMoodPercent/100)이고 기분 0%에서 0마리입니다. N 5는 20% 구간, N 10은 10% 구간, N 1은 기분이 양수인 동안 1마리가 지킵니다. 이는 구간 규칙이며 판당 비용을 정한 숫자가 아닙니다.

totalCostPercent를 논리 한 판에 한 번 차감하고 바닥 0으로 제한합니다. 몬스 개별로 비용을 나누지 않습니다. 저장된 defenseOrder/exhaustionOrder 순서대로 구간을 넘은 몬스가 이탈합니다. 한 판에 무조건 1마리 이탈하는 규칙은 없습니다. 정식 소모량은 결정 대기이며 훈련 기분 100/비용 10 등은 표시된 시험 입력값입니다.

| 판 시작 | 판정·표현 | 후속 상태 |
| --- | --- | --- |
| 수비 양수·정산 후 기분 양수 | 방패 일부 조각·균열을 표현하고 건물 피해는 없습니다. | 남은 방패를 잠시 유지한 뒤 해제합니다. |
| 수비 양수·정산 후 기분 0% | 실제 유리 방패 전체가 조각으로 분산·낙하합니다. | 그 판은 방어하며 다음 판부터 수비 0·건물 피해입니다. |
| 시작부터 수비 0 | 방패를 만들지 않고 실제 건물 변화 부품 표면에 충격·작은 파편·균열을 표현합니다. | 시설 한 단계만 낮추고 국소 잔재를 남깁니다. |

시설 단계는 3구성×10단계 합입니다. 30=[10,10,10], 29=[10,10,9], 28=[10,9,9], 27=[9,9,9] 실제 모델을 사용합니다. 무수비 한 판에 한 단계만 손상되며 수리 전에도 재공격할 수 있습니다. 시설 0단계만 해당 시설 공격 종료입니다. 전체 시설의 거대 붕괴로 대체하지 않습니다.

### 출격·로테이션·대상 파손·기분 표시 · 기존 표현 구현

1. 출격 준비 약 1.1초 동안 사격조가 접근하고 대기조가 양옆·뒤로 갈라집니다. 카메라는 현재 구도에서 선택 사격 구도로 위치·시선·화각을 부드럽게 전환합니다. 고정 구도도 이 일회성 전환을 재생합니다. 출격 중 사격 본편 시간·발사·정산은 모두 0입니다.
2. 출격 후 별도 사격 본편 10초를 재생합니다. 발사 1마리·교대 진입/퇴장 최대 2마리, 전면 총 최대 3마리입니다. 나머지는 뒤·옆에서 대기하고 차례에 접근→사격→퇴장합니다. 사격 신호마다 비용을 차감하지 않습니다.
3. 사격 종료 자세를 대상 파손·기분/탈진 마무리까지 유지합니다. 시작 수비가 있으면 실제 선택 방패를 부분/전체 파손하고, 없으면 실제 건물의 변화 대상 부품 한 단계만 손상합니다. 방패는 약 1.6초, 건물은 약 1.25초 표현 설정이며 CSV에서 조정합니다.
4. 사격·파손 중 게이지와 체크는 시작 값을 유지합니다. 이후 약 0.65초 동안 표시 기분을 줄이고 매 프레임 ceil(N×표시 기분%/100)로 남은 수·체크·동일 ID 몬스 퇴장을 맞춥니다. 원래 N개의 같은 구간과 체크를 끝까지 유지합니다.
5. 모든 표현이 끝난 뒤 논리 한 판을 한 번만 저장/완료 통지합니다. 독립 훈련은 정산된 기분·단계를 보존한 대기로 돌아옵니다. 외부 도착은 한 번의 결과만 보냅니다. 중단·대상 파손 일부 완료만으로는 결과를 확정하지 않습니다.

v08 공격 간격 frontZ 16.5m를 유지합니다. 앞선 13.5m에서 3.0m 뒤로 이동한 변경이며 카메라·방패·대기/교대·flightSeconds·사격 10초를 유지했습니다. 깊이 13.3→16.3m와 발사 원점 수평 거리 약 12.02→14.91m는 이전 정적 산술 자료이며 화면 실측값이 아닙니다.

### 편성·스킬·방패·카메라 · 기존 표현 구현

내 몬스 0~5를 우선하고 희귀 지원 5종, 추가 부족분은 실제 15종 풀의 다른 종으로 중복 없이 최대 10을 채웁니다. 유도·기관총·화염·번개·레이저·운석·파동·쌍나선·초승달·별빛의 서로 다른 10종 템플릿을 실제 공격자 수만큼 사용합니다. 기존 5마리의 각 2초 예시를 10마리 공통 고정 발수로 사용하지 않습니다.

공격 전면 좌우 30도/총 60도·몬스 기준 높이 1~5m를 유지합니다. 의도된 뒤·옆 대기와 후면 진출입은 전면 주체 구도와 구분합니다. 기본은 정면·좌우 쿼터 고정이고, 출격 전환 후 사격 구도를 고정합니다. 자동 옵션에서만 사격 10초의 느린 좌우 1회 왕복을 사용합니다. 과도한 후퇴를 피하고 웹·모바일을 각각 맞춥니다.

수비는 방패 윤곽에 모여 몸에서 빛을 냅니다. 공용 투명 유리 방패는 하나이며 공격 방어 때만 나타납니다. 수비 0이면 방패는 없습니다. 방패 높이는 건물과 비슷하며 전체 폭을 덮을 필요는 없습니다. 영구 유료 스킨은 외형만 바꾸고 기분 비용·방어 성능은 같습니다. 일반·판타지·황금 원형·캡틴 참고형의 기존 실루엣과 상품 수치 결정 대기 상태를 보존합니다.

### 기존 저장·로컬 경제 시험 경로 · 보존

독립 전투는 createDefenseStore의 load/saveProgress/commitRound/resetProgress/saveLineup을 사용합니다. userMoodPercent·selectedDefenseCount·rosterCount·buildingStage·committedRoundIds를 보존하며 개별 기분 레거시를 공용 기분으로 합성하지 않습니다. IndexedDB→localStorage→memory는 훈련 저장 경로입니다.

외부 표현은 __CASTING_BATTLE_ENCOUNTER__의 requestId/roundId·실제 편성·activeRosterCount·기분·명시 비용·시설·시드를 사용합니다. 완료 settlement와 시설 전후를 부모에 한 번 통지하며 표현 코드가 보상을 지급하지 않습니다.

기존 src/simulator/shared/casting-flow.mjs의 requests/bots/ledger/attackerDaily, requestId+arrivalKey 검증, bot별 기분·편성·시설별 builtStage/damageStages를 보존합니다. casting-growth-bridge.mjs는 receiptId를 성장 state.castingRewardReceipts에 기록하고 publish+checkpoint 성공 후 castingBattleRewardApplied ACK를 보냅니다. 신규 presentationOnly 요청은 같은 완료/복귀 경로를 사용하지만 reward.coins/fans와 피해자의 재화 손실을 0으로 둡니다. 기분·시설 피해·원장·ACK 상태는 이어집니다. 기존 실제 money/fans 반영 분기는 레거시 경제 시험으로 보존하며 새 정식 지급 구조를 확정하지 않습니다.

기존 flow_config의 base_arrival_r 100·기분 소모 10, 적중 15R/막힘 7.5R·메가 2%×3·팬 2%는 임시 연결 시험값입니다. 신 9시설×30단계 270행 비용과 cost_group_id는 비어 있어 새 S·R 규모는 결정 대기입니다. 구 S441,750/R662·16R/8.5R은 이전 경제 감사 자료이며 새 지급 기준이 아닙니다.

### 메인 환경·전용 콘텐츠 인계 · 확인한 기존 원본

기존 data/bad_energy/bad_energy_economy_rule.csv의 gauge_max=360, gauge_ticks=3, gain_roll_min=gain_roll_max=1, gain_rumor=15를 읽습니다. 메인은 굴림당 원본 단위 +1을 더하며 배수를 곱하지 않고 raw/360×100%로 표시합니다. 루머는 실제 카드 한 장당 +15이며 기존 tileParts의 가산을 중복 반영하지 않고 굴림 전 값과 실제 카드 수 기준으로 계산합니다. 이 작업은 기존 경제표 수치를 바꾸지 않습니다.

게이지가 360에 도달하면 나쁜 기운 디펜스 전용 툴에 같은 문맥을 넘깁니다. 전용 툴에서 돌아온 실제 api.state.gauge의 절대값만 메인에 반영합니다. 디펜스를 완료하지 않았으면 360을 유지하며 가짜 성공이나 임의 0 초기화를 만들지 않습니다.

새 data/simulator/hub.json의 routes는 building→simulator_module_building, event→simulator_module_events, bad-energy→simulator_module_bad_energy입니다. 쟁탈은 기존 pending/receipt/ACK 대전 경로를 유지합니다. src/simulator/shared/hub-flow.mjs의 공통 저장은 요청·검토 결과·ACK만 다루며 재화를 지급하지 않습니다. ctx.hub는 이 공통 연결을 전용 툴에 제공합니다.

이벤트는 기존 schedule/fan-cheer setting_ref_id를 hub.json의 eventBindings로 참조하여 같은 ID를 contentRef로 넘깁니다. schedule/fan-cheer의 기존 enabled=0·운영 금지 상태를 바꾸지 않고 전용 preview에서 검토하는 인계입니다. 전용 툴 열기·검토 결과 복귀를 정식 이벤트 활성화/실제 보상 지급 완료로 표시하지 않습니다. 건물 성장은 전용 building 툴이며 아이돌 능력 성장 전용 도구와 역할을 구분합니다.

### 임계값·후속 도착·중복 방지 · 최종 구현 계약

메인의 raw 게이지는 기존 표의 최대 360·굴림당 +1·루머 카드 한 장당 +15로 관리합니다. 360 상한에서 제한하며 배수를 수식에 직접 곱하지 않습니다. 한 번의 굴림에서 루머가 여러 장이면 실제 카드 수를 사용합니다. 기존 tileParts가 이미 더한 값을 다시 누적하지 않고 굴림 전 값과 실제 rumorCount 기준으로 한 번 계산합니다. 원본 경제표 수치는 바꾸지 않습니다.

360 임계값과 원래 착지 콘텐츠가 같은 굴림에 발생하면 나쁜 기운 디펜스를 먼저 엽니다. 디펜스 결과를 같은 문맥으로 저장한 뒤 원래 착지 route를 followup으로 이어 쟁탈·건물 성장·이벤트를 누락하지 않습니다. 전용 툴의 실제 api.state.gauge 절대값만 복귀 반영하고 미완료면 360을 유지합니다. 메인에서 가짜 성공/0 초기화를 만들지 않습니다.

공용 hub-flow는 active run을 격리하고 hub: UUID 요청으로 인계합니다. 결과 반영은 지속 상태 state.hubResultReceipts에 기록하여 같은 결과를 새로고침·재수신으로 중복 반영하지 않습니다. 부모가 후속 인계를 접수한 뒤 이전 요청을 ACK하므로 저장/접수가 실패한 후속 콘텐츠를 완료한 것으로 지우지 않습니다. 도착이 발생하면 자동 굴림도 즉시 멈추고 현재 인계/결과 복귀를 우선합니다. hub 저장은 요청·검토 결과·ACK만 다루며 새 재화를 지급하지 않습니다.

메인의 기본 안내는 팀 저장 상태·전용 툴 열기·메인으로 돌아가기입니다. 같은 원본 성장 노드를 공통 성장데이터 접이식으로 이동하고 복사하지 않습니다. 이전 g-board/g-build/g-sim/g-dice의 내부 설정은 현재 화면에서 숨기고 기획 이력으로 보존합니다. 메인 환경 설정에서는 기존 나쁜 기운 raw 0~360 시작값을 검토용으로 입력하며 원본 3눈금과 raw/360 비율을 함께 표시합니다. 상태 저장에 실패하면 시작값 변경을 적용하지 않습니다. 연출과 실제 기능의 확인 범위는 문구 정리와 구분합니다.

### 전용 툴 공통 안내·버튼·줄바꿈 정리 · 최신 직접 지시

기본 화면에는 저장 상태·메인으로 돌아가기·관련 전용 툴 열기만 역할이 분명한 문구로 보여줍니다. 「연결상태·로컬 시뮬」·「최신 연결 다시 읽기」·「오디션 열기」·「캐스팅 연결 시험」 등 이전 개발 시험 버튼, 「없음/잭팟/cap/carry」 자리표시, 「룰렛 설정 연결 확인·실행 대기」처럼 동작을 알기 어려운 내부 안내는 현재 기본 화면에서 숨깁니다. 이전 기능/설명은 기획 이력과 복원 원문에 보존합니다.

공통 데이터 패널의 버튼 크기·간격·줄바꿈·긴 문구 처리를 통일합니다. 관련 툴 열기는 실제 연결 대상을 명확히 표시하고, 구현되지 않은 연결은 준비 상태로 구분합니다. 문구를 예쁘게 고친 것만으로 기능 구현/연결 완료를 주장하지 않습니다. 메인의 상위 강조색과 각 전용 툴의 정보/복귀 역할을 함께 읽을 수 있게 합니다.

### 필요 시스템

콘텐츠 결정·Blender 캠퍼스·시설 선택/카메라·SNS를 유지하고 돈/주사위 3D 수집기·실제 DOM 앵커·팩 공개·요약/상세·완료/취소·시안 데이터 공급을 분리합니다. 기존 전투·정산 모듈을 호출하며 실제 경제 지급은 별도 어댑터의 후속 연결로 둡니다. 기존 훈련 저장·로컬 경제 시험의 모드 경계를 유지합니다.

### 화면·연출 목록

콘텐츠 결정, 상대 SNS 얼굴·닉네임, 9시설 전체 맵, 선택 시설 접근, 출격·10초 전투, 방패 방어·건물 적중 결과, 큰 돈/주사위와 실제 배지 수집, 봉인팩 탭/찢기, 모든 카드 개별 공개/상태/읽기, 최고/전체 요약·상세·확인, 실제 카드 배지 수집, 최종 획득 목록, 메인 복귀입니다. 각 화면은 같은 상대·선택 시설·같은 요청 결과를 사용합니다.

### 남은 결정

돈 지급량·성공/실패 차등, 주사위·카드 지급 조건/수량/등급/확률, SNS 실제 연동, 게릴라 콘텐츠 활성화 조건, 실제 수익·보유함 연동은 결정 대기입니다. 기존 정식 기분 소모·봇 회복/재매칭·도착 수입 중복 정책·피해자 보호/일일 상한/팬/메가/수리비·다음 도착/추가 입장·270행 시설 비용과 보상 규모도 결정 대기입니다.

### 카드 그림·등급의 공용 표 참조

봉인팩·개봉·큰 카드·최고/전체 요약 시안은 버전 v10으로 제작했습니다. 기존 Blender 동전·주사위·카드 소품과 9시설은 유지합니다. 카드의 테마 공용 그림·별 등급은 기존 card/card_theme/resource_master에서 읽고, 모노의 로고·인물·카드 이미지를 복사하지 않습니다.

| 공용 표 | 실제 열·키 | 예시 사용 경계 |
|---|---|---|
| `data/game/card.csv` | `card_id·name_ko·star_grade·ctm_id` | 이름·별 등급은 원표의 현재 등록값이며 정식 경제 발란스 확정이 아닙니다. 개별 `resource_id`는 비어 있습니다. |

| `data/master/resource_master.csv` | `resource_master_data_res_temp_card_card_theme_01_png~05_png` | 실제 경로 `data/res/temp/card/card_theme_01.png~05.png`·`stage=temp`를 참조합니다. |

새 isNew 예시는 실제 보유함 조회 결과가 아닌 시안 입력으로 구분합니다. 보유 정보가 없으면 보유 확인 대기입니다.

### 새 표현 범위와 공용 참조

표를 추가하지 않고 기존 casting_battle_presentation_value의 scope=entry-presentation에 진입 설정을 유지하고 rewardFx의 단계 순서·시간·크기·DOM 배지 수집·팩 공개·요약/상세·확인·참고 source·문구·예시를 갱신합니다. 열쇠 값은 기존처럼 전체 표 이름 casting_battle_presentation_value_ 접두어를 사용합니다. 봇은 casting_battle_bot_profile의 기존 ID와 상태를 유지하고 sns_avatar_url·sns_nickname 필드를 확장했습니다. 마스터의 건물·재화·아이템·카드 정체를 새 콘텐츠 표에 중복 정의하지 않습니다.
