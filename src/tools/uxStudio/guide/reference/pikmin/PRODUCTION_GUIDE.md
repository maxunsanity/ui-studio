# 피크민 샘플 제작·이어받기

제안(검수 대기). 버섯 참가와 꽃봉오리·엽서·개화 흐름의 독립 UI 샘플입니다.

## 먼저 읽을 것
1. 프로젝트 조사서 `../reference/index.html`과 `sources.json`에서 두 원본 영상과 관찰 시점을 확인합니다.
2. `ui-inventory.json`은 관찰한 상태 목록입니다. 미선택/선택 완료를 다른 화면 종류로 중복 집계하지 않습니다.
3. `common-layout-tokens.json`의 390×844 규격과 화면 역할별 장면 높이, 선택 목록 5열, 하단 고정 조작을 확인합니다.
4. 실제 저장 설계는 `../../ui-studio/designs/ux-f83f162e.json`입니다. 현재 revision과 화면 목록을 읽은 후 UI 스튜디오에서 편집합니다.

## 실제 제작 순서
스튜디오에서 프로젝트 선택 → 상세 편집 → 본 UI → 레이어 복제 → 이름·부모·위치·크기 입력 → 신규 이미지 넣기 → 입력·버튼 상태·화면 연결 → 파일에 저장 → 재읽기와 실제 미리보기 확인 순서입니다. 외부에서 설계 JSON을 생성하거나 덮어쓰지 않습니다. 샘플 전용 HTML/JS로 편집 화면을 대체하지 않습니다.

장면은 새로 그린 스틸입니다. 제목·수량·하트·보상·버튼·입력은 편집 가능한 부품으로 분리합니다. 분석 캡처는 조사서에서만 보며 제품 부품으로 잘라 붙이지 않습니다. 새 그림 원본은 `assets/authoring`, 사용 WebP는 `assets`와 자원 목록에 남깁니다.

## 입력과 상태
미선택 GO·다음은 비활성입니다. 자동 선택은 영상에서 관찰한 선택 완료 대표 상태로 이동합니다. 표기 수량은 영상의 예시이며 실제 재고·GPS·소비·보상 계산이 아닙니다. 개별 선택 수의 실시간 합산은 이 샘플에서 구현 여부를 별도로 보고합니다. 검색·정렬·정보 등 목적 화면이 관찰되지 않은 버튼은 공통 안내를 표시합니다. 원본에 없는 결과 화면을 임의로 늘리지 않습니다.

## 반복하지 않을 실수
- 검은색·흰색이 비슷해도 백판의 범위·모서리·앞뒤 순서를 확대해 비교합니다.
- 이미지를 바꾸면 버튼 종류가 이미지로 바뀔 수 있으므로 입력 종류와 사용 가능 상태를 다시 확인합니다.
- 부모가 달라진 레이어는 부모 기준 좌표를 다시 입력합니다. 화면 전체 그룹을 붙이면 원점·390×844 크기를 재확인합니다.
- 제목을 그룹 밖으로 꺼낸 뒤 뒤에 있던 불투명 전체 그룹이 제목을 덮지 않게 합니다. 편집 목록에 존재하는 것과 실제 보이는 것은 다릅니다.
- 상세 본문은 스크롤되며 하단 복귀 조작을 덮지 않아야 합니다.
- 버튼의 둥근 정도는 숫자 반경뿐 아니라 백판 모양도 확인합니다.
- 저장된 화면과 편집 중 상태를 구분합니다. 이미지 업로드 완료 후 실제 그림이 표시되는지 확인하고 저장합니다.
- 전용 선택창이 다른 앱으로 열릴 수 있습니다. Codex 앱 제어가 차단되었다는 사실을 스튜디오 전체 제작 불가로 확대하지 않습니다.
- 영상의 OS 경고·재생바·편집 자막은 게임 UI가 아닙니다.
- 원본 캐릭터의 3D 장식·실제 장소 지도와 새로 그린 간략 아이콘·가상 지도는 차이가 있습니다. 동일 원화 완성으로 보고하지 않습니다.

## 검수

실행 경로는 조사서의 ‘연결 미리보기’ 또는 상세 편집의 ‘미리보기’입니다. 전체 캔버스의 정적 저장 샘플 보기와 실제 연결 실행을 구분합니다. 브라우저 폭은 설정 요청값만 적지 말고 실제 문서의 표시 폭을 확인해서 기록합니다.
원본 시점 → 실제 저장 화면 → 미리보기 클릭 → 뒤로/취소 → 스크롤·비활성·눌림 → 390/430 크기·이미지 누락·넘침 → 조사서 진입을 확인합니다. 이번에 수행한 항목만 보고하며 과거 다른 샘플의 시험 수를 합산하지 않습니다. 최신 검수 기록은 `../../../../docs/collaboration/reports/20261120_pikmin_sample.md`를 확인합니다.

## 기기 변경과 조사서 연결

초기 `prepare.py`를 그대로 재실행하지 않습니다. 당시의 자원 목록·공통 규격을 다시 쓰므로 이후 보완한 목록을 잃을 수 있습니다. `publish.py`는 문서 뷰어용이며 현재 저장 revision·화면 수·연결 수와 문구를 대조해서 갱신합니다. native 설계를 외부에서 쓰는 용도로 사용하지 않습니다.
미리보기에서 기기를 바꾸면 시작 화면으로 돌아갑니다. 해당 경로를 다시 진입한 뒤 캡처합니다. 430×932 기기는 설계 폭390을 유지하여 논리390×845로 표시됩니다. 기기 목표 크기와 실제 미리보기의 확대·축소 크기를 혼동하지 않습니다. 스크롤·배율 전환 직후 수치에는 이전 상태가 남을 수 있으므로 새 화면을 다시 읽고 확인합니다.

이 환경의 브라우저 캡처에는1.25배 좌표 차이가 있었습니다. 잘못 잘린 첫 캡처를 증거로 사용하지 않고 실제 화면 전체가 포함된 것을 확인했습니다. 화면 원본을 편집해 제품 그림으로 사용하지 않습니다.

조사서는 프로젝트 폴더 메뉴의 현재 피크민 항목에서 열립니다. `src/tools/uxStudio/project-research.json`에는 피크민 경로와 조사서 링크만 추가했으며 기존 항목은 유지했습니다. 조사서·가이드 HTML은 문서 뷰어이며 샘플 실행기를 대체하지 않습니다. 실제 UI는 native 설계이고 조사서의 저장 화면 링크가 해당 화면을 엽니다.

초기 r49를 프로토타입 기준판으로 보존했고, 꽃잎 수량 옆 추가 버튼·4색 필터를 이후 revision에서 보완했습니다. 최신 revision은 실제 저장본과 보고서에서 확인합니다. 이후 수정은 실제 도구에서 새 저장 revision으로 남기고 기준판을 덮어쓰지 않습니다. 개별 셀 클릭은 현재 공통 안내이며, 자동 선택으로 대표 완료 상태를 확인합니다. 실제 선택 수 합산이 필요한 후속 작업에서는 이 범위를 먼저 분리해서 설계해야 합니다.
