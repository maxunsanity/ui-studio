## 3-1. 폴더 등록 전에 assets부터 만들지 않기

이번 본체 작업에서 확인한 순서상 교훈입니다. 미등록 폴더에 `ui-studio/assets`부터 만들면, `project.json` 메타가 없는 기존 `ui-studio` 폴더로 판단되어 폴더 등록이 거절될 수 있습니다. 자원 폴더가 있다는 사실만으로 유효한 프로젝트가 등록된 것이 아닙니다.

정상 순서는 **대상 상위 폴더 선택 → 도구가 프로젝트 메타 생성 → independent 선택 → workspace/project 확인 → 자원 준비·등록 → 실제 조립·저장**입니다. `project.json`이나 registry를 외부에서 만들어 등록을 우회하지 않습니다. 이미 준비한 자원/원본은 보존하고, 거절 시 본체가 확인한 정상 폴더 등록 절차로 정리합니다. 이번에는 본체가 이 순서로 폴더 등록·independent 선택·설계 이름 저장 사실을 전달했습니다. 이 초안 작성자가 같은 UI 절차를 재실행했다는 뜻은 아닙니다.

## 5. 공통 하단5메뉴 — 78×66 제작 규격

이번 샘플은 **각 입력 슬롯78×66 논리px**의 같은 규격5개를 사용합니다. 78×5=390의 제작 기준폭이며, 원본의 실제 선택탭 폭이나 다른 게임 공통 상수로 주장하지 않습니다. B 원본에는 선택 탭이 넓어지는 시각 상태도 관찰됩니다. 이번 동일 슬롯 규격은 제작 규격으로 구분합니다.

| 메뉴 순서 | 슬롯 x | W×H | 구분 |
|---|---:|---|---|
| 상점 | 0 | 78×66 | 고정 입력 부모 |
| 카드/컬렉션 | 78 | 78×66 | 고정 입력 부모 |
| 전투 | 156 | 78×66 | 고정 입력 부모 |
| 소셜 | 234 | 78×66 | 고정 입력 부모 |
| 검·월계관 | 312 | 78×66 | 원본 라벨/목적지 미관찰 유지 |

하단 메뉴 부모는 아래쪽 기준으로 고정하고, 중앙 본문과 형제로 둡니다. 화면 논리 높이·안전 영역·기기별 비례 정책은 본체가 실제 선택한 화면 정본을 확인한 뒤 설정합니다. 메뉴 x/W/H 표를 원본 source px로 오해하지 않습니다. 각 슬롯 안의 그림 비율·라벨·선택 배경·배지는 따로 정렬합니다.

제안 계층:

```text
HUD_BottomNav
  Btn_Nav_<Role>            입력 wrapper / 78×66
    Img_Nav_<Role>          그림 또는 atlas 영역 / parent 입력
    Group_Nav_Content       필요한 경우 / parent 입력
      Txt_Nav_<Role>        native 텍스트 / parent 입력
    Badge_Nav_<Role>         알림 표시 / 입력경로는 역할에 맞춤
```

다섯 메뉴가 보인다고 다섯 목적지가 구현된 것은 아닙니다. 미관찰 검·월계관 목적지, 표시만 있는 입력, 미조립 목적지는 연결 확정로 세지 않습니다. 화면 분류·stable ID·현재 부모를 지키며 이름 변경 때문에 재발급하지 않습니다.

## 6. native 텍스트·atlas 영역·프레임을 분리하기

- 이름·레벨·수량·가격·진행·타이머·평균·배지·설명은 별도 **native 텍스트**로 둡니다. 그림 안에 숫자/문구를 굽지 않습니다. 폰트는 원본 엔진 설정 미확인 상태이며, 우리 제작값을 선택·검수한 뒤 기록합니다.
- 카드 기본 유닛은 입력 wrapper / 프레임 / 원화 / 비용 배지 / 레벨 / 수량·진행 / NEW를 역할별로 나눕니다. 카드 원화 비율과 입력 사각형을 같은 것으로 처리하지 않습니다.
- production atlas를 사용하는 경우 원본 파일을 보존하고, 각 부품에서 **이미지 영역(source region)의 x/y/W/H**를 지정합니다. atlas 좌표·원본 W/H·assetRef·SHA·버전을 manifest에 기록하고 native UI에서 실제 적용 영역을 확인합니다.
- atlas의 전체 이미지를 각 부품의 그림처럼 축소하거나, source 영역 값과 화면 논리rect를 바꾸어 적지 않습니다. 투명 여백/실제 알파 실루엣/아트 box/입력 wrapper를 구분하고 contain 비율을 확인합니다.
- 정상/눌림 그림이 같은 상태군이면 캔버스·피벗·가로 중심·밑면·텍스트 기준선을 공유합니다. 상태별로 따로 타이트 crop해 재중앙정렬하지 않습니다.
- atlas와 영역을 준비한 것, workspace 자원 등록, 실제 부품 참조, 저장/재열기, 실화면 표시 확인을 각각 나눠 기록합니다. 이 초안에서는 atlas 제작/등록을 수행하지 않았습니다.

### 불투명 전체배경 JPEG 예외와 150×150 영역

새로 제작한 **full background 전체배경**이 본래 완전 불투명하고 투명 합성이 필요 없는 경우에만 경량 production JPEG를 사용할 수 있습니다. 원본 PNG 마스터·이전판·변환 근거와 SHA를 보존합니다. 이 예외는 원본 영상 캡처 전체를 production 배경으로 붙일 권한이 아니며, 개별 UI를 분리하는 원칙도 유지합니다.

투명 아이콘·카드/인물 cutout·버튼 상태·배지·프레임 등 **alpha가 필요한 부품에는 불투명 JPEG 예외를 적용하지 않습니다**. 알파가 필요한 아이콘을 흰/검정 배경 JPEG로 대체하지 않고 투명 자원을 사용합니다. 외곽에 구워진 사각형·프린지와 엔진 외부 그림자도 확인합니다.

이번 본체의 **Ctrl 단순 캐릭터 시트는 sourceRegion150×150 source px**를 각 그림에 사용하는 기준으로 전달받았습니다. 이150×150은 atlas 안 source 영역이며 화면의 논리 W/H가 아닙니다. native 이미지 영역으로 지정하고 인접 셀·투명 여백·테두리 혼입을 확인합니다. 이 초안 작성자는 실제 시트/자원을 열어 검수한 것은 아닙니다.

컨트롤의 비용/수량/레벨/진행·숫자는 해당 그림 영역에 포함시켜 굽지 않고 별도 native 텍스트로 분리합니다. 자원의 작은 숫자 자국을 잘라 다시 숫자 자원으로 사용하지 않습니다.

## 7. 3/9슬라이스·입체 상태·엔진 그림자

가변 직사각 판과 버튼은 원본에서 관찰한 모서리 역할을 기준으로 3/9슬라이스 후보를 정합니다. ‘원본도 Unity 9slice다’라고 확정하지 않습니다. source slice·화면 고정 edge·content padding은 서로 다른 값이며 새 자원의 실제 W/H를 확인한 후 입력합니다. 중앙 구간이 0 또는 음수가 되는 분할을 피하고 폭/높이 변경 뒤 모서리·테두리·내용 여백을 확인합니다.

캐릭터·카드 초상·장면·특이한 입체 원근을 가진 버튼을 통째로 9슬라이스하거나 한 축만 늘리지 않습니다. 입체 버튼은 같은 기준면/카메라/소실점/밑면의 정상·눌림 별도 그림을 만들고, 작은 눌림의 이동량은 이번 그림과 실제 상태에 맞춘 제작값으로 정합니다. 기존 모노폴리 GO 예제의2px/1.5px를 전역 상수로 복사하지 않습니다.

외부 투영 그림자는 **엔진 shadow**로 분리합니다. 원화의 측면·베벨·접촉 명암은 원화 재질이므로 지우지 않습니다. PNG에 구운 외부 그림자와 엔진 shadow를 겹치거나 부모/그림 자식에 같은 그림자를 두 번 적용하지 않습니다. 부모 입력 wrapper와 그림/콘텐츠 이동 대상을 따로 확인합니다. 눌린 면이 상태 그림에 이미 그려져 있으면 같은 그림을 다시 내려 이중 변형하지 않습니다.

그림자 ON/색/불투명도/x/y/blur, 상태 그림과 콘텐츠 이동값은 모두 우리 제작 설정입니다. 실제 원본 눌림 프레임/그림자 수치가 없으면 원본과 같은 설정이라고 하지 않습니다.

## 8. 입력 parent와 샘플 연결 경계

자체 동작 버튼이 입력의 주체입니다. 그 안 그림/텍스트를 눌러도 같은 버튼이 작동해야 한다면 자식을 ‘부모에 전달’로 두고 **그림→중간 그룹→버튼의 모든 단계**를 확인합니다. 중간 그룹이 표시 전용/입력 차단이면 경로가 끊길 수 있습니다. 배경·장면 장식은 표시 전용으로 분리합니다.

**실제 입력 owner가 없는 decorative image는 `none`(표시 전용)**으로 둡니다. 입력 주체가 없는 장식 그림에 근거 없이 parent를 지정하거나 보이지 않는 버튼을 새로 만들어 주지 않습니다. 반대로 실제 버튼 안의 그림/텍스트는 owner까지의 중간 그룹을 포함한 parent 경로를 유지합니다. decorative none과 버튼 자식의 parent는 서로 다른 역할입니다.

마우스와 키보드 Enter/Space를 각각 실제로 누르고 정상→hover/초점→pressed→해제복원을 확인합니다. 화면 캡처나 AX 호출이 성공했다는 사실만으로 실제 눌림·연결 성공이라고 기록하지 않습니다. 지원하는 tint/상태 이미지 기능과 실제 게임 동작은 구분합니다.

이것은 **페이지별 단독 편집 샘플**입니다. 모달/시트라는 이유만으로 뒤에 홈이나 다른 페이지를 삽입하거나 합성하지 않습니다. 원본의 배후딤은 관찰 자료이며, 기본 저장 샘플에서 자동 배후 페이지를 붙여야 하는 요구로 확대하지 않습니다.

저장 샘플 확인을 위해 임시 게임 입구·임시 화면·새 edge·장착·구매·보상 기능을 만들지 않습니다. 실제 모달 열기/배후 차단/복귀를 확인할 필요가 명시된 경우만 별도 동작 시험으로 분리하고, 기본 단독 샘플·원본 저장 설계와 시험 fixture를 구분합니다. 미관찰 버튼/닫기/타이머/스와이프는 구현 사실로 바꾸지 않습니다.
