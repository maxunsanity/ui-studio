## 확인 범위와 현재 상태

기초 문서는 같은 폴더의 [current-guide-draft.md](current-guide-draft.md)입니다. 본체가 보고한 정상 UI 입력·복사 실험, 이번 원본 프레임 재대조, 현재 레시피 v007의 정적 검증을 함께 정리했습니다.

- 본체의 중간 전달에는 저장 12보드·r25 기록이 있습니다. 이는 당시 상태이며 이 문서는 현재 모델을 열거나 최종 보드 수를 직접 집계하지 않았습니다.
- 대표 계획은 로비 포함 20보드(페이지11·팝업9)입니다. 계획 수·recipe 행동 수를 실제 완성·저장·재열기 통과 수로 바꾸어 쓰지 않습니다.
- 최종 저장, 재열기, 실제 클릭·스크롤, 1440 데스크톱·430 모바일 표시 결과와 사용자 승인은 본체확인대기입니다.
- 이 부록 작성자는 브라우저·편집기·모델·공용 STATUS를 조작하지 않았습니다. 원본과 준비 자산을 읽고 작업 폴더의 문서·승인받은 레시피 새 판만 작성했습니다.

## 3. 같은 역할의 규격·이름·앵커

기준 좌표는420×924입니다. 레시피의 자식 rect도 stage ABS입니다. 정상 UI가 부모 안의 local 좌표를 받으면 부모의 ABS 원점을 빼서 입력하고, 다시 합친 위치가 레시피 ABS와 맞는지 확인합니다.

### 공통 이름과 부모

- 표시 프레임: Panel_가족_역할 또는 Frame_가족_역할.
- 입력 root: Btn_가족_역할.
- 별도 그림: Img_가족_역할.
- native 글자: Txt_가족_역할.
- 버튼 root와 caption은 같은 가족 접두어를 사용하고 caption은 해당 버튼의 자식으로 둡니다.
- 가격·수량·시간·종류·이름을 원화에 굽지 않습니다. 공백을 여러 개 넣은 한 문자열로 다른 메뉴나 자원 값을 정렬하지 않습니다.
- 재사용 후 원래 가족 이름과 ‘복사’ 접미어를 남기지 않습니다. 화면 전체·다른 역할을 같은 규격으로 억지 통합하지 않습니다.

### 전역5칸 내비게이션 기준

본체가 지정한 전역 공통 기준입니다. 원본 엔진 설정을 역추정한 값으로 표현하지 않습니다.

|부품|규격|420×924 기준|
|---|---|---|
|Footer root|420×82|ABS(0,842,420,82), 화면 하단|
|전역 cell5개|각84×82|x0/84/168/252/336|
|각 glyph|60×60|cell 안에서 가로 중앙|
|각 native text|80×20|cell 안에서 가로 중앙, glyph 아래|
|이름·입력|각 cell 별도|버튼이 입력 주체, 표시 자식은 지정된 부모와 연결|

전역 cell 안의 예시 local 배치는 glyph(12,0,60,60), text(2,60,80,20)입니다. 실제 source 메뉴가 없는 칸에 새 기능이나 목적지를 만들지 않습니다.

상점 원본은 Back과4개 목적지입니다. 이를 전역5개 기능과 혼동하지 않습니다.

### 앵커와 긴 목록

Footer는 하단 기준, 고정 높이82를 먼저 맞추고 자식의 부모·local rect를 확인합니다. 화면 확대율과 저장 좌표를 혼동하지 않습니다. 다른 크기 미리보기에서의 실제 표시·safe-area 적용은 본체가 확인합니다.

Pilot List는 ListViewport ABS(0,280,420,520)를 투명 frame으로 두고 ‘영역 넘침 → 세로 스크롤’을 사용합니다. enum은 scroll-y입니다. Pilot1..9는 이 부모 아래에 두며 기존 ABS 위치·113×176 카드 크기를 유지합니다. 그림·레벨은 각 카드 자식입니다. 뷰포트 끝 y800에서 세 번째 행을 잘라 CollectionTabs·하단 메뉴와 겹치지 않게 하고, 정상 스크롤로 나머지를 볼 수 있게 합니다. 실제 스크롤·고정 탭 동작은 아직 검수 대기입니다.

표시 글자가 버튼 밖으로 나가지 않게 합니다. Chapter의 Normal/Elite는64×58 입력 영역에 해당 caption을 포함하고, Top/Local 탭·Filter·Advance의 글자도 각 버튼의 자식으로 둡니다.

## 4. 기본 버튼 상태와 투명 입력 영역

현행 코드의 상태 종류는 기본(normal), 가리킴·키보드 초점(hover), 눌림(pressed), 선택(selected), 비활성(disabled)입니다. 같은 역할은 같은 기준 버튼을 재사용하고 상태 효과 대상과 입력 root를 확인합니다. 이 문서는 해당 상태가 샘플 전체에 이미 설정·검수됐다는 뜻이 아닙니다.

- 기본 그림·프레임과 native caption을 분리합니다.
- 일반 CTA, 선택 탭, 닫기용 투명 hit area는 서로 다른 역할입니다.
- 눌림 그림이나 상태 tint를 지정하면 실제로 상태가 작동하는 화면에서 기본/눌림/비활성을 각각 확인합니다.
- 선택 상태는 관찰된 선택 탭에만 사용합니다. 버튼이 보인다는 이유만으로 selectable 정책을 추가하지 않습니다.
- 잔액으로 disable할 조건을 창작하지 않습니다. B의 부족 티켓은 알림창이 관찰된 것이며, 특정 disable 정책이 입증된 것은 아닙니다.
- no-skin은 자동으로 투명하다는 뜻으로 다루지 않습니다. 닫기용/배경용 입력만 남길 때에는 정상 UI에서 fill alpha0, 보이는 테두리0, 불필요한 shadow 없음과 skin 없음 모두 확인합니다.
- 투명 입력 root와 실제 caption을 별도 요소로 둡니다. 투명 root가 그림을 덮는 불필요한 색 면으로 보이지 않는지 확인합니다.
- 배경·프레임·glyph·문구가 독립 action을 갖거나 클릭을 가로채지 않게 입력 소유 관계를 확인합니다.

소스 근거: button-state.mjs의 BUTTON_STATES/createButtonState/validateButtonStates. 해당 코드는 읽었으며 변경하지 않았습니다.

## 5. 정상 UI 글자 입력과 복사 재사용

기초 초안의 입력 실험은 본체가 샘플 이름창에서 확인한 제한된 결과입니다. locator.fill과 clipboard Meta+V가 DOM value만 바꾼 사례가 있었고, 실제 layer 이름을 갱신하려면 정상 키 입력 후 Tab으로 편집을 마치는 방식이 검증됐습니다. 이를 모든 입력창의 제품 버그로 일반화하지 않습니다.

1. 대상 입력창을 정상 UI에서 포커스합니다.
2. Meta+A 후 검증된 ASCII 문자열은 각 문자를 순서대로 press하고 Tab으로 마칩니다.
3. Space/Enter/plus는 지원되는 실제 키로 처리합니다. plus 표기를 추정해 공통 규칙으로 만들지 않습니다.
4. Unicode 구간만 도구가 지원하는 순차 입력을 사용합니다. 섞인 문자열은 실제 표시와 모델 반영 여부를 확인합니다.
5. 실험값을 넣었다면 원래 값으로 복원하고 정상 UI에서 복원 결과를 확인합니다.

DOM.value/defaultValue 강제 대입, 모델 객체 변경, 저장 JSON·iframe 메시지 주입으로 편집하지 않습니다.

복사는 표시 프레임1part 또는 root+caption2part처럼 같은 역할의 기준만 선택합니다. 복사 payload에 button state·skin·나가는 행동이 포함될 수 있으므로 연결 없는 기준을 사용합니다. 붙여넣기는 새 UUID를 만들고 ‘복사’ 이름과 기본 +2%포인트 위치 offset을 적용할 수 있으며, 외부 부모와 원래 앵커 조건은 그대로 보장되지 않습니다.

붙여넣기 후 root ABS, caption local rect, 두 요소 이름, 새 부모/ID, slice·padding, 상태, 입력, 나가는 행동을 다시 확인합니다. 자식 ID를 예전 root-ui-label 규칙으로 조합하지 말고 실제 새 layer/ID를 읽어 선택합니다. 이후 정상 UI 저장과 재열기 결과를 본체가 기록합니다.

## 6. 비동기 그림 선택과 crop의 순서

본체가 전달한 이번 조립 교훈입니다. 이미지 드롭다운 선택이 화면의 source 교체보다 먼저 끝나면, 새 region을 이전 그림에 적용하는 경쟁 상태가 생길 수 있습니다. 단순히 x+y가 원본 bounds 안이라는 검사만으로는 ‘올바른 그림에 crop했다’는 것을 보장하지 못합니다.

정상 UI 절차는 다음 순서를 지킵니다.

1. 기대한 정확한 asset path/src와 source 크기·셀 정보를 정합니다.
2. 정상 이미지 선택 UI에서 해당 자산을 선택합니다.
3. 선택창의 값뿐 아니라 실제 미리보기/선택 속성의 src가 기대한 source로 바뀌고 source 크기도 맞을 때까지 확인합니다.
4. 이 조건을 확인한 뒤에만 해당 source용 region을 정상 UI로 입력합니다.
5. 최종 src·region·그림 미리보기와 캔버스 표시를 다시 확인합니다.
6. 도중에 source가 다르거나 갱신 중이면 crop 입력을 멈추고 source 확인 단계로 돌아갑니다.

같은200×200 crop은 파일이 잘못돼도 bounds 검사에 통과할 수 있습니다. 서로 다른 두600px 아틀라스 사이에서 특히 source 정체성을 먼저 확인해야 합니다.

|자산|실제 원본 크기|cell 규격|
|---|---|---|
|공통 자원 glyph atlas|256×192|64×64·4×3|
|새 파일럿 초상 atlas|600×600|200×200·3×3|
|새 상점 품목 atlas|600×400|200×200·3×2|

상점 atlas는 무료 묶음(0,0), 붉은 병(200,0), 파란 티켓(400,0), 금색 상자(0,200), 붉은 조종사 티켓(200,200), 크림·파랑 기체(400,200)이며 각 region의 w/h는200입니다. Tempus의 Item6은 원본A86에서 붉은 병으로 확인되어 (200,0,200,200)입니다. 이 원본 정정을 티켓으로 되돌리지 않습니다.
