# 짓기 화면 실툴 조립 최소 경로

2026-11-16 · codex(단이) · 제안(검수 대기). **현재 소스 확인만 수행했습니다. UI·제품 소스·설계 JSON 변경과 브라우저 검수는 하지 않았습니다.**

## 먼저 지킬 조건

- 복사 전 메인과 대상의 **기기 → 설계 기준551×984**를 사용합니다. phone390의 logical viewport는551×1192.42이므로 그 상태에서 복사하면 root의 % 정규화 높이가 달라집니다. 기기·확대는 보기이며 원본 logicalSize를 기기390×844로 바꾸지 않습니다.
- 선택한 부모를 **편집 → 복사**하면 모든 후손과 출발 행동 연결이 함께 복사됩니다. 선택 root는 기존 부모에서 분리되고 rectTransform/inset/useSafeArea가 해제되어 현재 viewport의 %로 정규화됩니다. 자식의 상대 배치·이미지 참조·속성은 유지됩니다. **붙여넣기/복제는 새 root의 X/Y에 각각+2%**를 더합니다. 새 ID/자식 parentId/buttonState.targetGraphic은 치환됩니다. 다른 형제·선택 root 밖 선조는 포함하지 않습니다. (commands.mjs:11,28 / layers.mjs:22)

## 새 Build 화면과 배경

1. 왼쪽 **프로젝트 → 화면 → ＋ 게임 화면 추가 → 화면 이름 → 추가**. 표시 이름은 Build로 정하고 생성된 screen ID는 그대로 사용합니다.
2. **속성 → 배치 → 응답형 배치 · 안전 영역 → 현재 화면 논리 크기 → 논리 너비 px551 / 논리 높이 px984**를 확인합니다. 이번 결함 보완 후 v4 새 화면은 선택한 page의 **저장된 logicalSize**를 상속합니다. 모달 선택 중 생성하면 entry page를 기준으로 하며 기기390×844/재flow1192는 상속하지 않습니다. v1~3는 기존 형식을 유지합니다. 보완 전에 만들어진 logicalSize 없는 메모리 화면은 소급 수정하지 않으므로 Undo 후 다시 만들거나 이 필드로 크기를 지정합니다. 메인551×984는 바꾸지 않습니다. (main.mjs:1525 / responsive-inspector.mjs:63)
3. 메인 레이어에서 **Slot_3D 부모를 정확히 선택 → 편집 → 복사 → 왼쪽 화면 Build → 편집 → 붙여넣기**. 자식 배경까지 들어오는 범위입니다. 배경 부모는 가이드에서 화면 기준[0,0,551,984]로 맞추거나 기존 % 배치 X0/Y0/W100/H100으로 재설정하고 **편집 → 맨 뒤로**. 복사된 offset/앵커 해제를 그대로 두지 않습니다.
4. 배경의 실제 이미지 자식을 선택해 **이미지 내용 → 프로젝트 이미지 경로** 또는 **실제 이미지 넣기**, **이미지 맞춤 → 가득 채우기 · 잘림**(cover)을 선택합니다. 기존 글자나 다른 UI 이미지는 교체하지 않습니다.
5. 새 page는 다른 page HUD/글로벌 common layer를 자동 합성하지 않습니다. 공통 스타일·유닛 자원은 공유하지만 화면 요소 목록은 각 page별입니다. 모달 편집의 배경 page 노출과 구분합니다. **Slot_3D가 content-slot/world binding을 갖고 있다면 복사에도 남고, 외부 host가 같은 슬롯을 공급할 때 슬롯 콘텐츠가 붙을 수 있습니다.** 실제 현재 Slot_3D의 binding 유무는 이 조사에서 확인하지 않았습니다. 일반 도시 배경이라면 필요 시 '유닛 추가 → 이미지 + 프레임'처럼 독립 부품을 쓰는 편이 슬롯 의미 혼동을 피합니다.

## Build 상단과 동일 카드5개

1. 메인 **TopbarGroup 부모 → 편집 → 복사 → Build → 편집 → 붙여넣기**. 원본은 보존하고 사본의 **요소 이름**을 Build용으로 바꿉니다. 필요한 SNS 자식만 골라 **요소와 하위 요소 삭제**합니다. 삭제할 부모의 후손 범위를 먼저 확인합니다.
2. 상단 사본은 정확한 원본 치수/위치로 다시 맞춘 뒤 **응답형 배치 · 안전 영역 → 앵커 → 왼쪽 위 고정**. 이 옵션은 현재 보이는 사각형을 보존해 고정 앵커로 변환하므로 **수치 먼저, 앵커 나중**입니다. card 부모 안 자식은 필요한 경우 **레이어 위치 · 크기 / 부모 레이어**로 같은 부모에 넣습니다.
3. 새로 만들면 **유닛 추가 → 복합 유닛 → 이미지 + 프레임 버튼**으로 부모/바탕/이미지/텍스트/프레임5개가 생성됩니다. 기존 navbutton을 재사용해도 먼저1개를 Build 카드 원본 규격으로 완성한 뒤 **편집 → 복제**4회가 최소 경로입니다. 단순 '콘텐츠 카드'는 같은 복합 분해 구조가 아닙니다.
4. navbutton 사본에는 원래 nav의 **행동 연결·알림 config/valueKey·배지 후손·버튼 효과**가 남습니다. **연결·조건 → 연결 삭제**로 원래 nav 행동을 정리하고 불필요한 배지 후손을 골라 삭제합니다. 새 랜드마크 행동/수치가 확정되지 않았다면 구매/발란스를 임의로 넣지 않습니다. 실제 이미지 자식과 텍스트 자식을 각각 교체합니다.
5. 5개 부모의 W/H를 같은 논리 px로 지정하고 자식 이미지/라벨 규격을 동일하게 맞춥니다. 복제 사본은 최상위로 붙으므로 동일 부모가 필요하면 **부모 레이어**를 각각 지정합니다. 상대 % 값만 같아도 부모 크기가 다르면 실제 크기가 달라집니다. 기존 수동 배치에서 같은 간격을 쓰려면 같은 부모로 맞추고 그룹/정렬을 적용합니다. 새 원본 카드 수치는 제공된 원본 관찰 명세를 사용하며 여기서 새 숫자를 정하지 않았습니다.

## 진입·Back·저장

- 메인 짓기 버튼: **속성 → 연결·조건**에서 기존 행동을 편집하거나 **행동 · 연결 추가**. **실행 조건 → 항상**, **무엇을 하나요? → 화면 이동**, **대상 UI → Build**. 새 행동의 초기 조건은 **미정**이라 반드시 '항상' 등 확인된 조건으로 바꿔야 실행됩니다. 기존 행동이 앞에 있으면 처음 참인 하나만 실행되므로 중복을 정리합니다. (main.mjs:431,1509 / model.mjs:271)
- Build 뒤로/닫기 버튼: **무엇을 하나요? → 이전 화면**, **대상 UI → 대상 없음**. '화면 이동 → 메인'은 새 history를 쌓으므로 Back과 다릅니다. Build를 편집한 상태의 '동작 시험'은 Build에서 시작해 history가 비어 있을 수 있습니다. **메인 선택 → 동작 시험 → 짓기 진입 → 뒤로** 순서로 확인합니다. (main.mjs:1457 / model.mjs:296)
- entryScreen은 기존 메인을 유지합니다. 상세 편집에는 entry 변경 폼이 없고, 전체 캔버스에는 **화면 설정 · 설명 → 시작 화면**이 있습니다. 이번 조립에서 entry를 바꿀 필요는 없습니다.
- **파일에 저장 → 저장 UI 함께 보기 ↗**로 실제 consumer를 확인합니다. 새 Build의551×984와 메인의 원본551×984, 부모/자식 수, 이미지404,5카드 동일 치수, 새 진입/Back을 확인합니다.

## 스크롤 복원: 소스 관찰과 미확인

- model.navigate/back은 page/selection/filter/focusReturn을 history에 저장·복원하며 runtime.scroll 자체를 지우지 않습니다. **상세 편집 동작 시험**에는 .kind-list의 scrollTop을 collectScroll로 수집하고 renderPreview에서 복원하는 코드가 있습니다. 일반 panel overflow 스크롤까지 수집하는 코드는 아닙니다. (main.mjs:689,852,878 / model.mjs:297)
- **standalone consumer**에는 scroll 수집 listener·navigate/Back 후 scrollTop 복원 코드가 없습니다. 페이지 전환에서 이전 요소 DOM이 제거되므로 상세 편집과 같은 복원 지원을 보장할 수 없습니다. 실행 DOM의 실제 Back/스크롤 복귀는 이번 하위 조사에서 검수하지 않았습니다. UI의 '닫기 후 복귀' 텍스트는 그 자체로 새 스크롤 동작을 구현하지 않습니다.
