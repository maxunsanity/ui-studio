## 가장 적은 자원으로 묶는 조립 순서

1. r63 footer에서 뒤로74×64, CTA336×64(3slice), 글자26/800/32를 각각 복제해 native 유닛으로 재사용합니다. 분할 행동/탭은 200×64로 통일하는 제안입니다. 스킨/글자/아이콘은 wrapper의 자식이고 클릭은 매 단계 parent로 전달합니다.
2. TS19/20의 사건 헤더를 먼저 한 번 조립해 두 화면에서 재사용합니다. TS19 하단 후보 카드와 TS20 스킬카드는 같은 영웅 원화+새 wrapper 크기만 사용합니다.
3. TS24 결과카드 143×453을 하나 만들고 영웅/조각 상태를 같은 판틀로 처리합니다. TS22 일반·고급도 두 화면 대신 동일 판틀의 관측 상태로 묶습니다.
4. 주민6명 초상을 한 번씩만 준비하면 TS30 6카드, TS28 미아/제이슨 보상, TS31 수잔 프로필이 공유합니다. 인물별 새 전신 그림은 필요 없습니다. 관계pill·도감카드·보상카드의 wrapper를 분리합니다.
5. TS23/26/전투의 3D 인물·전장은 새 래스터로 꾸미지 않습니다. 전체 화면 Slot_3D는 빈 3D 영역 표시, UI는 별도 2D 형제입니다.
6. TS27은 TS03 배후를 유지하는 해제 overlay, TS28도 TS03 배후+관계 보상, TS31은 TS30 배후+프로필로 구성합니다. 관측하지 않은 배경/닫기 목적지를 새로 만들지 않습니다.

공통 신규 그림 최소 역할은 주민 초상6종, 모집 홍보 아트2종, 필요한 독립 아이콘/초상만입니다. 같은 무늬의 패널·막대·pill은 현재 내장/기존 3·9slice를 재사용합니다. 채팅은 같은 기존 지휘관 초상으로 여러 행을 구성할 수 있습니다. 원본 skill3종·모집아이콘·상자·가속/물자 등은 기존 자원이 실제 맞는지 본체가 확인하고 재사용하며, 안 맞으면 그림이 필요한 미완료로 남깁니다. 스크린샷 crop을 정식 U 자원으로 쓰지 않습니다.

## 모든 가족에 적용할 부모/입력/표시

- Page 또는 Modal의 stable ID를 native 툴이 발급합니다. 사람용 이름만 아래 역할표를 따르며 다른 화면/기존 ID를 재발급하지 않습니다.
- 클릭 유닛: Btn_역할(action) → BG_역할(3/9slice,parent), Img_역할(parent), Txt_역할(parent). 중간 Group이 있으면 Group도 parent. 표시만인 그림/값은 none입니다. 한 클릭에서 부모 행동 하나만 실행합니다.
- native control(tabs/toggle/input)은 button 안에 중첩하지 않습니다. tabs는 각 bodyPanel과 선택skin을 연결하되, 관측되지 않은 본문은 지어내지 않습니다.
- 버튼 normal/pressed 그림은 실제 있는 상태만 사용합니다. 가이드에 있는 tint/상태 기능을 쓸 수 있지만 미관측 눌림을 원본 상태라고 부르지 않습니다.
- 3D는 Page → Slot_3D(0,0,504,894), 입력none, 빈 3D 영역. HUD/하단UI는 Slot_3D 자식으로 넣지 않습니다.
- header/footer는 native 고정 앵커, 스크롤은 body viewport만. 복제 최상위는 legacy %로 바뀔 수 있으므로 native 앵커를 재확인합니다.
- 기본 글자: 표제28/800/34, CTA26/800/32, 이름20/700/26, 본문18/600/25, 보조16/600/22, 수치20/700/26. 모두 제작제안이며 원본 font-family 미확인.
- 기기390×844/430×932에서는 전체화면 비례 보기와 고정 앵커를 별도로 확인합니다. 스크롤viewport 밖에는 실제 표시·입력 모두 clip되어야 합니다.
- 정확입력/게임결과가 미관측이면 표시를 보존하고 새 게임 기능을 만들어 채우지 않습니다. 관측된 시퀀스는 fixture 연결 제안이며 실게임 어댑터가 아닙니다.
