# 홈·새 작업 가이드 통합 메모

상태: 후보 / 제품 반영·홈 실화면 검수 미실시. 작성 범위는 이 폴더의 후보 2개뿐입니다. 제품 가이드·샘플 JSON·STATUS·보고·서버·브라우저는 변경하지 않았습니다.

## 반영할 문서

- 이 폴더 `START_PROJECT_GUIDE.md`를 `src/tools/uxStudio/guide/START_PROJECT_GUIDE.md`로 추가합니다. 링크는 제품 가이드 폴더에 놓인 상태를 기준으로 작성했습니다.
- `guide/index.json`의 공통판을 본체 검증 뒤 `2026-11-18.35`로 올리고 아래 항목을 처음 읽기 다음에 추가합니다. 현재 .34의 14문서를 보존하면 총 15문서입니다. 기존 프로젝트 .4 사본·project.json guideVersion은 자동 변경하지 않습니다.

```json

  "id": "start-project",
```

## 본체가 구현과 맞춰 확인할 경계

1. 홈의 최종 입구 문구가 ‘제작하기 / 샘플 보기 / 가이드’와 맞는지 확인합니다. 후보 문서는 실행 버튼과 사본 자동생성 기능이 이미 검증됐다고 주장하지 않습니다.
2. 샘플 분류는 실제 정본 `samples/<game>/` 바로 아래 프로젝트에만 적용합니다. folder-check 시험 fixture와 중첩 등록을 제외하고, 그 밖에 사용자가 선택한 별도 폴더를 내 작업으로 구분합니다. 이름의 sample 문자열·revision 크기·conversionDecision=independent를 분류 조건으로 쓰지 않습니다.
3. Royal Match는 2차 담당의 제작 중 참고 샘플입니다. 현재 제작 중 상태로 보이고 완성·실검수 통과 수치를 붙이지 않아야 합니다. 다른 샘플도 같은 기준으로 실제 저장 상태를 읽습니다. 이 후보 작성자는 샘플 저장 파일을 열거나 수정하지 않았습니다.
4. macOS 폴더 picker는 canCreateDirectories=false입니다. 제작용 상위 폴더는 Finder 등으로 먼저 준비→폴더 열기이며 툴 내 새 폴더 생성을 지원한다고 쓰지 않습니다. 선택 폴더 안의 ui-studio/ 자동생성·가이드 사본은 기존 기능입니다. 후보는 공통 .35가 기존 프로젝트 .4로 자동 전파된다고 쓰지 않습니다. 새 프로젝트 사본 판은 실제 생성 결과를 보고 기록합니다.
5. 홈의 UI 구현·표시·샘플/작업 전환·미저장 안전·경로 격리 검수는 본체가 실제 수행한 범위만 PROGRESS/보고에 추가합니다. 후보에는 .34의 647이나 과거 화면 검수를 새 홈의 통과 수로 가져오지 않았습니다.
6. 기본 경로·canvas.html의 ‘기본은 전체 캔버스’라는 기존 문장은 새 홈이 기본 진입이 되면 낡습니다. USER_GUIDE의 ‘1. 시작과 프로젝트 구분’, UX_WORKFLOW 시작 문장, AI_GUIDE ‘검증과 보고’, README/TOOL_SPEC/ARCHITECTURE/PROGRESS/AGENTS의 현재 입구 설명을 본체 허용 범위에서 짧게 보정하고 과거 검수 기록은 보존합니다.
7. projects API에는 수정시각이 없으므로 ‘최근 수정순’·‘최근 작업’이나 자동 최신/완료판 선택을 안내하지 않습니다. 홈은 기억된 설계가 있으면 그 설계, 없으면 목록 선택 순서이며 실제 project/revision을 확인합니다.
8. 가이드의 MD 상대 링크가 제품 가이드 패널에서 올바른 문서를 여는지, 홈에서 가이드를 열어도 문서/revision을 바꾸지 않는지 확인합니다.
