# 홈 사용법과 새 작업 규칙

이 문서는 새 프로젝트를 시작하거나 다른 AI가 작업을 이어받을 때 읽는 공통 진입점입니다. 최신 사용자 지시와 선택 프로젝트의 지침을 먼저 따릅니다. 자세한 편집 방법은 [전체 캔버스·상세 편집·디자인 가이드](UX_WORKFLOW_GUIDE.md), 기능과 지원 경계는 [사용 설명서](USER_GUIDE.md)와 [진척·미완료](PROGRESS.md)에서 확인합니다.

## 홈에서 고르기

| 입구 | 할 일 |
| --- | --- |
| 제작하기 | 새 작업을 둘 프로젝트 폴더를 선택하거나 기존 내 작업을 다시 엽니다. |
| 샘플 보기 | 참고 샘플의 저장 설계와 제작 상태를 살펴봅니다. |
| 가이드 | 사용법, AI 작업 규칙과 기능별 제작법을 읽습니다. |

**작업과 샘플은 구별합니다.** 내 작업은 사용자가 작업 대상으로 선택한 별도 프로젝트 폴더입니다. 참고 샘플은 UI 스튜디오 정본의 `samples/` 바로 아래에 둔 게임별 폴더입니다. 저장·격리 시험용 `folder-check`나 같은 프로젝트의 중첩 등록은 내 작업·게임 샘플 목록에 넣지 않습니다.

홈에서 기억된 설계를 열거나 목록에서 설계를 선택하더라도 가장 최근 수정판·완료판이 자동 선택됐다고 가정하지 않습니다. 실제 이름과 저장 revision을 확인합니다.

프로젝트 이름, 저장 revision, 작업 방식 `independent`는 작업과 샘플을 가르는 기준이 아닙니다. 서로 이름이 같거나 모두 독립 작업 방식이어도 실제 폴더와 workspace를 확인합니다. 샘플 목록의 ‘제작 중’은 미완료를 뜻합니다. Royal Match도 제작 중인 참고 샘플이며 목록에 있다는 이유로 완성·검수 통과로 읽지 않습니다.

샘플을 바탕으로 내 작업을 만들 때는 **다른 작업 폴더에 사본을 준비한 뒤** 편집합니다. 샘플 원본의 설계·자원을 내 작업처럼 바로 고치지 않습니다. 복사 대상 폴더·새 workspace·설계 ID와 필요한 자원 파일이 분리됐는지 확인합니다. 부품 복사만으로 다른 workspace에 자원 파일까지 전달됐다고 가정하지 않습니다. 원본과 대상이 같거나 사본 준비가 끝나지 않았다면 샘플을 편집하지 말고 먼저 분리합니다.

## 프로젝트 폴더를 열기

1. 작업할 프로젝트 폴더가 없으면 Finder 등으로 먼저 준비한 뒤 폴더 열기에서 선택합니다. 폴더 선택창은 제작용 상위 폴더를 새로 만드는 기능이 아닙니다. 선택 폴더 안에 `ui-studio/` 보관영역이 생성되며 설계·자원·프로젝트 정보·가이드 사본을 둡니다. 기존 `ui-studio/`가 있으면 저장된 내용을 다시 엽니다.
2. 폴더 열기 후 표시된 프로젝트 이름과 실제 경로를 대조합니다. 도구 주소의 `/ui-studio/`와 선택 프로젝트의 `ui-studio/` 폴더는 서로 다른 의미입니다.
3. 폴더를 구분하는 workspace ID와 설계를 구분하는 `document.projectId`, 현재 revision을 확인합니다. 같은 설계 ID가 다른 폴더에 있어도 같은 문서는 아닙니다. 저장·재열기·미리보기에 같은 workspace와 project가 전달되는지 확인합니다.
4. 선택 프로젝트의 상위 지침, `ui-studio/README.md`, `AGENTS.md`, `project.json`, `integration.md`와 `guide/`를 읽습니다. 공통 가이드와 프로젝트 사본의 판 차이를 확인하며 기존 프로젝트의 가이드·`guideVersion`을 자동 덮어쓰지 않습니다. 기존 프로젝트 `.4` 사본도 보존합니다.
5. 미저장 변경이 있으면 저장 후 전환·수정 버리고 전환·취소 중 실제 선택을 따릅니다. 저장 실패나 충돌 때는 현재 문서와 미저장 변경을 보존합니다.

처음 기존 게임 폴더를 열면 **기존 UI 변환·연결 여부를 사용자에게 먼저 확인**합니다. 폴더 열기, 가이드 읽기, 새 설계나 보관영역 생성은 변환 동의가 아닙니다.

- 변환·연결을 선택하면 원본 전체 UI 조사, 백업, 기존/변환 대응표와 실제 회귀 확인을 수행합니다. 선택 기록이 ‘요청’인 것과 변환·연결이 끝난 것은 구분합니다.
- 독립 UI 작업을 선택하면 원래 게임 UI와 게임 소스를 수정하지 않고 선택 프로젝트의 `ui-studio/` 안에서만 작업합니다. 사용자가 바꾸기 전에는 이 선택을 유지합니다.
- 취소하면 현재 작업에 남습니다.

세부 범위와 완료 기준은 [기존 게임 변환·독립 작업](EXISTING_GAME.md)을 따릅니다. 매번 다시 승인받는 절차를 추가하지 말고 이미 기록된 사용자 선택과 현재 요청을 확인합니다.

## AI가 새 작업을 시작하는 순서

1. **도구 사용법부터 파악합니다.** 이 문서와 [편집 흐름](UX_WORKFLOW_GUIDE.md), [AI 작업·수정 규칙](AI_GUIDE.md)을 읽고 작업에 필요한 전문 가이드만 이어 읽습니다. 도구에 없는 기능을 있다고 가정하지 않습니다.
2. **관련 원본을 직접 읽습니다.** 현재 지시, 최신 기획·표·원본 화면/영상, 필요한 코드와 저장 계약을 확인합니다. 관찰한 사실·추정·제작 제안·미확인을 나누고 보이지 않은 수치·입구·기능을 창작하지 않습니다.
3. **대상을 기록합니다.** 프로젝트 이름·경로, workspace ID, 설계 projectId/revision, 대상 화면·부품 ID·부모, 수정 범위와 백업 위치를 남깁니다. 다른 작업자의 설계·자원이나 샘플 원본을 자기 작업으로 바꾸지 않습니다.
4. **같은 구조를 단계별로 제작합니다.** W/P/U의 화면·부품 stable ID, 부모·자식 계층, 배치와 연결을 이어갑니다. 표현을 바꾸려고 설계를 복제하거나 ID를 새로 발급하지 않습니다. 제작 단계 기준판은 따로 보존하고 저장 위치를 확인합니다.
5. **실제 툴에서 조립하고 편집합니다.** 전체 캔버스에서 화면을 고르고 상세 편집의 트리에서 부모·자식을 선택한 뒤 디자인 가이드로 수치·그림·텍스트를 조절합니다. 저장 JSON 주입이나 특정 샘플 전용 화면 코드로 UI 제작을 대신하지 않습니다. 필요한 기능은 다른 프로젝트도 속성으로 쓸 수 있는 공통 툴 기능으로 다룹니다.
6. **저장하고 다시 확인합니다.** 미저장 미리보기, 파일 저장, 재열기, 저장 샘플 보기와 동작 시험의 확인 범위를 나눕니다. 아래 검수 항목과 실제 증거를 기록하고 성공·실패에서 얻은 방법을 공통 가이드에 남깁니다.

### 세 표현과 제작 단계는 구분하기

와이어프레임·세부 와이어프레임·본 UI는 **같은 저장 설계의 보기**입니다. workspace·project·screen을 유지하고 `view`만 바꿉니다. 세부 와이어는 기존 문구·폰트·배치와 실제 그림의 알파 윤곽을 읽으며, 본 UI는 현재 원화·색·효과를 표시합니다. 표현 전환으로 W/P/U 제작 단계가 완료되거나 기준판이 저장되지는 않습니다. 기준판을 저장했다는 사실만으로 완성 판정을 내리지 않습니다.

## 조립할 때 지킬 공통 규격

- 이름은 `Btn`·`Img`·`Txt` 등에 화면/영역/역할이 드러나게 붙입니다. 이름 정리를 위해 stable ID·부모·유효 연결을 재발급하거나 지우지 않습니다.
- 같은 역할은 같은 family/variant의 외곽·아이콘·글자·기준선·입력 규격을 사용합니다. [공통 UI 규격·제작 규칙](COMMON_UI_RULES.md)과 해당 프로젝트 토큰을 읽습니다. 다른 게임의 숫자를 그대로 강제하거나 미정 값을 0으로 채우지 않습니다.
- 프레임·배경·원화·입력 wrapper와 글자·수량·가격을 별도 편집 부품으로 둡니다. 전체 스크린샷 한 장이나 글자가 구워진 이미지로 제작을 대신하지 않습니다.
- 아이콘은 실제 투명 배경과 실루엣에 맞는 crop을 확인합니다. 알파 채널이 있다는 사실만으로 투명 판정을 내리지 않습니다. 상태별 그림은 공통 캔버스·기준점을 유지하므로 각 상태를 따로 잘라 재중앙정렬하지 않습니다.
- 가변 프레임은 기존 3·9슬라이스 계약을 사용하고 source slice·고정 edge·content padding·자원 알파·입력 경계를 구분합니다. 고정 장식을 통째로 늘리지 않습니다. 상세는 [사용 설명서의 3·9슬라이스 규칙](USER_GUIDE.md)을 따릅니다.
- 입체 버튼은 [입체 버튼 제작법](THREE_D_BUTTON_GUIDE.md)을 따릅니다. 같은 기준면·카메라·원근의 정상/눌림 원화를 만들고 텍스트·입력·외부 그림자를 분리합니다. 예제의 특정 카메라 수치나 눌림 거리를 모든 버튼의 상수로 사용하지 않습니다.
- 복사한 부품은 부모·앵커·이름·입력 전달·탭 대상·나가는 연결을 확인합니다. 복사본의 정상 그림만 보고 기능과 반응형 배치까지 보존됐다고 판단하지 않습니다. [복사와 미저장 편집의 부분 복구](USER_GUIDE.md#native-copy-recovery)에 보존 범위가 있습니다.

## 저장과 검수

파일 저장 후 같은 폴더·workspace·projectId와 revision으로 다시 엽니다. 저장 샘플 보기는 저장판을 읽고 상세 편집의 미리보기는 미저장 변경도 보여 줍니다. 선택 모달의 단독 샘플과 배후 차단·닫기·복귀를 시험하는 동작 시험도 서로 다른 경로입니다. 보기용 샘플 때문에 임시 게임 버튼이나 미확인 연결을 추가하지 않습니다.

확인할 것은 다음과 같습니다. 수행하지 않은 항목은 미확인으로 남깁니다.

- 데스크톱 1440px, 모바일 430px와 논리 폰 390×844에서 배치·기준선·긴 글·앵커·스크롤·넘침·이미지/링크 누락을 확인합니다. 브라우저 CSS 크기, 논리 크기와 캡처 파일 픽셀은 구분합니다.
- 정상·hover·pressed·disabled와 상태 그림, 실제 mouse·Enter·Space 입력을 확인합니다. 필요한 화면은 Close·Back·Escape·배후 차단·Tab 순환·원래 입력 초점 복귀를 확인합니다.
- 실제 관찰된 연결의 출처·조건·행동·목적지·payload·복귀를 확인합니다. 미정 목적지와 실제 게임 API는 연결 완료로 표시하지 않습니다.
- 저장·재열기·충돌 시 수정 보존, 다른 workspace와의 격리, ID·계층·자원·연결 보존을 확인합니다.

기록에는 실제 화면 진입 순서·표현·저장 revision·확인 크기·캡처 경로를 남깁니다. 소스 검사, 자동 시험, 저장 파일 대조와 실제 화면 검수는 각각 구분합니다. 이전 시험 수를 이번 실행 수로 반복하거나 부품 수·저장 성공을 시각 완성률로 쓰지 않습니다.

## 성공·실패 노하우와 컨펌 남기기

여러 작업에 재사용할 방법은 공통 가이드의 해당 전문 문서에 보완합니다. 프로젝트의 고유 수치·관찰·미확인은 해당 프로젝트 기록에 둡니다. ‘무엇을 시도했는지 → 왜 실패했거나 효과가 있었는지 → 재현 가능한 수정 순서 → 실제 확인 범위와 증거 → 남은 한계’를 짧게 적고 실패판·원본·이전 버전을 보존합니다. 같은 내용을 여러 가이드에 길게 복제하지 말고 정본에 연결합니다.

특정 버전의 사용자 컨펌은 원문·KST 시각·workspace/projectId·revision·원본/자원 판·실제 캡처와 함께 보존합니다. 방법에 대한 컨펌과 개별 수치·다른 화면·전체 시각 동등성 승인을 구분합니다. 일반적인 ‘계속’이나 도구 시험 통과를 UI 최종 승인으로 확대하지 않습니다.
