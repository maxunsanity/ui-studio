## 2. 모든 화면에 적용할 분리 체크리스트

- [ ] **배경 / frame / 그림 / native text / input / 외부 그림자**를 별도 부품으로 만듭니다. 전체 UI screenshot 한 장을 화면 배경으로 붙이지 않습니다.
- [ ] 제목·값·수량·설명·이름·리본 문구는 native text로 둡니다. 그림에 문구가 남아 native text와 중복되지 않는지 확인합니다.
- [ ] 의도된 panel·disc·frame 배경과 glyph 뒤의 불필요한 사각 바탕을 구분합니다. alpha 채널 유무만 보지 말고 production 이미지 외곽·실루엣을 직접 봅니다.
- [ ] 원화/master·상태별 캔버스·alpha/crop·등록 자원을 연결해 기록합니다. 참조 해제와 원본 삭제를 혼동하지 않습니다.
- [ ] parentId와 그리기 순서를 따로 확인합니다. 부모를 바꿨다는 이유로 맨앞에 그려진다고 가정하지 않습니다.
- [ ] 자원 등록 → assetRef 반영 → 저장 → 재열기 → 실화면 확인을 별도 단계로 기록합니다. 도구 성공 메시지가 뒤 단계 성공을 대신하지 않습니다.
- [ ] 외부 cast shadow는 엔진 효과로 분리합니다. 프레임의 재질 측면·안쪽 베벨·3D 장면 자체의 명암을 외부 그림자로 오인해 지우지 않습니다.
- [ ] 기존 stable ID·연결·다른 화면을 보존합니다. 사소한 분해 때문에 제품 소스/스키마를 불필요하게 넓히지 않습니다.

## 3. Gallery: 먼저 4개 frame family를 만들고 복제하기

수치는 아래 두 단계로 읽습니다.

1. 측정 JSON의 observedCardRects는 원본 가시 경계의 근사값입니다.
2. normalizedCardFamilies는 같은 family를 반복 제작하기 위한 **공통 제작 제안**입니다. 둘을 서로 덮어쓰지 않습니다.

### 3-1. 공통 slot과 내부 박스

단위는 모두 logical px, 내부 rect는 해당 frame의 local [x,y,w,h]입니다.

- [ ] scroll pin을 구현한다면 마커 전체 그룹을 세로 Viewport/Content의 자손으로 두고, 카드보다 앞에 그려지도록 순서를 정합니다. 시각 레이어 설명을 Root 직속 fixed overlay 부모로 오해하지 않습니다. 자식 숫자/별/화살표를 각각 따로 pin하지 않습니다.
- [ ] 콘텐츠 길이·pin 설정의 실제 제작값은 본체가 저장본에서 확인합니다. fixture나 제작용 높이를 원본 영상 수치라고 쓰지 않습니다.
- [ ] 카드 기본 target은 null이고 비입력 그룹입니다. Close→Main은 관찰된 순서 대응이지만 원본 exact mouse-down/API가 입증된 것은 아닙니다.
- [ ] 140 아래의 문구·단계·기능을 창작하지 않습니다. native preview의 wheel/drag/keyboard scroll과 원본 물리 입력 증거를 구분합니다.

### 4-5. Map에서 만들지 않을 조작

- [ ] 네 안정 상태에는 footer/X/Back/상단 제목/스크롤바가 보이지 않습니다. Gallery의 공통 footer를 Map에 자동으로 붙이지 않습니다.
- [ ] 수동 scroll·범위는 미관찰입니다. 초기 구조는 세 단계가 보이는 clip으로 두고, 세로지도라는 이름만으로 wheel/drag 기능을 확정하지 않습니다.
- [ ] stage 카드 target은 모두 null입니다. 잠금해제→말 이동→fade→다음 보드의 시각적 순서를 stage 클릭 API로 바꾸지 않습니다.
- [ ] 미리보기 종료가 필요하면 도구의 바깥 조작을 사용합니다. 이를 원본 게임의 Back/Close라고 부르지 않습니다.

## 5. 기존 자원 재사용 판단

- [ ] Gallery frame과 slot이 native 자원으로 이미 만들어졌다면 같은 family 원형을 확인해 재사용합니다. 실제 현재 등록/품질은 본체가 확인한 결과로 적습니다.
- [ ] gold-padlock.webp는 기존48×58 자원 후보입니다. Map 약82×110로 확대하기 전에 master 해상도/실루엣/열림 상태를 확인합니다. 후보 존재를 그대로 최종품질 통과로 쓰지 않습니다.
- [ ] 기존 shop의 빨간 리본과 Gallery 다음 순서 리본은 Map의 산호색 곡선 리본과 형태가 다릅니다. 제작법/중앙 slice 후보와 최종 대체 자원을 구분합니다.
- [ ] 다른 게임의 아트/수치를 가져오지 않습니다. 원본 측정 이미지와 기존 실패판은 보존합니다.

## 6. .29 입체 버튼 방법을 적용하는 범위

- [ ] 실제 입체 버튼이 등장할 때 같은 기준면·카메라·소실점과 먼 쪽 단축을 지킵니다.
- [ ] normal/pressed는 같은 물체의 별도 전체 입체 그림으로 만들고 캔버스·배율·바닥 기준을 공유합니다. 색만 어둡게 하거나 평면 한 장 이동으로 대체하지 않습니다.
- [ ] hit/고정 몸체와 native 글자를 분리하고, 그림에 이미 반영된 눌림을 같은 그림 translate로 다시 적용하지 않습니다.
- [ ] r300 예제의2px·230×220·카메라 수치를 모든 버튼 상수로 복사하지 않습니다. 개별 상태 그림에서 글자 이동량을 정합니다.
- [ ] 3D처럼 보이는 섬/lock/카드 장식이 곧 버튼인 것은 아닙니다. 미관찰 클릭을 만들기 위해 press 상태를 새로 붙이지 않습니다.
